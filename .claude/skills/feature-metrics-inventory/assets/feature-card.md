# 特性卡文档模板

> 用法：复制「文件骨架」到被管项目 `docs/features.md`（或就地对齐已有特性文档）；每个特性复制一张卡。写入项目时删除本用法说明。方法与判据见 skill 的 references/feature-method.md。

## 文件骨架

```markdown
# <项目名> 特性清单

<!--
维护约定：给盘点与开发本项目的人看；管理特性主干、特性卡与状态变更。
只在特性梳理/评审后更新；指标口径正本在 .bw/metrics.toml，本文件只引用不复制。
-->

## 主干（按向人解释项目的顺序，一行一个）

1. <特性名> —— <一句话：谁在什么场景得到什么>
2. …（共 3–5 个）

## 特性卡

<每特性一张，模板见下>

## Not Now 清单

| 候选 | 归置原因 | 重议触发条件 | 记录日期 |
|---|---|---|---|

## 变更记录

| 日期 | 变更 | 确认人 |
|---|---|---|
```

## 特性卡模板

```markdown
### <特性名：对象 + 动作 + 结果，人话>

- 状态：active | completed（人确认，日期） | canceled（原因，日期）
- 谁（Job Executor）：<具体角色/人；禁写「用户」>
- 场景触发：<何时、什么条件下>
- 旅程线：<起点> → <步骤2> → … → <终点拿到价值>（3–7 个动词短语，一行，不展开分支）
- 价值对照：相对 <现状凑合法>，好/快/省在 <哪里>
- 挂接目标：<北极星指标名 | 「北极星缺席，挂定性目标方向：…」>
- 引领指标：<名称>（口径：已进目录的指向 metrics.toml 条目；仅 Unknown 候选在本文档内记 8 字段口径卡） | 待盘
- 滞后指标：<名称>（同上） | 待盘
- 使用证据：<访谈纪要 / issue 链接 / 产物路径>（只记事实题，S1–S4 分级见 metric-rules）
```

## 填写纪律（写卡时对照）

- 名字过六问检验（外行/句式补全/动宾/指标挂钩/旅程回推/数量）；不过即改名。
- 每张卡必须挂得上目标——挂不上归 Not Now，记原因，不静默删除。
- 改名走显式迁移：同步 metrics.toml 所有 `feature` 标签、主干行与外部引用，人逐项确认。
- 指标两行允许「待盘」，不允许编造；没有数据源支撑的指标不进 metrics.toml。
