# 指标口径卡模板（8 字段契约）

> 用法：站 4 每条指标一张卡，人确认后随 PR/Issue 交接 metrics-refresh；正式定义落 `.bw/metrics.toml`（字段约束以指标协议为正本），本卡是盘点与交接载体。8 字段契约与 project-knowledge 的 feature-evidence.md 对齐——该文件是契约正本，本卡是其盘点场景模板；模板前两行「角色 / 特性归属」为交接定位字段，不属契约 8 字段，其后八行与正本逐一对应。写入项目时删除本用法说明。

```markdown
### <指标名（人话）>

- 角色：引领（盯：<滞后指标名>） | 滞后 | 北极星
- 特性归属：<特性名 = metrics.toml 的 feature 标签>
- 目标与角色：测量哪个用户结果；若是引领，它影响结果的假设是什么
- 关系与理由：引领为何可能改善滞后；哪些因素会干扰；不宣称已证明因果
- 口径：分子 / 分母 / 单位 / 去重 / 样本总体 / 排除项 / 窗口（周为周一到周一）
- 观察时间：事件时间 vs 采集时间；时区；迟到数据处理
- 来源：git / issue 字段 / PR / CI / 仓内文件 / 人工记录（标 S1–S4 级）；谁有权提供；能否独立读回
- 采集：脚本入口或待新建命令草案（collect = script + retro=true）；失败/缺数怎么表达（Unknown，不写 0）
- 基线与目标：已测读数及时间，或「未知」；目标的认可来源（候选 ≠ 承诺）
- 防失真：是否会缩分母 / 挑容易任务 / 牺牲质量 / 增加人工成本；配对的约束指标或人工抽查动作
```

## 确认门自查（人确认前逐项过）

- 可行性门槛：数据源可脚本化读回？不能 → 标「Unknown 候选」，不进 metrics.toml。
- 互牵制：刷高引领会被配对滞后暴露吗？不会 → 换。
- 禁用清单：不在 metric-rules.md 禁用清单内（自报省时/平台归属数字/计数类当价值/排名/挂考核）。
- 退役条件：写下「什么情况下这条指标该退」（对应特性 Not Now / 说不出改变了哪个决定 / 口径被扭曲）。
