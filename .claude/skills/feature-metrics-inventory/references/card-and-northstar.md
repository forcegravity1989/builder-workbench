# 名片与北极星

> 30 秒导读：站 1、站 2 读本篇。名片是四空一句话，配反退化测试与失败模式检查；北极星最多 1 个、6 判据、允许缺席。术语沿 [CONTEXT](../../../../CONTEXT.md) 与指标协议正本，本篇只给盘点方法与判据，不复制协议。

## 站 1：名片

### 为什么是四空一句话

Amazon Working Backwards 的 PR 六要素（标题/副标题/摘要/问题/方案/如何获得）服务「对外发布与说服投资」；AWS 官方流程极重（PR 可写逾一年、10+ 稿），但官方自己定位 PR 是「首稿几小时的轻量工具」。对 1–3 人内部项目只保留产生判断的要素：具体客群、客户视角的问题、差异化价值，加一条内部 FAQ 问「用户今天靠什么凑合」。媒体格式、引语、TAM、价格全部删——它们不产生判断。

### 模板

> 为〈具体谁〉，在〈场景触发〉时，能〈做到/得到什么〉，不再靠〈现状凑合法〉。

**凑合法一空填不出 = 问题不真实**，打回重问，不许硬填。这一空同时是差异化价值的对照基线：好/快/省都是相对凑合法说的。

### 正反例

正例：

- 为一人产品 owner，在版本收尾要判断有没有跑偏时，能拿到由真实数据算出的自洽版本报告，不再靠手工翻记录与印象。
- 为值班工程师，在半夜告警时，能从告警一步跳到嫌疑变更，不再依次翻三个系统。

反例（实现黑话）：「构建基于 Electron 渲染进程的统一指标中台，赋能版本管理闭环」——主语是系统不是人，无场景，无凑合法。
反例（空话）：「让团队研发更高效」「AI 驱动的下一代一站式工作台」——无具体谁，无可核对价值。

### 失败模式检查清单（出自 Working Backwards 官方附录，命中即打回）

1. 客群不具体（「为所有人」——副标题官方纪律：以为适合所有人就是错了）
2. 问题句主语是系统/技术而非人
3. 方案是特性清单堆砌、未直接答题
4. 没写现状（今天靠什么凑合）
5. 无 better/faster/cheaper 差异（新奇 ≠ 解决问题，官方反例 Fire Phone）
6. 含糊宏大（提效/赋能/一站式，无场景）
7. 把计划或原型写成已交付（PR 的「仿佛已发布」是目标写法，名片必须是现状事实）

1–7 用于名片；官方清单另有「只写好处不写三个最可能失败的理由」「堆页数证明工作量」「skills-forward（我们有 X 就做 X）」三条，在后续写特性 intent/spec 时一并检查。

### 反退化测试（目标层）

若「直接关掉这个环节」也能满足目标，目标就写错了。Impact Mapping 官方工作坊练习的原型：目标写「减少客服电话量」，关掉呼叫中心也能达成——正确目标是它背后的那个（如「提高首次付款成功率」）。名片的「能〈…〉」一空过不了反退化测试就打回。

### 落点与字段映射

- 被管项目：`.bw/project.toml` **保真补空**（只补空字段、不覆盖已填内容；已有字段要改须人显式确认），走固定分支 + PR 流。映射：为谁/什么问题/什么价值 → `brief`（想做什么）；现状凑合法与对标 → `benchmark`（对标）；定性目标方向 → `opportunity`。写入协议以 bw-assets 与关键信息维护正本为准（路径见 [落盘与交接](asset-writing.md)）。
- **量化北极星不进 project.toml**：`opportunity` 的历史别名是 north_star，但现行语义是定性「目标方向」（CONTEXT 已登记：定性目标方向与量化北极星分开）；量化北极星只落 `.bw/metrics.toml` 的 `[north_star]`。
- BW 自身：README 与原则 03 已是名片正本，站 1 只做对照校准（名片一句话与「30 秒导读」是否讲同一件事），不另写。

## 站 2：北极星

### 谱系与分工（一句话版）

术语出自 Sean Ellis：「量化客户体验到产品价值的那个点」（Airbnb 用 nights booked 而非挂牌数）。Amplitude playbook 形式化为三层分工：

| 层 | 定义 | 数量 |
|---|---|---|
| 北极星 NSM | 价值结果；团队**不可直达**，只能靠 inputs 间接推动 | ≤1 |
| 输入指标 inputs | 日常工作可直接影响的杠杆——特性级引领指标即承担此角色 | 每特性 1 引领 |
| 护栏 guardrail | 追 NSM 时不得击穿的底线（质量/可靠性类） | 按需，不硬凑 |

### 6 判据（全过才立）

1. **价值**：指标 = 用户实现价值的点，不是曝光/注册/纯活跃计数（Amplitude 官方点名 DAU、注册数不合格：「它们对客户价值只字未提」）。
2. **唯一**：全项目 1 个；其余候选归 inputs 或护栏。
3. **不可直达**：一天内能直接刷高的不配当北极星（playbook 合著者 Cutler：「如果你能直接推动北极星，它多半不是好北极星」）。
4. **前瞻**：能说清「它涨 → 项目长期成功（使命/省时/省人力）为什么跟着涨」。
5. **可复算**：能从 git/issue/文件/日志独立现算、重启前后一致；取不到 = Unknown。
6. **可换代**：登记退役条件（战略变、阶段推进、对应能力移除）；Amplitude 自述换过至少 3 次北极星——换代是正常运维不是失败。

### 无营收项目候选清单（内部工具/平台型）

| 候选 | 口径示例 | 坑 | 护栏配对 |
|---|---|---|---|
| 核心工作流完成率 | 目标用户中每周经工具完成核心工作流的比例 | 行政强推虚高——CNCF 平台成熟度模型：被强制使用是低成熟度信号（Erratic→强推→自愿拉→参与式） | 绕过率 / 自愿回访 |
| 首次价值时间 TTFV | 接入 → 首次成功完成核心任务的中位时长 | 只测上手不测持续价值；小样本噪声大，必须用中位数并写清口径 | 配持续使用类滞后 |
| 任务成功率 | 核心任务完成占比 + 失败/回滚占比 | 「成功」定义须可人工核验，否则被刷 | 重开率 |
| 自助比例 | 无人工介入完成请求的占比 | 小团队可能无工单系统；会诱导「堵入口刷数」 | 满意度/失败率不恶化 |
| 每周有意义操作数 | 每周产生真实产物的操作数 | 量 ≠ 价值；agent 时代可被无恶意刷量 | 人工确认记录 |

### 缺席纪律

- **缺席是合法产出**：记「本期缺席 + 原因 + 重议触发条件」（例：「等首个管理项目产生两次真实使用证据后重议」）。BW 自身现行选择即是不硬立（metrics.toml 头注与 overview-metrics STATUS 有记录），占位不成为指标。
- 定性「目标方向」不能代替量化北极星（CONTEXT 已登记）；单特性 traction 数不配当树顶（OST：树顶最好是用户行为结果）——宁可缺席不硬立。

### 反例清单（人坚持时给依据并记录分歧，不代填）

- DAU / 注册数当北极星：Amplitude 点名否定。
- NPS：1–3 人内部项目样本过小 + 社会期望偏差，只配当满意度信号。
- 代码量 / PR 数 / 提交数 / token 数：Cadillac Task 效应——AI 让某类活变便宜后计数虚高而价值不涨（METR：速度口径中位 3x vs 价值口径 1.4–2x）。
- 「感觉提速了」：METR 2025 RCT——资深开发者用 AI 实际慢 19%，事前预期快 24%、事后仍自信快了 20%；自报与实测系统性背离，人平均高估 AI 省时 40 个百分点。
