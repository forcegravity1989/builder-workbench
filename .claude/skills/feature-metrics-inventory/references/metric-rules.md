# 指标纪律与判据

> 30 秒导读：站 4 读本篇。每特性 1 引领 + 1 滞后、配对互牵制、口径可脚本化、没数据 = Unknown。指标配置全协议（schema、collect、窗口、coverage）以指标协议正本为准，本篇只管盘点判据。口径卡模板在 [../assets/metric-card.md](../assets/metric-card.md)。

## 正本分工（引用不复制）

- 定义与采集全协议：[指标协议](../../../../standard/system-prompt/references/metrics.md)（metrics.toml schema 2、脚本 stdout、窗口纪律、Unknown 语义）。
- 口径卡 8 字段内容契约正本：project-knowledge 的 [特性证据连接](../../project-knowledge/references/feature-evidence.md)——本篇的口径卡即其盘点场景模板；「先定义可解释的结果，再找引领假设；没有可信引领指标就列待验证假设；不得拿 MD 数、提交数凑齐」等纪律以该正本为准。
- 术语沿 [CONTEXT](../../../../CONTEXT.md)：引领/滞后、读数、Unknown、可回溯采集均为已登记词，不另造含义。

## 1+1 纪律

每特性恰 1 引领 + 1 滞后。依据是五个独立血统的成对结构（均一手）：

| 血统 | 成对结构 |
|---|---|
| 平衡计分卡（Kaplan & Norton, HBR 1992） | outcome measures + performance drivers 必须同卡出现，且 drivers 须反映该单元独特战略——通用驱动指标无效 |
| Amplitude 北极星体系 | NSM（不可直达的结果）+ inputs（可直接动的杠杆） |
| Anthropic AI-native SDLC playbook（2026-08） | 每个 play 固定「How to measure it：1 引领 + 1 滞后」 |
| DORA | 吞吐指标配不稳定指标互牵制；五指标自身定性为「组织绩效的引领、交付实践的滞后」 |
| Impact Mapping | impact（行为改变，短期可观察）= 引领；goal（captured value）= 滞后 |

**下限纪律而非上限教条**：没有任何权威源规定恰好 1+1，它是最小可互检配置。超出须人说理由（如确需可靠性护栏位），且每多一条如实告知多养一个采集脚本——维护成本是一等公民：Google 官方开源的 FourKeys 采集管道自己已声明 "not currently maintained"，零许可成本的脚本仍死于维护。

### 互牵制检查（站 4 确认门）

对每一对问：「如果有人刷高引领（缩分母、挑容易任务、改阈值），滞后会不会暴露它？」不会 → 换引领或补护栏。例：引领 = 需求返工次数，滞后 = 实施至合入耗时（返工数字好看但合入变慢会暴露）；官方同类纪律：playbook 要求人均合并量必须与返工率**成对读**、不许单独展示。

## 「真引领」判据（四条全过）

1. 时间上先行于配对滞后，且能说出因果假设——怎么影响滞后、哪些因素干扰；**不宣称已证明因果**。
2. 团队日常工作可直接影响（Amplitude inputs 的定义）。
3. 不挂目标与奖惩——度量成为目标就不再是好度量（Strathern 1997，通行句常误归 Goodhart 本人）；agent 时代加重：计数类指标会被**无恶意地**刷量。
4. 配对可验证：每次复盘检查「引领动了，滞后跟动了吗」；连续两个复盘周期不跟 → 退役或更换。

## 「滞后代表价值」判据（三条全过）

1. 度量「用户实际收到的价值」而非「团队做了多少」。
2. 生产者无法直接刷高（不可直达检验的镜像）。
3. 能从真实数据源独立读回；人工记录按下方证据分级。

## 可行性门槛（进配置前的硬门）

每条指标当场回答并记入口径卡：

1. 数据源是什么：git / issue 原生字段（含关闭原因）/ PR / CI / 仓内文件 / 人工记录文件？
2. 能否写成脚本独立读回并输出 day/week points（collect 协议只支持 script + retro=true）？当场写下采集方式草案（命令级）。
3. 不能读回 → 标「**Unknown 候选**」：按八字段卡记入特性卡文档的「Unknown 候选口径卡」节（来源与采集字段如实写缺口，附重议触发条件），并在变更记录登记一行；**不进 metrics.toml**——没有采集脚本的指标在总览显示为问题而非读数，宁缺毋滥。
4. 无法独立重算的平台遥测数字（AI 协助行数占比、PR 归属比、会话计数等）一律不作指标：违反现算铁律，且厂商自己标注算法局限（归属窗口、故意保守、不追踪删除、人工改写超阈值不归属）。AI 参与如需代理，只用可独立重算的 commit trailer 计数，并注明 trailer 可被剥离/误挂。

## 滞后证据强度分级（零埋点项目）

| 级 | 形态 | 例子 | 纪律 |
|---|---|---|---|
| S1 | 机器生成、可双源对账 | 发布记录 + 用户侧版本号对账；使用产物入库（报告/配置/数据文件）；服务端日志定期导出归档 | 只证明「装上了/调用了」，须与使用类证据配对 |
| S2 | 双方参与、有时间戳 | issue 关闭读回（原生关闭原因 + 用户回帖佐证，防自提自关）；结构化试用访谈（记受访人 + 日期 + 原话） | 访谈**只记事实题**（做过什么任务、产出在哪），态度题（「还会用吗」）礼貌性偏置、只作参考不作证据 |
| S3 | 单方人工记录 | 值班表 + 完成勾记（签名 + 日期） | 与第二来源（产物/issue）对账后才升级 S2 |
| S4 | 无证据裸数字 | 口头「大概有 10 个人在用」 | **不采用**，记 Unknown |

人工证据路线的权威依据（均一手）：DORA 度量指南——「为精确数据建多系统集成可能不值得初始投入，**更好的起点是对话**」；martinfowler.com（DX Core 4 引用文献）——「优先用来自人的数据而非系统数据；不挂奖惩时受访者没有撒谎动机；调研可采集客观事实（DORA 四指标本身就是问卷问出的）」；DX Core 4——「小 startup 可以只用 issue tracker 快速测量」「先用自报建基线，不要为等系统数据停摆」；GitHub ESSP——survey 与 telemetry 并列正当手段。**边界**：人工证据用于「使用事实与受益事实」，不用于「自报提效百分比」（METR：自报只能三角互证，问价值不问速度）。

可移植官方口径：GitHub engaged = 28 天窗口内 ≥2 个不同日活跃 → 人工勾记版「一个周期内至少两天真实使用才算 engaged」。

## 禁用清单

1. 自报省时 / 感觉提速类指标（METR：并行 agent 计时无法归因；最受益样本系统性退出对照；人平均高估 AI 省时 40 个百分点）。
2. 无法独立重算的平台归属数字（见可行性门槛第 4 条）。
3. 计数类当北极星或价值证明：PR 数、commit 数、任务关闭数、token 数、agent 数——Cadillac Task：AI 让某类活变便宜后人们狂做这类活，速度口径中位 3x vs 价值口径 1.4–2x。
4. 跨项目排名或横向比较（DORA 官方立场：只跟自己历史比；「disparate comparisons」明列为 pitfall；指标设成目标违反 Goodhart）。
5. 指标挂个人绩效考核（DX：diffs per engineer 禁用于个人层）。
6. 吞吐类指标单独展示（playbook 原文要求与返工率成对读）。
7. 失败写 0、用当前快照补历史、未结束窗口不带 coverage（指标协议正本）。
8. agent 产出单独立户计数（DX：计入所属团队吞吐即可）。

## 退役与剪枝（内建机制，不是失败）

任一命中即进退役审议：

1. 说不出它最近改变了哪个决定（DORA：从决定出发；说不出决定 = 不产生价值）。
2. 被当目标且行为已扭曲。
3. 战略/阶段变化失去代表性（Amplitude 自述换过 ≥3 次北极星）。
4. OMTM 轮换：阶段目标达成即 move on（Lean Analytics 把剪枝做成框架内建机制）。
5. 对应特性被删或归 Not Now。

退役不静默：在特性卡变更记录登记去向（替代口径或缺席原因）。「度量一切」是 DORA 点名反模式（Focusing on measurement at the expense of improvement）；GitHub ESSP 四原则之一即「度量成本与收益平衡」。

## 小样本与对外口径纪律

- 1–3 人项目数据列个体 + 中位数，不造百分比；单月不作数看滚动季度；单次成功不外推。
- 口径经人确认即钉死（分子/分母/窗口/配对规则/排除项）；改口径走站 4 重新确认——数字不动时不悄悄改口径。
- 时间口径分开记：「经过时间」「人亲自操作时长」「agent 运行时长」回答不同问题，不能相加（METR 并行计时教训）。
- 对外讲数必带口径、分母与窗口——无口径的厂商数字（「提效 90%」「多合 30% PR」）正是研究报告逐个点名批评的对象，不成为那种数字。
