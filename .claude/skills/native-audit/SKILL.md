# native-audit — native 评估

给一个 git 仓量「AI-native 制度化水位」：它把「让 AI 安全高速干活」的那套规矩，做到了口头、成文、还是机器强制的哪一级。**准则唯一正本是 [`docs/05-features/native-audit/rubric.md`](../../../docs/05-features/native-audit/rubric.md)**（9 段 37 条、阶梯 0-3、每条带 dsh 一手证据与 SDLC 对应）；本文件只写怎么执行，两处冲突以 rubric 为准。

## 用词对照（本技能用词 → 人话；词表已有的词直接用词表）

| 本技能用词 | 人话 | 来源 / 词表对应 |
|---|---|---|
| **native 评估**（native-audit，此前叫「仓考古」） | 对一个仓的全量 git 历史与过程制度件做只读分析，量出制度化水位与缺失清单 | 已登记 `CONTEXT.md` 工程操作词 |
| **制度化阶梯** | 一条规矩的四级：0 无/不可考 → 1 有痕迹（散见）→ 2 成文（写进仓）→ 3 机器强制（违规会被拦） | 已登记 `CONTEXT.md` 工程操作词 |
| **探针** / **探针脚本**（`battery.sh`） | 探针 = 一条只读命令出一个读数；探针脚本 = 把 37 条准则的探针打包成一个脚本。文件名 battery 取英文「一组测试」的惯用语 | 本技能自造，只在这里用 |
| **读数** | 探针输出的原始数字或字串，未经判读 | 词表「读数 / Reading」 |
| **活**（issue） | 一件要干的具体工作，最小单位；远端 codehub/GitHub 的 issue+标签是它的唯一正本。散文里一律写「活」，issue 只出现在代码、路径与 GitHub 功能名里 | 词表「活 / Issue」——不写工单、任务、ticket |
| **锚点** | 已经定过级的参照仓，用来校准定级手感：dsh ≈ 3 分、本仓 ≈ 2 分 | 本技能自造 |
| **门禁** | 机器跑的检查组（hook / CI / verify 脚本），违规就红 | 词表「门禁 / Gate checks」——**与 gate 不同**：gate 是人拍板的关卡 |
| **门禁自测** | 用一个故意做错的输入（已知坏例）证明门禁真会拦；dsh 的 verify 脚本 17/34 带这种自测 | 与 `docs/05-features/process-hardening` A3 同词 |
| **Unknown** | 拿不到数据时的诚实态；不写 N/A、不写待定、不补分 | 词表「未知 / Unknown」 |
| **读回** | 报告里的每个数都能用一条命令独立重新查出来 | 词表「读回 / Read-back」 |
| **复盘**（postmortem） | 事故写成的结构化记录：什么坏了、为什么每道防线都没拦住、加了什么防护 | 词表生命周期「运维复盘回流到原型」；dsh 目录名 `docs/postmortem/` 保留英文 |
| **产物链** | 意图件 → 规格件 → 计划 → 带测试的改动 → 带评审结论的 PR → 复盘 → 新意图件，每级进 git | `docs/10-reference/ai-native-sdlc-playbook.md` 用词；`docs/01-principles/01` 称制品链，同一个东西 |
| **playbook** | Anthropic《AI-Native SDLC Playbook》，AI 原生研发流程手册；仓内正本是它的提炼版 | `docs/10-reference/ai-native-sdlc-playbook.md` |

| **slop** | AI 写作垃圾：重复复述、叙述历史、推理过程留在文档里、强调符号通胀 | dsh `docs/AGENTS.md`「slop checklist」；对应本仓「写作纪律」与「黑话」 |
| **worktree** | 每张活一棵独立的 git 工作树 | 词表「运行」条用词 |
| **hook** | git 钩子：提交前 / 推送前自动跑的本地检查 | dsh 用 lefthook |
| **抖动测试**（flaky） | 时过时不过的测试；dsh 有专门剧本处理 | — |
| **harness** | 包着模型干活的那层运行时（工具、会话、沙箱、循环）；dsh = DeepSeek Harness | — |
| **误报** | 探针命中但人工复核不成立的读数（如举例路径被当死链） | 人话，不用「假阳性」 |
| **弱信号** | 只能说明「有没有提到」，不能说明「做得好不好」的读数；定级时看文件是不是本仓规矩，不看数字大小 | 本技能自造 |

写报告给人看时按此表说人话；`C##`/`S#` 编号只在表格与明细里用，正文第一次出现带准则名。

## 三层结构：为什么扫描器里没有业务知识

一把用来量别人的尺，不能刻着自己家的词。所以引擎、通用惯例、组织私有词汇是三层分开的：

| 层 | 文件 | 装什么 | 换仓时 |
|---|---|---|---|
| **引擎** | `battery.sh` | 只会「按模式表数东西」：数文件、数命中、算比例。不认识任何具体的目录名、词表词、语言 | 不动 |
| **通用惯例** | `patterns/core.conf` | 别的组织也会这么叫的命名惯例（ADR/RFC、post-mortem、`kind/`·`area/` 标签、`AGENTS.md`·`.cursorrules`·`copilot-instructions`…）。**入表门槛：能在两个以上无关组织的公开仓里见到** | 不动 |
| **生态与平台** | `patterns/ecosystem.conf` | 八种语言的严格编译/lint/测试标志，以及 GitHub Actions 之外的 GitLab·CodeHub·Jenkins·Woodpecker 等 CI 布局。引擎按仓里的标志文件自动选 | 不动（加语言＝加一组变量） |
| **方言** | `patterns/dialect.*.conf` | 某个组织私有的说法（本仓的「读回」「30 秒导读」「`bw:status:`」）。**默认不加载** | 每个组织一份 |

**跨仓比较一律只用通用读数**。方言词往往是本仓高频词，会把「含该词的文件数」这种弱信号抬得很高（实测本仓 C43 从 3 跳到 61、C45 从 9 跳到 73）——那不代表这个仓做得更好，只代表它爱这么说话。方言的唯一用途是：扫自己家的仓时，回答「这条纪律在我们这儿到底有没有成文」，避免因为用词不同而被判 0。报告里必须写明用没用方言。

## 硬纪律

- **只读**：不向目标仓写任何东西；远端仓 clone 进会话 scratchpad。
- **Unknown 纪律**：探针输出 `Unknown`（附 `reason=`）或拿不到的数据 → 该条记 0 并写明原因（浅历史 / squash / 无权限 / 超时 / 无已知生态标志），绝不推断补分。
- **可读回**：报告每个数字来自探针脚本的一行输出或一条给出的命令；每个定级带仓内证据路径。
- **别人的代码不算本仓的实践**：`vendor/`、`third_party/`、子模块里的手册、技能、决策记录一律不计入（引擎已按 `P_VENDORED_PATH` 剔除；实测本仓 skill 数从 52 降到 9，那 43 个是 vendored 的第三方剧本）。
- **两个锚点防漂移**：deepseek-harness（dd6322d604）≈ 3 分锚、builders-workbench（2026-09-02）≈ 2 分锚，两仓 37 条读数与定级在 [`prototype-report.md`](../../../docs/05-features/native-audit/prototype-report.md)。给新仓定级前先对照。
- **子代理**：仓群模式每仓一个子代理，模型 sonnet（难仓 opus），一律不用 Fable；并发 ≤5。

## 主路径（单仓）

1. **取仓**。本地路径直接用；远端 `git clone --filter=blob:none <url>`（历史全、文件内容按需拉，巨仓可行）到 scratchpad。失败 → 该仓整体 Unknown + 原因。
2. **跑探针脚本**（纯脚本、零 token）：

```bash
bash <skill 目录>/battery.sh <repo-path>
```

扫自己组织的仓、且该组织有自己的方言表时，追加 `--dialect <方言文件>`；用自定义模式表则 `--patterns <目录>`。

输出先打 `## META`（用了哪份模式表、有无方言、探到哪些生态、CI 配置几份、认出的手册是哪个文件），再按 S0–S8 分段、每行 `C## 键=值`。**META 必须原样进报告**——不知道用的哪把尺，读数就没法复算。

已知边界：死链探针只查相对 `.md` 链接，排除反引号内路径、含省略号的举例路径、`archived/` 冻结件与 vendored 目录，命中行仍须人工复核；含关键词文件数是弱信号（只证「提到过」，不证「做得好」）；生态探不到时相关条目输出 `Unknown reason=no-known-ecosystem-marker` 而不是 0，不要把它当成「没有」。

3. **读样本**（限额，防炸上下文）：根 AGENTS.md/CLAUDE.md、CI 主 workflow、PR 模板各读前 150 行；**顺着 AGENTS.md 的链接看它指向哪些正本**（原则篇 / 词表 / 技能）；决策记录抽 2 份看有没有「替代方案」与「后果」节；复盘抽 1 份看结构；评审剧本抽 1 份看阻断项。只为定级取证，不通读。
4. **定级**：逐条对照 rubric 的「3 分的样子」列打 0-3。读数只回答「有没有 / 多少」；成文（2）与机器强制（3）的区分看三件事：规矩写在哪个文件、有没有 hook/CI/脚本在拦、门禁有没有自测。段分 = 该段各条的中位数；总评用九段分 + 「差口集中在哪一跳」一句话。
5. **出报告**：模板见下。

## 报告模板

```
# <仓名> · native-audit 报告（<日期>，HEAD <sha>）
## 扫描条件（原样附 META：模式表 / 方言 / 生态 / CI 平台 / 认出的手册）
## 探针读数（原样附 battery.sh 输出）
## 九段评分
| 段 | 分 | 条目分 | 一句话差口 |
## 三十七条定级明细
| # | 级 | 证据路径 | 差口 |
## 缺失清单（按「升一级最便宜」排序，最多 8 条）
## 与锚点对照（dsh / BW 同条读数）
## 本次探针异常（Unknown 项、误报、降级）
```

## 仓群路径

1. 入参：清单文件（每行一仓）或 codehub 组名。组名模式先探测 `codehub-cli`；不可用则明确报「内网模式在此机不可用，需在装过 Workbench（旧名 buddy）的机器跑」，不装死、不降级成猜。**全群用同一份模式表与同一个方言设置**（要么都不带方言，要么都带同一份），否则各仓读数不可比。
2. 每仓派一个子代理跑主路径，只回传评分卡（九段分 + 37 条级 + top3 缺失 + 探针异常，≤60 行）。
3. 主线程汇总：九段 × 仓矩阵榜、全群 top 缺失（按条计频）、失败清单（含原因）、「BW 规范铺底可直接补哪些」对照段（AGENTS.md 铺底 → S0；docs/05-features/ 链 → S1/S2；guard 脚本 → C32/C73；技能 → C04/C51/C74）。
4. 超过 20 仓先扫每项目代表仓校准一轮（对照两个锚点看有没有系统性偏高/偏低），再全量。

## 出错与降级

命令超时（巨仓）→ 探针脚本加 `--since="1 year ago"` 等价窗口并在报告「探针异常」段标注；子代理失联 → 该仓 Unknown；探针输出 `Unknown` → 该条 0 + 原因。任何降级必须出现在报告正文，不静默。

## 边界

不评代码质量、不做安全审计、不自动建活。缺失清单转成活由人决定。
