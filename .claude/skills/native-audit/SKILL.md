# native-audit — native 评估

量一个 git 仓的 **AI-native 制度化水位**：它把「让 AI 安全高速干活」的那套规矩，做到了口头、成文、还是机器强制的哪一级。

准则正本是 [`references/rubric.md`](references/rubric.md)（9 段 37 条 + 阶梯定义），随本技能走；本文件只写怎么执行，两处冲突以 rubric 为准。

## 术语（本技能自己的词）

评估任何仓都用这套词说话，不借用被评估方的内部词汇。

| 词 | 意思 |
|---|---|
| **制度化阶梯** | 一条规矩被落实到的四级：**0** 无／不可考 · **1** 有痕迹（散见于提交、分支、个别文件）· **2** 成文（写进仓里给人和 AI 读，靠自觉与评审执行）· **3** 机器强制（违规会被钩子／CI／门禁脚本／类型系统拦下，且门禁有自测） |
| **探针** | 一条只读命令，出一个读数。37 条准则的探针打包成 `battery.sh` |
| **读数** | 探针输出的原始数字或字串，未经判读。读数只回答「有没有／多少」，不回答「好不好」 |
| **弱信号** | 只能说明「提到过」、不能说明「做得好」的读数（典型：含某关键词的文件数）。定级时看那份文件是不是该仓的规矩，不看数字大小 |
| **误报** | 探针命中但人工复核不成立（如把散文里的举例路径当成死链） |
| **Unknown** | 拿不到数据时的诚实态。写 `Unknown` 并附原因，不写 N/A、不写待定、不猜、不补分 |
| **门禁** | 机器跑的检查（钩子／CI／校验脚本），违规就红。与「人拍板的关卡」是两回事，本技能只量前者 |
| **门禁自测** | 用一个故意做错的输入证明门禁真会拦。没有自测的门禁可能一直报绿却什么都没守住 |
| **校准参考** | 已经定过级、读数留档的参照仓，用来防止评分随会话漂移。见 [`references/calibration.md`](references/calibration.md) |
| **方言** | 某组织私有的说法。默认不加载，只在评估该组织自己的仓时显式启用 |

## 三层结构：为什么扫描器里没有业务知识

一把用来量别人的尺，不能刻着某一家的词。所以引擎、通用惯例、私有词汇分三层：

| 层 | 文件 | 装什么 | 换个仓 |
|---|---|---|---|
| **引擎** | `battery.sh` | 只会「按模式表数东西」：数文件、数命中、算比例。不认识任何具体目录名、词汇、语言 | 不动 |
| **通用惯例** | `patterns/core.conf` | 别的组织也会这么叫的命名惯例。**入表门槛：能在两个以上无关组织的公开仓里见到** | 不动 |
| **生态与平台** | `patterns/ecosystem.conf` | 八种语言的严格编译／lint／测试标志；GitHub Actions 之外还认 GitLab、Jenkins、Woodpecker、Drone、Buildkite、Forgejo 等 CI 布局。按仓里的标志文件自动选 | 不动（加语言＝加一组变量） |
| **方言** | `patterns/dialect.*.conf` | 某组织私有说法。模板见 `dialect.example.conf` | 每个组织一份，默认不加载 |

**跨仓比较一律只用通用读数。** 方言词往往是该组织的高频词，会把弱信号抬得很高——那不代表这个仓做得更好，只代表它爱这么说话。方言的唯一用途是：评估某组织自己的仓时，别因为用词不同把已经成文的纪律判成 0。用没用方言必须写进报告。

## 硬纪律

- **只读**：不向目标仓写任何东西；远端仓 clone 进会话临时目录。
- **Unknown 纪律**：探针输出 `Unknown`（附 `reason=`）或数据拿不到 → 该条记 0 并写明原因（浅历史／squash／无权限／超时／无已知生态标志），绝不推断补分。
- **可复算**：报告里每个数字都来自探针的一行输出或一条给出的命令；每个定级都带被评估仓的证据路径。
- **别人的代码不算这个仓的实践**：`vendor/`、`third_party/`、子模块里的手册、技能、决策记录一律不计（引擎按 `P_VENDORED_PATH` 剔除）。
- **先对校准参考再定级**：给新仓打分前，先看 `references/calibration.md` 里同条目的读数落在什么区间，避免整体偏高或偏低。
- **子代理**：仓群模式每仓一个子代理，模型 sonnet（难仓 opus），一律不用 Fable；并发 ≤5。

## 主路径（单仓）

1. **取仓**。本地路径直接用；远端 `git clone --filter=blob:none <url>`（历史全、文件内容按需拉，巨仓可行）到临时目录。取不到 → 该仓整体 Unknown + 原因。

2. **跑探针**（纯脚本、零 token）：

```bash
bash <skill 目录>/battery.sh <repo-path>
```

评估某组织自己的仓、且该组织有方言表时追加 `--dialect <文件>`；用自定义模式表则 `--patterns <目录>`。

输出先打 `## META`（用了哪份模式表、有无方言、探到哪些生态、几份 CI 配置、认出的手册是哪个文件），再按 S0–S8 分段、每行 `C## 键=值`。**META 必须原样进报告**——不知道用的哪把尺，读数就没法复算。

已知边界：死链探针只查相对 `.md` 链接，排除反引号内路径、含省略号的举例路径、冻结归档与 vendored 目录，命中行仍须人工复核；含关键词文件数是弱信号；生态探不到时相关条目输出 `Unknown reason=no-known-ecosystem-marker`，不要当成「没有」。

3. **读样本**（限额，防炸上下文）：META 认出的手册、CI 主配置、PR 模板各读前 150 行；**顺着手册里的链接看它指向哪些正本**；决策记录抽 2 份看有没有「替代方案」与「后果」节；复盘抽 1 份看结构；评审剧本抽 1 份看阻断项。只为定级取证，不通读。

4. **定级**：逐条对照 rubric 的「3 分的样子」列打 0-3。成文（2）与机器强制（3）的区分看三件事：规矩写在哪个文件、有没有钩子／CI／脚本在拦、门禁有没有自测。段分 = 该段各条的中位数；总评 = 九段分 + 「差口集中在哪一跳」一句话。

5. **出报告**（模板见下），并把本次读数追加进 `references/calibration.md` 的参考表，供下次校准。

## 报告模板

```
# <仓名> · native-audit 报告（<日期>，HEAD <sha>）
## 扫描条件（原样附 META：模式表 / 方言 / 生态 / CI 平台 / 认出的手册）
## 探针读数（原样附 battery.sh 输出）
## 九段评分
| 段 | 分 | 条目分 | 一句话差口 |
## 三十七条定级明细
| # | 级 | 证据路径 | 差口 |
## 缺失清单（按「升一级最便宜」排序，最多 8 条）
## 与校准参考对照（同条目读数落在什么区间）
## 本次探针异常（Unknown 项、误报、降级）
```

## 仓群路径

1. **入参**：清单文件（每行一仓）或托管平台的组／命名空间名。走组名时先探测该平台的 CLI（`gh`、`glab`、或内网平台自带的 CLI）；探不到就明确报「此机没有可用的平台 CLI，需换一台装了的机器或改用清单文件」，不装死、不降级成猜。**全群用同一份模式表与同一个方言设置**，否则各仓读数不可比。
2. 每仓派一个子代理跑主路径，只回传评分卡（九段分 + 37 条级 + top3 缺失 + 探针异常，≤60 行）。
3. **主线程汇总**：九段 × 仓矩阵榜、全群 top 缺失（按条计频）、失败清单（含原因）。缺失按「补什么能一次覆盖多个仓」归类：手册与技能（S0）→ 意图与决策记录（S1/S2）→ 门禁与自测（C32/C73）→ 验证与发布（S4/S5）→ 复盘回流（S6）。
4. 超过 20 仓：先扫每个项目的代表仓校准一轮（对照 `references/calibration.md` 看有没有系统性偏高／偏低），再全量。

## 出错与降级

命令超时（巨仓）→ 探针加 `--since="1 year ago"` 等价窗口并在报告「探针异常」段标注；子代理失联 → 该仓 Unknown；探针输出 `Unknown` → 该条 0 + 原因。任何降级必须出现在报告正文，不静默。

## 边界

只量「过程制度化到哪一级」。不评代码质量、不做安全审计、不改被评估仓任何东西、不自动建工单——缺失清单要不要变成待办，由人决定。
