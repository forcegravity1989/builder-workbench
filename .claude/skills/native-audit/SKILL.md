# native-audit

回答一个问题：**这个仓把「让 AI 安全高速干活」的规矩，做到了哪一级？**

同一条规矩可以停在三个不同的地方——只在某人脑子里、写进了仓、或者违反了就会被机器拦下。第三种才叫真的有。逐条量出它停在哪，再给出「下一步补哪条最省力」。

只读，不改被评估的仓任何东西。

## 先问清楚三件事

动手前确认，问错了后面全白做：

1. **扫一个还是一批？** 一批走[仓群流程](#仓群怎么扫)，规矩不同。
2. **被扫的仓里有没有存着这套准则的副本？** 典型是它就是这个技能的来源仓。有的话把那些路径记下来——第 2 步要传给探针，否则准则原文会被当成「这个仓有这条规矩」，读数虚高。
3. **要不要用方言？** 只有评估某组织自己的仓、且他们有方言表时才用。跨仓比较一律不用——方言词是自家高频词，会把读数抬起来，那不代表做得更好。

## 单仓怎么扫

### 1 · 取仓

本地路径直接用。远端：

```bash
git clone --filter=blob:none <url> <临时目录>
```

历史全、文件内容按需拉，巨仓也能跑。取不到就到此为止：整仓记 Unknown，写明原因（无权限／网络／仓不存在），不猜。

### 2 · 跑探针

```bash
bash <skill 目录>/battery.sh <仓路径>
```

按第 0 步的答案追加参数：

| 情况 | 加什么 |
|---|---|
| 仓里存着准则副本 | `--self-exclude <路径前缀>`，每处一个，可重复 |
| 评估某组织自己的仓且有方言表 | `--dialect <文件>` |
| 用自定义模式表 | `--patterns <目录>` |

输出第一段是 `## META`：这次用的哪份模式表、有没有方言、排除了什么、探到什么生态、几份 CI 配置、认出的手册是哪个文件。**META 原样抄进报告**——不知道用的哪把尺，后面的数就没法复算。

接着是 `C## 键=值`，按 S0–S8 九段排列。

### 3 · 读样本

只为取证，不通读。限额：

- META 认出的那个手册、CI 主配置、PR 模板 —— 各读前 150 行
- 顺着手册里的链接看它指向哪些正本（原则、词表、剧本）
- 决策记录抽 2 份 —— 看有没有「替代方案」和「后果」两节
- 复盘抽 1 份 —— 看结构固不固定
- 评审剧本抽 1 份 —— 看有没有阻断项清单

### 4 · 逐条定级

对着 [`references/rubric.md`](references/rubric.md) 的三十七条，每条问一次「这条规矩在这个仓停在哪」：

| 级 | 判断 |
|---|---|
| **0** | 找不到，或数据拿不到 —— 写 Unknown 加原因，不推断补分 |
| **1** | 有痕迹：散见于某几个提交、某个分支、某个文件，没成规矩 |
| **2** | 成文：写进仓里给人和 AI 读了，但执行靠自觉和评审 |
| **3** | 机器强制：违反了会被钩子／CI／门禁脚本／类型系统拦下 |

**2 与 3 的分界是整套判读最容易错的地方**，只问一句：违反了会不会红？写得再详尽、再郑重，没有东西会拦，就是 2。

三条别踩：

- **读数只回答「有没有／多少」，不回答「好不好」。** 尤其「含某关键词的文件数」这类——它可能数到的是转述别人主张的文档。定级看那份文件是不是这个仓自己的规矩，不看数字大小。
- **探针命中要人工复核。** 死链探针会把散文里的举例路径也算上。
- **别人的代码不算这个仓的实践。** vendored、第三方、子模块里的东西引擎已经剔了，判读时也别捡回来。

定完先对 [`references/calibration.md`](references/calibration.md)：同一条在已定级的仓里是什么读数、判了几分。手上这个明显更高却想判低、或明显更低却想判高，停下来先解释为什么。

段分取该段各条的中位数。

### 5 · 出报告

```
# <仓名> · native-audit 报告（<日期>，HEAD <sha>）
## 扫描条件（原样抄 META）
## 探针读数（原样抄 battery.sh 输出）
## 九段评分
| 段 | 分 | 条目分 | 一句话差口 |
## 三十七条定级明细
| # | 级 | 证据路径 | 差口 |
## 缺失清单（按「升一级最省力」排序，最多 8 条）
## 与校准参考对照
## 本次探针异常（Unknown 项、误报、降级）
```

总评一句话：九段分 + 差口集中在哪一跳。

扫完把这次读数追加进 `references/calibration.md`，下次校准用得上。

## 仓群怎么扫

1. **拿清单**。入参是清单文件（每行一仓）或托管平台的组名。走组名先探测平台 CLI（`gh`、`glab`、或内网平台自带的）；探不到就直说「此机没有可用的平台 CLI，需换机器或改用清单文件」，不装死、不降级成猜。
2. **统一尺子**。全群同一份模式表、同一个方言设置——一半带一半不带，读数就没法比。
3. **每仓一个子代理**跑单仓流程，模型 sonnet（难仓 opus），一律不用 Fable，并发 ≤5。只回传评分卡：九段分 + 三十七条级 + top3 缺失 + 探针异常，≤60 行。
4. **主线程汇总**：九段 × 仓的矩阵榜、全群 top 缺失（按条计频）、失败清单（含原因）。缺失按「补什么能一次覆盖多个仓」归类：手册与技能 → 意图与决策记录 → 门禁与自测 → 验证与发布 → 复盘回流。
5. **超过 20 仓**先扫每个项目的代表仓校准一轮，对着 calibration 看有没有整体偏高偏低，再全量。

## 出岔子怎么办

| 情况 | 怎么做 |
|---|---|
| 巨仓跑超时 | 探针加 `--since="1 year ago"` 等价窗口，在报告「探针异常」段标注这次只看了近一年 |
| 探针输出 `Unknown reason=...` | 该条记 0，把 reason 抄进报告，**不要当成「这个仓没有」** |
| 生态探不到（`ecosystems=unknown`） | 相关条目全是 Unknown，报告里说明这个仓用的技术栈不在模式表里 |
| 子代理失联 | 该仓整体 Unknown，进失败清单 |

任何降级都要出现在报告正文，不静默。

## 不做什么

只量「过程制度化到哪一级」。不评代码质量、不做安全审计、不改被评估仓任何东西、不自动建工单——缺失清单要不要变成待办，人来决定。

## 想知道更多

- 三十七条准则与它们的出处：[`references/rubric.md`](references/rubric.md)

- 探针认哪些文件名、目录、词：`patterns/core.conf`（通用惯例）、`patterns/ecosystem.conf`（语言与 CI 平台）、`patterns/dialect.example.conf`（方言写法）。**要改「认什么」就改这些表，引擎不动。**
