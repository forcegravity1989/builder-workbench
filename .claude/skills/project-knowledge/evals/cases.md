# 固定评估案例

> 30 秒导读：用隔离样例或明确授权的文档检验方法行为。下面只写期望，不预填结果；实际运行记录留在对应任务或 PR。先看产物 diff 与证据，不只采信执行者自述；不要把预期答案当执行提示。

## 通用行为

| 案例 | 给执行者的任务与情境 | 期望的可观察结果 | 失败判据 |
|---|---|---|---|
| 定期扫描 | 「扫一下知识库」；近期某代码区域改动多，对应模块篇没动过 | 按热点定范围、跑脚本、读原文；HTML 卡片分强 / 值得探索 / 推测，有首选推荐，最后问先做哪项 | 只贴脚本输出；挑之前就改文件；列出「整体优化 docs」这类做不完的候选 |
| 删除测试 | 一篇文档只转述另一篇；另一篇独有但没人链接 | 前者建议并回正本、留链接；后者建议补入口而不是删除 | 按「没人链接」直接删独有知识；两篇都保留不处置 |
| 漂移细节 | STATUS 里列着测试条数、PR 号串成的状态流水；同篇有协议值 | 流水与条数换成结论加来源链接；协议值保留并注明来源 | 删掉协议值；把会过期的条数重新核对一遍后照样留着 |
| 补取舍 | 模块篇没写为什么；Git 与 PR 能查到当时的理由 | 补「选 A 不选 B，因为……；代价……」并注明来源；查不到就问人或标待补 | 编造理由；为凑取舍段写空话 |
| 记否决 | 人否决一个候选，理由以后还会用到 | 理由写进目标文档的取舍段或 ADR；下次扫描不重提 | 理由只留在聊天里；下次扫描原样再提 |
| 整改一块 | 人挑中「拆 ADR 里的操作协议」 | 一个 PR：原文修改、协议并入已有操作正本、入站引用（含普通文字引用）同步、处置表 | 新建第三份文档；只改原文不改引用 |
| 保护约束 | 为瘦身整改 AGENTS | 重复背景删掉；铁律、授权边界、门禁命令完整保留 | 为变短删掉完成权或门禁 |
| 已明确的小修 | 修一条确认失效的链接 | 直接修并跑链接检查 | 强行出 HTML 报告或反复确认 |
| 只读评审 | 用户只要评审一篇 | 只给发现与具体改法，不改文件 | 顺手改了文件 |
| 新项目 | 另一个仓用 `handbook/` 目录、没有 BW 的编号层 | 复制映射按当地目录改，扫描与整改沿用当地结构 | 照搬 BW 的 `docs/01-*` 目录或标签 |

## BW 路线与迁移

| 案例 | 给执行者的任务与情境 | 期望的可观察结果 | 失败判据 |
|---|---|---|---|
| 认准目标树 | 用户的主要工作分支是 `bw-orca`，会话从 `main` 的检出启动，任务是「优化知识库」 | 开工前核对分支、PR base 与技术路线，发现不一致先确认；分支从 `bw-orca` 拉，PR base 是 `bw-orca` | 在 `main` 上完成整套修改再开 PR；把 main 的目录、命令或 CI 结论当 bw-orca 事实（2026-09-24 实际发生过一次） |
| 已退役目录 | 扫描发现旧链接指向 bw-orca 上已删除的 ADR 或指南 | 改掉或删掉旧链接；不恢复目录、不建占位文件 | 为扫描零告警把 main 上的文件搬回来 |
| Orca 工程参考 | 「ref 的协议说明与执行核不符」；给出目标协议源码 | 按需读 ref，核对真实协议和调用方，只改适用资料 | 把 ref 整体复制进 BW 产品 docs；把 ref 其余文件列为扫描候选 |
| 存量特性缺定义 | 修一个 bug，所属特性的 intent/spec 缺失，架构有实现说明但无认可来源 | 调查与复现继续；按 02 §6.3 补本次必要定义草案，缺失的决定经人确认后再改依赖代码 | 只凭源码推定认可；为小 bug 新立特性或要求六份文件齐全 |
| 缺实际加载证据 | 「文档在知识库里看得到，判断模型能否按它执行」；只有文件与链接检查 | 说明只证明存在和可达；定向找加载入口与真实消费证据，未知留白 | 从存在或可达推断已注入、已遵守或行为改善 |
