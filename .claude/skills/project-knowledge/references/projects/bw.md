# BW 项目适配

> 30 秒导读：这里是 BW 的路径与边界映射，不是另一份开发规矩。每次执行读取目标工作树当前原件。其他项目跳过本篇，按知识模型映射自己的资料。

## 试点状态与范围

本包是仓内试用方法。采用它不代表全部文档已按候选规范整改、指标已有读数或桌面已经注入此方法。起手 Skill 负责开发任务路由；本 Skill 负责知识治理。

每轮先读目标基线的 AGENTS、文档索引与 Git/PR 状态。顶层整改的历史来源可查 [PR #211](https://github.com/forcegravity1989/builder-workbench/pull/211)，其状态不能由此文预设。DESIGN/CHANGELOG 若仍存在则按实际职责处理；已删除则不因模板或扫描候选路径而恢复。交付命令从目标 AGENTS 和 `.bw/release/verify/README.md` 读取。

用户已明确：AGENTS 等顶层文档和 docs 均可逐篇整改，规范覆盖的存量需要同步清债；不因旧文件说“过时不删”而无限保留重复债务。按用户指定目标实际执行，保留代码/产品约束和未决产品选择的边界。

当前产品知识、BW 自己的开发方法、对外 standard 分开。当前治理的是 BW 项目资料；本 Skill 是用于治理的方法。BW 知识库屏只是一个读取展示能力，不等于本 Skill 已接入桌面。

## 本次治理的呈现与判断顺序

用户希望先看到顶层文件是否适合、职责/格式的现行依据与目标样例、从 AGENTS 到规范的读取链，再通过同一份 HTML 报告对齐大方向，随后实际整改并用 PR 审核。此约定适用于职责和格式尚未对齐的治理块；已定的确定性修复可继续，不需重做审批。

本包 document-contracts 提供每类写法；其中尚未被项目采纳的部分仍是候选。Skill 入库与文档格式被全仓采用是两件事。报告已认可规则、候选写法与实际正文的差异，不能说无规范，也不能让模板覆盖当前原则。

## 首块建议与联动

按 [会话运作](../session-workflow.md) 读取真实交付并安排下一块；优先试用已有顶层规则、梳理特性、走通一个完整特性，不机械重跑已完成的整改。

AGENTS 首轮先对齐职责并清理实际旧债：必要约束和命令留清楚，详细目录指向 docs/README，任务必读的关键规范保留直链；联动 CLAUDE 和 workbench-start 的实际冲突。后续改变正本、入口或命令的轮次负责同步微调它。任何任务都可按授权完成整改与方法维护；通过仓内 Skill 版本、真实 PR/commit 和反馈交接，不依赖最初的设计会话，也不要求每轮复制一份 Skill。

每块同时处理：原文及旧段落去向、引用与加载、必要模板/检查、真实验证及缺口。模板内容应写回已有 spec/任务；不用为每个 bug 新建 intent/spec/metrics/test/report 五份 MD。

正在进行的任务可能使用各自固定版本；改治理方法时不覆盖其未提交文件。需要对齐时比较版本并在本任务范围内整合，主检出不作为默认试验落点。开发命令、门禁和提交权限以目标仓当前 AGENTS、CI 与用户授权核实。

## 特性候选来源提醒

先前报告从旅程与静态实现归纳了 12 项候选：接入/约定、版本目标与周一屏、Issue 进度、人机开工与续接、定时执行、发布出包、指标健康、群通知、环境与资产配置、知识查阅、帮助反馈、知识与方法进化。

这是待核定清单，不是已认可的 12 个特性，也不是现有 12 份 spec；勿自动创建 12 套文档或预填 12 组 KPI。需要完整盘点时逐项核对用户价值与事实，并标明遗漏/合并可能。

## 周一屏边界

- 交互原型是用户提供的 [外部 artifact](https://claude.ai/code/artifact/5664c6f6-0bad-4897-98af-fcdae70e15c8)，并未因链接出现就合入仓库。
- 设计侧产出可复用的 Skill、HTML 和数据模板；首用侧要交付 BW v0.4 的真实结果，再定义特性价值衡量、验收与 E2E。
- 复用原任务与已认可方案：Orca/自动化、HTML 资源方案；知识治理不另行建设 BW 原生高保真页面。
- 当前原型/模板、真实周结果、指标读数、测试执行是不同证据。具体设计和归档位置读取原开发任务当前决定，本适配不抢做设计正本。

## BW 周一屏示例（候选写法，不是已认可指标）

用户结果：从实际项目资料形成可确认、可追溯的一周承诺，后续可以检视完成情况。

| 对象 | 初始候选 | 验证边界 |
|---|---|---|
| 引领假设 | 计划冻结时，责任人、验收点、证据入口都明确的承诺项 / 冻结承诺项总数 | 还需审查“明确”的语义；只是价值假设 |
| 滞后结果 | 截止时已由人验收的原始承诺项 / 冻结承诺项总数 | 新增、取消与变更单列，不删分母；真实结果待观察 |
| 约束观察 | 准备耗时、澄清/返工、错误引用、维护成本 | 不以字段填满掩盖额外负担 |
| 验收 | 数据与 HTML 对应、缺数 Unknown、修订可追溯、重开能读回 | 外部原型和模板不等于真实 v0.4 结果 |
| 场景 | 用真实版本资料生成结果，修订一项、确认归档、重开核对 | 用例设计、可执行脚本、真实运行分别记录 |

设计团队交付的方法/HTML/数据模板，与首用者交付的 BW 本周结果是两类产物。复用原开发任务成果，不在知识治理中另造一套周一屏设计。
