# 知识模型与项目映射

> 30 秒导读：按内容回答的问题分类，再映射已有目录。分类不等于新建文件；一个文件可以承载紧密相关的几类内容，但每项事实只有一个维护位置。

## 三个范围

| 范围 | 核心内容 | 关系 |
|---|---|---|
| 项目知识 | 用户与价值、行为、架构、指南、术语、指标、验收、项目约束 | 开发与维护的依据；代码是实现证据，设计目标并不自动成为实现事实 |
| 项目开发方法 | 起手、构建、知识治理、交付格式、检查与 CI | 读取知识、执行工作、回写受影响知识；本 Skill 属于这里 |
| 共享方法 | 去除项目事实后的通用方法、模板、工具、评估和适配接口 | 从真实实践提炼；在另一个项目验证，不要求搬运原项目目录 |

AGENTS 是项目自己的开发约定，连接知识与方法。将它纳入治理不等于把所有开发方法塞进它。BW 的 standard 是产品分发资产，不能因本地知识整改自动改变共享行为。

这是通用关系，不覆盖项目既有分类。BW 的产品知识、Orca 工程参考、本仓开发方法、产品分发资产四类落点见 [BW 适配](projects/bw.md)；将知识库 UI 改成这些分类不等于文档职责、加载链或模型行为已经治理。

## 八类内容资产

这是本 Skill 的工作分类，来源是项目需求与业界机制的组合，不是某个框架的认证标准。

| 类别 | 回答的问题 | 常见载体 |
|---|---|---|
| 入口与词表 | 从哪读、什么词是什么意思 | README、AGENTS、CLAUDE、CONTEXT、文档索引 |
| 原则与产品目标 | 为什么做、哪些约束和价值选择成立 | 原则、产品 brief、PR/FAQ |
| 特性与行为 | 谁能完成什么、认可的行为是什么 | intent、spec、需求与验收章节 |
| 架构与决策 | 怎样协作实现、为什么选这条路 | architecture、模块说明、ADR、视觉系统 |
| 使用与运维 | 用户/操作者怎样完成任务 | 教程、操作指南、故障处理、参考说明 |
| 衡量与验证 | 值不值得、符合要求吗、证据到哪层 | 指标定义、采集器、用例、运行证据 |
| 执行方法 | 怎么可靠修改和交付 | Skill、system prompt、references、Issue/PR 模板 |
| 变更与历史 | 这次改了什么、过去为何这样做 | Issue、PR、变更计划、CHANGELOG、归档记录 |

HTML、JSON、TOML、脚本也有职责。已有机读协议保持其格式；展示层和生成索引从源生成。不要为了统一 Markdown 增加一份手工副本。

## 首次用于项目

1. 从既有入口发现约束与目录；用户限定文件时只追踪必要关联，不扩大成全库普查。
2. 将实际路径映射到上表。记录一处内容为何是现行依据、适用范围、冲突和缺口。优先放现有索引或本任务；不强制新增配置文件。
3. 区分“缺内容”和“缺独立文件”：已有 spec 的指标段足够时不再建 metrics.md。
4. 为本轮选定范围明确去向与最低格式，整改正文和存量。全库仍未覆盖部分进入原任务的后续队列。
5. 开发入口引用项目正本；下次真实任务检验能否正确找到和使用它。

项目映射可用：

| 内容职责 | 现有正本/章节 | 实际读取者 | 当前依据/状态 | 本轮处置 |
|---|---|---|---|---|
| 按实际项目填写 | 可定位链接 | 人/模型/工具及入口 | 已认可/候选/历史；证据来源 | 改原件/缺失待补/不在范围 |

这是落点映射，不另维护一套业务状态。可由扫描器生成的信息不要手工重复录入。

## 特性、模块和 Issue

- **特性**：用户获得的持续能力或信息价值。按用户目标归纳，再核对文档、实际实现与使用证据。目录数、页面数、crate 数不能当特性数。
- **模块**：实现责任与协作边界。一项特性可以跨模块，一个模块支持多项特性。
- **Issue**：一次有限变化，可以修复一个特性的部分行为，也可以涉及多个特性。基础设施任务可以直接关联工程约束，不硬造用户价值。
- **验收点**：可观察的行为判断。同一特性有多个验收点；一个用例可以覆盖多个点。
- **指标**：对价值或其引领假设的观测。测试通过率不自动成为用户价值指标。

稳定关联优先使用已有 ID、文档链接和章节锚点；需要扩展时先检查重名。对本轮没有必要的全局编号系统不提前建设。

## 两种状态不能混用

文档“候选 / 已认可 / 历史”描述知识适用性；任务“进行中 / 已验收”等来自任务系统；测试“未运行 / 通过 / 失败”来自执行记录。三个轴分别引用来源，不能由一个 STATUS 字段推出全部结论。

同理，特性边界已定、指标定义已认可、采集器可运行、读数已获得、价值改善有证据，是五件不同的事。
