# 面向模型指令的可选审查

> 30 秒导读：AGENTS、Skill、规则和提示词需要检查的不只是路径，还包括指令目的、加载方式与真实行为。这里借鉴 Prompt Audit 的证据和修订纪律；它是知识治理的一项专项审查，不取代文档职责设计。

## 何时使用

本轮涉及模型会读的指令、提示词或工具描述，且出现冲突、重复误解、无效约束或加载/执行偏差时使用。普通 CHANGELOG 历史整理、产品指标设计不自动触发整个提示词审计。

无需安装 claude-api，也不要求调用 Claude。模型相关结论以实际目标模型、宿主和可核验资料为准；未知就保留未知。不能把 Claude 特定代际或 API 的结论直接推广到其他模型。

## 审查方法

1. **找实际指令面。** 根据本轮范围追踪文件、拼接/引用入口、实际加载与消费者。文件存在、可达、被读、被正确使用分别记录。
2. **问指令为何存在。** 必要时查 Git 和原问题：保护什么业务约束、应对什么已知偏差、是否有更明确的正本。旧、长、重复或命令语气都不是自动删除理由。
3. **给有依据的动作。** 将真实缺陷与编辑偏好分开，指出具体位置、证据、影响、置信度和建议的保留/改写/迁移/删除/补充。缺少依据的模型效果推断只列待验证。
4. **形成可审查修订。** 对已能判断的问题给明确替换或 diff；正常执行顺序、产品边界、必要上下文仍有用途就保留。移除规则时检查引用、解析器、测试及实际依赖，不能留半截机制。
5. **验证行为假设。** 对争议的指令改动用同类输入对照观察，优先复用真实失败；需要时在隔离样例上复验。观察到回退就重审改法。模型自称不需要指令、静态字数减少、扫描无错误，都不是改善证据。

发现记录可嵌在本轮报告或反馈，不另强制建文档：

| 位置/来源 | 指令用途与约束 | 事实或行为证据 | 影响与置信度 | 建议变化/保留理由 | 验证及未观察项 |
|---|---|---|---|---|---|

清洁且有效的指令可以不改。知识职责调整可以因重复维护成本进行合并，但应如实称为治理选择，不能包装成已证明的模型性能优化。

## 采用与不采用

- 采用上游的来源追查、必要内容保护、具体修订建议、依赖同步和行为复验思想，以本包自己的文本实现。
- 不复制上游完整技能、模式表或 Claude API 配置；模型特定建议每次查实际适用证据。
- 不引入单纯为分数或 token 数优化的任务；成本观察有测量依据才报告。
- 不以“现代模型会规划”为由删掉人需要看见的治理阶段。阶段与交付解释是协作约定；内部工具调用顺序由执行者判断。
