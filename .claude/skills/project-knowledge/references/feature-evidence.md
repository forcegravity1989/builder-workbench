# 特性、指标、验收、用例与证据

> 30 秒导读：用两条关系判断价值与正确性。特性关联价值指标；特性行为关联验收点、用例与执行证据。两条关系共享特性，不强迫每个指标对应一个 E2E。

## 先确认特性边界

按 [知识模型](knowledge-model.md) 的“特性、模块和 Issue”定义核对边界，记录规格、实现与真实用例来源；边界不清先标候选。本篇只展开指标和验收证据关系。

总表只维护入口，可采用：

| 特性/用户结果 | 行为正本及适用状态 | 指标定义/采集入口 | 验收/用例/证据 | 缺口来源 |
|---|---|---|---|---|
| 实际项目候选 | 当前依据或缺失 | 链接，不复制公式 | 分别链接，不用单一完成勾选 | 原任务中的未决项 |

一个 Issue 可引用一个特性的具体验收点，或关联多项特性；小 bug 复用原行为。新价值、重大语义或缺关键决定时，先明确范围再拆可执行变化；按风险验证，不以改动行数决定流程。

## 指标的内容契约

| 字段 | 要回答什么 |
|---|---|
| 目标与角色 | 测量哪个用户结果；是滞后结果还是可影响它的引领假设 |
| 关系与理由 | 引领行为为何可能改善结果；哪些因素会干扰，不能宣称已证明因果 |
| 口径 | 分子、分母、单位、去重、样本总体与排除项 |
| 观察时间 | 事件时间/采集时间、窗口、时区和迟到数据处理 |
| 来源 | 具体文件/接口/事件/人工记录；谁有权提供，能否独立读回 |
| 采集 | 现有入口或所需新增脚本；失败/缺数怎样表达 |
| 基线与目标 | 已测读数及时间，或未知；目标的认可来源，候选不能冒充承诺 |
| 防失真 | 约束指标或审查：是否缩分母、挑容易任务、牺牲质量、增加人工成本 |

先定义可解释的结果，再找引领假设。暂时没有可信引领指标就列待验证假设；不得拿 MD 数、提交数、任务关闭数凑齐。分母为零/数据不足记不适用或未知，说明原因。人工采集可先试用，明确成本与误差。

正式配置沿用项目协议；字段不支持时先将候选口径放在特性/任务，再决定是否扩协议。口径只有一个维护位置，特性总表链接它。采集脚本算对与指标解释价值分别验证。

## 从行为到 E2E

```markdown
### 验收点：一个具体可观察的要求
前提/输入：...
操作：...
预期结果与失败行为：...
不允许的结果：...
用例：现有标识或文件锚点
执行入口与环境：...
独立读回：真实数据源/输出/界面
本次运行：版本、时间、通过/失败/未执行、不适用原因、证据链接
```

- 用明确例子暴露规则与未决问题；已有决定充分时直接设计验证，不重复开澄清会。
- 按影响选成功、缺数、失败、重试、重开、权限等场景；不是每个小修都跑全矩阵。
- 自动用例要能识别违背要求的结果。仅启动成功/渲染成功通常不能证明保存、完成或价值链成立。
- 单元、静态检查、集成、真实桌面、模型会话和真实远端分别标证据层。不把替身接口称为真实用户 E2E。
- 复用旧证据时说明源码、用例、配置与环境仍适用的依据。语义影响不明则复验，不能只按年龄判过期。

## 项目样例

BW 的路线、历史证据与当前验证边界见 [BW 适配](projects/bw.md)；六环执行接 [交付与证据约定](../../workbench-start/references/delivery-contract.md)。目标、实现、已验证与历史分列，不能把旧平台验收复制成新平台通过。其他项目按自己的目标、数据和环境形成样例，不继承 BW 的目录或命令。

## 内容级统计

每次统计标明扫描范围、适用集合、时间/版本、未映射项及排除理由。没有确认总体就报数量与缺口，不编覆盖百分比。

| 观察 | 分子 / 分母或记录方式 | 不能证明什么 |
|---|---|---|
| 定义完整性 | 满足本轮采用内容契约的对象 / 已纳入对象，未映射单列 | 内容语义正确、全项目无遗漏 |
| 验收设计覆盖 | 有适用用例定义的验收点 / 本轮已认可应验点 | 用例已运行 |
| 证据覆盖 | 有适用版本与环境下通过证据的验收点 / 本轮应验点 | 长期用户价值 |
| 指标可采集 | 窗口内取得有效读数的指标 / 本轮应采指标 | 口径有价值、因果成立 |
| 清债 | 本轮重复/冲突/失效入口的处理量与剩余量 | 字数越少越好 |
| 反哺 | 修订后同类错误 / 后续适用任务数，同时记录维护与介入成本 | 没有后续任务时不能记零复发 |

本包附文件链接检查器及只读全景扫描器。后者能统计已映射的资产、段落和指定验收表行；上述语义覆盖、有效读数和行为改善仍需要按项目结构接入真实证据或人工审查，不能由结构计数推算。
