# 项目知识库治理

> 30 秒导读：先弄清一篇文档的职责，再改原文、清存量、接引用、验证。这个包提供可携带的方法；项目已认可的规范决定当地正本。每次整改一块，维护方法自身也接受同样的审查。

## 新任务怎么用

用户说“用 project-knowledge 盘点顶层几个 MD”或“整改 AGENTS”即可。工作任务自行读取本包相关参考与目标项目现状，说明阶段，然后执行。无需回到最初的设计会话；整改、验证、交接和方法反哺可以在同一任务完成，也可以用 PR/commit 交给其他任务。方法知识在本包；项目事实在目标仓；历史执行和认可证据在真实 Git/PR/运行产物中，不复制成第二份规则。

## 治理对象和边界

- 治理项目自己的产品知识、实现知识、使用知识和本仓协作约定。AGENTS、词表、特性、架构、指标与证据都在可能范围内。
- 本 Skill 属于开发方法层，用来建立与维护这些知识；不是产品的知识库浏览功能，也不是自动重构代码的入口。
- 共享分发是第三层：先在项目中使用和反哺，再抽出通用部分。无需等全库完美才开始开发；每个任务用到的知识和开发方法交替成熟。
- Skill 的目录只用来定位支撑文件；业务仓根以用户选定的仓库为准。不能因为从别的工作树加载此 Skill，就把业务工作切过去。
- 用户请求逐篇整改时，完成授权范围内的实际修改与验证；仅请求评审时只给发现。已有授权继续有效，不重复要求批准同一范围。

## 自然语言起手与人可见的流程

用户说“盘点顶层几个 MD”即可开始，不要求追加规范化提示词。自行识别范围、已有决定与适用契约，先说明当前阶段、随后交付和需人判断的内容。多文档/结构治理先读 [评审与对齐流程](references/review-workflow.md) 和对应 [文档契约](references/document-contracts.md)：现行规范与 Skill 候选写法对照 → 默认 HTML 展示目标职责/格式及取舍 → 落实已认可决定 → 验证交付和反哺。扫描仅为辅助证据。

用户明确只读评审时只读；依据与授权已充分的确定性小修直接做。流程中的判断点用于解决真实未决事项，不重复索取已经给出的决定。

## 一次整改怎么完成

1. **确定范围。** 读目标仓的实际 AGENTS/上级规则、文档入口、目标篇及其直接依据；查工作树状态和并行修改。用已有任务记录本块主文档、关联文件及排除项，并让用户看见当前阶段和下一步。整改一个文件不意味着每次全仓扫描。
2. **找事实与职责。** 按知识模型映射已有内容，区分目标、认可规则、当前实现和运行证据。读入站引用及真实加载方；代码存在不等于行为已验收。先展示现行规则、Skill 类型契约、实际正文和拟采用格式的对照；有真实未决方向时按评审流程形成可判断的方案，已认可事项直接复用。
3. **实际修改。** 按已有授权和本轮已认可的职责/格式修正文，同时给原有段落明确去向：保留、合并、迁移、删除、归档。优先修原件，必要内容优先落已有正本。迁移要清旧副本、改引用；归档只保留有追溯价值的事实。
4. **补本块设施。** 规范写回该项目的规则正本；本 Skill 提供写法和执行方法。项目规则成熟后，试验 references 中的重复规则改成引用。能稳定识别的错误再加入检查；无需先建完全部模板、schema 或 ID 系统。
5. **验证。** 检查改动、入站链接、适用约束和读取路径；涉及行为/命令的内容按影响实际验证。明确未执行项。用下面的只读工具辅助查本地文件链接；它不判断内容正确性。
6. **交付和反馈。** 提供实际 diff、旧内容去向、验证结果、剩余债务。每轮必须复盘方法：有真实缺陷则修订并复验；无新缺陷则记录无需修订及依据。本块未解决的迁移债不能标成完成；其他尚未排到的文档保留明确队列。多人/跨会话推进按会话运作保留交接记录，合入状态由真实 Git/PR 读回。

## 交付出口

在原任务/PR 中用几行或一张表记录，不另建必填台账：

| 原件/原段 | 处置及理由 | 现行去向 | 检查与证据 | 剩余问题 |
|---|---|---|---|---|
| 本次实际处理的位置 | 保留/合并/迁移/删除/归档 | 唯一正本或历史来源 | 实际执行结果与限制 | 无则明确，无依据不编 |

完成条件：正文符合本轮认可职责；覆盖到的旧债已处理；必要引用/加载已同步；适用验证有结果；下次任务知道改哪份。涉及职责/入口重构时，用一个实际维护任务说明预期改善，并区分静态成立与后续任务已观察到的效果，见评审流程。总字数只是成本观察，不能通过删掉必要约束提高“瘦身率”。

## 本地辅助检查

需要 Node.js；没有 Node 时可以完成文档整改并用现有工具检查链接，明确脚本未运行。

```text
node <本Skill路径>/scripts/check-links.mjs --root <目标仓绝对路径> --file AGENTS.md --file CLAUDE.md
```

只读、无网络、无自动修复；只检查显式选定的 Markdown 和 `@文件` 导入。JSON 输出含来源行、文件指纹和未检查项。退出码：0 没发现文件路径错误；1 发现缺文件/越界引用；2 参数或读取失败。0 不代表知识合格；标题锚点、外链、HTML、复杂 Markdown 仍需独立检查。范围和测试见 [维护方法](references/maintenance.md)。

## 方法自身的约束

采用新规范时同步整改它实际覆盖的存量。不要只新增 Skill、模板或历史横幅而留下两份现行说法。保留仍有价值的规则、授权边界与真实证据；不凭文本更短宣称质量更高。

本包是 `0.3.2-pilot`，作为仓内试用方法交付；实际验证范围以对应 PR/运行记录为准。规则来源、BW 适配与本地组合见来源参考。使用后根据真实偏差更新，验证细节见固定 [评估案例](evals/cases.md)。安装、被引用、被读取、行为正确分别取证；只完成静态校验不能宣称模型行为改善。
