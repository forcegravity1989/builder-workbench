# 收集与交接参考

> 供提单助手在补取材料、判断分流和准备交接时读取。维护现场取材方法和示例。产品诊断入口或数据边界变更时同步核对。

## 取材顺序

- **用户现场**。用已收到的原话、批注、截图或录屏标出具体入口和动作。引用原材料可读位置或已授权的附件标识。附件不可访问时记下文件名和来源，按需补取。
- **事实范围**。对本机事件可从已开放的界面、日志目录或原生诊断能力取事实。版本、平台、时间段、运行位置或关联任务只有能核验且影响理解时才采集。跨机由原用户提供、已有材料带入或经授权读取，分别标注。
- **诊断类型**。操作不符合预期时优先用最短操作记录。卡顿、失败或状态异常时考虑相关日志或已存在的 trace。崩溃时考虑时间点、版本和可用崩溃记录。工具能力与参数由当前宿主帮助或现有执行接口核实，现场无能力则保留缺项。
- **外部引用**。先确认接手者的读取权限与材料是否需要脱敏。正文写业务可核对的事实，避免附不相关日志、令牌、环境变量、另一项目的材料或整包会话记录。

### 本机材料入口

| 现场                       | 可用入口和取法                                                                                                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 有原反馈                   | 先读原报告文字、版本环境与附件，沿原动作和发生时间对齐。材料来自外部时标清来源，省掉重复询问。                                                                                                                                              |
| 有操作失败、卡顿或启动异常 | 从设置的隐私诊断区域找「创建诊断文件」。先在本机查看诊断预览，围绕问题时间与动作找相关记录。经授权可沿界面发送诊断文件，提单只引用必要的脱敏片段或接手者获授权可读的材料。功能关闭或预览为空时仍可以只提交文字反馈。                        |
| 已知该实例的数据目录       | 只读对应实例的 userData 下 `logs/main.trace.ndjson`（存在时也可读轮转文件）和 `logs/daemon.log`。前者看主进程操作相关 trace，后者看 daemon 生命周期或恢复。按实际 profile、事发时间和线索筛选。安装版、开发版及其他宿主的数据目录各自核实。 |
| 崩溃后已重开               | 从「帮助」进入崩溃报告，查看可用记录、版本和发生时点。能读到崩溃提示、进程信息或报告引用时只取与当前问题相关的部分。没有记录时写用户报告的崩溃表现与时间。                                                                                  |
| 只看到 CLI                 | 当前已知 `diagnostics memory` 读取内存快照。只在内存相关问题且宿主帮助确认该命令可用时使用。收集 trace、创建诊断文件和提交报告走已核实的界面或实际工具接口。                                                                                |

入口或数据目录若与现场版本不同，记录入口不可用并继续整理已有材料。采集本机材料与向外部发送分别按各自授权处理。

## 分流与取舍

- “点清除后仍显示筛选结果”有已认可的清除行为时作为缺陷记录。保留版本、入口、动作与列表实际变化。尚不知道发生概率时写“本次观察发生，频率未知”。
- “希望切回任务屏保留上次筛选”是小诉求，写期望和为什么有价值。没有认可依据时保留为待评审，不向用户承诺行为改动。
- “界面不好用，看一下”尽量先结合批注定位对象。仍无法知道问题时，请用户明确一次操作或期望结果即可。用户反馈并不要求解释实现。
- 发现疑似重复时，对照用户受影响动作和期望结果。确认同一问题则沿原单补证据，保留原有决定。两个列表的同类症状仅作关联，等待进一步判断。

## 反哺信息

保留原人输入的可核对来源、关联 Issue 或 PR、以及需要维护者判断的重复摩擦。已有脚本能读取的工作流从目标仓 workbench-start 发起。没有 PR 或现有脚本不支持当前平台、模型或评论目标时，当前会话保留候选与来源，不构造指标或平行脚本。
