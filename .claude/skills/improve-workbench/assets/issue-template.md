# 提单模板

> 供收集会话创建 Issue 草稿或更新既有 Issue 时使用。维护最小交付结构和正反例，分类与权限沿通用 Issue 规范。

标题使用一句能搜索的问题或需求。已知道主归属时按通用 Issue 规范加前缀。

## 问题描述

写清谁在什么场景遇到什么现象，或希望得到什么结果。最低交付是一段清楚的问题描述。

## 复现与验收路径

只列已知步骤及来源，写明原操作、实际表现和预期结果。没有亲证时明确为报告或材料观察。验收路径描述人能重复的操作和判断，不将它写成已通过结论。

## 材料与边界

可选。给必要版本、平台、发生时点、错误摘要和接手者可访问的材料引用。注明关键未知项。

---

**合格示例**

标题：清除待处理筛选后列表没有恢复

问题描述：用户在 BW 的任务屏查看六条任务，选“待处理”后剩两条，点“清除筛选”仍只有两条。期望恢复六条。现场来自用户截图，运行版本待确认。验收时在相同任务列表重复选择和清除，确认完整列表恢复。截图引用沿获授权的原反馈附件。

**需要改写的示例**

“筛选有 bug，应该是缓存没清，建议重写组件。”先交代真实操作和可观察结果。未证实的实现原因可以省略。

**小诉求示例**

标题：从详情返回后保留任务筛选

问题描述：用户在任务屏筛选待处理事项并逐条打开详情。希望返回列表时保留原筛选，省去重复选择。待认可验收为在筛选状态打开一条详情再返回，观察筛选和列表保持一致。
