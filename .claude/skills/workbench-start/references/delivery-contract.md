## 一个任务的最小关系

BW 的六环与带入三问以目标分支 [原则 02](../../../../docs/01-principles/02-working-backwards.md) 为正本。对迁移先判断旧用户目标是否仍成立，再处理变化的旅程、平台边界与验收；不把“迁移”当默认照抄或全部重新立项。

| 执行环节 | 本任务怎样接上 | 证据限制 |
|---|---|---|
| intent / spec | 复用仍成立的认可来源；把新取舍和可判断验收落到原件，按项目 gate 处理 | 旧平台批准不自动覆盖新交互承诺；方向明确不等于制品已认可 |
| 实现设计 | 在目标 architecture 定位用例、能力、Electron 数据流，按需读模块/ref；实现后同步取舍 | 设计或源码只说明目标/实现，不说明运行正确 |
| TDD | 维护受影响的已有单测；新增单测只立两类看护——核心算法函数、与 E2E 强相关的数据协议（规范与单特性上限见目标仓环 4） | UI/文案/装配默认不新增单测；文档修改和低风险文字调整不强造测试；存量随特性大改盘点裁并 |
| 验收点 E2E | 当前 spec 与实际用例双向可查，按受影响判据跑当前平台链路并独立读回；特性初期先注册核心验收点，其余稳定后专项回补 | 有脚本或单测不等于 E2E 已通过；未注册验收点与未迁用例在 STATUS 记缺口 |
| 用户旅程 E2E | 按原则在真实 Electron 壳走完整用户目标，标清模型、文件/Git、远端参与范围 | 渲染、HTML 原型、模拟接口或旧 Rust/WebView2 不替代真实旅程 |

实现门禁与验证 Review 随 PR：推前按 SKILL §6 的推 PR 前 SOP 登记 TODO 并逐步完成，其中 subagent 全方位检视覆盖目标仓横切站 B 四维（顶层文档、特性文档资产与老资产清理、实现代码与老方案清除、测试资产配比），发现项同交付修正并记入 PR。人的验收/合入与发布授权另行核对。复用实际 `tests/e2e/`、`tests/playwright.config.ts`、Vitest 和 CI 入口，精确命令从目标 AGENTS 与受影响用例取得，不复制另一分支的 suite、深链或 verify 协议。STATUS 按原则记录六环状态、证据和债务，不能将文档齐全涂成行为通过。

开发触及已有独立特性时，按原则 02 §6.3 核对 intent/spec 及本次行为、验收与旅程依据。缺失或失效的必要定义先落草案；缺失、失效或未认可的决定经人 gate 后再改依赖代码。已有且仍成立的认可直接复用，整理为可定位来源，不重复审批。既有承载缺失时按当前目标补所需内容，不自动恢复整套旧文档；其余实现/验证债留在 STATUS 或 PR。

普通已知 bug 在必要依据明确时直接修复，不新立“bug 特性”或机械补六份文件。补定义期间仍可调查、复现与准备验证；缺决定只暂停依赖动作，不偷定产品行为。

```text
已有特性/约束 → 本次行为增量 → 验收点 → 场景/执行入口 → 本次运行证据
新价值（适用时）→ 引领假设及滞后结果 → 口径/来源/采集 → 观察结果
```

复用项目现有标识或章节链接，不先建 ID 系统。在当前 Issue、spec 或任务计划写清用户结果、范围、所属特性/约束、行为增量和证据入口，不复制第二份现行规格；归属未定记候选，不假装特性全集已确定。

| 验收点 | 场景与可观察预期 | 执行及独立读回 | 本次证据 |
|---|---|---|---|
| 本次改变的具体行为 | 有效输入及风险相关的失败/重开 | 用例、真实环境与数据来源 | 版本、结果、证据链接及限制 |

缺数显示 Unknown 的验收，应以缺数输入检查展示，再补真实读数核对变化；页面渲染成功不证明缺数行为正确。此例不要求给所有任务增加图表测试。

正式指标定义或版本目标的写入按已有授权及协议执行。候选口径不是已认可目标；基线未知不造数。源码、用例、环境改变后核对证据有效性；只写出用例应报告未执行。

新增用户价值或明确要求“特性→指标→E2E”时再展开衡量；小修复用已有口径，不为填表造指标，不让等待滞后结果阻塞功能验收。

## 运行证据怎样报告

记录源码/产物版本、用例/方法版本、环境、命令、结果和证据，说明修改后旧报告是否仍适用。静态/脚本、单元/集成、真实 Electron、实际 Orca 模型会话、Git/文件/远端读回分别说明覆盖；历史 Rust/WebView2、HTML 原型、截图或模拟不能替代当前真实依赖的验收。

代码可运行、验收通过、用户认可、价值已证实分别陈述。未实现、未运行和未知不记通过；合入、完成与发布仍按人的授权。
