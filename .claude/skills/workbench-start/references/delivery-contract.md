# 开发任务的交付与证据

> 30 秒导读：实现、相关知识与可复核证据一起交付。内容定义与知识治理共用；任务大小决定展开程度，不给每个 bug 强加全部表格。

## 按需读取共用定义

| 问题 | 参考 | 用法 |
|---|---|---|
| 文档承载什么、怎么写 | [文档契约](../../project-knowledge/references/document-contracts.md) | 只读受影响类型；目标项目已认可规则优先，候选需明确采用 |
| 特性、指标、验收、用例怎么关联 | [特性与证据](../../project-knowledge/references/feature-evidence.md) | 新价值展开指标；已有行为修复复用已有衡量 |
| 清旧债和反哺 | [维护方法](../../project-knowledge/references/maintenance.md) | 在原任务/PR 记录真实反馈，修正确归属 |
| 交给新任务 | [会话运作](../../project-knowledge/references/session-workflow.md) | 交接版本、证据、已认可决定及下一动作 |
| 业界借鉴及边界 | [来源](../../project-knowledge/references/sources.md) | 解释方法来由，不要求联网通读上游才开发 |

## 一个任务的最小关系

```text
已有特性/约束 → 本次行为增量 → 验收点 → 场景/执行入口 → 本次运行证据
新价值（适用时）→ 引领假设及滞后结果 → 口径/来源/采集 → 观察结果
```

复用项目现有标识或章节链接，不先建 ID 系统。在当前 Issue、spec 或任务计划用几行讲清，不复制第二份现行规格。

| 验收点 | 场景与可观察预期 | 执行及独立读回 | 本次证据 |
|---|---|---|---|
| 本次改变的具体行为 | 有效输入及风险相关的失败/重开 | 用例、真实环境与数据来源 | 版本、结果、证据链接及限制 |

缺数显示 Unknown 的验收，应以缺数输入检查展示，再补真实读数核对变化；页面渲染成功不证明缺数行为正确。此例不要求给所有任务增加图表测试。

正式指标定义或版本目标的写入按已有授权及协议执行。候选口径不是已认可目标；基线未知不造数。源码、用例、环境改变后核对证据有效性；只写出用例应报告未执行。
