## 决策

1. **出包和发版本是两颗按钮**。`cut_release`（远端 Release / tag + WeLink）本身不改。「出包」发 `PackRelease`：分别拉 pack / e2e，两行弹窗吃 JSONL，不打标签。「发版本」仍只走 `CutRelease`。
2. **任何被管仓同一套入口**。后台在仓根拉起，不交互、不读 stdin。入口**只认一份 `.cmd`**，不再「没有 cmd 再试 ps1」：
   - 出包：`.bw/release/pack/pack.cmd`
   - 验包：`.bw/release/e2e/e2e.cmd`
   - 参数都只有 `--version <号>` `--workdir <仓根绝对路径>`
   出包依赖（`.iss`、装完说明、实现脚本）放 `pack/`；验包用例与驱动放 `e2e/`；跨两棒共享的件放 `.bw/release/` 根，各只有一份：`protocol.ps1`（JSONL 协议：参数解析、版本串规则、协议行读写）与 `install.ps1`（静默装/卸 helper）。
3. **出口是 stdout 上的 JSONL**。进行中 `type=progress`，结束一条 `type=result`。编译器 / ISCC / Playwright 的嘈杂输出进 stderr。退出码：最后一条 `result.ok == true` 才是 0。
4. **出包和 E2E 必须能分开报状态**（两行弹窗各吃一棒）。出包非 0 不拉 E2E。
5. **本仓是样例，安装器正源在 `.bw/release/pack/`**。`packaging/` 整份搬走，不留第二路径。
6. **验包装出来的那份 exe，实点走 WebView CDP**（做法 1）。隔离桌面只负责藏窗。不在流水线里额外调用模型操作界面。不准对交互桌面 `SetForegroundWindow` / `SendInput`。不等用户闲下来。
7. **关窗不杀进程**。出包占着命令队列，停止不走队列，壳直接 `PackCtl::abort`：杀进程树，清这次的 `.bw/release/out/{version}` 与临时装目录。
8. **协议行必须是 UTF-8 字节**。内核按行切，非 UTF-8 当噪声丢掉，不整段读失败。验包 `result.cases` 给人看详情。

## 为什么

- 发版本今天只打 tag、发群，包好不好、壳亮不亮没人守。把出包和验包收成可拉起的命令，按钮才能转圈、打开目录、回显失败、显示成功数 / 总数。
- 采集脚本已经是「仓里写命令、stdout 吐 JSON」。出包 / E2E 同一类事，不另发明内核 API。
- 壳是 WebView2。对 DOM `click` 和人点同一套处理；OS 键鼠会抢走正在用的窗口。wry 写死了 browser args，会盖掉 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，所以验包进程用 `BW_CDP_PORT` 把调试口拼进**现有**那串 args。
- 不为兼容留 `packaging/`：正源只能有一份。

## 后果

- 本仓手工出包改走 `.bw/release/pack/pack.cmd`；`AGENTS.md` 出包段、gitignore、architecture 模块 11 一并改。
- 壳增加一个只认环境变量的缝：`BW_CDP_PORT` 有值才开调试口，没设与今天完全一样。
- 验包要本机 Node + Playwright；缺了报 `missing_tool`，人话写清。
- 下一棒按钮只消费这份 JSONL，不另定一套状态。

## 入口

后台 `CreateProcess`，工作目录 = `--workdir`（项目仓根）。

| | 出包 | E2E |
|---|---|---|
| 入口 | `.bw/release/pack/pack.cmd` | `.bw/release/e2e/e2e.cmd` |
| 参数 | `--version` `--workdir` | 同样两个，**不传**包路径 |

E2E 自己去 `{workdir}/.bw/release/out/{version}/` 找上一棒产物。目录或 setup.exe 不在：功能用例都记「未跑」，`passed=0`，`message` 人话写明候选包缺失原因与出包命令。包能不能静默装，出包相自验一次（不进 E2E `cases`）；验包用例装的是同一份候选包并现场核对哈希，卸载读回**是**用例（`installer-uninstall-clean`，判据=卸载器自己清干净，兜底强删不算过、另记收据）。

版本号原样当目录名与产物文件名。发布链的正式版本号 = **tag 串**（如 `v0.5.0`）：out 目录、产物名、结果记录、tag 与 Release 同一串；计划名（`v0.5`）只是规划粒度，不得充当发布产物身份。版本串只收 `^[A-Za-z0-9][A-Za-z0-9._+-]*\z`（首字符须字母或数字；`\z` 尾锚不放行结尾换行），否则 `bad_args`。

## 出口（JSONL）

stdout **只**打协议行。一行一条，`v` 恒为 `1`。

进行中：

```json
{"v":1,"type":"progress","phase":"probe","message":"在找 ISCC.exe"}
```

`phase` 是给转圈看的短名，`message` 给人看。出包常用：`probe` / `build` / `payload` / `iss` / `verify`。验包适配层只发 `verify`（逐行转发统一验证入口的输出；装/卸是用例内部脚手架，不再是协议相位）。

出包结束，二选一：

```json
{"v":1,"type":"result","ok":true,"artifact_dir":"D:\\proj\\.bw\\release\\out\\v0.5.0","artifact":"BuildersWorkbench-v0.5.0-Setup.exe","sha256":"e3b0c442…共64位hex","revision":"9f2c1a08…共40位hex","dirty":false,"source_unchanged":true,"packed_at":"2026-09-20T15:00:00Z"}
{"v":1,"type":"result","ok":false,"code":"missing_tool","message":"本机没有 Inno Setup（ISCC.exe）"}
```

产物身份字段（2026-09-20 增）：`artifact`=产物文件名（由版本串派生）、`sha256`=该文件的 SHA-256、`revision`=**开工时**构建工作目录的 git HEAD（描述 cargo 实际编译的树）、`dirty`=开工时工作树是否含未提交内容、`source_unchanged`=结束时 HEAD 与工作树状态同开工记录逐字一致、`packed_at`=UTC 时间戳。它们是候选包的身份记录、发布绑定校验的核对来源；`source_unchanged` 非 true 或 `revision`/`dirty` 缺省（非 git 工作目录）即身份不可信——缺省即 unknown，消费方不得当作干净，发布必须拒。既有消费方（`release_ship.rs`）忽略未知字段，协议扩展不要求它同步改。

E2E 结束：

```json
{"v":1,"type":"result","ok":true,"passed":2,"total":2,"cases":[{"name":"settings-restart-roundtrip","ok":true},{"name":"installer-uninstall-clean","ok":true}]}
```

`ok: false` 时同样带 `code` + `message`，并尽量带齐 `passed` / `total` / `cases`（含「未跑」的条，`ok: false`，`message` 写「未跑：上一条失败」）。`result.ok` 为 true 当且仅当 `passed == total` 且 `total > 0`。

失败码（`code`）：

| code | 何时 |
|---|---|
| `bad_args` | 缺参数、版本号不合法 |
| `missing_tool` | 缺 cargo / C 工具链 / ISCC / Node / Playwright / Claude Code（安装器拒装） |
| `build_failed` | `cargo build --release -p app-shell` 非 0 |
| `pack_failed` | 拷 dll、ISCC、或静默装校验/卸载失败 |
| `e2e_failed` | 验包有一条未过（人话写第一条失败的 `message`） |

缺什么工具，写进 `message`，前端原样回显。

## 两行弹窗怎么消费

点「出包」出弹窗两行，后台**分别**拉 pack、再拉 e2e。不打 tag。

| 行 | 吃谁 | 圈 | 行上写什么 |
|---|---|---|---|
| 打包 | pack 的 JSONL | 跑着黄转圈；成功绿；失败红；还没开始灰 | 成功：按钮打开 `artifact_dir`；失败：`message` |
| E2E | e2e 的 JSONL | 打包没结束一直灰、不转；打包成功后黄转圈 | `passed` / `total`；相等黑，不相等红 |

不是等用户离开再跑。验包进程和人正在用的 buddy 是两份。

## 本仓出包样例

`packaging/` **整份迁走，不留兼容层**：

```
.bw/release/
  pack/pack.cmd                 → 唯一出包入口
  pack/BuildersWorkbench.iss
  pack/AFTER-INSTALL-MVP.txt
  out/<version>/                → gitignore，ISCC 输出，产物 BuildersWorkbench-<version>-Setup.exe
```

`pack.cmd` 在仓根跑，顺序：

1. **probe**：cargo、本机 C 工具链（没有 → `missing_tool` +「本机没有 gcc」这类）、`ISCC.exe`（`PATH` + Inno Setup 6/7 默认安装路径）
2. **build**：`cargo build --release -p app-shell`
3. **payload**：`WebView2Loader.dll` 从 `target/release/build/webview2-com-sys-*/out/x64/` 拷到 `target/release/`
4. **iss**：`--version` 喂给 ISCC 的 `AppVersion` 并派生产物名，`OutputDir` = `{workdir}/.bw/release/out/{version}/`
5. **verify**：静默装到 `%TEMP%\bw-pack-verify-{version}`，确认有 `bw-dev.exe`，再卸载并读回。本相判据：`bw-dev.exe` 必须被卸载器清走、目录必须可清空；残留明细逐项记 `progress`（Defender 实时扫描会锁新装文件，Inno 静默卸载跳过且不重试），强删只兜底。E2E 验包用例判据更严：卸载器自己清干净才算过。这是包的校验和清理，不是 E2E。
6. 一条 `result`（产物身份记录或失败）

`.iss` 相对 `.bw/release/pack/` 往上三级取 `target/release/` 与 `crates/app-shell/app.ico`。AppId、装完必做文案、默认安装目录不改。`OutputBaseFilename` = `BuildersWorkbench-{#MyAppVersion}-Setup`：产物名由版本串派生，出包脚本按精确名取件、结果记录同名，出包后不得改名（v0.4 教训：恒名产物被人工改名分发，tag 记录名与实际文件对不上，只能靠 SHA 认定同一文件）。

gitignore：去掉 `packaging/**/output/`，改为 `.bw/release/out/` 与 `.bw/release/e2e/node_modules/`。

## 本仓 E2E 样例（验包，2026-09-20 收敛进统一验证入口）

入口 `.bw/release/e2e/e2e.cmd`，实现是同目录 `run-installer.ps1`：**统一验证入口的薄适配层**——跑 `node .bw/release/verify/verify.mjs --profile installer --version <号>`，把本次 run `result.json` 里 installer 套件的结果转译成本 ADR 的 JSONL 协议行。用例、断言、证据与清理全部由验证入口注册与执行（`e2e/suites/installer.json` + `e2e/installer.ps1`，真壳启动复用 `desktop.ps1`，Playwright 经 CDP 附着）；这一层不实现第二套用例，也不自行判定成功。老驱动线（`e2e/lib.ps1` 三用例 + `drive.mjs`）已删除，不留兼容层。

**验包用例（installer 套件两条；`total` 等于条数）**

| name | 干什么 | 过 |
|---|---|---|
| `settings-restart-roundtrip` | 静默装候选包 → 隔离桌面拉起装出的真壳（CDP）→ 设置屏改工作区根目录并保存 → 杀壳 → 重启 → 界面与 settings.toml 分别读回 | 与源码级 desktop-core 套件同一判据（读回级，不是导航级）；证据带 `setup-identity.json`（被测包现场 SHA-256，`pack-result.json` 在场即逐字比对，不一致直接失败） |
| `installer-uninstall-clean` | 静默卸载 → 条件读回等待（120s 上限；空目录壳连续 10s 提前收敛）→ 目录与残留枚举读回 | 卸载器清走它装的**全部内容**：目录消失最干净；仅剩空目录壳（Windows delete-pending 时序，收据如实记 `emptyDirectoryLeft`）算过；**文件级残留即失败**（兜底强删只清理、不改判据）。`uninstall-readback.json` 分开记 `uninstallerClean`/`emptyDirectoryLeft`/`forcedCleanup`/`residue` |

候选包不在、哈希与出包记录不一致、或静默装失败（含本机没有 Claude Code 被安装器拒装 → `missing_tool` 人话沿用安装器文案），后续用例记「未跑」。本机没有 Node：适配层报 `missing_tool`，不假装点过。

**隔离（硬约束，与源码级 E2E 同一套公用件）**

- 装进 `%TEMP%/bw-installer-e2e-<GUID>/`（本次运行专属，GUID 归属），不是人正在用的那份
- `BW_DB` / `BW_WORKSPACES` / `BW_LOG` / `WEBVIEW2_USER_DATA_FOLDER` 指到该次临时树，不碰日常数据目录
- 壳进程建在隔离桌面；独占的临时 CI 虚拟机可 `BW_E2E_DESKTOP=current` 复用已有桌面
- 调试口由启动器挑空闲本机端口写进 `BW_CDP_PORT`（拼进壳现有 browser args），听 `127.0.0.1`；不准对交互桌面 `SetForegroundWindow` / `SendInput`
- 装卸 helper 唯一一份在 `.bw/release/install.ps1`（出包 verify 相与验包用例共用）；JSONL 协议唯一一份在 `.bw/release/protocol.ps1`

**壳上的缝（只为验包，沿用）**

- `BW_CDP_PORT`：有值则在现有 `with_windows_browser_args` 后追加 `--remote-debugging-port=<port> --remote-allow-origins=*`
- 深链到设置 / 接入时诊断日志打 `[BW_VIEW] settings` / `[BW_VIEW] onboard`（和 `[BW_OPEN]` 同级）

证据（截图、日志、读回件、清理收据）落验证入口本次 run 目录，随 `manifest.json` 全量哈希；不再另设 `{artifact_dir}/e2e-shots/`。加验包站点 = 在 `suites/installer.json` 注册用例，不在适配层换驱动。

**与源码级验证的分工**：`verify --profile pack`（出包前）证明源码构建的行为；`installer`（出包后）证明「用户拿到的安装包」同一行为成立。两层对象不同，不能互相冒充；发布绑定要求两份记录都在场（见发布节）。

## 正式发布（2026-09-20 增：绑定与拒发）

**发布存储正本 = GitHub Releases**（assets + SHA-256 + 验包记录绑定）。WeLink 仅通知；OneBox 会丢、不作正本；CodeHub 是被管项目平台，不承载 BW 自己的包（2026-09-20 user 拍板）。

入口 `.bw/release/publish/publish.mjs`，**只在人明确授权后运行**。授权动作本身不由脚本代替：`--authorized-by` 把授权人与出处写进 tag message、Release 正文与收据，工具、脚本与定时任务不得虚构该值。命令形如：

```powershell
node .bw/release/publish/publish.mjs --version v0.5.0 `
  --pack-run .bw/release/out/verify/<pack门禁run> `
  --installer-run .bw/release/out/verify/<验包run> `
  --notes-file <版本说明.md> --authorized-by "<授权记录>"
```

**拒发条件**（任一命中：非零退出、逐条人话原因、零远端写入）：

1. 出包记录缺失或不可信：`out/<版本>/pack-result.json` 不在、`ok≠true`、产物名与版本串派生名不符、`sha256` 与现场复算不一致、`revision` 缺省、`source_unchanged≠true`、`dirty=true`（仅 `--allow-dirty` 显式放行且写入收据与 Release 正文）
2. 门禁验证记录缺失或不同源：`--pack-run` 非 `profile=pack` / `status=passed` / `sourceUnchanged`，或其 `source.commit` ≠ 出包 `revision`
3. 验包记录缺失或不同源：`--installer-run` 非 `profile=installer` / `status=passed`，或其 `setup-identity.json` 的现场 SHA ≠ 出包记录 `sha256`，或其 `source.commit` ≠ 出包 `revision`
4. 构建修订不在 `origin/main` 上（fetch 后非祖先）——不从游离分支或旧修订发布
5. tag 或 Release 已存在——同号不重发，重发须人先删或开下一号

**动作序列**（每步读回，读回不一致即中止并如实报中途态）：发布预检（gh 登录可达；远端状态只读查询）→ 从记录渲染附注 tag message（不手写）→ `git tag -a <版本> <构建修订>` → push → `ls-remote` 读回 tag 指向构建修订 → `gh release create`（正文 = 版本说明 + 机器生成的绑定块，资产 = 候选包原件）→ `gh release view` 读回 tagName/资产名/大小 → **下载资产复算 SHA-256** 与出包记录比对 → 收据落 `out/publish/<版本>/publish-receipt.json`（含 release-body.md 与资产读回件）。任何写入步失败时报错必须说明中途态（tag 是否已在远端、如何回退或续发）。

收据与 Release 正文绑定块是「发了什么、谁授权、对应哪次验证」的机器正本；版本报告（`.bw/planning/<版本>/`）引用收据，不另抄数字。绑定校验（条件 1–3，`validateBindings`）与远端状态校验（条件 4–5，`validateRemoteState`）都是纯函数，由 `publish.test.mjs` 拒发矩阵看护。

## 按钮怎么接

计划屏「出包」→ `Command::PackRelease`（`project_id` + 当前视图那个版本号）。只在某个版本视图，全部 issue 没有这颗。有同名 tag：`--workdir` 是新建的 `.bw/worktrees/pack-<号>`（检出该 tag，主检出不动）。在研且还没 tag：先快进工作区，`--workdir` 是仓根。既不是在研也没 tag：按钮灰，内核拒。不和「发版本」绑在一起。

1. 人点出包 → 弹窗两行都灰
2. 拉 `pack`，第一行黄转圈；读 `progress` / `result`
3. 失败：第一行红 + `message`，第二行保持灰
4. 成功：第一行绿 + 「打开目录」（`artifact_dir`）；拉 `e2e`，第二行黄转圈
5. E2E 结束：写 `passed/total`，相等黑，不等红
6. **不**走 `cut_release`。要打 tag / 发群，人再点「发版本」

进度步号 21 / 22，避开接入屏的 1 / 2 / 3。不出全屏遮罩，弹窗开着等人看两行。打开目录是壳上的 `explorer`，不进内核。
