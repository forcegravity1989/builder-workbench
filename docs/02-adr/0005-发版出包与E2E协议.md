# 0005 · 发版本先出包再验包：入口 / 出口协议（本仓样例）

> **30 秒导读**：计划屏「出包」先出包、再对包做 E2E；「发版本」只打 tag / 发群，两颗按钮分开。入口两个固定命令（`.bw/release/pack/pack.cmd`、`.bw/release/e2e/e2e.cmd`），出口一行一条 JSONL，出包和 E2E 状态分开报。出包走内核 `PackRelease`（两行弹窗吃进度）；`CutRelease` 仍只打标签。点击界面用 WebView 调试口（Playwright），窗藏在隔离桌面，不抢人正在用的键鼠。

- 状态:已接受(2026-09-01)；2026-09-02 改口：入口只认 `.cmd`、脚本分 `pack/` 与 `e2e/`、E2E 只记项目功能；计划屏「出包」接 `PackRelease`，与「发版本」分开；2026-09-03：出包可关窗续跑、停止清中间件；stdout 按行切 UTF-8；验包 `cases` 给人看详情；2026-09-07：有 tag 的号 `--workdir` 换成 `.bw/worktrees/pack-<号>`，在研无 tag 仍用仓根
- 相关:[`docs/architecture.md`](../architecture.md)(桌面壳、周循环与发版)、[`CONTEXT.md`](../../CONTEXT.md)(发版、读回、深链、对照日志)、[`AGENTS.md`](../../AGENTS.md)(出包旅程)

## 决策

1. **出包和发版本是两颗按钮**。`cut_release`（远端 Release / tag + WeLink）本身不改。「出包」发 `PackRelease`：分别拉 pack / e2e，两行弹窗吃 JSONL，不打标签。「发版本」仍只走 `CutRelease`。
2. **任何被管仓同一套入口**。后台在仓根拉起，不交互、不读 stdin。入口**只认一份 `.cmd`**，不再「没有 cmd 再试 ps1」：
   - 出包：`.bw/release/pack/pack.cmd`
   - 验包：`.bw/release/e2e/e2e.cmd`
   - 参数都只有 `--version <号>` `--workdir <仓根绝对路径>`
   出包依赖（`.iss`、装完说明、实现脚本）放 `pack/`；验包依赖（驱动、`package.json`、实现脚本）放 `e2e/`。两套不混。
3. **出口是 stdout 上的 JSONL**。进行中 `type=progress`，结束一条 `type=result`。编译器 / ISCC / Playwright 的嘈杂输出进 stderr。退出码：最后一条 `result.ok == true` 才是 0。
4. **出包和 E2E 必须能分开报状态**（两行弹窗各吃一棒）。出包非 0 不拉 E2E。
5. **本仓是样例，安装器正源在 `.bw/release/pack/`**。`packaging/` 整份搬走，不留第二路径。
6. **验包装出来的那份 exe，实点走 WebView CDP**（做法 1）。隔离桌面只负责藏窗。不在流水线里再开一只活模型。不准对交互桌面 `SetForegroundWindow` / `SendInput`。不等用户闲下来。
7. **关窗不杀进程**。出包占着命令队列，停止不走队列，壳直接 `PackCtl::abort`：杀进程树，清这次的 `.bw/release/out/{version}` 与临时装目录。
8. **协议行必须是 UTF-8 字节**。内核按行切，非 UTF-8 当噪声丢掉，不整段读失败。验包 `result.cases` 给人看详情。

## 为什么

- 发版本今天只打 tag、发群，包好不好、壳亮不亮没人守。把出包和验包收成可拉起的命令，按钮才能转圈、打开目录、回显失败、显示成功数 / 总数。
- 采集脚本已经是「仓里写命令、stdout 吐 JSON」。出包 / E2E 同一类事，不另发明内核 API。
- 壳是 WebView2。对 DOM `click` 和人点同一套处理；OS 键鼠会抢走正在用的窗口。wry 写死了 browser args，会盖掉 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，所以验包进程用 `BW_CDP_PORT` 把调试口拼进**现有**那串 args。
- 不为兼容留 `packaging/`：正源只能有一份。

## 后果

- 本仓手工出包改走 `.bw/release/pack/pack.cmd`；`AGENTS.md` 出包段、gitignore、architecture 模块 11 一并改。
- 壳增加一个只认环境变量的缝：`BW_CDP_PORT` 有值才开调试口，没设与今天完全一样。
- 验包要本机 Node + Playwright；缺了报 `missing_tool`，人话写清。
- 下一棒按钮只消费这份 JSONL，不另定一套状态。

## 入口

后台 `CreateProcess`，工作目录 = `--workdir`（项目仓根）。

| | 出包 | E2E |
|---|---|---|
| 入口 | `.bw/release/pack/pack.cmd` | `.bw/release/e2e/e2e.cmd` |
| 参数 | `--version` `--workdir` | 同样两个，**不传**包路径 |

E2E 自己去 `{workdir}/.bw/release/out/{version}/` 找上一棒产物。目录或 setup.exe 不在：功能用例都记「未跑」，`passed=0`，`message` = 「还没有这个版本的包」。包在不在、能不能静默装、装完清不干净，是出包校验和清理，**不进** E2E `cases`。

版本号原样当目录名（本仓样例用 `0.1.0-mvp` 这类，与现在 ISS `AppVersion` 一致）。空、含 `(`、含路径分隔符：`bad_args`。

## 出口（JSONL）

stdout **只**打协议行。一行一条，`v` 恒为 `1`。

进行中：

```json
{"v":1,"type":"progress","phase":"probe","message":"在找 ISCC.exe"}
```

`phase` 是给转圈看的短名，`message` 给人看。出包常用：`probe` / `build` / `payload` / `iss` / `verify`。E2E 常用：`probe` / `install` / `launch` / `cu_settings` / `cu_onboard` / `uninstall`（后三者里 `install` / `uninstall` 是脚手架进度，不是用例名）。

出包结束，二选一：

```json
{"v":1,"type":"result","ok":true,"artifact_dir":"D:\\proj\\.bw\\release\\out\\0.1.0-mvp"}
{"v":1,"type":"result","ok":false,"code":"missing_tool","message":"本机没有 Inno Setup（ISCC.exe）"}
```

E2E 结束：

```json
{"v":1,"type":"result","ok":true,"passed":3,"total":3,"cases":[{"name":"shell_launches","ok":true}]}
```

`ok: false` 时同样带 `code` + `message`，并尽量带齐 `passed` / `total` / `cases`（含「未跑」的条，`ok: false`，`message` 写「未跑：上一条失败」）。`result.ok` 为 true 当且仅当 `passed == total` 且 `total > 0`。

失败码（`code`）：

| code | 何时 |
|---|---|
| `bad_args` | 缺参数、版本号不合法 |
| `missing_tool` | 缺 cargo / C 工具链 / ISCC / Node / Playwright / Claude Code（安装器拒装） |
| `build_failed` | `cargo build --release -p app-shell` 非 0 |
| `pack_failed` | 拷 dll、ISCC、或静默装校验/卸载失败 |
| `e2e_failed` | 验包有一条未过（人话写第一条失败的 `message`） |

缺什么工具，写进 `message`，前端原样回显。

## 两行弹窗怎么消费

点「出包」出弹窗两行，后台**分别**拉 pack、再拉 e2e。不打 tag。

| 行 | 吃谁 | 圈 | 行上写什么 |
|---|---|---|---|
| 打包 | pack 的 JSONL | 跑着黄转圈；成功绿；失败红；还没开始灰 | 成功：按钮打开 `artifact_dir`；失败：`message` |
| E2E | e2e 的 JSONL | 打包没结束一直灰、不转；打包成功后黄转圈 | `passed` / `total`；相等黑，不相等红 |

不是等用户离开再跑。验包进程和人正在用的 buddy 是两份。

## 本仓出包样例

`packaging/` **整份迁走，不留兼容层**：

```
.bw/release/
  pack/pack.cmd                 → 唯一出包入口
  pack/BuildersWorkbench-MVP.iss
  pack/AFTER-INSTALL-MVP.txt
  out/<version>/                → gitignore，ISCC 输出，至少有 *Setup*.exe
```

`pack.cmd` 在仓根跑，顺序：

1. **probe**：cargo、本机 C 工具链（没有 → `missing_tool` +「本机没有 gcc」这类）、`ISCC.exe`（`PATH` + Inno Setup 6/7 默认安装路径）
2. **build**：`cargo build --release -p app-shell`
3. **payload**：`WebView2Loader.dll` 从 `target/release/build/webview2-com-sys-*/out/x64/` 拷到 `target/release/`
4. **iss**：`--version` 喂给 ISCC 的 `AppVersion`，`OutputDir` = `{workdir}/.bw/release/out/{version}/`
5. **verify**：静默装到 `%TEMP%\bw-pack-verify-{version}`，确认有 `bw-dev.exe`，再卸干净。这是包的校验和清理，不是 E2E。
6. 一条 `result`（`artifact_dir` 或失败）

`.iss` 相对 `.bw/release/pack/` 往上三级取 `target/release/` 与 `crates/app-shell/app.ico`。AppId、装完必做文案、默认安装目录不改。`OutputBaseFilename` 仍是 `BuildersWorkbench-MVP-Setup`（版本在目录名上，不在文件名上）。

gitignore：去掉 `packaging/**/output/`，改为 `.bw/release/out/` 与 `.bw/release/e2e/node_modules/`。

## 本仓 E2E 样例

入口 `.bw/release/e2e/e2e.cmd`。驱动是同目录 `drive.mjs`（Playwright 连 CDP）。点击不在编排脚本里点坐标。同目录一份 `package.json` 只声明 `playwright`；`node_modules` 不进仓。先找 `node`，没有再 `npm install`，缺哪样报 `missing_tool`（功能用例都记「未跑」）。调试口由脚本挑一个空闲本机端口，写进 `BW_CDP_PORT`，再传给 `drive.mjs`，不写死 9222。找包、静默装、卸临时目录是脚手架，打 `progress`，不进 `cases`。

**隔离（硬约束）**

- 另一份刚装进 `%TEMP%/bw-e2e-{version}/` 的 `bw-dev.exe`，不是人正在用的那份
- `BW_DB` / `BW_WORKSPACES` / `BW_LOG` / `WEBVIEW2_USER_DATA_FOLDER` 指到该临时树，不碰 `D:\builders-workbench\data` 也不碰 `%LOCALAPPDATA%\bw-dev`
- 进程建在隔离桌面（`CreateDesktop`）；调试口听 `127.0.0.1`，Playwright 从交互会话连过去
- 不准对交互桌面 `SetForegroundWindow` / `SendInput`
- 立刻跑，不等前台空闲

**壳上的缝（只为验包）**

- `BW_CDP_PORT`：有值则在现有 `with_windows_browser_args` 后追加 `--remote-debugging-port=<port> --remote-allow-origins=*`
- 深链到设置 / 接入时对照日志打 `[BW_VIEW] settings` / `[BW_VIEW] onboard`（和 `[BW_OPEN]` 同级）

**功能用例（本仓样例三条；`total` 等于条数）**

| name | 干什么 | 过 |
|---|---|---|
| `shell_launches` | 隔离桌面拉起，`BW_VIEW=settings`、`BW_CDP_PORT`、独立数据目录 | 限定时间内日志出现 `[BW_VIEW] settings` |
| `cu_settings` | Playwright 连调试口，点设置屏上真实控件、认该有的字 | 控件或文案对上设置屏 |
| `cu_onboard` | **同一进程里**点顶栏 / 侧栏进接入屏（不再起第二个 exe、不再改 `BW_VIEW`） | 对上接入 / 项目墙空态该有的字或按钮 |

前一条失败，后面 `ok: false` 且 `message` 以「未跑：」开头。安装器因本机没有 Claude Code 拒装 → `missing_tool`，人话沿用安装器那句，功能用例记「未跑」。

截图（失败时）落到 `{artifact_dir}/e2e-shots/`，人打开产物目录能对照。不是协议字段。

本机没有 Node 或没装 Playwright：`missing_tool`，不假装点过。

不在这一版走完第 0–6 站。先证明：包能装、壳能亮、隔离桌面上能点到两块顶层屏。加站只加 `cases`，不换驱动。

## 按钮怎么接

计划屏「出包」→ `Command::PackRelease`（`project_id` + 当前视图那个版本号）。只在某个版本视图，全部 issue 没有这颗。有同名 tag：`--workdir` 是新建的 `.bw/worktrees/pack-<号>`（检出该 tag，主检出不动）。在研且还没 tag：先快进工作区，`--workdir` 是仓根。既不是在研也没 tag：按钮灰，内核拒。不和「发版本」绑在一起。

1. 人点出包 → 弹窗两行都灰
2. 拉 `pack`，第一行黄转圈；读 `progress` / `result`
3. 失败：第一行红 + `message`，第二行保持灰
4. 成功：第一行绿 + 「打开目录」（`artifact_dir`）；拉 `e2e`，第二行黄转圈
5. E2E 结束：写 `passed/total`，相等黑，不等红
6. **不**走 `cut_release`。要打 tag / 发群，人再点「发版本」

进度步号 21 / 22，避开接入屏的 1 / 2 / 3。不出全屏遮罩，弹窗开着等人看两行。打开目录是壳上的 `explorer`，不进内核。
