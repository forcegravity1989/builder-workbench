# 0006 · 会话与执行内嵌进 Workbench，废弃外部 Orca iframe

> **30 秒导读**：会话屏不再嵌外部 Electron Orca 网页。开工、终端、接回、停止、本机自动化都在 Workbench 本进程（或同 workspace 的 runtime crate）完成。产品是**一个**桌面工作台，不是「看板 + 嵌另一个 IDE」。Open Design 仍可嵌本机网页（设计工具，不是执行宿主）。过渡期可双后端，目标态桌面路径**零外部 Orca 依赖**。

- 状态:**提议**(2026-09-11)
- 相关:[`docs/architecture.md`](../architecture.md)(§2 会话与执行、§3 三 crate)、[`docs/06-module/会话与执行.md`](../06-module/会话与执行.md)、[`CONTEXT.md`](../../CONTEXT.md)(会话 / 运行 / Connector)、[`crates/bw-engine/src/orca.rs`](../../crates/bw-engine/src/orca.rs)(现行 pipe 客户端)
- 特性链:[`docs/05-features/native-session-execution/`](../05-features/native-session-execution/)(intent / spec；可点高保真 `prototype.html` 本地打开)

## 决策

1. **一体产品，不要 iframe Orca。** 会话屏的执行表面是 Workbench 原生 UI（Dioxus）：终端输出、按 Issue 的 Workspace 列表、**Explorer / Source Control / Diff（对齐 Orca 审文件）**、接回与停止。人不再「进另一个应用里点会话」。计划屏 ▶开工仍是唯一开工入口；完成仍由人点（铁律不变）。开工链路与现行 `run_issue_orca` 同序：`provision` → `refresh_worktrees` → `create_session`（或跳过）→ `activate/reveal`。
2. **执行能力进本仓库 workspace。** 新增（或等价落点）`crates/orca-runtime`：本机 agent 宿主、PTY、会话生命周期、本机自动化调度。`bw-engine` 的 `orca.rs` 从「连外部 `orca-runtime.json` pipe」改为**对本 runtime 的门面**；对外方法名尽量保持（`create_session` / `activate_worktree` / `ensure_repo` / automations），好让 `bw/app/issue|session|project|orca_inject` 少改。
3. **三 crate 边界不破。**
   - `bw`：Issue ↔ 会话编排、`run_issue`、停跑命令、业务语义；不直接碰 PTY。
   - `bw-engine` / `orca-runtime`：能力底座——通用 id、路径、agent 名；不解释「这是不是某张 Issue」。
   - `app-shell`：会话屏渲染 + 终端字节走已有 broadcast（**不进 ViewModel**）；无业务判断。
4. **废弃外部 Orca 嵌页与配对配置（目标态）。**
   - 删除或停用：`SetOrcaWebUrl` / `OrcaWebUrlChanged`、设置页「Orca 网页地址」、环境变量 `BW_ORCA_WEB_URL`、会话屏对 Orca SPA 的 iframe、对外部 `orca-runtime.json` named-pipe/unix 的桌面依赖。
   - 词表与 architecture：对外称「会话 / 执行 / 开工工具」；「Orca」不再表示必须另装的桌面产品。crate / 模块名可暂留 `orca-*`，避免无意义的大搬家。
5. **Open Design 例外。** 本机 Open Design 网页内嵌保留——它是设计工具 Connector，不起 agent、不承载执行态；与本 ADR「不嵌执行宿主」不冲突。
6. **MVP 能力边界（做 / 不做见下）。** 第一版只服务 Workbench 主路径：Claude Code + Cursor（已通两条）+ 原生终端 + 接回/停止 + 三条本机自动化（week-plan / ops-audit / ledger）。不重建独立 Orca 桌面、不迁 mobile/SSH/Design Mode/完整编辑器。

## 为什么

- **现状矛盾**：开工走本地 pipe（Workbench 下命令），人看输出却靠嵌页配对。两条通道刻意分开后，人不知道「当前 Issue 对应 Orca 里哪条会话」；停止接口至今未接；设置里要贴带 token 的配对 URL——这是集成缝，不是产品。
- **产品命题**：Workbench 管整次迭代里人坐在哪、要点头的地方；执行层若仍是外挂 IDE，会话屏永远是租来的脸，飞轮（定方向 → AI 跑 → 人审）在屏上断一截。
- **工程现实**：BW 已是 Rust/Dioxus；worktree、远端 issue、计划/总览已在本仓。缺的是本进程 agent+PTY+会话 UI，不是再维护一个 Electron 运行时。`legacy_pty` 封存、pipe 客户端已把「要什么 API」钉死——内嵌是换实现，不是换产品故事。
- **否决「瘦 orcad + 继续 iframe」**：多一个进程、继续配对与双应用发布，集成成本高，且会话屏仍不是一等公民。

## 考虑过的选项

| 选项 | 结论 |
| --- | --- |
| 保留外部 Electron Orca + iframe | **否决**。双应用、配对 URL、停止难接、产品感割裂。 |
| 独立瘦 `orcad` + 保 pipe，会话仍 iframe 其 web | **否决**。协议可稳，但 UI 仍外挂；不符「整活成一个产品」。 |
| 独立瘦 `orcad` + BW 原生终端（pipe 客户端保留） | **备选过渡**。桌面可先 in-process；若日后要无 UI 的 headless 主机再拆二进制。MVP 不以此为交付形态。 |
| **本进程 `orca-runtime` + 原生会话屏** | **采纳**。零外部 Orca、一个窗口、API 门面可原地替换。 |

## 后果

- `docs/architecture.md` §2「会话与执行」、`docs/06-module/会话与执行.md`、`docs/hifi` 会话段、设置屏文案需改口径：去掉「嵌 Orca / 配对 URL」；写明原生终端 + 本机 runtime。
- `CONTEXT.md`：弱化「Orca 会话宿主」为必须外置 Connector；执行宿主变为 Workbench 内建能力，开工工具（Claude / Cursor 等）仍是 Connector。
- `bw-engine::orca`：连接失败文案从「Orca 没开吗」变为 runtime 未就绪/本机工具未装等；不再读用户目录下外部 `orca-runtime.json`（目标态）。
- 自动化：纳入项目时注入的三条调度从外部 Orca Automations **收回本机**；`destination=self` 语义保留（钉本机主机，不是远端 Server）。
- 终端流量：继续「桥上 broadcast、不进 ViewModel」；会话列表进 ViewModel 的是元数据（id / Issue / 状态 / worktree），不是字节流。
- 过渡期允许双后端（pipe / in-process）开关，但**不得**把「还要开外部 Orca」写成目标体验；合并前桌面主路径应能在无外部 Orca 时跑通开工与看输出。

## 本棒做 / 不做

**做（MVP）**

- workspace 增加 `orca-runtime`（或经评审等价并入 `bw-engine` 的清晰模块边界）
- in-process：`create_session` / `activate_worktree`（接回）/ `ensure_repo` 语义对齐现行调用方
- 原生会话屏：终端 + Workspace 列表 + **Explorer（当前 worktree 树）+ Source Control（Staged / Changes / Untracked，相对 compare base）+ 点文件开 Diff**；去掉 Orca iframe
- 建树语义对齐 Orca：`provision`（路径 `.bw/worktrees/issue-N`、分支 `bw/issue-N`）→ refresh → createAgentSession → activate/reveal；接回只 activate/reveal，不 silent 第二棵树
- `StopRun`（或同名命令）：能停本机 agent/PTY；不再把「本机记录变了」说成已杀进程
- 三条本机自动化迁回；删设置项与 `BW_ORCA_WEB_URL`
- 开工工具：Claude Code、Cursor；启动参数与信任处理沿用现行 `orca.rs` 已踩坑结论（勿借机重设计）

**不做（本 ADR / MVP）**

- 重做独立 Orca 桌面产品、mobile companion、SSH worktree、Design Mode、内嵌 Chromium 自动化
- 把 Open Design 改成本地非 iframe（可另议）
- 无限终端分屏、scrollback 冷恢复、**完整 IDE 编辑器**（可写任意文件、语言服务、多游标）；MVP 文件面只做到 Orca 审跑所需的树 / 变更列表 / Diff
- Orca「New workspace」自由 composer（任意命名 / PR·Linear URL / sparse / SSH run target）——Workbench 入口仍是计划屏 Issue ▶开工，路径与分支由 Issue 号定
- 40+ agent 归一化层、多 worktree 并行 fan-out（可 v2）
- 为「将来可能有很多种 agent」先建空抽象（见 `adapters/claude_cli/README.md`：不抄多 agent 归一化）

## 建议落地顺序

1. 本 ADR 评审接受后，改 architecture / 06-module / CONTEXT 口径（文档与代码同批或紧随）。
2. runtime 烟测：本进程起 Claude PTY（可先无漂亮 UI）。
3. 会话屏第一版终端；计划屏开工切到本 runtime。
4. Cursor + 接回 + Stop；拆除 iframe 与配对设置。
5. 三条自动化迁回；回归 macOS / Windows。

## 验收（提议）

- 本机**不安装、不启动**外部 Electron Orca，仍能：纳入仓 → ▶开工 → 会话屏看见终端输出 → 接回同一 worktree → 停止运行。
- 设置中无「Orca 网页地址」；`BW_ORCA_WEB_URL` 无效或明确废弃。
- Open Design 页签行为不因本 ADR 回退（探不到仍如实空着）。
