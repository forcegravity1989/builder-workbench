# 0006 · V3 删除与能力模块收为五个(旧 16 模块挪移)

- 状态:已接受(2026-08-24 V3 删除;2026-09 能力模块 6→5 收口)
- 相关:[`docs/architecture.md`](../architecture.md)(§1 用例 / §2 能力模块)、[`../../AGENTS.md`](../../AGENTS.md)(V3 已删)、`v3` 分支(全量史实)

## 决策

1. **V3 的六个 crate**(bw-core / bw-engine / bw-store / bw-app / ui / app-desktop)**于 2026-08-24 删除**,全量在 `v3` 分支。当前 Workbench MVP 不是从 V3 迁移来的:底座(`bw-engine`)是拷过来接管后做了三件减法(断掉对 V3 内核的依赖、删只有 V3 用的出口、删两条零调用死链);内核(`bw`)是全新的库与全新的 Command/Event——旧库的二十张表与架在表上的用例整片接不上,改它等于拆了重装还会连累当时还在跑的 V3。两个能力模块(① 关键信息维护、⑤ 桌面壳)对已删 V3 crate 零依赖。名字里的版本号(`bw`、bin 名 `bw-dev`)是共存期的权宜。
2. **能力模块从六个收为五个**:①「正本读写」改名「关键信息维护」并扩范围(正本分两类:活态数据正本 + 人持文档正本);②「健康推导」降为 ① 下的二级特性(密封 `DerivedHealth` 守「没数据不装绿」铁律不变,代码不删只降结构层级);原 ③-⑥ 顺位前移为 ②-⑤。

## 为什么

- V3 的二十张表与 V4 旅程(规范铺底 / 运作活 / 项目群)接不上,留它在仓里改不动、删不得;删掉换成零库 + codehub issue 正本(见 [ADR-0001](0001-codehub-issue-正本-本地零库.md))后,数据归属一句话讲清。
- 健康推导是从 ① 维护的信息里现算出来的派生视图,不够独立成和会话 / 壳平级的同辈能力;折进 ① 作二级特性,模块边界对齐「能力 = 一件能独立说清是什么的事」。
- 「正本读写」名字过窄——它还管人持文档正本的维护纪律(asset-audit 盘),改名「关键信息维护」盖住两类正本。
