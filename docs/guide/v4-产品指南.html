Workbench MVP · 产品指南

30 秒导读

这是什么——Workbench MVP 的使用指南，一站一站写，从零把一个项目接进来、每周转一圈。给谁看——第一次打开 Workbench 的人（先是我们自己，然后是同事）。现在还作数吗——作数（2026-08-25）。
  • 只写已经真走过一遍的站。没走到的站列在「先记着的缺口」，不提前编。
  • 怎么建 / 跑 / 测、门禁，看仓根 AGENTS.md。机制为什么这么定，看 docs/architecture.md。
还没做的活看各模块「没建什么」，不另开清单。Workbench-guide.html 是 V3 种子，不作数。

怎么干活

一个项目接进来一次,之后每周转一圈,一圈六站(下面那张图就是这一圈)。你做的事只有两类：说清楚要什么，以及在关键路口点头。剩下的——查资料、写代码、写文档、提交、开 MR——交给 agent。

所以整份指南只有一条主线：接进来 → 每周定目标 → 派活 → agent 干 → 你验收。

六站旅程环一个项目每周怎么转

0 只做一次；1–6 已经走过一圈
实心 = 已经真走过一遍 浅实心 = 这一站正在走、还没走完 虚线 = 设计定了，还没真走到

这份指南跟着实践走：每走完一站、那一站的改动合入之前，把这一站从「还没走到」搬进「已经走过」。今天第 0–6 站都走过一遍；还没建的记在「先记着的缺口」，不挡这一圈打结。

两条你随时可以拿去核对的规矩「完成」永远由人点：agent 干完最远只到「评审中」；定时任务只会自动建活，绝不自动完成活。没数据就是灰，不是绿：健康灯只能从真实数据推出来，界面上任何一个数字都能用 codehub-cli / gh 或打开仓文件独立核对。
设计正本 docs/architecture.md；还没做的活看各模块「没建什么」。
怎么用 · 第 0 站

把一个项目接进来

这一站已经走过，下面写的都是实际发生的。

你要准备什么

一个 git 仓
GitHub 或 codehub 上的都行，你有它的读权限。
本机装好命令行工具并登录过
gh（GitHub）或 codehub-cli（内部）。项目墙上那条环境条会当场去 PATH 里找这些命令，找得到绿、找不到红。红的不影响别的事，只影响对应那条路能不能走。

工作区目录先看一眼

「设置」里有一格「工作区根目录」。以后接进来的项目，仓就 clone 到这个目录下面，一个项目一个子目录。默认值在 macOS 上是 ~/.builders-workbench/workspaces，Windows 上是用户目录下的同名路径；要放到别的盘，现在就在这格里改掉、点保存——改完立刻生效，重启还在，而且已经接进来的项目不会跟着搬家（它们的路径当场被钉死在原处）。

接：两步

1
点「+ 接入项目」。第一步只问一件事：这个项目在哪。光标点进「项目地址」那格，Workbench 就去问平台要你账号下的仓，列成下拉框；打字即在这批里检索，点一行即选中。不想理列表就直接把 owner/repo 打进去，一样算数。框里右边那个 ⟳ 是重新拉一次。
2
第二步是基础信息，四格：项目名称、你想做什么、最像的对标、三个月长成什么样。
列不出来的时候会把命令的原话摆给你看（多半是没装或没登录），不会摆一张假列表。

第二步顶上：这个仓被 Workbench 接管过没有

判据是去它远端读 .bw/project.toml：

你会看到意思你该做什么
已经被 Workbench 接管过同事先接过，或者你以前接过四格是回显出来的，直接改就行；接进来时不会覆盖仓里已有的字
还没被 Workbench 接管过仓在、就是没这份文件四格自己填
找不到这个仓地址敲错了、私有仓没权限、没登录先把地址改对，接一个不存在的仓后面每步都会失败
没查成没登录、网不通、或没从列表点选（没带上默认分支时会去查 main）照样能接；仓里真有名片的话，接入时以仓里的为准

最后两行是特意分开的：「没查成」不等于「没被接管过」。混成一句的话，你会照着空格子填一遍，接进去反而把仓里真正的名片盖掉。

点「完成接入」之后会发生什么

界面上一步一句地摆出来，做完的那行原地换成结果——这一下要十几秒，别猛点：

1
取仓——目录里已经是 git 仓就直接用（顺带把它的 origin 报出来给你核对）；目录不在或是空的就 clone；没填远端就建个空目录并说明它是空的；目录里有东西又不是 git 仓就当场弹回，既不敢往里 clone，也不敢把别人的目录当成这个项目的仓。
2
本机清单落一行项目——只存定位：名字、本机路径、远端地址。名片不进这份清单。
3
写名片——.bw/project.toml。仓里已经有就一个字不覆盖、只补空着的字段。
4
自动建一张「规范铺底」的活——它开一条分支、往仓里写规范骨架、提一个 MR，然后停在评审中等你合。它不会自动合，也不会自动把活标成完成。
5
自动进这个项目。

第 4 步只铺马上要用的骨架，全在 .bw/ 底下，不是一口气铺二十几份：

文件是什么
.bw/project.toml第 3 步写的名片机读件（仓里已有就不覆盖）
.bw/PROJECT.md项目名片给人看：这个项目是什么、对标谁、北极星是什么
.bw/standard.toml铺的是哪一版规范、开了哪几类件
.bw/managed.toml记指纹，以后对账用
.bw/issue-policy.toml类别 → 开工工具 → workflow 的映射，加上周五资产盘点节律。接入这一次一起铺。

指标正文和采集脚本不在这一站预铺——跟第 2/3 站那张运作活①走，已有的不覆盖。「配置」屏只对账，不再二次铺底。

两件事你会注意到

  • Workbench 铺进你仓里的东西，全都在 .bw/ 里，一个例外都没有。仓根一个字不动——README.md、AGENTS.md、CLAUDE.md、docs/，接项目这一步全都不碰。「哪些是 bw 的资产」ls .bw/ 一眼可数。
  • Workbench 自己的规矩不往你仓里写。完成由人点、指标只能真采、合并永远是人——这些每次开工都会现给 agent，写进你仓里只会变成第二份会过时的副本。
  • 想让 Workbench 给你的项目写一份开发手册（仓根 AGENTS.md：怎么建、怎么跑、怎么测、目录里什么在哪）——那是另一件事，不在接项目这一步。它归资产盘点首次模式里的 project-handbook：问过你才写，走 MR。今天还没接上，见 docs/architecture.md 资产盘点模块「没建什么」。
  • Workbench 自带的技能不会进你的仓。它们住在 Workbench 自己的目录里，agent 开工时 Workbench 只把这张活要用的那一份的名字和路径告诉它，正文让它自己去读。你仓里 .claude/skills/ 下的技能仍然是你自己的，Workbench 不碰。

你仓里本来就有的 README.md、CLAUDE.md、AGENTS.md，Workbench 根本不碰——不是「已存在就跳过」，是这一步压根不往仓根写东西。

第 4 步没成不会推翻前面：项目已经接进来了、仓已经在本机了，这两件是真的。回头在「配置」屏点一次「规范铺底」重来就行——它按标题幂等（只认开着的同标题活），重来不会多建一张活。

以前铺过、但 MR 没合、issue 也关了——远端默认分支没有 .bw/project.toml，这一站仍算「还没纳入过」，接入后应再开一张新铺底和 MR。总览那三个运作活点只看开着的活；③写「已完成」只当件已经在默认分支上，关过的旧活不冒充铺过。

接错了怎么办

项目卡右上角有个 ✕。点一下先问一句，再点「移走」才真移走。它只把这个项目从工作台移出去（项目行、它所有活的账），仓一个字节都不动——硬盘上的代码还在原地，活自己的工作目录也还在。回执里会告诉你仓在哪儿，你真要删自己去删。

最后一下：你点完成，合那个 MR

接入只把活推到「评审中」。合入永远是人点的——计划屏把这张「规范铺底」从「评审中」拖到「已完成」（详情抽屉里那颗「✓ 点完成」是同一下）。松手会弹出确认框，写明先合哪个 MR；确认之后框不关，一步一句写正在合 MR、拉仓、结清（要两三秒）。合不成就整条不算数，活留在评审中，可以重试。

通知屏只通知，不在那儿合。「等你合入」告诉你有一张 MR 等着；去计划屏拖到「已完成」，或总览上那颗「合入并完成」。不要只在 codehub 网页关 issue——那不会合 MR。

这一站结束时你手上有什么

  • 本机一个真实的仓（clone 下来的）
  • 工作台上一个项目
  • 默认分支上有 .bw/ 骨架（合入之后才有；合之前只在铺底那条分支上）
  • 那张「规范铺底」活已完成，对应 MR 已合

合完这一下，第 0 站结束。下一站是周一看总览。

怎么用 · 第 1 站

周一看总览

项目已经接进来。这一站是打开它，看清「这是什么、健康吗、这周要推什么、指标现在几个数」。

操作

1
项目墙点进这个项目。侧栏默认停在「总览」。
2
从上往下看：名片和健康灯、北极星、本周计划进度、滞后性、引领性、代码仓级、在研版本。
3
进项目这一下，Workbench 会自己采一轮指标和仓统计（本会话第一次打开这个项目）。卡上会先写「正在采…」，采完折线出现。还想再采，用各块上的「重新采集」。

背后

  • 对远端代码仓：读这个项目的 issue 列表（开着的和关过的都读）。周目标那一句话来自本周运作活①最新一条评论里的 ## 周目标。纳入了哪些活看 bw:week:YYYY-Www 标签。
  • 对你的机器：在项目工作区跑 .bw/metrics.toml 里的采集脚本，窗口是近四周。脚本只吐一个当下值时，折线只在本周那一格画一个点，前几周断开。仓统计走 git（再问远端合入的 PR）。
  • 对 .bw/：指标定义读 metrics.toml。B 类点「采集」或每天 09:00 自动采，都把当天的值追加进 readings.jsonl（只追加，键是日历日，和 V3 一天一行对齐）。折线按周画，取那一周最后一天。没有 run 的 B 类仍然采不到。C 类在卡上填今天这个数，同一天再记覆盖读回。

得到什么

  • 健康灯和三条理由。没数据就是灰，不是绿。
  • 北极星 / 滞后 / 引领每张卡：有读数才有现值和折线。A 类点「采一次」现算四周；B 类同样点采集，当下值进流水。穿刺北极星已经是 B 类：脚本 .bw/scripts/stars.py 在、Workbench 会把当下值写进 readings.jsonl。这周读到 0 是真值（CodeHub 上 0 star），不是「没采到」。CodeHub 没有 star 时间戳，升不了按日的 A 类。卡片「口径」认字段 def，写成 definition 会空着。
  • 本周计划进度：周号 + 周目标一句 + 五段计数。运作活①本周已关会写「已完成」，不是「未建」。侧栏下面就是计划，总览上不再放「去计划」。
运作活③写「已完成」只看默认分支有没有 .bw/standard.toml。以前铺过、issue 也关了、但合入的 MR 没进默认分支——件不在主干上，总览仍写「未建」。关 issue 不等于铺进了仓。

健康灯怎么亮只从真实数据推,不能被人调

灯旁边同时列出这次判断的理由。界面上原样显示的就是这几句（成立打勾、不成立打圈）：

  • 本周定了周目标，仓里也有真实提交。目标要写进运作活①评论的 ## 周目标，只开着这张活还不算定了。不成立时会说周目标还没写进评论、这张活还没开，或者有目标但本周还没有真实提交。
  • 本周或上周有指标读数。读的是仓里 .bw/metrics/readings.jsonl。点过采集、脚本吐了数，这一条才会打勾。
  • 上周有合入或发版。不成立时显示「上周既没有合入也没有发版」。

三条怎么合成一盏灯，见 docs/architecture.md 健康推导模块。没数据 = 灰，不是绿。

怎么用 · 第 2/3 站

开始本周，写下目标和纳入的活

总览上看过了。这一站用一次会话把「复盘 → 指标 → 本周目标和活清单」做完。计划正本挂在运作活①的评论上，不另写周计划文件。

操作

1
总览顶上「开始本周」。本周还没开过运作活①才会出现这颗按钮；已经做过（含已完成）不再冒出来。
2
跳到会话屏。agent 按 week-planning 剧本走：复盘、采指标、起草周目标与纳入清单。你在内嵌终端里看着、随时能停。
3
你确认之后，agent 当场建纳入的业务活，并打上本周 bw:week:YYYY-Www。周目标、纳入清单、指标读数快照写成运作活①的三条评论，标题必须是 ## 周目标 / ## 本周纳入 / ## 本周指标读数（旧评 ## 本周目标 也能读）。
4
侧栏点「计划」。周头是那句周目标；点某一周只看打了那一周标签的活，没打周标签的只在「issue总览」。运作活①做完、issue 关掉之后，总览那三个点里①应写「已完成」。

背后

  • 对远端代码仓：建一张标题为 更新指标 + 制定本周计划 YYYY-Www 的运作活①（同一周标题幂等，不会建第二张）。评论挂在这张 issue 上。纳入的活是真的 codehub issue，不是本地草稿。
  • 对你的机器：这张活自己的 worktree。缺的 metrics.toml 空壳和采集脚本会在开工时铺上（已有不覆盖），经这张活的 MR 合进默认分支。
  • 对 .bw/：指标定义和脚本进仓。周目标不进 .bw/plan/——那个目录已经不存在。

得到什么

  • 总览和计划屏同一句周目标，杀进程重开还能读回来（读的是 issue 评论）。
  • 本周范围内的活：看板上能点开。穿刺这一周纳入了「精品 skill 打磨」那张业务活。旧会话建的卡可能没打类别——详情里选一次即可；定本周剧本现在要求新建卡必须打 bw:category:*。
  • 运作活①可以关。关了不等于铺底没合入——那是另一张活、另一条 MR。
计划屏「新建活」先弹种类、标题、正文。业务活再选五阶段类别（原型默认 Open Design）。运作活选①或②，标题按本周幂等，类别锁成运作。周中要补一张计划或盘点，就在这里建运作活，不必等周五。要验 OD：种类选业务活、类别选「原型」，创建后点开卡片再「▶ 开工」。两种入口都会跳到会话屏。

怎么用 · 第 4 站

把一张活开起来干

这一站已经走过。开工、作废、收会话、原型进 Open Design、计划屏按周看卡，都是真碰到过的。提交开 MR、合入、点完成、记发版在第 5 站。

操作

1
计划屏点开一张卡（整张都能点）。没打类别的先在详情里补一类——不开工工具的活会被拒绝开工，不会悄悄起 Claude。
2
卡片或详情上「▶ 开工」，或把卡拖进「进行中」。确认框写开工工具和 workflow。确认后跳会话屏。
3
原型类默认停在 Open Design 标签，嵌的是本机 OD 首页。不会自动开跑，你在 OD 里打一句发出去，它的 AI 才动。提示词尽量灌进 OD 的系统提示；对话列表里不一定看得见这一单。构建类走内嵌终端里的 Claude。
4
不想干了：详情「作废」，写原因。这不是完成——打已取消标签并关掉远端 issue，卡到「已取消」。
5
作废不会拆本机会话。要收掉：会话屏「删除会话」，确认之后才停终端、收这棵工作目录、删本机会话行。远端那张 issue 不动。
6
计划屏点某一周，只看打了那一周标签的活；没打周标签的只在「issue总览」。顶栏刷新读远端，右栏跟着改文件自己刷新不做。
7
会话屏左右两栏都能收，把中间终端撑大。右侧「指南」哪一屏都在，打开就是这份产品指南。

背后

  • 对远端代码仓：开工改状态标签到进行中。作废写原因评论、打 bw:status:cancelled、关掉 issue。删除会话不碰远端。周范围认 bw:week:YYYY-Www。
  • 对你的机器：每张活一棵工作目录。原型开工探活后嵌 OD 首页，并向 /api/runs 灌系统提示词；灌不上就说没灌上，不假装已经进了某一单对话。构建类在伪终端里起 Claude。删会话才强制收掉这棵目录。
  • 对 .bw/：会话身份落本机 sessions 文件。指标读数不在这一站写——点采集才追加 readings.jsonl。

得到什么

  • 拖进进行中 = 开工，和按钮是同一条路。
  • 作废卡不会冒充已完成。作废后再点开工，会说这张活已经取消。
  • 原型：会话停在 Open Design 标签。退路是「看看喂了什么」，把提示词拷过去。不在 OD 里另建一单、也不深链到某一会话。
  • 右侧文件树是问这棵工作目录；「改动」只列还没提交的脏文件；「MR」只在评审中才去查开着的合并请求。刚开工、目录干净，写「无改动 / 还没有 MR」是实话。

怎么用 · 第 5 站

合入、点完成、记进一个版本

这一站已经走过。不是到点自动结束一周：活到评审中之后，你点完成才合 MR、结清；本周做完的活，再点「发版本」记进远端的一个 Release。

操作

1
计划屏把评审中的卡拖到「已完成」，或详情里「✓ 点完成」。确认框写明先合哪个 MR。合不成就整条不算，活留在评审中，可以重试。
2
通知屏只告诉你有 MR 等着，不在那儿合。不要只在 codehub 网页关 issue——那不会合 MR。
3
本周有已完成的活，计划屏点「发版本」。弹窗里填版本号，默认是在研号的下一位（接入默认在研 v0.1，所以默认常是 v0.2），可以改。确认后才建远端 Release。
4
去 codehub 的版本页，或跑 codehub-cli release list，核对远端真有这个版本。总览「已发版次数」优先读远端 Release。

背后

  • 对远端代码仓：先合那张 MR，再关掉 issue（完成）。发版先建 codehub Release（打 git 标签），成功后再给勾过的活打 bw:released:vX。顺序不能反。
  • 对你的机器：合入后尽量把主检出拉到最新，收掉这张活的工作目录。本机不会多出一个发版文件。
  • 对 .bw/：在研版本仍是 project.toml 里那一行，发版不改它。要切号，去配置屏改完点保存。

得到什么

  • 远端多一个 Release；选中的活带上版本标签。穿刺仓读回是 v0.2。
  • 总览「在研版本」还是名片上的 v0.1，不是写死，是发版没去改那一行。
  • 总览「已发版次数」跟远端 Release 列表走；远端读不到才退回本机 git 标签。
发版不是只打 issue 标签。标签是第二步。第一步是远端 Release。在研号发完不改——切号去配置屏。次数读的是已经发出去的 Release，不是名片上的在研号。

到点建一张盘点，停在评审中

这一站已经走过。周五晚上（默认可改）Workbench 开着，会自己建「资产盘点」并开工，最远评审中。完成仍要你点。仓根手册不会这一周写出来。

操作

1
配置屏能看见「资产盘点 · 到点自动建 · fri 20:00」，还有一行「B 类指标采集 · daily 09:00 · 今天还没采过」。盘点节律写在 .bw/issue-policy.toml；B 类日采是写死的 09:00，不另开一张定时表。
2
Workbench 开着、过了本周那个时刻，计划屏会出现「资产盘点 YYYY-Www」。类别锁成「运作」，改不了五阶段。剧本跟标题走，不跟映射走。
3
这张活会自己开工。看会话或详情：最远到评审中。合入、点完成仍是你来。
4
周一回到总览，开始下一圈。盘点报告挂在这张活的评论里；微重构只出建议，不直接改业务代码。

背后

  • 对远端代码仓：建一张标题固定的运作活（本周有了就不建第二张），打本周标签，开工后改状态。每周模式只对账、写报告；首次模式才给老 issue 补周标签。
  • 对你的机器：Workbench 开着每 60 秒判一次「本周这一刻过了没有」。当时没开着，下次开着会补建。注入的是 asset-audit，不是构建类那套对齐→实现→评审。
  • 对 .bw/：每周盘点对照指纹看规范件落后没有，只记差异、不擅自升级。仓根 AGENTS.md 不在这一周写。

得到什么

  • 多一张运作活②，类别显示「运作」、改不了五阶段。剧本跟标题走，不跟映射走。
  • 写仓根开发手册的 project-handbook 还在技能表里，挂在首次盘点「问过你再写」上，会话没接上。先记着，不挡这一站。
  • Workbench 开着、过了本机 09:00，会自动采一轮 B 类，按当天写入 readings.jsonl。折线按周，取那一周最后一天。点「采集」也能立刻再采今天。
运作活和五阶段类别是两套。优化 / 运维 / 运营推广是业务活的默认打法，不要把盘点、周计划塞进去。组内项目要有 AGENTS.md，靠首次盘点里的手册剧本，不是每周五那次对账。

健康灯怎么亮只从真实数据推,不能被人调

第 1 站已经走过，判断依据和界面上那三条理由写在「第 1 站 · 看总览」。下面这张图只留机制形状。

数据推导，不能手点；没数据就停在灰

灯下面那三条理由,界面上原样显示的就是这三句(成立打勾、不成立打圈):

  • 本周定了周目标,仓里也有真实提交。目标要写进运作活①评论的 ## 周目标，只开着这张活还不算定了。不成立时会说周目标还没写进评论、这张活还没开，或者有目标但本周还没有真实提交。
  • 本周或上周有指标读数 —— 不成立时显示「最近两周都没有记过指标读数」。
  • 上周有合入或发版 —— 不成立时显示「上周既没有合入也没有发版」。

三条怎么合成一盏灯(什么时候黄、什么时候红、为什么没数据是灰不是绿),见 docs/architecture.md 健康推导模块。

完成 = 锁定态，只能人工点开 红色虚线 + × = 定时任务被结构性挡在完成之外，不是靠自觉
