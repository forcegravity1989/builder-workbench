# buddy 使用指南(V4)

> **30 秒导读**:这是什么——教你把一个项目接进 buddy、之后每周转一圈的**使用指南**,「怎么用」这件事以本文为正本。给谁看——第一次打开 buddy 的人(先是我们自己,然后是组里的同事)。现在还作数吗——作数(2026-08-25 起以本文为「怎么用」正本;图文版 [`v4-产品指南.html`](v4-产品指南.html) 保留,冲突时以本文为准)。**只写已经真走过一遍的站**:没走到的站只留一句「它打算做什么」,不编步骤。想知道「为什么这么设计」看 [`../v4-prototype/design.md`](../v4-prototype/design.md);还有什么没做只认 [`../LEFTOVERS.md`](../LEFTOVERS.md);要给 buddy 本身开发新特性,看仓根 `DEVELOPMENT.md`。

## buddy 是怎么让你干活的

一个项目**接进来一次,之后每周转一圈**。你做的事只有两类:**说清楚要什么**,以及**在关键路口点头**。剩下的——查资料、写代码、写文档、提交、开合并请求(下文简称 MR)——交给 agent。

一圈六站:看总览 → 一次 agent 会话定出本周目标和活 → 每张活选好工具开工、agent 干你看着 → 评审、合入、你点完成 → 记发版 → 周五定时自动跑一次资产盘点,下周一回到总览。

**目前的实况**:第 0 站(接入项目)已经真走过一遍,下面的步骤都是实际发生过的;第 1–6 站设计定了、还没真走完,只在文末列标题。本指南跟着实践走——每走完一站,就把那一站从「还没走到」搬上来写成步骤。

## 两条你随时可以拿去核对的规矩

1. **「完成」永远由人点。** agent 干完最远只到「评审中」;定时任务只会自动**建**活,绝不自动**完成**活。
2. **没数据就是灰,不是绿。** 健康灯只能从真实数据推出来,不能手动设置;界面上任何一个数字都能查库或打开仓文件核对。

## 第 0 站 · 把一个项目接进来(已走过,以下是实况)

### 你要准备什么

- **一个 git 仓**:GitHub 或 codehub(内部)上的都行,你有它的读权限。
- **本机装好命令行工具并登录过**:`gh`(GitHub)或 `codehub-cli`(内部)。项目墙上那条环境条会当场去 PATH 里找这些命令,找得到绿、找不到红;红的只影响对应那条路,不影响别的事。
- **看一眼工作区目录**:「设置」里有一格「工作区根目录」,以后接进来的项目都 clone 到它下面,一个项目一个子目录。要放别的盘,现在就改掉、点保存——立刻生效,重启还在;已接进来的项目不会跟着搬家。

### 接:两步

1. 点「**+ 接入项目**」。第一步只问一件事:**这个项目在哪**。光标点进「项目地址」格,buddy 去问平台要你账号下的仓、列成下拉框,打字即检索,点一行即选中;不想理列表就直接把 `owner/repo` 打进去,一样算数。列不出来的时候会把命令的原话摆给你看(多半是没装或没登录),不会摆一张假列表。
2. 第二步是**基础信息**,四格:项目名称、你想做什么、最像的对标、三个月长成什么样(北极星)。

第二步顶上会告诉你**这个仓被 buddy 接管过没有**(判据:去远端读 `.bw/project.toml`):

| 你会看到 | 意思 | 你该做什么 |
|---|---|---|
| 已经被 buddy 接管过 | 同事先接过,或你以前接过 | 四格是回显出来的,直接改;接入不会覆盖仓里已有的字 |
| 还没被接管过 | 仓在,就是没这份文件 | 四格自己填 |
| 找不到这个仓 | 地址敲错、私有仓没权限、没登录 | 先把地址改对——接一个不存在的仓,后面每步都会失败 |
| 没查成 | 网不通、默认分支不叫 main | 照样能接;仓里真有名片的话,接入时以仓里的为准 |

「没查成」不等于「没被接管过」——混成一句的话,你会照着空格子填一遍,反而把仓里真正的名片盖掉。

### 点「完成接入」之后会发生什么

界面一步一句摆出来,做完的那行原地换成结果。这一下要十几秒,别猛点:

1. **取仓**——目录里已经是 git 仓就直接用(顺带把它的 origin 报出来给你核对);目录不在或是空的就 clone;没填远端就建个空目录并说明;目录里有东西又不是 git 仓就**当场弹回**,不敢往里写。
2. **库里落一行项目**——只存定位(名字、本机路径、远端地址),名片不进库。
3. **写名片**——`.bw/PROJECT.md` 等文件;仓里已有的一个字不覆盖,只补空着的字段。
4. **自动建一张「规范铺底」的活**——它开一条分支、往仓里写规范骨架、提一个 MR,然后**停在评审中等你合**。它不会自动合,也不会把活标成完成。
5. **自动进这个项目。**

第 4 步这次只铺你马上要用的几份,全在 `.bw/` 底下;其余的(指标正本、周计划目录、发版记录……)等你真走到那一站再出现。想提前补齐,「配置」屏那颗「规范铺底」点一次就全铺上。

### 几件你会注意到的事

- **buddy 铺进你仓的东西全在 `.bw/` 里,仓根一个字不动**——你的 README、CLAUDE.md、AGENTS.md、docs/ 这一步全不碰。`ls .bw/` 一眼可数哪些是 buddy 的。
- **buddy 自己的规矩不往你仓里写**(完成由人点、合并永远是人……这些每次开工现给 agent),**buddy 自带的技能也不进你的仓**;你仓里 `.claude/skills/` 下的技能仍然是你自己的。
- 想让 buddy 给你的项目写一份开发手册(仓根 `AGENTS.md`)?那归「资产盘点」那一站:buddy 真读一遍你的仓、摊给你看、**你点头才写**——给你的项目加东西是在改你的项目,得先问过你。(这一步还没实现,见 [`../LEFTOVERS.md`](../LEFTOVERS.md)。)
- **第 4 步没成不会推翻前面**:项目已接进来、仓已在本机,这两件是真的。回头在「配置」屏点一次「规范铺底」重来即可——重来不会多建一张活。

### 接错了怎么办

项目卡右上角的 ✕:点一下先问一句,再点「移走」才真移走。它只把项目从工作台移出去(项目行和它所有活的账),**仓一个字节都不动**——硬盘上的代码还在原地。回执会告诉你仓在哪儿,真要删你自己去删。

### 这一站结束时你手上有什么

本机一个真实的仓;工作台上一个项目;一张停在「评审中」的「规范铺底」活和它在远端的 MR。**下一步是去合那个 MR**——合完,这个仓就有管理体系的正本了。

## 还没走到的站(只留标题,不编步骤)

想提前知道它们打算怎么做,看设计正本 [`../v4-prototype/design.md`](../v4-prototype/design.md)——但那是设计,不是实况。

| 站 | 打算做什么 |
|---|---|
| 第 1 站 · 周一看总览 | 这项目是什么、健康吗。第一次多半是灰的(没数据 = 灰,不是绿) |
| 第 2/3 站 · 开始本周 | 一次 agent 会话里做完「复盘上周 → 更新指标 → 定本周目标和活清单」 |
| 第 4 站 · 干活 | 每张活按类别选开工工具,agent 在这张活自己的工作目录里干,你在内嵌终端里全程看得见、随时能停 |
| 第 5 站 · 验收闭环 | 提交并开 MR → 评审 → 合入 → 你点完成 → 记发版 |
| 第 6 站 · 定时 | 资产盘点自动建活并自动开工,停在评审中;下周一回到总览 |

每走完一站,那一站的改动合入之前,把它从这张表搬上去写成实况步骤。

## 出问题的时候,界面会怎么对你

buddy 的一贯做法是**失败如实**:列不出仓列表就把命令报错原话摆给你;探测不到某个工具,对应入口灰掉并写一句怎么装;agent 中途断了,活如实停在「进行中」可重试,不冒充失败也不假装完成。看到灰和报错原话,不是坏事——那是它没在骗你。
