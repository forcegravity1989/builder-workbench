## 1. 组织方式

使用指导按**界面操作的站**组织(今天是第 0–6 站 + 概览「每周怎么转」)。实践推进到哪、能见到哪,就写到哪;不预先猜未来的站。截图在本地 `docs/guide/img/`(gitignore)。

## 2. 每站屏结构

每站四段式:**操作 → 背后 → 得到什么**(+ callout 坑 + foot 事实源)。「背后」讲这一步做完 Workbench 自动干了啥(白话),「得到什么」讲用户手上多了啥、关注啥。

```
<eyebrow>   怎么用 · 第 X 站
<h1.disp>   站名
<lede>      一句话定位(用户视角,讲心智不是讲机制)
<h2.sec> 操作        → .ops 有序步骤
<img>       截图按步放(每步下面放该步的截图,不堆在末尾)
<h2.sec> 背后        → .res 三轴白话(见下)
<h2.sec> 得到什么    → .res 用户手上多了啥
<callout>           可选:该站坑/边界
<.foot>             事实源脚注
```

### 必填内容

- **操作**:界面上的真实操作步骤,按序号写,能照着点。截图按步放;本质上同一界面的步可共用一张。
- **背后**:点完关键操作(如「确认」)Workbench **一次性**在背后干了啥。用**白话三轴**组织,不按 `Command::` 代码命令、不用增删改查的开发话术:
  - **对远端代码仓**(GitHub/CodeHub):建仓 / 开 Issue / 推提交……
  - **对用户的机器**:clone / 写文件 / 探活……
  - **对 `.bw/` 仓文件**:写名片/指标/规范件(正本走 MR,本地零库)……
  - 给个地址 + 一笔核心信息描述即可;代码级细节(具体字段/函数)属于 `docs/architecture.md`,这里只讲用户能感知的。
- **得到什么**:用户走完手上多了啥、该关注啥(不是"看到界面呈现"的流水账,是"你得到了什么能力/资产")。

## 3. 组件清单(class 名 + 用途)

现行指南在用的:

| class | 用途 |
|---|---|
| `.ops` + `.li` | 操作有序步骤(带序号圆点) |
| `.res` + `ul/li` | 结果清单(背后 / 得到什么) |
| `.callout` `.warn/.note/.danger` | 提示框(坑/说明/铁律) |
| `.diagram` + `.cap` | 主图外框 + 图注(概览页的六站图等) |
| `.ktable` | 关键表(文件/命令/状态对照) |
| `.rules` + `.rule` | 铁律四宫格 |
| `.checklist` + `.chk` | 安装清单(第 0 站前置) |
| `pre.code` | 代码块 |
| `.foot` | 事实源脚注(每站末必填) |

新内容优先复用上表组件;为可读性可少量增加组件,须落在暖纸 token 内,禁止为单页发明第三套视觉语言。V3 期专给「维护指南」用的组件(`.stages` / `.pipe` / `.split2` / `.cc` / `.linker` 等)已随两本结构退役,见 git 历史。

## 4. 加一个新站

实践推进到新站时:

1. 复制一个现有站 `<section class="screen" id="uX" data-title="第 X 站 · 站名" data-sec-name="怎么用">`,按四段式填。
2. 侧栏「怎么用」组加一行 `<div class="nav-item" data-screen="uX">`。

`data-screen` 指向 `id`,JS 自动接管切换 + localStorage 持久化(key `Workbench-v4-guide-screen`),无需改 JS。

## 5. 内容规范

- **真实实践优先**:只写已实践/已可见的操作;没走到的站只留章节名占位(一句「还没走到」+ `.foot` 标事实源),不预先填内容。
- **用户语言**:按钮名、界面结果、白话后果;开发契约/字段/缺陷编号不进指南。
- **术语统一**:以 `CONTEXT.md` 为唯一规范词表(Builder / 队友 / 阶段 / 迭代 / Issue / 读数 / 指标 / 信号 / 北极星 等),不自造同义词。
- **诚实口径**:无数据 = Unknown ≠ 绿;Done 永不自动;手填带徽;数字可 `codehub-cli`/`gh`/`git`/`cat .bw/…` 读回(本地零库,不用 sqlite3)。涉及健康处必须重申。
- **事实源脚注**:每站末 `.foot` 必填,宜短(实跑/设计文档即可);表名、文件名、命令、状态值用 `code` 包裹(真实值)。
- **机制细节指 architecture**:一句话讲不完的机制,指 `docs/architecture.md` 对应模块,不在指南里复写第二份。

## 6. 视觉规范摘要(Workbench 自有设计系统)

- **色**:暖纸底 `#EFEBE2` / clay 主色 `#C5654A`(文本用深调 `#A84A30`);信号四态:Green 隐身、Amber 黄、Red 红、Unknown 灰。绿色不出声,只有红黄出声。
- **字**:Noto Serif SC(display)/ Noto Sans SC(body)/ JetBrains Mono(code·数字)。
- **字距**:ALL CAPS ≥ 0.06em;display 标题 -0.02em;body 行高 1.6。
- **accent 节制**:clay 作结构色(序号/eyebrow/激活态),不泛用为 CTA。
- token 全在 `:root`,改一处全局生效。
