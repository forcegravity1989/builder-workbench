# Intent · 总览做成项目健康看板

> **30 秒导读**：这是什么——#36 的意图件：总览按人定的目标态重排，做成能看清项目是什么、版本在推什么、指标有没有带动结果的健康看板。给谁看——过意图 / 规格 gate 的人。现在作数吗——**谈定**（2026-09-03 会话拍板，高保真 [`docs/hifi/overview-36.html`](../../hifi/overview-36.html)）。

**发起人**：产品会话 2026-09-03（#36）。**状态**：谈定，已落地待合入。

## 痛点

打开总览，人要回答三句话：这项目是什么、这周这个版本在推什么、指标有没有朝目标走。现行总览做不到：

- 健康占一整栏，北极星另起一行，第一眼看的是灯不是目标。
- 滞后和引领各开一块，看不出「这条引领是不是在带动那条滞后」。
- 版本目标和周进展埋在「本周计划进度」里，和历史发版另开一块；发版记录重复了计划屏已经有的 tag。
- 项目指标铺了说明性空话，现行三条（提交 / 合入 PR / 未处理 issue）有时灰着，人以为没采。
- 图只有周，没有天；手填框不写是哪条指标。

## 解决方案（体验语言）

总览仍是**项目健康看板**，不是 SDLC 地图，也不是看板。

- 第一行：左名片（健康只是名字旁边一颗灯），右北极星。没读数就是灰「—」，Unknown ≠ 绿。
- 版本计划与进展：页签切在研 / 历史版本。左版本目标、右每周进展，各能装 6 行，多了框内滚。下面是进度条，只报数，不列 issue。
- 滞后和引领合在一块。页签按指标上的「所属特性」分：没写就是「主要」，写了才出「XX特性」。栏默认就在。一张图 = 一条滞后 + 它带着的 0 到多条引领。同一页签多条滞后就多张图横排。没写关联的引领，落到该页签第一条滞后上。图例可勾选显隐。手填写在对应滞后那一行，标签就是指标名。
- 项目指标 · SDLC 只留现行三条，用已经在采的数画图。周 / 天可切。不发明 12 宫格，不写「距上次发版天数」，不另开「发版记录」。

ISO 周仍是节律（周初定计划、健康看哪几天、周五盘点），不当版本名。

## 飞轮检验（对齐 03）

- **加强哪一截**：定框——人看见自己定的版本目标和指标，而不是一排工程虚荣数。
- **不把人拽回搬运工**：不新人肉对账滞后/引领；图上直接叠。采集仍是一颗按钮 / 打开时现算，不铺进被管仓。
- **不破坏铁律**：没数据不装绿；完成仍由人点；进度条只报挂了这个版本的活，不代人点完成。

## 约束

- 总览不做特性拆业务指标的产品决策以外的事：`feature` / `leads` 是定义字段，UI 按字段分页签；本仓当前两条都没写特性，只出「主要」。
- 更多 SDLC 指标、采集脚本搬进 Workbench、codehub/GitHub 采集归一，另窗。
- `principles/03` 不动。词表补「所属特性」「引领关联」。

## 五大拷问摘要

| 拷问 | 答案 |
|---|---|
| 谁是客户？ | 每周要看「这项目还健康吗、这个版本推到哪」的单人 Builder。 |
| 痛点？ | 总览块多、图拆开、看不出引领有没有带动滞后；SDLC 三条有数却灰着。 |
| 核心利益？ | 一屏看清名片、北极星、版本进度、滞后是否被引领带动、仓过程三条。 |
| 如何知道？ | 发起人连续拍板（会话 2026-09-03）：看板不是地图；图的最小单元是一条滞后带若干引领；多滞后横排；没写 leads 落到第一条滞后；手填写清指标名；SDLC 只用现行三条真数；图上可切周/天。 |
| 体验什么样？ | 见同目录 `spec.md` 与 [`docs/hifi/overview-36.html`](../../hifi/overview-36.html)。 |
