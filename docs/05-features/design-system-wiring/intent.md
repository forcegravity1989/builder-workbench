# Intent · 壳接上 Builder 设计系统

> **30 秒导读**:这是什么——把 `docs/04-design-system/` 里那套已经落仓、但一直「未接线」的 Builder 设计系统真正接进桌面壳:壳编译期直接拼入它的样式表,八屏的按钮、标签、表单、卡片、侧栏、页签、列表、看板、弹窗、回执全部改用它的组件类与 token。给谁看——过意图 / 规格 gate 的人。现在作数吗——**谈定**(2026-09-07,发起人以 `/goal` 直接下达「根据 system design 规范文档刷新所有 UI/UX 设计元素」,视为意图 gate 已过)。

**发起人**:产品会话 2026-09-07。**状态**:谈定,已落地待合入。

## 痛点

- 设计系统 2026-08-31 落仓后,壳仍跑着从高保真 `<style>` 块搬来的一整张 `hifi.css`:自己一套 token(`--clay` / `--ink-3` / `--paper`……)、自己一套组件类(`chip` / `btn-sm` / `modal` / `il-pill`……)。两套正本并存,改颜色要改两处,新界面不知道抄哪边。
- 高保真的类名是原型顺手起的,不成体系:同一个「状态标签」在看板叫 `kcard-src`、在列表叫 `il-pill`、在项目墙叫 `chip`;同一个「切换」在总览叫 `ov-seg`、看板叫 `seg-tab`、接入叫 `pill`。
- 屏里散落 140 多处带色号 / 字号的行内 `style`,主题一动就漏。
- 衬线标题 + 暖纸底的视觉和设计系统定的「安静、密、精确的工具界面」不是一回事。

## 解决方案(体验语言)

打开 Workbench,看到的是 Builder 设计系统 **Claude 配色**下的工具界面:象牙白底、赤陶色只用于主操作与链接、发丝线分结构、系统字体(中文走苹方 / 微软雅黑)、4px 网格、6–12px 圆角。

- 项目轨是标准侧栏(28px 行,当前项 8% 墨色);顶栏 44px 发丝线;图标轨在表面色上。
- 按钮只有 primary / secondary / ghost / danger 四种,每个视图一颗实底主按钮;取消 / 关闭永远安静。
- 状态一色一态:待办中性、进行中警示色、待评审第二强调色、完成成功色、阻塞危险色,看板列头、卡片、列表、标签全用同一套。
- 分段控件与页签是设计系统的 `.seg` / `.tabs`,不再各屏各画。
- 弹窗在浮层级、40% 遮罩;回执 toast 是底角深色条,点「关闭」才走(不自动消失,失败原话不能藏)。
- 卡片不套卡片:总览的指标小盒子改成发丝线分隔的行。
- 没数据仍是灰,不是绿。

## 飞轮检验(对齐 03)

- **加强哪一截**:「可信所以敢放手」——界面一套语言、一处正本,人看得快、AI 改得准。
- **不把人拽回搬运工**:改一个 token 只改 `styles.css`,壳下次编译自动跟上;设计侧改了走 `design-system-import` 拉回。
- **不破坏铁律**:纯视觉层,不碰状态机、现算、完成由人点。

## 约束

- 只改壳(`crates/app-shell`)的样式与标记,不改行为、命令、内核。
- 不为旧 `hifi.css` 留兼容层:旧 token 与旧类名整体删除。
- 高保真 `docs/hifi/` 降为版式与旅程原型,不再是样式来源。
- 配色选 Claude 板(与产品既有暖色身份连续);Apple 板留在样式表里,切一个属性即可换。
