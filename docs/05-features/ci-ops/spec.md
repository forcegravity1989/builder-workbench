## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；操作在 CI 固定树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

CI 屏是项目级入口，与项目总览、任务、自动化、知识库同级；左侧为 Orca 原生会话（该会话的产品称呼为「CI 助手」），右侧为业务板面，与计划/验收两屏同构。首次进入经原生工作树能力创建 bw/ci 固定树；执行记录与错误日志存该树本地 `.bw/ci/`，默认不上仓。

**页头与计划/验收屏同构**：标题左、动作右同一行——标题「CI」+ 会话收折 chip +「更新代码」（唯一同步入口，把主检出快进到主干最新并重读资产与记录）+「配置自动化」（打开原生自动化编辑器，轮询模块的定时调度在这里登记与停用）。不设批注模式：本屏无会中逐对象评审事务。板面动作按钮一律图标+短动词统一格式。

**板面为单页纵向四区 + 记录区**：部署 → 监控 → 故障检测 → 重启 → 执行与报错记录。顶部模块状态导航复用旅程导航形态（序号+模块名+状态短语，滚动侦测高亮、点击定位），四枚状态灯在导航行一眼可比；导航只做同页定位，不是门禁。**板面不铺说明文本**：模块语义、脚本路径、轮询间隔等工作机制收在按钮提示与 ci-ops skill 正本，板面只留状态、读数与动作；轮询间隔配在自动化调度里，不在板面展示。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 留下什么 |
|---|---|---|
| 接入 | 首次进入四灯全灰；人点「生成脚本」，CI 助手按 ci-ops skill 模板结合项目实际代码生成四脚本，提 PR 经人审合入 main；板面 5 秒扫描主检出，扫到资产灯灰→黄 | 项目 main 里的四模块脚本资产、黄灯 |
| 部署 | 人点「部署」，请求注入 CI 助手会话；脚本把已发布版本的包装到指定环境，完成后独立读回服务状态与版本并写记录 | 生产环境里跑起来的服务、部署记录 |
| 监控与检测 | 人点「启动」，经 Orca 自动化登记定时调度，到点真实开会话执行脚本；监控查服务可用性，故障检测按指标与日志查关键功能报错；每轮写记录 | 每轮读数记录、运行中的轮询 |
| 故障与重启 | 轮询报错置红灯并落记录；人按需先停止监控/检测（灯回黄、历史保留）；人点「重启」，基于已发布版本的包快速重新拉起，读回写记录 | 报错记录与日志、恢复记录 |
| 记录回看 | 记录区按时间倒序回显全部执行与报错，按模块筛选；报错条目默认折叠，页内展开看日志原文 | 可追溯的运行历史 |

## 行为规则与异常

### 四模块语义

- **部署**：把已发布版本的安装包部署到指定环境（生产机器），完成后独立读回服务状态与版本并写执行记录。单次执行，人点按钮注入请求。
- **监控**：轮询检查整个服务的可用性（在线/离线、健康端点）。轮询执行，经 Orca 自动化到点开会话。
- **故障检测**：按指标与错误日志轮询检查关键功能是否报错；越线判定用阈值与控制带，不用模型判断「有没有事」。轮询执行。
- **重启**：服务不可用时，基于已发布版本的包快速重新拉起——同版本同环境、跳过完整检查，尽快恢复可用。单次执行，**人触发**；自动自愈是后续演进，不在本版。

### 状态灯（健康信号）

灯只能从真实读数推导，store 不提供手设绿灯；没数据就是灰，不是绿。

| 灯态 | 含义 | 进入条件 |
|---|---|---|
| 灰 | 未接入 / 未知 | 5 秒扫描主检出未见该模块脚本 |
| 黄 | 已接入 · 待执行 / 未启动 | 扫到脚本且无执行记录，或轮询模块被停止 |
| 绿 | 最近成功 / 运行中 · 最近一轮通过 | 单次模块最近一次执行成功；轮询模块运行中且最近一轮通过 |
| 红 | 最近失败 / 最近一轮报错 | 单次模块最近一次执行失败；轮询模块最近一轮报错 |

- **停止回黄**：运行中的监控/故障检测可随时停止，灯回黄，已写记录保留；重新部署期间大概率误报，允许人预先停止。
- **最新结果决定绿红**：报错后下一轮通过即回绿，不锁死；历史报错永久保留在记录区，不因后续通过消失。
- 灯永远配文字状态短语（如「运行中 · 最近一轮报错」），不用裸灯表态。

### 接入与脚本资产

灰态模块卡给「生成脚本」按钮，接入机制说明收在按钮提示与 skill 正本，不占板面。生成请求注入 CI 助手会话：按 ci-ops skill 的模块模板，结合本项目实际代码（构建方式、部署入口、服务形态、运行环境）生成 `.bw/ci/deploy.sh`、`monitor.sh`、`health-check.sh`、`restart.sh` 与使用说明，提交项目仓 PR，**经人审合入 main**——板面不直接写脚本，不绕过评审。板面每 5 秒扫描主检出固定路径，扫到资产灯灰→黄；「更新代码」把主检出快进到主干最新后立即重扫。脚本路径固定，不按项目另设路径。

### 执行

所有执行都是会话驱动，板面按钮与在会话里直接说同一请求等价：

- **单次（部署/重启）**：人点按钮，请求经 Orca 原生发送弹窗递交 CI 助手；脚本在会话中执行，完成后**独立读回**（服务状态、版本、耗时）并写执行记录。成功绿、失败红，失败原因进记录。
- **轮询（监控/故障检测）**：人点「启动」，经 CI 助手登记 Orca 自动化定时调度（监控默认每 5 分钟、故障检测默认每 15 分钟，间隔可在原生编辑器调整）；到点真实开会话执行脚本，每轮结果写记录。启动与停用不改变定时登记的启用状态以外的任何记录。
- 执行期间按钮呈执行中瞬态；重复点击不重复启动。
- 助手在部署/重启执行前若监控或故障检测正在运行，提醒人可先停止以避免误报，由人决定，不自动停。

### 记录与错误日志

- 每轮/每次执行结果写 bw/ci 固定树本地 `.bw/ci/records.jsonl`（时间、模块、结果、摘要）；报错附日志文件。**默认不上仓**：生产报错内容不进代码评审流；脚本资产在项目 main，代码与数据分离。
- 板面记录区按时间倒序回显全部执行与报错，可按模块筛选；报错条目默认折叠，**页内展开回显日志原文**——不让用户去后台看文件。日志只读回显，不在板面编辑。
- 记录永久保留，不自动清理；「最新结果决定绿红」以记录为正本推导。

### 异常

- 脚本执行失败、轮询报错：红灯 + 记录 + 日志，如实呈现失败原因，不降级为「未知」。
- 主检出读不到、扫描失败：灯保持原状或灰，不装绿；连接不可用呈现原生失败。
- 记录文件缺失或损坏：板面如实显示读不到，不伪造记录。
- 自动化调度未登记就点启动：助手先登记再启动，不静默失败。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| C01 | 新项目首次进入四灯全灰、无预置记录，灰态给生成脚本入口；不装样子 |
| C02 | 脚本经人审合入 main 后，扫描在 5 秒内把对应模块灯灰→黄；未见脚本保持灰 |
| C03 | 部署单次执行：请求注入会话、脚本执行、独立读回写记录；成功绿、失败红且原因进记录 |
| C04 | 监控轮询：启动经自动化登记、到点真实触发、每轮写记录；通过绿、报错红 |
| C05 | 故障检测按阈值/控制带判定，报错红 + 记录；不用模型判断有没有事 |
| C06 | 停止回黄：停止后灯黄、按钮变启动、历史记录保留；可再启动 |
| C07 | 重启人触发：基于已发布版本的包快速重拉、读回写记录；不自动自愈 |
| C08 | 记录区回显全部执行与报错、按模块筛选、报错默认折叠页内展开看日志原文，不需要人去后台 |
| C09 | 执行记录与错误日志存 bw/ci 树本地、默认不上仓；脚本资产在项目 main 经人审合入 |
| C10 | 灯不可手设、没数据为灰；杀进程重开灯与记录从真实数据重新推导、前后一致 |

CJ01：首次进入（全灰）→ 生成脚本 → 人审合入（全黄）→ 部署（绿）→ 启动监控与检测（绿）→ 制造故障（检测红 + 记录 + 日志页内展开）→ 停止监控（回黄）→ 重启（恢复绿）→ 记录筛选回看 → 杀进程重开核对灯态与记录一致。无真实脚本执行、真实报错与真实恢复读回的模拟不能计 CJ01 通过。
