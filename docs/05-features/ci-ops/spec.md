## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；操作在 CI 固定树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

CI 屏是项目级入口，与项目总览、任务、自动化、知识库同级；左侧为 Orca 原生会话（该会话的产品称呼为「CI 助手」），右侧为业务板面，与计划/验收两屏同构。首次进入经原生工作树能力创建 bw/ci 固定树；执行记录与错误日志存该树本地 `.bw/ci/`，默认不上仓。

**页头与计划/验收屏同构**：标题左、动作右同一行——标题「CI」+ 会话收折 chip +「更新代码」（唯一同步入口，把主检出快进到主干最新并重读资产与记录）。不设批注模式。板面动作按钮一律图标+短动词统一格式。

**板面为单页纵向两区**：部署卡 → 执行与报错记录。部署卡自上而下：模式切换（开发/上线）→ 版本选择（仅上线）→ 统一「配置」入口与已配置/未配置事实 → 三阶段六步流程条 → 最近一次读数 → 动作行；进入即见全量形态，不靠切换展开。**板面不铺说明文本**：机制与配置（脚本资产、扫描机制、服务器信息）收在按钮提示与 ci-ops skill 正本；板面只留事实——状态、读数、流程步骤推进、灰态扫描结果（「主分支未见脚本」）与动作。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 留下什么 |
|---|---|---|
| 接入与配置 | 首次进入灯灰、无预置记录；人点「生成部署脚本」，CI 助手按 ci-ops skill 勘察项目实际代码与已有资产，生成 `.bw/ci/deploy.sh`（复用优先），提 PR 经人审合入 main；配置走部署卡统一「配置」入口——向 CI 助手递交配置请求（开发启动命令与端口、探针 URL、上线服务器信息），已有配置先读出确认、缺失经会话收集，落项目资产随脚本同审；板面只显示「已配置/未配置」；扫描扫到资产灯灰→黄 | 项目 main 里的部署脚本与配置资产、黄灯 |
| 开发部署 | 人点「部署」（开发模式），六步流程在本地跑：软件包准备（校验启动命令）→ 预检（端口/旧实例）→ 清场（杀旧进程）→ 部署（执行启动命令）→ 验证（本地探针）→ 记录 | 本地跑起来的服务、一条带流程结果的记录 |
| 上线部署 | 人选版本（来自验收屏的包登记，默认最新），点「部署」（上线模式），六步流程在远端跑：软件包准备（校验所选包）→ 预检（连通/磁盘/目录）→ 清场（远端停服务）→ 部署（上传解包启动）→ 验证（探针+版本核对）→ 记录；服务器密码在部署执行时输入（密文显示、不可复制、不落盘不进记录） | 远端环境里跑起来的指定版本服务、可追溯的部署记录 |
| 失败与重试 | 任何步失败流程**停在该步**，红灯+失败步定位进记录，日志页内展开；修复后「从失败步重试」，已完成步不重复执行 | 如实的失败记录与重试路径 |
| 记录回看 | 记录区按时间倒序回显全部执行与报错（含模式与版本）；报错默认折叠，页内展开看日志原文 | 可追溯的运行历史 |

## 行为规则与异常

### 部署语义与两种模式

把版本部署到目标环境并独立读回写记录。单次执行，人点按钮注入请求。两种模式共用同一条流程与板面形态，差异收在 per-project 资产：

- **开发部署（本地）**：在本地执行启动命令把服务跑起来。启动命令不暴露在板面——由用户经会话输入、模型落进项目资产（后续支持模型与用户聊着自动从项目获取）。
- **上线部署（远端）**：连接服务器（IP/用户/上传路径来自配置资产；密码部署执行时输入），把所选版本的软件包部署到远端并启动。**软件包来自验收屏的包登记**（`preparedArtifacts`：版本 → 包路径；包由项目自己的构建工具产出，无集中存放处）。

### 部署流程：三阶段六步（两种模式同骨架）

| # | 阶段 | 步骤 | 开发部署 | 上线部署 | 通过判据 |
|---|---|---|---|---|---|
| 1 | 部署前准备 | **软件包准备** | 无包模式：校验启动命令已配置 | 从验收登记选版本包，校验文件存在可读 | dev：命令已配置；release：包在（包没了→该版本项灰掉，选不了） |
| 2 | 部署前准备 | **预检** | 端口占用、旧实例探测 | ssh 连通、磁盘余量 ≥ 包大小×2、目标目录存在 | dev：端口空闲**或探到旧实例**（旧实例≠失败，是待清场）；release：三项全过 |
| 3 | 部署前准备 | **清场** | 杀本地旧进程、等端口释放 | 远端停服务（systemd stop / 杀进程） | 旧进程退出+端口释放；无旧实例 → 显示「跳过」不报错 |
| 4 | 开始部署 | **部署** | 执行启动命令拉起服务 | 上传包 → 远端解包 → 按项目方式启动 | dev：进程拉起且 3 秒不退；release：远端命令退出码 0 + 解包非空 |
| 5 | 部署后验证 | **验证** | 本地探针（未配探针退化为进程存活） | 远端探针读回 + **部署目录版本 = 所选包版本** | 探针 ok / 退化判据过；版本对不上 → 红 |
| 6 | 部署后验证 | **记录** | 写 records.jsonl（模式、版本、各步结果、失败步定位、耗时） | 同左 | 追加成功 |

**排序原则**：软件包准备在最前——**没有可用包（或未配置启动命令）时，失败发生在清场之前，不该把正在跑的服务停了**；破坏性步骤（清场）尽量晚、且只在确定要部署时执行。

**失败与重试**：任何步失败 → 流程停在该步，红灯 + `failedStep` 进记录，该步日志可页内展开；「从失败步重试」只重跑失败步及其后步骤，已完成步不重复执行（清场过的不用再清）。

### 状态灯（健康信号）

灯只能从执行记录推导，store 不提供手设绿灯；没数据就是灰，不是绿。

| 灯态 | 含义 | 进入条件 |
|---|---|---|
| 灰 | 未接入 / 未知 | 5 秒扫描主检出未见 `.bw/ci/deploy.sh` |
| 黄 | 已接入 · 待执行 | 扫到脚本且无执行记录 |
| 绿 | 最近一次成功 | 记录最近一条流程全步通过 |
| 红 | 最近一次失败 | 记录最近一条停在失败步 |

最新结果决定绿红；历史报错永久保留；灯永远配文字状态短语。

### 接入与配置资产

- **脚本资产**：`.bw/ci/deploy.sh` 固定路径，按 ci-ops skill 生成（勘察→复用已有资产优先→缺失才生成），PR 经人审合入 main；板面不直接写脚本。
- **配置资产与统一「配置」入口**：六步流程所需的配置——开发启动命令与端口、探针 URL、上线服务器信息（IP/用户/上传路径）——由部署卡内统一「配置」按钮向 CI 助手递交配置请求：已有配置先从项目资产读出给人确认，缺失或要改的经会话收集，落项目资产随脚本同审。板面随模式显示各配置项「已配置/未配置」事实，不显示配置内容。**密码不是资产、不进配置**：只在部署执行时输入（密文显示、不可复制），不落盘、不进记录、不进日志。
- 板面每 5 秒扫描主检出固定路径，扫到资产灯灰→黄；「更新代码」快进主检出后立即重扫。

### 版本选择（上线模式）

- 数据源：各版本验收材料里的包登记（版本 → 包路径），不另建版本登记表；无登记时版本选择如实显示「验收屏未见包登记」。
- 默认选中最新一个包；包文件被清理/不可读 → 该版本项灰掉并标「包不存在」，不隐藏（历史记录引用的版本对得上号）。
- 所选版本进执行记录，可追溯。

### 执行

会话驱动，板面按钮与在会话里直接说同一请求等价：人点按钮，请求（含模式与所选版本）经 Orca 原生发送弹窗递交 CI 助手；脚本在会话中真实执行，**按步骤标记协议输出进度**（`[ci-step] <步骤> <start|ok|fail|skip>`，协议正文见 [skill-deploy](skill-deploy.md)），板面流程条据此逐步点亮。执行期间按钮呈执行中瞬态；重复点击不重复启动。助手不自动重试——失败如实红，恢复靠人修复后从失败步重试。

### 记录与错误日志

- 每次执行结果写 bw/ci 固定树本地 `.bw/ci/records.jsonl`：时间、`ok`、`mode`（dev/release）、`version`（上线所选版本）、`steps`（各步结果）、`failedStep`（失败定位）、读回读数、`elapsedMs`、日志指针。协议正文见 [skill-deploy](skill-deploy.md)。**默认不上仓**。
- 板面记录区按时间倒序回显全部执行与报错（含模式与版本）；报错条目默认折叠，**页内展开回显日志原文**。记录永久保留，不自动清理。

### 异常

- 脚本执行失败：红灯 + failedStep + 记录 + 日志，如实呈现，不降级为「未知」。
- 主检出读不到、扫描失败：灯保持原状或灰；连接不可用呈现原生失败。
- 记录文件缺失或损坏：板面如实显示读不到，不伪造记录。
- 密码输入后连接失败：如实报错，密码不因重试而缓存复用，重新输入。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| C01 | 新项目首次进入灯灰、无预置记录，灰态给「主分支未见脚本」事实与生成脚本入口；不装样子 |
| C02 | 脚本经人审合入 main 后，扫描在 5 秒内把灯灰→黄；未见脚本保持灰 |
| C03 | 部署流程执行：六步流程条逐步推进可见、成功全步通过绿；失败停在该步红、failedStep 进记录 |
| C04 | 从失败步重试：修复后从失败步重跑，已完成步不重复执行 |
| C05 | 版本选择（上线）：列验收登记的版本包、默认最新、包不存在灰掉并标注；所选版本进记录 |
| C06 | 两种模式：开发=本地流程（无包选择、校验启动命令）；上线=远端流程（含包选择与服务器配置）；模式进记录 |
| C07 | 记录区回显全部执行与报错（含模式与版本）、按时间倒序，报错默认折叠、页内展开看日志原文 |
| C08 | 执行记录与错误日志存 bw/ci 树本地、默认不上仓；脚本与配置资产在项目 main 经人审合入；密码不落盘不进记录 |
| C09 | 灯不可手设、没数据为灰；杀进程重开灯与记录从真实数据重新推导、前后一致 |
| C10 | 统一「配置」入口：部署卡「配置」按钮向 CI 助手递交配置请求（开发启动命令与端口、探针 URL、上线服务器信息），已有配置先读出确认；板面随模式显示各配置项已配置/未配置；密码不经此入口 |

CJ01：首次进入（灰）→ 生成脚本与配置（合入后黄）→ 开发部署（六步绿）→ 上线部署选历史版本（绿、记录带版本）→ 制造失败（红 + failedStep + 日志页内展开）→ 从失败步重试（回绿、已完成步未重跑）→ 记录回看 → 杀进程重开核对灯态与记录一致。无真实脚本执行、真实报错与真实重试读回的模拟不能计 CJ01 通过。

## 取舍与待决问题

**已决（设计对话拍板，2026-10-27/28/29）**：灯态机四态；最新结果决定绿红、历史报错永久保留；灰→黄由「skill 规范格式 + 5 秒扫描主分支文件」判定；错误日志存 CI 固定树本地、默认不上仓、前端折叠回显；板面文本精简（机制与配置不上板面，板面只留事实与动作）；**只做部署模块**，复用项目已有资产优先；**修订而非另立**：两种模式（开发/上线）、上线选版本（数据源=验收包登记，默认最新，包不存在灰掉）、三阶段六步流程（软件包准备最前——无可用包不动正在跑的服务；清场独立成步；从失败步重试）、流程条板面（摆法 A）、密码部署时输入（密文、不可复制、不落盘）、记录协议加 mode/version/steps/failedStep、探针未配退化为进程存活+退出码；**2026-10-29 评审反馈**：六步流程配统一「配置」入口（配置请求经会话落资产，板面只显示已配置/未配置）；原型不做场景切换、进入即呈现已接入后的全量形态。

**仍待决**：

1. **监控/故障检测/重启三模块**：转后续演进，部署模块在真实项目用稳后再议。
2. **多环境维度**：是否扩环境选择（测试/预发/生产）与按环境分灯。
3. **告警通知通道**：报错是否推 WeLink 等外部通道。
4. **启动命令自动获取**：模型与用户聊着从项目自动推断启动命令（v1 为用户经会话输入）。
5. **脚本模板细则**：gate 后落 `standard/skills/ci-ops/`，随首批真实项目使用打磨。
