# CI：让发布后的生产部署看得见、管得住

> 给 Builder、Leader 与负责人判断价值和范围时读；本文管用户目标，不写控件与实现。行为见 [spec](spec.md)，证据见 [STATUS](STATUS.md)。目标或边界变化时更新。
>
> 状态：**草案待人确认（[Issue #461](https://github.com/forcegravity1989/builder-workbench/issues/461)，2026-10-28）**——高保真原型已建（[prototype.html](prototype.html)）供评审；四模块语义、灯态机、记录与日志归属等关键决定已在设计对话中拍板，尚未过正式人 gate。原型与演示数据不代表任何能力已交付。

## 用户与问题

Builder 把版本发布出去之后，生产机器上的部署就成了 BW 的盲区：验收屏的「部署」只覆盖会中演示环境，发布后要在生产机器上装包、确认服务活着、出问题时快速拉起，只能回到终端里手敲命令。部署做了没有、服务现在是否在线、最近有没有报错，BW 一律看不见，也帮不上。

Leader 与协作者需要几分钟内读懂生产状态：部署到哪台环境、服务是否可用、出过什么故障、怎么恢复的。没有真实读数就只能问人，或者等用户投诉。

每个项目的部署入口、服务形态、健康口径、日志位置都不同，通用面板给不出真实读数——硬编码一套「标准部署」只会造出假绿灯。真实读数只能来自按项目实际代码生成的脚本资产，并且只能从执行结果推导。

## 价值与依据

给发布链路补上「发布之后」的一段：出包（项目流水线）→ 验收（演示环境）→ 发布 → **CI 屏（生产部署与运行读数）**。四模块（部署、监控、故障检测、重启）各配脚本资产与 ci-ops skill SOP，读数全部从真实执行推导，让「生产环境现在怎么样」成为一块能看的板面，而不是一句要去问的话。

依据为 #461 的明确缺口（生产部署无入口、无流程、无状态读回）与四铁律：信号只能从数据推导，没数据就是灰，不是绿；完成与恢复由人确认；定时任务真实到点触发。脚本资产按项目实际代码生成、经人审合入，沿用 standard/ 沉淀方法资产的既有做法。

## 目标体验

新项目第一次进 CI 屏，四个模块（部署、监控、故障检测、重启）的灯都是灰的——未接入，不装样子。人在灰态点「生成脚本」，CI 助手按 ci-ops skill 的模板结合本项目实际代码生成四个脚本，提 PR 经人审合入 main；板面每 5 秒扫描主检出，扫到资产灯变黄：已接入，待执行。

人点「部署」，请求进左侧 CI 助手会话，脚本在会话里把已发布版本的包装到指定环境，完成后独立读回服务状态并写执行记录——成功灯绿，失败灯红、报错进记录。监控与故障检测启动后由 Orca 自动化到点开会话轮询执行：监控查整个服务的可用性，故障检测按指标与日志查关键功能是否报错（阈值与控制带判定，不靠模型「感觉没事」）；每轮写记录，最近一轮通过绿、报错红。重新部署期间大概率误报，人可以先把监控与检测停掉——灯回黄，历史记录保留，部署完再启动。

监控发现服务不可用时，人点「重启」：基于已发布版本的包快速重新拉起，同版本同环境、跳过完整检查，尽快恢复可用；恢复结果读回写记录。

所有执行与报错在板面底部记录区回显：按时间倒序、可按模块筛选；报错条目默认折叠，点开在页内看日志原文，不用去后台翻文件。错误日志存在 CI 固定树的本地目录，默认不上仓——生产报错内容不进代码评审流。

## 范围与边界

- 包含：四模块脚本资产的生成链路（ci-ops skill 模板 + 项目实际代码 + PR 人审）、会话驱动的单次执行（部署/重启）、Orca 自动化轮询调度（监控/故障检测）、从读数推导的四态灯、执行与报错记录及前端回显、bw/ci 固定树的本地存储。
- **灯是健康信号，不可手设**：灰=未接入/未知，黄=已接入·待执行或未启动，绿=最近成功或运行中·最近一轮通过，红=最近失败或最近一轮报错；停止回黄；最新结果决定绿红；历史报错永久保留。没数据就是灰，不是绿。
- **重启由人触发**：监控红灯只是提示，不自动重启、不自动自愈；自动自愈是后续演进，不在本版。
- **错误日志不默认上仓**：执行记录与日志存 bw/ci 固定树本地 `.bw/ci/`；脚本资产在项目 main，代码与数据分离。
- 不做出包（出包归项目流水线与验收屏）、不做通用监控平台（读数来自项目自有脚本）、不重建会话或调度器（复用 Orca 原生）、不代判健康（阈值与控制带判定）、不替人确认任何完成。
- 单环境起步：先服务「指定环境」一个部署目标，多环境（测试/预发/生产）维度是否扩展见待决。

## 成功判据与待决问题

新项目首次进入四灯全灰；脚本合入后五秒内变黄；部署成功绿、失败红；轮询每轮落记录、报错红灯；停止回黄且历史不丢；重启后服务恢复、记录可追溯。报错在页内能展开看到日志原文，不需要人去后台。杀进程重开，灯与记录从真实数据重新推导、前后一致。

**待决**：①自动自愈（监控红灯时是否给一键重启建议或自动执行）；②多环境维度（是否扩环境选择与按环境分灯）；③告警通知通道（报错是否推 WeLink 等外部通道，随真实需要另议）；④四脚本模板细则归 ci-ops skill 正本，随首批真实项目使用打磨。
