# CI 部署 — 六环状态

> 给接手开发、评审和验收的人读取。只记录认可、实现和证据缺口；有真实认可或运行结果时更新。价值见 [intent](intent.md)，行为见 [spec](spec.md)，助手方法与 prompt 见 [skill-deploy](skill-deploy.md)。

**本特性处于设计阶段，尚无生产代码。** [Issue #461](https://github.com/forcegravity1989/builder-workbench/issues/461) 提出生产部署缺口后，按 02 逆向工作法先落 intent/spec 草案与高保真原型，交人 gate。2026-10-28 评审收敛：**只做部署模块**（目标是简化部署动作、帮助用户构建和使用已有的部署脚本；监控/故障检测/重启转后续演进），评审物从高保真原型扩展为四件——原型、ci-ops skill 草案（含递交 prompt 真实文本与记录协议）、真实项目样板间。**2026-10-29 第二轮修订**（设计对话拍板）：两种部署模式（开发=本地执行启动命令 / 上线=连服务器部署所选版本包）、上线版本选择（数据源=验收屏包登记，默认最新，包不存在灰掉）、六步流程（**软件包准备最前——没有可用包不动正在跑的服务**；清场独立成步；失败停在该步 + 从失败步重试）、流程条板面（摆法 A）、密码部署执行时输入（密文、不可复制、不落盘）、记录协议加 mode/version/steps/failedStep、步骤标记协议（`[ci-step]`）。**2026-10-29 评审反馈**：原型去场景切换、进入即呈现已接入后的全量形态；部署卡增统一「配置」入口（配置请求经会话落项目资产，板面只显示已配置/未配置，密码不经此入口；spec 增 C10）；流程条改数字徽章标序（1–6 常显，完成绿色实心，失败定位与记录文案同用步序号）；**同日四轮（grill 会话）**：流程改竖排列表为板面核心（每步读数内联——记录协议增 readings；块级整段日志开关；执行中自上而下推进）、记录区降位为默认收起摘要行（降位不删除；「报错记录」按钮=展开+只看报错）、黄态显示六步骨架、「进入即见全量」口径=部署卡完整形态+记录摘要行；**同日五轮反馈**：部署后验证拆出「归档」阶段（四阶段六步：部署前准备/开始部署/部署后验证/归档，「记录」步归入归档）、阶段标签放大加粗；**同日六轮反馈**：阶段标签文字居中、组间灰色虚线分割；**同日七轮反馈**：流程块增「命令」详情开关（板面读 deploy.sh 步骤分段回显每步将执行的命令，纠错不经会话；skill 契约补步骤分段注释，spec 增 C11）；**同日八轮反馈（「在哪用在哪显示」）**：报错与日志集成进流程列表对应步骤——每步执行时间跟在步骤名后、历史报错常驻失败步（上次失败时间与原因）、报错日志在该步日志区回显，移除「报错记录」按钮与筛选；「命令」「日志」开关与「部署」主动作集中到「配置」旁（流程块头只留读数）；「日志」按步骤区分回显；「再次部署」更名「部署」；记录区只留执行历史索引（C07 改写）；**同日九轮反馈**：移除记录区（板面不设独立执行历史区），模式行「命令」「日志」后增「历史记录」下拉——点选最近 10 次部署记录切换执行块回显该次执行（每步状态/时间/读数/日志，失败带步序定位），默认最近一次，执行中禁用；历史报错常驻失败步收窄为「比所选记录更早」的报错。正式确认以本 PR 评审为准。

**样板间已实跑（2026-10-28）**：给真实项目 [gtsllm-dfx](showcase-gtsllm-dfx.md)（Node 局域网服务，已有 build/deploy 资产）搭 `.bw/ci/deploy.sh` 部署入口——项目已有脚本一行未改，只补编排、独立读回与执行记录。本机实走：新鲜版本包构建 → 解包部署（运行发出去的包）→ `/healthz`/`/readyz` 200 + 版本读回（全程 5348ms）→ `records.jsonl` 落 `ok:true`；强杀服务后项目自己的监督脚本 12 秒内自动拉回（downMs 19726ms 计量准确）；坏路径部署如实落 `ok:false` + 日志；`--stop` 干净停止、端口释放。远端 Linux 路径已构建未实走（无真实目标机）。**样板间脚本为 2026-10-28 版结构（构建→部署→读回→记录），早于六步流程契约；步骤标记与 `--from` 重试参数随 gate 后脚本升级补**，明细见[样板间报告](showcase-gtsllm-dfx.md)。

高保真原型 [prototype.html](prototype.html) 已按第二轮修订与评审反馈改版：复用 G3 计划屏设计语言（g3-planning.css + vendor.js 依赖注入 + esbuild 单文件 bundle），部署卡自上而下：**模式行**（模式 toggle 开发/上线 → 版本选择（仅上线，来自验收登记演示数据，包不存在灰掉）→ 配置事实（随模式显示各配置项已配置/未配置）→ 统一「配置」→「部署」主动作（红态为「从失败步重试」）→「命令」「日志」查看开关 → **「历史记录」下拉**）→ **执行块**（读数头 + 竖排四阶段六步流程列表：阶段标签居中加粗、组间灰色虚线分割、数字徽章 1–6 常显标序、完成绿色实心、竖向连线随完成变绿、**执行时间跟在步骤名后**、每步读数内联；「命令」开关按 deploy.sh 步骤分段回显每步将执行的命令，「日志」开关**按所选记录分步骤**回显该步实际输出；**历史报错常驻失败步**——比所选记录更早的上次失败时间与原因一行事实、报错日志随「日志」开关在该步回显；执行中自上而下逐步点亮、读数与时间随完成进板面，失败步红色定位，重试时已完成步不重跑）；灰态动作行给「生成部署脚本」。**不设独立记录区（九轮反馈）**：「历史记录」下拉列出最近 10 次部署记录（时间、模式、版本、结果，失败带步序定位），点选切换执行块回显该次执行，默认最近一次，执行中禁用。**不做场景切换，进入即呈现已接入后的全量形态**（绿态·上线模式·六步全过·每步时间与读数·历史报错常驻失败步；全量=部署卡完整形态），灯态四态与生成/重试等灰红态交互经断言内动作驱动验证。板面文本沿用定稿规则：机制与配置收进按钮提示与正本，板面只留事实（状态、每步时间与读数、流程推进、已配置/未配置、失败步「上次失败」、灰态「主分支未见脚本」）与动作。Playwright DOM 断言 **78/78** 通过（`prototype/verify-ci.cjs`：竖排流程列表与每步时间/读数、命令与日志按步回显、历史报错常驻失败步与报错日志归位、模式行集中入口（配置·部署·命令·日志·历史记录）、历史下拉切换最近 10 次记录（失败记录第 4 步红色定位与原因/日志、切回最近一次恢复、执行中禁用、新记录入列）、进入即全量、两模式与版本选择、配置入口与配置事实、执行瞬态与逐步点亮、失败步定位、重试不重跑已完成步、递交 prompt 与 skill 草案逐字一致、无 console/page error；截图仅存临时目录供人工查看）。演示数据全部预置，生产不预置任何记录。
