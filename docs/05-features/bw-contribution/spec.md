# 贡献 BW：操作与验收规格

> **读者与时机**：设计评审者、实现者与验收者，在制作局部原型、改变批注交接或开工路径前读取。
> **职责与维护**：维护入口、完整旅程、对象来源、异常、验收判据和产品取舍；价值归 [intent](intent.md)，认可与验证归 [STATUS](STATUS.md)。不放遗留清单、施工步骤或讨论流水。行为决定改变时同步原型和验收判据。

## 导读与状态

研发保障下的贡献旅程，按用户认可的“批注交接 → 助手提单 → 原生开工”定义目标行为。局部原型和 Skill 第一版供人体验；原生组件存在不代表跨组件流程已接通。

唯一体验入口：[局部交互原型](prototype/index.html)。只呈现批注交接与会话开工两处增量，复用原生组件，不绘制整套工作台。使用已有依赖，在仓根运行 `node docs/05-features/bw-contribution/prototype/build.cjs` 后打开；生成物位于忽略的 `prototype/dist/`。演示数据不产生真实 Issue、会话或修复树。

## 范围与入口

在当前页面用快捷键唤起原生批注工具。点选或框选对象，输入批注并保存，可继续补充其他对象。保留原复制动作，在批注浮窗复制控件旁直接增加带 Tooltip 的“交给改进助手”图标按钮，不藏入右键菜单。元素、批注和可用环境材料直接交接，不经剪贴板回读；复制仍可独立使用。

只通过快捷键进入批注：默认 `Ctrl+Alt+B`（macOS 为 `⌘⌥B`），可在设置的快捷键中发现、改绑和停用。界面不增加开启批注按钮。

批注工具栏平时隐藏，唤起后沿用原生停靠位置。保存批注后保留工具栏供继续批注、复制或交接；非输入批注状态下按 Esc 退出，或交给助手时收起工具栏。隐藏不清除已保存材料，再次唤起可继续使用。

不增加工作区右上角反馈按钮，也不先打开发送反馈表单。现有帮助中的发送反馈维持原用途。快捷键发现入口若需补充，仅调用同一批注动作，不另建提单流程。正式版目标是在原实例直接留下现场，不要求切另一 dev 重现；可用范围与实际证据必须明确。

## 完整用户旅程

### 1. 批注并交给助手

人在原页面选中对象、补一句问题或期望，点“交给改进助手”。系统保留来源机器、实例/版本、页面与时点、批注和附件引用，交给独立原生助手会话。准备完成后打开原生 floating workspace 的独立智能体草稿，原页面和输入保留，用户可原生收起并返回原工作。

每次新反馈创建独立浮动会话；同一批材料的重复交接找回已有会话。后续补充在该会话继续，另一个问题才新建。交接不要求先选版本、BW 项目、开发宿主或创建修复 worktree。原工作草稿与页面位置保留；取消不产生 Issue，失败保留材料并可重试同一次交接。

### 2. 加载起手 Skill，整理问题

沿计划助手的完整 Skill 包准备、宿主安装与可读路径返回机制准备提单 Skill。草稿先放原批注，再追加可核验的环境摘要和短起手提示，包含完整 Skill 的真实路径。注入前把双引号换成全角引号、把换行换成 ⏎，然后走计划助手同一条未发送草稿。目标为形成或关联 Issue、给出真实链接并引导可选开工。用户可看清额外注入的提示，按回车发送后才执行，不自动提交。助手执行前完整读取 [改进 BW Skill](../../../.claude/skills/improve-workbench/SKILL.md) 及其按动作指定的规则；源码入口供仓内维护，用户电脑使用完整包的实际安装路径。

“交给改进助手”是交接材料的明确动作；缺模型、包安装失败或会话不可启动时保留材料、说明恢复入口，不能显示已接收。用户无需手工拼提示。会话可收起和找回，临时界面关闭不意味着问题记录删除。

助手先用已有信息，根据缺口在用户本机补充相关环境、操作记录、错误、trace 或崩溃材料。读取范围与工具能力以实际可用为准，不让用户先填全套表。知识库提供稳定产品行为和诊断入口；源码可用时再核对实现，不以源码或确认根因为提单条件。

BUG 分清实际行为、应有行为、观测/复现路径与证据；小诉求说明对象、期望、范围与可观察的验收方式。已有材料可回答的先调查，只有影响描述或验收的缺项才问人。未复现、无日志与假设如实保留，不把未知补成事实。

### 3. 创建或关联 Issue

沿通用 Issue 规范查重，写入原问题、必要上下文和证据，保留已存在的人工决定。问题能描述清楚即可记录；是否已具备修复所需信息与是否允许提单分开，不以完整诊断阻止贡献。若问题跨多个独立结果，说明拆分理由。

确认 BW 目标仓及可用 provider，不能从当前业务项目自动推定 BW 的 Issue 仓。版本/目标仅在已确认时关联。写后读回真实链接；失败或结果未知时先查已有记录，避免重复创建。知识不足的归属可留待确认，不编造分类。

### 4. 会话内开始修复

助手输出已读回的完整 Issue 链接；本机 floating workspace 的原生链接菜单提供“开始修复”，调用任务界面同一开工流程，无需到任务页重新寻找。原生开工弹窗负责选择可用、已授权主机上的 BW 项目与工作树创建；当前业务项目不自动成为修复仓。原生关联、已有工作区判断与失败恢复继续复用，不另起派工协议。

开工备注自动带入且允许编辑：

> 拉取最新代码，按项目 workbench-start 处理 Issue <链接>。

备注只给工作请求，不重复宿主和工作树安排，不铺开发 SOP。开工成功后在目标工作树沿原生机制准备 worker 会话。若原生路径将关联 Issue 与备注交付为未发送草稿，须明确呈现并由用户发送后执行，不能把创建会话当成模型已开工；不另加自动发送绕过原语义。取消弹窗不丢 Issue 与会话；已有执行记录先找回，不能盲目重复开工。仅反馈者可停在 Issue，不强迫参与修复。

### 5. 看交付并反哺

workbench-start 自身承担开发、验证、独立检视与 PR 交付。问题描述、用例路径、基线/修复证据与 dev 身份回指原 Issue。人可读报告、按同路径复验或请强模型辅助，不把守门员设为每单默认步骤。合入、关闭、完成与发布各自按人的授权处理。

获准发布后，将可用版本关联原反馈并回告；用户可在日用实例重复原动作，不把 dev 修复说成正式版已生效。

收集与修复沿 workbench-start 原有会话提取、标注、报告和六项指标反哺。人的原话、补充、批注、附件与评审意见保留来源，转发和模型转述不重复计数。采用本收集流程的 Issue 使用 `bw:improve-workbench` 样本标签，不承载状态；提单阶段的人工介入摘要落 Issue 评论，沿同一报告脚本的 issue-only 模式适配，不新造指标引擎。无权限、无原记录或报告不可生成时保留具体缺项，不伪报反哺已完成。反哺经确认修回所属原件，减少重复人工补位。

## 行为规则与异常

| 情形 | 行为 |
| --- | --- |
| A：当前项目就是 BW | 本机独立助手会话收材料；有源码可参考，修复按原生开工选择 |
| B：当前为其他项目，无 BW 源码 | Skill 与本机现场足以开始；不读取业务规范来替代 BW 规则，不在业务仓建修复树 |
| 有源码、无已登记 BW 项目 | 可帮助定位；修复时沿既有项目纳入/开工处理，不阻塞先提 Issue |
| 本机或共享主机有 BW 项目 | 开工弹窗选择对应可用位置，不能默认开放另一人的主机 |
| C：只反馈或没有本机模型/桌面 | 原渠道由维护侧承接同一 Skill；保留原消息出处，无法访问的现场不假装可见，反馈者不必修复 |
| 后续 Bot 接入 | 复用 Skill、材料、会话/Issue 关联和开工请求，原渠道身份与回告沿实际 Bot 能力处理 |
| 现场不足 | 本机按需补采；无法自动取得的说明具体缺什么，不把复杂远端取证设为前提 |
| 会话、Issue 或开工失败 | 保留原输入及已完成结果，按真实身份读回后恢复，不重复写入或假报成功 |

独立会话的具体容器按原生能力选择；浮动窗口、会话和 Git 工作树不是同一个对象。目标体验不绑定一个专用非 Git 目录，也不把尚不支持的浮动结构化聊天画成已接通。宿主必须拿到可读的 Skill 与材料；本机路径不能冒充远端可读路径。

## 验收与衡量

| 标识 | 场景与可观察结果 |
| --- | --- |
| BC-01 | 在当前现场唤起原生批注；复制保留，新交接动作能被发现并携带正确批注 |
| BC-02 | 交接后可继续原工作、找回助手；追加不串问题，取消/失败保留材料且不重复提交 |
| BC-03 | B 无 BW 源码仍能加载完整 Skill、按需取得本机现场并形成准确问题；业务仓不被当成 BW |
| BC-04 | C 只反馈也能形成可追溯 Issue；没有本机模型时由维护侧承接，Bot 不作为 A/B 前置条件 |
| BC-05 | BUG/小诉求有相应描述与验收路径，事实和假设分开；先查重、写后读回，无源码不阻塞提单 |
| BC-06 | 会话内开工等同任务界面开工；BW 项目/宿主/工作树由原弹窗处理，短备注可见、可改并实际进入 worker 启动 |
| BC-07 | PR/dev 证据回答原问题，完成由人确认；获准发布后能沿反馈找到可用版本并复验 |
| BC-08 | 实际人工输入进入同一反哺链，Issue/PR 口径不重复，规则修改回到原件 |

原型交互、Skill 格式、包安装、模型实际读取与真实业务验收分别留证。效率沿既有人工介入与返工口径观察，不增加第二套公式。

## 取舍

优先复用批注与原生会话的局部动作，避免为接收同一份材料增加中间表单。提单与修复分职责，使无源码用户可贡献；愿意修复时再选择项目位置。执行容器与 Skill 分发需要实际调用链支持，不能为减少人工点击而隐藏失败或权限边界。当前工程缺口与安排放仓外 plan，不改变本篇目标旅程。
