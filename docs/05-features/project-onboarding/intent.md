# 项目接入与项目约定（intent · 定义草案）

> **状态**：定义草案——按 [02 §6.2 补链两层](../../01-principles/02-working-backwards.md) 于 2026-09-20 回填。特性已交付且在用（真实项目已接入、E2E 已注册），本篇是既有特性的定义补齐，**人确认 = 批准本 PR**。素材来源：architecture §1「接入」站、特性盘点草案 §4.3①、pr-onboarding 注册用例。

1. **标题**：项目接入与项目约定（Onboarding）
2. **副标题**：给第一次用 BW 的 Builder——把真实仓库纳入管理，此后人和 agent 都能读到项目身份与约定。
3. **总结**：打开本地仓库或克隆远端仓库，确认基础信息后得到项目名片（`.bw/project.toml`）与「项目约定」Issue；杀进程重开后路径、远端、资料读回一致。
4. **痛点**：第一次用的时候 BW 不知道你说的是哪个项目；agent 开工缺项目上下文；约定只在人脑里，换机器、换人就丢。
5. **解决方案**：接入屏引导选择真实本地路径或克隆远端 → 确认名片 → 自动长出项目约定 Issue；此后总览/计划/会话/知识屏都以它为入口。
6. **如何获得**：启动 `bw-dev` 桌面壳 → 顶层接入屏（深链 `BW_VIEW=onboard`）或壳内「添加项目」。
7. **五大拷问答案（摘要）**：
   - **谁**：被管项目的 Builder（含 BW 团队自己的被管项目）。
   - **痛点**：见第 4 条。
   - **核心利益**：一次接入，全链读回一致（铁律一的接入形态）。
   - **怎么知道客户想要**：真实使用——user 的真实项目已接入；pr-onboarding 沙箱旅程与 week-plan 真实旅程（v0.4）的首段都以真实接入开始。
   - **体验**：接入屏 → 名片 → 约定 Issue → 重启读回。
8. **开放问题**：
   - 重复接入、权限/克隆失败的验收点尚未成注册用例（已知债，带入时按 02 §6.2 补）。
   - week-plan 旅程首段复用本特性用例；旅程归属边界（接入是否只作旅程首段）带入时定。
