# Spec · 记分牌与完工预测

> **30 秒导读**:这是什么——本特性的**规格件**:客户怎么用、产品预置什么、每条指标怎么决定自己长什么样、代价在哪。给谁看——审规格的人、以及接手施工的会话。现在作数吗——**未认**(2026-09-10 起草,随 PR 送审)。意图见 [`intent.md`](intent.md);可点原型 [`prototype.html`](prototype.html)。

## 1. 可点原型

[`prototype.html`](prototype.html) —— 单文件、浏览器直接打开,左栏点「总览 / 计划」切两屏。1440×900,壳与 token 继承 [`docs/hifi/overview.html`](../../hifi/overview.html) 与 [`docs/04-design-system/styles.css`](../../04-design-system/styles.css),**没有另起一套视觉**。页内数字是演示数据(顶栏 ✱ 标),取的是本仓真实 Issue 编号与量级。

原型画的是**成熟态**(跑了 12 周、指标定齐)。接入第一天、只有一条指标、数据不满 8 周的样子**没画**——见 §7 留白。

## 2. 产品预置的是文法,不是视图

发起人的硬约束:「每个业务、每个软件项目它的指标是不一样的,我们没办法预置所有的视图,这都是要跟着项目构建起来的。」

所以**不做**「产品内置一套固定图表」,也**不做**「用户自己拖一个仪表盘出来」——后者是这类工具的常见死法(白板 + 没人维护)。做法是第三条:**一条指标的声明决定它自己长什么样。**

`MetricDef`([`crates/bw/src/repo/metrics_file.rs`](../../../crates/bw/src/repo/metrics_file.rs))今天已有的三个字段,其实已经在决定这件事:

| 已有字段 | 现在管什么 | 实际决定 |
|---|---|---|
| `collect.retro` → `MetricClass` A/B/C | 能不能重算历史 | **有没有时间轴**:A 类才有周序列;B/C 类只有当前一格 |
| `leads` | 引领盯哪条滞后 | **记分牌的行结构**:缩进、挂靠、同图叠放 |
| `target` | 一句人话门槛 | **用哪个图元** —— 但今天是 `String`,读不出来 |

`target` 是唯一缺口:`"≥3"` 分不出是「每周都要 ≥3」还是「到年底累计到 3」,而这是两张完全不同的图。

### 2.1 图元(四个,穷举)

| `target` 的形状 | 图元 | 数据要求 | 例 |
|---|---|---|---|
| 阈值 `≥80%` / `≤14 天` | 记分牌一行(周格子)+ 单线 | A 类有历史列;B/C 类只有本周一格 | CI 首过率、评审等待 |
| 到某日累计到 N | 路面(目标斜率 + 实际轨迹) | A 类 且 ≥8 周读数 | 纳入项目数 → 8,到 12-31 |
| 分位 `p85 ≤ 14 天` | 分布(散点 / 直方图 + 分位线) | 样本 ≥20 | 周期时间、完工预测 |
| 空 | **不画图**,只有一格数 + Unknown | — | 本仓北极星现状 |

第四行不是兜底,是规矩:**没定目标就没有图**。视图数量天然等于「你真定了几条指标」,不需要任何开关。

### 2.2 退化规则(不报错、不阻塞)

- `target` 解析不出形状 → 退回**阈值行**,照样上记分牌。
- 够形状但数据不够(不满 8 周 / 样本 < 20)→ **图不出现**,只留记分牌那一行,不外推、不补零。
- 采集脚本失败 → 那一格**灰**,不写 0(现行契约,不改)。

这套取舍和 `metrics_file.rs` 已有的「不做 `deny_unknown_fields`,多出来的字段直接忽略」是同一条:**人手写的文件,宁可少显示,不要整份崩。**

## 3. 预置的边界(哪些图能预置,哪些不能)

| | 数据来自 | 能不能预置 |
|---|---|---|
| **总览的图** | 项目自己定义的业务指标(`.bw/metrics.toml`) | **不能** —— 按 §2 长出来 |
| **计划的图** | Workbench 自己产生、所有项目同构的数据:issue 什么时候开、什么时候关、MR 什么时候合 | **能** —— 这个 schema 是产品的,不是项目的;接入第一天就有数 |

`CONTEXT.md` 区分项目指标（提交、Issue、MR 等工程统计）与业务指标，不能仅凭工程活动量判断业务健康。本特性认定:**它同时也是「图能不能预置」的分界线。**

所以完工预测、周期时间散点、累计流三张图对**每一个**被管项目都成立、都不用配。

## 4. 长出来的顺序

```text
接入第一天    总览只有名片 + 北极星卡(空 target → 一格数 + Unknown)
              计划屏三张图已经有数(issue 是现成的)
定第一条滞后  记分牌长出第一行,右边一格「目标未设」
挂一条引领    缩进的第二行出现,leads 连上
攒够 8 周     那条指标的图自己浮出来;之前不占版面
```

没有任何一步是「去设置里加一个图表」。

## 5. 操作逻辑

**主路径(总览)**:打开 → 现算一轮 → 记分牌按 §2 渲染 → 见红行右侧「进议题」→ 落进「本周节奏」卡 → 「创建 Issue」→ 建 issue 并跳计划屏。

**主路径(计划)**:打开 → 「预测」页签(看板 / 列表不动)→ 三张图现算 → 「长时间未完成的 Issue」把分位线变成每个 Issue 身上的刻度 → 点一个 Issue 进详情。

**分支**:

| 情形 | 界面 |
|---|---|
| 没有 `.bw/metrics.toml` | 记分牌整块不出现,不占位、不显示空壳 |
| 只有北极星、没有滞后 | 记分牌不出现;北极星卡照常 |
| 指标全是手填 | 记分牌只有「本周」一列 |
| 本周没有见红 | 节奏卡只有四步条 + 上周回顾,没有议题行 |
| 剩余 Issue 为 0 | 完工预测不画,显示「本版本没有剩余 Issue」 |

**出错**:采集脚本失败 → 灰格 + 悬停说明哪条脚本失败(不写 0、不沿用上周值);`metrics.toml` 是旧格式 → 沿用现行行为,整份拒收并提示重定,记分牌不出现。

## 6. 硬核挑战(内部 FAQ)

**`target` 变机读,代价多大?** 改动本身小(加一层解析 + 一张形状→图元表),真代价是**人手写 `metrics.toml` 会更啰嗦**。折中:`target` 仍是人话字符串,产品尽力解析,解析不出就退化(§2.2)。**不加必填字段、不做迁移**。

**为什么不做图表编辑器?** 图表定义的所有权必须留在 `metrics.toml`(仓里、可评审、可 diff)。做成界面上拖拽,定义就跑到本机状态里去了,和「仓是唯一统计源」直接冲突。**不做拖拽编辑、不做配置面板。**

**图怎么画?** 壳内 `rsx!` 内联 SVG,不引前端图表库。约束沿用图表底座既有结论:**单轴,永不双轴**;系列色 **6 槽封顶**;文字用 ink token 不用系列色。

**完工预测的口径?** 输入只有两样:剩余未完成 Issue 数、近 12 周每周完成数。放回抽样跑一万次。**不吃估点、不吃人填的工作量。** 吞吐样本不足 12 周就按实有周数算并在图上标明。

**它会不会自动推进 Issue?** 不会。预测是预测,**不写回任何 Issue 的状态、不自动排期、不参与完成判定**。完成永远人点(铁律 3)。

**成功怎么量?** 本特性自己吃自己:上线后本仓 `metrics.toml` 里「记分牌上有多少条指标是绿/黄/红而不是灰」应当逐周上升;若三个月后仍大面积是灰,说明文法没用对,该退回重想而不是加图。

## 7. 留白(没做/没验的,如实列)

- **成熟态之外的三个状态没画**:接入第一天、只有一条指标、数据不满 8 周。
- **只在 headless Chrome 里看过,没在真壳里看过**。本批不动 Rust,壳里还没有这两屏;截图是本机 headless Chrome 渲染原型单文件出的(1500×1000)。真壳接上以后的渲染差异(Dioxus 拼样式表、WebView 字体回退)**没验**。
- **记分牌宽 13 周是拍的**,没有依据。
- **`target` 形状的具体写法没定**(`→8 @2026-12-31` 只是示意,不是提案)。
- **一行 Rust 都没动**。本 PR 只有文档与原型。
