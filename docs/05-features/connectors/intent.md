# intent — 集成页三卡收敛（Connectors）

> **状态：已经人 gate（2026-10-15）；待决 1–4 项内决定仍开放。** 来源 [#323](https://github.com/forcegravity1989/builder-workbench/issues/323)（含 v0.6 自 #301 转入的安装引导遗留）。本篇只写为什么做与范围；目标行为见 [spec.md](spec.md)，链状态见 [STATUS.md](STATUS.md)，可点样张见 [prototype.html](prototype.html)。
>
> **维护约定**：给判断「BW 集成页该长什么样、三张卡从缺办到通值不值得做」的人读。集成页行为变化、CLI 依赖变化或待决项拍板时更新本篇；不抄实现清单，不记过程流水。

## 用户与问题

被管项目的 Builder 在内网环境工作，BW 真正依赖三个 CLI：`gh`（GitHub 任务与 PR）、`codehub-cli`（CodeHub 任务与 MR）、`welink-cli`（项目群通知）。他打开设置 → 集成想确认三者可用，看到的却是八张卡：六张（GitLab、Bitbucket、Azure DevOps、Gitea、Linear、Jira）与 BW 工作流无关，真正要用的 WeLink 反而没有卡。剩下两张也只报缺、不帮着办：

- GitHub 没装时只有跳官网的按钮；没登录时只把 `gh auth login` 这行字摆出来，要自己开终端敲。
- CodeHub 只区分「在 PATH 上」与「不在」，不探登录，也没有登录入口。

结果是「知道自己缺什么」要跨三个地方查，「把缺的补上」要离开应用。新 Builder 的第一轮环境准备在这里最容易卡住。

## 价值与依据

核心收益：**一个页面把三个 CLI 的状态看全，缺什么有按钮指路**。全部动作拼装 Orca 现有能力，不新造交互：

- welink-cli 检测照 GitHub 卡现成的 preflight 模式补（探安装 + 探登录）。
- 安装入口照现有模式：gh 保持现有外链按钮（跳 cli.github.com）；welink-cli 安装命令已由人确认（见 spec 命令表），注入终端执行。
- 登录从「摆一行字让人自己敲」升级为「点按钮、命令注入终端」：复用开发屏（Orca 主工作区）现有终端页签与启动命令投递机制，人不敲命令，点按钮后只与 CLI 自己的交互提示打交道（扫码、设备码）。

依据：#323 由人提出并标注 Feature；v0.6 补充承接 #301 群反馈遗留的 codehub-cli / welink-cli 安装与配置引导收敛。三个 CLI 的登录命令与 `auth status` 支持性已在本机实测核对，welink-cli 安装命令为人给定的权威口径（见 spec 命令表）。多 Builder 的真实使用读回还没有，价值效果仍是假设。

## 目标体验

设置 → 集成只剩三张卡，按「代码托管」（GitHub、CodeHub）与「项目群」（WeLink）分组，沿用现有卡片模板与状态口径（检查中 / 未安装 / 未登录 / 已连接 / 不可用，即现有 `CliProviderCardState` 五态）：

- 没装：gh 点「安装」跳 cli.github.com（现有行为）；welink 点「安装」，安装命令注入开发屏终端页签执行；codehub 安装口径待内网补，如实占位。
- 没登录：点「登录」，`auth login` 注入开发屏终端页签执行，人按 CLI 提示完成登录；登完回卡上点「重新检查」。
- 已连接：只留「重新检查」。
- 状态来自远端 Orca 服务器或 WSL 时，只报状态，不给安装、登录按钮。

## 范围与边界

- **做**：集成页收敛为三卡；welink-cli 检测照 gh 现成模式补（含登录探测）；codehub-cli 从「只探 PATH」补齐登录探测；三卡安装入口（gh 外链保持、welink 命令注入、codehub 待内网补占位）；三卡「登录」按钮把 `auth login` 注入开发屏终端页签（复用现有启动命令投递）；分组标题按 issue 口径。
- **范围外**：不做卡片内嵌终端、不自动感知命令结束（登录后由人点「重新检查」刷新）；按钮只注入卡上可见的那一条命令，不做通用命令执行器；不新增六张被收敛卡的替代入口；不改 Orca 原生对其他 provider 的能力与协议；不探 CLI 版本新旧。
- **相邻**：CodeHub 任务行为归 [codehub 特性](../codehub/intent.md)，本特性只管「codehub-cli 装好登好」这一站；安装引导（setup-guide）对 codehub-cli / welink-cli 的补齐按 #323 v0.6 补充与本卡状态对齐，引导正文归其所属旅程。

## 成功判据与待决问题

**判据**：一台三 CLI 全缺的新机器上，Builder 从集成页能看全三卡状态、每张卡缺什么都有按钮指路，全程不需要手敲安装 / 登录命令；装好登好后「重新检查」全部翻已连接；杀进程重开，状态仍从真实探测读回，不出现假绿。六张被收敛的卡不再出现在 BW 集成页。

**待决（需 gate，共 4 项；issue 初稿所列「卡片内终端形态」已定为复用开发屏终端页签 + 命令注入，不再开放）**：

1. **被收敛六卡的代码去留**——只隐藏 UI，还是连带删除其探测与状态代码？删除缩小维护面但加大与 Orca 上游同步的冲突面；仅隐藏保留上游能力。草案倾向仅隐藏 UI、探测代码留给上游同步（待拍板）。
2. **codehub-cli 安装口径**——内网分发二进制，权威安装命令或说明链接待内网确认；补齐前安装按钮先隐藏还是给占位？（welink-cli 安装命令已由人确认，不再待决。）
3. **welink-cli 的 EXPIRED 中间态**——`auth status` 存在「Token EXPIRED、下一条命令自动刷新」的中间态（本机实测）。探登录时它算已连接还是未登录？草案倾向算已连接（自动刷新兜底），不让人为过期重登（待拍板）。
4. **分组标题的 i18n 呈现**——分组词「代码托管 / 项目群」已定，待决仅剩五语词条怎么译（现有英文标题 Review providers / Task providers 退役）。
