# intent — 集成页三卡收敛（Connectors）

> **维护约定**：给判断「BW 集成页该长什么样、三张卡从缺办到通值不值得做」的人读。集成页行为变化、CLI 依赖变化或待决项拍板时更新本篇；不抄实现清单，不记过程流水。

## 用户与问题

被管项目的 Builder 在内网环境工作，BW 真正依赖三个 CLI：`gh`（GitHub 任务与 PR）、`codehub-cli`（CodeHub 任务与 MR）、`welink-cli`（项目群通知）。他打开设置 → 集成想确认三者可用，看到的却是八张卡：六张（GitLab、Bitbucket、Azure DevOps、Gitea、Linear、Jira）与 BW 工作流无关，真正要用的 WeLink 反而没有卡。剩下两张也只报缺、不帮着办：

- GitHub 没装时只有跳官网的按钮；没登录时只把 `gh auth login` 这行字摆出来，要自己开终端敲。
- CodeHub 只区分「在 PATH 上」与「不在」，不探登录，也没有登录入口。

结果是「知道自己缺什么」要跨三个地方查，「把缺的补上」要离开应用。新 Builder 的第一轮环境准备在这里最容易卡住。

## 价值与依据

核心收益：**一个页面把三个 CLI 的状态看全，缺什么有按钮指路**。全部动作拼装 Orca 现有能力，不新造交互：

- welink-cli 检测照 GitHub 卡现成的 preflight 模式补（探安装 + 探登录）。
- 安装入口：gh 保持现有外链按钮（跳 cli.github.com）；welink-cli / codehub-cli 的自包含安装命令已由人确认（见 spec 命令表），由应用后台执行——安装不需要人交互，不占会话栏（2026-10-16 真壳反馈拍板）。
- 登录从「摆一行字让人自己敲」升级为「点按钮、命令填进卡内终端」：复用上游 `OnboardingInlineCommandTerminal`（onboarding / 技能安装面板的现成内嵌终端），命令粘贴不回车、人按回车执行，人不敲命令，点按钮后只与 CLI 自己的交互提示打交道（扫码、设备码）。

依据：#323 由人提出并标注 Feature；v0.6 补充承接 #301 群反馈遗留的 codehub-cli / welink-cli 安装与配置引导收敛。三个 CLI 的登录命令与 `auth status` 支持性已在本机实测核对，welink-cli 安装命令为人给定的权威口径（见 spec 命令表）。多 Builder 的真实使用读回还没有，价值效果仍是假设。

## 目标体验

设置 → 集成只剩四张卡，按「代码托管」（GitHub、CodeHub）与「项目群」（WeLink）分组，2026-10-19 起另设「构建」分组放 CloudBuild（cb，#366 增补），沿用现有卡片模板与状态口径（检查中 / 未安装 / 未登录 / 已连接 / 不可用，即现有 `CliProviderCardState` 五态）：

- 没装：gh 点「安装」跳 cli.github.com（现有行为）；welink、codehub 点「安装」，应用后台执行各自的自包含 npm 安装命令（口径均已由人确认），卡上持续显示「安装中」，完成与失败都弹通知，成功后自动复查。
- 没登录：点「登录」，卡内展开内嵌终端（临时终端域，不挂接入的项目工作树），`auth login` 已粘贴待回车，人按回车后按 CLI 提示完成登录；命令结束卡自动复查，也可手动点「重新检查」。
- 已连接：只留「重新检查」。
- 状态来自远端 Orca 服务器或 WSL 时，只报状态，不给安装、登录按钮。

## 范围与边界

- **做**：集成页收敛为三卡；welink-cli 检测照 gh 现成模式补（含登录探测）；codehub-cli 从「只探 PATH」补齐登录探测；三卡安装入口（gh 外链保持、welink 与 codehub 由应用后台执行自包含命令，含安装中状态与完成 / 失败通知）；三卡「登录」按钮在卡内展开上游内嵌终端并粘贴 `auth login`（人按回车执行，命令结束自动复查）；分组标题按 issue 口径。2026-10-19 增补（#366）：cloudbuild-cli（cb）照同一卡模板加入「构建」分组，探测 / 安装 / 登录口径见拍板 8。
- **范围外**：登录内嵌终端不感知登录业务结果（只感知命令结束并复查探测）；按钮只执行卡上可见的那一条命令，不做通用命令执行器；不新增六张被收敛卡的替代入口；不改 Orca 原生对其他 provider 的能力与协议；不探 CLI 版本新旧。
- **相邻**：CodeHub 任务行为归 [codehub 特性](../codehub/intent.md)，本特性只管「codehub-cli 装好登好」这一站；安装引导（setup-guide）对 codehub-cli / welink-cli 的补齐按 #323 v0.6 补充与本卡状态对齐，引导正文归其所属旅程。

## 成功判据与待决问题

**判据**：一台三 CLI 全缺的新机器上，Builder 从集成页能看全三卡状态、每张卡缺什么都有按钮指路，全程不需要手敲安装 / 登录命令；装好登好后「重新检查」全部翻已连接；杀进程重开，状态仍从真实探测读回，不出现假绿。六张被收敛的卡不再出现在 BW 集成页。

**待决（4 项已全部由人拍板，2026-10-16；issue 初稿所列「卡片内终端形态」首版曾定为复用开发屏终端页签 + 命令注入并关闭，2026-10-19 由人翻转回卡片内嵌终端，见文末拍板 7）**：

1. **被收敛六卡的代码去留**——**已拍板：留在仓**。组件、探测与词条保留，只改渲染名单；删除会加大与 Orca 上游同步的冲突面，恢复某张卡也更容易。
2. **codehub-cli 安装口径**——**已拍板：单条自包含命令**（人确认 2026-10-16）：`npm install -g @codehub/codehub-cli --registry=<内网源> --strict-ssl=false`，welink 同款、不动机器 npm 配置；安装按钮与命令文字行已接（见 spec 命令表）。
3. **welink-cli 的 EXPIRED 中间态**——**已拍板：算未登录**（人拍板 2026-10-16，推翻草案倾向）。`auth status` 输出含 EXPIRED 即 not-authenticated，卡上给登录按钮让人重扫，不给过期 token 亮绿灯。
4. **分组标题的 i18n 呈现**——**已拍板：只补中文**（人拍板 2026-10-16）。「代码托管」「项目群」标题与描述行进 zh.json，其余语言仍回退英文。

**真壳验证拍板（2026-10-16，第一轮人工验证反馈，推翻 spec 两处旧取舍）**：

5. **安装后台化 + 生命周期反馈**——安装不需要人交互，不再开进会话栏的前台终端会话：应用后台执行，卡上持续显示「安装中」，完成与失败都弹通知（失败带原因与输出尾部），成功后自动触发复查。原「应用后台代跑命令——放弃」的取舍对安装作废；登录因需要扫码 / 输入保持终端注入。
6. **登录走浮动终端页签**——登录命令注入开发屏浮动终端页签（终端自身启动目录，不挂接入的项目工作树），并自动跳转聚焦；注入不再要求有激活工作树，只要求本机范围。原「注入按钮还要求有激活工作树」的约束作废。**2026-10-19 被拍板 7 作废。**
7. **登录改卡片内嵌终端**（2026-10-19，人拍板翻转拍板 6）——浮动面板 reveal / 激活链路连续暴露缺陷（点登录无跳转、真壳复现一次点击产生两个页签且空白者被激活），且自动回车提交偏离 issue 原文「人按回车执行」；首版拒绝卡片内嵌终端的理由「为设置页新造终端交互面」不成立——上游 `OnboardingInlineCommandTerminal`（2026-05 起服务设置面板）就是现成内嵌终端。登录改为卡内展开该组件：命令粘贴不回车、人按回车，OSC 133;D 感知命令结束自动复查；登录中离开设置页终端随卡片卸载关闭（知情取舍）。
8. **cloudbuild-cli 加入集成页**（2026-10-19，人随 #366 提出并给定安装口径）——CloudDragon 的 `cb` 照三卡同模板入页：探测用 `cb version` 子命令（`--version` 是未知旗标）、登录判定从 `cb auth status` 输出标记读（`Token Expires` 且不带 `(expired)` 才算已登录，退出码恒 0 不可用，实测口径同 codehub/welink 的假绿陷阱）；登录命令 `cb login`。安装口径由人指定为**两条命令**：先 `npm config set @hw-cloudbuild:registry <内网源>` 再 `npm install -g @hw-cloudbuild/cloudbuild-cli`——与 codehub/welink 的单条自包含命令不同，这条会改机器 npm 配置（scoped registry 持久化），不带 `--strict-ssl=false`。分组为本特性自行判断的「构建」（cb 既非代码托管也非 IM），**待人确认**。
