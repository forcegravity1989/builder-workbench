## 用户与问题

被管项目的 Builder，在 Workbench 会话屏里对 agent 下指令、回答它的提问，手上常有别的事（开会、看代码、走动）。

现在能用的只有 Orca 执行核自带的听写：按 `Mod+E`，麦克风语音经本机模型或 OpenAI 云端转成文字，直接插进终端或输入框。它的边界：

- 模型目录写死在代码里（10 个本地模型 + 2 个 OpenAI 模型），要加一个模型得改源码发版；下载只认 HuggingFace，内网机器下不到。
- 远端只认 OpenAI 一家、一把密钥；内网网关、OpenAI 兼容的第三方或自建服务配不进去。
- 转出来的字原样上屏，除 SenseVoice 一个模型自带的数字与标点转换外没有后处理。中文口述的真实痛点（2026-09-22 本机实测调研）：多数模型把「幺三五零幺二三四五六七」原样上屏；同事名、产品名、内部术语听成同音字（「Qwen」听成「千问」）；句尾句号风格不受控。模型层热词只有一类模型支持，SenseVoice 在模型层完全做不了热词。
- 没有朗读。agent 答完了，人必须回到屏幕前读。
- 推理线程数写死，没有可调项。

## 目标体验

| 时刻 | 你在哪 | 点什么 | 发生什么 | 手上多了什么 |
|---|---|---|---|---|
| 周一上午 | 会话屏，agent 在等你 | 按住 `Mod+E` 说「把二四七的验收点拆成三条任务，截止周五」 | 本机模型（或你配的内网端点）转写，经词典纠错与数字转写后上屏：「把 #247 的验收点拆成三条任务，截止周五」 | 一条回车就能发的指令 |
| 换机器 / 进内网 | 设置 → 语音 | 「导入模型」选本机目录，或把下载源改成内网镜像；「添加端点」填内网 API 地址和密钥，点「测一下」 | 模型与端点状态从「未知」变成「可用」，或给出真实失败原因 | 不改代码就换了引擎 |
| 项目接入后 | 项目仓 `.bw/voice/lexicon.txt` | 写上团队的人名、产品名、术语和别名 | 这个项目的听写用它做热词和纠错 | 项目词表一次写、所有会话共用 |
| agent 答完 | 会话屏 | 点「朗读」，或在设置里开「自动朗读 agent 回复」 | 本机模型（或远端）把最后一条回复念出来 | 不用盯屏 |

## 价值与依据

核心收益是：数字、人名、术语在上屏前就对了；模型和端点跟着人走机器，内网也能配；听与说都有。

依据：Orca 上游自基线（2026-09-15）以来 2234 次提交里只有 2 处听写小修，没有引擎抽象、没有朗读，等上游不现实；听写代码 BW 一行未动，可在其上做薄挂载；本机推理库的新版已提供离线朗读、静音检测、标点模型与重采样接口（2026-10-09 读包核实，未实机运行）；后处理每一步的做法与误纠率数据在 2026-09-22 调研里有本机实测。真实 Builder 的使用读回还没有，收益仍是假设。

## 范围与边界

- **做**：引擎可插拔（本地 CPU 推理、远端 OpenAI 兼容端点，两者并存按模型选）；模型目录数据化、本机导入、下载镜像；后处理（清理、词典纠错、数字转写、标点风格，可选标点模型与静音检测）；朗读（本地模型与远端端点）；设置面与「测一下」；全局词典与项目词典。
- **范围外**：GPU 推理（本机推理库的预编译插件是否带 GPU 未核实，暂不承诺，设计留字段）；通用错字纠错模型与大模型后编辑（误纠率证据为负，见 design §2.6）；手机端新能力（现有配对协议只保持兼容）；会议录音文件转写（归会议记录特性，本特性只在引擎接口留口）；向 Orca 上游提 PR。
- **相邻**：会话与执行（Orca 原生终端与 composer 是听写的插入目标，不动）；项目接入（项目词典文件住在 `.bw/`，接入特性不管它的内容）。

## 成功判据与待决问题

**判据**：Builder 在没有外网的机器上，用导入的本地模型完成一次中文口述，数字与词典里的术语上屏即正确；换成内网端点后同一句话同样上屏；杀进程重开，模型、端点与词典配置原样读回，状态重新探测而不是沿用旧结论；agent 的一条回复能被朗读出来。所有「可用」都来自真实探测或真实一次转写，没有假绿。

**待决（需 gate，会改变意图或范围的）**：

1. 第一版范围：听写引擎 + 远端端点 + 后处理先行，朗读同版做最小闭环（推荐），还是朗读放第二版。
2. 词典来源：全局词典 + 项目 `.bw/voice/lexicon.txt`（推荐），只做全局，还是从项目词表文档自动抽取。
3. 远端隐私：在设置里选了远端端点的模型，之后每次听写音频离机不再另弹确认（推荐，选端点那一下就是授权），还是每次开始听写都确认一次。
4. intent 认不认。

实现选型（承载方式、数字转写路线、远端协议范围、推理库升级）在 [design §4](design.md)，同一张决策投影上一起拍板。
