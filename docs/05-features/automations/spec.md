## 范围与入口

调度、运行与编辑器复用 Orca 原生 Automations（执行核）；BW 叠层只加「AI 创建自动化」入口与 composer 会话编排，不另建聊天、历史或第二条调度链。生成会话复用原生会话机制与 `orca automations` CLI，不新增 RPC 工具面。外部 provider（hermes/openclaw）沿用现有映射；表达不了的新字段如实降级显示。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 留下什么 |
| --- | --- | --- |
| 生成 | 计划屏点「AI 创建自动化」，一句话描述周期目标；AI 起草配置（prompt、调度、agent、precheck、并发、上下文、通知）并展示全文 | 草稿配置与人的自然语言需求记录 |
| 调试 | AI 创建禁用态任务并试跑（开独立终端，用户可实时看）；AI 读回运行结果，分析偏差、迭代修改、再试跑；试跑前告知真实副作用 | 若干试跑运行记录与最终调好的配置 |
| 上线 | 人在自动化页确认启用；调度按配置真实到点触发 | 已启用的定时任务与逐次运行历史 |
| 运转 | 到点触发、并发跳过、携带上次结果、留存提示词快照；完成/失败按设置通知 | 可追溯的运行历史、系统通知与 Welink 群消息 |
| 搬运 | 列表行菜单导出 JSON 文件；另一台机器导入，人重新绑定项目/工作区/宿主后创建 | 可移植的任务配置文件 |

## 行为规则与异常

### 调度表达

- 调度选择器在现有五种预设（每小时/每天/工作日/每周/自定义 cron）上新增：**一次性**（选日期与时间）、**每 N 分钟**、**每 N 小时**（数字输入）。
- 一次性任务到点触发一次；错过在宽限期内补跑一次（沿用现有 `missedRunGraceMinutes`），超宽限记 `skipped_missed` 并自然终结。跑完（任何终态）即终结，记录保留不自动删除，列表显示「已结束」。
- 间隔任务按 `dtstart + k×间隔` 现算下次触发，不受小时边界影响（「每 90 分钟」合法）。
- **执行次数上限**为可选输入（留空即无限）：计**实际派发**的次数，`skipped_overlap`/`skipped_missed` 不消耗额度；到数后任务自然终结。改大上限可复活，改小立即到数——语义一致。
- 「已结束」是现算推导值（一次性过期/跑完、次数到数），不是存储状态；与人的暂停开关 `enabled` 分开呈现。

### 生成与调试会话

- 入口在计划屏页头，与「配置自动化」并列；点击后以用户描述作为一次性上下文启动 composer 会话并打开原生终端。
- 会话内 AI 的操作序列：起草并展示配置 → `orca automations create --disabled` → `orca automations run` 试跑 → `orca automations runs --json` 读回 → `orca automations edit` 迭代 → 提示人在自动化页启用。
- **AI 不执行启用**：`--enabled` 永远留给用户操作。
- **试跑是真实执行**：会改文件、调外部服务；AI 发起试跑前必须告知用户副作用。
- 试跑终端与 composer 会话是两个窗口：试跑在目标工作区用目标 agent 跑，composer 会话是编排者，读回结果继续迭代。

### 运行时行为

- **提示词快照**：每次运行记录当时实际递交的完整提示词（含一次性上下文与携带的上次结果）；运行详情页折叠展示；存量运行无此字段显示「未记录」，不造假。
- **并发策略**：每任务「到点时上次仍在运行」→ 跳过本次（默认）/ 允许并行。跳过记 `skipped_overlap`，同因拒绝折叠成一条，高频任务不刷爆历史。手动「立即运行」不受限——人明确要跑就跑。存量任务行为随默认值从「允许并行」变为「跳过」，属修 bug 不改特性，发布说明写明。
- **携带上次结果**：每任务开关（默认关）。开启后派发时把该任务最近一次 `completed` 运行的输出快照附在提示词末尾；快照被保留策略裁掉就如实不附；截断快照带标记照附。复杂状态由任务自己在工作区维护状态文件，composer Skill 教做法。

### 通知

- 运行进入终态时按每任务设置判定：**不通知 / 仅失败（循环任务默认）/ 每次都通知（一次性任务默认）**。
- **系统通知**：Electron 原生通知，任务名 + 状态 + 输出摘要一行；点击聚焦窗口并跳转该运行详情。
- **Welink 群推送**：设置页配置群机器人（全局一份）；与系统通知同判定、两路都发；内容含任务名、状态、时间、输出摘要与「请在 Workbench 查看详情」。
- 推送失败记入运行记录的通知备注，最多补试一次，不重试轰炸；推送不阻塞运行状态机；投递成功不等于通知送达，如实区分。

### 导入导出

- **导出**：列表行菜单「导出」→ 保存对话框，JSON 文件（带 `schemaVersion`），默认名 `automation-<名称>.json`；CLI `orca automations export <id> [--file]`。
- 文件只含可移植子集：名称、提示词、precheck、agent、调度（含一次性时间）、时区、宽限、并发、携带上次结果、通知设置、工作区模式、基线分支、会话复用。机器绑定字段（宿主、工作区、项目、启用态、计数器、时间戳）不导出。
- **导入**：UI 为主——选文件 → schema 校验（不符指名报缺失字段，不部分导入）→ 预填原生编辑器（宿主/项目/工作区留空让人选）→ 人确认后创建新记录；同名任务提示已存在，导入不覆盖。CLI `orca automations import <file>` 需显式传目标参数。
- composer 会话可帮用户导出调好的任务供其他机器导入。

## 兼容与迁移

- 存量任务无新字段：行为与今天完全一致（含并发默认值变化，见上）。
- 存量 RRULE 无 `INTERVAL`/`COUNT`：按 `INTERVAL=1`、无上限解析，行为不变。
- 一次性任务 `onceAt` 存在即判别，`rrule` 字段为空；判别与生命周期推导统一走单一模块，消费者不各写字段判断。
- 外部 provider 任务表达不了一次性/间隔/次数时如实显示「不支持」，不阻塞其余功能。
