## 范围与入口

调度、运行与编辑器复用 Orca 原生 Automations。BW 只加两样东西：计划屏上的「AI 创建自动化」入口，和它背后的 composer 会话编排。不另建聊天、历史或第二条调度链。

生成会话复用原生会话机制和 `orca automations` CLI，不新增 RPC 工具面。外部 provider（hermes/openclaw）沿用现有映射；表达不了的新字段，如实显示「不支持」，不阻塞其余功能。

## 完整用户旅程

| 阶段 | 用户与系统 | 产物 |
|---|---|---|
| 生成 | 用户在计划屏点「AI 创建自动化」，一句话描述周期目标；AI 起草配置（提示词、调度、agent、precheck、并发、上下文、通知）并展示全文 | 配置草稿和用户的原话记录 |
| 调试 | AI 创建禁用状态的任务并试跑（独立终端，用户实时可见）；AI 读回运行结果，分析偏差、迭代修改、再试跑；试跑前告知真实副作用 | 若干试跑记录和最终调好的配置 |
| 上线 | 用户在自动化页自己启用；调度按配置真实到点触发 | 已启用的任务和逐次运行历史 |
| 运转 | 到点触发、上次未完跳过、可携带上次结果、留存提示词快照；完成或失败按设置通知 | 可追溯的运行历史、系统通知 |
| 搬运 | 列表行菜单导出 JSON 文件；另一台机器导入，重新绑定项目/工作区/宿主后创建 | 可移植的任务配置文件 |

## 行为规则与异常

### 调度

- 调度选择器在现有五种预设（每小时、每天、工作日、每周、自定义 cron）上新增三种：**一次性**（选日期和时间）、**每 N 分钟**、**每 N 小时**（数字输入）。
- 一次性任务到点触发一次。错过时，在宽限期内（沿用现有 missedRunGraceMinutes）补跑一次；超过宽限，记一条 skipped_missed，任务显示「已结束」。跑完（无论成功失败）即「已结束」，记录保留不删。
- 间隔任务按「起点 + k × 间隔」算下次触发，不受小时边界影响，「每 90 分钟」是合法配置。
- **执行次数上限**可选，留空即无限。只计实际派发的次数：跳过和错过不消耗额度。到数后任务自然「已结束」。改大上限可以复活，改小立即到数，两个方向语义一致。
- 「已结束」是现算的推导值（一次性过期或跑完、次数到数），不是存储状态；和用户的暂停开关 enabled 分开呈现。

### 生成与调试会话

- 入口在计划屏页头，与「配置自动化」并列。点击后，用户的描述作为一次性上下文启动 composer 会话，并打开原生终端。
- 会话里 AI 的操作序列：起草并展示配置 → `orca automations create --disabled` 创建 → `orca automations run` 试跑 → `orca automations runs --json` 读回 → `orca automations edit` 迭代 → 提示用户去自动化页启用。
- **AI 不执行启用**：`--enabled` 永远留给用户。
- **试跑是真实执行**：会改文件、调外部服务。AI 发起试跑前必须告知副作用。
- 试跑终端和 composer 会话是两个窗口：试跑在目标工作区用目标 agent 跑；composer 会话是编排者，读回结果继续迭代。

### 运行

- **提示词快照**：每次运行记录当时实际递交的完整提示词（含一次性上下文和携带的上次结果），运行详情页折叠展示。存量运行没有这个字段，显示「未记录」，不造假。
- **并发策略**：每任务设置「到点时上次仍在运行」怎么办——跳过本次（默认）或允许并行。跳过记 skipped_overlap，同因折叠成一条，高频任务不刷爆历史。手动「立即运行」不受限：人明确要跑就跑。存量任务的默认从「允许并行」变为「跳过」，属修 bug 不改特性，发布说明写明。
- **携带上次结果**：每任务开关，默认关。开启后，派发时把该任务最近一次成功运行的输出快照附在提示词末尾。快照被保留策略裁掉就如实不附；截断的快照带标记照附。复杂状态由任务自己在工作区维护状态文件，composer Skill 教做法。

### 通知

- 运行进入终态时，按每任务设置判定：**不通知 / 仅失败（循环任务默认）/ 每次都通知（一次性任务默认）**。失败算「失败」；skipped_missed 和 skipped_overlap 属于跳过不算失败，仅在「每次都通知」时发——一次性任务默认「每次都通知」，错过也能被知道。
- **系统通知**：Electron 原生通知，任务名 + 状态 + 输出摘要一行；点击聚焦窗口并跳到该运行详情。通知异步发送，不阻塞运行状态机；发送失败记入运行记录备注，不影响运行状态本身。
- **Welink 群推送为后续待办**：整仓尚未接入 Welink，本特性先不做（2026-10-09 拍板）；届时在设置页配置群机器人（全局一份），与系统通知同判定、两路都发，推送失败与运行失败分开记录。

### 导入导出

- **导出**：列表行菜单「导出」→ 保存对话框，JSON 文件（带 schemaVersion），默认名 `automation-<名称>.json`。CLI `orca automations export <id> [--file]`。
- 文件只含可移植子集：名称、提示词、precheck、agent、调度（含一次性时间）、时区、宽限、并发、携带上次结果、通知设置、工作区模式、基线分支、会话复用。机器绑定字段（宿主、工作区、项目、启用态、计数器、时间戳）不导出。
- **导入**：UI 为主——选文件 → schema 校验（不符指名报缺失字段，不部分导入）→ 预填原生编辑器（宿主、项目、工作区留空让人选；agent 标识随文件预填，目标机器上不存在时由人重选）→ 人确认后创建新记录。同名任务提示已存在，导入不覆盖。CLI `orca automations import <file>` 需显式传目标参数。
- composer 会话可以帮用户导出调好的任务，供其他机器导入。

### 失败

| 现象 | 结果 |
|---|---|
| 一次性任务错过超过宽限 | 记 skipped_missed，任务「已结束」，按通知判定告知，不静默 |
| 到点时上次仍在运行（策略为跳过） | 记 skipped_overlap，同因折叠；不消耗次数额度 |
| 派发被拒（如宿主不可用） | 宽限内下个 tick 重试（同因已折叠）；一次性超宽限记 skipped_missed 后终结 |
| 通知发送失败 | 记入运行记录备注；不影响运行状态 |
| 导入文件不合法 | 指名缺失字段，不部分导入 |
| 外部 provider 表达不了新字段 | 如实显示「不支持」，不阻塞其余功能 |

## 兼容与迁移

- 存量任务没有新字段：行为与今天完全一致（并发默认值变化除外，见上）。
- 存量 RRULE 没有 INTERVAL/COUNT：按 INTERVAL=1、无上限解析，行为不变。
- 一次性任务靠 onceAt 字段存在与否判别，此时 rrule 为空；判别与生命周期推导统一走单一模块，消费者不各写字段判断。
- 外部 provider 表达不了新字段时如实显示「不支持」，不阻塞。

## 验收

| 标识 | 场景 | 可观察结果 |
|---|---|---|
| AU01 | 一次性任务到点（应用开着） | 真实触发一次；跑完即「已结束」；记录保留；重启后读回一致 |
| AU02 | 间隔任务「每 90 分钟」 | 按「起点 + k×间隔」到点触发，不受小时边界影响 |
| AU03 | 次数上限 5 次 | 实际派发 5 次后自然「已结束」；跳过、错过不消耗；改大上限复活 |
| AU04 | 到点时上次仍在运行 | 默认跳过并记 skipped_overlap（同因一条）；手动「立即运行」不受限 |
| AU05 | 打开任一条历史运行 | 能回答「当时用的什么提示词」；存量运行显示「未记录」 |
| AU06 | 计划屏一句话 → composer 会话 | 起草展示 → 禁用态创建 → 试跑（有副作用告知）→ 读回迭代 → 人启用；AI 不执行启用 |
| AU07 | 运行进入终态 | 按任务设置发系统通知，点击跳运行详情；发送失败不影响运行状态记录 |
| AU08 | 导出 → 另一台机器导入 | 校验、预填、人重新绑定后可运行；同名不覆盖；坏文件指名报错 |

旅程 AUJ01：计划屏点「AI 创建自动化」→ 一句话描述 → AI 起草并试跑迭代 → 人启用 → 到点真实触发 → 收到通知 → 杀进程重开读回一致。验收用例和证据按六环登记；一次性到点真实触发与 composer 全链路是必验项。

## 取舍与待决问题

存储维持 Orca 原结构、只追加可选字段（评估见 [design](design.md) 决策记录），换来以后增量同步 upstream 不冲突；代价是「一次性还是循环」要靠字段存在性判别，收口在单一模块里，不让每个消费者自己判断。

待决：无——原型豁免已拍板（见篇首状态）；Welink 推送为后续待办（见通知节）。
