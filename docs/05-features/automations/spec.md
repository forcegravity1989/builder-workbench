## 范围与入口

调度、运行与编辑器复用 Orca 原生 Automations。BW 加三样东西：计划屏上的「AI 创建自动化」入口与其背后的 composer 会话编排、serve 模式的 webhook 触发端点、配置导入导出。不另建聊天、历史或第二条调度链。

生成会话复用原生会话机制和 `orca automations` CLI，不新增 RPC 工具面。外部 provider（hermes/openclaw）沿用现有映射；表达不了的新字段，如实显示「不支持」，不阻塞其余功能。

## 完整用户旅程

| 阶段 | 用户与系统 | 产物 |
|---|---|---|
| 生成 | 用户在计划屏点「AI 创建自动化」，一句话描述目标；AI 起草配置（提示词、调度、agent、precheck、上下文）并展示全文 | 配置草稿和用户的原话记录 |
| 调试 | AI 创建禁用状态的任务并试跑（独立终端，用户实时可见）；AI 读回运行结果，分析偏差、迭代修改、再试跑；试跑前告知真实副作用 | 若干试跑记录和最终调好的配置 |
| 上线 | 用户在自动化页自己启用；调度按配置真实到点触发 | 已启用的任务和逐次运行历史 |
| 运转 | 到点触发；上次未完跳过并记录；完成或失败沿用现有完成通知 | 可追溯的运行历史、现有完成通知 |
| 外部触发 | serve 模式下，任务详情展示 webhook 地址与 token；外部系统带 token 调用 → 触发一次运行，历史记 trigger=webhook | 可被外部事件驱动的任务 |
| 搬运 | 列表行菜单导出 JSON 文件；另一台机器导入，重新绑定项目/工作区/宿主后创建 | 可移植的任务配置文件 |

## 行为规则与异常

### 调度

- 调度选择器维持现有五种预设（每小时、每天、工作日、每周、自定义 cron）不变；一次性任务经 composer 会话或 CLI（`--trigger once --at`）创建，不加预设项（2026-10-10 再审：预设增强砍除）。
- 一次性任务到点触发一次。错过时，在宽限期内（沿用现有 missedRunGraceMinutes）补跑一次；超过宽限，记一条 skipped_missed，任务显示「已结束」。跑完（无论成功失败）即「已结束」，记录保留不删。
- 自定义 rrule 含 `FREQ=MINUTELY`/`INTERVAL` 时按标准语义解析（起点 + k × 间隔），「每 90 分钟」可经自定义表达；不提供专用预设。
- 「已结束」是现算的推导值（一次性过期或已派发），不是存储状态；和用户的暂停开关 enabled 分开呈现。
- 执行次数上限不支持（2026-10-10 再审砍除）；rrule 里的 `COUNT` 解析容忍不报错、不生效。

### 生成与调试会话

- 入口在计划屏页头，与「配置自动化」并列。点击后，用户的描述作为一次性上下文启动 composer 会话，并打开原生终端。
- 会话里 AI 的操作序列：起草并展示配置 → `orca automations create --disabled` 创建 → `orca automations run` 试跑 → `orca automations runs --json` 读回 → `orca automations edit` 迭代 → 提示用户去自动化页启用。
- **AI 不执行启用**：`--enabled` 永远留给用户。
- **试跑是真实执行**：会改文件、调外部服务。AI 发起试跑前必须告知副作用。
- 试跑终端和 composer 会话是两个窗口：试跑在目标工作区用目标 agent 跑；composer 会话是编排者，读回结果继续迭代。

### 运行

- **并发行为（固定，不可配置）**：到点时上次仍在运行 → 跳过本次，记 skipped_overlap，同因折叠成一条，高频任务不刷爆历史。手动「立即运行」不受限：人明确要跑就跑。存量任务的默认从「允许并行」变为「跳过」，属修 bug 不改特性，发布说明写明（2026-10-10 再审：不提供每任务策略开关）。
- 运行历史每条记录状态、时间、错误与输出尾部；不存提示词快照（2026-10-10 再审砍除）。

### 通知

- 运行完成或失败，沿用现有的会话完成通知（仓内悬浮窗与系统弹窗），本特性**不新建通知链路、不加按任务的通知设置**。
- 错过（skipped_missed）与并发跳过（skipped_overlap）没有运行发生，现状下没有通知——**一次性任务错过暂为静默**，如实登记，随后续待办补。
- **按任务通知设置与 Welink 群推送为后续待办**（整仓尚未接入 Welink，2026-10-09 拍板先沿用现有）：届时一并设计通知判定（失败与跳过分开算）与推送通道。

### webhook 触发

- 仅 serve 模式提供：HTTP 端点接收触发请求，鉴权为每任务随机 token（创建时生成，可重新生成）。
- 调用合法且任务启用 → 立即派发一次运行，运行历史 trigger 记 'webhook'；上次仍在运行时按并发固定行为跳过并记录。
- 任务停用或 token 不符 → 如实返回错误，不触发。
- 桌面模式（非 serve）不开放端口：任务详情如实显示「webhook 触发需要 serve 模式」，不假装可用。
- 不做签名验证、token 轮换策略、IP 白名单（矩阵明确这些是独立能力，届时随事件触发器特性一并设计）。

### 导入导出

- **导出**：列表行菜单「导出」→ 保存对话框，JSON 文件（带 schemaVersion），默认名 `automation-<名称>.json`。CLI `orca automations export <id> [--file]`。
- 文件只含可移植子集：名称、提示词、precheck、agent、调度（含一次性时间）、时区、宽限、工作区模式、基线分支、会话复用。机器绑定字段（宿主、工作区、项目、启用态、计数器、时间戳、webhook token）不导出。
- **导入**：UI 为主——选文件 → schema 校验（不符指名报缺失字段，不部分导入）→ 预填原生编辑器（宿主、项目、工作区留空让人选；agent 标识随文件携带预填——当前实际只用 claude，不做多 agent 兼容特设）→ 人确认后创建新记录。同名任务提示已存在，导入不覆盖。CLI `orca automations import <file>` 需显式传目标参数。
- composer 会话可以帮用户导出调好的任务，供其他机器导入。

### 失败

| 现象 | 结果 |
|---|---|
| 一次性任务错过超过宽限 | 记 skipped_missed，任务「已结束」，如实登记（通知沿用现状，见通知节） |
| 到点时上次仍在运行 | 记 skipped_overlap，同因折叠 |
| 派发被拒（如宿主不可用） | 宽限内下个 tick 重试（同因已折叠）；一次性超宽限记 skipped_missed 后终结 |
| webhook 调用 token 不符 / 任务停用 / 非 serve 模式 | 如实返回错误，不触发、不记录运行 |
| 导入文件不合法 | 指名缺失字段，不部分导入 |
| 外部 provider 表达不了新字段 | 如实显示「不支持」，不阻塞其余功能 |

## 兼容与迁移

- 存量任务没有新字段：行为与今天完全一致（并发默认值变化除外，见上）。
- 存量 RRULE 没有 INTERVAL：按 INTERVAL=1 解析，行为不变；含 COUNT 的表达式容忍忽略、不生效。
- 一次性任务靠 onceAt 字段存在与否判别，此时 rrule 为空；判别与生命周期推导统一走单一模块，消费者不各写字段判断。
- 外部 provider 表达不了新字段时如实显示「不支持」，不阻塞。

## 验收

| 标识 | 场景 | 可观察结果 |
|---|---|---|
| AU01 | 一次性任务到点（应用开着） | 真实触发一次；跑完即「已结束」；记录保留；重启后读回一致 |
| AU04 | 到点时上次仍在运行 | 默认跳过并记 skipped_overlap（同因一条）；手动「立即运行」不受限 |
| AU06 | 计划屏一句话 → composer 会话 | 起草展示 → 禁用态创建 → 试跑（有副作用告知）→ 读回迭代 → 人启用；AI 不执行启用 |
| AU07 | 自动化运行完成/失败 | 现有会话完成通知照常出现（悬浮窗/系统弹窗）；本特性不新建通知链路 |
| AU08 | 导出 → 另一台机器导入 | 校验、预填、人重新绑定后可运行；同名不覆盖；坏文件指名报错 |
| AU09 | serve 模式 webhook 触发 | 带 token 调用真实派发一次，历史记 trigger=webhook；错 token 拒绝；桌面模式如实提示 |

旅程 AUJ01：计划屏点「AI 创建自动化」→ 一句话描述 → AI 起草并试跑迭代 → 人启用 → 到点真实触发 → 收到通知 → 杀进程重开读回一致。验收用例和证据按六环登记；一次性到点真实触发与 composer 全链路是必验项。

（AU02 间隔预设、AU03 次数上限、AU05 提示词快照随 2026-10-10 再审砍除；INTERVAL 解析正确性由单元测试看护。）

## 取舍与待决问题

存储维持 Orca 原结构、只追加可选字段（评估见 [design](design.md) 决策记录），换来以后增量同步 upstream 不冲突；代价是「一次性还是循环」要靠字段存在性判别，收口在单一模块里，不让每个消费者自己判断。

待决：无——原型豁免已拍板（见篇首状态）；按任务通知设置与 Welink 推送为后续待办（见通知节）。
