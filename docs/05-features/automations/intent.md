# 定时任务：可生成、可调试、可信赖的定时工作

> 给 Builder 与开发判断价值和范围时读；本文管用户目标，不写控件与实现。行为见 [spec](spec.md)，设计见 [design](design.md)，证据见 [STATUS](STATUS.md)。目标或边界变化时更新。
>
> 状态：2026-10-09 设计会话逐节确认范围（G1–G6、G8、G9、G13）、增量字段方案与对话式调试形态；文档待人 gate。设计认可不表示实现或真壳验收通过，证据见 STATUS。

## 用户与问题

Builder 已能把工作交给会话执行，也希望周期性或指定时刻的工作自动发生——依赖巡检、发布准备、一次性提醒。现状定时任务直接手写 prompt 保存：写错要到下次到点触发才发现，没有生成与调试过程；调度只有五种无限循环预设，「明早九点跑一次」「每半小时」「跑五次就停」都表达不了；上次没跑完，到点会再开一个终端堆叠；任务后来被编辑，历史说不清当时跑的是什么；跑失败没人知道；调好的任务不能搬到另一台机器。

## 价值与依据

让定时工作从「配好祈祷它跑对」变成「调好再上线、跑坏能知道、历史说得清、配置可搬运」。依据：2026-10-09 竞品调研——Cursor（`/automate` 自然语言生成配置）、腾讯 WorkBuddy（一次性为一级调度类型）、DeepSeek Harness（固定间隔与日历时间分模型、指令快照、错过只补最新）、OpenClaw（一次性任务生命周期）、GitHub Copilot CLI（`/every`、`/after`）一致验证这些是标配能力；本仓代码核对确认缺口真实存在（RRULE 解析器静默忽略 `INTERVAL`/`COUNT`、无并发保护、运行记录无 prompt 快照）。

## 目标体验

用户在计划屏点「AI 创建自动化」，用一句话描述周期目标；AI 起草完整配置并展示，创建禁用态任务、试跑一次、自己读回结果分析偏差、迭代修改，全程对话内闭环；满意后由人在自动化页启用。调度配置覆盖一次性、每 N 分钟/小时、执行次数上限；到点时上次仍在运行则跳过本次；每次运行留存当时实际使用的提示词快照，可携带上次运行结果；运行完成或失败按任务设置发系统通知与 Welink 群消息；任务可导出为文件，在另一台机器导入后重新绑定宿主即可用。

## 范围与边界

- 包含：调度表达扩展（一次性／固定间隔／次数上限）、生成与调试会话、运行提示词快照、并发跳过策略、携带上次结果、系统通知与 Welink 群推送、导入导出。
- 存储维持 Orca 原有结构，只追加可选字段；一次性判别与生命周期推导收口单一模块，便于增量同步 upstream。
- 不做：事件触发器（GitHub/CodeHub 事件，届时单独立特性）、agent 自适应节奏、按任务工具白名单、模板市场、截止日期 UNTIL 与 precheck 独立调试（缓）。
- 外部 provider（hermes/openclaw）表达不了的新字段如实降级显示，不阻塞。
- 启用永远由人操作：AI 只创建禁用态与迭代，不替人启用（四铁律「完成由人确认」的延伸）。

## 成功判据与待决问题

Builder 能从一句话描述出发，经试跑迭代得到一个按时正确触发的任务；一次性任务到点真实触发且跑完即终结；高频任务上次未完成时不堆叠；任何历史运行能回答「当时用的什么提示词」；跑失败当天能收到通知；任务文件在另一台机器导入即用。

待决：spec 原型是否豁免（UI 均为现有编辑器与列表的增量控件，待人拍板）；Welink 群机器人配置面细节（webhook 凭据形态）随实施核对。
