# 定时任务增强 — 发布说明草稿

> **维护约定**：给发布时取用文案的人读取；发布后本篇归档不再演进，行为正本在 [spec](spec.md) 与 [design](design.md)。只写用户可见变化与迁移影响，不写实现历史。草稿随特性分支维护，正式发布由人拍板取用。

以下为定时任务增强的用户可见变化，按影响排序。

## 行为变化（存量任务受影响）

- **并发默认从「允许并行」改为「跳过」**：到点时如果上一次运行还没结束，本次不再并行开新会话，而是记一条跳过（`skipped_overlap`，同因重复跳过折叠成一条并计数），运行历史不再被高频任务刷爆堆叠终端。手动「立即运行」不受此限——人明确要跑就跑。存量任务同样适用，属缺陷修复而非新策略：堆叠终端从来不是用户想要的。不提供每任务策略开关（2026-10-10 再审拍板）。

## 新增能力

- **一次性任务**：`orca automations create --trigger once --at <ISO时间>` 建立只跑一次的任务；到点由调度器真实派发（非手动触发），派发后任务进入「已结束」，列表与详情显示「Once at \<时刻\>」与「Finished」。试跑（手动运行）不消耗一次性机会。
- **间隔任务**：`--trigger every <N>m|h`（如 `every 90m`），按固定间隔触发。
- **Webhook 触发（serve 模式）**：每任务一枚 token，`POST /webhooks/automations/<id>` 带 `x-webhook-token` 头即可触发；停用返回 409，token 不符 401。桌面模式无此端点。
- **导入导出**：`orca automations export <id>` 导出可移植 JSON（只含配置，不含宿主/启用态等机器绑定字段），`orca automations import <file> --repo|--workspace|--project` 在另一台机器导入（导入后默认停用，需人启用）；UI 列表行菜单「Export」、工具栏「Import」同能力。
- **AI 创建自动化**：计划屏页头新增入口，用一句话描述目标，AI 起草完整配置、以禁用态创建、试跑、读回迭代；启用永远留给用户自己操作。

## 界面

- 一次性任务的调度列与详情显示「Once at \<时刻\>」；派发后下次运行列与详情显示「已结束」（这是推导出的生命周期状态，与人的暂停开关分开呈现）。
- 运行历史中因上次未结束而跳过的行显示「Skipped — previous run still active」。
