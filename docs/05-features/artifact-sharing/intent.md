# 产物分享：把本地 HTML 成果变成团队可打开的链接

> 给 Builder、Leader 与评审者判断价值和范围时读。本文定义为什么做、为谁做及边界；行为与验收见 [spec](spec.md)。价值或范围变化时更新，不记开发流水。

团队成员在 BW 里生成报告、原型或验收材料后，需要把成果发给同事评审。现状两条路都不合适：Orca 原生分享依赖个人账号并把文件传到外部服务；远程连接要求对方已配对同一台主机，分享人的机器一关就打不开。团队希望用自己的服务器承接这份产物，链接对任何能访问内网的人有效。

团队评审中，查看者只能把位置转述到聊天工具。[Issue #760](https://github.com/forcegravity1989/builder-workbench/issues/760) 记录了在分享页直接标注元素、让所有查看者可见的需求。

## 目标体验

1. 分享人在浏览器标签工具栏或编辑器页头点「Share as artifact」，确认后把当前文件上传到团队自管的分享服务，拿到一个公开链接。
2. 同一个文件再次分享时覆盖原链接内容；分享人不需要管理另一套链接列表。
3. 分享服务地址与登记密钥随客户端内置；首次分享自动登记设备并保存令牌，用户不做任何配置或复制粘贴。
4. 分享人的机器可以关机，同事与外部浏览器只要有网络访问即可打开链接。
5. 打开链接的任何内网用户无需账号即可在页面上留下批注，批注可定位到具体元素（如某个按钮、某段文字）；批注完成后，所有查看这份分享的人都能看到全部批注，评审讨论留在页面上而不是回到聊天工具里转述位置。

## 边界

- 客户端分享入口、设置 → Artifacts 的本机分享清理列表与 CLI 迁移已随 PR #691 合入 main（2026-11-20），真实内网与真壳人验收待补；Orca 云端 Artifacts 管理页与相关开关已随之移除，分享不再依赖 Orca 账号或云端 artifacts 接口。分享服务地址与登记密钥编译内置，没有用户可配置的服务器设置项。
- 不改造 Orca 账号、配对或权限体系；分享链接不携带 BW 身份，也不校验登录。
- 分享页批注是**异步多人批注**，不是实时协同：查看者写完批注后，其他人刷新或轮询可见即可，不追求两人同时在线时的即时互见；配对会话内的双人实时批注由 #576 单独跟踪。批注匿名可写（无账号门槛），靠限流与条数/长度上限治理滥用；分享者可删除任意批注，批注作者可删除自己的。
- 链接内容是点击分享那一刻的快照；批注挂在链接上，随内容覆盖更新保留（内容变了批注仍在，元素定位可能失效，失效时降级为页面级展示）。服务端只接受 HTML；客户端把 Markdown 渲染为独立 HTML 文档后上传，两条入口的清洗差异见 [spec](spec.md)。
- 分享地址与登记密钥是编译进客户端的部署常量；设备令牌是本机文件，不进入同步设置或账号体系。
- 服务端的部署、容量与运维文档见 `services/bw-share/`。

## 成功判据

用户首次分享即得到可打开的链接，不需要填写地址或令牌；重复分享更新同一链接；服务端不可达、设备被拒或文件过大时如实说明原因。第二位查看者打开同一链接，能看到第一位留下的批注，并定位到仍存在的目标元素。真实内网机器、不同浏览器打开以及重启后链接回显由后续验收补齐，单元测试与本地联调不能替代。
