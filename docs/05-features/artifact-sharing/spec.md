# 产物分享规格：自管服务上的分享入口

> 给设计、实现、内部评审与验收者读取。本文维护产物分享的入口、配置、数据归属与验收点；价值见 [intent](intent.md)，可点原型见 [prototype/index.html](prototype/index.html)（分享弹层与设置页，演示假体，不构成验收证据）与 [prototype/annotations-viewer.html](prototype/annotations-viewer.html)（分享页批注，演示假体，不构成验收证据），链状态与证据边界见 [STATUS](STATUS.md)。用户已确认批注操作路径，整篇规格经授权检视通过。行为或认可状态变化时更新对应主题，不追加施工流水。

## 承载与复用

- 浏览器标签工具栏和编辑器页头继续使用既有「Share as artifact」按钮与 Popover，不新增常驻导航或第二套分享入口。
- 分享弹层复用原生 Popover、Button 和状态文案；已分享的链接沿用既有链接面板（复制、在浏览器打开、更新内容、删除）。
- 设置 → Artifacts 展示本机分享过的文件列表并可删除：删除走与弹层「Remove link」相同的主机端链路，成功后原公开链接即失效。列表不引入账号逻辑，只读本机 `records.json`。设置页没有分享服务地址、令牌输入或功能开关；Orca 云端 Artifacts 管理页、「Show Artifacts Button」「Allow publishing public artifact links」等开关已全部移除。
- CLI `orca artifacts list/share/update/unshare/delete` 走 `workbench.share.*` RPC，与页面点击同一条主机端链路、共用同一份本机记录；CLI 不再依赖 Orca 账号或云端 artifacts 接口。CLI 单命令传输上限 800 KB（受运行时 RPC 约 1 MiB 控制帧限制），超限提示改用页面分享，页面上限仍是 10 MiB——这是显式取舍，不是遗漏。来源键决定「同一文件是否同一条链接」：本机文件两条入口都用绝对路径，SSH 远程文件由主机侧 passthrough 统一包成 `["ssh", 目标, 路径]`，因此**这两类都指向同一条链接**；只有远程运行时（非 SSH）文件例外，编辑器用 `["editor", 环境, 主机, 路径]` 元组而 CLI 用 SSH 元组，同一文件从两条入口分享会得到两条互不覆盖的链接。
- 弹层内的公开链接由本机分享记录读回，不请求 Orca 账号状态。
- 公开链接 `/s/:id` 打开的是**分享查看页（viewer）**：原始内容在沙箱 iframe 中展示，页面提供批注面板；原始内容本身经 `/s/:id/raw` 提供，与上传内容逐字节一致。viewer 与批注 API 同源，被分享内容在 opaque 沙箱内：读不到批注 API 响应，写批注被服务端的 `application/json` content-type 校验挡下（沙箱内容发该类型会触发 CORS 预检，预检不被允许；`text/plain` 简单请求被 415 拒），也带不上删除令牌头——现有安全边界不变。

## 配置与数据归属

- 分享服务地址与设备登记密钥编译在客户端，用户无需配置，也不经过设置页或 RPC。服务地址与登记密钥的修改走代码评审。
- 设备上传令牌由客户端在首次分享时用登记密钥自动换取，保存在本机 `userData/workbench-share/config.json`（0600），之后持续复用；用户不手工填写或复制令牌。服务端只保存令牌哈希。
- 服务端返回 401 时清除本地令牌、重新登记并重试一次，避免一次性失效让用户卡死。编辑令牌只留在主进程，不随发布结果返回渲染进程。
- 每个文件对应的分享记录保存在同目录 `records.json`（0600），按文件来源键索引，记录分享 id、公开链接、编辑令牌和过期/更新时间。编辑令牌只留在本机，用于覆盖内容或删除链接。两个文件都复用仓内既有的安全写入（临时文件 + ACL 收紧 + fsync + rename），断电不会留下零长文件把记录伪装成「没分享过」。
- 本机记录在每次写入时顺带清理**服务端保留期已过**的条目（按本机时钟判断；时钟超前于服务端时可能提前清理，此时旧链接在服务端仍活着但本机不再管理）。`expiresAt` 为空（服务端关闭保留期）或无法解析的一律保留——清理不允许丢掉可能仍有效的记录。**不设条数上限**：按数量丢弃最旧记录会让仍然公开、仍可编辑的链接失去本机唯一的编辑令牌，产品内再也无法撤销，与「清理列表」的定位相反；索引规模实际由服务端保留期约束，每条约 200 字节。
- 配置与记录不进入同步设置、Orca 账号或项目仓库；服务端故障不写坏本地文件，读写失败如实返回错误。

## 分享流程

- 弹层每次打开都按文件来源键查询本机记录；查询失败显示重试。已有链接展示链接面板；没有记录时显示「Generate link」。
- 点击「Generate link」后重新读取当前文件内容，按 10 MiB 上限校验；HTML 原样上传，Markdown 经 `marked` 渲染为独立 HTML 文档（含标题与基础样式）后上传，文件名扩展名改为 `.html`。页面入口在浏览器 DOM 内用 `DOMPurify` 清洗渲染结果；CLI 无 DOM，渲染结果直接包装上传，信任级别与 HTML 原样上传一致。
- 有本机记录时用编辑令牌覆盖服务端同一链接；服务端返回 404 说明链接已失效，则删除本地记录并新建链接。
- 上传成功提示「Artifact shared」或「Artifact updated」，链接只在面板中展示，不放进提示消息。
- 设备令牌被拒、编辑令牌失配、超过上限、限流、服务忙、链接失效、网络不可达等错误码由渲染层映射为可读原因；未知码才回显主进程消息。空文件在上传前拒绝。
- 超过 10 MiB 时明确显示「File is too large to share」，并给出实际大小与 10 MiB 上限；上传前本地校验和服端 413 都进同一文案，不让用户猜。
- 链接面板提供「Remove link」，行内二次确认后先调服务端删除，成功才删除本机记录；删除失败保留链接并如实报错。唯一例外是服务端拒绝本机编辑令牌（`stale-record`）：此时本机记录已被移除、行随即消失，界面如实说明原链接可能仍然存在、需运维在服务端删除。

## 分享页批注

- **入口与身份**：任何打开 `/s/:id` 的人无需账号即可批注。作者名自填（留空显示「匿名」），由查看页记在本机浏览器 `localStorage` 中下次自动带出；批注不携带任何 BW 或账号身份。viewer 界面文案纯中文；服务端 404 等静态页维持既有中英双语先例。
- **元素定位**：查看页的「添加批注」打开表单，可直接填写并提交页面级批注。需要定位时点击「选择元素」进入选择模式，点击 iframe 内元素即选中并高亮，选中信息（CSS selector、元素文本摘要、视口内坐标）随批注一起提交。无文本元素（图标按钮、图片、svg、输入框）的摘要回退到可访问标签（aria-label/alt/title/placeholder）或标签名，仍可为空字符串——服务端接受空摘要，查看页此时显示 selector，不因无文本而拒绝批注。查看批注时点击列表项在 iframe 内高亮对应元素；内容更新覆盖后 selector 可能失效，失效的批注保留文字但不再高亮，列表如实标注「元素已变化」（查看页加载与每次刷新时经桥主动探测 selector，失效即标注，无需点击；点击高亮回包按批注 id 匹配，同一 selector 的多条批注各自标注），不删除批注。选择模式下按 Esc 退出选择，表单保持打开并保留已输入的文字；不选元素直接提交则为页面级批注。取消选择或关闭表单即通知沙箱退出选择模式，内容立即恢复正常点击交互（不吞掉取消后的第一次正常操作）；已取消流程的迟到选择结果被丢弃，不会带入重新打开的表单。
- **可见性**：批注提交后立即出现在提交者列表中；其他查看者通过轮询看到（页面可见时每 30 秒拉取一次，页面切到后台时暂停），刷新页面立即拉全量。不做实时推送，两人同时在线不保证秒级互见。
- **写入治理**：单条批注文字上限 2000 字符；每个链接批注总数上限 500 条，写满后如实提示「批注已满」；写入受服务端 IP 限流约束，超限提示稍后再试。
- **删除权**：批注作者可删除自己的批注——提交时服务端生成随机删除令牌随响应一次性返回，查看页按批注独立存于本机浏览器 `localStorage`（同一浏览器多标签互不覆盖，跨标签同步删除能力），服务端只存其哈希；删除时凭令牌匹配。他人不能删除别人的批注；分享者凭编辑令牌经服务端 HTTP 接口删除任意批注（本期 curl/运维直调，BW CLI 不加命令，查看页不内嵌分享者管理界面）。删除失败（本机令牌失效、限流、网络异常）在列表下方如实提示原因，批注保留不误删。
- **数据归属**：批注保存在服务端该链接的批注文件中，随链接删除或过期一起消失；不进 BW 客户端、不进本机分享记录、不进任何账号体系。批注内容不参与内容覆盖更新——重复分享同一文件时批注原样保留。
- **客户端零改动**：分享弹层、设置页与 CLI 的分享/删除链路不变；查看者全程在浏览器中，BW 客户端不感知批注的存在。

## 事实读回与失败

- 分享成功后才写入本机记录；上传失败不改动已有记录，重复分享不会丢失原链接。
- 记录中的链接是本机事实，不宣称服务端一定可访问；打开链接仍由浏览器实际请求决定结果。
- 已保存的设备令牌不因一次网络失败而清空；只有服务端明确拒绝（401）才丢弃并重新登记。
- 设备令牌文件损坏时改名为 `.corrupt-<时间戳>` 留档并按空令牌继续（下次分享重新登记），避免一次损坏锁死分享。
- 本机记录文件读不出来时（零长、被外部改坏）同样隔离留档，但**不当成「没有分享过」**：设置页显示可读的失败原因与重试，不显示空列表；弹层按无记录处理，可以重新分享，此时会建立一条新链接。成功写入一次记录后该状态自动解除。
- 服务端已创建成功但本机记录写不进去时，主机端撤销这次创建再报错，不留一条产品内无法撤销的公开链接；撤销也失败时把链接 id 记进日志，交运维在服务端回收。
- 服务端拒绝本机记录的编辑令牌时（记录来自备份或另一台机器）：分享会丢弃该记录并新建链接，**旧链接可能仍然公开且本机再也管不到**，只能由运维在服务端删除；删除则移除本机记录并按上一条如实告知。
- 分享服务不可达时，已分享文件的弹层仍显示本机记录的链接，但更新会如实报错。

## 取舍

- **viewer 包装页而非脚本注入直出**：向任意 HTML 注入脚本受结构不可控（无 `</body>`、自带 CSP meta）、CSP 冲突与字节承诺破坏制约；viewer 把原始内容留在沙箱 iframe、`/s/:id/raw` 保持与上传内容逐字节一致，安全边界不变。
- **异步轮询而非实时推送**：需求是「批注完成后均能看到」，不是两人同时在线的即时互见；SSE/长连接对 1 GB 级部署机是连接数压力，轮询（30 秒、后台暂停）满足判据且零长连接。配对会话内的双人实时互见由 #576 单独跟踪。
- **匿名可写、令牌删自己的**：内网信任模型下写批注不设门槛（已拍板）；滥用靠 IP 限流 + 条数/长度上限治理。作者删除靠服务端生成并交给查看页保存的随机令牌（服务端存哈希），不引入账号。
- **元素定位用简化模型**：selector + 元素文本摘要 + 视口坐标，不复用 BW 批注的完整 grab payload（computedStyles/reactComponents 等是 agent 修复用的，网页查看者不需要）；selector 失效降级为「元素已变化」的文字批注，不删除。
- **分享者管理批注经服务端 HTTP 接口**：编辑令牌只在 BW 主进程，不进浏览器 URL 或页面；查看页不内嵌分享者管理界面，避免令牌泄露面扩大。BW CLI 本期不加命令，运维用 curl 凭编辑令牌直调。
- **批注只删不改**：匿名身份下「谁能编辑」无法界定，删除重发覆盖绝大多数场景，实现与治理都最简。

## 旅程

在连得上已部署 `services/bw-share` 的机器上打开一个本地 HTML，点「Share as artifact」→「Generate link」，确认首次分享自动完成设备登记，复制链接到另一台机器或非 BW 浏览器打开；修改文件后再次分享，确认同一链接内容更新；重启 BW 后打开弹层读回链接并确认未重新登记；最后点「Remove link」确认删除后本机记录一起消失，再次分享会重新登记/新建。批注段：在打开的分享页上以两个不同浏览器分别添加元素级批注，确认两边都能看到对方的批注并点击高亮；再次分享覆盖内容后批注仍在；作者删除自己的批注后另一边列表同步消失。
