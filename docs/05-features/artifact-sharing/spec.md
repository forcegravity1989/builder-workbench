# 产物分享规格：自管服务上的分享入口

> 给设计、实现、内部评审与验收者读取。本文维护产物分享的入口、配置、数据归属与验收点；价值见 [intent](intent.md)，可点原型见 [prototype/index.html](prototype/index.html)（演示假体，对齐检视返工后的实现，不证明已交付），链状态与证据边界见 [STATUS](STATUS.md)。整篇人工认可：待人确认。行为变化时更新对应主题，不追加施工流水。

## 承载与复用

- 浏览器标签工具栏和编辑器页头继续使用既有「Share as artifact」按钮与 Popover，不新增常驻导航或第二套分享入口。
- 分享弹层复用原生 Popover、Button 和状态文案；已分享的链接沿用既有链接面板（复制、在浏览器打开、更新内容、删除）。
- 设置 → Artifacts 展示本机分享过的文件列表并可删除：删除走与弹层「Remove link」相同的主机端链路，成功后原公开链接即失效。列表不引入账号逻辑，只读本机 `records.json`。设置页没有分享服务地址、令牌输入或功能开关；Orca 云端 Artifacts 管理页、「Show Artifacts Button」「Allow publishing public artifact links」等开关已全部移除。
- CLI `orca artifacts list/share/update/unshare/delete` 走 `workbench.share.*` RPC，与页面点击同一条主机端链路、共用同一份本机记录；CLI 不再依赖 Orca 账号或云端 artifacts 接口。两处差异是显式取舍：CLI 单命令传输上限 800 KB（受运行时 RPC 约 1 MiB 控制帧限制），超限提示改用页面分享，页面上限仍是 10 MiB；来源键按表面构造，本地文件两条入口指向同一链接，远程文件的编辑器入口用带目标的元组键、CLI 用远端绝对路径，因此**同一远程文件从两条入口分享会得到两条互不覆盖的链接**。
- 弹层内的公开链接由本机分享记录读回，不请求 Orca 账号状态。

## 配置与数据归属

- 分享服务地址与设备登记密钥编译在客户端，用户无需配置，也不经过设置页或 RPC。服务地址与登记密钥的修改走代码评审。
- 设备上传令牌由客户端在首次分享时用登记密钥自动换取，保存在本机 `userData/workbench-share/config.json`（0600），之后持续复用；用户不手工填写或复制令牌。服务端只保存令牌哈希。
- 服务端返回 401 时清除本地令牌、重新登记并重试一次，避免一次性失效让用户卡死。编辑令牌只留在主进程，不随发布结果返回渲染进程。
- 每个文件对应的分享记录保存在同目录 `records.json`（0600），按文件来源键索引，记录分享 id、公开链接、编辑令牌和过期/更新时间。编辑令牌只留在本机，用于覆盖内容或删除链接。两个文件都复用仓内既有的安全写入（临时文件 + ACL 收紧 + fsync + rename），断电不会留下零长文件把记录伪装成「没分享过」。
- 配置与记录不进入同步设置、Orca 账号或项目仓库；服务端故障不写坏本地文件，读写失败如实返回错误。

## 分享流程

- 弹层每次打开都按文件来源键查询本机记录；查询失败显示重试。已有链接展示链接面板；没有记录时显示「Generate link」。
- 点击「Generate link」后重新读取当前文件内容，按 10 MiB 上限校验；HTML 原样上传，Markdown 经 `marked` 渲染为独立 HTML 文档（含标题与基础样式）后上传，文件名扩展名改为 `.html`。页面入口在浏览器 DOM 内用 `DOMPurify` 清洗渲染结果；CLI 无 DOM，渲染结果直接包装上传，信任级别与 HTML 原样上传一致。
- 有本机记录时用编辑令牌覆盖服务端同一链接；服务端返回 404 说明链接已失效，则删除本地记录并新建链接。
- 上传成功提示「Artifact shared」或「Artifact updated」，链接只在面板中展示，不放进提示消息。
- 设备令牌被拒、编辑令牌失配、超过上限、限流、服务忙、链接失效、网络不可达等错误码由渲染层映射为可读原因；未知码才回显主进程消息。空文件在上传前拒绝。
- 超过 10 MiB 时明确显示「File is too large to share」，并给出实际大小与 10 MiB 上限；上传前本地校验和服端 413 都进同一文案，不让用户猜。
- 链接面板提供「Remove link」，行内二次确认后先调服务端删除，成功才删除本机记录；删除失败保留链接并如实报错。

## 事实读回与失败

- 分享成功后才写入本机记录；上传失败不改动已有记录，重复分享不会丢失原链接。
- 记录中的链接是本机事实，不宣称服务端一定可访问；打开链接仍由浏览器实际请求决定结果。
- 已保存的设备令牌不因一次网络失败而清空；只有服务端明确拒绝（401）才丢弃并重新登记。
- 设备令牌文件 JSON 损坏时改名为 `.corrupt-<时间戳>` 留档，随后按空令牌继续（下次分享重新登记），避免一次损坏锁死分享。
- 本机记录文件读不出来时（半写、被外部改坏）同样隔离留档，但**不当成「没有分享过」**：设置页如实报告记录不可读并给出重试，不显示空列表；弹层按无记录处理，可以重新分享，此时会建立一条新链接。原链接仍然有效，只能在服务端删除。
- 服务端拒绝本机记录的编辑令牌时（记录来自备份或另一台机器）：分享自动丢弃该记录并新建链接；删除则移除本机记录，并明确告知原链接可能仍然存在、需运维在服务端删除——不留下既改不动也删不掉的行。
- 分享服务不可达时，已分享文件的弹层仍显示本机记录的链接，但更新会如实报错。

## 验收点

| #   | 场景                       | 期望                                                                                                                       |
| --- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| A01 | 全新机器首次分享           | 自动登记设备并生成链接，用户无须填写地址或令牌                                                                             |
| A02 | 再次分享                   | 复用已保存的设备令牌，不重复登记                                                                                           |
| A03 | 服务端拒绝旧令牌           | 自动重新登记并重试一次，成功后用户只看到正常分享结果                                                                       |
| A04 | 分享 HTML 文件             | 拿到本机记录的链接，公开浏览器可打开                                                                                       |
| A05 | 分享 Markdown 文件         | 上传的是渲染为独立文档的 HTML，链接内容可读                                                                                |
| A06 | 同一文件重复分享           | 覆盖同一链接内容，不产生第二条记录                                                                                         |
| A07 | 服务端链接被删除后再次分享 | 自动新建链接并替换本机记录                                                                                                 |
| A08 | 超过 10 MiB、服务不可达    | 分别显示「File is too large to share」及实际大小、网络原因；不写坏本地记录                                                 |
| A09 | 重启应用                   | 已分享文件的弹层仍能读回链接，令牌继续有效                                                                                 |
| A10 | 删除链接                   | 二次确认后服务端删除成功才移除本机记录；网络等失败保留链接，只有服务端明确拒绝本机编辑令牌时才移除记录并告知链接可能仍存在 |
| A11 | Web 或远程客户端           | 发布、读链接、删除 RPC 在主机端直接拒绝；设置 → Artifacts 显示「在主机端打开」提示而非空列表                               |
| A12 | 设置页清理已分享文件       | 列表读本机记录，删除二次确认后服务端删除成功才移除记录，原链接随即失效                                                     |

## 旅程

在连得上已部署 `services/bw-share` 的机器上打开一个本地 HTML，点「Share as artifact」→「Generate link」，确认首次分享自动完成设备登记，复制链接到另一台机器或非 BW 浏览器打开；修改文件后再次分享，确认同一链接内容更新；重启 BW 后打开弹层读回链接并确认未重新登记；最后点「Remove link」确认删除后本机记录一起消失，再次分享会重新登记/新建。
