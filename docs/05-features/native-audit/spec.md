## 判读准则

**正本在 [准则正本](../../../.claude/skills/native-audit/references/rubric.md)**（v2，2026-09-01）：9 段 37 条，段落按 [AI-Native SDLC playbook 提炼版](../../10-reference/ai-native-sdlc-playbook.md)的六阶段 + 贯穿机制 + 治理四条排列——S0 规矩正本 · S1 计划·意图 · S2 设计·决策 · S3 构建 · S4 测试·验证 · S5 评审·合入·发布 · S6 运维·复盘 · S7 知识维护·反 slop · S8 AI 协作。每条按**制度化阶梯**打分：**0 = 无/不可考（Unknown）· 1 = 有痕迹 · 2 = 成文 · 3 = 机器强制**。分数只回答「这条纪律被制度化到哪一级」，不评价代码好坏。rubric 末尾两张矩阵证明双向覆盖：dsh 58 组做法零孤儿，playbook 每阶段 / 贯穿机制 / 治理条均有准则承接；三条 playbook 主张 dsh 无一手实证（禁改测试、回滚排练、指标越线检测），如实标注。

**Unknown 纪律（对齐四铁律）**：探针拿不到的条目标 Unknown 计 0 并注明原因（浅历史、squash、无权限、超时），绝不推断补分。

**判读一致性**：机械读数由随 skill 携带的 `battery.sh` 出，两仓同一把尺；0-3 定级对照 rubric「3 分的样子」列 + 两个锚点（dsh ≈ 3 分锚、本仓 ≈ 2 分锚，读数与定级见 [prototype-report.md](prototype-report.md)）。v1 七维（规范/决策/门禁/AI/commit/验证/反 slop）已并入 v2 的 C01-02 / C21-23 / C32 / C81 / C36 / C41-42 / C71-73。

## 操作逻辑

**主路径（单仓）**：入参仓路径/地址 → 若远端则 `git clone --filter=blob:none`（历史全、blob 惰性，巨仓可行）到临时目录 → 跑探针脚本（纯脚本出数）→ 读关键规范件样本（AGENTS/贡献规矩/CI 配置，限额防炸上下文）→ 按准则定级 → 出单仓报告（探针读数 + 九段评分与 37 条明细 + 缺失清单按「升一级最便宜」排序 + 与锚点对照 + 探针异常）。

**仓群路径**：入参清单文件（每行一仓）或 codehub 组名（`codehub-cli` 列仓）→ 每仓一个子代理跑主路径（模型 sonnet，难仓 opus，**一律不用 Fable**；并发 ≤5）→ 主线程只收各仓评分卡 → 汇总榜（九段 × 仓矩阵）+ 全群 top 缺失（按条计频） + 「BW 铺底可直接补哪些」对照。

**出错**：clone 失败/无权限 → 记入失败清单继续下一仓，报告如实列出；命令超时（巨仓）→ 降级为近一年历史并在报告标注窗口；子代理失联 → 该仓整体标 Unknown。任何降级都出现在报告里，不静默。

## 客户会问（外 FAQ）

- **和资产盘点、知识库体检什么关系？** 资产盘点盘 BW 可见物齐不齐、知识库体检查被管项目 `.bw/` 知识件健康度——都是对着 BW 规范查。native 评估对**任意仓**（不必被 BW 管）量 AI-native 制度化水位，是拉新证据链，不是存量健康检查。
- **不做什么？** 不评代码质量、不做安全审计、不改被扫仓任何东西（只读）、不自动建活（缺失清单转成活由人决定）。
- **报告可信吗？** 探针命令随报告附出，任何数字可复算；判读级别附引用的仓内证据路径。

## 硬核挑战（内 FAQ）

- **`codehub-cli` 本机不可用**：内网仓群扫描必须在装过 Workbench（旧名 buddy）的机器（`%USERPROFILE%\bin\codehub-cli.exe`）或有内网 git 权限的环境跑。skill 启动即探测，不可用则明确报「内网模式在此机不可用」，不装死。**这是首扫的第一风险。**
- **成本**：机械层零 token；判读层每仓一个子代理（读样本 + 定级），10 仓一轮约一顿饭时间。100+ 全量前先用 10 仓校准准则，避免用漂移的尺量全群。
- **准则会不会带 BW 私货**：会，且是本意（发起人指令「结合我们bw的一些理念」）。准则里 BW 特有取舍只有两条：Unknown 纪律、验证形态不限（不因 E2E-only 扣分）。其余准则来自 dsh 一手实证与 playbook 主张，逐条对应见 rubric 的 M1/M2 矩阵。
- **成功指标**：首扫 N 仓 N 份报告全出、失败清单为空或有因；缺失清单被引用去开活/铺底 ≥1 次（30 天内）。
