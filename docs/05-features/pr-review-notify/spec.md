# 通知规格：PR 评审旅程

> 给设计、实现、内部评审与验收者读取。本文维护通知特性的行为、来源边界、验收与旅程；首期只有 PR 评审通知。价值见 [intent](intent.md)，实现与验证见 [STATUS](STATUS.md)。行为变化时更新对应主题，不追加施工流水。

## 承载与复用

- 工作树原生上下文菜单增加「发送评审」；没有可定位的开放 PR 时置灰并说明原因。
- 本机一个可拖动入口，原生 Popover 中显示「我发出的评审」与「待我评审」，不增加侧栏状态或全局页签。角标是两类记录总数，不代表未读数。
- 拖动、位置夹取与持久化共用原生浮动工作区能力，位置键独立；按钮、分节、徽标、工具操作复用原生组件。
- 点击通知直接定位原生 PR 详情。作者与评审人的可用动作由原生详情和 provider 权限决定，不新增通知专属只读规则。
- [原型](prototype/index.html)直接编译产品通知组件，外壳引用现行版本工作区原型；主机与 PR 为模拟数据。既有 PR 详情标为沿用，不重画。

## 发送与接收对象

- 工作树原生菜单「发送评审…」打开小弹窗，展示 PR / MR、可搜索的已连接主机多选列表、全选和发送按钮；不新增常驻导航或配置页。
- 首次默认全选当前已验证、传输就绪的主机；用户可逐项取消或多选。项目是否登记不影响收件资格，主机名称不代表人的身份。本期不建立群组、成员名册或角色映射。
- 再次发送默认沿用该请求上次确认发送的完整名单，允许调整；新增连接不自动加入。断开、移除或重配的旧目标明确显示不可用，可移除或保留以取得真实失败结果，不静默替换为新身份。取消或零选择不投递。
- 发送前重新核对原生连接、配对版本和当前 runtime 身份。逐台投递，一台失败不阻断其他目标；全部成功、部分成功或全部失败及原因逐主机可见。至少一个保存成功才推进轮次，全失败保留原记录。
- 投递复用原生加密 RPC 与鉴权。接收端验证请求并持久保存后确认送达，不以本机项目登记拒收；不配置独立监听端口或 token。
- 你已连接对方即可通过该方向发送；对方若没有本地项目副本，需要已有对项目所在主机的连接才能访问。通知不自动反向配对、不授予新权限、不自动克隆项目。

## 通知、轮次与删除

- 同一 PR / MR 的发出记录持续保留，直到作者删除。上轮已确认送达后，再次发送为新轮次并重新记录统计起点。确认超时或全部失败的尝试在本机保存为待重试请求，不显示为已送达；用户手动重试复用该请求的身份和时间，避免双方统计起点不一致，不后台自动重试。
- 一个请求有独立周期身份。删除后再发生成新周期，从第 1 轮开始；接收端不会因为旧周期曾到第 2 轮而丢掉新请求。
- 接收端按项目与 PR 汇总。相同周期重复或较旧轮次不重建条目；同一发送身份的较旧周期不覆盖新周期。新轮次清空旧读数，旧在途请求也不得写入新轮次。
- 「待我评审」不随点击消失，不另造已评审/未评审状态。项目尚未接入或访问暂不可用时仍保留通知并提示「暂时无法访问该项目」；项目或连接恢复后重新定位和读回。
- 从收件名单移除主机不会撤回旧通知。删除只影响本机发出记录及周期，不关闭 PR、不撤回其他主机已经保存的请求。
- 有当前轮次未解决意见且 PR 仍开放时，允许「解决检视意见后 · 再发起评审」。通知不会替 provider 标记线程已解决。

## 事实读回与失败

- PR / MR 定位与检视线程读取沿原生宿主路由。打开通知优先匹配本机相同远端身份的项目，其次匹配可访问的远程项目；CodeHub 详情的请求与缓存绑定同一来源，不受当前焦点主机变化影响。仓库身份保留 host 与完整路径，支持 CodeHub 多级项目。
- 本期接入 GitHub PR 与 CodeHub MR。未解决数统计本轮起点之后创建、尚未解决的检视线程，同一线程只算一次。GitHub 沿用完整 review thread；CodeHub 以讨论根的时间与 resolved 为准，回复不覆盖根状态，系统活动和独立普通评论不计入。原生详情仍保留这些评论。
- 完整性由宿主读端明确证明。网络/权限/线程接口失败、旧宿主不支持完整读回、线程根、解决状态或时间缺失、线程超过当前原生查询范围时，显示未知而不是零。
- 状态、Checks 和意见徽标只展示成功读回的事实。失败时隐藏旧徽标，显示原因与最后读回时间；历史值不能冒充当前成功。
- PR 动态不写入通知存档。打开面板、窗口聚焦、发送及接收新轮次时刷新；自动刷新同一轮次至少间隔 30 秒，手动刷新可立即重读。
- 收件箱由本机 runtime 持久保存；窗口挂载、聚焦及每 5 秒通过原生 RPC 读取一次。窗口关闭/重载不丢已确认通知；runtime 不可达则发送端报告失败，本期不提供离线代投或后台自动重试。
- 发出记录保存在本机用户存储。存档读取/写入失败明确报错，不覆盖损坏数据、不声称重启可恢复。通知不写项目仓库、不建业务数据库。

## 验收点

| #   | 场景                                                | 期望                                                                   |
| --- | --------------------------------------------------- | ---------------------------------------------------------------------- |
| N01 | 有开放 PR 的工作树                                  | 原生菜单可发送；无 PR/关闭/合入时置灰说明                              |
| N02 | 多台已连接主机，含无本地项目的决策主机              | 默认全选，可搜索多选；只给明确选择的主机投递                           |
| N03 | 发送全部/部分/全部失败                              | 逐主机如实回报，至少一台保存成功才推进轮次                             |
| N04 | 接收端窗口重载与 runtime 重启                       | 已确认请求可恢复，不依赖临时端口或窗口广播                             |
| N05 | 本机副本、共享远程项目或暂不可访问                  | 前两者进入对应宿主的原生详情；无访问时保留通知，重载后仍在，恢复后重读 |
| N06 | 新轮次与删除后重发                                  | 新周期第 1 轮能收到；重复及过期结果不覆盖                              |
| N07 | GitHub / CodeHub 线程、系统及普通评论、缺失根或状态 | 只统计完整读回的本轮未解决线程，回复不覆盖已解决状态，失败为未知       |
| N08 | 成功读回后断网                                      | 两类通知隐藏旧徽标并显示失败及最后读取时间                             |
| N09 | PR 合入或关闭                                       | 状态按事实展示，不再显示再发起入口                                     |
| N10 | 重发、增减收件人、旧目标断开/移除/重配              | 沿用上次名单，可显式调整；旧目标不可用明确提示，不自动加入新连接       |
| N11 | 删除及应用重启                                      | 发出记录、周期与删除结果一致；PR 动态重新读取                          |
| N12 | 拖动、窗口尺寸变化、深浅色                          | 与原生浮动工作区共用行为，独立保存位置                                 |

## 旅程

两台真实主机 A/B 已建立原生连接，B 分别以本机项目副本和通过反向连接访问 A 项目两种方式验证：A 在工作树右键多选收件主机后发送 → B 收到通知 → B 直接进入对应宿主的原生 PR / MR 详情并提出检视意见 → A 看到本轮未解决数并再发起 → B 收到新轮次 → B 合入 PR → A 读到已合入并删除通知。再验证一次接收端重载、失败读回及删除后第 1 轮重发。

本机 CDP 可验证原生入口、UI、宿主 API 与持久读回的简单路径；真实两主机、跨网络与实际评审写入留给具备条件的环境，不用模拟数据代替。
