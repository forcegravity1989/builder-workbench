# spec — 任务管理：链接直达

> **维护约定**：给实现、检视和验收本次链接直达的人读取。范围为既有任务管理的终端／会话入口，不重定义全部任务列表和管理交互。价值见 [intent.md](intent.md)，可点目标见 [prototype.html](prototype.html)，证据边界见 [STATUS.md](STATUS.md)。行为或验收决定变化时更新。

## 范围与入口

终端 HTTP／OSC 8 链接和原生智能体会话的网页链接复用同一动作菜单。识别 GitHub Issue／PR 与 CodeHub Issue／MR；原型仅表达菜单到既有详情的导航，不代表新详情设计或已交付能力。

本次方向、默认内部及最小承载范围于需求会话中经人选项确认；仓外实施计划已获批准。现有详情布局与操作原样复用。

## 用户旅程

1. Builder 在会话或终端找到完整任务链接。
2. 普通点击按已有链接菜单开关显示动作；启用时主项为「在任务中打开」，Ctrl／Cmd 点击直接执行主项。第二项 System Browser 对应 Shift+Ctrl／Cmd 点击；可用的 Orca Browser 为无快捷键的第三项。
3. 以完整来源匹配已登记项目，使用本机 `gh` 或 `codehub-cli` 点读明确类型的任务。
4. 身份核对成功后进入已有 Issue／PR／MR 详情；关闭详情返回原视图，不丢原工作区和会话。
5. 读取失败显示原因与下一步，不自动打开浏览器；Builder 可以重新点击原链接并显式选择浏览器。

## 行为规则与异常

- 来源与本机账号沿 [页面读取来源](../../architecture.md#页面读取来源)。终端所属主机不覆盖任务屏的账号策略。
- GitHub.com 按完整 owner／repo 识别；自定义 GitHub Enterprise 主机必须有已登记的 GitHub 来源身份支持，不将任意 `/issues/N` 网页当 GitHub。
- CodeHub 按现有主机规则和完整项目路径识别，支持 `issues/N`、`merge_requests/N` 及 `/-/` 路由，Issue 和 MR 不互相猜测。克隆主机与网页主机不同时，只有本机 CLI 的项目元数据证明两者属于同一登记项目才接受。
- 后一次点击替代尚未完成的任务导航；读取期间离开原视图、工作区或会话后，旧结果不抢回页面。模块加载失败同样显示原因与浏览器恢复提示。
- 仓库匹配考虑已登记 origin／upstream；有本机副本优先，不按目录名或当前活动项目猜测。
- 链接编号必须为正安全整数；读取返回的类型、编号、仓库与请求不一致则拒绝打开。
- 未登记项目提示先添加该项目；缺 CLI、未登录或无权限提示检查本机集成和访问权限。保留原会话。
- 显式浏览器选择绕过任务路由，并保留查询与评论锚点。普通网页和文件／工作区／终端 handle 的原有行为不变。
- 内部打开只读；评论、关闭、重开、评审、合入仍由已有原生动作和人的明确操作负责。本次不触发上述动作。

## 验收

| 标识 | 场景                                | 可观察结果                                                 |
| ---- | ----------------------------------- | ---------------------------------------------------------- |
| TL01 | 终端点击 GitHub Issue／PR           | 菜单优先内部；直达正确类型与编号的现有详情                 |
| TL02 | 原生会话点击 GitHub／CodeHub 任务   | 与终端相同的主动作，数据沿正确 CLI                         |
| TL03 | CodeHub Issue／MR 链接              | 完整项目路径与 host 一致，Issue 不误开为 MR                |
| TL04 | 显式选择系统／内置浏览器或普通网页  | 仍按原行为打开原链接，任务路由不抢显式选择                 |
| TL05 | 仓库未登记、身份不符、CLI／访问失败 | 提示原因与下一步，不误开当前项目同号任务，不自动克隆或登记 |
| TL06 | 关闭详情并继续会话                  | 返回原视图，工作区／会话保持，导航未产生业务写操作         |

旅程 TLJ01：在真实 Electron 终端或会话打开任务链接 → 查看对应真实 CLI 详情 → 返回原会话；GitHub 与 CodeHub 的执行证据分别记录。评论定位不作为本次判据。

## 取舍

复用现有详情与来源路由，只加薄挂载。不以 Orca Browser 替代原生任务，不放宽远端执行白名单、不新增凭据面。不支持未登记仓库的无检出浏览器式详情，因为现有详情需要明确项目上下文；失败可用浏览器继续。
