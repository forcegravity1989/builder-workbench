# intent — 任务管理

> **维护约定**：给判断与实现任务管理的人读取。本篇承载既有任务管理特性的用户目标；本次只定义从终端和会话链接直达任务详情，不补写全部历史任务交互。操作与验收见 [spec.md](spec.md)，范围与证据见 [STATUS.md](STATUS.md)。目标或边界经人确认变化时更新。

## 用户与问题

Builder 在 Workbench 的终端或智能体会话中阅读交付结果，遇到 Issue、PR／MR 链接时只能进入系统或内置浏览器，无法直接回到已有任务详情核对结果。用户在 [#698](https://github.com/forcegravity1989/builder-workbench/issues/698) 对应的需求会话中要求直接在应用内打开，沿 `gh` 和 `codehub-cli`。

## 价值与依据

减少终端、网页和任务屏之间的搬运，同时保持托管平台的真实任务与交付状态作为正本。链接只导航，不代替人判断完成、关闭或合入。收益依据是本次用户反馈，尚无量化使用效果。

## 目标体验

Builder 点击任务链接，在既有链接动作菜单中看到优先的「在任务中打开」；按 Ctrl／Cmd 点击可直接进入对应详情。普通网页仍按原有浏览器偏好打开，显式浏览器选项继续可用。详情关闭后返回原会话，继续阅读与执行。

## 范围与边界

- 本次覆盖 GitHub Issue／PR、CodeHub Issue／MR，复用已有原生详情和本机 CLI 账号。
- 完整平台、仓库、类型和编号决定打开对象，不按当前项目或同号猜测。
- 已登记项目可以来自本机或已知远端副本；本次不自动克隆、登记项目或切换账号。
- 未登记、无权限或返回身份不一致时明确提示；不自动改走网页。
- 不新增任务编辑器、管理动作或评论锚点精确定位。点击评论链接只打开其所属详情，浏览器选项保留完整原链接。
- CodeHub 特有行为继续由 [CodeHub 规格](../codehub/spec.md)定义；通用任务列表的历史定义和完整旅程不因本次补齐而视为已完成。

## 成功判据

从终端或会话打开链接，显示的对象与完整链接一致，返回后原会话仍在；数据来自正确平台的本机 CLI，导航不产生业务写操作。错误可理解且可继续用浏览器查看。不新增记账、审批或第二份任务状态。
