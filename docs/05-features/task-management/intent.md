# intent — 任务管理

> **维护约定**：给产品、设计、实现和验收者读取。本篇只维护任务管理的用户结果、价值、范围和排除。行为与验收见 [spec.md](spec.md)，当前证据边界见 [STATUS.md](STATUS.md)。认可的决定直接改写正文，不追加开发流水或历史方案。

## 用户结果

Builder 在 Workbench 的终端或智能体会话中看到 Issue、PR 或 MR 链接时，可以回到 Workbench 的既有任务详情核对结果，并在关闭详情后继续原来的会话和工作区。

## 价值与依据

任务链接在终端、会话和任务页之间保持连续，减少复制链接和切换窗口。托管平台的任务与交付状态仍是正本，链接导航不代替人判断完成、关闭或合入。需求依据为 [#698](https://github.com/forcegravity1989/builder-workbench/issues/698)，使用效果暂未量化。

## 范围

- GitHub Issue／PR 与 CodeHub Issue／MR 使用完整来源、仓库、类型和编号匹配，复用已有任务详情和本机 CLI。
- 终端 HTTP／OSC 8 链接与原生智能体会话链接共用链接动作菜单。主动作可以在任务中打开，显式浏览器动作继续可用。
- 未登记项目、来源身份不一致、缺少 CLI、未登录或无权限时给出原因和下一步，保留原链接和原会话。

## 排除

不新增任务编辑器、评论锚点定位、任务状态副本、项目登记、仓库克隆或账号切换。CodeHub 来源适配仍由 [CodeHub 规格](../codehub/spec.md)维护，任务列表和任务处理的其他行为沿现有页面。

## 成功判据

用户从终端或会话打开任务链接后看到与完整链接一致的真实对象，返回后原会话和工作区仍可继续。导航只读，不产生评论、关闭、重开、评审或合入等业务写操作。失败提示可理解，用户可以重新选择浏览器打开原链接。
