# 团队多人协作意图

> 给 Leader、共同开发的 Builder 和设计评审者读取。本文定义 G1 要解决的用户结果、边界和取舍；交互与验收见 [规格](spec.md)，当前证据边界见 [状态](STATUS.md)。原型与文档经人确认后，才生成仓外实现 plan。

## 为谁解决什么

同一团队的 Builder 各自在自己的主机上工作。同一个项目分散在两台主机时，成员需要反复登记主机、辨认重复项目，还要猜某个进展属于谁。Leader 需要看到团队项目并参加评审，但没有必要接管 Builder 的窗口或共享个人项目。

G1 让团队只配置一次 WeLink 群空间目录：成员、主机、项目身份和来源都沉淀在团队资产里。每个人打开 BW 后能看到同一个团队项目；项目卡保持现有 BW 的样式和状态，来源是否连接仍由现有状态表达。需要连接时，成员从左下角「管理远程主机」进入 Orca 原生入口，项目卡不承担连接动作。

## 核心用户结果

- 一台主机只绑定一个团队：成员用当前 WeLink 身份在团队设置中填写团队群号和群空间 ID 绑定一次，之后从本机记住的绑定和群空间中的 `BW/team.json` 读回，不再询问。群空间文件只承载群绑定、成员/主机和仓库身份；成员在本机项目墙登记项目时，登记动作同时把本机项目标为团队项目，其他主机的来源从各自项目墙核验，不维护一份人工来源名单。成员读取沿用已核对的 `welink-cli` 命令，群空间文件读写能力以预研和内网接口为准。
- 团队目录按项目身份聚合多台主机的来源。同一项目只出现一张现有样式的项目卡，每个主机来源仍保留；个人项目不会因为加入团队而自动公开。
- 团队项目对已连接成员默认全量只读：可以查看已有工作树、文件、会话和终端输出，不能新建工作树、创建会话、发送输入或执行命令。未连接只显示现有的离线状态。
- 所有 runtime 连接默认只读；完全访问只由主机持有人在共享访问设置中逐设备授予并写回设备登记。旧登记没有访问级别字段时也按只读处理。共享访问列表以 WeLink 成员姓名和头像作为主要识别，稳定的 runtime/device ID 只作辅助信息，不作为日常操作对象。
- 主机持有人在 Orca 原生共享访问列表中选择一个或多个已经建立只读连接的主机，一次授予整机完全访问；未选择的主机保持只读。授权不按项目或工作树拆分，仍沿用同一条 Orca 共享连接，并可逐个撤销连接。
- 被访问主机由持有人查看宿主侧访问日志，按动作、结果、时间和成员/设备搜索；默认保留 14 天并自动老化。常规成功只读请求（包括项目墙、侧栏和会话列表的后台读取）不逐条记录，避免把正常浏览刷成日志；连接建立/断开、授权变更、拒绝、错误和高价值写动作记录请求元数据与结果。日志不记录模型输入、命令正文、终端流或凭据，也不把这些内容复制进团队目录。
- Leader 可以在自己的 BW 中接收和处理成员评审请求。评审通知通过团队只读共享连接写入 Leader 主机的评审收件箱，但不授予整机完全访问；Leader 使用现有仓库账号完成评审，双方读回代码托管事实。

## 范围与不做

本轮交付 G1 的 intent、spec、可点击主旅程原型和落地前技术对齐。实现优先复用 BW 项目墙、项目卡、左下角远程主机管理、Orca 配对/共享访问、RPC 路由和宿主日志能力，只增加 WeLink 群空间目录、团队项目来源聚合、只读过滤、多选完全授权和日志展示所需的薄适配。

不在 G1 引入组内一级/二级代码仓库，不要求接管他人窗口，不把团队项目拆成树级权限，不把完全授权默认发给所有成员，也不改变项目卡既有布局和未连接状态。成员和项目目录的文件编辑权限由 WeLink 群空间管理；BW 不另造一套目录权限系统。

## 成功判断

评审者能从项目墙的团队设置绑定群号，看到成员和主机，登记一个已有项目并在两台主机来源间核对；随后能从左下角远程主机管理建立默认只读连接，在 Orca 共享访问列表多选目标并授予整机完全访问；未选目标仍只读，所有请求和拒绝可由主机持有人在 14 天日志中回溯。真实 WeLink、双机通信、宿主鉴权和重启读回属于实现验收，不由 HTML 原型冒充已完成。
