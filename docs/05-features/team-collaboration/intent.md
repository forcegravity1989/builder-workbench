# 团队多人协作意图

> 给负责多项目的 Leader、共同开发的 Builder 和设计评审者读取。本文定义协作对象、用户结果、范围与取舍。行为与验收见 [规格](spec.md)，认可及证据见 [状态](STATUS.md)。目标或边界变化时更新。

## 为谁解决什么

同一团队的 Builder 各自在自己的主机上工作。即使两人做同一个项目，其他成员也要反复导入主机、辨认哪个条目是同一个项目、猜进展在哪。Leader 只需看团队项目并参加评审，现有通知却要求发起者能连接到 Leader 的主机。

我们希望团队配置一次团队入口，组内成员便能从自己的 BW 找到团队项目、查看各 Builder 的真实进展、按人发起与处理 PR 评审。共同开发的两位 Builder 各自继续自己的工作，不依赖把对方窗口接过来。

## 目标体验

- 任一获准维护群空间的成员输入 WeLink 团队群号，在 BW 配置成员主机地址、项目群、主负责人和参与者。成员重新打开 BW 后能读回团队，匹配本机仓库显示为团队项目。
- 同一项目在项目墙和任务入口显示一次。项目内可以查看来自不同 Builder 主机的工作树、会话与进展，并保留来源。PR、Issue 和归档材料各沿权威来源读回。
- 团队成员通过已认证的 Orca 团队连接只读访问已登记的团队项目，包含已有会话和终端输出。个人项目只对本人及获得单独整机授权者开放。两位 Builder 有互操作机器的需要时，由主机持有人通过 Orca 独立授予或撤销完全访问。
- Leader 可以在 BW 收到团队成员的评审请求，使用自己的代码托管权限处理，发起人能读回实际结果。主机持有人能按动作、结果和时间查回远端访问和执行尝试。宿主日志按保留期自动清理。

## 本轮交付

v1.1 G1 准备可点原型、意图和规格。后续真壳对应三件事：团队群和项目群可绑定并读回，一项目两主机可按项目聚合和逐来源核对，Leader 未共享整机仍能在 BW 收到并完成 PR 评审。只读、完全访问、撤销和宿主日志一起设计与验收。

群空间承载团队目录。有文件编辑权限的成员都可维护，Leader 可在 WeLink 调整权限。继续沿用各项目现有仓库。工作树、文件和会话仍归拥有资源的主机。G2 的会议、实时原型批注沿会议协作交付。主机地址同步和连接稳定性沿已有事项处理。[特性主单 #342](https://github.com/forcegravity1989/builder-workbench/issues/342) · [v1.1 归档计划](https://github.com/forcegravity1989/builder-workbench/pull/675)
