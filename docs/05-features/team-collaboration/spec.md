## 完整用户旅程

1. **发现或建立团队。** 登录 WeLink 的成员打开 BW，由当前身份发现可读团队目录。首次登记人在项目墙点「团队设置」，填 WeLink 团队群数字 ID。BW 读回群名、群主、成员的工号、姓名及头像、关联群空间，预览后进入配置。群主在 BW 显示为 Leader，群空间文件权限决定谁能维护目录。群里已有团队目录时直接读回；首次登记才创建。
2. **在 BW 配置并保存。** 主机用默认监听端口时，成员行填稳定的局域网 IP 或主机名即可。使用自定义端口时填写 `IP:端口`。登记项目时先选已有仓库，带入仓库身份和已知项目群 ID，再选一位主负责人和参与者。登记人可预览文件，一次保存到群空间并独立读回。以后有文件编辑权限的人可以在 BW 维护，也可直接编辑群空间里的同一份目录。
3. **成员重新打开 BW。** 项目墙读回团队和目录项目。本机已纳入的仓库与目录仓库匹配时，项目类型直接显示「团队项目」。未纳入本机的团队项目也可呈现目录信息及来源状态。同一项目只一张卡，两位 Builder 的来源分别可点。目录有地址但尚无有效凭据时，墙卡显示「只读 · 待连接」。点击进入 Orca 团队连接，成功以后默认可只读查看对应工作树、会话、文件和终端。团队项目统一应用这条规则，项目设置只显示项目类型与说明。
4. **按人发起评审。** Builder 从开放的 PR/MR 发起评审，在项目或团队成员中选择 Leader。Leader 的 BW 评审通知可独立读回请求，使用本人代码托管权限处理，发起人能查到实际结果。项目群可作为同一请求的通知入口，收件能力需在内网验证。
5. **管理授权并查看日志。** 整机完全访问在 Orca 原生配对入口作单独授权和撤销。撤销后，有效的团队只读连接仍可用。宿主日志在「共享此主机」的原生授权列表下查看，可按动作、结果、时间筛选及搜索。

## 团队目录文件

群空间内建议使用固定位置 `BW/team.json`。文件中的群 ID、群空间 ID、项目群 ID 和工号均用字符串保留原值。群主、姓名、头像与成员资格每次从 WeLink 读回。目录只保存需要共同维护的项目、主机和人员关联。项目主负责人、参与者说明谁负责和参与项目，成员通过有效团队连接查看已匹配的团队项目。配对凭据和权限等级由宿主保存。

原型以项目主负责人和参与者登记的主机作为跨机来源候选，并以宿主上的仓库身份确认该来源。团队内其他成员也可以查看这些只读来源。未被列为负责人或参与者的成员若在本机打开同仓项目，是否也应自动贡献主机来源，留待本轮内部评审确认。

```json
{
  "schema_version": 1,
  "team_group_id": "100000000000000001",
  "team_space_id": "200000000000000001",
  "hosts": [
    {
      "id": "lin-desktop",
      "member_id": "A0010002",
      "name": "安泰工作站",
      "address": "192.0.2.10"
    },
    {
      "id": "chen-desktop",
      "member_id": "A0010003",
      "name": "远舟工作站",
      "address": "192.0.2.11:6768"
    }
  ],
  "projects": [
    {
      "name": "星图服务",
      "repository": "https://codehub.example.invalid/team/star",
      "project_group_id": "300000000000000001",
      "owner_id": "A0010002",
      "participant_ids": ["A0010003"]
    }
  ]
}
```

上例的 IP 和 ID 为演示数据。省略端口时尝试当前 Orca 默认 TCP 端口 `6768`。自定义端口按目录显式配置。地址用于定位端点。被访问主机须运行可从局域网访问的 Orca WebSocket RPC 监听，可用状态以实际可达、Orca 主机身份核验和设备认证为准。目录中的同仓项目归并，项目群 ID 可从项目名片建议；发现群号与项目名片冲突时提示差异，由人选择修订处。

BW 编辑和直接编辑共用同一个文件。保存前重新读取群空间版本；发现文件有变化时保留当前草稿，提示重新核对。保存后再次读回，验证群、主机和项目记录与提交一致。OneBox 稳定文件身份和并发更新行为要用内部 CLI 核对。

## 行为规则与异常

### 团队目录与项目身份

- 团队群决定成员资格及 Leader，群空间承载团队目录。已知数字群号可按负责人确认读回群主、成员与头像以及群空间。项目名片的 `[chat].group_id` 是群聊数字 ID，崩溃报告的 OneBox `spaceId` 是独立的群空间 ID。两种 ID 均单独保存。项目名片、版本材料和任务留在各自来源。目录是团队资产。任何享有 WeLink 群空间文件编辑权限的成员都可以维护目录；Leader 可直接在 WeLink 调整文件权限。宿主独立核对申请人当前的团队成员资格、本机仓库与团队目录中的匹配关系，以及当前设备授权。
- 先匹配现有仓库远端身份或明确的项目登记。无匹配或存在冲突时，显示待确认并保留来源；同名、同目录名或同一主机本身不代表同一项目。同一项目跨主机及工作树只显示一次，同一台主机上的不同项目各自独立。
- 工作树、会话以其拥有主机的身份区分。任务和 PR 按代码托管平台、仓库和编号去重。已归档的版本材料按其版本及承载依据去重，对端工作稿保留材料来源。沿用现有的版本目录与材料归属规则。一个来源离线时显示该来源暂不可用，其他来源仍可读；恢复后刷回旧项目。
- 无权读群空间、登录过期、群成员核对失败、绑定冲突分别给出具体原因。对无法核验的共享授权请求，宿主拒绝并给出核验失败提示。已读目录只用于显示最近已核对状态，授权以宿主当前判定为准。

### 两档权限

| 权限             | 授予与范围                                                               | 允许的结果                                                                 |
| ---------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 团队项目全部只读 | 默认适用于匹配团队目录的本机项目，团队成员通过已核验的 Orca 团队连接访问 | 读取该项目资料、工作树、文件、已有会话和终端输出。整个项目统一按只读处理。 |
| 主机完全访问     | 主机持有人明确完成独立 Orca 配对，可撤销。范围是该宿主账号下的 Orca 能力 | 运行终端、创建工作树、启动或接续会话、发送输入等原生操作。                 |

团队项目读请求由资源宿主按调用者、项目归属、动作鉴权。资源通过宿主使用真实归属核对，包括列表、详情、直接资源标识和持续订阅。只读工作区在会话栏标记「团队项目只读」。点击「新建会话」显示「当前来源为只读」。本机有该项目时提供「切回本机工作区」，否则提供「返回项目墙」以打开或克隆到本机。点击提示不发创建请求。只有目录地址的来源需先连接，未登记或已不可用的来源返回项目墙。宿主对直接发来的创建、修改、删除、发送输入与执行请求独立鉴权和拒绝。本人的代码托管账户仍决定 PR 评论和评审写入。

撤销完全访问时，宿主断开对应设备凭据与订阅。有独立有效的团队只读连接时，重新按只读载入，超出权限的操作由宿主拒绝。团队成员资格丧失或项目移出团队目录时，结束相应只读订阅，界面提示原因并回到项目墙或其他可用来源。

### Orca 复用与宿主访问日志

- **Orca 现有能力。** [配对与撤销入口](../../../src/renderer/src/components/settings/RuntimePairingUrlGenerator.tsx) 已管理主机访问，[已共享服务器访问列表](../../../src/renderer/src/components/settings/RuntimeAccessGrantList.tsx) 显示配对设备名称、创建时间和最近使用。撤销 [删除原生授权并断开该设备](../../../src/main/runtime/runtime-rpc/runtime-rpc-pairing.ts)。在现有配对表单中补主机完全访问的说明。通信复用 Orca WebSocket RPC、设备令牌和端到端加密。现行配对链接包含实际连接端点、设备令牌与宿主公钥，[由现有配对代码生成](../../../src/main/runtime/runtime-rpc/runtime-rpc-pairing.ts#L202)。
- **G1 授权落盘。** 复用宿主的 [`userData/orca-devices.json` 设备登记](../../../src/main/runtime/device-registry.ts#L72)。提议为 `scope: runtime` 的设备授权加 `accessMode`，值为 `team-read` 或 `full`。团队只读授权还绑定经过核验的 WeLink 团队群和成员身份。保留历史上已显式配对的 Orca `runtime` 授权语义，团队凭据独立发放并显式限定为 `team-read`。同一台客户端可分别持有两种凭据。群空间的 `team.json` 只提供地址和项目目录。
- **G1 权限判断。** 复用 [Orca WebSocket RPC 设备鉴权入口](../../../src/main/runtime/runtime-rpc/runtime-rpc-websocket-dispatch.ts)。被访问主机在凭据验证后，按成员、资源实际所属项目和请求动作核验团队只读请求。例如已有会话可读取，发送输入由宿主拒绝。原生完全访问走现有配对授权。
- **G1 日志。** 被访问主机记录远端请求的时间、已认证成员和设备、项目及资源、动作、放行或拒绝及原因，也记录配对、撤销和订阅起止。记录动作元数据，模型输入、命令正文、终端流及凭据保留在原内容源。主机持有人在「设置 → 远程 Orca 服务器 → 共享此主机」的原生共享访问列表下方查看。日志可组合筛选动作、结果、时间，按人、设备、项目和资源搜索，并显示条数。拟复用 [Orca 本机日志目录](../../../src/main/observability/logs-directory.ts)，按日写入 `userData/logs/team-access-YYYY-MM-DD.ndjson`，暂按 30 天保留，在启动和运行期间定期清理到期文件。

### 送达与恢复

成员可选择有权阅览该项目的评审人；收件后保留请求、PR 身份和结果。没有仓库权限时保留通知并说明如何继续。送达依据接收端可读回，失败时显示失败对象和重试入口。重启后以通知与代码托管事实读回，团队目录的群绑定及成员以 WeLink 读回。

## 验收

| ID   | 场景                                                                          | 证据                                                                                                                                           |
| ---- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| TC01 | 登记人输数字群号、登记主机和项目；两位 Builder 首次打开再重启                 | 读回同一群、群空间、成员、主机和项目分工；两名有文件编辑权限的人可修改同一目录；匹配的本机仓库自动归为团队项目，权限收回后仍可在有权读取时查阅 |
| TC02 | 两台主机上的仓库匹配同一团队项目，另含一个同名异仓项目及一个个人项目          | 同一项目仅一项，两个来源及各自工作树可核对；同名异仓独立；其他 Builder 看不到个人项目                                                          |
| TC03 | Viewer 打开远端现有工作树、会话和终端，再直接请求创建、发送输入和打开个人资源 | 地址可定位但连接成功后才能读内容。新建会话入口显示只读提示并导回本机。宿主拒绝直接发来的越权读取、写入和执行，可在日志查到真实请求和拒绝原因   |
| TC04 | Leader 不共享自己的机器，仍从 BW 通知进入并提交 PR 评审                       | 发起人看到送达与真实结果；重启后 Leader 和发起人状态一致；仓库无权场景给出继续路径                                                             |
| TC05 | 持有人单独配对再撤销，另测成员退出 WeLink 群或项目移出团队目录                | 完全访问只在单独授权后生效。撤销后相关连接结束，已有的团队只读权限继续有效。被移除的项目或已离群的成员失去对应的团队访问能力                   |
| TC06 | 断线或 WeLink 无权，随后恢复                                                  | 对应来源清楚标为不可用，独立的可用信息保留，恢复后按同一项目身份读回                                                                           |
| TC07 | 按动作、结果、时间及搜索词查宿主日志，放入一批到期样例后重启                  | 查到放行、拒绝和配对撤销，多个条件叠加有效。只读提示本身无伪造宿主事件，超过保留期的日志文件被清理。                                           |

TC01 与 TC04 对应 [#552](https://github.com/forcegravity1989/builder-workbench/issues/552) 和 [#480](https://github.com/forcegravity1989/builder-workbench/issues/480)。原型用于评审操作和结果。验收需要真实 WeLink、独立账号、至少两台 Builder 主机及宿主侧独立读回。

## 取舍与待决问题

- 复用 Orca 已认证设备、原生配对/撤销、远端资源路由与宿主 RPC 分发。需在内网确定可由宿主独立核验的 WeLink 身份及团队成员凭证，再据此签发团队只读的 Orca 设备凭据。现有 `scope` 继续区分 `mobile` 和 `runtime`。项目只读由新增的授权等级、RPC 动作和资源归属共同约束。核心协议、宿主鉴权的改动边界在原型后确认。
- GitHub/CodeHub 任务继续沿当前主干的本机账号策略；任务项目选择器沿主干的项目身份归并。PR [#504](https://github.com/forcegravity1989/builder-workbench/pull/504) 可参考远端身份未读到时的来源识别与任务选择器。它的远端 CodeHub 路由要重新与 [#642](https://github.com/forcegravity1989/builder-workbench/pull/642) 和同仓目录归并 [#685](https://github.com/forcegravity1989/builder-workbench/pull/685) 校对。
- 首次只凭成员身份自动发现团队，需要从已登录用户出发枚举团队群或读取等价的团队入口，按可读群空间中的 BW 目录识别。原型展示自动发现的目标体验。录入人按群号查询已确认；首次发现所需的入口、同一目录文件更新和评审收件方式待内网实测。若内网接口只支持已知群号，候选方案是成员首次从群内打开一次团队入口，之后重开 BW 自动读回。
