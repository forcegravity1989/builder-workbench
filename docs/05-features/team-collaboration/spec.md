# 团队多人协作规格

> 给交互设计、实现与验收者读取。本文是 G1 的当前设计基线，和 [意图](intent.md) 一起在人确认后进入实现。打开 [旅程变更原型](prototype.html) 可从项目墙、团队设置、左下角远程主机管理和 Orca 共享访问页走完整主旅程；原型不代表真实 WeLink、双机通信或宿主鉴权已经交付。

## 完整用户旅程

1. **绑定团队。** 一台主机只绑定一个团队。本机还没有绑定时，成员在项目墙打开团队设置，看到「连接团队」弹窗，同时填写 WeLink 群 ID 和群空间 ID 后点「绑定团队」；CLI 不能由群号反查空间 ID，所以两者都由人提供一次。本机已有绑定时，打开团队设置直接进入团队目录，不再询问；绑定的目录读取失败时回到该弹窗并保留已填的两个 ID。BW 通过已核对的 `welink-cli im query-group-member --group-id "<群号>"` 读取成员和群主，并在本机记住这组绑定。群名、头像和编辑权限只有在内网接口实际提供后才写入或展示。当前登录 WeLink 身份与本机身份的匹配以 `auth status` 实际输出为准，群主在界面上标为 Leader。群空间文件编辑权限由 WeLink 控制，BW 不复制一套权限。
2. **登记主机和项目。** 每位成员在自己的成员行看到 WeLink 姓名、头像和主机地址；主机名就是成员姓名，稳定的 runtime/device ID 不作为主操作文本。地址栏是普通文本输入；本机可点击图标按钮「一键生成并填入」，已有 Orca 配置时直接复用并填入，不要求先离开 BW 去复制链接。项目登记只能从本机项目墙选择已有项目；写入群空间的仓库身份同时把这个本机项目标为团队项目。其他成员把自己的同一 `repoId` 项目切为团队项目后，项目墙读回时自动成为同一张卡的来源，不再维护来源人名单。
3. **读回项目。** 成员重开 BW 后读回群空间目录。项目墙按现有 BW 规则显示团队项目和个人项目；同一个项目只出现一张卡，卡片显示现有的负责人和主机来源标签。来源未连接时只显示原生离线状态，不弹出连接动作。团队目录里其他成员公布的链接会自动加入本机「管理远程主机」列表，默认保持未连接；成员需要时在该列表里自己点连接。同步只新增和刷新（成员换了链接时更新由团队同步加入的那几台），不自动删除，也不改动成员手动添加的主机。同步发生在：BW 启动后台一次、打开团队设置时、左下角「管理远程主机」菜单的「刷新团队主机」；不轮询。
4. **默认只读。** 连接建立后，团队项目来源默认只读。已有工作树、项目文件、已有会话和终端输出可查看；向终端或 Agent 发送输入、新建工作树、写项目文件或 Git、以主机持有人的账号写回外部系统，都由宿主 RPC 拒绝并提示只读；启动或续接会话（不带提示词）、新建终端和页签不拦；启动时带提示词等同于向 Agent 发消息，会被拒绝。个人项目不会因团队目录存在而自动可读。成员连接时在加密握手里带上自己的 WeLink 成员身份（成员 ID、姓名、头像，团队内自报、不防冒充：持链接的人冒用已获完全访问成员的 ID 会得到同样的访问级别，这是团队内信任下已接受的取舍）；同一条团队共享链接上，宿主为每位成员各建一条设备记录，日志、批注作者和评审发送人都显示该成员姓名，完全访问也按成员单独授予和撤销。成员 A 连接成员 B 与 B 连接 A 对称，权限规则相同。
5. **切换成员访问级别。** 主机持有人进入 Orca「共享此主机」的「共享服务器访问」列表。每位成员一行，行内有「只读 | 完全访问」切换，点击即生效，不再勾选或二次确认；成员姓名和头像是识别主线，device ID 仅保留在辅助信息或诊断中。切到「完全访问」要求该成员已连接，未连接时该项不可点并说明原因；切回「只读」随时可用。已打开的终端也立即按新级别放行或丢弃输入，不需要成员重连。两个方向都记日志（授予完全访问、恢复只读）。授权范围是整台主机的 Orca 能力，不按项目或工作树拆分。设备仍可单独撤销连接。
6. **回溯和评审。** 被访问主机持有人在同一设置页查看日志，按动作、结果、时间和搜索词筛选，默认查看最近 14 天。Builder 继续使用个人工作区和仓库账号发起评审：PR 评审和原型评审通知都通过已建立的团队只读共享连接，送到所选主机的评审收件箱，接收方在自己的 BW 收到并处理。通知不需要整机完全授权，也不另设权限管控；PR 评审双方读回真实 PR 结果。原型评审的路径是：主机持有人在自己的 HTML 预览工具栏点「邀请评审」选择成员；成员点通知，直接在自己的预览里打开这份 HTML 文档（成员对该工作树的只读副本），用原生元素批注，点「提交给 {主机名}」，批注（文字与元素定位，不含截图）写入主机并自动通知持有人；持有人点通知打开自己的预览，批注托盘显示各成员的批注，由持有人用原生「发送给模型」决定是否交给工作模型。成员不能把批注发给模型。

## 群空间目录

群空间只保存团队协作目录，不保存模型输入、命令正文或宿主授权状态；成员主机地址保存为完整的 Orca 只读配对链接（含只读设备令牌）。推荐文件路径为 `BW/team.json`，字段保持字符串身份：

```json
{
  "schema_version": 1,
  "team_group_id": "938583054774198541",
  "team_space_id": "20065474",
  "identity_source": "welink-cli",
  "hosts": [
    {
      "member_id": "A0010002",
      "name": "林安",
      "avatar": "林",
      "host_id": "host-linan",
      "orca_endpoint": "orca://pair?code=<只读配对码>"
    }
  ],
  "projects": [
    {
      "repo_id": "star",
      "name": "星图服务",
      "repository": "https://codehub.example.invalid/team/star"
    }
  ]
}
```

`team_group_id` 是 WeLink 群数字 ID，`team_space_id` 是人提供或从已有 `team.json` 读回的 OneBox 空间 ID。它不是群号换算出来的值，也不生成虚构的 `welink://` 地址。成员姓名、头像和成员资格每次以 WeLink 读回为准；主机身份由各桌面的 `welink-cli` 登录用户与成员工号匹配。`orca_endpoint` 是该主机的 Orca 只读配对链接（`orca://pair?code=...`，含只读设备令牌）。已确认的取舍：能读取群空间目录的成员即可凭它以只读身份连接该主机，不需要主机持有人再发配对码或二次授权；持有人随时可在 Orca 共享访问里撤销该设备。该令牌只有只读权限，整机完全访问仍须持有人逐设备授予。

团队目录文件实际上传到群空间的 `BW/team.json`。BW 在当前用户的本地界面存一份群号到群空间 ID 的最近绑定，用于重开团队设置时直接读回已有目录；这份本地提示不是团队事实，群空间文件仍是目录正本。

项目来源不因同名自动归并，必须先有 `repoId` 或明确仓库远端身份。登记项目就是把本机项目切换为团队项目的唯一入口；其余成员在自己的项目墙重复这一动作，来源由项目墙读回并按 `repoId` 聚合。项目群、负责人和参与者留在项目约定中，不写入团队目录，也不等价于主机完全授权。保存前重新读群空间版本，发现并发变化时保留草稿并要求核对，保存后再读回确认。

## 权限与宿主边界

| 权限 | 默认与授予 | 用户可见结果 |
| --- | --- | --- |
| 团队项目只读 | 已连接到团队主机后默认获得；整个团队项目统一只读 | 查看和切换已有工作树、文件、会话、终端输出，以及打开对方工作树里的 HTML 文档并在自己的预览里批注、提交给持有人；可启动或续接会话（不带提示词）、新建终端。不能给会话、终端或模型发送输入，不能新建或删除工作树，不能写项目文件或 Git，不能读项目之外的本地文件，不能以主机持有人的账号写回 GitHub、GitLab、Jira、Linear、CodeHub。宿主按「默认放行、只拒绝这几类动作的核心入口」判断，新增能力无需逐个登记 |
| 主机完全访问 | 仅主机持有人在 Orca 共享访问列表的成员行切换后授予，随时可切回只读，也可逐个撤销 | 沿用 Orca 原生整机能力；可在该主机创建工作树、启动/接续会话和发送输入 |

一次切换只影响该成员的设备，其他成员和未建立连接的设备不变。完全授权的判断在宿主侧完成，项目墙上的状态只用于展示。成员退出 WeLink 群、项目被移出目录或设备凭据撤销后，宿主结束相应订阅；仍有独立有效的只读连接时，按只读重新载入。

## Orca 复用与日志

- 连接沿用 Orca WebSocket RPC、配对 URL、设备登记、端到端加密和远程资源路由。G1 不另造 HTTP 通道或共同代码仓库。
- 团队目录公布只读配对链接，成员读回后沿 Orca 原生连接建立只读连接；完全授权是宿主持有人对指定设备的显式动作，不由群目录或项目负责人自动推导。
- 宿主在完成设备认证和团队成员核验后，对每个请求按调用者、设备和动作鉴权。宿主默认放行，只拒绝发送输入、读项目之外的文件、写回外部系统、改项目文件、Git 和工作树这几类动作。
- 日志记录连接建立/断开、授权变更、拒绝、错误和高价值写动作的时间、成员/设备、动作、放行或拒绝及原因；常规成功读取不记录，因此项目墙和侧栏后台加载不会刷屏。不记录模型输入、命令正文、终端流或凭据。日志只在被访问主机的 Orca 共享访问设置中由主机持有人查看，支持动作、结果、时间和成员/设备搜索。
- 设计默认保留 14 天并自动清理。建议按天写入 `userData/logs/orca-shared-host/YYYY-MM-DD.ndjson`；实际文件命名和轮转复用 Orca 当前日志目录实现，落地前以代码调用链为准。

## 验收

| ID | 场景 | 证据 |
| --- | --- | --- |
| TC01 | 输入群号，读回成员、主机和群空间；登记一个已有项目 | 群空间目录可读回，项目身份只登记一次，负责人/参与者和来源可核对 |
| TC02 | 两台主机发布同一项目，另有个人项目和同名异仓项目 | 同一项目一张现有样式卡；个人项目不被公开；同名异仓不归并 |
| TC03 | 远程来源未连接、从左下角管理远程主机建立连接、查看团队项目 | 卡片只显示现有离线状态；连接从原生远程主机入口建立；连接成功后整个团队项目只读 |
| TC04 | 主机持有人在共享访问列表把成员 A 切到「完全访问」，再切回「只读」 | 只有 A 变化，其他成员仍只读；A 已打开的终端立即按新级别放行或丢弃输入；授予和恢复只读各有一条日志 |
| TC05 | 撤销连接、成员退出群或项目移出目录 | 完全访问按设备撤销；撤销后断开；成员和项目资格变化不再可读 |
| TC06 | 读取、创建、发送和执行请求 | 只读请求可查阅，越权请求在 UI 和宿主 RPC 双重拒绝，并记录原因 |
| TC07 | 按动作、结果、时间和搜索词查看日志，加入到期样例后重启 | 多条件筛选有效；超过 14 天的日志按日清理；重启后仍能读回未过期记录 |
| TC08 | 主机持有人在 HTML 预览点「邀请评审」；只读成员点通知打开该文档、批注并「提交给主机」 | 通知写入对方评审收件箱；成员在自己的预览批注并提交，持有人收到「提交了 N 条批注」通知，打开自己的预览看到带成员名的批注；成员没有发给模型的入口；日志有「提交原型批注」 |

真实 WeLink、双机通信、宿主鉴权、日志落盘和重启读回需要实现后在内网验收；HTML 原型只用于确认入口、状态和完整旅程。

## 技术边界与待确认

- **已确认决策。** 所有 runtime 连接默认只读；旧登记缺少访问级别时按只读处理，完全访问只由主机持有人在界面中逐成员切换并写回设备登记，切回只读随时可用；日志第一版只记录请求元数据并按 14 天轮转，不记录模型输入、shell 命令正文或终端流。14 天在可回溯和宿主本地存储成本之间取平衡，后续可做成宿主配置项。
- 复用当前 BW/Orca 的项目墙、远程主机管理、设备配对、访问列表、RPC 分发和日志目录。只有在现有宿主鉴权无法表达「团队项目只读」时，才新增最小的团队凭据/动作过滤适配；不把尚未核对的字段当成现行 Orca 能力。
- 团队目录文件是团队资产；目录编辑权限由 WeLink 群空间控制。完全访问的授权状态和日志由宿主保存；目录里的只读配对链接不能授予整机访问。
- PR #504 仅作为远端来源识别和任务选择器的参考，需与当前 CodeHub/主机路由实现重新校对，不复刻其入口。
