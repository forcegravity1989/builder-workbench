## 入口与演示

首次使用三个同级入口：加入团队、创建团队、先做自己的项目。有邀请时优先展示邀请上下文，但可暂存或取消。已有用户进入上次工作区，团队入口常驻侧栏；不重复首次问卷。现有 OnboardingFlow 的终端／智能体／集成准备按需复用，邀请接受和目录浏览不依赖模型配置。

HTML 是离线可运行的设计演示：12 条旅程、逐步播放／暂停、前后跳转、步骤定位、倍速、关系图、实现与权限说明。所有人名、项目与结果均为模拟。原生仓库创建器、工作区、会话、代码评审用标明复用的示意，不声称复刻完整生产 UI。对应引导 G01/G02/G05/G07、F19/F20/F24，补充团队邀请、共享范围、刷新结果和撤销后的继续路径；现行引导矩阵在设计认可前不标为已交付。

## 关系模型（推荐）

| 关系 | 基数 | 约束与意义 |
| --- | --- | --- |
| 人 ↔ 团队 | M:N，经 Membership | 人可参加多团队；团队至少一位管理员；创建者为首位管理员，最后一位退出前必须转交或解散 |
| 团队 → 协作项目 | 1:N | 一个项目只有一个归属团队；跨团队共享暂不隐式联通，可邀请参与者加入目标团队 |
| 人 ↔ 协作项目 | M:N，经有效团队成员资格派生 | 首版团队内项目默认全员可发现；不额外维护同一份项目成员名单。团队管理员只能发布自己有权分享的内容，宿主资源仍由宿主所有者授权 |
| 协作项目 ↔ 代码仓 | M:N，经 ProjectRepository | 一个项目可多仓；相同仓可用于多个协作项目。原生 Project 仍是代码仓身份，新增 CollaborationProject 是聚合层；原生 project group 仍是本机展示分组 |
| 代码仓 ↔ 执行主机 | M:N，经 ProjectHostSetup | 一个仓在多机有检出；一机可承载多仓；每个 setup 只有一个仓、一个主机、一个路径 |
| setup → 工作树 → 会话 | 1:N → 1:N | 原生 host-qualified 身份不变；合并项目标题不能合并或搬迁目录、工作树和会话 |
| 人 → 登录设备 | 1:N | 一人多设备独立登录；共享机器可有不同用户的隔离 profile，不能按机器名称推断人 |
| 成员 ↔ 可共享资源 | M:N，经 ResourceGrant | 授权对象为项目 setup／工作树，权限为只读或执行；授予人须有宿主管理权，团队管理员不自动拥有此权 |
| 团队 → 邀请 | 1:N | 邀请绑定团队、可选项目及接收身份；单次接受、可过期／撤销；不包含宿主 token |

同仓识别使用 provider 实例＋仓库稳定身份，保留端口、fork 和 origin/upstream 差异；名称只是显示。无法确证身份时让用户明确关联，不按目录名合并。协作项目 UUID 不由 repoId/envId 派生；同一远端在两个团队中对应的协作卡片仍分开。一个项目内同仓副本只计一次，原生执行行保留全部来源。

## 完整用户旅程

| 编号 | 用户动作与系统响应 | 结果与异常继续路径 |
| --- | --- | --- |
| J01 首次受邀 | 打开邀请→核对团队／邀请人→登录确认本人→接受→进入团队项目→本人 Git 权限检测→已有本机副本直接打开，否则原生克隆→开始工作 | 接受超时先查成员资格，幂等重试；未安装时安装后恢复邀请；错误账号可切换；Git 无权请求代码权限，不借用邀请人的凭据 |
| J02 创建团队 | 选择创建→登录→填写团队名称→创建→选择已有项目／打开或克隆→预览发布字段→发布→生成邀请 | 团队创建失败保留输入；创建与重试共用幂等键；邀请由人自行分享。没有项目也可先邀请，展示明确空态 |
| J03 个人开工 | 先做自己的项目→原生打开／新建→必要智能体准备→工作 | 不要求 BW 团队登录；之后在项目菜单“共享到团队”补协作关系，保留已有工作树与会话 |
| J04 共享已有项目 | 选择团队→选仓库／明确主要材料仓→预览名称、负责人、仓库地址→发布 | 发布目录引用，不上传本机源码、个人路径、会话或密钥；负责人为描述字段，不赋权；共享信息仍从 Git 名片读，团队目录只保存引用及带版本的展示缓存 |
| J05 老用户刷新 | 恢复工作→展示可读缓存及来源时间→同步成员资格与团队目录→按本次版本提交目录变化→分别刷新任务和执行位置 | 事件触发增量更新；手动刷新强制重新验证。新增项目出现、不重复克隆；当前工作不被切换。空目录、未授权、网络失败分别处理 |
| J06 离线与恢复 | 对方主机离线→团队项目仍可见→本机副本继续工作→主机回来后恢复对应来源 | 目录服务离线时展示已知目录为过期只读；无缓存显示暂不可获取；远端写入拒绝；不把无读数显示为零 |
| J07 同伴只读协作 | 项目内打开“同伴工作区”→明确选择人／主机／工作树→宿主检查授权→只读查看→给出评审反馈 | 只读接口只输出脱敏快照／受控文件内容，禁止 shell、PTY 输入、写文件、自动化、任意浏览器操作、可写附件和模型代执行；同伴未共享时可申请，不假设团队成员全可访问 |
| J08 远端执行 | 默认本机开工；用户选择“在远端运行”→指定主机／范围→宿主批准与隔离环境检查→进入有来源标识的工作区 | 宿主不支持项目授权／隔离时停在不可用状态；不能把旧整机配对包装为项目权限。可返回本机工作，不自动降级到别的主机 |
| J09 撤回与退出 | 管理员移除成员或撤回项目共享→权威目录写撤销版本→通知在线客户端和宿主→失效授权与订阅→显示已失去访问 | 本机代码不删除；Git 权限由 provider 单独撤销。团队授权会话的后续输入和待执行任务被拒，专属执行任务终止；成员自己在本机启动的工作保留。退出不删除团队项目 |
| J10 地址变更 | 主机登记新地址→客户端验证同一持久公钥身份→更新端点→原生重连→恢复同一资源 | 地址不是身份；公钥变化暂停并需重新确认。仅加入团队不自动配对。服务只发布公开端点，设备 token 沿原生安全存储，不进入团队目录 |
| J11 邀请／代码权限异常 | 过期邀请拒绝接受并提供重发方向；账号不匹配可切换；有效邀请接受后发现 Git 无权 | 加入团队与取得代码权限分开显示；修复 Git 权限后从同一项目重试，不重复入组、不创建假工作区 |
| J12 既有用户迁入 | 保留既有本机与配对目录→选择加入／创建团队→逐项目确认关联或发布→恢复原工作区 | 原 team 标记不自动生成成员或权限；旧主机连接放在高级连接中，不能混成新项目授权。迁移前预览、逐项幂等，失败保留原工作可继续 |

## 共享的含义与权限矩阵

“共享项目”默认共享项目目录与仓库引用；代码仍从 Git 平台读取。它不隐式共享主机、全部会话或本机文件。普通文件夹没有可供他人克隆的代码源，必须先接 Git 或明确授权远端受控查看；不能承诺点击发布后别人自动拿到文件。

| 动作 | 团队成员 | 团队管理员 | 执行宿主所有者 |
| --- | --- | --- | --- |
| 发现团队项目、查看公开目录字段 | 允许 | 允许 | 需具备团队资格 |
| 邀请／移除成员、发布／撤回目录项目 | 不允许，向管理员申请 | 允许 | 不因拥有机器获得团队管理权 |
| Git 读取、提交、PR/MR | 本人 provider 权限 | 同左 | 同左 |
| 查看其他人的工作树／会话 | 需有效只读资源授权 | 同左 | 可管理本机资源授权 |
| 远端执行／自动化 | 需执行授权＋受控执行环境 | 同左 | 审核并提供执行资源 |
| 修改机器设置、凭据、授权其他项目 | 项目授权不允许 | 同左 | 通过独立宿主管理入口 |

执行权包含明确的读权限。成员权限取团队资格、资源 grant、provider 及宿主能力的交集；任一拒绝即拒绝。团队删除需管理员显式确认，先撤销目录和相关 grant，再保留各人的本机文件；最后管理员不能直接退出。团队转移所有权及跨团队项目迁移在首版不提供隐式操作。

ResourceGrant 必须绑定 `teamId + collaborationProjectId + membershipId + resourceScope + capability`，不能只有“人＋主机”。同一个仓或 setup 出现在不同协作项目时，每条 grant 仍有明确授权来源；撤回一个项目只撤该项目上下文的授权，不误撤其他团队或项目的授权。每次访问携带并验证所选项目上下文，不能借其他项目的有效 grant 重新读取已撤回目录。任务和订阅也绑定该上下文，撤销只影响相应授权启动的任务。

### 权限必须在宿主执行

现有 DeviceRegistry 的设备 token 和 mobile 方法白名单不提供项目隔离。新增的授权上下文必须贯穿 RPC、事件订阅、文件、PTY、自动化、浏览器、agent 工具及缓存读回；只过滤前端按钮不成立。路径解析规范化并拒绝越界、符号链接逃逸和跨项目对象 ID。只读会话快照不包含可复用 token、敏感环境和私有提示。

任意终端命令能越出目录，因此“可执行但仅限项目”需要独立 OS 身份或容器／受控工作区、限定挂载、网络与最小凭据；仅 cwd 限制不成立。宿主缺这类能力时只开放受控只读或本人本机执行，J08 明确展示不可用。此项需改变原生授权／执行边界，按仓规停在设计评审，不能当薄 UI 接线承诺。

推荐所有新的远端敏感操作在线验证有效 membership 与 grant revision；撤销事件立即关闭订阅、拒绝后续写入。活动流以最长 30 秒授权续租为提议上界，失联到期停止输出；已启动的团队授权专属任务到期终止，返回终止回执。30 秒是待实现的目标，需真实双机断网验收；不承诺断网撤销瞬时生效。离线期间不新增远端权限。已经读取或克隆的数据无法收回。

## 实现建议与事实归属

推荐新增轻量团队目录服务作为成员、邀请、项目引用、授权修订和公开端点的权威来源；部署在组织可达的服务，不依赖某位成员笔记本常在线。身份复用组织现有身份提供者，BW 只保存稳定 subject 映射；不假设现有 GitHub／CodeHub CLI 登录可直接证明同一个 BW 人员。具体身份接口和部署地址尚未验证。

| 数据／能力 | 归属及落点建议 | 现有基础与增量 |
| --- | --- | --- |
| 团队、成员、邀请、目录 | 新增团队服务；带 revision 的变更与幂等操作 | 当前无此业务服务；需运营、备份和身份接入决定。客户端只有可丢弃 JSON 缓存，不新增本地业务数据库 |
| 代码仓、Issue、PR、名片与版本材料 | Git/代码平台及仓文件 | 复用现有 provider、charter、materials；不搬进团队服务做第二正本；多仓项目显式选材料主仓 |
| 仓库／检出／工作树／会话 | Orca 原生目录与执行核 | 复用 Project、ProjectHostSetup、AddRepoDialog 和工作区激活；新增协作项目到原生 repo identity 的映射 |
| 连接／密钥／重配 | Orca 配对与 DeviceRegistry | 复用原生传输；公开端点发现新增，身份和连接持久化沿原生；不把团队邀请直接当设备授权 |
| 资源权限与隔离 | 宿主授权入口＋受控执行环境 | 新增 ResourceGrant、授权版本、范围校验、订阅撤销与任务归属；涉及原生核心改造，需专门评审 |
| 项目墙与刷新 | BW 目录投影，按团队 UUID＋项目 UUID 建卡 | 当前墙基于主机仓库行，新增团队目录层使主机离线仍可发现项目；原有来源合并、快照与失败提示复用 |

刷新顺序：身份验证→成员资格与授权修订→目录版本→可访问来源→卡片事实。团队切换／退出时递增请求 generation，旧响应不得写回新团队。完整成功快照中缺失才视为删除；增量删除必须有明确 tombstone。部分失败保留对应来源快照并标时间，权限撤销则立即清理可见缓存，不能因“保留旧数据”泄露。先收到 revocation 后到达的旧内容按 revision 拒绝。持久缓存分账号、团队、项目、来源；重启不恢复过期授权。

项目目录刷新不执行 git pull，不打断会话，也不切换执行宿主。“更新代码”仍是独立的用户动作。任务按 provider 实例＋仓库身份＋类型＋编号去重，以本人本机 CLI 读取；多台机器不生成多份任务。远端材料与本机任务可独立读取，依据 #641，实际接入状态须实施时核查。任务计数保持真实来源规则，未知不能补零。

## 分段落地与验收

1. 确认原则边界、团队身份和服务方案；服务与客户端首先交付创建／邀请／项目目录＋本机开工，覆盖 J01–J06/J11/J12。该阶段明确不宣称已满足 #552。
2. 宿主受控只读、项目／工作树授权、撤销与订阅，完成 J07/J09/J10。老整机配对继续作为独立高级能力，不能自动迁成项目授权。
3. 受控远端执行、任务身份与隔离验证，完成 J08。三个阶段属于完整设计的实施次序，不将后两段从最终目标删去。

每条 Jxx 对应动画和验收路径。真实实施应覆盖两个独立用户、两台主机、不同 Git 权限、同仓多检出与 fork、服务断网与进程重启。核心判据：邀请仅接受一次；无配对可在本机开工；新增项目一次显示；部分刷新不删项目；旧响应不恢复被撤权限；只读直接 RPC／模型工具攻击仍被拒；远端执行无法读取范围外文件／凭据；撤销后新请求拒绝、授权任务按界限终止并读回；重配不重复建卡。动画验收只证明这些故事可看、交互可用，不能替代上述产品验证。

## 待评审取舍

推荐最小真实团队＋独立目录服务，团队管理员／成员两种协作职责，项目默认对团队可发现，代码权限仍归 provider。与现行原则 03 冲突的变更应在认可后同步，不在本次偷改。组织身份提供者、服务部署与运维负责人需确定；没有适用身份服务时不能用显示名充当身份。

备选“hosts.json＋主机共享”成本低但无法在主机离线时保持目录，也无法表达稳定成员和撤销；备选“Git 仓保存团队成员清单”便于审计但授权撤销和实时目录依赖 Git 传播，不能作为强制权限源。推荐服务不是已选定技术栈，也不需要把代码、任务、聊天或模型运行搬到云上。
