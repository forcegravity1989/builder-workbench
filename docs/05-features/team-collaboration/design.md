# 团队多人协作实现设计

> 给实现与技术评审者读取。本文记录 G1 的实现落点、复用边界和持久化契约；用户结果见 [intent](intent.md)，交互与验收见 [spec](spec.md)，当前证据边界见 [STATUS](STATUS.md)。不记录施工流水；实现边界变化时更新。

## 入口与数据流

项目墙页头的团队设置图标复用现有项目墙工具栏。一台主机只绑定一个团队：本机没有绑定时，团队设置弹窗同时要求 WeLink 群 ID 和群空间 ID，绑定后每次直接打开团队目录。读取时 `welink-cli im query-group-member --group-id` 返回成员账号、群主和当前身份，再用 `welink-cli contact detail` 批量补成员中文名和头像（读不到时界面退回账号与首字母占位）。群号不能反查群空间 ID，所以空间 ID 由人在首次绑定时提供；本机保存这一组绑定（`bw:team-group-id`、`bw:team-space-id`），之后从绑定和群空间文件读回。OneBox 读写在群空间的 `BW/team.json` 中完成。

团队目录是薄目录。它保存群绑定、成员/主机身份和仓库身份；不保存完全访问授权状态、日志、项目负责人或人工维护的来源名单；主机地址保存为 Orca 只读配对链接（含只读设备令牌，已确认的取舍，成员无需二次输入授权码）。登记项目时，`TeamSettingsDialog` 通过现有项目墙仓库身份写入团队项目，并把本机项目的 `projectVisibility` 设为 `team`。其他成员在自己的项目墙执行同一动作；项目墙按 `repoId` 读回各主机来源并聚合成一张现有项目卡。个人项目没有登记就继续留在个人范围。

```text
项目墙团队设置
  ├─ welink-cli 群成员/群主 ──┐
  ├─ OneBox BW/team.json       ├─ 团队目录读取/保存
  └─ 本机项目墙 repo identity ─┘

项目墙项目卡 ← 各主机项目墙来源按 repoId 聚合
左下角管理远程主机 → Orca 原生连接状态 → 团队项目来源
```

## Orca 复用与身份显示

- 远程主机入口复用 `SshStatusSegment` 的 `MonitorSmartphone` 图标、popover、连接/断开动作和「管理远程主机」设置入口。团队目录只提供地址和人类可读的成员信息，不另造连接协议。
- 连接和配对复用 `RuntimePairingUrlGenerator`、`RuntimeAccessGrantList`、`DeviceRegistry`、WebSocket RPC 和原生设备凭据。团队地址生成使用 `scope: runtime`、`accessMode: team-read` 和 `teamBinding`；已有 Orca 地址直接填入目录，缺少地址时从同一入口生成并填入。
- 共享访问列表的授权操作区只展示已建立连接的 `team-read` 设备。行首使用无文字 Checkbox，Tooltip/aria-label 说明“选择该设备授予完全访问”；成员姓名和头像来自 WeLink 目录，是主要识别。稳定 `deviceId` 仍作为权限和撤销键，放在辅助信息或诊断字段，不以姓名做权限键。
- 设备登记必须保留原始 `teamBinding`（或不可变的同等来源字段）。升级为 `full` 只改变有效访问级别，不能丢掉成员身份，否则重启后无法显示“哪位成员连接了本机”或审计授权对象。非团队 Orca 设备继续使用原生设备名。

## 权限边界

`team-read` 使用「默认放行 + 明确拒绝清单」。原先的纯读 allowlist 漏登了数百个读取方法（项目墙、侧栏、评审详情等后台读取被整片误拒），改为只拦会让成员驱动宿主或触达团队项目之外内容的方法：创建/删除工作树、会话、终端，给会话、终端、agent 和编排发送输入，桌面、模拟器、语音和剪贴板族，文件写入，Git 写入，宿主托管账号上的写操作，宿主设置、账号、插件、技能、SSH 和更新，Workbench 写入，以及浏览器脚本、cookie/凭据、上传下载等。浏览器页面本身（查看、点击、输入、跳转、刷新）放行，但页面只能打开网页地址，不能打开宿主本地文件；成员新开的页面不抢宿主窗口焦点。终端订阅的二进制流里的输入、窗口大小帧同样丢弃。

清单与测试同在 `runtime-rpc-team-read-policy.ts` 和对应测试：测试遍历全部 RPC 名，名字看起来像写入、却没进清单也没登记为「已核对的读取」的方法会让测试失败，新增方法必须有一次明确决定。拒绝方法本身是否有副作用要按调用链核对（例如读取时会消费邮箱消息的 `orchestration.check` 也在清单里）。

已知尚未收紧的读取：宿主全部 AI 会话的列表和搜索、宿主账号列表、SSH 目标、jira/linear/gitlab 的只读查询目前放行，因为界面的后台读取会调用它们，贸然拒绝会让基础协作出错；是否收紧留给后续专门摸排各方法的界面调用方后再定。

成员身份由客户端在加密握手里自报（成员 ID、姓名、头像），宿主在同一条团队链接下为每位成员建一条设备记录（`parentDeviceId` 指向链接，每条链接最多 200 条）。授权级别只读宿主记录，客户端不能自报权限；但身份不防冒充，持链接的人冒用已被授予完全访问成员的 ID 会得到该成员的访问级别，这是团队内信任的已接受取舍。

整机完全访问沿原生设备登记。主机持有人在共享访问列表的授权操作区多选已连接的只读设备，确认后逐设备写入 `full`；未选设备、未连接设备和其他项目都不受影响。项目和工作树不再细分权限，团队项目统一只读。

## 宿主访问日志

日志继续由宿主 `RuntimeAccessAudit` 写入 `userData/logs/orca-shared-host/`，默认保留 14 天并自动清理，界面在同一 Orca 共享设置页提供动作、结果、时间和成员/设备筛选，以及清理按钮。

记录连接建立/断开、授权/撤销、拒绝、错误和敏感动作的元数据：时间、成员、访问级别、方法分类、结果、耗时和请求 ID。敏感动作包括浏览器截屏、跳转、点击、输入，批注增删和评审收发。成功的常规读取（无论 `team-read` 还是 `full`，包括项目墙、侧栏、工作树列表、会话和终端内容的查看）不逐条落盘，避免正常协作刷屏；成功的写入或显式授权仍记录。成员打开工作树时界面自动发出的写请求（切换标签页、恢复布局、新增终端、保存工作树标签）会被拒绝，但这类拒绝不是成员的选择，不进日志。请求参数、文件内容、模型输入、shell 正文、终端流和凭据永不进入日志。界面用友好中文动作名展示，原始 RPC 名只作诊断辅助。

## 关键代码落点

| 能力 | 现有落点 | G1 适配 |
| --- | --- | --- |
| 团队目录 | `src/main/team-directory-client.ts`、`src/main/ipc/team-collaboration.ts`、`src/renderer/src/workbench/TeamSettingsDialog.tsx` | 群成员/群主读回、`BW/team.json` 读写、登记即标为团队项目、地址一键填入 |
| 项目聚合 | `ProjectWallPage`、项目来源与仓库身份读取 | 以 `repoId` 聚合团队来源，保留现有卡片和未连接状态 |
| Orca 连接 | `SshStatusSegment`、`RuntimePairingUrlGenerator`、`DeviceRegistry` | 默认 `team-read`，共享访问列表按成员显示，保留来源身份 |
| 只读路由 | `runtime-rpc-team-read-policy.ts`、WebSocket dispatch | 默认放行、明确拒绝写入类，新增方法由测试强制决定 |
| 日志 | `runtime-access-audit.ts`、`RuntimeAccessAuditLog.tsx` | 14 天轮转、筛选/清理、抑制成功常规读取 |

原型 [prototype.html](prototype.html) 只表达上述入口、状态和旅程；不另造生产组件或协议。生产实现必须回查原生组件与本设计，不能把原型中的示例头像、地址或目录数据当作真实事实。
