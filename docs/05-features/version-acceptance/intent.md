# 版本验收：把一版交付核对清楚并归档

> 给 Builder、Leader 与验收负责人读取。本文只说明用户结果、价值和范围。行为见 [spec](spec.md)，实现边界见 [design](design.md)，当前证据见 [STATUS](STATUS.md)。本特性承接探索 Monica 的 W04「验收成果」。不在本文保存开发流水、运行日志或逐次变更记录。

## 用户与问题

Builder 需要把同一候选版本的交付件、演示环境、证据和人的判断组织成一场可进行的验收会议。Leader 需要在会上快速核对每个目标做到了什么、证据在哪里、未达项怎样安排。计划、Issue、报告和会议记录分散时，验收结果难以回读，也容易把演示、合入或 Issue 关闭误当成达成。

## 价值与依据

版本验收把计划承诺、Issue/PR 合入时留下的验收件、演示环境、人的目标结论、会议纪要和归档引用连到同一版本。主要依据是周五验收会议的用户要求、[#257](https://github.com/forcegravity1989/builder-workbench/issues/257) 与 [#471](https://github.com/forcegravity1989/builder-workbench/issues/471) 的确认。举证在各 Issue/PR 合入时完成，验收屏只聚合并呈现证据。

## 目标体验

用户从版本入口开始验收。原生会话实际打开后，右侧显示四个可往返的区域。

- 验收准备固定候选，登记包，按项目入口部署演示环境，生成并登记一份按目标和 Issue 组织的验收证据报告，预览后预订会议。
- Showcase 复用固定计划的目标和验收标准。人可以演示真实环境或打开报告，并逐目标选择未判定、达成或不达成。
- 会议纪要接收板面批注、可选转写和人的编辑，整理为按目标组织的共识与遗留。人确认后才生效，也可以撤销确认后重改。
- 归档 PR 及发版本由验收会话执行。板面只显示引用和真实读回状态，发布前由人明确授权，发布后按 tag 现算读回。

## 范围与边界

- 个人自验和逐条验收件采集发生在周中开发流程。本屏只聚合已有验收件，不新增第二套验收工作面。
- 一个版本只有一轮正式验收，不承载跨周轮次刷新。固定提交上的历史材料仍可只读回看，供下版计划使用。
- 验收证据报告负责逐 Issue 的证据罗列，`monica-release` 负责版本收尾叙事，两者各自有来源。
- 会议预订先生成完整预览，经人确认后执行。纪要同步只写预订会议的草稿，最终发送由人完成。
- 不自动合入 PR、关闭 Issue、确认目标、打 tag 或发布 Release。出包、合入、Issue 完成和正式发布分别沿各自正本读回。
- 没有固定计划、项目连接或远端权限时保留身份并显示空、失败或未知，不借用其他版本或宿主补事实。

## 成功判据与未决问题

Builder 能从同一候选连续完成准备、展示、纪要和归档。验收者能按目标核对证据并留下可追溯结论，未达项有下一步或真实跟进 Issue。重启和重新进入后仍能读回同一版本的材料、人工字段和来源身份。

会议通知与纪要协议级目标绑定、真实会议服务获取会议 ID、跨宿主模型会话和完整发布链路仍需对应环境核验。未形成真实证据时保持未知，不把原型、静态检查或协议测试写成通过。
