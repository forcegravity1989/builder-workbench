# 版本验收：准备真实交付，展示成果并归档

> 给 Builder、Leader 与验收负责人判断价值和范围时读；本文管用户目标，不写控件与实现。行为见 [spec](spec.md)，设计见 [design](design.md)，证据见 [STATUS](STATUS.md)。目标或边界变化时更新。
>
> 状态：独立屏与固定工作区沿用既有定义；用户已确认本轮会话入口、目标核对与纪要高保真，作为下一步实施输入。设计认可不表示实现或真壳验收通过，证据见 STATUS。

## 用户与问题

Builder 需要与模型一起核对本版交付，再向 Leader/showcase 参与者说明兑现了什么、有哪些证据、未达项如何处理。准备材料与逐目标验收应当连贯，不能要求用户在另一组通用交付清单、特殊迁移弹窗和重复会话入口之间来回操作。

## 价值与依据

按原计划承诺组织交付、演示和人的判断，让包、证据、实测指标与结论都能追溯到同一候选版本。依据为本轮用户对周五上午出包、下午 showcase、独立验收分支以及 #257 相关交付反馈的明确要求。一次验收不依赖先开启下版计划。

## 目标体验

用户进入验收，即可看到“准备交付 → Showcase 与验收 → 归档”。左侧完整复用固定 bw/week-acceptance 工作区的 Orca 会话、历史和工具，右侧围绕原目标核对实际交付。首行“新建验收”让首次进入、尚无会话或遇到旧数据的用户都能开始协作；已有会话由原生入口继续。版本是主对象，周次是运行上下文。

用户在会话里按项目实际需要准备交付与证据，在同一组目标卡查看材料、历史指标读数及 Issue 状态，由人判断达成、未达或待核并说明下一步。页面不额外设置统一的交付准备清单。目标区可预览、复制当前结果派生的验收纪要；归档通过会话提 PR、人合入，总览按实际记录回看。

## 范围与边界

- 包含交付准备的会话协作、候选与证据关联、展示材料、原承诺核对、人的结论、未达安排、纪要归档和原生周期触发；不重建会话、历史或调度器。自动化首次登记默认关闭，由用户在原生编辑器配置。
- 包构建与测试复用项目实际已有工具；没有安装包概念的项目直接准备约定交付件，不强制二进制包或同一种报告格式。
- 不自建通用发布平台，不把出包等同正式发布，不自动完成 Issue、合入 PR、打 tag 或发布 Release。
- 原目标和约定保持只读，交付说明与人的判断可编辑。实际指标可选当前目录中支持日／周历史的脚本，保留计划原目标与基线，由人说明可比性；不反推读数或自动判定达成。
- 不做里程碑规划器；总览只读取已形成的版本记录。

## 成功判据与待决问题

Builder 能从上午准备连续完成下午展示与归档，验收者能核对每项目标及同一候选的材料，未达项有明确安排。首用周记录取证困难、候选不一致、重复录入与归档遗漏，建立可用于优化的真实观察，不预填改善比例。

正式发布与验收人为项目既有安排；周五时间是典型旅程，不禁止其他日期使用，也不强制所有项目同一时刻。
