# 版本验收 — 六环状态

> 给接手开发、评审和验收的人读取。只记录认可、实现和证据缺口；有真实认可或运行结果时更新。价值见 [intent](intent.md)，行为见 [spec](spec.md)，工程设计见 [design](design.md)。

目标平台是主干 main 的 Electron/Orca 叠层。单页目标卡、按周呈现、会议指导与遗留、会话栏收折和无独立周报导出的方向已由用户确认；[v9.5 原型](prototype.html) 是形态依据。跨周以上周内容为起点、目标结论重新待确认、当前周刷新最新指标及已确认指导回流周一候选，均经用户明确确认。

## 当前实现与证据边界

计划与验收共用 `VersionGoalCard`、原生会话壳和任务详情路径。验收的进展、材料、指标、Issue 备注/标记与人的结论在目标卡内呈现；会议指导在页底逐条确认；纪要是所选材料的派生文本。没有独立周报屏、周报导出、板内搜索或全量 Issue 快照区。

材料沿用 schema 3，可选增量字段不触发旧材料迁移。统一的轮次身份不受目标顺序影响；跨周先提交上轮完整材料，封存引用通过 Git 字节修订与当前持久内容核对后，才允许在一次保存中创建新轮并清除旧目标结论与上轮阶段/归档引用。人填进展、备注、标记等继续作为起点；历史材料与固定计划驱动整页只读视图。旧摘要缺失的内容如实标未记录，不借当前材料补齐。

会议取稿继承 [Issue #374](https://github.com/forcegravity1989/builder-workbench/issues/374) 的内部 eMeeting 脚本机制，接入原生浏览器和工作树宿主文件通道。会话读取全部录制后由独立 subagent 按本项目议题总结，带来源与不确定清单；模型仅能提出 pending 指导。已确认且标为“纳入下周计划”的条目成为周一候选，由人决定承诺。无法取稿时 Builder 在会话补充关键信息，不要求导入文件。

本轮验证采用本地协议测试、真实临时 Git 仓测试、类型检查及静态/替身链路检查。用户明确不运行 CI 和真壳；真实内网取稿、模型遵从、人工操作和重启旅程均未据此宣称通过。提交所用版本、命令、结果与审查修复记录保存在 PR 验证评论，不在本页维护提交流水。
