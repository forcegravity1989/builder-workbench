## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力;BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行,连接或权限不可用时呈现原生失败,不切换到其他机器读写。

验收与计划为同级独立入口,左侧 Orca 原生会话、右侧业务板面。验收走独立固定 bw/week-acceptance 工作树;**分支与选版不上板面**:版本由左侧栏(G2 外框)选定,出包从主分支构建,验收 JSON 在验收分支——均为实现事实,页头不显示分支 chip、不放选版下拉。

右板首行保留「与 Agent 一起核对版本交付」协作卡片与「新建验收」。**页头与计划屏同构**:标题「版本验收」+ 会话收折 chip +「更新代码」(唯一同步入口)+「配置自动化」+「批注模式」。**页头不设全局助手按钮**:「唤起验收助手」的入口按对象就近放置——纪要区「让验收助手整理纪要」、归档区「让验收助手发起归档」,部署/发布按钮本身兼任请求注入,Showcase 无模型填写事务不设助手入口;对象级动作一律经 Orca 原生发送弹窗递交左侧持久验收会话(不新建、不注入,保留已输入草稿)。点击材料后自动展开会话区并展示原生浏览器或编辑器。

**边界:个人自验不在本屏。** 逐项核对需求是否完成发生在周中的会话与开发流程;本屏承载会议材料准备、会中展示、纪要、归档与发版。屏上不提供逐条验收件核对工作面。

**板面为单页四区,顶部阶段导航只做同页定位**(序号+标题+副题,滚动侦测高亮,点击滚动到位):验收准备 → Showcase → 会议纪要 → 归档 PR 及发版本。**界面不设灯**:旅程灯、出包灯、归档灯全部退役,状态以文字与 chip 如实读回;`workflow.stage` 降级为材料内部进度(供 skill 恢复校准与自动化),界面不渲染。导航不是门禁或完成按钮,先备哪步、往返修改均可。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 留下什么 |
|---|---|---|
| 验收准备 | 人点「出包」「部署」(自动下载、本地部署启动、内置 Orca 浏览器打开服务前端);模型按目标整理验收点并采集证据、做演示分诊——易现场演示的记操作路径,不易演示/步骤复杂/需等待的落进验收证据报告(一份/版本,全目标合并);固定候选、登记包 | 部署中的服务(真机演示环境)、一份验收证据报告、登记齐全的材料 |
| Showcase | 周五会议:勾勾表复用计划屏目标行(只读+批注),对着目标逐条演示——环境实操或打开报告对应验收点;每条目标行尾由人标**达成/不达成** | 每个目标的人判结论 |
| 会议纪要 | 会议纪要卡(与计划屏同款机制):批注+可选转写稿 → 验收助手总结「共识/遗留」两块 → 人编辑(可直接粘贴)、逐条确认;遗留条目即下版计划屏「会议遗留」的来源 | 结构化纪要随材料保存,人工确认生效 |
| 归档 PR 及发版本 | 验收 JSON(结论、纪要、报告引用、登记)在固定树提 PR 归档,屏内只放引用+状态+打开 Orca 原生 PR 页入口;需发布的版本经人知情授权后按项目发布入口执行,独立读回发布记录 | 归档的验收记录、已发布版本、总览可回看 |

## 行为规则与异常

### 验收准备:出包、部署与验收证据报告

出包区块可收缩,默认收起为一行最新包摘要;展开后按项目远端自动对接出包流水线,界面不区分平台:下拉只列可出包的流水线;由人点「出包」启动,受理后最新包信息每分钟自动刷新,不重复启动;最新包四字段(项目名称/版本号/创建时间/包文件)是平台真实读数,须核对对应本次候选,不把旧包当本次交付包;报错(无流水线、无权限、远端认不出、非本机宿主)如实呈现,改按项目自有出包入口执行并核对;没有包要求就不造包要求。

「部署」是**会话驱动**的:点击后向验收助手会话注入部署请求,模型下载最新包并**按项目自有部署入口**部署启动(各服务部署逻辑不同,不设固定脚本;桌面应用类=安装并启动,web 服务类=部署并起服务),完成后把**演示环境 URL(桌面应用为启动状态)写回材料**;板面「演示环境」行读回,URL 点击经**内置 Orca 浏览器**打开——该环境即版本的**真机演示环境**(版本级交付件=一份完整交付件+演示环境,不再按目标记录交付件,`goals[].deliverable` 退役与存量兼容读回按 G3 移交项处理)。板面按钮与在会话里直接说同一请求等价。缺部署入口说明缺什么,不虚构命令;环境缺少所需工具时说明缺什么并请人安装,不降级绕道。

**验收证据报告**:一个版本一份,所有目标合并。按「目标 → 验收点」组织,每个验收点含**详细的验收说明**和**一条条罗列的验收证据**(截图、指标读数、平台读回、文件位置);适合现场演示的验收点标注「现场演示」并附操作路径,不强落静态证据。报告按技能资产模板生成(正本:`standard/skills/version-acceptance/assets/evidence-report-template.md`),**每个目标须含「本版目标值 vs 本期读数」对比**(指标退出板面后的对照点);缺证据的验收点进「缺口清单」如实标缺。**指标证据只存在于报告中,Showcase 区不回显指标行。**报告由模型在验收准备阶段生成,落 `.bw/planning/<版本>/` 并登记进验收 JSON;未生成时如实显示并引导在会话中发起。材料打开规则:HTTP(S) 链接经当前工作区的 Orca 内置浏览器打开;`.bw` 相对路径以选定验收工作树为根、按所属宿主在原生编辑器打开;远端材料不交给客户端本地文件 API。报告只收可核对实物与说明,不用大段文本代替证据;缺证据的验收点如实标缺,不凑数。

**与版本收尾总结报告的区别**:本报告是逐验收点的证据罗列(给验收核对与会议展示用);workbench-release 的版本收尾报告是偏总结的叙事(给领导与升级试用者用)。两者独立,不可互相代替;BW 自身收尾时两份都出。

候选固定后写入 `candidateRef`;包出现后登记 `preparedArtifacts`(`kind=package`,含 checksum、location、实际命令)。包重出不自动刷新板面已填内容;是否重新核对相关证据由模型在会话中提醒、人决定,只核受影响部分。

### Showcase 勾勾表

目标行**复用计划屏 GoalRow 裁剪形态**:收起态=目标句、负责人、关联 Issue 数、批注角标、**行尾「达成/不达成」**;展开态=验收标准(只读回显)、关联 Issue 平铺(编号、标题、原生状态、内联备注输入、「遗留」标记)、未达目标的「下一步」输入、打开报告对应验收点的入口。**目标只读**:来自计划材料,本屏不编辑、不添加、不删除目标;**不设指标区**(证据在报告中);无逐条验收件清单 UI。

「达成/不达成」是**人判结论**,不是演示进度——演示过与否不进材料。两个动作互斥,再点取消回未标;未标保持空白,不冒充、不推定。结论写入验收材料 `results[].decision`,沿人工字段守卫(模型/CLI 通道拒写)。

会中每条目标的演示方式由演示者现场选择:内置浏览器实操(真机演示环境),或打开验收证据报告对应验收点;屏不强制演示顺序、不记录演示轨迹。

不达成的目标:原因与安排写进纪要、目标「下一步」与对应 Issue 的备注/「遗留」标记。**风险标记与呈现能力整体去掉**(2026-10-21 决定,与计划屏同步;未来有真实需要再议恢复)。Issue 只核对真实状态,不在验收中拆任务;全关不自动判目标达成;已关闭 Issue 不计入遗留数,保留其已存备注只读展示,不再提供备注或标记编辑。

**遗留双轨**(供下版计划屏「上版回顾」两行回显):Issue 级「遗留」标记=**延期遗留**(上版规划未干完、带入下版的 Issue,呈现编号+标题);纪要「遗留」块条目=**会议遗留**(呈现编号+描述)。旧三标签处置体系(本次验收已解决/纳入下周计划/记录遗留)随指导区块退役。

**在线批注**:与计划屏同一组件族与交互——页头「批注模式」进入,点击目标句或 Issue 行,在对象旁小窗记录,板面批注窗汇总(编号、编辑、删除、板面级批注),Esc 先关小窗再退模式;发送经 Orca 原生发送弹窗递交验收助手,作为会议纪要输入。纪要区不参与批注。

### 会议纪要

与计划屏同款 **MinutesCard 机制**,纪要框常驻各阶段、随时可编辑:输入=①板面在线批注(发送验收助手)②可选会议转写稿(会议 ID 由人提供;自动获取属后续演进)③人直接编辑/粘贴(添加一点、逐条改)。**不设「整理纪要」「基于纪要核对」按钮**——需要模型整理时直接在会话里说。验收助手把输入总结为纪要,正文固定两块:「**共识**」(若干点,可编辑)与「**遗留**」(若干点)。**遗留条目不设闭环状态位**——验收侧没有闭环的消费方;会上已解决的事项写进共识或不写入遗留,遗留条目原样成为下版计划屏「会议遗留」的来源。**经人工确认生效**,生成或填写不自动等于确认;模型不代签、不代确认。纪要独立保存随材料,是会议结论的正本载体;界面派生「预览纪要」退役。

### 归档 PR 及发版本

**归档**:用户在会话中要求归档,核对材料与结论状态后写 `stage=archive`;在固定 bw/week-acceptance 工作树内提交材料(验收 JSON、验收证据报告及截图)并推送,创建到主分支的 PR/MR,按项目流程和授权执行,不另建工作树或分支;开出后把 provider/repository/number 写入 `workflow.archivePr`。**屏内只放归档引用、真实状态(已合入/待合入/已关闭/状态未知,读不到保持未知)与打开 Orca 原生 PR 页的图标入口**;不重复渲染 PR 评论、审核要求或差异统计,不设归档按钮。合入后从项目主干基线读回,总览每版显示一份当前材料。

**发版本**:需要发布的版本在本区由人点「发布」:预检呈现版本号、发布提交与验收包一致性、各目标达成状况、版本说明就绪——**不达成不阻断发布,由人知情决定**;发起后请求送入验收助手会话,**经人明确授权**按项目自有发布入口执行;核对发布提交与验收的包一致,不一致(如会后修复)列出差异与来源待人确认;发布后**独立读回**(tag、时间、资产、校验值)写入材料发布记录(`workflow.release`),本区发布行读回显示。归档 PR 未合入时发布记录随同一 PR 补注;已合入按归档后补证处理,继续编辑同一份验收并保留 cycleId。未经人明确授权不创建 Release、不打标签;不合并 PR、不关闭 Issue、不替人确认版本达成。出包、合入、Issue 完成和正式发布不互相代替。

### 材料与版本机制(沿 v9.5,退役项除外)

选版与初始化(选版入口移至左侧栏/G2 外框,机制不变)、验收可选版本(本分支已提交 `data.json`)、固定计划修订、「更新代码」唯一同步入口、材料服务(CAS、expectedRevision、自动保存)、会话与自动化登记、旧格式材料处理提示,沿用 v9.5 条款。**草案预验收条款随空板硬门禁退役**:计划归档 PR 未合入时不能开始验收(空板+如实报错),不再有"草案预验收"通道。

Issue:详情与编辑复用 Orca 并按来源返回;状态经 provider 刷新,失败不变 0/0。

**本候选退役的 v9.5 界面机制**(协议字段处置见待决问题):轮次选择器与按周呈现、会议指导与遗留独立区块及指导条目、单页目标卡三格展开态与会前/会中/会后姿态叙事、结论三态下拉(改行尾达成/不达成)、界面派生预览纪要、全部灯(旅程/出包/归档)、Issue 风险标记、按目标「约定交付」呈现、页头选版下拉与分支 chip(面包屑与会话收折 chip 随计划屏同款保留)。结论与材料修订的绑定保留为账本字段,板面不做主动失效或待重核呈现。

## 验收与衡量(v10 候选)

| 标识 | 可观察结果 |
|---|---|
| A01 | 独立 bw/week-acceptance 树、原生会话、单页四区+定位导航(无灯、非门禁);候选、目标、Issue 核心信息可读 |
| A02 | 固定计划修订正确;目标只读复用计划屏行形态,不另造副本、无编辑/添加/删除目标;计划归档 PR 未合入时空板+报错,不能开始验收 |
| A03 | 出包区块真实读数与如实报错;「部署」注入会话请求、模型按项目入口部署并写回环境 URL/启动状态;URL 点击经内置 Orca 浏览器打开 |
| A04 | 验收证据报告一份/版本、全目标合并、逐验收点含说明与证据罗列、演示项标操作路径;落材料目录并登记 JSON,内置浏览器可打开;未生成如实显示 |
| A05 | 勾勾表行尾由人标达成/不达成;互斥、可取消回未标;未标空白不冒充;结论落 `decision` 且模型通道拒写;重启后读回一致 |
| A06 | 纪要框常驻各阶段、直接可编辑/粘贴,或经在线批注与可选转写稿由验收助手总结为共识/遗留两块(不设整理按钮,需要时在会话里说);人可增删改、人工确认生效;遗留条目无闭环位、原样供下版计划屏会议遗留回显;模型不代确认 |
| A07 | 归档走固定树 PR;屏内只有引用+状态+原生 PR 页入口;状态如实读回、读不到未知;无归档按钮 |
| A08 | 发布经预检+知情授权;发布提交与验收包一致性核对;独立读回写发布记录并在本区读回;未授权不建 Release/tag |
| A09 | Issue 只核对不拆解,关闭数不判达成;遗留标记与备注为人字段;无风险标记;指标证据只在报告,板面无指标区 |
| A10 | 「更新代码」唯一同步入口;重启、切树、脏树恢复不丢输入 |
| A11 | 边界:屏上无个人自验工作面、无验收件清单 UI;准备产物只以报告与登记形态存在 |
| A12 | 自动化真实到点触发,不自动确认完成;手动运行不改定时启用 |

AJ01(v10 候选):验收准备(人点出包 → 部署启动 → 内置浏览器打开服务 → 模型按目标采集证据并演示分诊 → 生成一份验收证据报告并登记 → 写 candidateRef、登记包)→ 周五 Showcase(勾勾表逐条:环境实操或展示报告,行尾人标达成/不达成)→ 会议纪要(批注+转写经助手总结,人编辑确认纪要)→ 归档 PR 及发版本(会话发起归档提 PR → 屏内点发布、预检、知情授权 → 按项目入口执行 → 独立读回补注 → 人合入 → 总览读回 → 重启核对)。无真实服务、真实报告与真实发布读回的模拟不能计 AJ01 通过。

AJ02:同次恢复、脏树与失败恢复;跨周场景待轮次遗留问题解决后另定。

首用周记录材料找不到、报告与演示对不上、重复录入和未达无安排等问题;不通过剔除未标项制造达成率。完整用户旅程和结果由真实 Electron、模型、文件与 provider 共同取证。
