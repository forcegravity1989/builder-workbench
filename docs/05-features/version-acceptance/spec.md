# 版本验收规格

> 给设计、实现与验收者读取。本文是版本验收的当前行为和可观察判据。价值见 [intent](intent.md)，实现边界见 [design](design.md)，证据见 [STATUS](STATUS.md)。本特性承接探索 BW 的 W04「验收成果」。只记录当前规则、失败边界与未决行为。

当前交互原型是 [prototype.html](prototype.html)。旧版基线与 Showcase 页面已从工作树删除，历史形态由 Git 追溯。原型和静态检查不能证明生产行为或 W04 真实旅程。

| W04 | 探索 BW 的主工作旅程，覆盖证据核对、人工结论、纪要和归档 | 作为本特性的唯一用户旅程入口 |

本特性最多登记一条验收点 E2E 和一条跨特性用户旅程 E2E。两者观察同一真实主链时复用一个入口。只有 W04 无法观察的、规格明确命名的高风险边界才增加一条特性验收 E2E。

## 入口与身份

验收与计划是同级入口。默认使用 `bw/<版本>/acceptance` 固定工作树，旧无绑定上下文兼容 `bw/week-acceptance`。版本身份由绑定工作树、项目、仓库、宿主、runtime owner 和流程类型共同确定，不能从会话标题、日期或分支名推断。材料初始化只接受可读的 committed 固定计划，并校验版本、cycleId、sourceCommit 和 revision。没有来源或身份不一致时不创建材料、不伪造 `planRef`。

用户点击“开始验收”后，专用入口准备完整 Skill，打开原生会话并预填可编辑请求。只有会话实际打开成功才显示四区。计划未合入不阻断启动，助手在会话中提醒并由人处理。普通终端存在不算验收已开始。

Bots 的「BW 验收会议助手」模板是第二个入口：建 Bot 时从同一 Skill 包正源解包独立的 `acceptance-meeting` 会议技能（含 references）进 bot 主目录，不依赖 Orca 云连接器；该技能只管会议预订与材料 `meeting` 写回，验收屏其余步骤仍由 `version-acceptance` 承接，两边同期并存、互不替代。bot 会话不在工作树内，身份按人给定的版本从 `worktree list` 找绑定的验收工作树读回，找不到或多个匹配交人指认。WeLink 沿 bot 所在宿主的 `welink-cli`，建会前先核对材料可写，不可写不建会。

## 行为

### 验收准备

固定候选写入 `candidateRef`，包写入 `preparedArtifacts`。出包沿项目已有流水线，下载、校验和失败信息按真实来源呈现。部署由会话按项目自有入口执行。Web 服务把系统名和 URL 写入 `demoEnv`，桌面应用写入已启动状态，不伪造链接。

“聚合”生成一个版本一份的 `acceptance-evidence.html`。报告按目标和 Issue/PR/MR 展示承诺、基本用例、实际结果、来源和截图，缺证据的项目保留待核对。生成后登记为 `verification` 制品并提供打开入口。文件存在但未登记时不推断报告可用。

预订会议由会话生成完整预览，包含项目、版本、时间、议题和与会人，经人确认后执行并把会议 ID、时间、链接和与会人写入 `meeting`；写回只合并 `meeting` 字段，人工结论原样保留。建会前先以原文保存试探核对材料可写，不可写说明补救并停止。写回失败时先把会议 ID 告知人，再读最新修订重写同一会议，不重复建会；创建结果未知先用 WeLink 核实。已预订不重复执行，改期或取消同样先预览。同步会议纪要只写草稿，最终发送由人完成。

### Showcase

目标和验收标准来自固定计划，只读呈现。Issue 按未关闭、未知、已关闭分组，成功读回才显示类型和计数。演示者可打开真实演示环境或从准备区打开报告。每个目标只有一个人工状态“未判定、达成、不达成”。Issue 关闭、演示完成、出包或 PR 合入都不能推定目标达成。

延期遗留记录在 `issueMarks.carry`，会议遗留记录在人工确认的 `minutes.followups`。前者供下版计划回顾 Issue，后者供下版计划回顾会议结论。旧材料没有 `minutes` 时只读兼容已确认的旧指导条目。

### 会议纪要

纪要正文只有“共识”和“遗留”两块，协议保持平铺列表，呈现按 `G<n> ·` 前缀分组。板面批注、可选转写和人的编辑都可作为整理输入。模型只能修改未确认正文，确认后正文冻结，撤销确认后才能继续编辑。归档前每条遗留要有已落实的计划或结论，或关联真实跟进 Issue，页面不增加逐项闭环门禁。

### 归档与发布

归档由验收会话在固定树提交验收材料、报告和截图并创建 PR/MR。板面只显示材料中的 provider、仓库、编号、真实状态和原生页面入口，以及注入归档请求的对象级动作。归档合入、目标达成和 Issue 关闭是不同事实。

发布请求由人从板面注入会话。模型在会话中呈现版本、候选一致性和目标结论，得到明确授权后沿项目入口执行。发布后把 tag 写入 `workflow.release`，板面依据 tag 向 provider 现算状态、时间、Release 地址和资产。读不到时显示未知并保留原因，总览不复制发布状态。

### 保存、同步与失败

“更新代码”是唯一显式同步入口。材料使用 `schema_version=3`、版本身份校验、CAS revision、锁和原子替换。冲突时人工字段保留本地、模型字段取远端，缺少合并基线时交由人处理。重启、切换版本或切换工作树后按身份独立读回，不能用缓存补当前事实。

项目连接、文件、命令、任务、PR/MR 和会议读取沿 Orca 原生能力。失败显示失败，缺数据显示未知，不切换到其他宿主，不把空态当作没有事实。

## 验收点

| 编号 | 可观察结果 |
| --- | --- |
| A01 | 原生会话成功打开后显示四区，收折会话栏不丢失材料板 |
| A02 | 固定计划、版本身份和并发初始化可核对，缺来源保留空态 |
| A03 | 出包、部署和两种演示环境形态沿真实项目入口读回 |
| A04 | 报告生成、登记、打开和待核对项状态可见 |
| A05 | 人工目标结论可选、可清除，重启后保持 |
| A06 | 纪要按目标呈现，确认冻结，撤销后可编辑并重新确认 |
| A07 | 归档 PR/MR 引用和原生状态可打开，读不到保持未知 |
| A08 | 发布 tag 引用与 provider 状态独立读回，失败不猜 |
| A09 | Issue 分组、计数、类型和遗留边界遵循成功读回规则 |
| A10 | 同步、重启、切树和冲突处理保留字段归属与人工输入 |
| A11 | 验收屏只聚合周中验收件，不提供个人自验工作面 |
| A12 | 原生自动化入口复用现有调度，未到点时不伪造结果 |
| A13 | 旧材料退役字段宽容读回，只读呈现，不参与当前结论 |
| A14 | 会议预订、通知和纪要同步先预览后执行，最终发送由人完成 |
| A15 | 批注模式、默认 Alt+A、改绑和空板负例遵循原生快捷键边界 |

## 测试入口与限制

协议纯函数、材料解析、CAS、人工字段守卫、来源映射和状态读回沿现有 TDD。业务 E2E 按 [开发规范](../../development.md#测试用例) 和 `tests/e2e/AGENTS.md` 控制数量。当前入口与真实环境边界见 [STATUS](STATUS.md)。原型播放、静态检查和协议测试不能替代 W04 的真实 Electron 主链。
