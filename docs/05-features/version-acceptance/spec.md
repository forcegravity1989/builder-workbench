## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

验收与计划为同级独立入口，左侧 Orca 原生会话、右侧业务板面。验收走独立固定 bw/week-acceptance 工作树。出包从主分支构建、验收 JSON 在验收分支，均为实现事实，不作为板面对象呈现。

**选版与计划屏同构**：版本在页头面包屑选定。G2 侧栏版本树（[#389](https://github.com/forcegravity1989/builder-workbench/pull/389)，未合入）落地后，选版入口移至左侧栏、页头面包屑随之移除；在 G2 合入前页头保留选版，不留「无处选版」的空窗。分支名不上板面。

「新建验收」入口只在空板态呈现（「与验收助手新建验收」，点击触发计划合入检测，见「材料与版本机制」）；验收开始后不设首行协作卡片，回到会话经会话栏与各对象级助手入口。**页头与计划屏同构**：标题「版本验收」+ 会话收折 chip +「更新代码」（唯一同步入口）+「配置自动化」+「批注模式」。**页头不设全局助手按钮**：「唤起验收助手」的入口按对象就近放置——纪要区「让验收助手整理纪要」、归档区「让验收助手发起归档」，部署与发布按钮本身兼任请求注入，Showcase 无模型填写事务不设助手入口；对象级动作一律经 Orca 原生发送弹窗递交左侧持久验收会话（不新建、不注入，保留已输入草稿）。点击材料后自动展开会话区并展示原生浏览器或编辑器。

**边界：个人自验不在本屏。** 逐项核对需求是否完成发生在周中的会话与开发流程；本屏承载会议材料准备、会中展示、纪要、归档与发版。屏上不提供逐条验收件核对工作面。

**板面为单页四区，顶部阶段导航只做同页定位**（序号+标题+副题，滚动侦测高亮，点击滚动到位）：验收准备 → Showcase → 会议纪要 → 归档 PR 及发版本。空板态不渲染阶段导航。**界面不设灯**：旅程灯、出包灯、归档灯全部退役，状态以文字与 chip 如实读回；`workflow.stage` 降级为材料内部进度（供 skill 恢复校准与自动化），界面不渲染。导航不是门禁或完成按钮，先备哪步、往返修改均可。

**界面四步与材料三阶段不同名、不映射**：板面四区是阅读定位，材料 `workflow.stage` 是模型 SOP 进度（preparation/showcase/archive 三值，纪要的人工确认是材料字段事实、不占 stage）。两者各自成立，界面不派生灯、不派生完成度。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 留下什么 |
|---|---|---|
| 验收准备 | 人点「出包」「部署」（自动下载、本地部署启动、内置 Orca 浏览器打开服务前端）；模型按目标整理验收点并采集证据、做演示分诊——易现场演示的记操作路径，不易演示/步骤复杂/需等待的落进验收证据报告（一份/版本，全目标合并）；固定候选、登记包 | 部署好的演示环境、一份验收证据报告、登记齐全的材料 |
| Showcase | 周五会议：勾勾表复用计划屏目标行（只读+批注），对着目标逐条演示——环境实操或打开报告对应验收点；每条目标行尾由人标**达成/不达成** | 每个目标的人判结论 |
| 会议纪要 | 会议纪要卡（与计划屏同款机制）：批注+可选转写稿 → 验收助手总结「共识/遗留」两块 → 人编辑（可直接粘贴）、逐条确认；遗留条目即下版计划屏「会议遗留」的来源 | 结构化纪要随材料保存，人工确认生效 |
| 归档 PR 及发版本 | 验收 JSON（结论、纪要、报告引用、登记）在固定树提 PR 归档，屏内只放引用+状态+打开 Orca 原生 PR 页入口；需发布的版本由人点「发布」注入请求，在会话中经人知情授权后按项目发布入口执行 | 归档的验收记录、已发布版本（正本在 Git 标签与 Release 页） |

## 行为规则与异常

### 验收准备：出包、部署与验收证据报告

出包区块可收缩，默认收起为一行最新包摘要；展开后按项目远端自动对接出包流水线，界面不区分平台：下拉只列可出包的流水线；由人点「出包」启动，受理后最新包信息每分钟自动刷新，不重复启动；最新包四字段（项目名称/版本号/创建时间/包文件）是平台真实读数，须核对对应本次候选，不把旧包当本次交付包；报错（无流水线、无权限、远端认不出、非本机宿主）如实呈现，改按项目自有出包入口执行并核对；没有包要求就不造包要求。

「部署」是**会话驱动**的：点击后向验收助手会话注入部署请求，模型下载最新包并**按项目自有部署入口**部署启动（各服务部署逻辑不同，不设固定脚本），完成后把**演示环境写回材料**。板面「演示环境」行读回，分两种形态如实呈现——**web 服务类**给出环境 URL，点击经**内置 Orca 浏览器**打开；**桌面应用类**没有 URL，呈现「已启动」状态文字，不伪造链接、不降级为占位地址。该环境即版本的**真机演示环境**：版本级交付件=一份完整交付件+一个演示环境，不再按目标记录交付件（`goals[].deliverable` 与 `results[].deliveries` 退役，存量兼容读回见「退役清单」）。板面按钮与在会话里直接说同一请求等价。缺部署入口说明缺什么，不虚构命令；环境缺少所需工具时说明缺什么并请人安装，不降级绕道。尚未部署时如实显示未部署并说明下一步，不显示空链接。

**验收证据报告**：一个版本一份，所有目标合并。按「目标 → 验收点」组织，每个验收点含**详细的验收说明**和**一条条罗列的验收证据**（截图、指标读数、平台读回、文件位置）；适合现场演示的验收点标注「现场演示」并附操作路径，不强落静态证据。报告按技能资产模板生成（正本：`standard/skills/version-acceptance/assets/evidence-report-template.md`），**每个目标须含「本版目标值 vs 本期读数」对比**（指标退出板面后的对照点）；缺证据的验收点进「缺口清单」如实标缺。**指标证据只存在于报告中，Showcase 区不回显指标行。**报告由模型在验收准备阶段生成，落 `.bw/planning/<版本>/` 并登记进验收材料的制品清单（沿用既有 `verification` 制品类型，不另立顶层字段）；未生成时如实显示并引导在会话中发起。材料打开规则：HTTP(S) 链接经当前工作区的 Orca 内置浏览器打开；`.bw` 相对路径以选定验收工作树为根、按所属宿主在原生编辑器打开；远端材料不交给客户端本地文件 API。报告只收可核对实物与说明，不用大段文本代替证据；缺证据的验收点如实标缺，不凑数。

**与版本收尾总结报告的区别**：本报告是逐验收点的证据罗列（给验收核对与会议展示用）；workbench-release 的版本收尾报告是偏总结的叙事（给领导与升级试用者用）。两者独立，不可互相代替；BW 自身收尾时两份都出。

候选固定后写入 `candidateRef`；包出现后登记 `preparedArtifacts`（`kind=package`，含 checksum、location、实际命令）。包重出不自动刷新板面已填内容；是否重新核对相关证据由模型在会话中提醒、人决定，只核受影响部分。板面不做主动失效或「待重核」呈现。

### Showcase 勾勾表

目标行**复用计划屏 GoalRow 裁剪形态**：收起态=目标句、负责人、关联 Issue 数、批注角标、**行尾「达成/不达成」**；展开态=验收标准（只读回显）、关联 Issue 平铺（编号、标题、原生状态、内联备注输入、「遗留」标记）、未达目标的「下一步」输入、打开报告对应验收点的入口。**目标只读**：来自计划材料，本屏不编辑、不添加、不删除目标；**不设指标区**（证据在报告中）；无逐条验收件清单 UI。

「达成/不达成」是**人判结论**，不是演示进度——演示过与否不进材料。两个动作互斥，再点取消回未标；未标保持空白，不冒充、不推定。结论写入验收材料 `results[].decision`，沿人工字段守卫（模型/CLI 通道拒写）。行尾两个动作不采集原因文本：不达成的原因与安排的正本是纪要、目标「下一步」与对应 Issue 的备注，结论字段不重复承载（协议落点见 [design](design.md)）。

会中每条目标的演示方式由演示者现场选择：内置浏览器实操（真机演示环境），或打开验收证据报告对应验收点；屏不强制演示顺序、不记录演示轨迹。报告未生成时该入口禁用并如实说明，不静默失败。

不达成的目标：原因与安排写进纪要、目标「下一步」与对应 Issue 的备注/「遗留」标记。**风险标记与呈现能力整体去掉**（2026-10-21 决定，与计划屏同步；未来有真实需要再议恢复）。Issue 只核对真实状态，不在验收中拆任务；全关不自动判目标达成；已关闭 Issue 不计入遗留数，保留其已存备注只读展示，不再提供备注或标记编辑。

**遗留双轨**（供下版计划屏「上版回顾」两行回显）：Issue 级「遗留」标记=**延期遗留**（上版规划未干完、带入下版的 Issue，呈现编号+标题）；纪要「遗留」块条目=**会议遗留**（呈现编号+描述）。旧三标签处置体系（本次验收已解决/纳入下周计划/记录遗留）随指导区块退役。**消费方是计划屏的上版回顾**：验收侧改为由纪要承载会议遗留后，计划屏那处读取必须同批调整，否则「会议遗留」行会静默变空——这是本规格的连带义务，不是可选优化。遗留条目的编号按条目固定身份存、按顺序显示，人工增删不让既有编号漂移。

**在线批注**：与计划屏共用同一批注组件族，但**可批注对象与角标形态按屏各自定义**——验收屏的批注对象是目标整头与 Issue 行两级，验收标准区块不参与批注；角标合并呈现为一个入口而非逐号圆点。页头「批注模式」进入，点击对象在其旁小窗记录，板面批注窗汇总（编号、编辑、删除、板面级批注），Esc 先关小窗再退模式；发送经 Orca 原生发送弹窗递交验收助手，作为会议纪要输入。纪要区不参与批注。**批注是内存态**（与计划屏一致）：重启、切版即清空，发送后不清空、作为纪要输入记录保留在会话侧，不落验收材料；模型删除对象时对应的孤儿批注一并清理。

### 会议纪要

与计划屏同款 **MinutesCard 机制**：纪要框常驻各阶段、随时可见，**点「编辑纪要」进入编辑态后才可增删改与粘贴**（与计划屏同一交互，不做「常驻即编辑」）；退出编辑保留内容。输入=①板面在线批注（发送验收助手）②可选会议转写稿（会议 ID 由人提供；自动获取属后续演进）③人直接编辑/粘贴（添加一点、逐条改）。纪要卡内不设整理按钮，也不设「基于纪要核对」入口（验收目标只读，无调整目标事务）；**纪要区标题行设「让验收助手整理纪要（可提供会议 ID）」对象级入口**，经 Orca 原生发送弹窗递交，与会话中直说等价。验收助手把输入总结为纪要，正文固定两块：「**共识**」（若干点，可编辑）与「**遗留**」（若干点）。

**遗留条目不设闭环状态位**——验收侧没有闭环的消费方；会上已解决的事项写进共识或不写入遗留，遗留条目原样成为下版计划屏「会议遗留」的来源。计划屏纪要的遗留条目带闭环位，两屏共用组件、由验收侧关闭该能力，不因此给验收材料留恒假的死字段（协议落点见 [design](design.md)）。

**经人工确认生效**，生成或填写不自动等于确认；模型不代签、不代确认。**确认可以撤销**：撤销后确认态清零、模型可重新整理该节；处于已确认态时整节冻结，模型通道不得改写。纪要独立保存随材料，是会议结论的正本载体；界面派生「预览纪要」退役。

### 归档 PR 及发版本

**归档**：用户在会话中要求归档，核对材料与结论状态后写 `stage=archive`；在固定 bw/week-acceptance 工作树内提交材料（验收 JSON、验收证据报告及截图）并推送，创建到主分支的 PR/MR，按项目流程和授权执行，不另建工作树或分支；开出后把 provider/repository/number 写入 `workflow.archivePr`。**屏内放归档引用、真实状态（已合入/待合入/已关闭/状态未知，读不到保持未知）、打开 Orca 原生 PR 页的图标入口，以及注入式「让验收助手发起归档」对象级入口**（经原生发送弹窗递交，归档仍由模型在会话中执行）；不重复渲染 PR 评论、审核要求或差异统计，不设直接执行归档的按钮。合入后从项目主干基线读回，总览每版显示一份当前材料。

**发版本**：需要发布的版本在本区由人点「发布」——**板面只有这一个入口，点击即把发布请求注入验收助手会话**。预检、一致性核对、知情授权、按项目自有发布入口执行、发布后独立读回，全部在会话中完成：模型先呈现版本号、发布提交与验收包一致性、各目标达成状况与版本说明就绪状态，**不达成不阻断发布，由人知情决定**；发布提交与验收的包不一致（如会后修复）时列出差异与来源待人确认；**经人明确授权**后执行；发布后独立读回（tag、时间、资产、校验值）在会话中如实报告。

**板面不设预检弹窗、不设发布状态读回行，验收材料不存发布记录**：发布读数的正本在 Git 标签与 provider 的 Release 页，抄一份进材料即造第二正本；总览也不显示「已发布」，需要时按标签现算或直接看 Release 页。这与 BW 仓自身的 workbench-release 技能做法一致（发布后读回给人看，不写版本材料）。

未经人明确授权不创建 Release、不打标签；不合并 PR、不关闭 Issue、不替人确认版本达成。出包、合入、Issue 完成和正式发布不互相代替。归档 PR 未合入时的发布，其记录随该 PR 的材料提交一并留痕于 Git；已合入则按归档后补证处理，继续编辑同一份验收并保留 cycleId。

### 材料与版本机制

选版与初始化、验收可选版本（本分支已提交 `data.json`）、固定计划修订、「更新代码」唯一同步入口、材料服务（CAS、expectedRevision、自动保存）、会话与自动化登记、旧格式材料处理提示，沿用 v9.5 条款，退役项除外。**草案预验收条款随空板硬门禁退役**：计划归档 PR 未合入时不能开始验收（空板+如实报错），不再有「草案预验收」通道。检测读计划材料记录的归档 PR 与其真实状态，读不到状态即按未知处理、不放行。

Issue：详情与编辑复用 Orca 并按来源返回；状态经 provider 刷新，失败不变 0/0。

**跨周场景不在本规格内**：一个版本做一轮验收，不再有「每周五刷新一轮进展验收」的按周呈现与历史周回看（2026-10-22 决定，取代 v9.5 已确认的跨周承接）。轮次退役后，历史仍可按固定提交读回——计划屏「上版回顾」依赖这条链路读取旧验收材料，不得随轮次一并删除。

### 退役清单（v9.5 → v10）

**界面机制退役**：轮次选择器与按周呈现、会议指导与遗留独立区块及指导条目、单页目标卡三格展开态与会前/会中/会后姿态叙事、结论三态下拉（改行尾达成/不达成）、界面派生预览纪要、全部灯（旅程/出包/归档）、Issue 风险标记、按目标「约定交付」呈现、发布预检弹窗与板面发布读回行、总览「已发布」呈现。

**协议字段处置：宽容读回，不剥离、不迁移。** 材料是严格校验，直接删字段会让 v10 之前写下的每一份存量材料整份解析失败——那是把真实的人工记录变成读不出来，不是退役。所以轮次、会议指导、Issue 风险标记、目标级交付件与材料链接、人填进展**保留为 schema 里的旧格式可选字段**：v10 的任何界面与模型通道都不写它们，板面在末尾一个明确标注「旧格式记录（v10 前）」的只读折叠区如实呈现（有哪些就显示哪些：进展原文、交付件与材料链接可点打开、会议指导带处置标签与确认状态、轮次带周次与封存时间、风险标记只留档），并把「不参与任何结论、纪要与遗留回显」写在区块里。要把文件真正转换到当前格式，走会话迁移路径由模型说明方案、经人确认后执行，不留旧文件副本——与 schema2→3 的既有先例一致；读回本身永不改写存量文件。结论与材料修订的绑定保留为账本字段，板面不做主动失效或待重核呈现。

**旧材料的会议遗留不断链**：v10 之前没有纪要节，其「会议遗留」来自已确认且标为「纳入下周计划」的会议指导条目。计划屏上版回顾在读不到纪要节时继续读这些旧条目，使旧版本的两行回显不因退役而变空；一旦该版有了人工确认的纪要，就以纪要为准。

**总览连带**：总览的版本纪要派生文本读取验收材料的结论、交付件、读数与制品登记，退役目标级交付件与新增报告登记后须同批调整，否则总览会显示已退役字段或漏掉报告。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| A01 | 独立 bw/week-acceptance 树、原生会话、单页四区+定位导航（无灯、非门禁，空板态不渲染导航）；候选、目标、Issue 核心信息可读 |
| A02 | 固定计划修订正确；目标只读复用计划屏行形态，不另造副本、无编辑/添加/删除目标；计划归档 PR 未合入时空板+报错，不能开始验收，无草案预验收通道 |
| A03 | 出包区块真实读数与如实报错；「部署」注入会话请求、模型按项目入口部署并写回演示环境；web 服务类 URL 点击经内置 Orca 浏览器打开，桌面应用类如实显示「已启动」而非伪造链接 |
| A04 | 验收证据报告一份/版本、全目标合并、逐验收点含说明与证据罗列、演示项标操作路径；落材料目录并登记进制品清单，内置浏览器可打开；未生成如实显示且报告入口禁用 |

| A06 | 纪要框常驻可见、点「编辑纪要」进入编辑态后可增删改/粘贴；或经在线批注与可选转写稿由验收助手总结为共识/遗留两块（纪要区标题行设「让验收助手整理纪要」对象级入口，经原生发送弹窗递交；卡内不设）；人工确认生效且**可撤销**，已确认态整节冻结、模型通道拒写；遗留条目无闭环位、编号按固定身份、原样供下版计划屏会议遗留回显 |
| A07 | 归档走固定树 PR；屏内为引用+状态+原生 PR 页入口+注入式「发起归档」助手入口，状态如实读回、读不到未知；不设直接执行归档的按钮 |
| A08 | 板面发布区只有一个「发布」按钮，点击注入请求到验收会话；预检、一致性核对、知情授权、执行与独立读回全在会话中完成；未授权不建 Release/tag；**板面无预检弹窗、无发布读回行，材料不存发布记录，总览不显示已发布** |
| A09 | Issue 只核对不拆解，关闭数不判达成；遗留标记与备注为人字段；无风险标记；指标证据只在报告，板面无指标区 |
| A10 | 「更新代码」唯一同步入口；重启、切树、脏树恢复不丢已录入材料的人工输入（批注为内存态，按设计清空，不属「输入」） |
| A11 | 边界：屏上无个人自验工作面、无验收件清单 UI；准备产物只以报告与登记形态存在 |
| A12 | 自动化真实到点触发，不自动确认完成；手动运行不改定时启用 |
| A13 | 旧格式材料宽容读回：v10 之前写下的材料照常打开，退役字段在「旧格式记录（v10 前）」只读区如实呈现且不参与任何结论；模型通道改写旧格式字段被拒；按固定提交的历史读取链路仍可用（计划屏上版回顾依赖），旧材料的会议遗留在无纪要节时仍能被下版读到 |

AJ01：验收准备（人点出包 → 部署启动 → 内置浏览器打开服务 → 模型按目标采集证据并演示分诊 → 生成一份验收证据报告并登记 → 写 candidateRef、登记包）→ 周五 Showcase（勾勾表逐条：环境实操或展示报告，行尾人标达成/不达成）→ 会议纪要（批注+转写经助手总结，人编辑、确认，必要时撤销后重新确认）→ 归档 PR 及发版本（会话发起归档提 PR → 屏内点发布注入请求 → 会话中预检与知情授权 → 按项目入口执行 → 独立读回 → 人合入 → 总览读回 → 重启核对）。无真实服务、真实报告与真实发布读回的模拟不能计 AJ01 通过。

跨周旅程（原 AJ02）随跨周场景退役删除；同次恢复、脏树与失败恢复并入 AJ01 的重启核对与 A10。

首用周记录材料找不到、报告与演示对不上、重复录入和未达无安排等问题；不通过剔除未标项制造达成率。完整用户旅程和结果由真实 Electron、模型、文件与 provider 共同取证。

## 取舍与待决问题

**已决（2026-10-22 负责人拍板，不再作为待决）**：跨周场景不做（轮次整套退役）；纪要先点编辑再改；人工确认可撤销、已确认态冻结；演示环境分 URL 与「已启动」两形态；发布区只剩注入按钮、板面与材料均不留发布呈现与记录、总览不显示已发布；选版过渡期同计划屏留在页头面包屑；批注共用组件族而粒度与角标按屏各自定义。
