# 版本验收规格

> 给交互、实现与验收者读取；本文定义行为与可观察判据，不写执行流水。价值见 [intent](intent.md)，工程取舍见 [design](design.md)，证据见 [STATUS](STATUS.md)。行为变化时更新。
>
> 状态：用户已确认本轮右板协作入口、逐目标核对、纪要与首次/异常高保真，作为实施输入；新增或不确定行为须人工确认，实施证据见 STATUS。[交互原型](prototype.html) 为本特性的独立入口，演示工作区与验收交互；未接产品出包、保存、采集和自动化。

原型源自 v8 评审输入，会话复用边界与数据问题入口随当前规格更新，不表示能力已交付；默认展示 v0.5 快照，页面末尾“原型说明与场景”可切换首次空板、旧数据无法读取及仅其他版本异常，不表示产品会自动选择版本。说明和脚注不进入最终界面。本屏源码位于 [prototype/screen.jsx](prototype/screen.jsx)。来源、离线使用与历史附件边界见[版本计划规格](../version-planning/spec.md)。

## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

验收与计划为同级独立入口，左会话右侧直接编辑，右侧仍是一页。计划走 bw/week-plan，验收走独立固定 bw/week-acceptance 工作树；计划与验收完整复用 Orca 原生会话工作区：顶部新建会话和 Agent 控件、标签/分屏、资源管理器、智能体历史及可收起的工具侧栏均由 Orca 拥有。左侧保留 BW 导航，其下与其他页一样显示项目列表。右板正文首行为“与 Agent 一起核对版本交付”协作卡片，放置带会话图标的“新建验收”，与计划屏一致；分支名在右板页头弱化展示。原生标签栏不另加 BW 启动按钮，不另建聊天、历史或会话绑定。

旅程轴是“准备交付 → 展示验收 → 归档”（与已确认原型一致的节点标签），无独立滚动条。典型周五上午准备、下午展示后归档；不是强制时段门禁。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 留下什么 |
|---|---|---|
| 准备交付 | 确定版本与计划修订、候选提交；会话运行项目已有出包/验证入口，汇集实际交付、包和报告、showcase 材料，刷新指标与 Issue | 有来源的候选与材料、尚未补齐的缺口 |
| Showcase 与验收（旅程轴节点标签为“展示验收”） | 打开同一候选的包/演示/报告，对照原目标逐项说明实际结果；人判断达成、未达、待核，必要时讨论后补证 | 人的结论、依据、未达原因及下一步 |
| 归档 | 由当前结构化结果生成验收纪要，可复制；按钮准备会话请求，按授权提 PR，由人审核合入 | 固定修订的验收记录，总览中可按版本/周回看 |

## 行为规则与异常

### 候选、材料与出包

材料准备在原生验收会话中按项目约定协作完成，实际交付与材料链接汇入对应 G1/G2/G3 目标卡供人核对。页面不设独立“交付准备”卡片或第二个“准备交付”按钮，也不预列一组“待关联”的包、报告和展示占位。项目没有某项交付要求时可不填，不新增统一必填包、报告或 showcase 链接；来源随实际材料保留，长材料按需打开。

准备阶段是用户与模型准备实际交付的过程，不另设页面上的“材料备齐”勾选流程。材料是否满足目标在对应目标卡由人核对；固定计划、候选或采用的材料变化后需重新核对。机器检查分别呈现真实结果与未知，不因填了链接就宣称材料已通过验证或目标已经达成。

“新建验收”启动原生验收会话，已有会话可继续准备与核对；由模型按项目约定协作，不在点击旅程节点时静默运行 shell 或发布。已有可用命令和授权可直接执行，缺项目入口就说明缺什么，不虚构命令。

材料注明 candidateRef、执行工作区/入口和结果来源；包适用时附版本/校验值。源码候选与验收材料工作树分开定位，不能从验收分支旧 HEAD 打包。候选更新后，旧包、验证和展示证据显式标不匹配；重新验证或由人解释适用范围，不能沿用旧绿灯。准备中断保留已完成材料，重试不重复启动同一仍运行的构建。

### 目标卡与事实

原计划 goalId、目标句、约定交付、验收说明、指标目标与基线保持只读，新增实际交付、只读实测、人的结论及后续。验收可从当前指标目录选择实际采集指标，包括原计划未绑定指标的目标；没有选择时不凭空加数值行。验收指标选择不改写计划承诺，原目标与基线保留供参考，目标值与实际值不互相覆盖。

验收可选版本是本验收分支上已提交的 `.bw/planning` 版本目录：目录里有 `data.json` 就是一个版本，不按评审合入记录决定能不能开始。唯一候选的计划修订自动预填进下拉仅是渲染便利，不表示人已选版；选版与开轮始终由人点击触发。进入验收屏先把采用分支最新拉进本分支（保证周一定稿合入主干后，周五在验收分支直接可见该计划）；同步失败或冲突如实提示、不阻断进入、不更换数据来源，由用户在会话中带工作模型处理。开始本轮时读取该目录在本分支上的当前计划。未合入的计划可以明确进行草案预验收；计划更新先提示差异，由人决定换引用。跨工作树读同一个明确项目和修订，不把规划树最新未保存内容当已批准承诺。归档与合入状态只作提醒信号：读不回真实合入证明（如 CodeHub 项目）一律如实记 Unknown，不假绿，也不据此隐藏记录或阻塞读取。

业务指标只接入支持按日／周查询历史的已登记脚本，不保留“仅当前值”路径；数据存储由被管理项目负责，不新增 BW 采样、存储或指标自动化。刷新同步项目正式来源并重新读取指标目录，使用最新已合入定义与脚本，不把更新合进计划／验收工作树或覆盖草稿。

计划保存的提交号或指标定义与当前不同，不阻止本次采集；展示计划原约定与本次选择，保存实际采用的来源、日／周窗口和读数。证据详情展示来源、采集时间、配置提交与脚本修订，定义指纹保存在材料中供追溯；旧基线和已保存证据保留历史身份。界面不增加专门的定义/单位变化对比，可比性由用户在验收依据中说明，不按数值大小自动判定达成或跨口径改善。更换实际证据仍按下文要求重新人工核对。实际值不可手填，旧人工记录不作为本期有效读数；失败、陈旧、未知与真实零分别呈现。

Issue 区是状态核对，无任务拆解动作。读取真实编号、标题、目标关联、状态与读取时间；失败不变 0/0，Issue 全关不自动判断目标达成。详情和编辑复用 Orca，返回验收/计划/任务的实际来源，恢复版本、周记录、草稿、会话、筛选和滚动。

### 结论、历史与归档

人作出达成、未达或待核结论，未达在对应目标下写明缺口和下一步；带入下版先形成候选，不自动承诺或排期。“遗留”不另设流程。验收纪要从固定计划、候选、实际材料、指标和 Issue 快照及人的结果生成，不维护第二份手写会议正文。“预览纪要”放在本版目标验收区标题旁，打开只读内容并提供复制；页面右上角不再另放“验收报告”入口。

人的结论保留当时采用的证据关联。只补充某个目标的材料，该目标提示“待重新核对”，其他目标保留原验收状态；更换整版源码候选、候选交付包或固定计划修订，则全部目标提示重新核对。同一源码提交重新打包后，候选包记录的校验值或其他来源发生变化，也不能沿用原验收状态。旧结论和依据继续可见，由人再次确认，模型不重新签署。

同一版本只保留一轮活动验收；新周原生会话可继续该轮材料，跨周本身不使有效证据失效。验收、计划分别推进，验收保持固定 planRef。该轮实际结果即使未达也可归档；归档与合入状态是提醒信号不是开轮门——上一轮未归档不阻塞开始下一轮（都在同一固定分支上，未合入不影响继续改新的或改老的），唯一的门是当前轮未保存修改，防止新轮草稿覆盖人的输入。历史按固定提交留存，不保证每个自然周都有独立纪要；不支持多轮未归档草稿。总览回看摘要和原文，不覆盖历史或伪造完成结论。

保存、人的验收、PR 合入和正式发布是不同事实。归档只预填当前聚焦的原生聊天输入框，不自动发送；没有可用输入框时提示先新建或打开原生会话，实际执行遵守已有授权；不自动完成 Issue、合入或发布。未开始/未知灰，进行中/待审黄，明确失败/未达红，有对应依据才绿。未达报告合入时归档可绿、结论仍红。

### 会话、周期与恢复

“配置自动化”入口位于右板页头分支名旁，打开对应的 Orca 原生编辑器；首行协作卡片只保留“新建验收”，手动启动一次不改变定时启用状态。高保真中的原生编辑器只作带脚注的占位，首次与异常场景可从页底“原型场景¹”展开查看；这些原型控件不进入最终界面。

验收独立固定工作树，由原生项目/宿主身份定位。进入页面只选中工作区，不新建会话；已有原生标签、分屏、历史与工具直接复用，上午到下午从原生入口继续同一会话。

“新建计划／验收”调用对应已登记自动化的原生手动运行，使用用户当前保存的提示、工具和模型，并自动打开、聚焦本次原生会话；定时运行仍在后台。普通原生新建会话不自动注入 BW Skill。首次登记默认关闭定时、使用固定工作区且 reuseSession=false，按 creationKey 去重；已有条目按当前 BW 版本覆盖同步 BW 所有的提示词，用户所有的设置（启用开关、触发时间、模型、会话复用）保留不覆盖；后续运行尊重用户保存的会话复用配置。“配置自动化”打开原生编辑器，历史恢复和运行打开完全沿用 Orca。

首次进入无版本、无会话时，首行协作入口仍可使用，下方保持空板。旧格式或损坏材料在同一卡片内紧凑提示实际版本与计划/验收数据文件；“新建验收”把当前明确选中的版本、具体文件及读取问题带入原生会话，作为一次性上下文随已登记自动化的手动运行与保存提示合并为单次递交（automation.runNow 的 oneShotPrompt，capability 门控，不另建会话），不再另放“在会话中处理”启动按钮。模型先读文件、说明问题与备份/迁移方案，经用户确认后执行，不把点击按钮当成同意改数据；只有其他旧版本异常时不阻塞正常版本。页面不保留专用迁移预览/确认弹窗或额外的旧结果入口；迁移工具及安全约束仍由材料服务和 Skill reference 承担。

写入统一材料服务，限制到验收工作树的验收对象，expectedRevision 冲突保留双方输入。同步项目基线前检查工作树与未归档修改，脏树不重置，冲突可见并保留原件。真实执行、读回和重启必须核对不同工作树不会串写。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| A01 | 独立 bw/week-acceptance 分支/工作树、原生会话及单页三阶段；候选、目标、Issue 核心信息可读 |
| A02 | 固定计划修订正确、承诺只读；跨树读取与草案预验收不混淆，换计划先显式处理差异 |
| A03 | 上午通过项目实际入口准备交付，材料可打开且绑定候选；失败恢复、候选变化与缺工具可见，不假报出包/验包成功 |
| A04 | 从当前目录选择支持日／周历史的脚本实测，与总览/计划同源；原计划承诺保留，定义变化不阻止采集，实际来源/窗口/读数可追溯、可比性由人说明 |
| A05 | Issue 真实状态可刷新，无任务拆解入口，不以关闭数自动判目标达成 |
| A06 | 原生任务详情编辑后按来源返回，保留正确版本/周记录、会话与草稿 |
| A07 | 下午展示同一候选材料，人逐目标判断；未达安排可保存并带入会话，模型不代签 |
| A08 | 验收纪要可复制，含候选/来源/待核与未达；归档后总览按版本及多周读回，旧修订不被覆盖 |
| A09 | 跨树隔离、并发/失败/重启和脏树恢复不丢输入；包/证据与候选不一致时不能沿用完成状态 |
| A10 | 原生自动化真实到点，默认新运行新会话并尊重用户保存的复用配置，原生运行入口与 BW 验收双栏、同日准备到展示及同次恢复/重试不重复，保持发布权限边界 |

AJ01：直接进入独立验收树 → 固定计划及候选 → 真实出包/验证或项目约定交付 → 打开证据/刷新指标/核对 Issue → 下午 showcase → 人判含未达 → 会话提 PR → 人合入 → 总览历史读回 → 重启核对。AJ02 覆盖跨周运行、同日恢复、脏树与候选变更失败恢复。无可核对构建结果的模拟不能计 A03/AJ01 通过。

首用周记录材料找不到、候选不一致、重复录入和未达无安排等问题；不通过剔除待核项制造达成率。完整用户旅程和结果由真实 Electron、模型、文件与 provider 共同取证。
