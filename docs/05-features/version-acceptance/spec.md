## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

验收与计划为同级独立入口，左会话右侧直接编辑，右侧仍是一页。计划走 bw/week-plan，验收走独立固定 bw/week-acceptance 工作树；计划与验收完整复用 Orca 原生会话工作区：顶部新建会话和 Agent 控件、标签/分屏、资源管理器、智能体历史及可收起的工具侧栏均由 Orca 拥有。左侧保留 BW 导航，其下与其他页一样显示项目列表。右板正文首行为“与 Agent 一起核对版本交付”协作卡片，放置带会话图标的“新建验收”，与计划屏一致；分支名在右板页头弱化展示。原生标签栏不另加 BW 启动按钮，不另建聊天、历史或会话绑定。会话栏支持收起为窄轨并随时展开恢复，同一壳内计划/验收两屏共用——平时看板与投屏展示时收起、把整幅宽度让给板面，需要在会话区查看报告或页面时展开；收折不中断会话，只改变布局。

旅程轴是“准备交付 → 出包 → 展示验收 → 归档”（与已确认原型一致的节点标签），无独立滚动条。三个阶段灯只读模型写入材料的 `workflow.stage`：灯位不超过 stage 为绿，其后为灰；「出包」灯是唯一例外，不跟 stage，随出包区块读到的最新制品包点亮，读到真实包才绿。典型周五上午准备、下午展示后归档；不是强制时段门禁。「展示验收」节点定位到目标验收区。

## 完整用户旅程

| 阶段                                          | 用户与系统协作                                                                                                       | 留下什么                                  |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 准备交付                                      | 确定版本与计划修订、候选提交；会话运行项目已有测试/交付入口，汇集实际交付、包和报告、showcase 材料，刷新指标与 Issue | 有来源的候选与材料、尚未补齐的缺口        |
| 出包                                          | 需要安装包时在出包区块选流水线并由人点「出包」启动；区块按项目远端自动对接出包流水线，展示最新制品包真实读数，可下载安装包本体 | 对应候选的最新制品包信息与可打开的安装包   |
| Showcase 与验收（旅程轴节点标签为“展示验收”） | 打开同一候选的包/演示/报告，对照原目标逐项说明实际结果；人判断达成、未达、待核，必要时讨论后补证                     | 人的结论、依据、未达原因及下一步          |
| 归档                                          | 由当前结构化结果生成验收纪要，可复制；归档在会话中发起，模型记录阶段、按授权提 PR 并写回 PR 引用，由人审核合入              | 固定修订的验收记录，总览中可按版本/周回看 |

跨周版本在最终展示验收前，每周五进行一轮「进展刷新」：可以不出包，刷新进展、指标读数与遗留/风险标记，人的结论可暂不作出；该轮记录随材料保存，界面按周呈现。最终轮完成展示验收与归档。周与轮次行为见「周次与轮次」。

## 行为规则与异常

### 候选、材料与出包

材料准备在原生验收会话中按项目约定协作完成，实际交付与材料链接汇入对应 G1/G2/G3 目标卡供人核对。页面不设独立“交付准备”卡片或第二个“准备交付”按钮，也不预列一组“待关联”的包、报告和展示占位。项目没有某项交付要求时可不填，不新增统一必填包、报告或 showcase 链接；来源随实际材料保留，长材料按需打开。

出包区块位于准备交付与展示验收之间，按项目远端自动对接出包流水线，界面不区分平台：流水线下拉只列可出包的流水线；由人点「出包」启动所选流水线，启动受理后流水线在平台上运行约数分钟，最新包信息每分钟自动刷新，不重复启动。最新制品包的项目名称、版本号、创建时间与包文件是平台真实读数——须核对确实对应本次候选，不把旧包当本次交付包；「下载」把最新安装包本体保存到人选择的目录。区块报错（无流水线、无权限、远端认不出、非本机宿主）时如实呈现并改按项目自有出包入口执行；没有包要求就不造包要求。

准备阶段是用户与模型准备实际交付的过程，不另设页面上的“材料备齐”勾选流程。材料是否满足目标在对应目标卡由人核对；固定计划、候选或采用的材料变化后需重新核对。来源行只呈现记录事实与纯声明比对（材料与候选的一致性），不做在线文件与执行探测；不因填了链接就宣称材料已通过验证或目标已经达成。

“新建验收”启动原生验收会话，已有会话可继续准备与核对；由模型按项目约定协作，不在点击旅程节点时静默运行 shell 或发布。已有可用命令和授权可直接执行，缺项目入口就说明缺什么，不虚构命令。

材料注明 candidateRef、执行工作区/入口和结果来源；包适用时附版本/校验值。源码候选与验收材料工作树分开定位，不能从验收分支旧 HEAD 打包。候选更新后，旧包与展示证据在目标卡和来源行显式标不匹配；由人重新验证或解释适用范围，旧结论按证据变化标记待重新核对，不沿用。准备中断保留已完成材料，重试不重复启动同一仍运行的构建。

### 目标卡与事实

原计划 goalId、目标句、约定交付、验收说明、指标目标与基线保持只读，新增实际交付、只读实测、人的结论及后续。指标行仅用于计划已承诺的指标或已保存的读数，无这两者的目标不显示指标区；额外采集诉求在会话明确后补证。无交付件约定及现存交付证据时不预铺交付输入区。验收指标选择不改写计划承诺，原目标与基线保留供参考，目标值与实际值不互相覆盖。

验收可选版本是本验收分支上已提交的 `.bw/planning` 版本目录：目录里有 `data.json` 就是一个版本，不按评审合入记录决定能不能开始。只在页头选一次版本；选中后回显已有验收，没有验收时按该版当前计划初始化并自动保存。移除重复选计划及“开始本次／下一轮验收”入口。进入验收屏先回显原生工作区和现有材料，进屏不做任何 Git 动作；页头「更新代码」是唯一同步入口，把本分支快进到主干最新，执行期间提示状态、材料暂时只读，无论快进成败都重读候选和材料，保留脏草稿并提示实际冲突。切走后不会因更新完成跳回；快进不了（分叉等）保持原样、如实提示、不更换数据来源，由用户在会话中带工作模型处理。初始化时读取该目录在本分支上的当前计划；已有验收继续使用其固定引用。未合入的计划可以明确进行草案预验收；计划更新先提示差异，由人决定换引用。跨工作树读同一个明确项目和修订，不把规划树最新未保存内容当已批准承诺。归档灯只读 `workflow.stage`；PR 合入状态按模型记录的 `archivePr` 向 provider 薄读取并显示在归档状态行，读不回（如 CodeHub 项目）一律如实保持未知，不假标已合入，也不据此隐藏记录或阻塞读取。

业务指标只接入支持按日／周查询历史的已登记脚本，不保留“仅当前值”路径；数据存储由被管理项目负责，不新增 BW 采样、存储或指标自动化。刷新读取项目主干基线（正式来源）并重新读取指标目录，使用最新已合入定义与脚本，不把更新合进计划／验收工作树或覆盖草稿。

计划保存的提交号或指标定义与当前不同，不阻止本次采集；展示计划原约定与本次选择，保存实际采用的来源、日／周窗口和读数。证据详情展示来源、采集时间、配置提交与脚本修订，定义指纹保存在材料中供追溯；旧基线和已保存证据保留历史身份。界面不增加专门的定义/单位变化对比，可比性由用户在验收依据中说明，不按数值大小自动判定达成或跨口径改善。更换实际证据仍按下文要求重新人工核对。实际值不可手填，旧人工记录不作为本期有效读数；失败、陈旧、未知与真实零分别呈现。

Issue 区与计划共用状态、详情样式；验收只核对状态，无任务拆解动作。读取真实编号、标题、目标关联、状态与读取时间；失败不变 0/0，Issue 全关不自动判断目标达成。每个目标的关联 Issue 内列在该目标卡的可收缩子块中（编号、标题、可读状态），按提单分类标签分组呈现（Bug 类／Feature 类／未分类，无标签如实归未分类、不猜测）；卡内逐条人工标记「遗留」与「风险」——开放 Issue 不自动判遗留、关闭不自动判达成，标记是人的判断并随轮次记录。Issue 责任人从原生 assignee 读回展示，未指派不显示、不手填。页面不设全量 Issue 快照区；页顶摘要行提供总数、完成数与刷新状态入口，与卡内内列读同一快照。详情和编辑复用 Orca，返回验收/计划/任务的实际来源，恢复版本、周记录、草稿、会话、筛选和滚动。

### 单页目标卡与会前/会中/会后

验收板是单页，不设面切换或独立展示屏：一个目标一张卡，整卡可收缩。

- **收起态 = 结论行**：结论灯、目标句、人的结论选择、关联 Issue 完成计数、遗留/风险标记数。长文本不出现在收起态。
- **展开态 = 完整故事与编辑**，按「横排故事行 → Issue 分组子块 → 进展备注」组织：横排一行三格（约定交付｜实际交付与交付件链接｜指标实测，实测的取值区间与口径收进详情）；约定交付格附计划完成与负责人只读展示——两者取自计划材料既有字段（计划屏填写），缺值如实显示未记录/未指派，验收屏不另设输入位；关联 Issue 进可收缩子块，按提单分类标签分组呈现，逐条可人工标记「遗留」「风险」；进展/备注栏可填可不填、自然语言由人主导（遗留或风险的原因必须在会前写好），未达时该栏即「未达项与原因」，并配「下一步」栏与「交给会话」入口。
- **出包区块属会前**，整块可收缩：默认收起为一行摘要（最新包版本与创建时间），会中不占视野；出包与下载操作展开后进行，行为规则不变。
- 严格意义上验收覆盖 **showcase 会前、会中、会后**三个阶段；三阶段看的是同一块板、同一组主要信息，变的是密度与操作姿态，不变界面：**会前**（准备交付/出包节点）卡片展开编辑——填实际交付与依据、标记遗留与风险、刷新指标、出包；**会中**（展示验收节点）「全部收起」得结论行一览，讲哪个目标展开哪张卡，预览纪要是派生只读文本，领导的关键指导由人逐条记录；**会后**（归档节点）补未达安排与下一步、确认结论、按会上指导安排发布与跟进、在会话中发起归档。旅程轴保持既有四节点及其 `workflow.stage` 协议映射不变，三阶段是使用姿态叙事，不新增界面节点或模式。
- 「全部展开/全部收起」是页面级控件；单卡开合记忆用户意图，默认值 = 未填写结论与材料时展开，避免漏填。
- 页底不设「遗留与风险」汇总卡（卡头计数与卡内标记已呈现，不设第二份汇总），改放**「领导会上指导」**：人逐条记录会上的关键指导，附影响标签（影响会后发布／纳入下周计划／本版跟进）与可选关联目标；指导随轮次写入材料（草案），供会后发布判断与下周计划会话读回；人记录原文要点，模型不代笔、不自动生成。进展、依据等自然语言内容同样由人主导填写，模型经人确认后才写入材料，不代笔结论（防止会中讲述者对内容不知情）。

### 周次与轮次

- **周呈现**：跨周版本在界面按自然周呈现——周次选择器显示「2026-W40（本周 · 展示验收）／2026-W39（进展刷新 · 历史）」式条目，默认落本周。「轮次」只作为材料协议层的记录维度，不上界面。
- **轮次记录**：同一版本的验收材料按轮次记录。首轮随开始验收建立；此后每个周五进展刷新新增一轮，由已登记自动化运行（或其手动运行）中模型写材料建立，页面不设开轮按钮——既有「开轮入口移除」条款继续适用于页面控件；到点只开会话，不代任何人确认。本周可编辑；历史周只读、从 Git 读回，用于回看既往进展与纪要。归档后的补证与状态变化记入新一轮，不改写已归档轮次。轮次不改变「完成永远由人确认」：新一轮不自动继承上一轮的人的结论，沿用需人再次确认。
- **周报不设独立屏与导出件**：周报信息（目标结论、实际交付与交付件链接、遗留与风险、Issue 明细、会上指导）由验收屏承载，「预览纪要」是唯一派生文本出口，规则见纪要条款。不设独立周报自动化、独立固定分支与第二份周报数据正本。
- **Issue 分类标签**：卡内分组依赖提单时的 bug/feature 分类标签，标签随计划屏提单与拆解流程落地（已立项，随生产实施批交付）；存量 Issue 无标签的如实归「未分类」，不回填猜测。

### 结论、历史与归档

人作出达成、未达或待核结论，未达在对应目标下写明缺口和下一步；带入下版先形成候选，不自动承诺或排期。“遗留”不另设流程。验收纪要从固定计划、候选、实际材料、指标和 Issue 快照及人的结果生成，不维护第二份手写会议正文；纪要只呈现人能读的正文（结论、约定与实际交付、指标实测、下一步、未达与后续），周期、材料修订、固定提交、定义指纹等技术标识留在材料与 Git，不进纪要。“预览纪要”放在本版目标验收区标题旁，打开只读内容并提供复制；页面右上角不再另放“验收报告”入口。

人的结论保留当时采用的证据关联。只补充某个目标的材料，该目标提示“待重新核对”，其他目标保留原验收状态；更换整版源码候选、候选交付包或固定计划修订，则全部目标提示重新核对。同一源码提交重新打包后，候选包记录的校验值或其他来源发生变化，也不能沿用原验收状态。旧结论和依据继续可见，由人再次确认，模型不重新签署。

同一版本保留一份当前材料与按轮次记录；新周开新一轮，换会话与归档后补证均记入当前轮，保留 cycleId 和固定 planRef，历史轮次只读从 Git 追溯。未达也可归档，合入不代表目标达成。归档灯随模型记录 `stage=archive` 点亮；空白草稿初始化及后续修改均自动保存，归档与补证在原会话继续处理，页面不设归档操作按钮。总览每版展示当前材料，旧修订从 Git 追溯。

两屏共用自动保存与冲突处理；页头“更新代码”快进固定树并重读材料及候选。页面不展示原始目录诊断、固定计划 UUID 或全局指标窗口行，必要来源收进具体证据详情。保存、人的验收、PR 合入和正式发布是不同事实。归档请求直接在会话中发起，页面不预填终端草稿、不设等待框（贴草稿通道已整体退役）；实际执行遵守已有授权，不自动完成 Issue、合入或发布。旅程灯色只有两态：模型记录阶段完成则绿，未记录则灰；灯是进度信号不是完成权威。未达报告归档时归档灯可绿、目标结论仍按未达呈现。

### 会话、周期与恢复

“配置自动化”入口位于右板页头分支名旁，打开对应的 Orca 原生编辑器；首行协作卡片只保留“新建验收”，手动启动一次不改变定时启用状态。高保真中的原生编辑器只作带脚注的占位，首次与异常场景可从页底“原型场景¹”展开查看；这些原型控件不进入最终界面。

验收独立固定工作树，由原生项目/宿主身份定位。进入页面只选中工作区，不新建会话；已有原生标签、分屏、历史与工具直接复用，上午到下午从原生入口继续同一会话。

“新建计划／验收”调用对应已登记自动化的原生手动运行，使用用户当前保存的提示、工具和模型，并自动打开、聚焦本次原生会话；定时运行仍在后台。普通原生新建会话不自动注入 BW Skill。首次登记默认关闭定时、使用固定工作区且 reuseSession=false，按 creationKey 去重；已有条目按当前 BW 版本覆盖同步 BW 所有的提示词，用户所有的设置（启用开关、触发时间、模型、会话复用）保留不覆盖；后续运行尊重用户保存的会话复用配置。“配置自动化”打开原生编辑器，历史恢复和运行打开完全沿用 Orca。

首次进入无版本、无会话时，首行协作入口仍可使用，下方保持空板。旧格式或损坏材料在同一卡片内紧凑提示实际版本与计划/验收数据文件；只有旧计划、尚无验收文件时也保留该版本候选和升级诊断；“新建验收”把当前明确选中的版本、具体文件及读取问题带入原生会话，作为一次性上下文随已登记自动化的手动运行与保存提示合并为单次递交（automation.runNow 的 oneShotPrompt，capability 门控，不另建会话），不再另放“在会话中处理”启动按钮。模型先说明旅程，再把旧字段收成新计划，对不上的目标问人，经用户确认后执行，不留旧文件副本，也不把点击按钮当成同意改数据；只有其他旧版本异常时不阻塞正常版本。页面不保留专用迁移预览/确认弹窗或额外的旧结果入口；迁移工具及安全约束仍由材料服务和 Skill reference 承担。

写入统一材料服务，限制到验收工作树的验收对象，expectedRevision 冲突保留双方输入。同步项目基线前检查工作树与未归档修改，脏树不重置，冲突可见并保留原件。真实执行、读回和重启必须核对不同工作树不会串写。
