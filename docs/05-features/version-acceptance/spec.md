# 版本验收规格

> 给交互、实现与验收者读取；本文定义行为与可观察判据，不写执行流水。价值见 [intent](intent.md)，工程取舍见 [design](design.md)，证据见 [STATUS](STATUS.md)。行为变化时更新。
>
> 状态：已合入并作为实施输入；新增或不确定行为须人工确认，实施证据见 STATUS。[第八版交互原型](prototype.html) 为本特性的独立入口，演示工作区、准备材料与验收交互；未接产品出包、保存、采集和自动化。

原型为历史评审输入，不表示能力已交付；本屏源码位于 [prototype/screen.jsx](prototype/screen.jsx)。来源、离线使用与历史附件边界见[版本计划规格](../version-planning/spec.md)。

## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

验收与计划为同级独立入口，左会话右侧直接编辑，右侧仍是一页。计划走 bw/week-plan，验收走独立固定 bw/week-acceptance 工作树；侧边分支、会话列表、输入及归档上下文一致，不仅替换显示文字。

旅程轴是“准备交付 → Showcase 与验收 → 归档”，无独立滚动条。典型周五上午准备、下午展示后归档；不是强制时段门禁。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 留下什么 |
|---|---|---|
| 准备交付 | 确定版本与计划修订、候选提交；会话运行项目已有出包/验证入口，汇集实际交付、包和报告、showcase 材料，刷新指标与 Issue | 有来源的候选与材料、尚未补齐的缺口 |
| Showcase 与验收 | 打开同一候选的包/演示/报告，对照原目标逐项说明实际结果；人判断达成、未达、待核，必要时讨论后补证 | 人的结论、依据、未达原因及下一步 |
| 归档 | 由当前结构化结果生成验收纪要，可复制；按钮准备会话请求，按授权提 PR，由人审核合入 | 固定修订的验收记录，总览中可按版本/周回看 |

## 行为规则与异常

### 候选、材料与出包

准备区提供候选提交/来源、交付包或制品、验证报告和展示材料的摘要与打开动作。项目没有某项交付要求时可不填，不新增统一必填包、报告或 showcase 链接。长材料按需展开，常用桌面一屏能看见候选、目标结果与 Issue 汇总。

准备灯表示项目所需材料已备齐并由人核对，不要求系统证明全部生成来源。用户可在准备区标记材料备齐；固定计划、候选或所列材料变化后需重新核对。机器检查分别呈现真实结果与未知，不把人工核对标成机器证明，也不据此判断目标达成。

“准备交付”把当前版本和缺口放入本次验收会话，由模型按项目约定协作；不在点击旅程节点时静默运行 shell 或发布。已有可用命令和授权可直接执行，缺项目入口就说明缺什么，不虚构命令。

材料注明 candidateRef、执行工作区/入口和结果来源；包适用时附版本/校验值。源码候选与验收材料工作树分开定位，不能从验收分支旧 HEAD 打包。候选更新后，旧包、验证和展示证据显式标不匹配；重新验证或由人解释适用范围，不能沿用旧绿灯。准备中断保留已完成材料，重试不重复启动同一仍运行的构建。

### 目标卡与事实

原计划 goalId、目标句、约定交付、验收说明、指标目标保持只读，新增实际交付、只读实测、人的结论及后续。没有约定指标不凭空加数值行；目标值与实际值不互相覆盖。

固定 planRef 优先读项目指定基线已合入的计划提交。未合入计划可以明确进行草案预验收；基线/计划更新先提示差异，由人决定换引用。跨工作树读同一个明确项目和修订，不把规划树最新未保存内容当已批准承诺。

指标只执行已登记脚本：能回溯则按窗口查历史，只能查当前就显示当前值/时间及能力限制；后者不能据此声称完成历史周或区间目标。实际值不可手填，旧人工记录不作为本期有效读数。失败、陈旧、未知与真实零分别呈现，归档固定实际采用的证据。

Issue 区是状态核对，无任务拆解动作。读取真实编号、标题、目标关联、状态与读取时间；失败不变 0/0，Issue 全关不自动判断目标达成。详情和编辑复用 Orca，返回验收/计划/任务的实际来源，恢复版本、周记录、草稿、会话、筛选和滚动。

### 结论、历史与归档

人作出达成、未达或待核结论，未达在对应目标下写明缺口和下一步；带入下版先形成候选，不自动承诺或排期。“遗留”不另设流程。报告从固定计划、候选、实际材料、指标和 Issue 快照及人的结果生成，不维护第二份手写会议正文。

人的结论保留当时采用的证据关联。只补充某个目标的材料，该目标提示“待重新核对”，其他目标保留原验收状态；更换整版源码候选、候选交付包或固定计划修订，则全部目标提示重新核对。同一源码提交重新打包后，候选包记录的校验值或其他来源发生变化，也不能沿用原验收状态。旧结论和依据继续可见，由人再次确认，模型不重新签署。

同一版本只保留一轮活动验收；新周原生会话可继续该轮材料，跨周本身不使有效证据失效。验收、计划分别推进，验收保持固定 planRef。该轮实际结果即使未达也可归档，归档后才能开始下一轮。历史按实际归档的固定提交留存，不保证每个自然周都有独立纪要；不支持多轮未归档草稿。总览回看摘要和原文，不覆盖历史或伪造完成结论。

保存、人的验收、PR 合入和正式发布是不同事实。归档只预填未发送请求，实际执行遵守已有授权；不自动完成 Issue、合入或发布。未开始/未知灰，进行中/待审黄，明确失败/未达红，有对应依据才绿。未达报告合入时归档可绿、结论仍红。

### 会话、周期与恢复

验收独立固定工作树，由原生项目/宿主身份定位。新每周运行开新会话，同次手动打开、上午到下午及自动化重试恢复原会话。计划与验收分别登记 Orca 自动化，existing + reuseSession=false 用于新运行；时区/时间/启停遵从用户设置，不额外安排下午第二条自动化。自动化后台启动，运行记录仍打开原生项目会话；从 BW 验收入口打开时恢复同一原生会话与材料，不另开一条双栏专用会话。

写入统一材料服务，限制到验收工作树的验收对象，expectedRevision 冲突保留双方输入。同步项目基线前检查工作树与未归档修改，脏树不重置，冲突可见并保留原件。真实执行、读回和重启必须核对不同工作树不会串写。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| A01 | 独立 bw/week-acceptance 分支/工作树、原生会话及单页三阶段；候选、目标、Issue 核心信息可读 |
| A02 | 固定计划修订正确、承诺只读；跨树读取与草案预验收不混淆，换计划先显式处理差异 |
| A03 | 上午通过项目实际入口准备交付，材料可打开且绑定候选；失败恢复、候选变化与缺工具可见，不假报出包/验包成功 |
| A04 | 脚本实测不可手填，与总览/计划同源；历史查询与仅当前值可区分，不用当前数验历史目标 |
| A05 | Issue 真实状态可刷新，无任务拆解入口，不以关闭数自动判目标达成 |
| A06 | 原生任务详情编辑后按来源返回，保留正确版本/周记录、会话与草稿 |
| A07 | 下午展示同一候选材料，人逐目标判断；未达安排可保存并带入会话，模型不代签 |
| A08 | 验收纪要可复制，含候选/来源/待核与未达；归档后总览按版本及多周读回，旧修订不被覆盖 |
| A09 | 跨树隔离、并发/失败/重启和脏树恢复不丢输入；包/证据与候选不一致时不能沿用完成状态 |
| A10 | 原生自动化真实到点，新周期新会话，原生运行入口与 BW 验收双栏、同日准备到展示及同次恢复/重试不重复，保持发布权限边界 |

AJ01：直接进入独立验收树 → 固定计划及候选 → 真实出包/验证或项目约定交付 → 打开证据/刷新指标/核对 Issue → 下午 showcase → 人判含未达 → 会话提 PR → 人合入 → 总览历史读回 → 重启核对。AJ02 覆盖跨周运行、同日恢复、脏树与候选变更失败恢复。无可核对构建结果的模拟不能计 A03/AJ01 通过。

首用周记录材料找不到、候选不一致、重复录入和未达无安排等问题；不通过剔除待核项制造达成率。完整用户旅程和结果由真实 Electron、模型、文件与 provider 共同取证。
