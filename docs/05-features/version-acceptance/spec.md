## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

验收与计划为同级独立入口，左侧 Orca 原生会话、右侧业务板面。验收走独立固定 bw/week-acceptance 工作树。出包从主分支构建、验收 JSON 在验收分支，均为实现事实，不作为板面对象呈现。

**选版与计划屏同构**：绑定流程树的版本由侧栏与工作树绑定决定，页头只读回显；旧无绑定固定树保留面包屑选版。每版验收使用对应 bw/<版本>/acceptance 固定树，旧无绑定流程继续使用 bw/week-acceptance。分支名不上验收板面。

未开始时显示短卡“版本验收尚未开始”和“开始验收”。点击时先将该条目的工具保存为 BW 当前默认智能体，再沿原生自动化手动运行；工具同步失败则回显错误并停止启动，该条目后续运行使用同步后的工具。只有本次运行会话实际打开成功后展示四区；失败保留卡片并回显原因。计划未合入或归档状态无法确认不在前端阻断会话，助手开场先提醒并协助处理，不自动合入。无可读固定计划时 Showcase 目标为空，不借用其他版本或伪造 planRef；纪要显示只读空态，整理请求仍可发往会话。成功启动的视图状态按流程、版本、项目/宿主/owner 与工作树隔离，仅在渲染进程内保留，切屏回来继续四区；普通终端存在不算启动。已有有效材料独立恢复板面。开始后不常驻重复入口，回到会话经会话栏与对象级助手动作。**页头与计划屏同构**：标题左、动作右同一行（2026-10-23 UI 对齐轮，旧列布局退役）——标题「版本验收」+ 会话收折 chip +「批注模式」+「更新代码」（唯一同步入口）+「配置自动化」；板面动作按钮一律图标+短动词统一格式（`BoardActionButton`）；「批注模式」入口在页头右上角（#426 v0.7 验收会决议，与计划屏同位：页头不随内容滚动，会中随时进出、未发送条数角标常驻可见，取代「入口贴着可批注对象」的区块头形态；空板态与无计划时无可批注对象，不渲染）。**页头不设全局助手按钮**：「唤起验收助手」的入口按对象就近放置——准备区「聚合」「预订会议」、纪要区「让验收助手整理纪要」「同步会议纪要」、归档区「让验收助手发起归档」，部署、聚合、预订会议、同步会议纪要与发布按钮本身兼任请求注入，Showcase 无模型填写事务不设助手入口；对象级动作经 Orca 原生发送弹窗递交指令，可选择已有会话或沿原生快捷入口新建智能体，保留原有输入草稿。点击材料后自动展开会话区并展示原生浏览器或编辑器。

**边界：个人自验不在本屏，举证随各 Issue/PR 合入时留下。** 逐项核对需求是否完成发生在周中的会话与开发流程——有开发的 Issue 在 PR 评论中留下验证评论，无开发直接关闭的 Issue 在 Issue 评论中留下证据（#471 举证前移）；本屏承载会议材料准备、会中展示、纪要、归档与发版，对验收件只聚合呈现、不采集。屏上不提供逐条验收件核对工作面，也不做多人协作验收。

**板面为单页四区，顶部阶段导航只做同页定位**（序号+标题+副题，滚动侦测高亮，点击滚动到位）：验收准备 → Showcase → 会议纪要 → 归档 PR 及发版本。未开始短卡不渲染阶段导航；成功启动后即使材料尚未形成，四区及导航也保持可见。**界面不设灯**：旅程灯、出包灯、归档灯全部退役，状态以文字与 chip 如实读回；`workflow.stage` 降级为材料内部进度（供 skill 恢复校准与自动化），界面不渲染。导航不是门禁或完成按钮，先备哪步、往返修改均可。

**界面四步与材料三阶段不同名、不映射**：板面四区是阅读定位，材料 `workflow.stage` 是模型 SOP 进度（preparation/showcase/archive 三值，纪要的人工确认是材料字段事实、不占 stage）。两者各自成立，界面不派生灯、不派生完成度。

## 行为规则与异常

### 验收准备：出包、部署、预订会议与证据报告聚合

出包区块可收缩，默认收起为一行最新包摘要；展开后按项目远端自动对接出包流水线，界面不区分平台：下拉只列可出包的流水线；由人点「出包」启动，受理后最新包信息每分钟自动刷新，不重复启动；最新包四字段（项目名称/版本号/创建时间/包文件）是平台真实读数，须核对对应本次候选，不把旧包当本次交付包；报错（无流水线、无权限、远端认不出、非本机宿主）如实呈现，改按项目自有出包入口执行并核对；没有包要求就不造包要求。

「部署」是**会话驱动**的：点击后向验收助手会话注入部署请求，模型下载最新包并**按项目自有部署入口**部署启动（各服务部署逻辑不同，不设固定脚本），完成后把**演示环境写回材料**（web 服务：系统名+URL；桌面应用：启动状态）。板面「演示环境」行读回，分两种形态如实呈现——**web 服务类**显示系统名（未给系统名回退 URL），点击经**内置 Orca 浏览器**打开；**桌面应用类**没有 URL，呈现「已启动」状态文字，不伪造链接、不降级为占位地址。该环境即版本的**真机演示环境**：版本级交付件=一份完整交付件+一个演示环境，不再按目标记录交付件（`goals[].deliverable` 与 `results[].deliveries` 退役，存量兼容读回见「退役清单」）。板面按钮与在会话里直接说同一请求等价。缺部署入口说明缺什么，不虚构命令；环境缺少所需工具时说明缺什么并请人安装，不降级绕道。尚未部署时如实显示未部署并说明下一步，不显示空链接。

**预订会议**：会话驱动。人点「预订会议」注入请求，模型生成完整预览——日期时间、与会人、议题——**人确认后执行**（用 `welink-cli meeting create` 创建会议，默认开启 AI 听，不伪造开启步骤），把会议信息（标题、时间、会议 ID、接入链接）写回材料 `meeting`，板面「验收会议」行读回。已预订不重复订；改期或取消由人说明后同样先预览再执行。会议动作的逻辑（先预览后执行、只写草稿、幂等跳过、中断先核对）内置于验收技能，不依赖额外安装的会议技能；会议工具缺失或未登录时如实转告缺什么、请人安装或登录，不虚构步骤、不绕道。

**验收证据报告（聚合）**：一个版本一份，按「目标 → Issue」组织。举证在各 Issue/PR 合入时已经留下——**有开发的 Issue**，证据在 PR 评论中关于该开发或修复的验证评论；**无开发直接关闭的 Issue**，证据在 Issue 相关评论；形式为截图或其他易于人理解的实物，不是大段文本。本屏不采集证据、不做演示分诊。人点「聚合」注入请求后，模型按各目标的 Issue 清单归并验收件，按技能资产模板生成报告（正本：`standard/skills/version-acceptance/assets/evidence-report-template.md`），每个 Issue 含验收说明与逐条证据（PR 验证评论/Issue 评论的链接与摘要、截图、平台读回、文件位置）；缺证的 Issue 在报告里如实标出，由人确认缺口或自行补充，模型不代采、不凑数。报告落 `.bw/planning/<版本>/` 并登记进验收材料的制品清单（沿用既有 `verification` 制品类型，不另立顶层字段）；未生成时如实显示并引导在会话中发起。材料打开规则：HTTP(S) 链接经当前工作区的 Orca 内置浏览器打开；`.bw` 相对路径以选定验收工作树为根、按所属宿主在原生编辑器打开；远端材料不交给客户端本地文件 API。验收件只进报告，板面不回显。

**与版本收尾总结报告的区别**：本报告是逐 Issue 的验收件罗列（给验收核对与会议展示用）；workbench-release 的版本收尾报告是偏总结的叙事（给领导与升级试用者用）。两者独立，不可互相代替；BW 自身收尾时两份都出。

候选固定后写入 `candidateRef`；包出现后登记 `preparedArtifacts`（`kind=package`，含 checksum、location、实际命令）。包重出不自动刷新板面已填内容；是否重新部署演示环境、是否重新聚合报告由模型在会话中提醒、人决定——验收件在各 Issue/PR 合入时已留下，包重出不改变它们。板面不做主动失效或「待重核」呈现。

### Showcase

目标行复用计划屏目标行的只读形态：收起显示目标、负责人、Issue 分组计数、批注角标和单个人工结论状态；展开显示验收标准、Issue 逐行列表与未达目标的下一步。标题不显示“勾勾表 · 人判 N/N”。目标来自明确固定计划，本屏不编辑、添加或删除；无可读固定计划显示空目标，不补示例数据。报告入口仅在“验收准备”，一版本一份、全目标合并；本区不设指标行或逐条验收件清单。

目标行计数后行内只有一个可选择“未判定 / 达成 / 不达成”的状态标识（#471 批注6：样式以生产实现为准）；选择未判定清除人工结论，沿现有中性/警示色，状态文字始终可见。结论由人操作，写入 results[].decision 并保持人工字段守卫，模型和 CLI 不代判。Issue 关闭数、演示进度、出包或合入都不能推定目标达成。原因与安排写在纪要、下一步或对应 Issue 备注，不重复增加结论原因字段。

会中每条目标的演示方式由演示者现场选择：内置浏览器实操（真机演示环境），或从「验收准备」打开本版验收证据报告自行翻到该目标各 Issue 的验收件（报告按「目标 → Issue」组织，板面不做目标级深链）；屏不强制演示顺序、不记录演示轨迹。报告未生成时该入口禁用并如实说明，不静默失败。

不达成的原因与安排写入纪要、目标下一步或 Issue 备注。只对读回为未关闭的 Issue 提供遗留标记与备注编辑；已关闭记录保留既有人工备注只读展示，未知状态不冒充未关闭。目标计数显示“未关闭 N · 遗留 N · 已关闭 N”，未知另列；遗留仅为未关闭且人工标记项的子集，不另加到总数，关闭后不再计遗留，也不删除已存人工记录。Issue 按未关闭、未知、已关闭分组排序，同组保留计划顺序；标记遗留不重排。仅成功读回的 Issue 显示 Feature/Bug 标签，复用计划屏 taskKind 口径；未读到数据不猜类型。风险标记已退役，Issue 状态以 provider 为准，不在本屏拆任务。

**遗留双轨**（供下版计划屏「计划准备」区两行回显）：Issue 级「遗留」标记=**延期遗留**（上版规划未干完、带入下版的 Issue，呈现编号+标题）；纪要「遗留」块条目=**会议遗留**（呈现编号+描述）。旧三标签处置体系（本次验收已解决/纳入下周计划/记录遗留）随指导区块退役。**消费方是计划屏的计划准备区**：延期遗留读 `issueMarks.carry`，会议遗留读**已人工确认**纪要的遗留块；材料没有纪要节时（v10 之前写下）回退到已确认且标为「纳入下周计划」的旧指导条目，使旧版本两行回显不因退役变空。遗留条目的编号按条目固定身份存、按顺序显示，人工增删不让既有编号漂移。

**在线批注**：与计划屏共用同一批注组件族，但**可批注对象与角标形态按屏各自定义**——验收屏的批注对象是目标整头、验收标准与 Issue 行（#426 v0.7 验收会决议：验收标准参与批注，与计划屏对齐；「下一步」输入件是人工填写区，不参与）；角标合并呈现为一个入口而非逐号圆点。页头右上角「批注模式」进入（常驻可见，带未发送条数角标，面板关掉也看得出还有批注没发出去），点击对象在其旁小窗记录，板面批注窗汇总（编号、编辑、删除、板面级批注），Esc 只关小窗、不退模式（2026-10-29 #444 拍板，与计划屏同口径）；Orca 键位体系的「板面批注」快捷键（默认 Alt+A、设置 → Shortcuts 可改绑，同键进出，#444，与计划屏共用同一动作）是退出模式的唯一键盘路径——小窗开着时按它直接退模式（与点按钮一致），终端聚焦时和弦流向 TUI、浏览器 webview 聚焦时不触发（与 `browser.grabElement` 同等已知局限），空板或无可读固定计划时入口不渲染、按键无反应；发送经 Orca 原生发送弹窗递交验收助手——助手按对象理解意见后回应或修订材料，批注同时是会议纪要整理的输入之一（双意图，2026-10-24 负责人明确，与计划屏同口径）。纪要区不参与批注。**批注是内存态**（与计划屏一致）：批注会话按板面身份（scope+版本）键控存放，两屏各读写自己的会话——切屏保留各自未发送批注（会中看一眼另一屏是正常动作）、切版即清空、重启随渲染进程丢弃，不落验收材料；模型删除对象时对应的孤儿批注一并清理。**发送成功即清空已递交批注**（2026-10-23 负责人拍板与计划屏统一 A 案，取代原「发送后不清空」条款）：每次发送都是全量清单、以最新一次为准，递交后记录已在会话侧，板面留着会让下次发送重复喂给助手、污染纪要；清空只在发送成功门控内发生，失败或 Esc 不清现场，回执明说清了几条。

### 会议纪要

与计划屏同款 **MinutesCard 机制**：纪要框常驻各阶段、随时可见，**点「编辑纪要」进入编辑态后才可增删改与粘贴**（与计划屏同一交互，不做「常驻即编辑」）；退出编辑保留内容。输入=①板面在线批注（发送验收助手）②可选会议转写稿（会议 ID 由人提供；自动获取属后续演进）③人直接编辑/粘贴（添加一点、逐条改）。纪要卡内不设整理按钮，也不设「基于纪要核对」入口（验收目标只读，无调整目标事务）；**纪要区标题行设「让验收助手整理纪要（可提供会议 ID）」对象级入口**，经 Orca 原生发送弹窗递交，与会话中直说等价。验收助手把输入按纪要质量标准**提炼**为纪要（Skill 侧正本 meeting-minutes reference，与计划屏同口径——板面已呈现的达成情况/Issue 状态不进纪要，#428/#431），正文固定两块：「**共识**」（若干点，可编辑）与「**遗留**」（若干点）。**按目标组织**（#471 批注5）：条目带「G<n> ·」目标前缀，读视图按前缀分组到各目标小标题下；骨架随目标同步显示——固定计划可读时每个目标先占一节（小标题+共识/遗留待填），不依赖条目填入才出现；协议仍是平铺清单，编辑态保持平铺，前缀分组是呈现级实现，协议级目标绑定留给后续会议相关 Issue。共识记各目标会上产生的结论性决定，不复述板面已呈现的达成情况。

**同步会议纪要**：纪要卡脚部「标记人工确认」右侧设「同步会议纪要」对象级入口（#471 评审新增）：把材料中已形成的纪要按固定样式（按目标分节）渲染成草稿，只写人已填写或确认的内容，不虚构、不补写；完整预览（含写回目标会议）经人确认后写入预订会议的纪要草稿，返回纪要链接并提醒最终发送是人在会议系统的手动动作；材料尚未预订会议时入口禁用并说明先在准备区预订。中断或状态不确定时先打开会议系统核对草稿是否已写入，不直接重试覆盖。

两屏纪要都使用共识/遗留文本列表，不设逐项闭环开关。归档前，每条遗留须明确已落实到计划或结论，或引用真实的跟进 Issue；助手核对并补齐去向，人在 PR 审查。跟进 Issue 可以未完成，不要求先关闭；页面不增加硬门禁。计划材料旧 closed 字段兼容保留且无编辑控件，不据此推断新状态；不增加新的材料协议。下版会议遗留只是固定来源参考，已落实项不自动生成任务或承诺，关联 Issue 也不自动排期。

**经人工确认生效**，生成或填写不自动等于确认；模型不代签、不代确认。**确认可以撤销**：撤销后确认态清零、模型可重新整理该节；处于已确认态时整节冻结，模型通道不得改写。纪要独立保存随材料，是会议结论的正本载体；界面派生「预览纪要」退役。

### 归档 PR 及发版本

**归档**：用户在会话中要求归档，助手核对材料、结论及每条会议遗留已落实或真实 Issue 跟进后写 `stage=archive`；在本版绑定验收树（旧无绑定树为 bw/week-acceptance）内提交材料（验收 JSON、验收证据报告及截图）并推送，创建到主分支的 PR/MR，按项目流程和授权执行，不另建工作树或分支；开出后把 provider/repository/number 写入 `workflow.archivePr`。**屏内放归档引用、真实状态（已合入/待合入/已关闭/状态未知，读不到保持未知）、打开 Orca 原生 PR 页的图标入口，以及注入式「让验收助手发起归档」对象级入口**（经原生发送弹窗递交，归档仍由模型在会话中执行）；不重复渲染 PR 评论、审核要求或差异统计，不设直接执行归档的按钮。合入后从项目主干基线读回，总览每版显示一份当前材料。

**发版本**：需要发布的版本在本区由人点「发布」——**板面只有这一个执行入口，点击即把发布请求注入验收助手会话**。预检、一致性核对、知情授权、按项目自有发布入口执行、发布后独立读回，全部在会话中完成：模型先呈现版本号、发布提交与验收包一致性、各目标达成状况与版本说明就绪状态，**不达成不阻断发布，由人知情决定**；发布提交与验收的包不一致（如会后修复）时列出差异与来源待人确认；**经人明确授权**后执行；发布后独立读回（tag、时间、资产、校验值）在会话中如实报告，并把 tag 引用写入 `workflow.release` 供板面读回。

**板面不设预检弹窗；发布状态经读回行呈现，材料只存 tag 读回键**（#462 修订 v10「板面不呈现发布状态」决策，2026-10-27）：发布后板面按材料里的 tag 引用向 provider **现算读回**——是否已发布、标签、发布时间、Release 页地址与资产清单；读数不落材料，正本在 Git 标签与 provider 的 Release 页，抄一份进材料即造第二正本。读回行四态如实呈现：材料无 tag 引用=「未发布」（材料事实，无需读）；引用在而 provider 查无对应 Release=「未找到 Release」（真实读数，不是未知）；读回失败=「状态未知」并注明原因；读取中如实标注。Release 页地址点击经内置 Orca 浏览器打开。发布前读回行显示「未发布」，不显示授权提示文本。总览仍不显示「已发布」。

未经人明确授权不创建 Release、不打标签；不合并 PR、不关闭 Issue、不替人确认版本达成。出包、合入、Issue 完成和正式发布不互相代替。归档 PR 未合入时的发布，其记录随该 PR 的材料提交一并留痕于 Git；已合入则按归档后补证处理，继续编辑同一份验收并保留 cycleId。

### 材料与版本机制

选版、固定计划修订、“更新代码”唯一同步入口、材料 CAS 与自动保存沿现有材料服务。会中冲突保持字段归属合并：人字段保留本地、模型字段取远端，只有缺少合并基线时由人处置。验收启动不再读取归档 PR 状态作前端门禁；助手在会话开场核对计划是否合入，未合入或无法确认时先提醒，不自动合入。材料初始化仍只接受可读 committed 固定计划，核对版本、cycleId、来源提交和 revision，并保留并发写入护栏；没有来源或身份不符不创建验收材料、不伪造 planRef。允许先开会话不等于恢复 draft 计划协议，也不代表计划已正式归档。

Issue：详情与编辑复用 Orca 并按来源返回；状态经 provider 刷新，失败不变 0/0。

**跨周场景不在本规格内**：一个版本做一轮验收，不再有「每周五刷新一轮进展验收」的按周呈现与历史周回看（2026-10-22 决定，取代 v9.5 已确认的跨周承接）。轮次退役后，历史仍可按固定提交读回——计划屏「计划准备」区依赖这条链路读取旧验收材料，不得随轮次一并删除。

### 退役清单（v9.5 → v10）

界面机制的退役项不在此枚举——现行形态由上文各节定义，v9.5 原形从 Git 与 [prototype.html](prototype.html) 追溯。本节只保留**会影响存量材料能否读回**的协议处置。

**协议字段处置：宽容读回，不剥离、不迁移。** 材料是严格校验，直接删字段会让 v10 之前写下的每一份存量材料整份解析失败——那是把真实的人工记录变成读不出来，不是退役。所以轮次、会议指导、Issue 风险标记、目标级交付件与材料链接、人填进展**保留为 schema 里的旧格式可选字段**：v10 的任何界面与模型通道都不写它们，板面在末尾一个明确标注「旧格式记录（v10 前）」的只读折叠区如实呈现（有哪些就显示哪些：进展原文、交付件与材料链接可点打开、会议指导带处置标签与确认状态、轮次带周次与封存时间、风险标记只留档），并把「不参与当前结论；旧验收没有纪要节时，已确认的 next-week-plan 指导仍供下版会议遗留只读回顾」写在区块里。要把文件真正转换到当前格式，走会话迁移路径由模型说明方案、经人确认后执行，不留旧文件副本——与 schema2→3 的既有先例一致；读回本身永不改写存量文件。结论与材料修订的绑定保留为账本字段，板面不做主动失效或待重核呈现。#471 的退役项（会前采集、演示分诊、现场演示标注、目标值 vs 读数对比、缺口清单、包重出自动重核）均为行为与报告口径变化，不涉及材料 schema——旧报告照常打开，只读历史不受影响。

**总览连带**：总览的版本纪要派生文本读验收材料的结论、读数、纪要两块与制品登记；不读已退役的目标级交付件，版本级交付件与演示环境由 `demoEnv` 与制品登记承载，报告按既有 `verification` 制品类型渲染。总览不呈现发布状态。
