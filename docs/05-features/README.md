# docs/05-features/ — 特性清单与链状态矩阵（正本）

> **本篇维护约定**
> - **读者与时机**：开发特性、盘点、排期、回答「BW 现在有哪些特性、链走到哪」时读；从 AGENTS「特性级变更」行与 [02 §6.2](../01-principles/02-working-backwards.md) 进入。
> - **职责与边界**：只装三层特性清单 × 六环链状态总览 × 使用分诊 × 跨特性已知债登记。**不装**：特性定义正文（在各特性目录 intent/spec/STATUS）、方法论（02 §6.2/6.3）、交付机制规范（`.bw/release/README.md`）、盘点过程证据（git 历史与 PR 记录）。
> - **结构**：判据 → 产品特性矩阵 → 开发方法资产 → 预研 → 已知债登记。
> - **更新触发**：特性带入/定义回填、分诊或归属变化、任一特性 STATUS 链状态变化、相关 PR 合入、预研候选增删。本篇是现状正本，不记流水；改动随引发它的 PR 同批提交。

## 判据（一句话版，正文见 02 §6.3）

- **特性** = 持续提供给用户的一件完整的事；目录/页面/crate/屏数 ≠ 特性数；组合形态（自动化+skill+屏，如周一屏）算一个特性；四铁律等横向约束是横切站/内核义务，不是特性。
- **分层看用户身份**：被管项目的 Builder ⇒ 产品特性（本目录）；BW 开发团队自己 ⇒ 开发方法资产；尚无真实用户 ⇒ 预研（不开链）。
- **新工作带入三问**（修改存量 vs 新增承载）：服务已有特性的用户目标 ⇒ 改存量并带入其链；开新用户目标 ⇒ 新特性先立 intent；答不出谁在用 ⇒ 预研或不做。
- **补链规则**：只补**在用**特性的定义层（intent/spec/验收点/旅程定义）；实现层（E2E 代码、TDD 归属）随带入补。基本不用的特性正常列出、链暂不补，**处理该特性 BUG 或重设计之日起**补。
- 格值：**●** 齐 ／ **◐** 部分 ／ **○** 缺（未回填）／ **待建** = TDD 特性归属清单暂缓（workspace 单测在门禁常跑，非无测试）／ **—** 不适用。
