# BW 特性矩阵

> 开发特性、给 BW Issue 定归属或核对交付现状时读。本篇是 BW 归属名称、文档入口和六环链状态总览的正本。按用户旅程一项结果一行，横向能力列在旅程之后；共用目录可分行。归属或证据变化时同步对应行，具体行为读规格，链状态按各自 STATUS 的证据范围填写。判据见[原则 02 §6.2–6.3](../01-principles/02-working-backwards.md#62-六环交付链)。

## 特性矩阵

BW Issue 按主要用户结果选一个主归属。每行名称可直接用于标题；版本、目标和主单身份按[通用 Issue 规范](../../standard/references/issue-state.md)填写。

| 主归属 | 用户结果 | 定义与证据 | 链状态概览 |
|---|---|---|---|
| 项目纳入 | 将仓库纳入 BW，记录项目身份与信息 | [接入规格](project-intake/spec.md) · [状态](project-intake/STATUS.md) | 接入已有定义；共享链接回显已在进程重启后验证，完整接入旅程未验证。 |
| 项目墙 | 跨项目、主机扫墙，按真实读数选择要跟进的项目 | [墙卡规格](project-intake/spec.md) · [状态](project-intake/STATUS.md) | 墙卡读数与配置已有设计、协议测试及局部真壳证据；跨主机扫墙旅程未验证。 |
| 项目总览 | 按日期和特性安排里程碑，对照版本计划与实际目标结果 | [总览规格](overview-metrics/spec.md) · [里程碑状态](overview-metrics/STATUS.md#里程碑认可与验证边界) | 里程碑规划、独立预期日期和目标结果投影已确认；规划到验收及重启的完整旅程未验证。 |
| 版本计划 | 与团队确定本版目标、验收条件和任务，评审并归档计划 | [计划规格](version-planning/spec.md) · [状态](version-planning/STATUS.md) | 目标与规格已确认，材料协议和部分真壳旅程已验；模型执行与真实来源归档的覆盖见状态。 |
| 版本会话管理 | 从侧栏找到版本、目标、工作区与会话，准备并进入流程树 | [侧栏规格](version-workspace/spec.md) · [状态](version-workspace/STATUS.md) | 版本导航、绑定和固定树恢复有协议与真壳证据；跨宿主与侧栏其他交互按已验范围判断。 |
| 任务管理 | 跨来源查找、筛选和处理 Issue、PR/MR，跟进任务结果 | [任务页现有资料](codehub/spec.md#任务列表与详情) · [CodeHub 范围证据](codehub/STATUS.md) | 独立用户特性，现有资料覆盖 CodeHub 来源及部分任务交互，通用任务旅程尚无完整定义和验证。 |
| 版本验收 | 围绕目标核对证据、记录人的判断并归档验收结果 | [验收规格](version-acceptance/spec.md) · [状态](version-acceptance/STATUS.md) | 会议流程与来源契约已有定义，入口和部分操作有真壳证据；完整会议至归档旅程未验证。 |
| 工程部署 | 查看被管项目的 CI 结果，部署并读回运行结果 | [验收中的出包入口](version-acceptance/spec.md) | 现有资料覆盖验收中的出包环节；独立的 CI 至部署定义及整段验证尚缺。 |
| 版本总览 | 回看本版目标、交付阶段及活动依据 | [版本总览规格](version-overview/spec.md) · [状态](version-overview/STATUS.md) | 历程与事实来源已有规格、实现及协议测试，交互和真实数据验证范围见状态。 |
| 指标能力 | 定义指标、采集历史值，并在总览和验收中读回 | [指标规格](overview-metrics/spec.md) · [指标六环状态](overview-metrics/STATUS.md#六环状态) | 历史采集和来源协议有定向验证；配置、采集、合入、采用及重启的完整旅程未验证。 |
| 内部集成 | 接通内部服务，使用 CodeHub 仓库与 WeLink 通信、发起评审 | [接入规格](connectors/spec.md)及[状态](connectors/STATUS.md) · [CodeHub 适配](codehub/intent.md)及[状态](codehub/STATUS.md) | 接入卡已有规格、实现和测试，完整登录旅程未验；CodeHub 有局部真壳证据。接入证据仅覆盖相应服务和动作。 |

侧栏统一规划归版本会话管理，包括原生项目与工作区区域的布局、置顶、展开收起、显示身份和归属。任务列表、详情和处理交互归任务管理，来源特有的接入与通信归内部集成。多人协作随用户结果归属：通过 WeLink 发起评审归内部集成，借助 WeLink 完成本版验收归版本验收。

## 特性之外的归属

| 主归属 | 适用范围 |
|---|---|
| 产品基础 | 跨旅程的通用产品体验，包括没有对应特性的 Orca 原生改造。原生改动若服务某一已有特性，直接归该特性。 |
| 研发保障 | BW 团队自身的开发、验证、上游升级与发布，包括 [PR 独立评审](reviewer-agent/STATUS.md)和 [BW 出包发布](workbench-release/STATUS.md)。 |
| 待定/预研 | 用户、独立结果或验收方式尚未明确的研究，如 AI 资产管理。专题结论明确后按用户结果定归属。 |
