# Intent · 帮助收成一张浮层面板

> **30 秒导读**:这是什么——把贴在屏幕右缘的两条竖排文字标签(「指南」「上报问题」)撤掉,帮助收成**一个入口一张小窗**:侧栏底部一颗「帮助」,点开在右下角浮起一个能拖的独立小窗,里面是本机环境 + 指南目录 + 上报表单三页。给谁看——过意图 gate 的人。现在作数吗——**谈定**(2026-09-08,发起人拿 Claude 桌面版的 Get help 做参照直接下达)。

**发起人**:产品会话 2026-09-08。**状态**:谈定,已落地待合入。

## 痛点

对着 Claude 桌面版的帮助面板看自己这一块,差的是五件事:

1. **入口贴在屏幕边上,还是两个**。`.guide-tab` / `.issue-tab` 用 `writing-mode: vertical-rl` 竖排中文贴右缘 —— 网页客服贴片的做法。两个并列还逼人先决定「我要指南还是要上报」,而人这时候只知道「我卡住了」。
2. **上报是居中弹窗**。为填一个标题把整屏压暗,重得不成比例。
3. **同一件事说三遍**。弹窗正文「默认会附上对照日志」+ 提示条「勾选后会随 issue 附上」+ 勾选项说明「有文件才附上」。
4. **有状态数据却没画**。工具探活(`Vm.env`)只出现在项目墙的环境条上;人是从帮助里找「我这儿是不是缺了什么」的,那里反而看不到。
5. **指南章节号收了不用**。`GuideNav::open(chapter)` 一直收着章节 id,抽屉却永远从第一章渲染 —— 项目墙「怎么处理 →」点进去也是从头翻。

## 解决方案(体验语言)

侧栏底部,「设置」上面一颗**帮助**。点开,**右下角**浮起一个独立小窗 —— 帮助窗都在那儿,而且**按住深色头能把它拖到任何地方**,挡住手上的活就挪开:

- 顶上一块深色头,一句「需要帮手?」。
- 压在它下缘的第一张卡是**本机环境**:一颗灯 + 「本机环境就绪」或「3 项工具没找到」,底下把没找到的名字念出来,不让人再去设置屏找一遍。
- 往下每条都是一行可点的卡:**上报问题**(带一句「建一条 issue 到 Workbench 仓,可带本机日志」)、**产品指南**的前四章,末行「全部 8 章」。
- 底部三个页签:主页 / 指南 / 上报。指南页是搜索框 + 全部章节;上报页是标题 + 一个勾选 + 一颗「发送报告」,**一件事只说一遍**。
- 点某一章 → 小窗收起,右侧宽抽屉打开并**直接翻到那一章**。小窗负责找,抽屉负责读:一份完整的产品指南塞不进 380px。

## 不做

- 不做小窗内读正文(指南是一份带自己侧栏的完整文档,窄面板读不了)。
- 不做全文检索(先按章节标题过滤;正文搜索等指南本身有索引再说)。
- 不做未读消息 / 会话列表那一栏(Claude 有「消息」是因为背后有客服;我们背后是 issue)。
- 不做缩放、不记住关掉时的位置到本机文件(拖到哪只活在这次运行里)。
