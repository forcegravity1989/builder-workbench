## 用户与问题

许多项目由一个人维护开发，需求、缺陷和日常工作已汇聚到 CodeHub Issue。原先独立的 DTS 和需求系统不再使用，信息来源更集中，项目管理要关心的目标、进展、风险、交付节点与责任仍然存在。

BW 的周五验收屏与会话一起服务材料准备、展示、逐目标核对和人的判断，是协作过程中的工作面。Builder 与 Leader 还需要一份收敛后的结果：不用重新进入会话、翻讨论和逐项展开过程材料，就能看全项目情况，并在之后回看当时依据与修订。现有验收纪要派生与只读预览可作为基础，但预览和复制本身不等于可独立查阅的报告归档。

## 价值与依据

核心收益是把已有周五材料自动提炼为可保留、独立阅读和追溯的报告。模型调用工具统计，按目标组织进展、风险和详细工作，渲染概要与完整正文；人只在缺失、歧义、失败或需要纠正时补充，并审阅结果。

用户提供的两份周报样例说明应保留完整项目管理关注点；最新澄清说明结果件需要独立查看。报告与周五屏内容重叠，是复用同一事实的不同用途：周五屏用于准备和协作，报告用于收敛阅读、汇报与历史回看。不另建一次周五执行流程，也不要求人在另一套管理表中重填已有内容。

## 目标体验

周五工作会话沿用项目方向、版本目标、Issue／MR、指标与交付材料，自动生成并保留报告草稿。草稿关联项目、统计周期、涉及版本和采用的材料修订；目标未达、材料待核或部分信息缺失也能如实生成，不等待所有工作完成。

Builder 或 Leader 从项目的报告归档查看概要，打开后阅读完整目标、关键进展、关键风险、子目标／需求详细进展、问题单进展与项目成员；节点、客户支撑和业务指标随实际材料出现。关键结论能查看来源正文、身份和取数时间。收起会话后，报告仍能独立阅读，不依赖聊天上下文才能理解。

需要补充时回到同一周五工作会话修订；自动处理不了的内容可以直接编辑兜底。保存修订保留人工身份与依据，并形成可回看的报告修订；重新生成保留人工补充，提示核对，不静默覆盖。历史报告保留当时采用的事实，不用最新 Issue 状态改写过去。读者可导出当前查看的报告修订为完整 HTML。

统计周期与版本分别标示：版本可跨周，同一周可涉及多个版本。报告引用既有目标与材料，不每周新建目标、验收轮次或重复完成记录。报告保存与内容审阅不替代人的目标验收、材料合入或发布决定。

## 范围与边界

- 覆盖已有周五材料的自动提炼、草稿保留、报告归档列表、独立完整阅读、历史修订、人工兜底与 HTML 导出；生产入口位置尚待确认，不预设新的管理台或全局导航。
- 报告同时提供概要与完整管理内容，包含证据／来源、统计范围、时区、取数时间和人工修订身份。核心关注点缺数据时显示 Unknown；可选节点和支撑按材料组织，不把逐栏手填设成生成前置条件。
- CodeHub Issue 仍是工作状态事实源，目标与人的验收结论仍在原有材料。报告是固定来源的汇总结果，不建立第二套工作状态、目标、需求或会议正文正本；报告编辑不顺带修改源记录。
- 复用 Orca 会话、已有周五准备／验收、工作树与文件／Git 能力；不另建会话、周期调度器或业务数据库。生产报告保存、发现与共享方式需后续确认，浏览器存储仅用于原型演示。
- 数字由工具根据可证明记录计算，模型组织和解释。缺失、取数不全、失败和零值分别呈现；没有风险记录不能写成“无风险”，无法证明达成不能写成已完成。
- 不自动关闭 Issue、合入 MR、确认目标达成、发布或发送报告。保存报告结果与原验收材料的评审合入分别成立，报告未核实内容保持可见标记。

## 成功判据与待决问题

Builder 能从已有材料得到一份完整、可追溯且保留的报告，正常路径无需逐栏搬运。Leader 在会话关闭后仍能独立找到报告、看全信息及依据；后续修订能回看原稿与人工修改，不把当前状态冒充历史。缺失或失败时可以继续处理，重新生成不丢人工输入，相同范围和来源的数字能独立重算。

本轮交付意图草案和可点击 MVP demo，供人判断结果件体验；真实会话与取数、生产入口、真实周期选择、报告文件／Git 存储、修订发现和共享权限均未锁定或未建。生产接线前须确认本篇与 [规格](spec.md)，并验证来源期间事件、分页和证据范围，不能以模拟通过宣称已交付。
