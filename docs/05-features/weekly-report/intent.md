# 项目周报：固定模板，自动提炼项目情况

> 给单人维护项目的 Builder、需要了解项目情况的 Leader 和产品评审者在判断价值与范围时读。本文只定义用户问题、价值、目标体验和边界；操作与异常见 [spec](spec.md)，原型及认可状态见 [STATUS](STATUS.md)。按用户与问题、价值与依据、目标体验、范围与边界、成功判据组织；用户价值或边界变化时更新，产品主张以 [原则 03](../../01-principles/03-press-release-faq-flywheel.md) 为准，开发准备与验收读 [版本验收](../version-acceptance/spec.md)，不追加讨论流水。

## 用户与问题

许多项目由一个人维护开发，需求、缺陷和日常工作已汇聚到 CodeHub Issue。原先独立的 DTS 和需求系统不再使用，信息来源更集中，项目管理仍需要了解目标、关键进展、关键风险、需求和问题的推进情况以及责任人。

周五屏服务开发过程中的材料准备与核对，周报也是项目过程中的管理视图，是把分散信息提炼出来、让人了解项目情况的地方。Builder 和 Leader 希望打开就看到内容，不用翻会话或先理解生成步骤、来源清单、取数过程和归档规则。保留报告便于之后回看，阅读重点始终是当期项目情况。

## 价值与依据

沿用团队日常使用的周报模板和配色，让大模型会话自动统计、提炼并填入熟悉的栏目。模板稳定，项目的目标、行项、进展、风险和可选节点随工作变化；人不必每周重新搬运信息和排版。信息缺失、歧义、失败或需要纠正时，人再补充并审阅。

用户提供的两份日常周报样例是模板依据，固定栏目以用户指定的目标、关键进展、关键风险、可选里程碑、子目标／需求详细进展、问题单进展和项目成员为准，列适配当前 CodeHub 项目，不声称两份原版都含相同七栏或逐字复刻。本推理项目沿用 PT 的紫色标题、淡紫表头；改进 HTML 的阅读与导出体验，不让每个项目生成另一种报告结构。

## 目标体验

Builder 打开项目周报，选定周期和版本，直接阅读按固定模板呈现的项目情况。版本只是简洁的关联范围，不要求读者理解材料轮次、修订编号或归档状态。

点击更新，会话利用已有目标、周五工作材料、CodeHub Issue／MR 和可靠指标，自动统计并提炼本期信息，更新相应栏目；目标未达或材料不全也可以如实呈现。报告固定展示目标、关键进展、关键风险、需求详细进展、问题单与成员，确有节点时展示里程碑。项目内容变化体现在条目、文本和数值中，栏目及表格列保持稳定。

需要补充时，Builder 说清要补充或修正的内容，或者直接编辑兜底。已有人工输入在再次更新时保留；信息不足处说明未知，失败时旧内容不丢，可重试或继续补充。读者可留存和回看周报，也可导出同样模板与配色的完整 HTML；主界面专注内容，不铺操作流程和技术说明。

## 范围与边界

- 覆盖固定模板阅读、周期与简洁版本选择、会话自动更新、人工补充和 HTML 导出；可留存回看，保存与历史机制不占据主内容区。
- 模板固定管理栏目及详细表格列，采用原样例配色；按项目工作增减内容行，可选里程碑按实际材料出现。单人项目的成员责任简洁呈现，有协作再展开。
- 复用既有目标、周五材料和 CodeHub 工作记录，不重复填写、不另建开发或验收流程。Issue 状态、目标和人的验收结论仍由原正本承载，周报是提炼呈现它们的管理视图。
- 自动渲染为正常路径，手动补充仅用于缺失、歧义、失败或纠正；更新保护人工输入，不顺带修改源记录。缺数据保持未知，不能写成零、无风险或已完成。
- 统计由工具基于可证明记录计算，模型负责提炼和填充固定模板。报告阅读不要求用户理解来源流水或技术协议；必要追溯信息在内部保留，不作为主界面栏目。
- 内容审阅、保存和导出不自动关闭 Issue、合入 MR、确认目标达成、发布或发送周报。真实接线与原型范围见 [STATUS](STATUS.md)。

## 成功判据与待决问题

Builder 无需逐栏搬运就能获得熟悉、完整的周报；Leader 打开即能理解目标推进、关键进展与风险，详细需求、问题和成员可以直接查阅。不同周期或版本使用同一模板，人工补充和失败不会导致旧内容丢失，导出仍保持完整且易读。

本轮依据上述方向修订意图与规格，整篇待人审；模板细则及精简操作见 [规格](spec.md)。真实周期、来源取数、会话接线和留存协议随认可后的实现设计确认；本篇不把设计原型当成生产运行事实。
