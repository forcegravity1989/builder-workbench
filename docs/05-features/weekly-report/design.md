# 项目周报 — 原生项目会话与文件呈现

> 给实现、评审与接手者读；定义周报的项目身份、文件协议、自动更新与人工保护取舍，接口或数据流改变时更新。用户价值与行为见 [intent](intent.md)、[spec](spec.md)，运行证据见 [STATUS](STATUS.md)。整体定位沿 [architecture](../../architecture.md) 的项目概况、事实层与会话执行层；不新增开发或验收流程。

## 项目与执行宿主

周报入口复用原生 activity 页面槽位；项目来自当前选中仓库，宿主来自其唯一原生主工作树。报告读取与写入固定在同项目、同宿主的 `bw/weekly-report` 工作树。打开仅阅读已有文件，更新或首份人工补充时才通过既有 `ensureNamedWorktree` 准备工作树；外部已建树沿原生收件箱导入，不新造同分支副本。选中项目、执行宿主或登记改变时停止操作。

文件通过既有 runtime-file-client 读取、列目录、写入和重命名，绑定工作树自身的 runtime／SSH 身份与连接代次，不跟随另一项目的活动 runtime。读取时核对报告的 canonical repository 与当前项目，错配或无效文件报错并保留之前内容，不混入其他项目。

## 报告协议与模板

单份 [weekly-report.ts](../../../src/shared/workbench/weekly-report.ts) 定义七栏固定列、日期算法与严格 JSON 协议。记录包含项目、周期排他结束边界、关联软件版本、生成时间、七栏纯文本表格、问题摘要、内部来源和人工内容；未定义里程碑为空，缺信息为未知。报告业务正本仍是原 Issue、计划、验收和可靠指标。

每个记录新增到 `.bw/weekly-reports/<开始日期>/<UUID>.json`，不另存索引、当前副本或数据库。报告版本从文件重算，以生成时间和稳定路径排序；保存前后核对同周期基线，发现竞争写入撤回本次追加、保留输入。写入先用非候选临时文件，重命名后独立读回；异常独立核对并撤回本次 UUID 的临时与正式路径，无法核对时明确提示结果未确认；这复用通用文件接口的乐观检查，不声称具有版本材料服务的跨进程事务锁。

人工版本标记 `origin=manual`。按时间读取时，把最近人工版本的 manual 沿用到之后的自动报告；即使模型遗漏该字段，人工修订仍有效，旧版本保持当时内容。空 manual 的人工版本代表显式删除，不能复活之前补充。编辑器保存冲突后读取最新基线、保留输入，由人再次保存。

页面、空报告和导出都调用 [同一 renderer](../../../src/shared/workbench/weekly-report-format.ts)，先转义全部外来文本；来源和人工标记留在 JSON，不铺进正文。完整 HTML 仅含报告正文与同一主题。真实 GitHub demo 由 [构建脚本](../../../config/scripts/build-weekly-report-demo.mjs) 从钉住取数时间的已核验材料生成，不运行模拟更新。

## 自动提炼

“更新周报”复用原生 `launchAgentInNewTab`、本机工具选择、工作树选择与 prompt delivery，进入该项目真实会话；不创建新自动化或扩计划／验收 workflow。提示使用同一 SYSTEM 模板，携带项目、周期、时区、唯一报告路径及固定列协议，指示会话完整分页取数、保留关闭原因与实际窗口，读取最新人工内容并写后读回。

模型提炼本期方向和关键变化，数字由实际工具记录计算。历史峰值、当前验收窗口和项目纳入数分别陈述；当前快照不能写成历史期末量。提示发送失败如实反馈；输入已接受或 turn 已开始均不证明报告完成。当前周报树加入 Orca 唯一应用级文件监听，按目录与宿主合并去重，沿用统一生命周期，不与编辑器争抢 watch/unwatch。返回报告页面或文件事件触发重新读取，只有有效新文件才成为可阅读版本。

## 验证边界

协议、日期与文本安全由少量 shared 测试看护；UI 不新增组件单测，主旅程登记 [WJ01](../../../tests/e2e/workbench-weekly-report.spec.ts)，经隔离 Electron、真实 GitHub 仓库和实际文件读写核对。隔离测试不带用户工具登录，不能冒称已验证模型完成；安装应用的真实会话与文件生成结果另行独立读回，实际状态统一进入 STATUS 与 PR 验证报告。
