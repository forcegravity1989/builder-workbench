# 项目周报：固定模板与内容更新

> 给交互设计、实现、评审与验收者读。本文定义固定模板、精简操作、行为和异常及验收判据；用户价值见 [intent](intent.md)，原型、认可与未集成范围见 [STATUS](STATUS.md)。开发准备和验收读 [版本验收规格](../version-acceptance/spec.md)，材料写入权限读 [版本材料契约](../../../standard/system-prompt/references/version-records.md)。行为或验收变化时更新，工程接线进入实现设计，不维护执行流水。

## 范围与入口

项目周报是项目过程中的管理视图，由会话提炼、更新已有项目情况，可以留存回看。打开即可阅读完整周报；主界面只保留周期、简洁版本选择和“更新周报”“补充或修正”“导出”操作。版本只说明本期关联范围，周与版本分别成立，同一版本可跨周，不另建目标或验收轮次。

周报利用项目目标、周五开发材料、CodeHub Issue／MR 和可靠指标，保持正常路径自动渲染，人工只兜底缺失、歧义、失败和纠正。页面以内容为主，不铺生成步骤、来源清单、取数时间、修订身份、档案卡片或原型帮助说明；确有失败或缺口时，在相关位置给出必要短提示。

## 固定模板

栏目顺序和表格列固定，项目变化体现在内容、行项与数值中；更新不能重新发明模板。以下七栏来自用户指定的管理关注点。两份原样例的栏目和细节并不相同，本表保留其管理骨架并适配当前 CodeHub 项目，不声称逐字复刻或恢复旧 SR／DTS 系统。

| 栏目 | 固定列 | 内容规则 |
|---|---|---|
| 目标 | 目标／交付要求／计划完成／当前情况 | 沿用已有目标与约定，说明实际推进；未验收不能写成达成 |
| 关键进展 | 工作方向／关键进展／下周计划 | 提炼本期关键变化和后续安排，不重复堆 Issue 列表 |
| 关键风险 | 风险等级／风险描述／应对措施／责任人／计划关闭／状态 | 说明影响和处理，缺风险信息显示未知；不能默认“无风险” |
| 里程碑 | 节点／计划完成／达成条件／当前情况 | 内容可选，有已定义节点才填；没有定义时保留栏目骨架及短空值，不自造节点 |
| 子目标／需求详细进展 | 子目标／任务／计划完成／责任人／状态／本周进展 | 按子目标组织 CodeHub 需求与工作，保留真实状态及本期推进 |
| 问题单进展 | 问题／状态／责任人／处理进展／下一步 | 汇总明确的问题 Issue；同栏提供本期新增、关闭、未关闭数字及详细行 |
| 项目成员 | 姓名／角色／负责范围 | 呈现真实责任，单人项目简洁显示维护者，不猜工号或部门 |

本推理项目采用 PT 样例的紫色风格：主标题与节标题背景 `#785ED8`、白字；表头 `#EEDEEE`、黑字；白色明细底、黑色表格边框、微软雅黑。风险需要强调时沿用红色 `#C00000`，不把 AIops 的蓝色／桃色混入此模板，也不以绿色装饰代替真实状态。

HTML 可以改善字号、间距、长文本换行和窄屏阅读，但保持连续周报表格及固定栏目，不能改成卡片仪表盘。原型的 [data.js](prototype/data.js) 用单份 `weeklyTemplate` 承载列定义；主屏和导出调用同一正文 renderer，导出复用同一报告主题，不分别维护两套模板或颜色。

## 完整用户旅程

1. Builder 或 Leader 打开项目周报，选择周期和版本，直接阅读七栏内容；切换范围后显示对应内容，不混入其他周期的人工补充。
2. Builder 点击更新周报，会话自动统计和提炼现有材料，填入同一模板；更新期间旧内容可读，失败保留当前周报，并提供重试或补充。
3. 需要补充时点击补充或修正，提交背景、风险判断或明确修正，必要时直接编辑兜底。内容写入对应栏目，已有人工输入在再次更新时保留。
4. 阅读与审阅后导出完整 HTML，保持当前周期、版本、七栏内容及模板配色；保留周报供之后回看，不要求用户先完成归档流程或了解保存协议。

## 行为规则与异常

### 信息提炼与真实状态

同一事实可被摘要和详细行引用，不创建重复工作或完成记录。需求／缺陷分类沿用项目既有标题和协议，不能把所有 Issue 当问题单，不增加 kind、tool、workflow 标签。Issue 状态和目标验收仍由原正本承载，周报更新、补充和导出不改变它们。

数字由工具根据可证明记录计算，模型负责提炼与填表。内部保留统计范围、来源及人工修正信息以便核对；这些信息不组成周报主界面的另一块说明区。期间新增／关闭需对应事件，期末量需可证明状态，当前快照不能猜历史；部分分页或记录不足时相关数字未知，不用零代替。平台合入证据不足仍遵守 [CodeHub 规格](../codehub/spec.md)。

人工补充在内部保留其作用范围、身份和时间，不冒充平台事实。更新保护人工输入，显式修正仍保留，不能静默覆盖；需要核对的信息保留在内部记录或编辑器，不在周报正文添加“人工修正”“待核对”等操作注释。正文继续呈现真实的未知、待验收或阻塞等业务状态。不宣称模型已经识别自然语言语义冲突，补充报告不顺带修改 CodeHub 或签署目标验收。

| 情况 | 内容与继续方式 |
|---|---|
| 目标、风险或验证信息不足 | 对应内容说明未知／待核，已有内容继续展示，不造目标、绿灯或完成结论 |
| 无可选节点 | 固定里程碑栏目保持，显示短空值，不自动编造节点 |
| 更新失败或取数不全 | 保留当前周报及人工输入，失败短提示并可重试／补充；未证明数字未知 |
| 留存失败 | 保留当前页输入，简短说明尚未保存并可重试，不冒称成功 |
| 人工补充后再次更新 | 人工内容仍在，核对信息只进入内部记录或编辑器，正文只展示内容与业务状态 |

### 留存、导出与权限

周报可以留存回看；历史内容保持当时记录，不用最新 Issue 状态改写过去。具体生产保存与发现协议进入实现设计，复用文件／Git 和既有会话能力，不另造数据库、平行扫描或周期执行流程。保存周报不等于验收材料经 PR／MR 合入。

导出当前阅读范围的完整 HTML，正文与页面共用模板和配色，含标题、周期、简洁版本及完整七栏内容；无需外链脚本或样式即可阅读。导出不追加来源流水、取数过程或档案说明，不自动发送，不关闭 Issue、合入 MR、确认目标达成或发布。

## 验收与衡量

| 标识 | 场景 | 可观察结果 |
|---|---|---|
| W01 | 打开及更新周报 | 七栏及固定列完整，PT 紫色表格模板稳定；直接阅读内容，无生成／来源／档案说明区 |
| W02 | 选择周期和版本后更新 | 显示对应项目情况，简洁版本保持；内容改变，模板不变，不新造目标或验收轮次 |
| W03 | 补充、再次更新或失败 | 人工内容保留，缺数据未知；失败不丢当前周报，可重试或手动兜底 |
| W04 | 导出当前周报 | HTML 独立可读，周期／版本及七栏内容与页面一致，使用同一模板配色，无流程说明附录 |

主旅程 WJ01：选择周期和版本 → 阅读 → 更新周报 → 补充或修正 → 再次更新仍保留人工内容 → 导出完整 HTML。价值观察关注是否减少逐栏搬运、读者能否直接理解目标推进和风险、固定模板是否便于比较各期、补充与失败是否可以继续处理。原型验证范围和真实接线缺口统一见 [STATUS](STATUS.md)。
