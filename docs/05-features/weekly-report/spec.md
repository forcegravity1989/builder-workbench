## 范围与复用

报告是已有周五准备与验收过程的结果件。复用会话、计划／验收材料、目标、Issue／MR 和指标；不新增一次周五执行流程，不新增另一套工作管理台。现行验收纪要已从明确材料修订派生，并有只读预览／复制；本设计补足自动收敛、结果保留、独立查看及报告修订回看，不以报告保存替代验收结论或源材料合入。

每份报告关联项目、统计周期、涉及版本和采用的来源修订。版本与自然周分别成立；同一版本跨周不改变原材料 cycleId，不补造每周验收快照。报告修订不是验收轮次、会话运行或归档提交。未达、待核或尚未合入的材料也能生成草稿，显式说明来源状态。

demo 采用固定示例周期 2026-10-05 至 2026-10-09，并切换材料齐全、缺验证／风险、生成失败等场景；保留自动生成、依据、人工补充与显式修正、重生成核对和导出体验。原型借用“知识库”作为暂定报告查看入口，生产位置待产品确认；周五工作区来源可参看 [验收原型](../version-acceptance/prototype.html)。真实选周期、期间历史与部分分页读取、客户／局点支撑、真实会话尚未接线。原型不声称模型能识别自然语言语义冲突，只演示显式人工修正和重新生成后的核对提示。生产报告存储与发现协议待确认。

## 完整用户旅程

1. Builder 在既有周五工作会话准备材料，确认项目与统计范围，沿用已确认目标、版本和来源修订，不在另一套报告表中重填。首次材料不足也能开始，不自造已确认目标。
2. 会话自动取数、统计和提炼，生成概要与完整正文，并保留报告草稿。界面说明报告范围、来源、取数时间与缺口；生成失败不将旧报告替换为空白，也不要求目标全部完成。
3. Builder 或 Leader 打开项目报告归档列表，按项目、统计周期和版本找到报告及修订，打开只读结果；概要便于快速了解情况，完整正文与依据无需进入会话即可阅读。收起会话后仍能打开报告和历史修订；单纯查看不启动会话或重新取数。
4. 需要补充时返回同一周五工作会话修订，自动处理不了时直接编辑兜底。保存修改形成报告修订，保留人工身份与依据，不改写原报告或源材料状态。
5. 再次生成更新自动内容，保留人工补充并提示核对。读者可回看此前修订的完整内容与当时来源，导出当前查看的修订；保存、审阅或导出不触发 Issue 完成、目标验收或材料合入。

## 行为规则与异常

### 内容、来源与统计

概要提炼目标推进、关键进展、风险和下一步；完整正文保留目标、关键进展、关键风险、子目标／需求详细进展、问题单进展和项目成员。里程碑、客户支撑及特殊指标有材料时出现。核心内容缺数据说明 Unknown；可选内容区分不适用、未发现记录和读取失败。

每份报告保存采用的来源正文或可独立阅读的证据摘要，以及原始身份／链接、来源状态、材料修订、统计范围与时区、生成／取数时间、人工修订身份。不能只放会话链接要求读者回到聊天理解结论；模拟材料与模拟取数必须明确标为示例。单人项目成员简洁显示真实责任，有协作再展开，不猜人员身份。

同一 Issue 可被多个栏目引用，不创建重复工作或完成记录。需求／缺陷分类沿用既有标题和协议，不增加 kind、tool、workflow 标签，不能把所有 Issue 都当问题单。目标结论引用原材料中人的确认，不由关闭数或报告文案推断达成；人工修订报告不改源目标、Issue 或验收结论。

统计采用起始日零点至结束日次日零点的半开窗口。新增／关闭来自期间事件，期末开放量需可证明期末状态；去重口径明确，不将关闭事件数混称为关闭问题数。当前快照不冒充期间历史；未读全分页或范围不完整，总量保持未知，可展示明确范围的已读数量。数字由工具计算，模型筛选重点和解释；[CodeHub 规格](../codehub/spec.md) 无法读回的合入证明保持未知，不以 Git 可达性替代平台合入。

### 报告保留、归档查看与修订

本设计的报告归档指保留可回看的报告结果，不等同于源验收材料经 PR／MR 合入。报告显式显示草稿、待核及来源状态，缺口不阻止如实保留与阅读。历史修订保留当时内容、来源与人工修改，不用实时 Issue 状态重写历史。

生成与修改保存后，结果可从项目报告归档独立发现；关闭或收起会话不删除已保留结果。查看旧修订不改变当前报告或工作状态。源材料修订和报告修订分别标示，重生成产生新结果，不悄悄替换读者正在查看的历史。

生产保存位置、文件／Git 协议、修订发现、并发和共享权限待实现设计确认，复用既有材料发现能力，不另造数据库或平行 Git 扫描。demo 的浏览器存储仅是模拟结果保留；不能以本地浏览器操作证明生产持久化、跨机访问或重启后真实读回。保存失败显示原因并保留输入，不能宣称已归档。

### 人工兜底与重新生成

人工补充用于缺失背景、风险判断和修正，保留补充者、作用范围、依据和人工身份；不能包装成平台读回事实。源记录的修改遵循原有授权与流程，不在报告生成时顺带执行。

重新生成只更新自动部分，保留人工输入；明确删除人工内容才可移除。显式修正继续保留，重新生成后提示人核对再确认本份报告；不声称已自动识别自然语言冲突。报告审阅只确认本份内容，不能代签源验收。

| 情况 | 可见结果与继续方式 |
|---|---|
| 缺目标、风险或验证材料 | 定位缺口，相关结论 Unknown；已有工作仍可整理，不造目标、绿灯或“无风险” |
| 部分读取失败、分页或期间历史不足 | 标明范围不完整，受影响总量未知；保留可靠事实，可补充或重试 |
| 全部生成失败 | 保留旧报告与人工输入，提供重试；首次可继续手动草稿，不能标成已自动取数 |
| 重新生成且含人工修正 | 保留人工内容并提示核对；旧修订仍可查看，不静默覆盖 |
| 保存失败 | 明确结果尚未保留，保留输入并可重试，不给出已归档假象 |
| 目标未达、材料待核或未合入 | 可保留报告草稿并显示来源状态，报告不代替人的验收或合入 |
| 收起会话或查看旧修订 | 归档结果与完整来源仍可读取，不启动新会话或取最新状态覆盖历史 |

### 导出与权限

导出当前查看的报告修订为独立 HTML，包含概要、完整管理内容、证据正文及身份、范围、时区、生成／取数时间、人工修订与缺口标记；无需外链脚本或样式。允许导出未确认草稿，不能把下载等同于审阅通过。导出由人触发，不自动发送，不关闭 Issue、合入 MR、确认目标达成或发布。

## 验收与衡量

以下是目标行为；demo 只能验证模拟交互，生产取数、真实会话与报告文件／Git 独立读回须以后续 E2E 证明。

| 标识 | 场景 | 可观察结果 |
|---|---|---|
| W01 | 周五材料齐全，自动生成 | 无逐栏填写即可获得概要与完整管理内容及证据，草稿被保留 |
| W02 | 周期、版本与材料变化 | 周与版本分别标示，目标仍引用原身份，可选节点随材料出现，不新建验收轮次 |
| W03 | 缺目标、风险证据或期间历史 | 定位缺口，相关结论／统计 Unknown，不制造目标、绿灯或历史 |
| W04 | 补充、保存修订后重新生成 | 保留人工身份和输入，生成后待核对；历史修订可按当时内容与来源回看 |
| W05 | 读取或生成失败 | 保留旧报告与补充，可重试或手动草稿；未证明总量 Unknown |
| W06 | 导出含人工补充或缺口的选定修订 | HTML 独立可读，含概要、完整正文、范围、来源和人工身份，不改变源状态 |
| W07 | 收起会话后重新查看归档 | 能找到报告列表、只读结果及历史修订，读取完整信息，不重开会话或重取事实 |

主旅程 WJ01：周五会话准备材料 → 自动生成并保留草稿 → 收起会话 → 报告归档独立阅读及查依据 → 返回会话补充或直接编辑并保存修订 → 再收起会话回看历史 → 导出选定修订。异常旅程 WJ02：生成失败 → 保留旧报告／首次手动草稿 → 补充或重试并保存 → 收起会话独立阅读带缺口的结果。demo 周期固定；真实来源、生产存储与完整旅程保持未建，模拟通过不等于真实 E2E。

价值观察关注是否减少搬运、是否无需翻会话就能看全信息、结果与历史是否可找到、结论是否能核对及缺口是否能继续处理，不预填效率比例或健康评分。

## 取舍与待决问题

过程与结果分别服务协作与阅读，复用同一事实；保留独立结果查看，不新增重复执行或验收步骤。固定管理关注点保证完整，动态组织适应项目，不恢复 DTS、独立需求系统或成员协同套件。

生产入口位置、文件／Git 保存与发现协议、真实统计周期及期间事件／分页能力、与会话和工作区的接线尚未确认或未实现。意图与规格经人认可后定义实现设计；不以浏览器存储预定生产方案，不假定新的全局调度时间。
