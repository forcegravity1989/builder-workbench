# 项目周报 — 六环状态

> 给接手、评审与验收的人读。本文只记录制品认可、当前链状态、验收与旅程证据及缺口；有真实认可、实现或验证时更新。价值见 [intent](intent.md)，行为和模板正本见 [spec](spec.md)，格式正本为 [原则 02](../../01-principles/02-working-backwards.md#62-六环交付链)。原型身份与证据边界写在此处，不铺在周报主界面，不维护讨论或验证流水。

## 当前认可与边界

用户已认可固定模板风格，并明确选择在 Orca 项目内接入真实周报入口、读取与更新操作。周报是项目过程中的信息提炼视图，采用自动渲染、手动兜底；周五屏仍服务开发准备和核对。既有目标、Issue 与验收正本不变。

模板依据为用户提供的 PT 推理与 AIops HTML 周报，七栏及配色规则见 [规格](spec.md)。当前固定采用 PT 紫色标题、淡紫表头和黑色边框；页面、空报告、导出和 [真实内容 demo](prototype.html) 使用同一份列定义、正文 renderer 与主题。

Demo 已替换为 forcegravity1989/builder-workbench 在 2026-10-10 的真实 GitHub 取数快照，来源与原始字段保存在 [github-report.json](prototype/github-report.json)，规范化报告见 [weekly-report.json](prototype/weekly-report.json)。它是指定时刻的报告示例，不会自行更新。取消的 Issue 呈现“不再计划”，目标达成只引用人的验收；项目纳入数量不冒充周活跃指标，未定义里程碑不编造。

源码已接项目“周报”入口、独立 bw/weekly-report 工作树、所属宿主的原生文件读取、原生会话更新、人工修订和 HTML 导出，设计见 [design](design.md)。报告按周期追加不可变 JSON；人工内容在后续生成遗漏时仍保留。冲突保留输入，读取新基线后由人明确再次保存。它是乐观冲突检查，不能冒称跨进程事务锁。本地保存不等于经 PR/MR 归档。

“更新周报”已改为 Agent 驱动 [weekly-report Skill](../../../standard/skills/weekly-report/SKILL.md)。入口传入真实宿主上下文、周期和固定输出结构；正文、提炼参考与保存协议通过 Orca 原生指南按需读取。2026-10-12 新构建 CLI 的正文及参考读取通过，相关四文件 25 项检查通过（另有两项既有跳过）。独立 Agent 使用上述 2026-10-10 真实快照试跑，完成取事实、提炼七栏、新 UUID 报告保存及严格校验读回；未将不再计划计为完成、未由作者推导负责人、未编造里程碑。同日以 BW 构建配置重跑 WJ01，通过真实仓库、人工版本、冲突恢复、历史和进程重启读回；CLI 及 Electron 构建、构建产物闭包核对通过。Skill 快照试跑没有历史人工记录，未实测 Skill 执行中的人工继承及并发保护；固定快照也不证明实时取数、完整远端分页或安装版配置模型已完成生成。

当前安装应用独立核对已纳入 builder-workbench、axodendron、gtsllm-dfx、benchmark 四个项目。原生工作树清单已登记真实周报工作树，真实报告文件已落盘，原生浏览器页已读回正确文件标题与无加载错误。安装版尚不含本分支新增导航；不能把安装版 HTML 预览说成已部署的新周报入口。
