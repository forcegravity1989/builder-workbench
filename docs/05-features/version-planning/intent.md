# 版本计划

> 给 Builder、Leader 和产品评审者阅读。本文只说明用户结果、价值和范围。行为与验收见 [spec](spec.md)，实现边界见 [design](design.md)，证据状态见 [STATUS](STATUS.md)。产品价值或范围改变时更新，不写实现流水。

## 用户与问题

Builder 需要把场外要求、项目现状和自己的判断组织成一个版本目标。Leader 需要快速理解准备交付什么、为什么值得做，以及之后怎样核对结果。目标、任务、会议材料和聊天记录分散时，用户需要重复搬运内容，模型也可能把仓内不完整信息当成完整事实。

## 价值与依据

版本计划在一个可编辑、可讨论、可评审的工作面上形成版本承诺，让目标、验收标准、任务和会议结论能够沿同一版本读回。价值依据包括 [Issue #257](https://github.com/forcegravity1989/builder-workbench/issues/257)、[Issue #249](https://github.com/forcegravity1989/builder-workbench/issues/249) 和版本规划原型评审。自动化接线属于本特性的支撑能力，相关背景见 [Issue #252](https://github.com/forcegravity1989/builder-workbench/issues/252)。

## 目标体验

用户从侧栏进入“计划”。计划尚未开始时看到开始卡，原生计划会话实际打开后进入四个区域。

- 计划准备展示固定来源的上版延期遗留和会议遗留。
- 本版目标支持结果目标、验收标准、可选指标承诺和真实 Issue 关联。
- 会议纪要接收板面批注和可选转写稿，整理为“共识”和“遗留”，由人确认后生效。
- 归档区域显示真实 PR 或 MR 引用和状态，并回到 Orca 原生评审入口。

计划助手沿用 Orca 原生会话、历史、工具和权限。目标讨论、任务拆解、会议纪要和归档均通过该会话完成。模型提出建议，人确认目标范围、纪要和归档结果。

## 范围与边界

包含单页版本计划、目标编辑、指标承诺入口、任务关联与详情往返、固定上版回顾、批注与会议纪要、草稿恢复、归档状态、原生自动化入口和会话历史复用。

不重建 Orca 会话、任务编辑器、调度器或发布链。不新增共同编辑服务，不自动合入 PR，不自动关闭或确认 Issue。指标定义、采集和读数由 [总览指标](../overview-metrics/intent.md) 负责，验收结论由 [版本验收](../version-acceptance/intent.md) 负责。

## 成功判据与未决问题

用户可以从真实要求形成一份版本目标，与 Leader 评审并读回同一份计划、任务关联、纪要和归档状态。重启或重新进入后，材料仍按版本和固定工作树独立读回。成功不以字段填满或 Issue 关闭数量衡量。

会议服务能否自动取得 Leader 群组或 WeLink 的会议 ID仍待用户组旅程确认。没有可靠指标读数时继续显示未知，不能把目标草案当作已承诺结果。
