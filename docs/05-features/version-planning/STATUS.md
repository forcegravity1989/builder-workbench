# 版本计划 — 六环状态

> 给接手开发、评审和验收的人读取。只记录认可、实现和证据缺口；有真实认可或运行结果时更新。价值见 [intent](intent.md)，行为见 [spec](spec.md)，工程设计见 [design](design.md)。

目标平台为主干 main 的 Electron/Orca 叠层。计划与验收统一目标卡、完整原生会话工作区、会话栏收折及紧凑指标的形态已经用户确认；[高保真](prototype.html) 是形态依据，不是持久化或真实宿主执行证据。

## 当前实现与证据边界

计划屏在同一页展示版本进展、风险与 Top 3 目标。目标直接编辑并自动保存，计划完成/负责人使用紧凑字段；指标从目录添加、按名称防止重复承诺，旧定义明确提示更新，不将仍存在的指标误判为删除。目标卡与验收共用 VersionGoalCard，卡片开合按项目、版本和屏保留。Issue 在目标卡内按 Bug、Feature、未分类展示，详情复用原生入口，拆解由会话按人的选择执行。

版本进展使用明确选定的固定验收来源，可为同版本上周或上一版本。“查看验收依据”定位到相同来源的只读整页，纪要与验收屏共用证据新鲜度计算；读取失败不改读最新材料。已确认且标为“纳入下周计划”的会议指导进入周一候选，由人决定是否进入 Top 3。

计划与验收使用各自固定工作树和原生自动化。进屏先回显已有数据，不自动同步 Git；“更新代码”是显式同步入口。归档由会话提 PR/MR，状态行从 provider 读回真实状态，读不到保持 Unknown。归档和目标完成是不同事实，完成仍由人确认。

普通新建会话不额外注入 BW Skill；专用入口使用已登记自动化，BW 提示词与 Skill 投影同步、人的时间/模型/复用设置保留。材料修订冲突保留输入，不覆盖另一个会话的更新。没有独立计划确认门槛、贴草稿等待框、全量任务区或第二套会话实现。

本轮通过本地材料/指标/报告协议测试、类型与静态检查、生成物一致性检查；原型三个入口通过模拟 DOM 启动。用户明确不运行 CI 和真壳，本地替身及原型证据不能证明实际 Electron 视觉、远端往返、模型遵从或重启体验。

## G2 候选原型的证据边界

[高保真修订 6](version-workspace-prototype.html?rev=6) 与 [旅程报告](version-workspace-journey.html) 供内部评审。已确认多版本并行、版本平铺回看、逻辑目标目录、目标工作树按需创建、原生创建器与工作区复用、不新增冻结操作、版本下方统一保留当前项目与私人项目的原生工作区入口。候选在新建版本时准备计划/验收两树，侧栏入口合并流程树；原型按整屏标注计划/验收复用，目标仅筛选同一任务屏。初始 v0.7/v0.6，新增版本由用户创建。完整 spec 与生产接线仍待评审反馈。

本轮修改设计资料与原型，未改 Electron 生产代码、真实工作树、自动化或会话记录。项目总览及其他既有屏幕仅标复用位置；删除 G2 中重复的项目总览和任务屏复刻文件。所有新建、父树选择及会话均为内存演示，刷新清空。新增图标操作与顶部业界依据，官方案例与采用边界见 spec，不把参考当实现证据。

修订 6 的浏览器检查及提交前门禁结果留在 PR 验证记录。未验证 Electron 真壳、共享宿主、实际工作树创建与恢复、provider 写回、原生会话历史和旧共享树迁移；前版浏览器结果不能证明本版生产接线。
