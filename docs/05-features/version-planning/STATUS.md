## 当前实现与证据边界

计划屏为 G3 四区单页：页头（面包屑选版、保存状态、会话收折 chip、分支名、更新代码、配置自动化、批注模式）、顶部 4 分区导航（无灯）、上版回顾（固定来源延期遗留 / 会议遗留两行）、本版目标（G3 目标卡：行内编辑、就近删除二次确认、整卡删除级联移出 tasks 与批注、Issue 平铺 + Bug/Feature 角标 + 开工箭头临时开原生详情）、会议纪要（材料 minutes 节 + 人工确认 / 闭环）、归档 PR（真实合入状态 + 打开 Orca 原生 PR 页）。指标承诺形态换装、行为链不变（目录选取、按名防重、旧定义提示更新）。VersionGoalCard 收敛为验收只读骨架。对象级动作与批注发送经原生发送弹窗；空板「与计划助手新建计划」是计划屏唯一会话发起入口。

上版回顾按 summary.progressSource 固定来源读取并核验身份，映射 carry 标记与 confirmed+next-week-plan 指导为两行；延期遗留三态：有标记无 carry=「上版无延期 Issue」、验收未记录任何 issueMarks=Unknown 文案 + 实时读回参考行（2026-10-22 轮，v0.6 即此态）、读取失败如实报错不改读。「打开验收屏」定位同源只读整页。总览计划列直读存储纪要，无存储纪要的历史版本如实显示「纪要未记录」（D10，历史版本可见变化已在 PR 说明）。已确认且标为“纳入下周计划”的会议指导进入周一候选，由人决定是否进入 Top 3（验收侧不变）。

计划与验收使用各自固定工作树和原生自动化。进屏先回显已有数据，不自动同步 Git；“更新代码”是显式同步入口。归档由会话提 PR/MR，状态行从 provider 读回真实状态，读不到保持 Unknown。归档和目标完成是不同事实，完成仍由人确认。

普通新建会话不额外注入 BW Skill；专用入口使用已登记自动化，BW 提示词与 Skill 投影同步、人的时间/模型/复用设置保留。材料修订冲突保留输入，不覆盖另一个会话的更新。没有独立计划确认门槛、贴草稿等待框、全量任务区或第二套会话实现。

本轮通过类型与静态检查、lint-staged、生成物一致性（build-g3.cjs --check）、ratchet 持平（226）；dev profile 真壳按验收点矩阵与截图四件套验证，含杀进程重启后材料 / 纪要 / 确认状态独立读回一致、批注按设计清空。CI、真实模型会话、自动化到点触发、CodeHub MR 与 824 窄板未在本轮执行。
