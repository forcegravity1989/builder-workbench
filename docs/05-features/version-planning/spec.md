### Builder 主旅程

1. **计划准备（上版回顾）**：不回显上版目标、进展或实际交付——目标不会整个遗留，带入本版的只是其中个别未干完的 Issue；完整材料留在验收屏。这里只有两行、各自独占一行，与验收屏同样式回显：「延期遗留」＝上版规划未干完、带入本版的 Issue，呈现 Issue 编号 + 完整标题，可点击打开原生任务详情；「会议遗留」＝上版验收会议纪要「遗留」块的条目（v10 起的现行来源；v10 之前写下的材料没有纪要节，回退读已确认且标为纳入下版的会议指导条目），呈现事项编号 + 描述。缺项如实显示，不另写验收摘要，不在这里编辑风险或约束。**延期遗留区分三种数据态（2026-10-22 真机反馈轮，四铁律：没数据是 Unknown 不是绿）**：验收 `issueMarks` 有标记且无 carry → 「上版无延期 Issue」；验收完全未记录 `issueMarks`（如 v0.6）→ 「上版验收未记录延期标记」，并附一行**实时读回参考**：独立读回上版 `taskSnapshot` 所引 Issue 的当前 open 状态（异步、不阻塞板面、失败显示未知并可重试，通道与任务读取同源），只陈述 open 事实、不冒充人工延期结论。**不设解释脚注（2026-10-22 第八轮，删原「读回为 Issue 当前状态，未经人确认延期；确认请在验收屏标记」）**：Unknown 语义已由「未记录延期标记」文案与「实时读回」标签承担，确认入口已由区块头「打开验收屏」承担，再用一行向用户解释设计属内部协议话术；会议遗留缺项仍显示「上版会议未单独记录」。生产数据源接验收材料现有字段（2026-10-21 落地校准经用户确认）：延期遗留 ← `results[].issueMarks` 中 carry 标记的任务，编号/标题/跳转按任务身份 join 文档顶层 `taskSnapshot`（兼容 legacy 裸编号键；join 不到只显示编号，不猜标题）；会议遗留 ← **已人工确认**纪要的 `minutes.followups`，按数组顺序编号 M1…Mn、描述取 `text`，未确认的草稿不流入本版；材料没有纪要节时（v10 之前写下）回退读 confirmed 且 `tag=next-week-plan` 的 `meetingDirectives`，两者都没有才显示缺项。完整依据直接进入验收屏，生产按明确选定的固定来源定位；读取失败不改读其他材料。无 progressSource 时两行显示「未选定上版验收来源 · 在计划会话中明确后写入」，不推断版本。验收侧已按此区分交付，处置见「对验收侧的移交项（处置结果）」。
2. **本版目标**：一个目标一张可收缩卡片，保留卡间留白与标题、正文、元信息的层次。收起显示目标、负责人和 Issue 数；展开时目标标题只出现一次。目标卡不设「交付内容」，只留「验收标准」承载可核对的结果——Leader 决定：版本级一份完整交付件加一个真机演示环境归验收呈现，不再按目标记录交付件（字段退役见移交项）。卡内恢复「指标承诺」区块，与验收标准以分隔线相邻、保持卡片布局层次：指标从项目共用目录选取，每条承诺呈现当前读数（本期未采集显示「—」并提示）与本版目标值，未采集时目标值标「目标草案」，不拿旧读数冒充本期值；无指标承诺的目标只显示「添加指标承诺（可选）」选择入口，纯交付目标不强制绑定指标，更换或移除承诺不删除目标与验收标准。「配置指标」保留在目标区标题旁（点击在固定指标工作区新建原生会话）。默认阅读、按需行内编辑；不常驻大输入框。关联 Issue 在目标内逐行展示，每行带 Bug / Feature 分类角标——按 issue-state 规范标签推导，精确含 bug / 缺陷标签的显示 Bug，没有分类标签的一律默认按 Feature 显示（2026-10-21 用户确认，计划屏已按此替换旧「无标签归未分类」三折叠分组；验收侧分组显示沿移交项跟进调整）。任务读取未就绪的行不渲染分类角标、状态显示「状态未知」——labels 未知不冒充 Feature（Unknown 铁律）。目标卡可整卡删除：展开后卡片头 × 图标触发就近二次确认（确认删除 / 取消，不弹窗），删除即把该目标的 Issue 引用与相关批注一并移出本版计划，侧栏任务等计数随之现算；生产语义为计划文档编辑，经材料读写服务保存。用户可直接修改目标，或到计划助手讨论如何衡量，不生成质量分、虚构基线或强制数值字段。
3. **持续的计划助手与对象级动作**：「计划助手」是左侧 Orca 原生计划会话的产品称呼，目标讨论、Issue 拆解 / 关联、提供会议 ID 都回到这个同一会话，完整复用标签、历史、输入与工具——整栏含顶部标签栏与会话标题均为原生，BW 不绘制自己的会话头；原型只示意边界，不另造聊天面板或输入框。会话入口是页头带图标的「收起会话 / 展开会话」按钮（可访问名收折会话栏 / 展开会话栏）——只打开 / 聚焦，不新建、不注入，保留已输入草稿；页头不再另设助手图标（与收折按钮重复，2026-10-21 退役），原生 Orca 会话本身没有 ×，也不加。**会话栏收起时不渲染计划屏与会话屏之间的左右分隔条（2026-10-22 第九轮拍板）**：分隔条只在会话栏展开时有意义，收起态留着是「看着能拖、拖了没反应」的死 UI；展开仍走页头「展开会话」。对象级动作（目标卡「拆解 Issue」、纪要区 / 纪要空态卡「整理纪要」、批注面板「发送给计划助手」——2026-10-22 真机反馈轮收敛为三个入口，均为**图标 + 短动词文字按钮**：纯小图标经真机验证过于隐蔽；动词 + 宾语的业界通行写法，AI 角色由图标与弹窗标题承载）经 Orca 原生发送弹窗携带一句话指令与对象上下文——与浏览器批注「发送给 Agent」同一条链路，由用户在弹窗中确认目标会话后发送，动作同时自动展开会话栏；已退役的贴草稿通道不恢复。**发送弹窗在动作按钮处弹出，三段式（2026-10-22 补齐，此前实现只触发了侧边栏 target mode 高亮、漏掉弹窗本体，导致点击无后续）**：①指令预览——只读的一句话指令 + 对象上下文（BW 包装层新增，原生菜单不显示待发送文本）；②「发送至」——该工作树运行中会话列表（状态点 + 名称，不可用行置灰并显示原因）；③「新建智能体」——快捷启动，会话就绪后自动递交指令。②③复用 Orca 原生发送菜单组件（`ReviewNotesSendMenuContent` 链），不改 Orca 契约；Esc 关弹窗（批注模式中的 Esc 分层不变：先关弹窗，再退模式关面板）。发送成功后板面给瞬态反馈「{动作名}已发送给计划助手 · 在会话栏查看进展」——**不含会话名：原生 `onPromptDelivered` 回调无参数，不改为取会话名而扩 Orca 契约；原型演示含会话名属偏差（design D18）**。拆解指令要求助手按该目标验收标准核对已有 Issue、给出拆解 / 关联建议，标题与标签按 issue-state 规范；助手先给建议，再按人确认执行。**纪要确认后不设独立「调整目标」入口（2026-10-22 用户决定）**：整理纪要触发后，计划助手的 Skill SOP 自然引导人跟着调整目标并由人确认，屏上不重复设动作点。页头同时呈现分支名与「配置自动化」入口——自动化绑定固定工作树 bw/week-plan、与版本选择解耦，不因版本不再固定分支而移除。Agent 是用户感知的协作角色，底层仍复用既有工具、Skill、会话与权限，不另造执行核。

各持一份同名常量，不重复散写）。第八轮定四处语义：落点是计划材料 `minutes` 节而非聊天正文；会中发送批注是「累积输入、现在不要整理」（原文以「整理」结尾会被误当整理请求）；全量清单以最新一次为准；转写稿由必有输入改为助手询问一次。**第九轮瘦身（2026-10-22 用户反馈）：按钮 prompt 只承载触发意图与关键约束——整理纪要只一句「把会话中已发送的板面批注汇总为共识 / 遗留两块，需要转写稿就问我要一次会议 ID」，批注发送只一句「全量清单记录、以最新为准、现在不要整理」；落点确认、闭环由人、无批注不编造等 SOP 级规则归 week-planning Skill 与系统提示词（随本轮 Skill 专项同步落地），按钮 prompt 不复述，builder 一眼能懂**。计划助手把两块输入总结为纪要，正文固定两块：「共识」（若干点，支持编辑）与「遗留」（若干点，每点带闭环状态）——闭环 = 版本计划已按该条修改，只能由人标记（完成由人确认的铁律），模型与自动化不得代标；统一格式提高 Leader 归档 PR 审核效率，不加复杂度。纪要存储在计划材料可选 `minutes` 节（复用材料 CAS/锁/轮询/固定提交历史读取链，契约与守卫见 [version-records](../../../standard/system-prompt/references/version-records.md)），经人工确认生效，生成或填写不自动等于确认；确认后正文对模型通道冻结，要改先由人在屏上撤销确认。**纪要未生成（或助手尚未整理）时显示同结构骨架卡（2026-10-22 用户决定）**：虚线边框 + 「未生成」徽章 + 「整理纪要」动作在卡上 + 共识 / 遗留两块占位，界面结构稳定可预见，人能看见纪要生成后的样子；生成后原位换成纪要卡。**第八轮减注释密度（2026-10-22 用户反馈：初始化界面不好看、界面注释过多）**：原空态有 4 段说明文字 + 1 个区块小注，「闭环 = …由人标记」在骨架卡 / 纪要卡 / tooltip 重复出现三次，占位灰条带边框配虚线卡看着像渲染坏了；现只留脚部一句、占位条压细去边框降到 45% 宽，「会议 ID」这类操作指引移到「整理纪要」的发送弹窗指令预览（那里才是人要动手的地方，不该常驻板面）。「计划未建」时按钮禁用并同时用 `title` 与脚部一句给出原因，不留按不动又不说明的死按钮。纪要确认后由计划助手的 Skill SOP 自然引导人跟着调整目标并由人确认，屏上不设独立「调整目标」入口（见第 3 条）；不设逐条握手状态或事条卡片，Leader 认可随归档 PR 评审与合入表达。原「预览纪要」目标派生模板出口已整体退役（验收侧同向调整，见移交项）。
5. **PR 归档**：计划助手沿现有流程创建 / 更新 PR，屏内只放归档引用、真实状态与打开 Orca 原生 PR 页的图标入口（复用原生 PullRequestPage，不跳外部浏览器）。Leader 在原生 PR 页或代码仓审核、评论和合入。计划屏不重复渲染 PR 评论、审核要求、变更摘要、差异统计或冻结材料；修订历史由 Git / PR 承载。PR 合入不等于目标达成。

顶部阶段导航用于同页定位，各区按内容自然纵向展开；不要求在一屏看全上版与本版，不以压缩字号、行距或卡片间距达成一屏容纳。阶段导航不是门禁或完成按钮。先拆解、先讨论、往返修改均可；浏览、填写回应、任务关闭都不能替代人的目标确认。

### 极简交互

- 能由稳定图标表达的编辑、完成编辑、展开、添加、助手、跳转动作使用图标按钮；按对象就近摆放，避免一排长文案按钮。导航名、目标句和状态是内容，保留文字。

左侧导航底部明确标记“G2 外框示意”，不会把装饰性导航包装成本轮设计。原型开工只显示交接说明和 G2 设计链接，不模拟建树成功。验收屏由其负责人处理，本轮不修改其布局或业务。

## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

沿用 BW 侧栏总览、计划、任务、验收、自动化、知识库；计划、验收是独立入口。计划与验收完整复用 Orca 原生会话工作区：顶部新建会话和 Agent 控件、标签/分屏、资源管理器、智能体历史及可收起的工具侧栏均由 Orca 拥有。左侧保留 BW 导航，其下与其他页一样显示项目列表。计划屏的启动入口是目标区空板卡「与计划助手新建计划」（唯一会话发起入口，仅无计划时显示；内部沿用已登记自动化的手动运行链，材料问题作一次性上下文随同带入），验收屏保留右板首行协作卡片“新建验收”（带会话图标）；不在原生标签栏另加启动按钮。分支名显示在右板页头，“配置自动化”入口在页头分支名旁——一次性配置不占每周主操作区。不另建聊天、历史或会话绑定。右侧直接编辑版本材料。版本是业务对象，周次是运行上下文；显示关联信息时版本在前，原生会话标题不强改。

每周自动化先启动本次原生会话，Skill 展示已有版本候选，由用户在会话确认本次沿用或新建的版本。右侧始终保留同一计划布局，未明确版本时各区显示空态，可直接用下拉框查看已有版本，不要求先有会话，也不自动创建或修改计划。不能按日期、文件修改时间、上次打开项或未发布状态推断本次版本。选已有版本读取其现有目标；只有用户明确新建才创建新计划。不同周默认开启不同会话，用户改过自动化会话复用设置时尊重其配置；版本选择不再触发一次运行。

右侧只有一页（G3 四区结构，详见「计划旅程（G3）」节）：页头（面包屑版本下拉、保存状态、会话收折 chip、分支名、批注模式、更新代码、配置自动化），顶部 4 分区导航（计划准备 / 本版目标 / 会议纪要 / 归档 PR，同页定位与滚动高亮，不是门禁或完成按钮；第一步名 #426 验收会决议自「上版回顾」改，与验收屏「验收准备」口径一致，区块内容不变），正文四区自然纵向展开。两屏界面都不渲染旅程灯：`workflow.stage` 契约不变（模型仍写，供会话校准与自动化），计划屏与验收屏都不再消费它渲染状态。目标呈现为一个目标一张 G3 可收缩卡片：收起显示目标句、负责人和 Issue 数，展开承载目标句（只出现一次）、验收标准、指标承诺、计划完成/负责人与关联 Issue 逐行展示（Bug/Feature 角标、状态、开工入口），不设交付内容字段（`goals[].deliverable` 保留在共用 schema 作可选字段，两屏都不显示不编辑）；验收屏 v10 用独立只读勾勾表行 `AcceptanceGoalRow`，原共用 `VersionGoalCard` 已删除，「约定交付」呈现随目标级交付件退役。计划完成与负责人写入可选 deadline/owner 字段，验收屏只读展示。目标卡开合按项目、版本和计划/验收屏分别记忆，默认收起，单卡与全部展开/收起共用同一视图状态；页面不另设全量任务区，Issue 不再按 Bug/Feature/未分类三折叠分组（计划屏平铺 + 角标）。上版回顾只回显固定来源的延期遗留 / 会议遗留两行；进展与风险编辑区从计划屏移除（summary.progress/risks 字段保留在 schema，risks 人工守卫不变；验收屏风险能力已整体去掉，`issueMarks.risk` 留作只读旧格式字段）。归档区一行卡片：PR 引用、真实合入状态与打开 Orca 原生 PR 页入口，不设操作按钮。

验收来源由人明确，可来自同版上周或已完成版本，不按版本号、日期或最新一条记录推定。计划在 `summary.progressSource` 保存验收版本、固定提交与材料修订（轮次字段随 v10 跨周场景退役，不再写入；存量材料里的轮次身份仍参与寻址核验）；引用由模型在会话中与人核对后写入，页面不再提供选源弹窗。上版回顾按引用的版本、周期、固定提交和修订读取固定验收材料并核验身份（不一致如实报错，不改读其他材料），映射为延期遗留 / 会议遗留两行回显（映射规则见「计划旅程（G3）」节第 1 条）。

**「打开验收屏」的落点未定（现行只作普通入口）**：验收屏 v10 退役轮次后没有只读历史整页，`version-cycle/open-acceptance-source.ts` 当前只是切到验收屏看**当前**材料，钉不住 progressSource 里那个固定提交（该处已留注释说明）。寻址协议本身已具备（版本 / cycleId / sourceCommit / revision，身份不符即抛错不改读）。两条候选——给验收屏补只读历史整页（深链或历史模式），或把计划屏这个入口改为在会话中打开固定提交的材料——待负责人拍板，见验收 spec「取舍与待决问题」#1。来源缺失时只作普通验收入口，不替人推定版本。写入引用不覆盖 summary.progress 字段（该字段保留、计划屏不再编辑），内容由会话核对后按授权整理并保存；没有来源不生成成绩，已有编辑保留。读取失败如实提示，不回退当前验收树或最新材料。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 产物 |
|---|---|---|
| 准备 | 先看完整流程和版本候选，明确本次版本；读取现状，交流场外要求，查上版回顾的固定来源两行遗留 | 明确的版本、有固定来源的上版遗留认知与约束 |
| 目标 | 直接编辑或与模型讨论结果，选择已登记指标并读取当前值，填写版本目标值 | 一份版本目标草稿 |
| 拆解 | 会前会话核对已有任务，按已认可范围创建或修改 Issue；右侧回显真实编号、标题、状态和关联目标 | 远端任务与版本关联 |
| 评审 | Builder 与 PL 开会，对着目标卡讨论并现场直接修改目标与验收标准，评审意见经批注模式记录 | 评审后修订的目标原件与板面批注 |
| 归档 | 会话中发起归档；模型核对材料、记录阶段并按用户授权提 PR，把 PR 引用写回材料；人审核合入 | 可追溯的计划修订与 PR 状态 |

每阶段完成时模型把 `workflow.stage` 写入材料，供会话校准与自动化使用；**两屏界面都不渲染灯**（计划屏自 G3、验收屏自 v10 起），计划屏顶部导航只做同页定位。阶段语义与写入契约见 [version-records](../../../standard/system-prompt/references/version-records.md)。

评审后的会议纪要整理是内容输出，不是评审前置：计划助手把在线批注与可选会议转写稿总结为「共识 / 遗留」两块写入材料 `minutes` 节（仅未确认时模型可写正文），人在屏上确认后生效，遗留逐条闭环由人标记。常见顺序是评审会后整理，也可以在拆解前整理；不为此新增流程阶段或强制检查点，不把生成或填写当作评审通过。

## 行为规则与异常

### 目标与指标

目标卡以一句可读的结果为主，目标句、验收标准、计划完成/负责人经铅笔进入编辑态后直接在卡片内行内编辑，不设目标补充弹窗；计划屏不再提供交付件编辑（字段退役见移交项）。没有指标承诺时，仅显示“添加指标承诺（可选）”选择入口；一目标可按需绑定多个不同名称的指标，每条呈现当前读数与本版目标值，定义、长期目标及采集依据收在可展开说明中。纯交付目标不要求绑定指标，移除指标不删除目标或验收标准；更换指标清空旧目标值及基线，避免不同口径沿用。目录中同名指标定义更新时保留既有承诺与基线来源，并提示定义已更新，不再把它作为新指标重复添加。存量同名承诺不自动合并或删除；验收显示全部承诺并提示无法唯一比较，由人在计划会话核对。指标和其他验收说明按需补充，不设置三类目标下拉或统一必填报告、点数、showcase。新特性、反馈优化、场景交付的引导放在 Skill references。Top3 用于聚焦；历史有更多目标时完整保留，不截断原承诺。

指标从项目共用目录选取，只接入支持日／周历史查询的脚本；取值只读，版本目标值可写，项目长期目标与本版目标分别显示。刷新调用总览的同一采集能力，读取主干基线（正式来源）并采用最新已合入定义和脚本，不合并计划树或覆盖草稿；显示采集窗口与来源。无定义、无可用采集或失败时显示未知，不把旧基线、0 或上一次其他窗口读数当成本期值。未就绪的数值目标标草案，不阻止保存其他内容，也不制造承诺已就绪的绿灯。

“配置指标”入口在目标区标题旁，每次点击均在固定指标工作区新建原生会话并注入提示，旧会话从 Orca 原生工作区继续，不自动续接。“配置指标”悬停提示为“新建会话，配置指标”；验收屏“新建验收”沿用对话气泡＋图标语义，不加星光或改成纯图标；计划屏空板「与计划助手新建计划」为文字按钮。

### 纪要、任务与返回

会议纪要存储在计划材料可选 `minutes` 节：`consensus` 共识若干点、`followups` 遗留若干点（条目含稳定 id、text 与 closed 闭环标记）、`confirmed/confirmedAt` 人工确认、`sources/updatedAt` 可选来源描述与更新时间（契约与人工守卫见 [version-records](../../../standard/system-prompt/references/version-records.md)）。正文由计划助手基于在线批注与可选会议转写稿总结，仅在未确认时由模型通道写入或改写；人在屏上确认后整节对模型冻结，闭环只能由人标记，确认与闭环都不是目标达成或 Issue 认可。纪要编辑走同一自动保存 CAS 草稿链；总览计划列直接读取本节渲染两块，无存储纪要的历史版本如实显示「纪要未记录」。旧三节模板（本周 Top3 目标、周五交付件、数字指标变化）的派生与「预览纪要」出口已整体退役删除，不读会议录音、不设手填纪要的第二正本。

版本任务在目标卡内逐行展示；任务拆解在会话中与模型讨论并写入材料引用，页面不提供直接建任务按钮——目标卡「拆解 Issue」对象级动作经原生发送弹窗携带指令与对象上下文，由用户确认目标会话后发送。模型负责与用户讨论后创建/更新，页面读取真实 Issue；草稿不得显示假编号。Issue 行「开工」箭头本轮为临时语义：打开原生任务详情（可访问名「打开 #N 原生任务详情」）；真开工（侧边栏固定目录建 worktree）归 G2/#385，永久接线时调 G2 统一 Start/Open resolver。点 Issue 标题复用 Orca 任务详情及其正文编辑、保存、错误提示和缓存回写。详情主返回按钮回到来处计划，保留项目、版本、草稿、会话、目标筛选和滚动位置；从原生任务列表打开时才返回任务列表。状态写入仍遵守 issue-state，关联任务不代表可以批量完成。

### 会话、保存与归档

“配置自动化”入口位于右板页头分支名旁，打开对应的 Orca 原生编辑器；计划屏启动入口只保留目标区空板卡「与计划助手新建计划」（验收屏为首行协作卡片“新建验收”），手动启动一次不改变定时启用状态。高保真中的原生编辑器只作带脚注的占位，原型场景切换控件不进入最终界面。

沿用固定 bw/week-plan 工作树；验收另用 bw/week-acceptance。进入页面只准备并选中原生工作区，不自动创建会话；已有工作区先回显会话与现有材料，进屏不做任何 Git 动作。页头「更新代码」是唯一同步入口：把固定树快进到主干最新并重读材料与版本候选，保留未保存输入；执行期间显示状态，材料暂时只读并暂停自动保存；同一工作区的在途更新复用一次请求，切走后不因完成而跳回。快进不了（分叉等）保持原样、如实提示、不更换数据来源，材料仍照常重读，由用户在会话中带工作模型处理。该树已打开的所有原生会话、活动标签与分屏直接可见。切换到其他工作区时不被 BW 强拉回。

“新建计划／验收”调用对应已登记自动化的原生手动运行，使用用户当前保存的提示、工具和模型，并自动打开、聚焦本次原生会话；定时运行仍在后台。普通原生新建会话不自动注入 BW Skill。首次登记默认关闭定时、使用固定工作区且 reuseSession=false，按 creationKey 去重；已有条目按当前 BW 版本覆盖同步 BW 所有的提示词（BW 持续演进，定时与手动跑的必须始终是新版提示），用户所有的设置（启用开关、触发时间、模型、会话复用）保留不覆盖，同步失败如实提示且不阻断启动；后续运行尊重用户保存的会话复用配置。“配置自动化”打开原生编辑器，历史恢复和运行打开完全沿用 Orca。

首次进入无版本、无会话时，空板卡「与计划助手新建计划」仍可使用，其余各区保持空态。旧格式或损坏材料在同一空板卡内紧凑提示实际版本与计划/验收数据文件；启动入口把当前明确选中的版本、具体文件及读取问题带入原生会话，作为一次性上下文随已登记自动化的手动运行与保存提示合并为单次递交（automation.runNow 的 oneShotPrompt，capability 门控，不另建会话），不再另放“在会话中处理”启动按钮。模型先说明旅程，再把旧字段收成新计划，对不上的目标问人，经用户确认后执行，不留旧文件副本，也不把点击按钮当成同意改数据；只有其他旧版本异常时不阻塞正常版本。页面不保留专用迁移预览/确认弹窗或额外的旧结果入口；迁移工具及安全约束仍由材料服务和 Skill reference 承担。

直接编辑后自动保存草稿，正常状态只在标题旁简短呈现，不设常规保存按钮；保存不是评审完成。右侧与模型使用同一读写服务及修订条件，连续编辑顺序写入；切换版本前先确保当前修改已保存，失败则停止后续动作。冲突或写入失败暂停自动写入并保留输入，由人处理冲突或明确重试，不循环覆盖。归档后的材料仍可编辑；两屏界面都无灯，`workflow.stage` 只作材料内部进度。切版本、离开页面、重启要可恢复，加载失败不能伪装为空版本。

删除“确认计划”按钮和旧三阶段确认门槛。人的评审决定可来自当前会话或真实 PR，不从“打开过纪要”推定已批准；用户在会话中明确确认评审后由模型写入 `workflow.stage=review`，灯据此点亮，页面不设评审控件。归档、拆解与未达跟进都直接在会话中发起：页面不提供贴草稿按钮与等待框（该通道已整体退役），提 PR 后模型把 provider/repository/number 写入 `workflow.archivePr`，归档状态行显示 PR 链接与合入状态（已合入／待合入／已关闭／读不到保持未知）。两屏页头均使用“更新代码”快进固定树并重读材料与候选，不自动采集指标。归档遵循被管项目指定基线与原生默认分支配置，不能把 BW 自身的开发分支写成所有项目的永久基线。

同一版本保留一份当前计划，编辑、换会话与归档后补充均不改变 cycleId（跨周按轮次刷新场景已于 2026-10-22 退役，一个版本做一轮验收）。总览按项目主干基线（主检出）的版本目录展示一份当前材料，旧内容从 Git 追溯，不重复列出旧提交或迁移前快照。**两屏界面都不渲染灯**（计划屏自 G3、验收屏自 v10 起）：`workflow.stage` 是模型写入的进度信号，只供会话校准与自动化，不是完成权威，也不代表目标达成或 PR 已合入。

合入与目标完成是不同事实，分别由归档状态行的 PR 合入状态与任务、验收结论呈现；未读取 PR 不冒充尚未创建。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| P01 | 计划独立单页，顶部 4 分区导航定位与自然滚动；1365×768、1280×720 与 824×668 窄板可见四区并继续操作，长文本与缩放不破版，顶部导航不随内容滚动 |
| P02 | 场外要求可进入目标；三种情形通过交流引导，不强制分类或填齐所有证据字段 |
| P03 | 指标与总览同定义、同窗口、同来源；只编辑版本目标，刷新、失败、未知与旧值有明确区别 |
| P04 | 纪要只含共识/遗留两块，编辑后的数据一致；确认与闭环只能由人标记，已确认纪要模型通道拒写，不补造事实 |
| P05 | 创建/复用 Issue 后真实回显；编辑原生详情后返回计划并保留上下文，失败不假报保存 |
| P06 | 计划与验收分树，复用全部原生会话、标签/分屏及侧栏；原生入口与 BW 入口查看同一工作区；普通新建不注入 Skill，专用新建走已登记自动化；未选择版本不写材料；空会话时数据问题入口也能新建并自动发送 |
| P07 | 自动化登记去重、BW 提示词覆盖同步、用户设置保留；一次真实到点触发、失败与重试可追溯，不自动确认完成 |
| P08 | 手填与模型并发保存有修订冲突处理；重启、切项目、切版本后数据与文件独立读回一致 |
| P09 | 归档在会话中发起；两屏界面都不渲染旅程灯（stage 契约不变，仍供会话校准与自动化），归档卡按 archivePr 显示真实合入状态并可打开 Orca 原生 PR 页，读不到保持未知，不假标已合入 |
| P10 | 总览按主干基线（主检出）的版本目录读取一份计划/验收摘要，计划列读存储纪要、无纪要版本如实显示未记录，往返保留草稿；旧提交不重复入列，坏当前文件如实提示 |

注册旅程 PJ01：进入计划 → 看四区结构并交流场外要求 → 写目标/采集指标 → 会前核对已有任务并建 Issue → 与 PL 评审并现场修改目标、批注评审意见 → 改描述并返回 → 会话提 PR → 人合入 → 批注发送给计划助手整理纪要 → 人工确认与闭环标记 → 重启独立读回。另覆盖会中或评审后整理同一份纪要，不依赖任务或 PR 状态。PJ02 覆盖跨周自动化与同次恢复。验收用例和证据按 [六环](../../01-principles/02-working-backwards.md#62-六环交付链) 登记；原型检查不能代替真壳与真实模型旅程。

首用周记录需要重新澄清的目标及原因、因遗漏约束造成的返工、真实归档次数；先核对口径与基线，再决定是否登记为产品指标，不预填改善比例。

## 取舍与待决问题

保留会话与直接编辑，减少步骤和重复正文；代价是必须把保存、远端状态与人的认可分别呈现。交付件与指标不统一强制，但已承诺数值不能脱离采集依据。自动化只负责触发与恢复，具体启用安排交项目用户配置。
