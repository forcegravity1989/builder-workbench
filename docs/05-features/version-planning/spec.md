## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

沿用 BW 侧栏总览、计划、任务、验收、自动化、知识库；计划、验收是独立入口。计划与验收完整复用 Orca 原生会话工作区：顶部新建会话和 Agent 控件、标签/分屏、资源管理器、智能体历史及可收起的工具侧栏均由 Orca 拥有。左侧保留 BW 导航，其下与其他页一样显示项目列表。BW 在右侧业务板正文首行提供“与 Agent 一起制定版本计划／核对版本交付”协作卡片，放置带会话图标的“新建计划／验收”，不在原生标签栏另加启动按钮；分支名显示在右板页头，“配置自动化”入口在页头分支名旁——一次性配置不占每周主操作区。不另建聊天、历史或会话绑定。右侧直接编辑版本材料。版本是业务对象，周次是运行上下文；显示关联信息时版本在前，原生会话标题不强改。

每周自动化先启动本次原生会话，Skill 展示已有版本候选，由用户在会话确认本次沿用或新建的版本。右侧始终保留同一计划布局，未明确版本时各区显示空态，可直接用下拉框查看已有版本，不要求先有会话，也不自动创建或修改计划。不能按日期、文件修改时间、上次打开项或未发布状态推断本次版本。选已有版本读取其现有目标；只有用户明确新建才创建新计划。不同周默认开启不同会话，用户改过自动化会话复用设置时尊重其配置；版本选择不再触发一次运行。

右侧只有一页：一行协作入口、版本进展与风险卡片、当前版本 Top3 目标、一行归档状态。目标呈现与验收屏统一为同一套目标卡骨架（2026-10-18 经用户确认并已接线）：一个目标一张卡、整卡可收缩——收起为结论行（目标句、关联 Issue 数），展开承载制定与拆解（目标句、交付件、验收标准、指标承诺、计划完成/负责人、关联 Issue 分组子块与原生详情入口）；计划完成与负责人写入可选 deadline/owner 字段，验收屏只读展示；拆解创建或更新的 Issue 逐条按人确认性质打 Bug/Feature 分类，生产展示时有标签但没有 Bug/缺陷标签的默认归 Feature，无标签归未分类；目标卡开合按项目、版本和计划/验收屏分别记忆，单卡与全部展开/收起共用同一视图状态；页面不再另设全量任务区。版本进展以人选定的验收纪要为依据，可引用同版上周或已完成版本：有引用时进展区直接回显按固定材料派生的只读纪要（只含人话正文，不含周期/修订/固定提交等技术标识），无引用或读取失败时显示文本输入并如实提示（不改读其他记录）；引用材料缺失时留空，不制造成绩。“查看验收依据”按钮跳转验收屏查看完整记录与来源，更丰富的视图在验收屏，进展区只回显派生纪要。风险由用户填写，模型不代填（模型通道写入被守卫拒绝）。取消旧结果第一屏、第三屏页签和两个会议文本输入区。旅程轴保留图标和连线，用于定位对应正文并显示模型记录的阶段状态；评审是 Builder 与 PL 讨论并直接修改目标，不由打开纪要承担，归档在会话中由模型发起，页尾归档卡片是只读状态行，不设操作按钮。

验收来源由人明确，可来自同版上周或已完成版本，不按版本号、日期或最新一条记录推定。计划在 `summary.progressSource` 保存验收版本、轮次、固定提交与材料修订；引用由模型在会话中与人核对后写入，页面不再提供选源弹窗，“查看验收依据”按引用的版本、周期、固定提交和修订打开验收屏对应的只读历史整页；来源缺失时只作普通验收入口，不替人推定版本。进展区内联纪要由固定验收材料及其当时采用的计划派生，不冒充另存的历史 Markdown 原文。写入引用不覆盖进展文本，内容由会话核对后按授权整理并保存；没有来源不生成成绩，已有编辑保留。读取失败如实提示，不回退当前验收树或最新材料。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 产物 |
|---|---|---|
| 准备 | 先看完整流程和版本候选，明确本次版本；读取现状，交流场外要求，查必要的上版验收 | 明确的版本、有来源的进展、风险与约束 |
| 目标 | 直接编辑或与模型讨论结果，选择已登记指标并读取当前值，填写版本目标值 | 一份版本目标草稿 |
| 评审 | Builder 与 PL 开会，对着目标卡讨论并现场直接修改目标、交付约定和指标 | 评审后修订的目标原件 |
| 拆解 | 会话核对已有任务，按已认可范围创建或修改 Issue；右侧回显真实编号、标题、状态和关联目标 | 远端任务与版本关联 |
| 归档 | 会话中发起归档；模型核对材料、记录阶段并按用户授权提 PR，把 PR 引用写回材料；人审核合入 | 可追溯的计划修订与 PR 状态 |

每阶段完成时模型把 `workflow.stage` 写入材料，旅程灯随之点亮；阶段语义与写入契约见 [version-records](../../../standard/system-prompt/references/version-records.md)。

评审后的会议纪要整理是内容输出，不是评审前置。常见顺序是完成任务拆解与 PR 合入后，Builder 填写会议纪要时预览、复制当前目标派生的三段内容；也可以在评审后、拆解前复制。不为此新增流程阶段或强制检查点。

## 行为规则与异常

### 目标与指标

目标卡以一句可读的结果为主，目标、交付件和可选验收标准直接在卡片内编辑，不设铅笔入口或目标补充弹窗。没有指标承诺时，仅显示“添加指标承诺（可选）”选择入口；一目标可按需绑定多个不同名称的指标，每条呈现当前读数与本版目标值，定义、长期目标及采集依据收在可展开说明中。纯交付件目标不要求绑定指标，移除指标不删除目标、交付件或验收标准；更换指标清空旧目标值及基线，避免不同口径沿用。目录中同名指标定义更新时保留既有承诺与基线来源，并提示定义已更新，不再把它作为新指标重复添加。存量同名承诺不自动合并或删除；验收显示全部承诺并提示无法唯一比较，由人在计划会话核对。交付件、指标和其他验收说明按需补充，不设置三类目标下拉或统一必填报告、点数、showcase。新特性、反馈优化、场景交付的引导放在 Skill references。Top3 用于聚焦；历史有更多目标时完整保留，不截断原承诺。

指标从项目共用目录选取，只接入支持日／周历史查询的脚本；取值只读，版本目标值可写，项目长期目标与本版目标分别显示。刷新调用总览的同一采集能力，读取主干基线（正式来源）并采用最新已合入定义和脚本，不合并计划树或覆盖草稿；显示采集窗口与来源。无定义、无可用采集或失败时显示未知，不把旧基线、0 或上一次其他窗口读数当成本期值。未就绪的数值目标标草案，不阻止保存其他内容，也不制造承诺已就绪的绿灯。

“配置指标”每次点击均在固定指标工作区新建原生会话并注入提示，旧会话从 Orca 原生工作区继续，不自动续接。模型工作入口使用 Orca 的“对话气泡＋”图标并保留短动作文字；“配置指标”悬停提示为“新建会话，配置指标”，“新建计划／验收”沿用相同图标语义，不加星光或改成纯图标。

### 纪要、任务与返回

纪要严格遵循 [三节模板](../../../standard/skills/week-planning/assets/minutes-template.md)：本周 Top3 目标、周五交付件、数字指标变化。内容由当前目标、约定交付、指标目标及当前读数派生；缺项保留待明确，不添加无来源结论。目标标题旁的“预览纪要”打开含复制按钮的预览框，用于评审后的会议纪要填写，有可读取计划时即可使用，不强制等待任务拆解或 PR 合入，也不从点击行为推定评审通过。复制与预览一致，修改目标后重新生成；不读会议录音、不设手填纪要的第二正本。

版本任务在页内展开；任务拆解在会话中与模型讨论并写入材料引用，页面不提供请求按钮。模型负责与用户讨论后创建/更新，页面读取真实 Issue；草稿不得显示假编号。点 Issue 复用 Orca 任务详情及其正文编辑、保存、错误提示和缓存回写。详情主返回按钮回到来处计划，保留项目、版本、草稿、会话、目标筛选和滚动位置；从原生任务列表打开时才返回任务列表。状态写入仍遵守 issue-state，关联任务不代表可以批量完成。

### 会话、保存与归档

“配置自动化”入口位于右板页头分支名旁，打开对应的 Orca 原生编辑器；首行协作卡片只保留“新建计划”，手动启动一次不改变定时启用状态。高保真中的原生编辑器只作带脚注的占位，首次与异常场景可从页底“原型场景¹”展开查看；这些原型控件不进入最终界面。

沿用固定 bw/week-plan 工作树；验收另用 bw/week-acceptance。进入页面只准备并选中原生工作区，不自动创建会话；已有工作区先回显会话与现有材料，进屏不做任何 Git 动作。页头「更新代码」是唯一同步入口：把固定树快进到主干最新并重读材料与版本候选，保留未保存输入；执行期间显示状态，材料暂时只读并暂停自动保存；同一工作区的在途更新复用一次请求，切走后不因完成而跳回。快进不了（分叉等）保持原样、如实提示、不更换数据来源，材料仍照常重读，由用户在会话中带工作模型处理。该树已打开的所有原生会话、活动标签与分屏直接可见。切换到其他工作区时不被 BW 强拉回。

“新建计划／验收”调用对应已登记自动化的原生手动运行，使用用户当前保存的提示、工具和模型，并自动打开、聚焦本次原生会话；定时运行仍在后台。普通原生新建会话不自动注入 BW Skill。首次登记默认关闭定时、使用固定工作区且 reuseSession=false，按 creationKey 去重；已有条目按当前 BW 版本覆盖同步 BW 所有的提示词（BW 持续演进，定时与手动跑的必须始终是新版提示），用户所有的设置（启用开关、触发时间、模型、会话复用）保留不覆盖，同步失败如实提示且不阻断启动；后续运行尊重用户保存的会话复用配置。“配置自动化”打开原生编辑器，历史恢复和运行打开完全沿用 Orca。

首次进入无版本、无会话时，首行协作入口仍可使用，下方保持空板。旧格式或损坏材料在同一卡片内紧凑提示实际版本与计划/验收数据文件；“新建计划／验收”把当前明确选中的版本、具体文件及读取问题带入原生会话，作为一次性上下文随已登记自动化的手动运行与保存提示合并为单次递交（automation.runNow 的 oneShotPrompt，capability 门控，不另建会话），不再另放“在会话中处理”启动按钮。模型先说明旅程，再把旧字段收成新计划，对不上的目标问人，经用户确认后执行，不留旧文件副本，也不把点击按钮当成同意改数据；只有其他旧版本异常时不阻塞正常版本。页面不保留专用迁移预览/确认弹窗或额外的旧结果入口；迁移工具及安全约束仍由材料服务和 Skill reference 承担。

直接编辑后自动保存草稿，正常状态只在标题旁简短呈现，不设常规保存按钮；保存不是评审完成。右侧与模型使用同一读写服务及修订条件，连续编辑顺序写入；切换版本前先确保当前修改已保存，失败则停止后续动作。冲突或写入失败暂停自动写入并保留输入，由人处理冲突或明确重试，不循环覆盖。归档后的材料仍可编辑，旅程灯不因材料改动变色，只读 `workflow.stage`；不要求另开轮次。切版本、离开页面、重启要可恢复，加载失败不能伪装为空版本。

删除“确认计划”按钮和旧三阶段确认门槛。人的评审决定可来自当前会话或真实 PR，不从“打开过纪要”推定已批准；用户在会话中明确确认评审后由模型写入 `workflow.stage=review`，灯据此点亮，页面不设评审控件。归档、拆解与未达跟进都直接在会话中发起：页面不提供贴草稿按钮与等待框（该通道已整体退役），提 PR 后模型把 provider/repository/number 写入 `workflow.archivePr`，归档状态行显示 PR 链接与合入状态（已合入／待合入／已关闭／读不到保持未知）。两屏页头均使用“更新代码”快进固定树并重读材料与候选，不自动采集指标。归档遵循被管项目指定基线与原生默认分支配置，不能把 BW 自身的开发分支写成所有项目的永久基线。

同一版本保留一份当前计划，编辑、跨周、换会话与归档后补充均不改变 cycleId。总览按项目主干基线（主检出）的版本目录展示一份当前材料，旧内容从 Git 追溯，不重复列出旧提交或迁移前快照。旅程灯只读 `workflow.stage`：灯位不超过 stage 为绿，其后为灰，没有黄/红中间态；stage 是进度信号不是完成权威，绿灯不代表目标达成或 PR 已合入。

旅程灯色只有两态：模型记录阶段完成则绿灯，未记录则灰。合入与目标完成是不同事实，分别由归档状态行的 PR 合入状态与任务、验收结论呈现；未读取 PR 不冒充尚未创建。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|

注册旅程 PJ01：进入计划 → 看 SOP 并交流场外要求 → 写目标/刷新指标 → 与 PL 评审并现场修改目标 → 建 Issue → 改描述并返回 → 会话提 PR → 人合入 → 预览并复制纪要用于会议纪要填写 → 重启独立读回。另覆盖评审后、拆解前复制同一份当前内容，不依赖任务或 PR 状态。PJ02 覆盖跨周自动化与同次恢复。验收用例和证据按 [六环](../../01-principles/02-working-backwards.md#62-六环交付链) 登记；原型检查不能代替真壳与真实模型旅程。

首用周记录需要重新澄清的目标及原因、因遗漏约束造成的返工、真实归档次数；先核对口径与基线，再决定是否登记为产品指标，不预填改善比例。

## 取舍与待决问题

保留会话与直接编辑，减少步骤和重复正文；代价是必须把保存、远端状态与人的认可分别呈现。交付件与指标不统一强制，但已承诺数值不能脱离采集依据。自动化只负责触发与恢复，具体启用安排交项目用户配置。

## G2 版本运作（设计定稿）

关联 [#383](https://github.com/forcegravity1989/builder-workbench/issues/383)、[#328](https://github.com/forcegravity1989/builder-workbench/issues/328)、[#334](https://github.com/forcegravity1989/builder-workbench/issues/334)。本节与 [高保真修订 7](version-workspace-prototype.html?rev=7)、[旅程及数据说明报告](version-workspace-journey.html) 定义 G2 行为；上文保留当前已实现的计划屏规格。已定稿决定：多版本并行、版本平铺回看、逻辑目标目录、目标工作树按需创建、目标与 Issue 开工复用同一原生创建器、不新增周冻结或目录生成操作；版本归档必须实现并复用 Orca 原生归档能力。生产接线与真壳证据见 STATUS。

### 价值与复用范围

Builder 从项目墙进入项目后，能按“版本 → 计划承诺 → 目标与执行 → 验收结果”持续交付：知道为什么做、从哪开始、正在做哪版、按什么验收、后来如何回看。BW 增加的是业务关联、范围、交付依据与总结；原生执行核继续承担实际工作。

上部侧栏聚焦项目墙选定项目；项目标题为静态标识，切换项目沿项目墙，不提供无实际动作的下拉箭头。知识库与版本之间用横线分隔，各版本并列展开总览、计划、任务、验收。版本下方统一显示 Orca 项目工作区，保留当前项目及私人项目的原生入口；当前项目的未归版旧共享树、项目约定树等仍从这里可达，上方不再另设重复的“项目工作区”入口。不设专门“历史会话”或“已归档”分区；版本归档不产生分区，已归档版本留在原版本列表位置、带“已归档”标识、默认收起，可展开回看；不收窄 Orca 原生完整项目/工作树集合。

项目总览、计划、验收、任务、自动化、知识库及会话区继续复用。高保真只画新增导航、范围/动作的挂载位置与版本总览；既有业务板和完整会话用“沿用”标出，不复制另一套页面。计划/验收作为原有整屏沿用，包含 Orca 会话区及右侧业务板。G2 原型只标明整屏复用及版本上下文，不分别画会话区与业务板占位、不接管两区布局；原板发起会话的入口在原型操作区演示归属，不能据此当作新增产品按钮。分支卡片、agent、菜单、父子关系与激活沿原生能力；流程标签和挂载位置需要 BW 的展示/路由适配，不声称所有原生 UI 零改动。滚动样式沿 Orca，侧栏不出现横向滚动条。

### 新建版本与固定流程工作区

“版本”旁提供“＋ 新建版本”，填写名称后“创建并进入计划”。采用方式：由 Orca 准备本版独立计划、验收两棵稳定工作树，准备空白计划材料并打开既有计划屏。代表仓试验若示初始化成本不可接受，再评审验收树延迟准备，不私改当前方式。版本目录本身不创建实体父树；目标与任务树按需创建。计划、验收分别沿用 `.bw/planning/<version>/data.json` 与同目录 `acceptance.json`；验收材料在明确计划依据后准备，不因提前建树就生成结论。

创建不启动 agent、不启用定时、不自动创建 Issue、提 PR 或发布；新建计划/验收会话仍由各业务板已有按钮发起。已存在版本直接回显对应材料，版本从侧栏明确带入，板内取消重复选版；选中 agent 打开完整原生会话区及对应业务板。普通原生新会话不一律注入 BW 计划/验收提示。

计划入口与其唯一固定树合为一行，验收同样处理。点名称打开原业务屏，点箭头展开本树原生 agent；分支名在详情/悬停中可见，保留原生工作树菜单。一个版本可以有多个计划会话，但不会为每个会话再复制计划树。

版本名称沿用现有材料目录规则；重名不重复建版。两棵树未准备齐则显示未完成、保留输入及已有成功结果，核对原生登记后补齐；不自动删树回滚、不虚报成功。初次验收核对实际代码与交付候选，再走安全同步；分叉、未提交修改保留现场，不因建树较早就自动 reset。Git 对象通常共享，检出文件与初始化脚本/依赖/构建产物仍可能各占空间，不能承诺任意大仓库无成本。

### 目标出现与计划定稿（用户已确认）

目标一经保存到计划就按稳定 goalId 呈现在“任务”下，草案/未核对与正式修订状态分别表达，不加“生成目标目录”按钮。目标名称、排序与引用从计划投影；显示目录不等于目标获批、已开工或达成。改名/排序不改工作区绑定；删除目标不能隐式删树，失去目标引用的工作区仍从原生项目工作区可达并提示待整理。

用户已确认把“本周固定”收敛为采用经过人工评审并合入项目基线的计划修订；本版跨周继续保留同一材料身份，不按日期自动冻结或另造计划。识别时必须核对实际已合入材料及其修订；workflow 阶段灯、PR 曾经合入、目录已有内容，都不能单独证明当前编辑稿已定稿。正式依据后又修改，呈现“有待确认修改”；读取失败保持未知。正式验收使用明确固定的已合入计划，草案预验收另标。

不新增周冻结、目录生成或额外确认操作，不新增一套快照存储和手填定稿状态。沿现有 Git 材料、评审与引用识别正式修订和后续变动；当前未实施的状态适配仍需验证。用户确认的理由是避免无实际用户价值的操作、存储和方案复杂度。

### 目标开工与 Issue 开工：同一原生创建器

**已确认：保留逻辑目标目录，目标工作树按需创建。** 点任务看本版完整 Issue 范围，点 G1/G2 只改变同一个 Orca 任务屏的目标筛选，不为每个目标新增任务屏或重复存储任务。目标目录和版本目录都不是实体工作树。

Issue 开工仍从原生任务列表/详情发起。当前路径已经打开 Orca 的新建工作区弹窗，并预填任务来源、仓库和名称；已有明确关联工作区时可以直接打开。目标开工放在侧栏目标“···”菜单，复用同一个底层创建器：带入目标名称、交付约定、计划依据和相关 Issue 引用，不伪造一个目标 Issue、不绕过弹窗直接创建树，不新增单独的 BW 多步骤向导。

BW 必须补齐正确的项目/宿主、版本/目标归属和任务来源；名称、开始分支、模型、原生执行选项保留可修改性。沿用原生已有偏好，不假设原生没有记忆的字段已经会记忆，也不增加“每个 Issue 建树/一律复用目标树”的全局策略设置。用户若改变项目或宿主，重新校验业务关联；不能把旧上下文绑定到不匹配的工作区。

有唯一合适的同项目/同宿主目标树时，可在原生父工作树选择器中预选它，用户可改为其他合法父级或无父级；没有目标树时不预建。原生创建器已有父级选择，但当前入口没有完整业务预填，需要薄接入，不能声称只改一份配置即可。父级仅决定导航嵌套，不改变代码起始分支、合入方向，也不使已有任务自动重挂。实际父子关系按用户在原生创建器确认的结果存储。

相关的小 Issue 可以在目标工作区的原生会话里顺序处理；需要并行隔离、分别评审时，在任务屏分别开工并选择独立工作树。目标关联任务是上下文，不自动表示全部已开工。一个目标工作区覆盖多个任务时，不冒用原生单一 linkedIssue 字段；若要在任务行显示对应目标工作区，须保存明确的引用映射并接入同一打开动作。原生“采用已有分支”也不等于“在某个已存在工作树中新开会话”，分别沿其已有入口。

已确认当前版关联工作区时先提供“打开”；新开工进入原生创建器，避免重复创建或误开另一版同号 Issue。原型只展示创建器挂载位置、BW 带入项和原生提交后的结果，不复制第二套创建弹窗；支持演示采用目标父级与不设父级。

原生任务列表、详情、搜索、分页和开工 UI 继续复用；BW 适配完整版本/目标范围及工作区定位。计划内如 G3 / #385 保留快捷开工，也调用同一动作，不另造继续逻辑。目标/Issue 工作区打开完整原生界面，不附加自造任务右板。

参考官方文档后的设计判断：相关工作共享工作区、独立并行工作使用隔离树是可选安排，没有一条统一规则要求每个 Issue 必建树；不把外部工具做法直接当作 BW/Orca 的既有能力。来源：[VS Code 并行工作安排](https://code.visualstudio.com/docs/agents/guides/delegate-two-tasks)、[会话与工作区选择](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions)、[Claude Code 工作树](https://code.claude.com/docs/en/worktrees)。

### 目录、绑定、持久化与共享

三类数据分开：① 仓库材料中的版本/稳定 goalId/任务引用，是业务目录来源；② Orca 已登记的工作树、父子关系、会话与自动化，是执行记录；③ G2 新增的“项目、版本、用途、目标及任务引用 → 原生工作区身份”是连接两者的绑定。

现行 Orca 有持久化工作树元信息与 lineage，桌面 profile 的原生状态写入 `orca-data.json`；这不等于 G2 绑定已经存在。绑定优先扩展原生工作区附属信息并走既有宿主读写，不另建 BW 业务数据库。必须保留原生稳定身份和所属 runtime/host，不以分支标题、目录名或当前 UI 机器猜归属。

正常重启与共享访问读回同一绑定是实施验收要求，当前仅有源码依据，尚无 G2 真壳证明。Git clone 可以恢复已提交材料和目标目录，不能自动恢复另一台机器的工作树/会话；删除 profile、树或原生历史也不保证恢复。不能向用户承诺“任何情况下不会丢”。

共享/配对继续访问工作树的原宿主、同一份材料和原生记录，不因新增版本目录在访问者机器重建树。沿用项目访问与写权限，不重新配对、不改已有凭据或远端地址。新增绑定须在已有宿主授权通道读写；对端不支持时如实提示并保留原生访问，不降级成本机路径读写。

### 存量与在用流程的兼容要求

存量 schema3 版本从已有仓库材料可读，不要求为查看历史版本先预建两棵树，也不批量复制所有历史版本。已有计划/验收材料身份、固定引用及验收轮次保留。进入需要编辑的旧版时，再核对或准备本版工作区；共享旧树中未合入草稿应明确来源后导入，不覆写主干材料。

`bw/week-plan`、`bw/week-acceptance` 及其混合版本会话继续从项目原生工作区可达，不自动改名、搬目录、整树归到某一版或中断在跑会话。已运行自动化继续绑定原工作区；迁移条目须明确版本与用途并保留用户的启用、时间、工具/模型与会话复用设置，不能因侧栏切版改写运行目标。

共享主机配置、项目约定、总览、指标、知识库等共用能力继续由原功能维护。G2 改变了固定树定位与选版上下文，项目墙/总览对 `workbenchSelectedVersion` 和固定计划树的读取必须同步适配或保持明确旧上下文，不能仅宣称“不影响”。项目墙读数继续按明示版本计算，失败显示未知；不借机改其视觉设计或数据口径。

### 版本归档（复用 Orca 原生归档）

版本归档是版本生命周期收尾的显式动作：版本行“···”菜单提供“归档版本”，确认框如实列出本版在跑会话、未合入材料草案与仍启用的定时任务，经人确认后执行；不按 PR 合入、发布、任务全关或材料归档自动归档。

归档做两件事，不新增归档存储：把可选归档记录（归档时间与确认人；缺失或为 null 即未归档）写入版本计划材料，与其他材料写入同用 CAS 修订规则，跨机器一致、重启可重算；把本版计划/验收流程树经 Orca 原生工作树归档（`worktree.set` 的 `isArchived`）收起——原生侧栏与跳转面板隐藏、父级候选与任务关联匹配排除、原生工作区清理按“Archived”回看、可取消归档恢复。归档宿主立即应用该投影；其他宿主在下次访问该版本时对账，只处理原生树，不动会话与自动化。codex/Claude 的会话归档（active 列表隐藏、保留可回看）只作交互参照，不搬代码。

归档不级联归档目标/Issue 树（沿原生清理与父子语义各自处理），不删除任何树、会话或材料；归档≠删除，仍不做一键级联删除版本。已归档版本留在原版本列表位置、带“已归档”标识、默认收起；展开后总览/计划/任务/验收可进入回看，材料从 Git 归档来源读取，会话与工作树按原生状态如实呈现，不可用即不可用，不伪造恢复入口。编辑已归档版本需先取消归档并核对或准备本版工作区。取消归档清除材料归档记录并恢复本版流程树的原生可见列表；已有会话与定时任务不自动恢复。

归档不改写自动化条目（保留用户的启用、时间、模型与会话复用设置）；本版自动化仍启用时在确认框如实提示，是否停用由人在原生编辑器决定。归档后条目若到点触发，按原生树状态如实呈现，不静默恢复、不假报成功。版本总览把材料归档（archivePr 合入状态）、发布证据与版本归档状态分开呈现，不互相冒充。

### 版本总览、回看与必要验证

版本总览持续汇总承诺、任务事实、人工验收、发布与遗留，发布后成为同一版总结，不再手填报告。历史总结优先使用已归档 Git 材料与现有引用，不增加独立冻结操作或报告副本；后来的 Issue 变化不得悄悄改写当时验收。材料归档、PR 合入、发布、目标达成与版本归档状态分别呈现。不做一键级联删除版本或专门归档分区；版本归档只是标识与原生工作树归档，不是删除动作；原生删树须沿已有预检与父子语义，Git 材料可读不代表 agent 可恢复。

高保真重点路径：新建版本 → 两棵流程树就绪且无 agent → 右侧原计划按钮发起会话 → 侧栏点目标查看任务 → 目标菜单打开同一原生创建器 → 预填目标上下文 → Issue 原生创建器可采用或取消目标父级 → 提交后回显真实层级 → 切版后找回正确会话 → 旧版本材料及项目共用树仍可达 → 版本“···”菜单归档与取消归档，回看已归档版本。初始显示 v0.7（在制）与 v0.6（已归档回看）仓库材料快照，不预置空白 v0.8；用户可从“＋”创建 v0.9 体验新版本入口。全部树、会话、归档与创建过程为内存演示，计划编辑仍由既有计划屏负责；页面不伪造正式定稿状态。

实施验收至少覆盖正常重启读回、两个版本并行、同 Issue 跨版、目标改名/移除不丢树、旧共享树在跑会话、未合入草稿保留、配对宿主读写及权限拒绝、项目墙/总览版本与读数、版本归档读回与取消归档恢复、其他宿主归档对账。浏览器原型不能替代这些证据；生产接线与真壳证据见 STATUS。

### 极简操作与业界依据

能清楚表达动作的操作按钮优先图标化：版本旁 ＋、关闭、进入/查看、重置及顶栏评审工具。图标提供完整可访问名称、悬停和键盘聚焦提示，触达区域至少 24 × 24。项目、版本、目标、分支和会话名称保留为导航内容；菜单项（含版本归档与取消归档）保留文字以区分没有通用图标的业务动作。生产界面使用 Orca 既有 IconButton/Tooltip/菜单原语；此原型只模拟效果。该调整限定 G2，不擅自修改项目设计系统或重做其他特性的界面。

顶部书本图标打开“设计依据”，按“操作 → 参考案例 → BW 采用方式及边界”说明，并链接官方资料：

| 操作 | 官方参考 | BW 采用边界 |
|---|---|---|
| 图标动作 + 悬停/聚焦名称 | [GitHub Primer IconButton](https://primer.style/product/components/icon-button/guidelines/)、[Accessibility](https://primer.style/product/components/icon-button/accessibility/) | 只替换含义清楚的动作；不删导航名称 |
| 标题旁 ＋ 与少量必要输入 | [GitHub Primer Create](https://primer.style/product/scenario-patterns/create/) | 版本表单校验、失败保留输入；两树初始化不是外部案例规定 |
