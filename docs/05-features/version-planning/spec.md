## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

沿用 BW 侧栏总览、计划、任务、验收、自动化、知识库；计划、验收是独立入口。计划与验收完整复用 Orca 原生会话工作区：顶部新建会话和 Agent 控件、标签/分屏、资源管理器、智能体历史及可收起的工具侧栏均由 Orca 拥有。隐藏原生左侧项目/工作树列表，保留 BW 导航。BW 只在右侧提供业务板，在原生标签栏增加“新建计划”或“新建验收”；不另建聊天、历史或会话绑定。右侧直接编辑版本材料。版本是业务对象，周次是运行上下文；显示关联信息时版本在前，原生会话标题不强改。

每周自动化先启动本次原生会话，Skill 展示已有版本候选，由用户在会话确认本次沿用或新建的版本。右侧始终保留同一计划布局，未明确版本时各区显示空态，可直接用下拉框查看已有版本，不要求先有会话，也不自动创建或修改计划。不能按日期、文件修改时间、上次打开项或未发布状态推断本次版本。选已有版本读取其现有目标；只有用户明确新建才创建新计划。同版本的不同周仍各有会话，版本选择不再触发一次运行。

右侧只有一页：版本进展与风险卡片、当前版本 Top3 目标、页内展开的版本任务，以及一行归档入口。版本进展以上一版本验收纪要为来源，并保留所述版本；上版材料缺失时留空，不制造成绩。“上版验收”放在进展卡片内，便于核对原文。取消旧结果第一屏、第三屏页签和两个会议文本输入区。旅程轴保留图标和连线，用于定位对应正文；评审是 Builder 与 PL 讨论并直接修改目标，不由打开纪要承担，归档操作从正文卡片发起。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 产物 |
|---|---|---|
| 准备 | 先看完整流程和版本候选，明确本次版本；读取现状，交流场外要求，查必要的上版验收 | 明确的版本、有来源的进展、风险与约束 |
| 目标 | 直接编辑或与模型讨论结果，选择已登记指标并读取当前值，填写版本目标值 | 一份版本目标草稿 |
| 评审 | Builder 与 PL 开会，对着目标卡讨论并现场直接修改目标、交付约定和指标 | 评审后修订的目标原件 |
| 拆解 | 会话核对已有任务，按已认可范围创建或修改 Issue；右侧回显真实编号、标题、状态和关联目标 | 远端任务与版本关联 |
| 归档 | 点击归档将请求放入会话输入框；模型核对材料并按用户授权提 PR；人审核合入 | 可追溯的计划修订与 PR 状态 |

评审后的会议纪要整理是内容输出，不是评审前置。常见顺序是完成任务拆解与 PR 合入后，Builder 填写会议纪要时预览、复制当前目标派生的三段内容；也可以在评审后、拆解前复制。不为此新增流程阶段或强制检查点。

## 行为规则与异常

### 目标与指标

目标卡以一句可读的结果为主，目标、交付件和可选验收标准直接在卡片内编辑，不设铅笔入口或目标补充弹窗。没有指标承诺时，仅显示“添加指标承诺（可选）”选择入口；选取已登记指标后呈现原有读数与目标值行，可移除指标承诺。纯交付件目标不要求绑定指标，移除指标不删除目标、交付件或验收标准；更换指标清空旧目标值，避免不同口径沿用。交付件、指标和其他验收说明按需补充，不设置三类目标下拉或统一必填报告、点数、showcase。新特性、反馈优化、场景交付的引导放在 Skill references。Top3 用于聚焦；历史有更多目标时完整保留，不截断原承诺。

指标从项目共用目录选取，当前值只读，版本目标值可写；项目长期目标与本版目标分别显示。刷新调用总览的同一采集能力，显示采集时间与来源；无定义、无可用采集或失败时显示未知及准备入口，不把旧基线、0 或上一次其他窗口读数当成本期值。未就绪的数值目标标草案，不阻止保存其他内容，也不制造承诺已就绪的绿灯。

### 纪要、任务与返回

纪要严格遵循 [三节模板](../../../standard/skills/week-planning/assets/minutes-template.md)：本周 Top3 目标、周五交付件、数字指标变化。内容由当前目标、约定交付、指标目标及当前读数派生；缺项保留待明确，不添加无来源结论。目标标题旁的“预览纪要”打开含复制按钮的预览框，用于评审后的会议纪要填写，有可读取计划时即可使用，不强制等待任务拆解或 PR 合入，也不从点击行为推定评审通过。复制与预览一致，修改目标后重新生成；不读会议录音、不设手填纪要的第二正本。

版本任务在页内展开；“在会话中拆解”固定在任务卡片标题栏，收起时仍可操作，不在展开区重复“当前版本关联任务”说明。模型负责与用户讨论后创建/更新，页面读取真实 Issue；草稿不得显示假编号。点 Issue 复用 Orca 任务详情及其正文编辑、保存、错误提示和缓存回写。详情主返回按钮回到来处计划，保留项目、版本、草稿、会话、目标筛选和滚动位置；从原生任务列表打开时才返回任务列表。状态写入仍遵守 issue-state，关联任务不代表可以批量完成。

### 会话、保存与归档

沿用固定 bw/week-plan 工作树；验收另用 bw/week-acceptance。进入页面只准备并选中原生工作区，不自动创建会话；该树已打开的所有原生会话、活动标签与分屏直接可见。切换到其他工作区时不被 BW 强拉回。

“新建计划／验收”调用对应已登记自动化的原生手动运行，使用用户当前保存的提示、工具和模型，并自动打开、聚焦本次原生会话；定时运行仍在后台。普通原生新建会话不自动注入 BW Skill。首次登记默认关闭定时，按 creationKey 去重，已有条目不覆盖；“配置自动化”打开原生编辑器。每次新运行使用固定工作区、reuseSession=false，历史恢复和运行打开完全沿用 Orca。

旧格式或损坏材料只在右板顶部显示一行提示，点明实际版本与计划/验收数据文件，并附“在会话中处理”。点击新建原生会话，携带 SYSTEM、对应 Skill、具体文件和读取问题，沿原生就绪后发送通道自动递交；即使当前没有会话也可使用。模型先读文件、说明问题与备份/迁移方案，经用户确认后执行，不把点击按钮当成同意改数据。页面不保留专用迁移预览/确认弹窗或额外的旧结果入口；迁移工具及安全约束仍由材料服务和 Skill reference 承担。

保存是草稿持久化，不是评审完成。右侧与模型使用同一读写服务及修订条件；冲突保留双方内容，失败保留输入，不静默覆盖。切版本、离开页面、重启要可恢复，加载失败不能伪装为空版本。

删除“确认计划”按钮和旧三阶段确认门槛。人的评审决定可来自当前会话或真实 PR，不从“打开过纪要”推定已批准。归档动作不直接提交、不弹预览框；未聚焦可用聊天输入框时提示先从原生控件新建或打开会话，已起 PR 显示真实链接、检查和合入状态。归档遵循被管项目指定基线与原生默认分支配置，不能把 BW 自身的开发分支写成所有项目的永久基线。

同一版本只保留一轮活动计划，新周会话可以继续该轮材料，编辑不会改变轮次。该轮归档后可明确开启下一轮，沿现有目标调整；不支持同版本多轮未归档草稿。每次实际归档记录带 cycleId 与材料修订，总览按版本、实际记录提供三段摘要和原文；历史从固定 Git 提交只读回看，不保证每个自然周都有独立纪要。无记录明确为空，从历史返回恢复当前草稿。

旅程灯色：未开始或未读取灰；进行中、待核对、PR 待审黄；明确失败、请求修改或阻塞红；有对应完成依据才绿。可选字段空白不红，合入与目标完成是不同事实，未读取 PR 不冒充尚未创建。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| P01 | 计划独立单页，开场可见完整 SOP；1365×768 与 1280×720 可见三目标和任务汇总，缩放/长文本可继续操作，旅程轴不单独滚动 |
| P02 | 场外要求可进入目标；三种情形通过交流引导，不强制分类或填齐所有证据字段 |
| P03 | 指标与总览同定义、同窗口、同来源；只编辑版本目标，刷新、失败、未知与旧值有明确区别 |
| P04 | 纪要只含模板三节，编辑后的数据一致，复制内容一致，不补造事实 |
| P05 | 创建/复用 Issue 后真实回显；编辑原生详情后返回计划并保留上下文，失败不假报保存 |
| P06 | 计划与验收分树，复用全部原生会话、标签/分屏及侧栏；原生入口与 BW 入口查看同一工作区；普通新建不注入 Skill，专用新建走已登记自动化；未选择版本不写材料；空会话时数据问题入口也能新建并自动发送 |
| P07 | 自动化登记去重、保留用户设置；一次真实到点触发、失败与重试可追溯，不自动确认完成 |
| P08 | 手填与模型并发保存有修订冲突处理；重启、切项目、切版本后数据与文件独立读回一致 |
| P09 | 归档只准备会话请求；PR 真实状态决定灯色，待审不标失败，未合入不标归档完成 |
| P10 | 总览按版本、多周及固定归档修订读取计划/验收摘要，往返保留本版草稿；草案单列、坏历史不伪造 |

注册旅程 PJ01：进入计划 → 看 SOP 并交流场外要求 → 写目标/刷新指标 → 与 PL 评审并现场修改目标 → 建 Issue → 改描述并返回 → 会话提 PR → 人合入 → 预览并复制纪要用于会议纪要填写 → 重启独立读回。另覆盖评审后、拆解前复制同一份当前内容，不依赖任务或 PR 状态。PJ02 覆盖跨周自动化与同次恢复。验收用例和证据按 [六环](../../01-principles/02-working-backwards.md#62-六环交付链) 登记；原型检查不能代替真壳与真实模型旅程。

首用周记录需要重新澄清的目标及原因、因遗漏约束造成的返工、真实归档次数；先核对口径与基线，再决定是否登记为产品指标，不预填改善比例。

## 取舍与待决问题

保留会话与直接编辑，减少步骤和重复正文；代价是必须把保存、远端状态与人的认可分别呈现。交付件与指标不统一强制，但已承诺数值不能脱离采集依据。自动化只负责触发与恢复，具体启用安排交项目用户配置。
