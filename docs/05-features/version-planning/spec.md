# 版本计划规格

> 给设计、实现与验收者阅读。本文是版本计划的行为正本和可观察验收点。用户结果见 [intent](intent.md)，实现边界见 [design](design.md)，执行证据见 [STATUS](STATUS.md)。只记录当前行为、失败边界和未决决定。

## 适用范围与入口

版本计划是探索 BW 的工作旅程 W02“制定版本计划”的业务承接。W02 的五步是确定规划哪一版、定目标与验收标准、把目标落成任务、评审并归档、从计划开工。W02 的完整入口和演示结构见 [探索 BW 规格](../explore-workbench/spec.md#w02-制定版本计划)。

计划高保真形态见 [prototype.html](prototype.html)。`prototype.html` 和 `prototype/` 目录中的文件是原型资产，不是持久化、模型执行或远端写回证据。原型构建和视觉核验不改变本规格中的生产验收结论。

## W02 与旧旅程标识的对应关系

| 标识 | 当前含义 | 处理方式 |
| --- | --- | --- |
| W02 | 探索 BW 的主用户工作旅程，覆盖版本计划到开工 | 作为本特性的唯一主用户旅程入口 |
| PJ01 | 旧版“目标 → 评审 → 任务 → 归档 → 纪要 → 重启”名称 | 视为 W02 的主链别名，不再单独登记一条用户旅程 |
| PJ02 | 旧版“上版验收回顾 → 本版计划与恢复”分支名称 | 视为 W02 的计划准备和恢复分支，按风险验证，不新增主旅程 |

本特性最多登记一条用户旅程 E2E。验收点 E2E 只补充 W02 无法观察的高风险特性边界，当前入口和证据见 [STATUS](STATUS.md)。

## 行为

### 计划准备

新建版本先按版本目录规则定位紧邻前版，再查该版本的固定验收来源。已有计划优先使用材料中的 `summary.progressSource`，恢复时不自动替换来源。来源缺失时保留版本身份并显示空态，不回退更早版本，不把实时 Issue 状态当作验收结论。

固定来源存在时，计划准备只展示延期遗留和会议遗留。延期遗留来自验收材料中人工标记的 `issueMarks.carry`，会议遗留来自已人工确认的 `minutes.followups`。旧材料没有 `minutes` 时，兼容读取已确认的旧指导条目。来源缺失、身份不一致或字段未知时如实显示空、错误或未知，不推断“没有遗留”。

### 本版目标与任务

每个目标是一张可收缩卡片。卡片支持结果目标、验收标准、负责人、计划完成时间、可选指标承诺和关联 Issue。目标和验收标准可行内编辑，指标读数只读，未采集值显示未知或“—”，目标值显示为草案。没有指标承诺的目标仍可保存。

关联 Issue 按版本标签和标题中的目标段归属。Bug 标签显示 Bug，没有分类标签的任务显示 Feature，任务读取未就绪时显示未知，不以缺失标签猜测分类。无法解析目标段的版本成员进入未归类区域。删除目标会移除本版关联和对象批注，材料保存遵循同一修订条件。

### 计划助手与对象动作

计划助手是左侧 Orca 原生计划会话。页头入口只负责收折、展开或聚焦既有会话，不创建第二套聊天面板。拆解 Issue、整理纪要和发送板面批注均通过 Orca 原生发送弹窗携带对象上下文，由用户选择会话后发送。

板面批注支持目标句、验收标准、指标承诺、目标卡、Issue 行和板面级对象。批注在当前板面会话内保留，成功发送后清空已递交条目。纪要区域不参与对象批注。批注不直接写材料，纪要经人工确认后才成为材料正本。

### 会议纪要

会议纪要存储在计划材料可选的 `minutes` 节，正文只有“共识”和“遗留”两块。计划助手可以在未确认时整理或修改正文，人确认后冻结正文，撤销确认后才能继续编辑。旧 `closed` 字段只兼容读回，不提供逐项闭环控件，也不据此推断完成。

归档前，助手核对每条遗留已经落实到计划或结论，或者关联真实跟进 Issue。跟进 Issue 可以仍未关闭，页面不设硬门禁。整理纪要或填写正文不等于评审通过。

### 会话、保存与归档

计划和验收使用各自固定工作树与原生自动化。版本计划默认使用 `bw/<版本>/plan`，无绑定上下文时兼容 `bw/week-plan`。进入页面不自动执行 Git 操作，“更新代码”是显式同步入口。普通原生新建会话不注入 BW 提示，专用“开始计划”入口只预填可编辑请求，由用户发送。

材料编辑使用版本材料读写服务和 CAS 修订条件。冲突或写入失败时保留当前输入并提示处理，不覆盖另一方修改。重启、切版本或离开页面后按版本、项目、宿主和工作树重新读回材料。

归档由计划助手发起。页面显示材料中的 provider、仓库、PR 或 MR 编号和原生状态。读不到状态时保持未知。归档合入、目标完成和 Issue 关闭是不同事实，不能互相推断。

## 失败与未知边界

- 没有固定验收来源时保留来源身份并显示空态，不跳读其他版本。
- 任务、标签、指标或 PR 状态读取失败时显示未知或失败原因，不用缓存或默认值伪造事实。
- 材料身份或修订不一致时拒绝写入，保留用户输入并要求明确重试。
- 普通浏览、批注、填写或打开 PR 不替代人的目标确认和归档评审。
- `workflow.stage` 供会话和自动化校准，页面不渲染旅程灯，也不把 stage 当作完成权威。

## 用例入口与衡量

当前主用户旅程入口是 `tests/e2e/workbench/journeys/w02-cycle-main.spec.ts` 中的 W02 探索和版本计划主链测试。它可覆盖版本创建、计划入口、材料保存、重载读回和总览接续。真实模型会话、远端任务关联、CodeHub MR、真实会议转写和完整 PR 评审仍需在对应环境验证。

验收点 E2E 继续按每个特性最多一条控制。当前不新增第二条业务 E2E，也不把每个功能项拆成独立用户旅程。纯算法、材料协议和冲突处理回到 TDD 或集成测试。

## 未决问题

会议 ID 能否由 Leader 群组或 WeLink 自动取得，等待用户组旅程决定。指标目标值和指标读数仍须以总览指标的真实采集为依据。具体运行版本、环境、时间和结果写入 PR 验证评论或运行证据，不在本文维护流水账。
