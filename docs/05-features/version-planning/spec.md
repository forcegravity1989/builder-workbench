# 版本计划规格

> 给设计、实现与验收者读取；本文管目标行为与判据，工程边界见 [design](design.md)，价值见 [intent](intent.md)，执行证据见 [STATUS](STATUS.md)。行为变化时改对应主题，不记录开发流水。
>
> 状态：已合入并作为实施输入；新增或不确定行为须人工确认，实施证据见 STATUS。[第八版高保真评审包](https://github.com/forcegravity1989/builder-workbench/archive/f20f04ae57d510178c710c71216b9b734082c28e.zip) 下载后解压并打开 index.html，使用 BW 的真实版本材料；仅演示交互，不证明持久化、远端写回或自动化已实现。原型发布在永不合入的独立分支，链接固定提交。

## 范围与入口

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

沿用 BW 侧栏总览、计划、任务、验收、自动化、知识库；计划、验收是独立入口。计划保留左侧 Orca 分支会话、右侧直接编辑。版本是业务对象，周次是运行上下文；显示关联信息时版本在前，原生会话标题不强改。

每周自动化先启动本次原生会话，Skill 展示已有版本候选，由用户在会话确认或在界面选择已有版本、新建版本。未明确版本时右侧显示“待选择版本”，可以查看候选，但不新建或修改版本计划。不能按日期、文件修改时间、上次打开项或未发布状态推断本次版本。选已有版本读取其现有目标；只有用户明确新建才创建新计划。同版本的不同周仍各有会话，版本选择不再触发一次运行。

右侧只有一页：版本进展、风险上报、当前版本 Top3 目标，以及页内展开的版本任务。取消旧结果第一屏、第三屏页签和两个会议文本输入区。旅程轴展示完整 SOP，不设独立滚动条；准备、目标定位正文，评审打开纪要，拆解展开任务，归档准备会话请求。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 产物 |
|---|---|---|
| 准备 | 先看完整流程和版本候选，明确本次版本；读取现状，交流场外要求，查必要的上版验收 | 明确的版本、有来源的进展、风险与约束 |
| 目标 | 直接编辑或与模型讨论结果，选择已登记指标并读取当前值，填写版本目标值 | 一份版本目标草稿 |
| 评审 | Leader 阅读目标卡；三段纪要从当前卡片生成，可复制；讨论后改目标原件 | 修订后的目标，不再维护第二份会议正文 |
| 拆解 | 会话核对已有任务，按已认可范围创建或修改 Issue；右侧回显真实编号、标题、状态和关联目标 | 远端任务与版本关联 |
| 归档 | 点击归档将请求放入会话输入框；模型核对材料并按用户授权提 PR；人审核合入 | 可追溯的计划修订与 PR 状态 |

## 行为规则与异常

### 目标与指标

目标卡以一句可读的结果为主，交付件、指标和其他验收说明按需补充，不设置三类目标下拉或统一必填报告、点数、showcase。新特性、反馈优化、场景交付的引导放在 Skill references。Top3 用于聚焦；历史有更多目标时完整保留，不截断原承诺。

指标从项目共用目录选取，当前值只读，版本目标值可写；项目长期目标与本版目标分别显示。刷新调用总览的同一采集能力，显示采集时间与来源；无定义、无可用采集或失败时显示未知及准备入口，不把旧基线、0 或上一次其他窗口读数当成本期值。未就绪的数值目标标草案，不阻止保存其他内容，也不制造承诺已就绪的绿灯。

### 纪要、任务与返回

纪要严格遵循 [三节模板](../../../standard/skills/week-planning/assets/minutes-template.md)：本周 Top3 目标、周五交付件、数字指标变化。内容由当前目标、约定交付、指标目标及当前读数派生；缺项保留待明确，不添加无来源结论。复制与预览一致，修改目标后重新生成；不读会议录音、不设手填纪要的第二正本。

版本任务在页内展开。模型负责与用户讨论后创建/更新，页面读取真实 Issue；草稿不得显示假编号。点 Issue 复用 Orca 任务详情及其正文编辑、保存、错误提示和缓存回写。详情主返回按钮回到来处计划，保留项目、版本、草稿、会话、目标筛选和滚动位置；从原生任务列表打开时才返回任务列表。状态写入仍遵守 issue-state，关联任务不代表可以批量完成。

### 会话、保存与归档

沿用固定 bw/week-plan 工作树，展示其原生会话。每次新的每周运行创建新会话，恢复同一次运行继续原会话；验收另用 bw/week-acceptance，工作树与运行身份均分开，不按标题推断。手动入口与 Orca Automations 指向同一运行，不新增调度器。自动化后台启动不抢焦点；运行记录沿原生入口打开项目会话。从 BW 计划入口进入时，左侧恢复该次原生会话，右侧回填同份版本材料，不因入口不同新开会话。登记按项目和流程去重，已有启停、时间、时区与模型选择保留；首次配置由人选择，不静默启用定时工作。

保存是草稿持久化，不是评审完成。右侧与模型使用同一读写服务及修订条件；冲突保留双方内容，失败保留输入，不静默覆盖。切版本、离开页面、重启要可恢复，加载失败不能伪装为空版本。

删除“确认计划”按钮和旧三阶段确认门槛。人的评审决定可来自当前会话或真实 PR，不从“打开过纪要”推定已批准。归档动作不直接提交、不弹预览框；未连接会话时给出恢复入口，已起 PR 显示真实链接、检查和合入状态。归档遵循被管项目指定基线与原生默认分支配置，不能把 BW 自身的开发分支写成所有项目的永久基线。

同一版本只保留一轮活动计划，新周会话可以继续该轮材料，编辑不会改变轮次。该轮归档后可明确开启下一轮，沿现有目标调整；不支持同版本多轮未归档草稿。每次实际归档记录带 cycleId 与材料修订，总览按版本、实际记录提供三段摘要和原文；历史从固定 Git 提交只读回看，不保证每个自然周都有独立纪要。无记录明确为空，从历史返回恢复当前草稿。

旅程灯色：未开始或未读取灰；进行中、待核对、PR 待审黄；明确失败、请求修改或阻塞红；有对应完成依据才绿。可选字段空白不红，合入与目标完成是不同事实，未读取 PR 不冒充尚未创建。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| P01 | 计划独立单页，开场可见完整 SOP；1365×768 与 1280×720 可见三目标和任务汇总，缩放/长文本可继续操作，旅程轴不单独滚动 |
| P02 | 场外要求可进入目标；三种情形通过交流引导，不强制分类或填齐所有证据字段 |
| P03 | 指标与总览同定义、同窗口、同来源；只编辑版本目标，刷新、失败、未知与旧值有明确区别 |
| P04 | 纪要只含模板三节，编辑后的数据一致，复制内容一致，不补造事实 |
| P05 | 创建/复用 Issue 后真实回显；编辑原生详情后返回计划并保留上下文，失败不假报保存 |
| P06 | 计划 bw/week-plan 与验收 bw/week-acceptance 分树且运行身份分开；计划可先有会话、后由人明确版本，未选择不写计划；连续两周为不同会话，自动化原生入口与 BW 双栏入口恢复同次运行、不重复建会话，标题跟随 Orca |
| P07 | 自动化登记去重、保留用户设置；一次真实到点触发、失败与重试可追溯，不自动确认完成 |
| P08 | 手填与模型并发保存有修订冲突处理；重启、切项目、切版本后数据与文件独立读回一致 |
| P09 | 归档只准备会话请求；PR 真实状态决定灯色，待审不标失败，未合入不标归档完成 |
| P10 | 总览按版本、多周及固定归档修订读取计划/验收摘要，往返保留本版草稿；草案单列、坏历史不伪造 |

注册旅程 PJ01：进入计划 → 看 SOP 并交流场外要求 → 写目标/刷新指标 → Leader 评审 → 建 Issue → 改描述并返回 → 会话提 PR → 人合入 → 重启独立读回。PJ02 覆盖跨周自动化与同次恢复。验收用例和证据按 [六环](../../01-principles/02-working-backwards.md#62-六环交付链) 登记；原型检查不能代替真壳与真实模型旅程。

首用周记录需要重新澄清的目标及原因、因遗漏约束造成的返工、真实归档次数；先核对口径与基线，再决定是否登记为产品指标，不预填改善比例。

## 取舍与待决问题

保留会话与直接编辑，减少步骤和重复正文；代价是必须把保存、远端状态与人的认可分别呈现。交付件与指标不统一强制，但已承诺数值不能脱离采集依据。自动化只负责触发与恢复，具体启用安排交项目用户配置。
