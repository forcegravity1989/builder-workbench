# intent — 与「端口」同构的状态栏「常用链接」入口（quick-links）

> **状态：草案，待人 gate（2026-11-13）。** 来源 [#650](https://github.com/forcegravity1989/builder-workbench/issues/650)。本轮交付为**可点交互原型** [prototype.html](prototype.html)，不接真实数据。目标行为见 [spec.md](spec.md)，复用落点见 [design.md](design.md)，链状态见 [STATUS.md](STATUS.md)。
>
> **维护约定**：本篇给判断「端口之外要不要补一个常用链接快捷区、web-manager 的剩余价值到底是什么」的人读。价值、范围或 gate 结论变化时改正文，不追加聊天流水；不抄实现清单。

## 用户与问题

- **谁**：在本机同时开多个项目、经常回到同一批网页的 Builder。
- **场景**：开发时反复打开一批固定网页——内部设计规范、构建流水线、团队看板、正在跑的本地 dev server 页面。它们与当前项目强相关，但并不都是「本机在监听、可被端口面板识别」的服务。
- **现有做法为什么不够**：Orca 原生资源管理器 + 右下角「端口」面板已经能识别本机在监听的服务、并一键在内置浏览器打开，这块**不需要重做**。但纯网页地址（不监听端口的外部/内网页面、固定文档入口）没有归属：要开就得离开 BW 去浏览器书签里找，或手动敲地址；书签是全局的，不跟项目走，换项目时就混在一起。

## web-manager 的剩余价值 = 存储网页标签

本地 web-manager 的**识别本地服务**这一块，基本已被 Orca 端口面板覆盖（复用即可，不重建）。它真正多出来的、Orca 现在没有的能力是「**把一批常用的网页标签存下来、随手打开**」。因此本特性只取这一份增量：在端口面板之外补一个**项目级**的常用链接快捷区。

**明确的风险教训**：web-manager 自身的 PRD 记录过——v0.1 因为看起来像个「网页收藏夹」被批评，v0.2 才转向「本地环境控制平面」。所以本特性刻意**克制**：只存「名称 + 地址」、点击打开、就到这里；不探活、不自愈、不显示任何「状态灯」、不做书签分类树——避免退化成泛用书签管理器（即 PRD 警示的「收藏夹病」）。这与本仓「信号只能从数据推导，没数据就是 Unknown」的铁律二一致：常用链接本身不是服务，它没有可推导的健康信号，所以**不制造任何假的绿色状态**。

## 价值与依据

- **核心收益**：把「当前项目常用的几个网页入口」收进状态栏的常用链接面板、跟项目走、一键在内置浏览器打开；减少离开 BW 去全局书签里翻找的往返。
- **依据**：Issue #650（人提出并标注 Feature）；用户多轮澄清——Orca 端口面板已覆盖服务识别（复用、不重建），web-manager 的增量是存储网页标签，落点是「端口之外补一个常用链接」（2026-11 对话）。**2026-11-13 人评审进一步确定为「与端口同构」**：做成底部状态栏右端「图标 + 计数」入口，点开自己的 popover 面板，与 `PortsStatusSegment` 一致；先前「右栏子分区」与「独立窗口」两案均放弃。web-manager 侧「快捷区」与「服务」是两个物种的设计，见其 `docs/DISCOVERY-DESIGN.md` §14.2。
- **假设（标明）**：尚未有多个真实 Builder 的使用反馈；「项目级」是否比「全局 + 可分组」更贴合真实习惯、常用链接是否需要导入/导出，都还没有数据，属待验证。

## 目标体验

与 Orca 右下角「端口」入口**同构**：在底部状态栏右端放一个「**常用链接**」入口（图标 + 条目数），点开是它**自己的 popover 面板**——不塞进右栏子分区，也不另开窗口（人评审决定，2026-11-13）：

- 状态栏入口：图标 + 条目数，与端口入口并列；点击开合面板，同一时刻只开一个（与端口互斥）。
- 面板头：图标 + 「常用链接」标题 + 条目数 + 「添加」入口。
- 面板体：项目分组头（项目名 + 链接数）+ 链接行；行内主显示名称、次显示地址（主机 + 路径简写）。
- 点击该行即时在内置浏览器打开；hover 出动作簇：「复制 / 编辑 / 删除」（与端口行的 hover 动作同范式）。
- 「添加 / 编辑」表单：名称 + 地址；地址校验 http/https、不容忍账号密码、拒绝重复。
- 「打开」：点击该行即复用 BW 内置浏览器打开该地址（带修饰键转系统浏览器，与端口行一致）。
- 空态：无链接时给出「点添加」的引导。

**项目级**：链接归属当前激活项目，切项目看到各自的链接；重开 BW 仍在。

## 范围与边界

- **做**：底部状态栏「常用链接」入口（与端口同构）+ 其 popover 面板；名称+地址的增删改、复制、空态；点击复用内置浏览器打开；项目级持久化。
- **不做（明确边界）**：
  - 不重建端口扫描 / 服务识别 / 停止进程——已由 Orca 端口面板覆盖，本特性只在其旁的状态栏加常用链接入口。
  - 不对常用链接做探活、健康检查、自愈、状态灯——它不是服务，没有信号就不显示状态（避免「收藏夹病」与假绿灯）。
  - 不做书签分类树、标签体系、导入/导出、跨项目全局聚合（v1 边界，后续按真实反馈再议）。
  - 不另造浏览器打开通道，一律复用现有 `createBrowserTab` / 端口打开链。
- **相邻**：端口面板与服务扫描归 Orca 原生能力（本特性只读式复用，不改其协议）；浏览器内嵌页签归 Orca 浏览器能力。

## 成功判据与待决问题

**判据**：Builder 在某项目下添加一个链接 → 切到另一个项目看到的是另一个项目的链接 → 切回来原链接还在 → 杀进程重开后仍能读回（铁律一）；点「打开」在内置浏览器打开；常用链接区始终不出现任何健康/在线状态灯（无信号即不显示，铁律二）。

**待决**：
1. **持久化落点与格式**——倾向「项目级」小 JSON 配置文件（遵守本仓本地零业务数据库；不用 sqlite）。具体路径/字段见 [design.md](design.md)，**待人确认**。
2. **「项目级」的范围**——按 BW 激活项目，还是按仓库（repoId）？原型的说明按「项目」呈现，实现口径待定。
3. **是否需要导入 web-manager 已有数据**——首版不导入，仅手动添加；是否提供一次性导入待确认。
4. **面板内容取舍**——2026-11-13 起以「与端口同构」为准，原型的星标置顶、搜索框、分区折叠均已去掉（端口 popover 无这些）；若后续确需其中某项，再单列确认。
