# 版本会话管理：沿版本组织侧栏导航与工作区

> 给 Builder、Leader 和产品评审者读取。本文只定义为什么做、为谁做、范围和成功结果。行为与验收见 [spec](spec.md)，技术取舍见 [design](design.md)，当前证据见 [STATUS](STATUS.md)。用户价值或边界改变时更新，不追加讨论流水。
>
> 状态：版本业务边界及双列侧栏已确认。当前布局见 [高保真](prototype.html)，实现与验证缺口见 [STATUS](STATUS.md)。版本总览由独立特性维护。

## 用户与问题

[#383](https://github.com/forcegravity1989/builder-workbench/issues/383) 要让 Builder 从项目墙进入项目后，沿“版本 → 计划承诺 → 目标与执行 → 验收结果”组织交付。BW 帮用户判断为什么做、当前为哪版工作、按什么核对成果以及后来如何回看。多个版本可并行，切版不改变原有工作区和会话的归属。

## 价值与依据

新增的是业务导航与关联。用户可以从版本入口进入计划和执行工作区，看到版本、目标、原生项目、工作区和会话之间的归属。目标目录保留，目标工作树按需创建；正式承诺沿用人工评审与 PR 合入。版本级清理释放本机工作树与磁盘，但保留版本目录和材料回看。

## 目标体验

计划和验收继续使用现有业务板与 Orca 会话区。侧栏明确版本后，屏内不重复选版。每版保留计划、验收两棵固定流程树，目标与 Issue 开工复用同一原生创建器。需要隔离时再分别开工，不要求每个 Issue 建一棵树。绑定、改绑与解绑从同一原生右键菜单进入，解绑保留树、父子关系、文件和会话。

连接中断时保留原生状态表达和其他导航，不因一棵断链树丢掉整个版本目录。来源失败保持可见并支持重试，不把读取失败当成空目录。版本收尾沿 Orca 原生删除链执行版本级清理，默认处理本机 owned 工作树；材料和版本目录仍可回看。

## 旅程归属

本特性服务探索 BW 的 W02「制定版本计划」和 W03「构建交付」。W02 观察版本选择、新建、流程树准备和计划进入。W03 观察目标开工、工作区绑定、会话切换与恢复。W04「验收成果」由版本验收和版本总览特性维护，本特性提供上下文入口，不复制验收旅程。

## 范围与排除

项目总览、任务、工作树/父子、agent、自动化、知识库及共享宿主继续复用原生能力。版本工作区负责目录、业务绑定、流程树准备、版本上下文和版本级清理，不重建终端、会话租约、历史存储或任务完成状态。

不增加周冻结、目录生成按钮、独立快照协议、专门历史会话分区或统一工作树习惯设置。原型只表达布局和交互位置，不表示宿主通信、持久化、重启、双机或真实 provider 已交付。

## 成功判据

用户能够从现有项目入口形成版本承诺，进入正确计划和执行工作区，在多个版本间切换而不串归属，并按同版依据进入验收。版本收尾时一次版本级清理释放执行面资源，同时材料和目录保持可回看。判据依据为 [spec](spec.md)、[当前侧栏高保真](prototype.html) 和 [STATUS](STATUS.md)。
