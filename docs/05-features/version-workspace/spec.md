### 绑定、可见性与连接状态

[历史业务旅程原型](version-workspace-prototype.html) 演示以下业务行为；当前侧栏布局以[双列高保真](version-workspace-prototype-475.html)为准。关联 [Issue #439](https://github.com/forcegravity1989/builder-workbench/issues/439)。非性能项已作生产接线并补验 CI，证据见 [PR #441 验证报告](https://github.com/forcegravity1989/builder-workbench/pull/441)；性能增量目前仅作静态检视，实际耗时仍待测。真实持久化、断链恢复与双主机留白见 [STATUS](STATUS.md)。

- 新建版本表单只留项目、版本名、必要校验和“创建版本”；成功反馈只表达结果。
- 所有工作树都使用同一组原生右击绑定入口，包括版本下流程/目标/任务树、原生项目区的树及其子树；`issue-383` 子树不能例外。未绑定显示“绑定版本…”，已绑定显示“更改版本绑定…”和“解除版本绑定”，复用现有绑定选择器并预选当前树。动作作用于被右击的这一棵树，不隐式改父树或子树归属。移除版本级重复常驻“绑定已有工作树”按钮，不加批量绑定；原型也不能只为两棵示例树接菜单。
- 解绑仅清除版本归属；树、原生父子关系、任务关联、文件与会话保留，仍从原生项目区可达。没有会话的已绑定树照常出现在所属版本下。恢复沿 Orca 激活与历史会话机制，不新建 BW 恢复流程。
- 断链只在对应树保留 Orca 原生小图标。点击断链树沿原生激活机制，不叠加 BW 弹窗、toast 或就地解释；不清空版本目录、不让侧栏报错或崩溃，其他版本、本地树和导航仍可操作。连接状态来自原生宿主，尚未探测不能当断开。
- 版本区保留现有纵向滚动与无横向滚动形态，长目录最后一项须可达。

原型须能在每棵可见树上操作统一绑定菜单，演示绑定/改绑/解绑后的版本归属、原有父子关系和无会话树仍可见；包含 `issue-383` 子树，不能只用“复用 Orca”占位代替这些可观察结果。“模拟配对机断开”属于评审工具，演示原生小图标与其他导航不受影响；历史会话只标记原生恢复边界，不伪造恢复成功。这些操作不读写真实登记、宿主或会话。计划/验收仍整屏复用，通过链接查看各自高保真，不在本屏复制。

### 置顶栏目（#500）

- 复用 Orca 原生「已固定」栏目、树卡片与右键「固定 / 取消固定」，只把栏目移到版本模块上方；栏目跟随当前项目，保留该项目在各可见主机上的固定树，不混入其他项目，也不另造目标目录内置顶排序。
- 固定只改变原生 `isPinned`，不改变版本绑定、父子关系、文件或会话。解除版本绑定不清除固定态。
- 沿用 Orca 原生设置 `showPinnedWorktreesInGroups` 及其关闭的缺省：固定树默认只在「已固定」显示；用户开启后，原分组也显示同一棵树。版本目录内的实体树同样遵守该设置，逻辑版本、目标、计划和验收入口仍保留。
- 既有用户显式设置照常保留；BW 不另设置顶展示默认值。固定父树带入后代的行为、原生筛选和排序均由 Orca 承担。

### 双列侧栏（#475）

> 本节定义双列布局及其交互，复用 Orca 原生工作区工具。原型展示内存交互，真壳验证边界见 [STATUS](STATUS.md)。

- 布局为窄 Rail（全局入口）与第二列对象面板。第二列滚动内容依次为「已固定 → 当前项目版本 → 全部项目工作区」，使用同一滚动容器，不在原生树区域另设滚动条。
- 第二列顶部固定当前项目标题，右侧同一行放置 Orca 原生工具栏（查看活动 / 工作区选项 / 添加项目 / 新建工作区）。窄列优先保留工具按钮的完整点击区，项目名过长时截断。工具作用于原生工作区，菜单、按钮、设置和动作沿原生组件。
- 收起工作区栏只隐藏第二列。最左侧 Rail 保持可见可操作；原侧栏切换按钮和 Rail 的「版本工作区」都可在对象上下文恢复第二列。
- 第二列底部保留原生「显示活动工作区 / 工作区看板」；设置、帮助位于 Rail 底部。四个底部图标统一沿用 Orca 的 14px 图形和 24px 点击区。
- 版本区与已固定聚焦当前活动项目；已固定只显示当前项目的树，但保留该项目在各可见主机上的固定树，其他项目（含未纳入项目墙的个人项目）的固定树在切换为当前项目后显示。三块区域的实体工作区共用原生项目、宿主和可见性筛选规则，包括原生父子关系与可见性例外。版本目录候选包含已登记和检测到的绑定树，均按同一规则筛选；版本、目标和流程入口及绑定事实不受显示筛选改变，不将隐藏的树误判为缺失或触发补建。
- 点击任意项目的工作树或会话沿原生激活链切换当前项目，版本区随之更新；项目标题沿原生行为只展开或收起分组。项目墙仍只承载已纳入 BW 的项目，不承担全部原生项目的唯一切换入口。
- 第二列在版本／会话对象上下文显示；项目总览、普通任务、自动化和知识库使用整页。从全局模块点击「版本工作区」返回原生工作区内容；已处于版本对象上下文时保留当前页面。保留已有活动树和会话，不自动打开计划／验收、不准备工作树，也不重置版本展开态。
- 三块区域头部统一字号（13px）、行高（28px）、字重、原生前景色、图标槽位和左缩进。标题到首行及连续同级行复用原生 6px 间距。版本和项目行的收起箭头都在行的最右端，其他操作位于其左侧。已固定沿用原生可折叠标题，版本标题保留新建按钮。
- 版本区按现有顺序默认显示前三条。超过三条时，用「显示另外 N 个版本」展开余下条目，再点同处「收起更多版本」可收回。若从固定工作区、版本总览或其他入口进入第 4 条及以后的版本，自动展开余下条目并定位当前版本。折叠只影响显示，版本归属、去重与各版子目录的展开选择继续沿用原规则。
- 未调整展开状态时，在制版本和当前浏览版本默认展开；默认集合不写成用户设置。新建成功后展开该版本，保留其他版本的折叠选择。版本按钮支持原生键盘激活，列表自身的快捷键不拦截子按钮的 Enter。
- Rail 的任务入口直接复用原生任务按钮，只适配图标布局和对象上下文高亮；保留当前项目预选、悬停/聚焦预取及原生任务说明。
- 「全部项目工作区」默认把当前选中项目的完整分组放在第一位，其余沿用原生顺序；若项目在原生项目组内，保留组内结构，提升整个所属顶层分组。显式宿主分组保持宿主顺序。只做展示投影，不覆盖用户持久化的项目顺序。
- 排序复用原生选项与默认：按项目分组，项目默认手动，工作树默认最近活动。版本和目标目录保留业务顺序，目录内实体树沿原生排序；原生项目中的主工作树仍按原生规则置首。不把“最近活动”承诺为“最近一次聊天”，不新增 BW 排序器或设置页，也不覆盖已有用户选择。
- 高保真入口：[version-workspace-prototype-475.html](version-workspace-prototype-475.html)。评审工具提供跨项目示例和原生重复显示开关的内存演示；未展开的原生菜单标明复用，原型不证明宿主通信、虚拟列表、键盘定位或真实会话行为已验证。

### 价值与复用范围

Builder 从项目墙进入项目后，能按“版本 → 计划承诺 → 目标与执行 → 验收结果”持续交付：知道为什么做、从哪开始、正在做哪版、按什么验收、后来如何回看。BW 增加的是业务关联、范围、交付依据与总结；原生执行核继续承担实际工作。

版本区聚焦当前活动项目，项目标题只作标识。点项目墙卡片进入项目总览，不自动选择计划树、会话或初始化工作区。当前项目已挂到有效版本入口的树由版本区承载，原生项目区保留未归版与旧树；其他项目的树仍从原生项目区可达。固定树显示位置服从上文的原生固定策略。去重不依赖版本折叠或会话恢复；版本目录缺失的树保留原生入口，缺目标但版本有效的树留在版本下未分组区，隐藏父级下的未归版子树仅在展示上提升，不改实际父子关系。每个原生项目保留折叠、项目菜单与新建工作区入口，工具栏在第二列顶部只挂载一份。旧版本可展开回看，版本级清理仅删除工作树，保留版本目录与材料；不另设历史会话或已归档分区。

项目总览、计划、验收、任务、自动化、知识库及会话区继续复用。高保真展示导航、范围/动作的挂载位置；版本总览只标「沿用」，其 UI 由独立的 [版本总览特性](../version-overview/spec.md) 维护；本轮受影响的原生任务控件与创建器字段用可操作片段展示，其他既有业务板和完整会话用“沿用”标出，不复制另一套页面。计划/验收作为原有整屏沿用，包含 Orca 会话区及右侧业务板。G2 原型只标明整屏复用及版本上下文，不分别画会话区与业务板占位、不接管两区布局；原板发起会话的入口在原型操作区演示归属，不能据此当作新增产品按钮。分支卡片、agent、菜单、父子关系与激活沿原生能力；流程标签和挂载位置需要 BW 的展示/路由适配，不声称所有原生 UI 零改动。滚动样式沿 Orca，侧栏不出现横向滚动条。

### 新建版本与固定流程工作区

里程碑中的未来排期仅登记预期身份和日期，不创建计划材料或版本导航条目。用户主动「新建版本」时，已有同名排期沿用其 cycleId 与初始日期，否则新建身份；工作区准备完成后，即使目标尚未填写也显示该版本。旧版空占位按[里程碑实现设计](../overview-metrics/milestone-design.md)由项目一次性核对清理；版本目录不新增过滤规则，不按空目标或未来日期隐藏正常计划与历史验收。

计划树与验收树仍在新建版本时一并准备；两树就绪并读回本次主机的必要登记后进入计划屏。其他主机的工作树和项目目录随后独立刷新，不阻塞打开计划。

project、计划、验收和指标共用固定工作区准备规则：已有活树与本地分支优先；本地缺失时核实真实远端，同名远端分支唯一才定向拉取并沿该提交恢复，确认远端不存在才新建。PR/MR 是否存在不改变固定分支身份；常规 fetch 未覆盖该分支也不能当成不存在；恢复时仅补缺失的窄范围分支映射，保留既有 fetch 条目，保证后续原生 Fetch 与 Git 跟踪可用。显式排除或映射冲突需先核对配置。远端不可读或多个来源明确报错，不从主干创建空白树冒充恢复。版本用途仍以绑定为准，已绑定且改过分支名的树继续复用；已有未绑定或异版树不自动认领，已归档树需先在原生项目取消归档。重试复用已完成的步骤，不覆盖已有材料。实现边界见[会话与执行](../../06-module/会话与执行.md)。

“版本”旁提供“＋ 新建版本”，表单只保留项目、版本名、必要校验及“创建版本”；成功只反馈结果并进入计划。采用方式：由 Orca 准备本版独立计划、验收两棵稳定工作树，准备空白计划材料并打开既有计划屏。代表仓试验若示初始化成本不可接受，再评审验收树延迟准备，不私改当前方式。版本目录本身不创建实体父树；目标与任务树按需创建。计划、验收分别沿用 `.bw/planning/<version>/data.json` 与同目录 `acceptance.json`；验收材料在明确计划依据后准备，不因提前建树就生成结论。

创建不启动 agent、不启用定时、不自动创建 Issue、提 PR 或发布；未开始时各业务板只显示“开始计划 / 开始验收”短卡；原生运行会话实际打开后展示四区，计划目标为空也不等待模型才展开。已存在版本直接回显对应材料，版本从侧栏明确带入，板内取消重复选版；选中 agent 打开完整原生会话区及对应业务板。普通原生新会话不一律注入 BW 计划/验收提示。

计划与验收保留流程导航，下面的实际工作树直接复用原生卡片，单树与多宿主树均包含主机标识、会话、层级和菜单；分支名在原生详情/悬停中可见。一个版本可以有多个计划会话，但不会为每个会话再复制计划树。

版本名称沿用现有材料目录规则；重名不重复建版。两棵树未准备齐则显示未完成、保留输入及已有成功结果，核对原生登记后补齐；不自动删树回滚、不虚报成功。初次验收核对实际代码与交付候选，再走安全同步；分叉、未提交修改保留现场，不因建树较早就自动 reset。Git 对象通常共享，检出文件与初始化脚本/依赖/构建产物仍可能各占空间，不能承诺任意大仓库无成本。

### Issue 范围列表的读取与刷新

计划屏、验收屏的目标 Issue 引用共用同一来源的已读结果和在途请求；这些点读缓存保留。版本任务按原生标签查询与分页，不再锁定材料引用；目标任务仍投影完整目标引用集，按状态、标签、人员及标题/编号过滤后分页。首次没有读数时如实显示未知；已有读数先回显，再后台查询当前引用。计划/验收切目标只投影该目标引用，不能混入其他目标或版本；其材料保存、板内翻页与搜索不额外触发引用点读。原生任务页的搜索、筛选与分页仍按原生查询。手动刷新重新查询源头，正在读取时点击也不能被旧请求吞掉。

缓存只保留渲染进程内的 provider 结果，不写材料或新增业务数据库；重启重新读取。GitHub 沿现有支持域分组批量读取，失败或缺失项逐条补读；environment runtime 仍经所属 runtime 读取。CodeHub 沿原生 CLI 有界逐项读取。CodeHub 版本标签由服务端按 AND 匹配，沿原生每仓库 250 条上限读取；CLI 内部自动翻页，service 用 limit+1 推导 hasMore，仍有结果时提示缩小筛选范围，不冒充完整项目数据。目标引用点读不受列表上限截断。目标中的 @me 按每条任务对应仓库、托管站点及所属 runtime/WSL 读取当前用户；仅需要该条件时查询，身份读取失败明确提示，不借用本机或其他宿主账号，取消条件后恢复原生查询。目标关键词搜索明确限标题/编号，未支持的 GitHub 高级全文查询给出可恢复提示，不能冒充源端空结果。读取失败保持未知和原因，不能算作完成。验收 taskSnapshot 仅由当前完整引用集的新读数更新，缓存回显不生成新证据。

### 目标出现与计划定稿（用户已确认）

目标一经保存到计划就按稳定 goalId 呈现在“任务”下，草案/未核对与正式修订状态分别表达，不加“生成目标目录”按钮。目标名称、排序与引用从计划投影；显示目录不等于目标获批、已开工或达成。改名/排序不改工作区绑定；删除目标不能隐式删树，失去目标引用的工作区仍从原生项目工作区可达并提示待整理。

用户已确认把“本周固定”收敛为采用经过人工评审并合入项目基线的计划修订；本版跨周继续保留同一材料身份，不按日期自动冻结或另造计划。识别时必须核对实际已合入材料及其修订；workflow 阶段灯、PR 曾经合入、目录已有内容，都不能单独证明当前编辑稿已定稿。正式依据后又修改，呈现“有待确认修改”；读取失败保持未知。正式计划身份仍由人工评审与真实合入事实确定。计划尚未合入也可先开验收会话，助手先提醒并协助处理，不自动合入；验收材料仅能引用可读且身份核对一致的 committed 固定计划，无来源留空，不引入 draft planRef。

不新增周冻结、目录生成或额外确认操作，不新增一套快照存储和手填定稿状态。沿现有 Git 材料、评审与引用识别正式修订和后续变动；当前未实施的状态适配仍需验证。用户确认的理由是避免无实际用户价值的操作、存储和方案复杂度。

### 目标开工与 Issue 开工：同一原生创建器

**已确认：保留逻辑目标目录，目标工作树按需创建。** 版本“任务”仍打开完整原生任务页，进入时预选当前项目与 `bw:plan:<版本>` 标签；点具体目标，以该版本计划内的目标任务引用作为范围，首次显示全部状态；版本和目标在任务范围中标明，之后可用原生控件继续筛选。Issue/PR 切换、预设、仓库、标签/状态/人员筛选、搜索、刷新、分页、详情和开工保留，预选只作用本次进入，不改全局默认。移除目标回到本版任务；移除版本同时清目标，回到项目任务，面包屑与侧栏高亮随实际条件变化。列表查询不修改计划/验收的任务正本。现有任务引用仅支持 Issue，保留目标筛选时 PR 列表为空；移除目标可查询本版 PR，不根据同号 Issue 或其他推断聚合 PR。目标目录和版本目录都不是实体工作树。

Issue 开工仍从原生任务列表/详情发起。当前路径已经打开 Orca 的新建工作区弹窗，并预填任务来源、仓库和名称；已有明确关联工作区时可以直接打开。目标开工放在侧栏目标“···”菜单，复用同一个底层创建器：只带入已知项目、版本、目标、名称与父级建议，删除自动长备注和只为生成备注而做的完整计划预读；保留原生用户备注与 Issue 链接，不新增提示注入，不伪造一个目标 Issue、不绕过弹窗直接创建树，不新增单独的 BW 多步骤向导。

BW 必须补齐正确的项目/宿主、版本/目标归属和任务来源；关联 Issue 的侧栏树自动名称稳定显示“#编号＋完整 Issue 标题”，分支放在悬停或详情，显式手工改名优先；复用已保存的标题，不额外查询、不改分支或目录、不批量改存量名称。名称、开始分支、模型、原生执行选项保留可修改性。沿用原生已有偏好，不假设原生没有记忆的字段已经会记忆，也不增加“每个 Issue 建树/一律复用目标树”的全局策略设置。用户若改变项目或宿主，重新校验业务关联；不能把旧上下文绑定到不匹配的工作区。

有唯一合适的同项目/同宿主目标树时，可在原生父工作树选择器中预选它，用户可改为其他合法父级或无父级；没有目标树时不预建。原生创建器已有父级选择，但当前入口没有完整业务预填，需要薄接入，不能声称只改一份配置即可。父级仅决定导航嵌套，不改变代码起始分支、合入方向，也不使已有任务自动重挂。实际父子关系按用户在原生创建器确认的结果存储。

相关的小 Issue 可以在目标工作区的原生会话里顺序处理；需要并行隔离、分别评审时，在任务屏分别开工并选择独立工作树。目标关联任务是上下文，不自动表示全部已开工。一个目标工作区覆盖多个任务时，不冒用原生单一 linkedIssue 字段；若要在任务行显示对应目标工作区，须保存明确的引用映射并接入同一打开动作。原生“采用已有分支”也不等于“在某个已存在工作树中新开会话”，分别沿其已有入口。

已确认当前版关联工作区时先提供“打开”；新开工进入原生创建器，避免重复创建或误开另一版同号 Issue。原型展示原生创建器受影响的名称、Issue 链接与空白可填写备注，以及提交后的归属结果；保留父级选择演示，不定义第二套创建流程。

原生任务列表、详情、搜索、分页和开工 UI 继续复用；BW 适配完整版本/目标范围及工作区定位。计划内如 G3 / #385 保留快捷开工，也调用同一动作，不另造继续逻辑。目标/Issue 工作区打开完整原生界面，不附加自造任务右板。

参考官方文档后的设计判断：相关工作共享工作区、独立并行工作使用隔离树是可选安排，没有一条统一规则要求每个 Issue 必建树；不把外部工具做法直接当作 BW/Orca 的既有能力。来源：[VS Code 并行工作安排](https://code.visualstudio.com/docs/agents/guides/delegate-two-tasks)、[会话与工作区选择](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions)、[Claude Code 工作树](https://code.claude.com/docs/en/worktrees)。

### 目录、绑定、持久化与共享

三类数据分开：① 仓库材料中的版本/稳定 goalId/任务引用，是业务目录来源；② Orca 已登记的工作树、父子关系、会话与自动化，是执行记录；③ G2 新增的“项目、版本、用途、目标及任务引用 → 原生工作区身份”是连接两者的绑定。

工作树、父子关系和会话由 Orca 原生登记维护，G2 绑定扩展工作区附属元信息。绑定可见性只依赖登记和版本归属，不依赖会话是否打开或恢复；读写沿既有宿主授权，不另建业务数据库，保留稳定身份与所属 runtime/host，不以分支标题或当前 UI 机器猜归属。

正常重启与共享访问必须读回同一绑定；#439 的全树右击、解绑保留会话与断链增量目前只有静态源码证据，旧 G2 真壳记录不能替代本轮复验。Git clone 可以恢复已提交材料和目标目录，不能自动恢复另一台机器的工作树/会话；删除 profile、树或原生历史也不保证恢复。不能向用户承诺“任何情况下不会丢”。

共享/配对继续访问工作树的原宿主、同一份材料和原生记录，不因新增版本目录在访问者机器重建树。沿用项目访问与写权限，不重新配对、不改已有凭据或远端地址。新增绑定须在已有宿主授权通道读写；对端不支持时如实提示并保留原生访问，不降级成本机路径读写。

### 存量与在用流程的兼容要求

存量 schema3 版本从已有仓库材料可读，不要求为查看历史版本先预建两棵树，也不批量复制所有历史版本。已有计划/验收材料身份、固定引用及验收轮次保留。进入需要编辑的旧版时，再核对或准备本版工作区；共享旧树中未合入草稿应明确来源后导入，不覆写主干材料。

`bw/week-plan`、`bw/week-acceptance` 及其混合版本会话继续从项目原生工作区可达，不自动改名、搬目录、整树归到某一版或中断在跑会话。已运行自动化继续绑定原工作区；迁移条目须明确版本与用途并保留用户的启用、时间、工具/模型与会话复用设置，不能因侧栏切版改写运行目标。

共享主机配置、项目约定、总览、指标、知识库等共用能力继续由原功能维护。G2 改变了固定树定位与选版上下文，项目墙/总览对 `workbenchSelectedVersion` 和固定计划树的读取必须同步适配或保持明确旧上下文，不能仅宣称“不影响”。项目墙读数继续按明示版本计算，失败显示未知；不借机改其视觉设计或数据口径。

### 版本级清理（复用 Orca 原生删除）

版本收尾不设归档隐藏层：旧版本默认收起、可展开回看，即为退休形态；零散树与会话归原生 全部项目工作区，G2 不管。唯一收尾动作是版本级清理：版本行删除图标打开确认对话框（提示词与 Orca 删除对话框同口径），经人确认后沿与右击单树删除、工作区清理对话框同一条原生删除链逐棵执行，复用原生预检（未提交修改、子树、归档 hook）与权限复核，不另造删除路径。

确认对话框默认勾选**本机 owned** 的该版工作树（流程/目标/任务树）；他宿主 owned 的实例列出并标注 owner、预检状态与在跑会话数，默认不勾选；已知断链实例不可提交删除，在线实例显式勾选表示经共享通道在归属宿主删除该树，派发前复核配对权限。预检不过的树按原生规则阻塞或显式豁免，不静默跳过。

删除只改执行面：磁盘检出与原生登记（含挂在该登记上的 BW 绑定）一起消失；Git 材料与版本目录条目保留，删除后总览/计划/任务/验收仍可打开回看，工作树/会话列由登记实际缺失推导、如实显示不可用，不向仓库写任何“已删除”记录。任何路径删树后，版本/目标目录不得残留悬空绑定引用。agent 会话记录归各 provider，树消失后如实显示不可用，与 Orca 一致。版本材料老化属仓库治理课题（人走 commit/PR），与本按钮不耦合；G2 不提供“删除版本”级联动作。

清理不改写自动化条目（保留用户的启用、时间、模型与会话复用设置）；本版自动化仍启用时在对话框如实提示，是否停用由人在原生编辑器决定。树已删除后条目若到点触发，按登记缺失如实呈现，不静默重建、不假报成功。版本总览把材料归档（archivePr 合入状态）、发布证据与工作树可用性分开呈现，不互相冒充。

### 版本总览与必要验证

版本总览的已实现基线、重设计与验收判据由独立 [版本总览特性](../version-overview/spec.md) 承接。工作区提供版本上下文、导航与原生工作入口，进入总览不激活工作树。删除树不删除版本材料，历史继续可达。

工作区验证仍覆盖重启读回、两个版本并行、同 Issue 跨版、目标改名/移除不丢树、旧共享树会话、未合入草稿保留、配对宿主与权限、版本级清理预检和他宿主实例。浏览器原型不能替代这些证据，运行结果见 STATUS。
