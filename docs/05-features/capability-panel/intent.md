# Intent · 设置屏收成全局面板

> **30 秒导读**:这是什么——把「这台机器装了什么、Workbench 能干什么」全部收进**顶层设置屏**,排法照抄 Claude 桌面版的设置面板:左栏搜索 + 分节,列表点进去是带「← 返回」的整页详情。同时把**本来就是全局、却被摆在项目屏里的开工工具映射**挪回它该在的地方。给谁看——过意图 / 规格 gate 的人。现在作数吗——**待意图 gate**(2026-09-08 提出,2026-09-09 改版)。
>
> **目录名沿用 `capability-panel`**(立项时叫「能力面板」),内容已经从「配置屏的一块」长成「整个设置屏」,名字不改以免链接漂。

**发起人**:产品会话 2026-09-08 提出,2026-09-09 拿 Claude 现行设置面板重定方向。**状态**:待意图 gate。

## 痛点

**① 有一块设置在骗人。** 「开工工具映射」(哪类活用哪个工具)今天长在项目内的配置屏上,页头写着项目名。但它存的是 `settings.toml` 的 `tools` 表——**键是类别,没有项目维度**([settings.rs:29](../../../crates/bw/src/local/settings.rs));写入侧收到 `project_id` 直接下划线丢掉([tools.rs:16](../../../crates/bw/src/app/tools.rs))。也就是说:在项目 A 里把「构建」改成 Cursor,项目 B 也一起变了,界面上一个字都没说。这不是「要不要挪」,是它本来就在全局,界面把它放错了地方。

**② 工具被劈成两半。** 「用哪个」在配置屏,「在不在」在设置屏。最直接的后果:原型类活的产品默认工具是 Open Design,而本机 Open Design 起不来——这两件事写在两个屏上,人不跑到设置屏就不知道原型类根本开不了工。

**③ 探活把「没人用它」画成红色。** 六项探活红了四项,而这台机器上真正在用的 claude 和 gh 都在。界面每天自称三分之二坏了,人于是学会不看它——红色一旦不可信,真出事那天也没人信。

**④ 一行说完就没了。** 「本机路径里找不到 codehub-cli」之后没有任何下一步:它是干什么用的?谁会用到它?不装会怎样?界面全不说。

**⑤ 技能表印了两份,而且看不见里面。** 配置屏一份、知识库资产页签一份,同一个函数渲染两遍。更要紧的是:技能包本来就不止一个文件——week-planning 带着一个校验脚本(sidecar),mattpocock-skills 还挂着一整棵 vendor 库——今天界面上完全看不见。

**⑥ 开工真正注入 agent 的第三样东西看不见。** 每张活开工会按类别注入几份规范(指标铁律、改仓规则、`.bw` 现行契约),界面上一个字都没有。人不知道自己派出去的 agent 被告知了什么。

**⑦ 插件与 workflow 在界面上根本不存在。** 仓里 vendor 了**两个**技能库:`mattpocock-skills`(41 件,构建 / 优化 / 运维的默认 workflow 就出自它)和 `mohit-pm-claude-skills`(2 件指标技能)。后者 **vendor 了却没有任何 workflow 引用**——界面上看不见,所以没人知道。五个阶段各挂哪条 workflow(原型和运营推广空着、`proto-design` 源还没 vendor)同样看不见,今天只作为「开工工具」行的一句副文一闪而过。

**⑧ Orca 被当成一个输入框。** 开工会话真正跑在 Orca 里、三条运作节律的钟也在它上面,但今天它在界面上只是「本机」一节里一个填 URL 的格子:填了就当好了。而词表「探活」那条明写着 `_Avoid_`「把配置填好了当成连接通了」——Orca 恰好踩在上面,而且**它根本没有探活实现**([tools.rs:143](../../../crates/bw/src/app/tools.rs) 的 probe 只认 claude / cursor / open_design / welink)。

**⑨ AI Coding 资产观测不了。**(同事评审)外部希望能看清这些资产在各个被管项目里的分布——**Workbench 带给项目的** vs **项目自己的**,connector / skill / agent / workflow 都算。今天:skill 有「自带 / 项目自有」这一层但没有「哪个项目在用」的维度;connector 是本机的、没有项目维度;**agent 这一类 BW 完全没有**——全仓没有任何代码扫 `.claude/agents/`。

**⑩ `standard/` 下的技能催熟不了。**(同事评审)自带那几份都是拍脑子定的初稿,后续没被有效优化过。面板今天只有「用过几次」,没有「有多久没动过」——「用过 12 次、一次没改」这种催熟缺口显不出来,所以没人知道该改哪一份。

**⑪ 用户自己的 workflow 接不进来 —— 而且界面在说谎。**(发起人 9-10)每个项目会基于自己的资产和开发 loop 长出**自己的一套 loop 能力**,那才是它真正要的 workflow;Workbench 预置在 stage 上的(mattpocock-skills)是通用默认,不是它要的。但今天用户**没有通道**把自己的接进来——`skill_pointer` 三道门,每道都把项目自有的挡在外面([bootstrap.rs:339](../../../crates/bw/src/app/bootstrap.rs)):

1. `skill_slug(workflow)` 是硬编码 `match`,只认三个名字(运作活①②、`mattpocock-skills`),其余一律 `_ => None`;
2. 就算过了第一道,也只在 `standard::skills::all()`(编进二进制的 5 份)里找;
3. 路径只拼 Workbench 自己的资产目录,**根本不看被管仓的 `.claude/skills/`**。

**连带一个真 bug**:`skill_list` 的用量匹配是 `w == slug || skill_slug(w) == Some(slug)`,第一条会让**活上挂的名字和仓里目录名对上就计数**。于是界面显示项目自有技能「用过 N 次」,而开工时 `skill_pointer` 返回 `None`、那一段提示词根本不存在——**界面说注入过,实际一次都没注入**。

**⑫ AI Assets 和知识管理分层脱节。**(发起人 9-10)开工时 agent 实际会读到**三层**:被管仓自己的 `AGENTS.md`(提示词写「动手前读」)、Workbench 按类别注入的 references、活挂的剧本。我只把中间那层做成了 AI Assets,于是这一节答不了「这个 agent 到底会读到什么」。更远的:知识分层正本 [`01-document-organization.md`](../../01-principles/01-document-organization.md) 里写着 `.teamai/`「团队 harness 分发(skills / rules / hooks / MCP)」——那是 AI 资产的成文落点,面板里完全没有;项目自己的 `CONTEXT.md` / `docs/` 同样不在。

**⑬ 设置屏是一张长条。** 目录 / Orca / 配色 / 工具探活四节从上往下堆,没有导航、没有搜索。加一节就更长一截。

## 解决方案(体验语言)

**顶层设置屏排成一个左栏面板**,和 Claude 桌面版的设置一样:顶上一个搜索框,下面按节分组,右边是当前那一节的内容。

```
搜索设置
  本机 ── 目录 / 外观
  能力 ── Connector 7 / Skills 7 / Stage 5 / Plugins 2 / AI Assets 5
```

**列表点进去是整页详情,左上角「← 工具」返回**——不是弹窗、不是抽屉。这是抄得最实的一刀:BW 的工具和技能都有话要说,一行副文说不完。

- **Connector 详情**:名字 + 类型 + 路径,右上角是状态和「重新探这一个」。正文说清**它给 Workbench 供什么能力**——claude 供开工与注入、`gh` 供读活开 MR 与合入读回、Open Design 供原型类活的内嵌网页、Orca 供会话与节律。红的那个再加一节「怎么修」。
- **技能详情**:名字 + 出处(「Workbench 自带 · 编在二进制里」/「项目自有 · 来自 workbench 仓」)+ 用过几次。两个页签:**概览**(什么时候注入、正文为什么不进提示词、它会不会再指别的)和**文件 · N**(左边文件列表、右边正文,可切渲染 / 源码)。week-planning 在这里是「文件 · 2」,因为它真有两个文件。

**Skills 一节**顶上的色条按**催熟状态**分:用过但没改过 / 改过 / 还没用过;卡片上写「用过几次 · 改于哪天」,排序可选「按最久没改」——把「用得多却从没优化过」的那几份顶到前面。

**AI Assets 一节**改成回答「**这张活开工时,agent 会读到什么**」:第一行是项目自己的 `AGENTS.md`(标「项目」),下面是 Workbench 按类别注入的几份,可按来源筛。表下如实写缺口:项目自己的只有 `AGENTS.md` 一条、而且只是被指了一下,`CONTEXT.md` / `docs/` / `.teamai/` 都不在。

**Skills 一节**把「项目自有」那几张卡标上 **注入不了** —— 这不是设计,是今天的实况,界面必须先停止说谎。

**Connector 详情**对没装的给**怎么装**:仓里有据的直接给可复制命令(welink-cli 是 npm 全局装 + 自己 `auth login`),没据的如实写「装法仓里没记」并说清判据(PATH 上有这个名字就算装上)——不写一句重复列表页的废话。

**Stage 一节**:一行一个阶段,三件事摆一起——**用哪个执行器跑**(可改,下拉就在行里)、**按哪条 workflow 干**(产品默认)、**会注入哪几份 AI Assets**。行尾状态直接说这个阶段现在**能不能开工**。**插件一节**:两个 vendor 库的上游 / 版本 / 许可 / 技能数 / 谁在用——`mohit-pm-claude-skills` 那行明写「没有 workflow 用它」。**资产一节**:开工注入的规范只读表。

**界面文字压到最短**:每页顶上一条**状态色条 + 一行计数**代替整段说明,详情页用两列 `kv` 而不是句子。「为什么这么设计」一律移出窗口,进 spec 与在线原型的窗外卡片——那是给 gate 看的,不是给用界面的人看的。

Connector 页把「哪类活用哪个执行器」和 connector 表并排放:选哪个工具的下拉旁边直接显示那个工具在不在。红色改成只留给「有活会用到它、它不在」;没人用到的写「还没用上」,中性色——按这个口径同一台机器只剩一行红。

**明确不做**:没有 Discover、没有市场、没有安装数、没有「添加」按钮、没有每项开关。BW 的工具装在你的系统里,技能是把文件放进仓里——都不是「装一次」的东西,也没有别人的安装数可显示。给一个假的开关比不给更糟:真正决定注入什么的是活挂的 workflow。

## 配置屏留什么

能力这块搬走之后,项目内的配置屏留**真正跟项目走**的三样——远端、项目群、节律。这三样 `ConfigVm` 今天**已经算好了却一行没渲染**(`remote` / `chat_*` / `cadence` / `crons`)。所以这不是新增,是把已有的东西摆对位置。

## 飞轮检验(对齐 03)

- **加强哪一截**:「可信所以敢放手」。人一眼知道这台机器能干什么、缺什么、缺的怎么补;红色重新变得可信;界面不再把全局设置伪装成项目设置。
- **不把人拽回搬运工**:不引入安装流程、不引入市场浏览。工具还是装在系统里,技能还是放在仓里,面板只负责如实说出来。
- **不破坏铁律**:纯读 + 重排,不碰状态机、不碰现算、不碰「完成由人点」。探活与技能表本来就是现算,没数据仍显示未知,不猜。

## 约束

- **不新增屏**。八屏不变;设置屏内部重排,深链 `BW_VIEW=settings` 不变。
- 不做安装 / 开关 / 市场 / Discover / 安装数。
- 不改内核数据模型:探活、技能表、references 三样今天都算得出来。
- 知识库资产页签删掉重复的技能块,不留兼容双份。

## 开放问题

1. **agent 这一类要不要进面板。** 同事点名的四类资产里,connector / skill / workflow 面板都有了,**agent 一类 BW 今天完全没有**(没有任何代码扫 `.claude/agents/`)。进=新增一条数据链路,不是重排。
2. **「哪个项目在用」这个维度要不要做。** 面板是全局的,但要回答「这份 skill 在哪几个仓里」得跨所有接入项目各扫一遍,扫的时机与成本要定。
3. **插件和 workflow 是一件事还是两件事。** 今天 `mattpocock-skills` 既是插件名又是 workflow 名,很容易当成同义——但那是巧合:一个插件可以出多条 workflow(mattpocock 里 41 件技能今天只组了一条 SOP),一条 workflow 也可以不来自任何插件(四份运作剧本是 Workbench 自己写的)。原型按**两节**做:插件是来源,workflow 是挂在阶段上的那条 SOP。**发起人尚未定**,这是本特性最需要拍的一条。
4. **「AI Assets」这一节要不要进本轮。** 它是唯一一块新增界面,工具和技能都是把已有的东西摆对位置。倾向进——今天人完全看不见派出去的 agent 被告知了什么。
5. **配置屏这一轮动不动。** 能力搬走后它只剩两块空壳(映射搬走、技能搬走)。倾向本轮只搬走、不重建,把「配置屏改成远端 / 项目群 / 节律」另开一件——否则这件事一次要动两个屏。
6. **要不要给 Orca 加一次真探活。** 放进 connector 之后它的状态只能写「配了 / 没配」,写不了「通不通」——因为没有探活实现。加一次探活是新增行为,本轮倾向不加、如实标着;但这一行会一直是半个答案。
7. ~~设置屏要不要留工具摘要行~~ —— **已消解**:connector 整块就在设置屏里。
