# Spec · 配置屏收成「能力面板」

> **30 秒导读**:配置屏排成三组(工具 / 技能 / 注入规范),把设置屏的工具探活整块搬进来、和类别映射并排,知识库删掉重复的技能块。红色改成只对「有活会用到、却不在」的工具生效,红行给出可复制的修法。可点原型 [`prototype.html`](prototype.html)。**状态**:待规格 gate(意图 gate 之后)。

对应 intent:[`intent.md`](intent.md)。

## 1. 版式(照抄 Claude 的 Customize 面板)

配置屏内分两列:**左栏一列分组,右栏一个内容面板**——就是 Claude Customize 的排法。

| 左栏 | 右栏那一页装什么 | 今天在哪 |
|---|---|---|
| **工具** | 开工工具(一行一类别)+ 本机工具表(带「类型」列) | 配置屏 §① + 设置屏「工具探活」 |
| **技能** | 技能卡片网格(唯一一处),点开是详情弹窗 | 配置屏 §② + 知识库·资产页签 §1(重复) |
| **规范** | 开工注入的 references(只读表) | 界面上不存在 |
| ─ 分隔 ─ | | |
| **设置** | 目录 / Orca / 配色 | 顶层设置屏(整块搬进来) |

**设置挂在左栏底部**,和 Claude 一样——能力和偏好在同一个入口里答完。顶层那个独立设置屏因此撤掉,intent 痛点 6「设置屏混着两类东西」直接消失。

每页的页头也照抄:**页名 + 搜索框 + 页级动作**(工具页那颗动作是「重新探一次」;技能页没有动作,因为 BW 没有可执行的「添加」)。页头下面一条过滤条:左边一组状态 / 来源分段,右边排序。

行与表的写法仍走设计系统:设置文法(`set-group` / `set-row`)、表格(`table`)、卡片(`card`)、弹窗(`dialog`)、分段(`seg`)。**结构抄 Claude,视觉仍是 Builder**——和 9-07 那批抄 Codex 设置文法时同一个口径:抄排法,不抄它的黑主按钮和字号。

## 2. 工具页签 · 操作逻辑

### 2.1 开工工具(一行一个类别)

五行:原型 / 构建 / 优化 / 运营推广 / 运维。每行:

- 左:类别名 + 一句副文,写这类活的 workflow(产品默认,不可改)。
- 右:工具下拉 + 「保存」 + **该工具此刻的状态点**。

**主路径**:改下拉 → 点保存 → 存本机 settings → 状态点立刻按新工具重算(不重新探活,读已有探活结果)。

**分支**:选了「—(未定)」→ 状态点不显示,副文写「未定,开工会用产品默认」。

**出错**:保存失败照旧走回执 toast,原话不藏。

### 2.2 本机工具(一张表)

照抄 Claude connectors 那张表的列法(它是 Connector / Type / Status):

| 列 | 写什么 |
|---|---|
| 本机工具 | 名字 + 副文(找到就是路径;没找到就是原话) |
| 类型 | 本机 CLI / 本机服务 —— 失败原因与修法按类型分,今天六行长一个样把三种问题压成一句「没找到」 |
| 谁用到 | 哪几类活映射到它,或「没有类别用到」 |
| 状态 | 已找到 / 开不了工 / 还没用上 / 还没接 |
| — | 红行与「还没用上」行的「怎么修」,展开在下一行 |

表头上方一组过滤(**全部 / 开不了工 / 已找到 / 还没用上**,各带条数),页头有搜索框。两者都只作用于这张表,上面的「开工工具」不参与过滤——和 Claude connectors 页「Popular for…」那块不参与过滤同形。

**着色口径**(本特性的核心改动):

| 情形 | 状态 | 颜色 |
|---|---|---|
| 有类别映射到它,且探到了 | 已找到 | 绿 |
| 有类别映射到它,没探到 | **开不了工** | 红 |
| 没有类别映射到它,探到了 | 已找到 | 绿 |
| 没有类别映射到它,也没探到 | **还没用上** | 中性灰 |
| 这项探活还没接 | 还没接 | 中性灰 |

红色从此只意味着一件事:**有活要用它、它不在,现在就会挡住开工**。

> 注:`gh` / `codehub-cli` / `welink-cli` 不出现在类别映射里(它们是远端臂与群通知,不是开工工具)。它们按「这个项目的远端配的是哪一家」判:配了 GitHub 就看 `gh`,配了 codehub 就看 `codehub-cli`;没配到的那家算「还没用上」。

**「怎么修」写什么**:一句人话 + 一条可复制的命令或环境变量名。三类工具三种写法:

| 类型 | 例 | 怎么修 |
|---|---|---|
| 本机 CLI | claude / cursor-agent / gh / codehub-cli / welink-cli | 「装它,或用 `BW_CLAUDE_BIN` 指到已装的位置」+ 可复制命令 |
| 本机服务 | Open Design | 「先把本机 Open Design 起起来,再点重新探活」 |
| 登录态 | GitHub CLI | 「找到了不等于能用;登录态这项还没探,`gh auth status` 自己看」 |

**明确不做代劳**:不代装、不代起服务、不给填路径的输入框。Workbench 不该替人跑 `brew install`,也不该新开一份「工具路径」本机设置(今天路径口子是环境变量,新增一份存储就是两个正本)。**这里能给的最强动作就是把命令写对、可复制**——比一颗按不动的 Connect 按钮诚实。

**全表一颗**「重新探一次」按钮(`section-tools`),现探现算,不缓存。

## 3. 技能页签 · 操作逻辑

表改成**卡片网格**(照抄 Claude Skills 页的 For you 网格):每张卡是标题 + slug、description、来源标签 + 用过几次。页头有搜索,过滤条有来源分段(全部 / Workbench 自带 / 项目自有)和排序(用过几次 / 名字 / 来源)。除此之外改三处:

1. **成为唯一一处。** 知识库·资产页签的「技能与 workflow」块删掉,换成一句话 + 「去能力面板」链接。`skill_list` 仍是同一个函数,但只有一个调用点。
2. **点一张卡看正文。** 今天点一行没反应(`focus_skill` 字段在、没接)。改成开**详情弹窗**,显示 SKILL.md 正文与文件路径——Claude 点一个 skill 开的就是这个弹窗。区别只在内容:它给功能说明,我们给正文,因为我们的用户就是要读 SOP 的人。
3. **说明改对。** 今天写着「导入按钮还没接」「启用 / 停用也还没接」——按本特性的结论这两件都**不做**,说明改成:技能放进这个仓的 `.claude/skills/<目录名>/SKILL.md` 就会被扫出来,不需要导入;开不开由活挂的 workflow 决定,不在这里。

**不做**:导入按钮、启用停用开关、Discover / 市场、胜率列(没有结算记录)。

## 4. 规范页签 · 操作逻辑(待意图 gate 裁决)

只读一张表,一行一份 reference:名字 + 一句话 + 哪类活会注入它 + 文件路径。数据源是现成的 `references_for`,不新增存储。

**出错**:文件不在硬盘就如实少一行,不编路径——和提示词注入同一个口径。

## 5. 客户会问

**Q:为什么不给每项一个开关?Codex 就是开关。**
Codex 的插件跟着应用发,不可能缺席,所以它唯一的轴是开 / 关。BW 这几行全指向应用外面(PATH 上的 CLI、一个 loopback 服务),它们的轴是在不在。而技能开不开,真正的决定者是活挂的 workflow——在这里再放一个开关,就会出现「开关是开的,但这类活根本不挂它」这种说不通的状态。BW 的「开关」已经存在,它长得像开工工具那个下拉。

**Q:Claude 的 Customize 为什么不整个抄?**
抄了。左栏分组、底部挂设置、每页的搜索、状态 / 来源过滤、排序、connectors 那张带「类型」列的表、技能详情弹窗——全部照搬。只有两样没抄:**Discover / 安装数** 和 **「添加」按钮**,理由见下一问。

**Q:为什么不做 Discover / 市场?**
没有可 Discover 的东西。自带的四份运作剧本编在二进制里、开机就在;项目自有的扫仓目录。做一个空的 Discover 页签是自欺。

**Q:和现状的边界?**
探活结果、技能清单、注入规范三样数据今天都已经算得出来,本特性不新增任何一条数据链路,只改它们出现在哪、怎么着色、点下去发生什么。

**Q:不做哪些?**
安装、开关、市场、代装工具、代起服务、填路径的输入框、技能胜率。

## 6. 硬核挑战

- **着色口径要跨数据。** 「有没有活会用到它」得把类别映射(本机 settings)和远端配置(项目名片)一起看。判据写死在壳的 VM 层还是下沉进内核,需在实现时定;倾向壳层——它是纯展示口径,不是领域规则。
- **`ConfigVm.tools` 已经填了、没渲染。** 本特性正好把这个悬着的字段用上;别新加一份。
- **知识库删块会动到 `AssetsVm`。** 资产页签的 `skills` 字段删掉后,`AssetsVm` 少一块,`KbTab::Assets` 的「现扫一次」说明要跟着改。
- **代价**:配置屏从两块变三个页签,单文件会长;`guard-file-lines.sh` 是 2000 行硬上限,配置屏现在 168 行,不逼近,但页签内容应拆成同目录下的子模块而不是堆在 `mod.rs`。
- **成功怎么量**:开工前需要跳屏对照的次数归零(工具状态与工具选择同屏);红色项数等于真正挡住开工的项数(今天 4,按新口径这台机器上是 1——原型类映射到 Open Design 而它没起来)。
