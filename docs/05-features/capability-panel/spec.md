## 1. 版式(照抄 Claude 桌面版设置面板)

设置屏内部分两列。左栏 188px:**顶上一个搜索框**,下面按节分组;右栏是当前页。

| 节 | 条目 | 今天在哪 |
|---|---|---|
| **本机** | 目录 / 外观 | 设置屏两节,原样拆开(Orca 挪进 Connector) |
| **能力** | Connector 7 / Skills 7 / Stage 5 / Plugins 2 / AI Assets 5 | 设置屏「工具探活」与「Orca」+ 配置屏 §①②(搬过来)+ 三节界面上不存在(Stage / Plugins / AI Assets) |

**用词**(均已进 [`CONTEXT.md`](../../../CONTEXT.md),界面标签一律英文):**Connector** 是外部东西的上位词;**Skills** 是技能;**Stage** 是五个方法论阶段,一行一个,答「这类活用什么跑、按什么方法干、会读到哪几份规范」;**Plugins**(词表词条「插件」)是 vendor 进仓的整包技能库,即 skill 与 workflow 的来源;**AI Assets**(词表词条「资产」)是开工注入的规范文件——特意不叫「资产」,免得和知识库屏那个中文「资产」页签撞名。

**文字口径**(硬约束):

- 每页顶上一条**状态色条 + 一行计数**,不写段落。
- 详情页只用两列 `kv` 摆**这一项自己的事实**(路径 / 版本 / 许可 / 谁用到 / 探活方式),一个字都不解释机制。
- **界面里不讲 Workbench 怎么工作**——「提示词只给路径正文按需读」「vendor 是原样副本不是 fork」「文件不在就不编路径」这类话一律不进界面:它们是设计约束,写进本文件;用界面的人不需要被教。
- 设计理由进本文件和在线原型的**窗外**卡片,不进窗内。

条目右边带条数,和 Claude 一样。左栏搜索过滤条目;每个列表页自己另有一个搜索框(Claude 的 Connectors 页也是这样两级)。

**列表 → 详情是整页替换 + 左上角「← 工具」返回**,不是弹窗、不是抽屉。这是本次抄得最实的一处:BW 的工具和技能都有话要说,一行副文说不完。

行与表的写法仍走设计系统:设置文法(`set-group` / `set-row`)、表格(`table`)、卡片(`card`)、分段(`seg`)。**结构抄 Claude,视觉仍是 Builder**——和 9-07 那批抄 Codex 设置文法时同一个口径。

## 2. Connector 页 · 操作逻辑

> **用词**:这一节叫 **Connector**,不叫「工具」。它是上位词,指 Workbench 连出去用的一切外部东西——开工执行器、远端臂、群通知、会话宿主 Orca。词表已登记(见 [`CONTEXT.md`](../../../CONTEXT.md)),并写明它**不是** V3 那份 `.bw/connectors.toml`。「开工工具」是词表里更窄的已有词,专指 connector 里负责跑活的那一类,**保留不动**。

> **执行器映射搬去 Stage 了。**「哪类活用哪个执行器」不是 connector 清单,是**阶段 → 执行器**的映射;而 workflow 那节是**阶段 → workflow**的映射——同样五行、同样形状。把它们并成一张 Stage 表,Connector 这一节只留完整的 7 行清单(答「装没装上」)。下面 §2.1 的操作逻辑随之移到 §3.5。

### 2.1 开工工具(已移到 Stage,见 §4)

五行:原型 / 构建 / 优化 / 运营推广 / 运维。左边类别名 + 这类活的 workflow(产品默认,不可改);右边工具下拉 + 保存 + **该工具此刻的状态点**。

**这块从配置屏搬到设置屏**是本特性的一处硬修正:它存的是 `Settings.tools`(类别 → 工具 id),没有项目维度,`save_tool_mapping` 的 `project_id` 是 `_` 丢掉的。摆在项目屏里等于告诉人「这是这个项目的设置」,而它不是。

**主路径**:改下拉 → 保存 → 写本机 `settings.toml` → 状态点按新工具重算(读已有探活结果,不重探)。
**分支**:选「—(未定)」→ 不显示状态点,副文写「未定,开工会用产品默认」。
**出错**:保存失败走回执 toast,原话不藏。

### 2.2 Connector 表

照抄 Claude connectors 那张表的列法(它是 Connector / Type / Status):

| 列 | 写什么 |
|---|---|
| Connector | 名字 + 副文(找到就是路径;没找到就是原话) |
| 类型 | 本机 CLI / 本机服务 / 会话宿主 —— 失败原因与修法按类型分 |
| 谁用到 | 哪几类活映射到它 / 哪些项目的远端是它 / 「没有类别用到」 |
| 状态 | 已找到 / 开不了工 / 还没用上 / 还没接 |

表头上方一组过滤按**类型**分(全部 / 执行器 3 / 远端臂 2 / 群通知 1 / 会话宿主 1),页头有搜索框和「重新探活」。

**不按状态过滤**:状态已经由色条 + 行首色点表达完了,再拿它当筛选维度是同一件事说两遍;类型才是这张表真正的分类。**状态列也不写字**——顶上那行图例(● 已找到 2 · ● 开不了工 1 · ● 还没配 1 · ● 还没用上 3)就是解释,行里只留一颗色点(带 `title` 供读屏与悬停)。同理 Stage 表。

**着色口径**(本特性的核心改动):

| 情形 | 状态 | 颜色 |
|---|---|---|
| 有类别映射到它 / 有项目的远端是它,且探到了 | 已找到 | 绿 |
| 有类别映射到它 / 有项目的远端是它,没探到 | **开不了工** | 红 |
| 没人用到它,探到了 | 已找到 | 绿 |
| 没人用到它,也没探到 | **还没用上** | 中性 |
| 要填配置才能用,还没填(今天只有 Orca) | **还没配** | 中性 |
| 这项探活还没接 | 还没接 | 中性 |

红色从此只意味着:**有活要用它、它不在,现在就会挡住开工**。

> 「谁用到」跨两处数据:类别→工具映射(本机 settings)和各项目的远端 / 群通知(项目名片)。判据是纯展示口径,放壳的 VM 层,不下沉进内核。

### 2.3 Connector 详情(← Connector)

抄 Claude connector 详情页的骨架:图标 + 名字 + 出处一行,右上角状态 + 主动作(Claude 那是 Disconnect,BW 是**重新探这一个**)。正文一段导语 + 一组「**它给 Workbench 供什么**」:

| 工具 | 供什么(正文写这些,都是仓里真有的事实) |
|---|---|
| claude | 开工起交互式会话 / 一次性系统提示词注入 / `BW_CLAUDE_MAX_BUDGET_USD` 控预算 / `BW_CLAUDE_BIN` 换位置 |
| GitHub CLI | 读 issue 列表与详情 / 开 PR 与按分支反查 / 合入后读回状态(只信真变 MERGED)。另起一节写「登录态没探」 |
| Open Design | 原型类活的内嵌网页 / 探活是管道握手拿 loopback 首页超时 400ms / 不解析会话地址、不自动开跑 |
| cursor-agent | 选了就当真:探不到当场报错,不悄悄退回 Claude CLI |
| codehub-cli | 远端另一家,和 gh 同形两条路 |
| welink-cli | 项目群通知,配在名片的 chat 段,只在开 MR 时发 |
| **Orca** | 开工会话真正跑的地方(走本机管道,**不经网页地址**,所以地址没配不挡开工)/ 三条运作节律的钟 / 网页配对地址只认 loopback、带 token、绝不进仓与日志 |

**Orca 这一行只有「配了 / 没配」,没有「通不通」** —— 本机 Orca 服务没有探活实现。在加之前,界面不许拿「配了」冒充「通了」(词表「探活」条的 `_Avoid_`)。它的配对地址输入框就放在这个详情页里,不再单占「本机」一节。

**没装的那些,详情里给「安装」,不给重复信息。** 判据:仓里有据的直接给**可复制命令**;没据的如实写「装法仓里没记」+ 说清 Workbench 的判据(PATH 上有这个名字 / 版本命令能出结果)。绝不编一条 `npm i -g <猜的包名>`。

| Connector | 今天仓里有的依据 | 详情里给什么 |
|---|---|---|
| welink-cli | 「npm 全局装,用户自己 `auth login`,Workbench 不碰凭证」([architecture.md](../../architecture.md) 模块) | 两条可复制命令 + 一句「凭证你自己登」 |
| claude | `adapters::claude_cli::REQUIRES` 三条前置 | 「要用它得有」三条 |
| Open Design | 它是本机服务,不是装出来的 | 「起它」——起法与端口由你定,起完点重新探 |
| cursor-agent / codehub-cli | **仓里没记** | 「装法仓里没记」+ 判据(PATH 上有这个名字) |

**这暴露一件没建的事**:BW 没有一份「每个 connector 怎么装」的正本,只有零散记在 architecture 里的一句半句。真做的时候需要一张表(名字 → 装法 / 判据),否则详情页只能一半有内容一半留白。

**仍然不做**:不代装、不代起服务、不加填路径的输入框——Workbench 不该替人跑 `npm i -g`,也不该新开一份「工具路径」本机设置(今天路径口子是环境变量,新增一份存储就是两个正本)。

## 3. Skills 页 · 操作逻辑

卡片网格(抄 Claude Skills 的 For you 网格):标题 + slug、description、来源标签 + 用过几次。页头有搜索;过滤条有来源分段(全部 / Workbench 自带 / 项目自有)和排序(用过几次 / 名字 / 来源)。

**顶上的色条按催熟状态分**(用过但没改过 / 改过 / 还没用过),卡片写「用过几次 · 改于哪天」,排序可选「按最久没改」。这是对同事那条评审的回应:`standard/` 下几份都是初稿、没被优化过,而面板只报「用过几次」时,「用了 12 次一次没改」这种缺口是看不见的。

**「改于哪天」的数据从哪来**:自带那几份的正本是仓里的 `standard/skills/<slug>/SKILL.md`,开发期能 `git log -1` 拿到(实测 week-planning 09-04、project-handbook 09-03)。但**分发态没有源码树**——真做要在编译期把每份的最后改动时间烤进二进制。vendor 来的(mattpocock-skills)没有「我们改过」这回事,写「上游版本」。

**这是全局的一张表**:列所有接入项目的技能,项目自有的标出来自哪个仓(「项目自有 · workbench」)。知识库资产页签那块删掉,换一句话 + 一个跳过来的链接。`skill_list` 仍是同一个函数,但只有一个调用点。

### 3.1 Skill 详情(← Skills)

抄 Claude skill 详情页:图标 + 名字 + **出处行**(「Workbench 自带 · 编在二进制里 · 用过 12 次」/「项目自有 · 来自 workbench 仓 · 还没用过」)+ 右上角动作(**复制路径**)。两个页签:

- **概览** —— 什么时候注入、正文为什么不进提示词(只给路径,按需读)、它会不会再指别的、摊在哪。
- **文件 · N** —— 左边文件列表、右边正文,右上角切**渲染 / 源码**。

**为什么这一页对 BW 是真需求,不是抄壳**:技能包本来就不止一个文件。`week-planning` 带一个 sidecar `check-week-comment.py`(编在二进制、会一起摊到资产目录、提示词的技能指针不认它);`mattpocock-skills` 的入口之外还有一整棵 vendor 库。今天这些在界面上完全看不见。

**不抄的**:Claude 那个版本下拉(BW 技能没有版本,不放)、启用 / 停用开关(见「客户会问」)。

## 4. Stage 页 · 操作逻辑

一张表,五行(原型 / 构建 / 优化 / 运营推广 / 运维),四列:

| 列 | 写什么 | 可改吗 |
|---|---|---|
| 阶段 | 五个方法论阶段的名字 | 否 |
| 执行器 | 下拉 + 保存,就在行里 | **是** —— 写本机 `settings.toml` 的 `tools` 表 |
| Workflow | 挂在这个阶段的那条 SOP;没有就写 `—` | 否(产品默认,不进被管仓) |
| 状态 | **这个阶段现在能不能开工** —— 取决于它的执行器探到没探到 | — |

**为什么合成一张表**:执行器映射原来埋在 Connector 页底下,workflow 映射自成一节,两张表同样五行、同样形状——「阶段」被切成了两半。合起来之后,「这类活怎么干」一处答完,Connector 那节回归它本来的职责:**完整的外部依赖清单**。

**行尾 `›` 进阶段详情**(整行不能点——行里有下拉)。详情把这个阶段开工时**会拿到什么**摆齐:执行器(带路径 / 状态)、workflow(带 SOP 和来自哪个插件)、会注入哪几份 AI Assets。今天这三样分散在三个地方,拼不到一起。

**主路径 / 分支 / 出错**同 §2.1 原文:改下拉 → 保存 → 写本机设置 → 状态按新执行器重算(读已有探活结果,不重探);选「—」不显示状态;保存失败走回执 toast,原话不藏。

## 5. AI Assets 页 · 操作逻辑(待意图 gate 裁决)

**这一节回答一个问题:这张活开工时,agent 会读到什么。** 不是「references 清单」——那是它的一部分,不是全部。开工提示词实际给三层([`SYSTEM.md.tmpl`](../../../standard/system-prompt/SYSTEM.md.tmpl)):

| 层 | 今天怎么给 | 在表里 |
|---|---|---|
| 项目自己的 `AGENTS.md` | 提示词写一句「仓根 AGENTS.md 是入口,动手前读」,不塞正文 | 第一行,来自「项目」 |
| Workbench references | 按类别匹配后摊到资产目录,提示词只给一句话 + 路径 | 5 行,来自「Workbench」 |
| 活挂的剧本(skill) | `skill_pointer` 解析 | 不在这张表 —— 它在 Skills 那一节 |

按「来自」筛(项目 1 / Workbench 5)。表下如实写缺口:项目自己的只有 `AGENTS.md` 一条、而且只是被**指了一下**;项目的 `CONTEXT.md` / `docs/` / `.teamai/`(知识分层正本里写着装 skills / rules / hooks / MCP)今天都不在这张表里,Workbench 既不观测也没有接入通道。

只读一张表:名字 + 一句话 + 哪类活会读到 + 状态(已派发 / 未编进二进制)。数据源是现成的 `references()` + `want_ref`,不新增存储。文件不在硬盘就如实少一行,不编路径——和提示词注入同一个口径。

## 6. 客户会问

**Q:Claude 的设置面板为什么不整个抄?**
抄了:左栏搜索 + 分节、条目带条数、列表→详情整页跳转与「← 返回」、详情页的出处行与右上角主动作、「概览 / 文件 · N」与文件浏览的渲染 / 源码切换、connectors 那张带类型列的表、状态过滤条。只有两样没抄:**Discover / 安装数** 和 **「添加」按钮**。

**Q:那两样为什么不抄?**
背后没东西撑。BW 没有目录可逛(自带的编在二进制里开机就在,项目自有的扫仓目录),没有可执行的「添加」动作(添加 = 把文件放进仓),更拿不到别人的安装数。抄过来就是一页编出来的数字。仓里犯过一次同样的错:预置的六份「阶段方法论」技能一份没真派发过,最后被当成「预先搞的一堆没用的」删光。

**Q:为什么不给每项一个开关?**
BW 这几行全指向应用外面(PATH 上的 CLI、一个 loopback 服务),它们的轴是在不在,不是开不开。而技能开不开,真正的决定者是活挂的 workflow——开工只注入那一个。放个全局开关,六份技能里有五份任何时刻都不受它影响,是个假控件。BW 的「开关」已经存在,它长得像开工工具那个下拉。

**Q:为什么叫 Connector 不叫「工具」?**
因为这一节装的不只是「开工用的工具」:`gh` 是远端臂、welink-cli 是群通知、Orca 是会话宿主,都不参与「哪类活用哪个工具」那个选择。用「工具」当节名,Orca 进不来。Connector 是上位词——**Workbench 连出去用的外部东西**,一套判读(能真连的才叫连上)统管七件。词表里更窄的「开工工具」保留原义,指 connector 里负责跑活的那一类。这个词在 V3 有过一份 `.bw/connectors.toml`,词表已写明现在这个 connector 和它没关系。

**Q:和现状的边界?**
探活结果、技能清单、注入规范三样数据今天都已经算得出来,本特性不新增任何一条数据链路,只改它们出现在哪、怎么着色、点下去发生什么。

**Q:不做哪些?**
安装、开关、市场、Discover、安装数、代装工具、代起服务、填路径的输入框、技能胜率、技能版本。

## 7. 硬核挑战

- **「谁用到」要跨两处数据**:类别映射(本机 settings)+ 各项目远端与群配置(项目名片)。判据放壳的 VM 层——它是展示口径,不是领域规则。
- **技能表变全局要跨项目扫**:今天 `skill_list(ws, usage)` 只扫一个仓。改全局要对所有接入项目各扫一遍 `.claude/skills/`,并记住每份来自哪个仓。扫的次数和缓存策略要定——倾向进设置屏时现扫一次,不缓存(和探活同口径)。
- **用户自有 workflow 接不进注入链路,这不是面板能修的**:`skill_pointer` 三道门(硬编码 `skill_slug` / 只查编进二进制的 5 份 / 路径只拼 Workbench 资产目录)。要让项目自己的 workflow 能被挂上,得改的是**注入模型**——按名字解析改成「先查被管仓 `.claude/skills/`,再回落到自带」,`default_workflow` 从产品常量改成可被项目覆盖。**这是内核改动,不属于本特性**,建议另开一件;本特性只负责**如实把这个缺口显示出来**。
- **界面今天在说谎,必须先停血**:`skill_list` 的 `used()` 用 `w == slug` 匹配,会让项目自有技能显示「用过 N 次」,而 `skill_pointer` 实际返回 `None`。本特性范围内的最小修法:项目自有那几行标「注入不了」,用量不再按名字硬匹配(或至少标注「这个数不代表被注入过」)。
- **agent 这一类没有任何底座**:同事点名的四类资产(connector / skill / agent / workflow)里,agent 全仓零实现——没有扫 `.claude/agents/` 的代码、没有模型、没有注入。进面板 = 新开一条数据链路,不属于「重排已有」。
- **「哪个项目在用」要跨项目扫**:面板是全局的,但这个维度要对所有接入项目各扫一遍仓;扫的时机(进页现扫 / 缓存)与成本要定。
- **「改于哪天」在分发态拿不到**:开发期靠 `git log`,打包后没有源码树 —— 要编译期烤进二进制。
- **没有「connector 怎么装」的正本**:装法今天零散记在 architecture 里,只有 welink 和 claude 有,cursor-agent / codehub-cli 完全没有。
- **Orca 没有探活**:`probe()` 只认 claude / cursor / open_design / welink,`env` 那六行也没有 Orca。放进 connector 表后它只能显示「配了 / 没配」。加真探活是新增行为,列在 intent 开放问题 3。
- **`ConfigVm.tools` 已经填了、没渲染**:搬走之后这个字段跟着走,别留悬空。
- **配置屏会空**:能力两块搬走后它只剩壳。intent 开放问题 2 就是问这个——倾向本轮只搬走,配置屏重建(远端 / 项目群 / 节律,字段都已算好)另开一件。
- **知识库删块会动到 `AssetsVm`**:资产页签的 `skills` 字段删掉后,「现扫一次」的说明要跟着改。
- **单文件行数**:设置屏现在 300 行不到,加四个列表页 + 八个详情页会长。`guard-file-lines.sh` 是 2000 行硬上限,不逼近,但各页应拆成 `screens/settings/` 下的子模块,不堆在 `mod.rs`。
- **成功怎么量**:开工前需要跳屏对照的次数归零;红色项数等于真正挡住开工的项数(今天 4,按新口径这台机器上是 1);「在项目 A 改工具映射会不会影响项目 B」这个问题在界面上有明确答案(今天没有)。

## 8. 原型
