红只有一个意思:有活会用到它、它不在,现在就挡着开工。今天设置屏那张表六行红四行;按这个口径同一台机器只剩一行红。 另外:「开工工具」这块今天摆在项目内的配置屏里,但它存的是本机全局设置(settings.toml 的 tools 表,没有项目维度)—— 在项目 A 改了,项目 B 也变。挪到这里才是它本来的位置。

claude
本机 CLI · /Users/gravity/.local/bin/claude
已找到

Claude 的命令行。Workbench 靠它把一张活真的跑起来 —— 没有它,「▶跑」按不动。

  • 开工 —— ▶跑一张活时,在内嵌终端里起一个交互式 claude 会话。
  • 注入 —— 把活的信息、这类活要读的规范、活挂的剧本作为一次性系统提示词送进去(不落盘、不缓存)。
  • 预算 —— BW_CLAUDE_MAX_BUDGET_USD 控这一场花多少。
  • 换位置 —— 装在别处就用 BW_CLAUDE_BIN 指过去,Workbench 认这个环境变量。

技能
mattpocock-skills
Workbench 自带 · 业界 workflow · 用过 9 次

构建 / 优化 / 运维三类活的产品默认 workflow。入口是一份 SKILL.md,写的是一整套做事流程,自己调度该用哪个子技能 —— 所以 workflow 和技能是同一样东西,不分两张表。

  • 入口 —— grill → implement → review 的 SOP 链,指向 vendor 库里的子技能路径。
  • vendor 库 —— 整棵树摊到资产目录 …/assets/vendor/mattpocock-skills/,正文按需读。
  • 分发态的坑 —— 现在 vendor 是开发期从源码树复制;打包分发时没有源码树,入口仍注入但子技能读不到。如实标着,没修。

规范

每张活开工时,除了活本身和挂的剧本,Workbench 还按类别塞给 agent 这几份规范 —— 提示词只给「一句话 + 路径」,正文让它按需读。这里只读,改要改 standard/system-prompt/references/;文件不在硬盘就不列,不编路径。

规范写的是什么哪类活会读到状态
metrics怎么写 .bw/metrics.toml、脚本怎么吐数运作活①已派发
week-plan-comment运作活①评论三标题、标签、里程碑;周五每周进展怎么写运作活① · 运作活②已派发
build活的树在哪;评论和标签不是改仓构建 · 优化 · 运维 · 运作活②已派发
bw-assets运作活②对照的 .bw 现行契约运作活②已派发
review评审会话要读的那份评审未编进二进制

这一整块是本特性里唯一「新增界面」的部分 —— 工具和技能都是把已有的东西摆对位置。要不要进本轮,留给意图 gate 裁。
