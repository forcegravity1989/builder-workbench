# 探索 BW — 六环状态

> **维护约定**：给开发、设计、评审和验收者读取。本篇只记录探索目录作为产品基础资产的当前六环状态、W01–W05 交叉索引和证据边界。用户结果见 [intent](intent.md)，当前行为和判据见 [spec](spec.md)。运行命令、日志、截图和修复过程留在对应 PR 验证评论，不保存施工流水。

## 当前结论

探索 BW 的目录、工作旅程与功能分组承接 W01–W05。它负责内容导航和播放承载，不拥有业务结果，不把样例播放当成业务 E2E。[可点原型](prototype.html)是布局评审输入，产品功能和真实业务证据仍由各特性维护。

W01–W05 的名称、步骤联系和功能归属见 [引导规范与矩阵](../../04-design-system/guidance.md#探索-bw-矩阵)。W06“持续维护”和 W07“沉淀复用”保持建设中，不计入核心旅程数量。

W01 使用运营看板的真实完整窗口录像，项目墙、项目总览和里程碑在功能目录中各有独立短演示。Windows dev 已两轮执行共享业务步骤并独立读回文件、Git 与 GitHub PR；演示止于待评审，不包含人工合入和多人读回。探索播放器与业务操作分开留证，见 [#758 验证记录](https://github.com/forcegravity1989/builder-workbench/pull/758#issuecomment-7091322345)。

## W01–W05 交叉索引

| 旅程 | 探索职责 | 业务事实承接 |
| --- | --- | --- |
| W01 明确方向 | 目录、步骤联系和演示入口 | 项目纳入、项目总览、版本计划 |
| W02 制定版本计划 | 目录、五步联系和计划内容入口 | 版本计划、任务管理、版本会话管理 |
| W03 构建交付 | 目录、交付步骤和关联功能入口 | 任务管理、版本会话管理、通知、内部集成 |
| W04 验收成果 | 目录、验收步骤和验收内容入口 | 版本验收、版本总览、通知 |

30+ 个功能项沿引导矩阵映射到这些步骤。功能项不各自新增用户旅程 E2E。某条真实主链已经覆盖特性边界时，特性沿自身 STATUS 复用该入口。

## 证据边界

- 原型、模拟数据、静态检查和 Explore 播放只能支持目录、布局、内容状态和导航范围。
- 业务操作、真实 provider、双主机送达、人工验收、归档、指标采集、重启读回和跨特性结果必须由所属特性在真实 Electron 或对应环境独立验证。
- prototype/、prototype.html 和实现代码分属各自维护入口。原型是设计输入，业务 E2E 由所属特性维护。
- 未登记不表示功能不存在，只表示探索资产没有独立业务用例。各特性主旅程和验收点的文件、标题、执行入口、环境、独立读回和状态按各自 STATUS 维护。
