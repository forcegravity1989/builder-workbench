# 探索 BW — 意图

> **读者与时机**：设计、实现或评审探索 BW 的目录和内容承载时读取。
> **职责与边界**：说明用户价值与本次布局范围；交互及原型见 [spec](spec.md)，引导分类、旅程和功能覆盖只在[引导规范与矩阵](../../04-design-system/guidance.md)维护。
> **结构与更新**：状态 → 用户与问题 → 价值 → 目标体验 → 范围与成功判据；意图经人确认变化时更新。

## 状态

用户已确认探索分区与功能筛选范围，现有实现见 [#634](https://github.com/forcegravity1989/builder-workbench/issues/634)。本轮已对齐核心旅程的工作联系、两项贯穿能力及用局部动画串起旅程的方向。具体呈现按[布局规格](spec.md)评审。帮助入口见 #606，矩阵与走查方法沿 #607。

## 用户与问题

Builder 在实际工作中既需要理解“用 BW 怎样把一件事做完”，也需要随时查看一个屏幕或能力怎样使用。当前探索已有工作旅程与功能目录，并复用 Orca 的五组十一页介绍。用户需要从目录看见各条工作的联系，也需要通过一次局部操作快速理解如何上手。

## 价值与依据

让用户按眼前的工作或功能找到对应介绍，再继续实际工作。沿[产品主张](../../01-principles/03-press-release-faq-flywheel.md)，帮助用户理解方向、承诺、执行、验收与效果的联系。依据是本次用户确认的七条旅程及基础优先的整改顺序；易找、易懂的效果仍需原型评审和实际使用验证。

## 目标体验

从底部问号进入探索 BW，选择“工作旅程”或“功能”。左侧找到主题，右侧查看该内容；已有演示继续复用，尚未完成的内容如实区分。随屏小能力附着于对应主题，不要求先看完全部内容。关闭后仍可从原入口回来。

## 范围与成功判据

- 先用 W01 验证目录、选择态、四步演示区及局部动画的呈现。设计确认后逐项接入产品。
- BW 入门、新安装、反馈入口和业务屏本体由各自工作继续承担；播放沿探索内容区，操作引导沿原生机制，业务完成继续从事实来源读回。
- 功能项的选择与检查点只读矩阵；具体业务行为沿各自特性，本目录不复制完整操作说明。
- 用户能区分完整旅程和局部功能，能找到现有演示；空内容没有伪播放或伪完成，建设中不包装成可用流程。
- 首屏不强制自动播放，不以浏览进度阻止开工；已有内容与其持续回看入口保留。
