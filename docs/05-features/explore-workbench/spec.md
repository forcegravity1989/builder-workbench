# 探索 BW — 布局规格

> **读者与时机**：评审原型、实现探索布局或接入一项内容前读取。
> **职责与边界**：只维护探索的导航、内容区域、状态与接入约束；通用引导规则和内容范围引用[矩阵](../../04-design-system/guidance.md)，业务行为仍归原特性。
> **结构与更新**：状态与依据 → 范围与旅程 → 行为规则 → 验收 → 内容接入位置。布局或呈现决定变化时更新。

## 状态与依据

现有探索入口、弹窗与「工作旅程 / 功能」分区已认可。用户已认可目录、W01 四步布局与名片片段的演示顺序。四步同屏时保留起点、结果、步骤卡和当前操作提示，避免重复标题与解说。正式演示采用 Orca 的 React/CSS 局部动画方式，复用 BW 实际组件和样式，用独立样例驱动。[意图](intent.md) · [可点原型](prototype.html) · [状态](STATUS.md)。原型打开后直达「明确方向」供评审，功能分区引用现有演示。

现有实现依据：

- [FeatureWallModal](../../../src/renderer/src/components/feature-wall/FeatureWallModal.tsx)：底部问号打开的现有对话框，最大 1240 × 780。
- [FeatureWallTourPanel](../../../src/renderer/src/components/feature-wall/FeatureWallTourPanel.tsx)与 [FeatureWallRail](../../../src/renderer/src/components/feature-wall/FeatureWallRail.tsx)：左目录、右内容、页脚退出，以及展开子项的布局。
- [FeatureWallTourSurface](../../../src/renderer/src/components/feature-wall/FeatureWallTourSurface.tsx)：现有演示选择、内容和完成状态接入。现有状态混合访问与配置，不能直接当作业务完成。
- [原生内容目录](../../../src/shared/feature-wall-workflows.ts)与[本地化正文](../../../src/renderer/src/components/feature-wall/feature-wall-tour-localized-copy.ts)：已有五组十一页按内容身份复用，不把此次重新分组当成新内容验证。

## 范围与完整旅程

1. 从现有底部问号进入“探索 BW”，沿用对话框和关闭入口。
2. 通过“工作旅程 / 功能”切换目录。首次打开落在已有功能演示，避免首屏只看到空内容；两类可随时切换。
3. 功能按实际操作分组，选中组后展开具体功能；随屏内容在对应功能中提供相关入口，不机械展开为 29 个一级菜单。按矩阵中的八个重点组组织，并保留既有智能体编排的回看入口。
4. 左侧核心旅程按「明确方向 → 制定版本计划 → 构建交付 → 验收成果 → 查看效果」连接，「调整下一轮」回到明确方向。每条可独立选择，右侧说明起点、结果及相关功能。顺序表达工作联系。
5. 「持续维护」和「沉淀复用」放在「贯穿每一轮」，标题右侧显示轻量「建设中」标签。目录行可换行，标签保持一行。当前选中项同时用背景和左边线表达。已有内容沿原有区域展示，未填内容提供简介与实际可用的关联。
6. 关闭后从同一帮助入口重开，不新增首次安装弹窗或强制观看流程。

## 行为规则

### 信息与状态

- 导航与产品文案不展示 W/F 编号、16/8/5 分类或内部验收信息。
- “内容准备中”说明介绍尚未准备好，不表示对应功能不能用；“建设中”用于完整产品旅程尚未就绪。
- 已有演示只意味着可查看，不显示“该工作已完成”。业务结果和配置状态仍由原来源表达。
- 不为重分组清空既有用户记录。涉及查看记录的展示或迁移时先核对现有语义，只复用可准确解释的状态。
- 暂缓专项不删除已有演示；当前已有的智能体编排内容保留可回看入口。工程部署、SDLC 不在本次新增内容范围。
- 共享主机连接归协作相关内容：F24 核对连接/配对、项目可访问性与断连恢复，F08 复用；不新增成员或权限体系。

### W01 四步布局与片段

上方横排相连的「找到项目 → 明确共同方向 → 安排阶段成果 → 评审并更新」步骤卡，下方只有一个演示区。当前步骤用边线、背景和序号高亮。原型在 1280 × 720、1440 × 900、1920 × 1080 的评审窗口同屏显示四步与当前演示，窄屏保留分区滚动。

点击步骤停在该步起点。「顺序播放」从当前步开始，「暂停」保留当前画面，可继续播放。「从头重播」从当前内容的第一步开始。切换步骤或离开内容停止播放，整条播放结束停在第四步。相关功能从演示区下方进入。四张步骤卡以圆形序号、统一高度和等距连接保持原型的层次。

名片片段采用可编辑、有远端的团队示例仓。展开「周末书集」名片，经「编辑项目信息」进入共用设置栏。修改「愿景」后出现「提交评审」，点开「本次修改」，停在「确认提交」前。样例中的团队仓已连接代码托管。无远端本机仓的「保存」分支见[项目纳入规格](../project-intake/spec.md#项目信息编辑与失败反馈)。

[动画源码](prototype/charter-demo.jsx)采用 Orca [局部界面演示](../../../src/renderer/src/components/feature-wall/BrowserStoryboardWindow.tsx)的 React 分阶段渲染、光标和点击波纹方式，复用仓内原型 React 运行时与设计 token。运行 `node docs/05-features/explore-workbench/prototype/build-charter-demo.mjs` 更新可离线打开的脚本。

### W02 制定版本计划

沿用 W01 的步骤卡、演示区和播放控制。五步是「确定规划哪一版 → 定目标与验收标准 → 把目标落成任务 → 评审并归档 → 从计划开工」。样例沿用「周末书集」，从已有版本的计划入口开始，说明首版可以直接规划，示意评审合入后从一条 Issue 进入执行工作区。计划、任务管理与版本会话各复用对应片段。里程碑继续沿用 W01。业务步骤和状态见[版本计划规格](../version-planning/spec.md)。

### 内容逐项接入

目录、摘要、真实可用的内容、关联功能及指南按内容项接入；具体实现优先扩展当前目录与渲染组件。只有内容实际存在且完成适用验证，才展示相应查看、体验或指南动作，并更新矩阵对应格。

随屏功能仍保留各自覆盖和证据：运行状态、用量、编辑器、工作区看板和快捷跳转随执行场景；PR 检查和提交随检视交付；内部服务配置复用入门、使用随任务和协作。不能因一级菜单合并而丢失这些核对点。

[产品内演示](../../../src/renderer/src/workbench/explore/DirectionWalkthrough.tsx)在项目墙、项目总览和项目里程碑功能项重用对应片段。样例项目、表单和评审状态由动画驱动，空项目墙也可打开播放。动画按操作切换构图，展示当下真实控件及结果。功能页的「在界面中跟做」返回对应屏幕并启动原生引导。指南与长图沿用真壳截图。屏内引导遵循[引导规范](../../04-design-system/guidance.md#展示与结果)。正式实现涉及 Orca 同步边界时更新 [upstream](../../../ref/upstream.md)。

### 交互与异常

选中态、目录滚动、键盘操作和关闭优先复用现有原语；长标题可换行。窗口缩小时保留目录和内容的独立滚动，不横向溢出。主题切换只影响展示，不触发安装、配置或业务动作。缺内容显示真实状态，加载失败沿用具体内容的失败提示和恢复动作，不伪装成“准备中”。

## 验收

| 编号 | 可观察结果 |
|---|---|
| E01 | 底部问号打开探索；工作旅程与功能可切换，关闭后可重开 |
| E02 | 功能分组和相关入口保留矩阵采用范围，原有十一页可追溯、可回看；暂缓不误删原内容 |
| E03 | 未填内容不出现伪播放、虚假跳转或业务完成；W06/W07 明确建设中 |
| E04 | 随屏项可在所属主题找到，协作内容包含共享主机必要前提；不要求全部配置完成才能浏览 |
| E05 | 现有演示正文、动态效果与退出能力可复用；本轮不改变入门和反馈流程 |
| E06 | 中文、键盘与明暗主题可用；常用桌面尺寸同屏显示四步和演示 |
| E07 | 目录表达工作联系与下一轮回接；各项可独立打开，持续维护与沉淀复用保留建设中 |
| E08 | 四步可切换，顺序播放、暂停、重播均有可见结果；名片动画与当前真实控件及提交入口一致 |

## 内容接入位置

目录与内容对应关系见 [bw-explore-catalog](../../../src/renderer/src/workbench/explore/bw-explore-catalog.ts)。布局复用原生演示的选中逻辑、正文和配置卡。后续内容在对应条目接入，并独立更新矩阵和验证证据。
