# 探索 BW — 布局与内容规格

> **维护约定**：给设计、实现、内容维护和验收者读取。本篇只维护探索目录的导航、内容区域、状态和接入约束。用户结果见 [intent](intent.md)，当前六环和证据边界见 [STATUS](STATUS.md)，内容范围和覆盖矩阵见 [引导规范与矩阵](../../04-design-system/guidance.md)。不追加开发流水或被替代方案。

布局评审使用 [可点原型](prototype.html)。原型只表达目标布局和内容顺序，不证明生产行为或业务旅程已经通过。

## 范围与完整旅程

探索 BW 是产品基础资产。它把 W01–W05 的核心工作联系和功能入口组织到一个可回看的界面，业务结果由各特性承接。

| 旅程 | 用户结果 | 探索承接 | 主要协同特性 |
| --- | --- | --- | --- |
| W01 明确方向 | 找到项目、明确共同方向、安排阶段成果、评审并更新 | 目录、步骤联系和演示入口 | 项目纳入、项目总览、版本计划 |
| W02 制定版本计划 | 定版、定目标与验收标准、关联任务、评审归档、从计划开工 | 目录、五步联系和计划内容入口 | 版本计划、任务管理、版本会话管理 |
| W03 构建交付 | 找到目标任务、并行执行、验证和评审、读回交付结果 | 目录、交付步骤和关联功能入口 | 任务管理、版本会话管理、通知、内部集成 |
| W04 验收成果 | 对照目标核验证据、人工确认结果、归档并安排后续动作 | 目录、验收步骤和验收内容入口 | 版本验收、版本总览、通知 |
| W05 查看效果 | 查看进展与指标、识别偏差、决定调整、形成下一轮计划或任务 | 目录、结果步骤和总览内容入口 | 版本总览、指标能力、版本计划、任务管理 |

30+ 个功能项是这些旅程的能力入口。引导矩阵维护功能项的具体范围、复用关系和覆盖状态。功能项不因为出现在探索目录中而获得独立的用户结果、E2E 或验收结论。

探索本身不拥有项目、计划、任务、PR、验收、指标或通知的业务事实。进入功能或“在界面中跟做”时回到对应特性和原生入口，所属特性负责事实读取、写入和证据。

## 进入、切换与关闭

1. 从底部问号打开探索 BW。沿用现有对话框、目录和关闭入口。
2. 在“工作旅程”和“功能”之间切换。首次打开显示已有可用内容，不能把空内容当作已完成流程。
3. 左侧选择目录项，右侧显示摘要、起点、结果、步骤或局部演示。选中项有清晰的背景和边线，长标题可以换行。
4. 关闭后从同一帮助入口重开。探索不自动创建会话、项目、计划或任务，不阻止用户继续业务操作。
5. 目录、内容和页脚在窄窗口独立滚动，不横向溢出。键盘操作、中文和明暗主题沿现有原语处理。

内容准备中只说明介绍尚未准备好，不表示功能不可用。建设中用于尚未形成完整产品旅程的目录项。已有演示只表示可以查看，不表示业务工作已完成。

## W01–W05 内容规则

### W01 明确方向

展示“找到项目 → 明确共同方向 → 安排阶段成果 → 评审并更新”的联系。关联的功能项可在「功能」目录独立回看。探索展示样例的起点和结果，真实项目信息、阶段材料和评审结果分别由所属特性读取。

W01 使用运营看板样例，以实际 Electron 完整窗口录像展示页面之间的联系。侧栏、项目设置和里程碑均来自生产界面，不维护另一套仿工作台。录制复用 W01 真实 E2E 的业务操作；观赏停顿、指针标记和等待压缩只属于录制，不改变正常 E2E 的执行节奏或业务结果。

播放器提供四个章节、播放/暂停、重播和失败重试。项目墙、项目总览、里程碑各用原有的局部短演示独立介绍能力，分别展示搜索和进入项目、查阅和编辑共同方向、安排阶段成果和核对评审。操作中引导沿对应屏幕的帮助入口，指向真实控件。其他旅程的既有演示不随 W01 扩大改造。记录的评审尚未合入时，演示止于真实待评审状态，不补演已合入或正式安排更新。

素材与章节时间一同更新，发布前核对录制源码、样例材料、远端评审与真实画面。业务操作或等待失败不覆盖成功素材。探索播放只读取随应用分发的录像，不连接演示仓或操作用户项目。

### W02 制定版本计划

展示“确定规划哪一版 → 定目标与验收标准 → 把目标落成任务 → 评审并归档 → 从计划开工”。计划、任务和版本会话只提供内容入口与关联说明，材料保存、任务状态和工作区绑定沿各自特性。

### W03 构建交付

展示“找目标任务 → 并行执行 → PR 验证与评审 → 人确认完成并读回”。通知、CodeHub、浏览器批注、工作树和会话等能力按矩阵挂到相应步骤。模拟提交、评论、合入、关单或送达不能替代真实 provider、双主机或人工确认。

### W04 验收成果

展示“对照目标核验证据 → 人确认结果 → 归档并安排遗留和下一版”。验收屏、版本总览和通知提供入口。探索不代替人工结论、不生成归档材料、不推导发布状态。

### W05 查看效果

展示“查看进展与指标 → 识别偏差 → 人决定调整 → 形成后续计划或任务”。版本总览和指标能力提供入口。样例读数只用于解释查看方法，实际指标、来源权限、缺数和后续计划沿各自特性。

W06“持续维护”和 W07“沉淀复用”在矩阵中保持建设中描述。它们在形成独立用户结果、内容来源和验收方式前不加入五条核心旅程，也不登记独立 E2E。

## 内容接入与实现约束

- 目录与内容对应关系维护在 [bw-explore-catalog](../../../src/renderer/src/workbench/explore/bw-explore-catalog.ts)。新增或调整条目时同步引导矩阵和所属特性入口。
- 内容优先扩展现有目录与渲染组件，复用 Orca 的播放器、BW 组件和设计 token。不要为探索另造业务状态或执行通道。
- 内容动作只在目标内容、功能入口和适用验证都存在时展示。加载失败沿内容的真实失败提示和恢复动作，不用“内容准备中”掩盖失败。
- 样例动画可以使用安全 fixture 和独立样例。它必须明确为播放内容，不读写用户项目，不代表业务状态。
- 原型文件位于本目录的 prototype/ 和 prototype.html。它们只用于布局评审，不是业务实现入口。HTML、JSX、CSS 和生成物沿原型维护规范管理。

当前实现入口包括 [FeatureWallModal](../../../src/renderer/src/components/feature-wall/FeatureWallModal.tsx)、[FeatureWallTourPanel](../../../src/renderer/src/components/feature-wall/FeatureWallTourPanel.tsx)、[FeatureWallRail](../../../src/renderer/src/components/feature-wall/FeatureWallRail.tsx)、[FeatureWallTourSurface](../../../src/renderer/src/components/feature-wall/FeatureWallTourSurface.tsx)、[原生内容目录](../../../src/shared/feature-wall-workflows.ts) 和 [本地化内容](../../../src/renderer/src/components/feature-wall/feature-wall-tour-localized-copy.ts)。这些入口负责目录和播放器接线，不改变所属特性的业务事实。

## 可观察判据

| 编号 | 判据 |
| --- | --- |
| E01 | 问号打开探索，工作旅程和功能可以切换，关闭后可以重开。 |
| E02 | 功能分组、关联入口和既有内容仍可追溯到矩阵，暂缓内容不误删。 |
| E03 | 空内容不出现伪播放、虚假跳转或业务完成结果，建设中项有明确状态。 |
| E04 | 随屏功能可以从所属主题找到，浏览不要求先完成配置。 |
| E05 | 既有内容、播放控制和退出能力可以复用，探索不改变入门和反馈流程。 |
| E06 | 中文、键盘、明暗主题和常用桌面尺寸可用，窄屏不横向溢出。 |
| E07 | 目录表达五条工作联系，各项可以独立打开，建设中项不伪装成可用旅程。 |
| E08 | 内容选择、暂停、重播和离开时的状态符合当前播放器约定。 |

这些判据用于内容与界面验收。探索播放不构成业务 E2E。W01–W05 的真实结果由对应特性登记的 Electron 主链证明，同一条主链可覆盖多个特性。
