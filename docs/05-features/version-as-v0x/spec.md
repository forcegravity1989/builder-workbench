# Spec · 版本收成 v0.x

> **30 秒导读**：计划版本、自建版本、发版号是同一个 `v0.x`。对人说版本目标。运作活①「已经开过」用标题 + `bw:plan:v0.x` 一起判。旧周标签和旧计划名读回仍显示，新建只写 `v0.x`。原型见 [`prototype.html`](prototype.html)。

上游意图见 [`intent.md`](intent.md)。

## 设计拍板

1. **一个号**：`v主.次`（`^v[0-9]+\.[0-9]+$`）。三处同一串：`bw:plan:v0.3`、里程碑标题 `v0.3`、发版 Release / `bw:released:v0.3`。
2. **不再写周排期**：不打 `bw:week:*`，不建 `2026-W35` 里程碑。ISO 周只做节律（多久开运作活①、健康看哪几天、资产盘点周五）。
3. **本周确认哪个版本**：只在运作活①会话里。系统提示词灌上一发、未发列表、推荐下一号。人确认后 agent 打标、建或挂里程碑。
4. **发版**：按钮只在该版本视图。号=创建时的号，弹窗不能改。说明里**不**写上一发 / 未发。
5. **创建版本**：才写上一发 / 未发 / 推荐下一号。撞名拒收。未发布可改名；已发锁死。
6. **旧数据不迁、读回仍显示**：不把旧 `bw:week:` / 旧 `bw:plan:` 名改成 `v0.x`。下拉能切开看那些活。新建、排期不再写周标签。
7. **词**：界面和剧本「周目标 / 本周目标」→「版本目标」；「开始本周」→「开始本版本」；运作活①标题「更新指标 + 制定版本计划」（无周号）。`principles/03` 不动。

## 数据与匹配

**合法版本名**：`v` + 一段数字 + `.` + 一段数字。例：`v0.1`、`v0.12`、`v1.0`。不认 `v0.1.0`、`W35`、`2026-W35`、`MVP收尾`。

**版本集合**（创建、撞名、发版用它；下拉另外带上旧计划名和旧周）：

- 里程碑标题匹配 `v0.x` 的
- issue 上 `bw:plan:v0.x` 的
- 远端 Release / `bw:released:v0.x` 的（已发）

对不上 `v0.x` 的里程碑不当新版本。旧 `bw:plan:` 名和 `bw:week:` 读回仍算已排期，出现在下拉。新建只写 `v0.x`。

**上一发**：远端 Release 里最新一条且名字是 `v0.x` 的。没有再退同格式的 git 标签。

**未发**：在版本集合里、没有同名已发记录的。

**推荐下一号**：上一发与未发里最大的那个，末段 +1。上一发 `v0.1`、未发 `v0.2` → `v0.3`。都没有 → `v0.1`。

## 运作活①：已经开过（改字符串匹配，补标签）

现行逻辑是标题整句等于 `更新指标 + 制定本周计划 {YYYY-Www}`。改掉。

运作活①对人的标题：

| 何时 | 标题 |
|---|---|
| 刚建、还没确认版本 | `更新指标 + 制定版本计划` |
| 人确认之后 | `更新指标 + 制定版本计划 v0.3`（版本号，不是周号） |

workflow 人话名：`更新指标与版本计划`（剧本目录仍是 `week-planning`，不改 slug）。

**认一张运作活①**（满足一条即可）：

- 标题是 `更新指标 + 制定版本计划`，或以此开头且后面是空格 + 合法 `v0.x`
- workflow 是 `更新指标与版本计划`
- 身上有合法 `bw:plan:v0.x`（**补充的标签判据**）

**「本周已经开过、不要再新建」**：

1. 有一张**还没完成**的运作活①（光杆标题，或已打 `v0.x`）→ 进行中，挡住。
2. 有一张运作活①**带了合法 `v0.x` 标签**，且这张活的创建时间落在本 ISO 周 → 本周做过（含已完成），挡住。
3. 两条都不中 → 可以新建一张光杆标题的。

不再用「标题里有没有本周周号」去重。定时、健康的**时间窗**仍是 ISO 周（本周有没有提交、读数），不改成按版本号切窗。

建运作活①时**不**打 `bw:week:*`。确认版本后给这张运作活①和纳入的业务活打 `bw:plan:v0.x`，里程碑 `v0.x`。

健康灯「有没有版本目标」：读本 ISO 周那张运作活①（按上面规则找到的）评论里 `## 版本目标`。旧评 `## 周目标` / `## 本周目标` 只读。没读到不打勾。

## 操作逻辑

### 开始本版本

总览横幅「开始本版本」（本周还没有按上面判据开过才出现）→ 建光杆标题运作活① → 开工 → 切会话。

系统提示词多三段（现算，不落库）：上一发、未发列表、推荐下一号。剧本第三步先确认本周版本，再谈版本目标和纳入。

人确认后 agent：必要时把标题改成带 `v0.x`；打标签；建或挂里程碑；评论 `## 版本目标` / `## 本周纳入` / `## 本周指标读数`。纳入打 `bw:plan:v0.x` + `bw:category:*`，不打周标签。

### 创建版本

计划屏「全部 issue」→ 创建版本。

- 版本名默认=推荐下一号，人可改，必须是 `v0.x`
- 一行提示：上一发 / 未发 / 推荐
- 与已有计划版本或已发号撞名 → 按钮不可点，人话错误
- 通过：建里程碑，勾上的活打 `bw:plan:v0.x`

### 编辑版本名

钉在**计划屏 · 某个 `v0.x` 视图**，不是全部 issue，也不是独立弹窗。

工具条左上角是当前版本名。未发布时，名字右上角一只笔：

1. 点笔 → 版本名变成可编辑，笔换成绿色勾。
2. 点勾 → 保存。
3. 格式不是 `v0.x`，或与已有计划版本 / 已发号撞名 → toast 人话报错，退出编辑，左上角回到改之前的名字。远端一行不改。
4. 通过 → 一次做完三处，不允许只改一半：
   - 远端标签定义 `bw:plan:旧` 改名为 `bw:plan:新`（没有改名 API 就建新、迁、删旧）
   - 已经打在每张 issue 上的 `bw:plan:旧` 换成 `bw:plan:新`
   - 同名里程碑标题 `旧` → `新`（挂在里程碑上的 issue 跟着走）
5. 保存成功后勾变回笔，左上角和下拉都显示新号。

已发的版本：左上角只有号，**没有笔**。号锁死。

Esc 或不点勾就切走视图：不保存，回到原名。

### 发版本

只在某个 `v0.x` 视图。弹窗版本号只读，就是这个视图的号。没有可发的已完成活则按钮灰。确认：远端建同名 Release，再给本视图已完成的活打 `bw:released:v0.x`。

### 计划屏下拉

`全部 issue` + 各 `v0.x` + 旧计划名 + 旧周版本。进屏默认全部 issue。总览进度读本周运作活①确认的那个 `v0.x`，按挂了这张标签的活计数。创建 / 删除版本只在全部 issue；发版 / 改名只在未发的 `v0.x` 视图。

### 出错

- 名字不合法 / 撞名 / 改已发的 → 拒收，人话。
- 会话里模型写了 `W35` 或旧标题 → 校验脚本和非 `v0.x` 匹配都不认，活仍未分配，人再确认一次。
- 建里程碑失败 → 说出来，已打的标签不回滚（与现行挂里程碑口径相同）。

## 内核命令

| 命令 | 变什么 |
|---|---|
| `CreatePlanVersion` | 强制 `v0.x`；撞计划或已发号拒收 |
| `RenamePlanVersion { from, to }` | **新**。源必须未发布；目标过格式和撞名。一次同步：标签定义、issue 上的 `bw:plan:*`、里程碑标题 |
| `DeletePlanVersion` | 仍只删未发布；名字必须是合法 `v0.x` |
| `CutRelease` | `version` 必须等于正在看的那个计划版本且未发；壳不给改 |
| `StartWeekPlanning` | 去重改用上一节规则；`week` 仍传入（节律），不写进标题和标签 |
| `ScheduleIssue(week_of)` | 不再作为排期正本。排期只走 `ScheduleToPlan` |

## 词表与剧本

- `CONTEXT.md`：立「版本目标」；Avoid 周目标 / 本周目标。「计划 / 版本」写明号就是 `v0.x`，与发版号同一串。
- `week_comment.rs`：`HEADING_GOAL = "版本目标"`；读别名含 `周目标`、`本周目标`。
- `check-week-comment.py`、`week-plan-comment.md`、`week-planning/SKILL.md`、运作活①引导语：跟人话对齐。
- 壳：项目墙 / 计划屏周头 / 总览空态 / 健康灯四句。
- 指南、高保真、architecture 模块 13 跟壳对齐。CHANGELOG 旧条不回改。

指标卡上的「本周目标 ≥3」（指标的周数值）不是这个词，不改。

## 原型

同目录 [`prototype.html`](prototype.html)：步 1 总览横幅 → 步 2 会话灌词与确认版本 → 步 3 创建版本（上一发 / 未发）→ 步 4 版本视图发版（号锁死）→ 步 5 版本视图左上角笔 → 勾保存（撞名回退）。浏览器直接开。

## 客户会问

- **周版本去哪了？** 不再当新建的版本名。日历周还在，用来判断该不该开运作活①、健康看哪几天。已经打过的 `bw:week:` 读回仍显示，下拉能切。
- **能不能叫 W35？** 不能。新建和改名都要 `v0.x`。
- **上周的周标签怎么办？** 不迁。下拉还能看见、点进去看那些活。要收进 `v0.x` 再人手挂。
- **发版能不能改成 v0.4？** 不能。要发 v0.4 先有计划版本 v0.4，再进那个视图发。

## 硬核挑战

- **光杆标题只有一张，下周怎么再建？** 确认后标题改成带 `v0.x`。去重看「未完成的运作活①」和「本 ISO 周创建且带了 `v0.x` 的」。上周已完成的 `… v0.2` 不挡本周。
- **创建时间不在本机时区怎么办？** 与现行 ISO 周同一口径（机器本地时区、周一起点），不新开一套。
- **模型打错标签？** 新写对不上 `v0.x` 的不当新版本。人不点头不算确认。
- **为何发版不显示上一发？** 号已经锁死，再提示会让人以为还能选。上一发只在创建和会话里有用。

## 要求与验收

- **R1** 创建 / 改名 / 发版三处号一致；发版弹窗改不了号。
- **R2** 非法名、撞名、改已发 → 拒收。
- **R3** 开始本版本：未完成的运作活①或本周已打 `v0.x` 的运作活①会挡住再建。
- **R4** 旧周标签和旧计划名出现在下拉，点进去能看见那些活；新建 / 排期不再写 `bw:week:*`。
- **R5** 系统提示词能读回上一发、未发、推荐下一号。
- **R6** 门禁全过。规格 gate：本篇 + 可点原型。

## 不做

- 不改健康三条判据的时间窗算法（仍按 ISO 周看提交 / 读数）。
- 不改资产盘点标题和周五定时。
- 不迁旧周标签。
- 不改 `principles/03`。
- 不把运作活①改成按版本号一人一张、与周无关。
