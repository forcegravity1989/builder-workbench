# 探索 Monica — 意图

> **维护约定**：给产品、设计、实现与验收者读取。本篇只说明探索 Monica 作为目录与内容承载层的用户结果、价值、范围和排除。导航与内容规则见 [spec](spec.md)，当前认可和验证边界见 [STATUS](STATUS.md)。不在这里记录开发流水、运行日志或逐次取舍。

## 用户与问题

Builder 需要知道怎样用 Monica 完成一件工作，也需要在操作前快速理解一个屏幕或能力。只有功能清单时，用户难以看见工作之间的联系，也难以判断一项介绍是完整旅程、局部能力还是仍在建设。

探索 Monica 提供一个可回看的目录，把五条核心工作旅程和功能入口放在同一套导航中。它帮助用户找到内容并理解起点、动作和结果，业务事实和操作仍由所属特性提供。

## 目标结果

从现有帮助入口进入探索 Monica，用户可以在“工作旅程”和“功能”之间切换，选中主题后看到对应介绍、相关功能和当前内容状态。用户能随时退出并重新打开，不需要先完成浏览才能开始工作。

五条核心工作旅程按工作联系排列：

1. W01 明确方向
2. W02 制定版本计划
3. W03 构建交付
4. W04 验收成果
5. W05 查看效果

持续维护和沉淀复用在引导矩阵中作为建设中内容维护。在获得独立用户结果和验收方式前，它们不扩展 W01–W05 的核心旅程目录。

## 范围与边界

- 维护工作旅程与功能目录、分组、选中态、内容区、关闭和重开。
- 为每条旅程提供起点、结果、步骤联系和相关功能入口。30+ 个功能项是能力入口，不各自生成一条用户旅程 E2E。
- 复用现有演示播放器、组件和样式。内容只有在实际存在并完成适用验证后才展示对应动作。
- 业务行为、业务数据、计划、任务、验收和指标事实归各自特性。探索不复制完整操作说明，也不写入业务完成状态。
- 原型是布局和内容顺序的设计输入。原型播放、模拟数据和静态检查不能作为生产业务验收证据。
- 不新增安装弹窗、强制观看流程、业务数据库、平行执行器或单独的引导体系。

## 成功判据

- 用户能从帮助入口找到五条工作旅程和功能入口，并能区分完整旅程、局部介绍和建设中内容。
- 每个目录项都能回到引导矩阵和所属特性，内容状态与真实来源一致。缺内容时不伪造播放、跳转或完成结果。
- 关闭后可以从同一入口重开，目录选择、键盘操作、窄屏滚动和明暗主题不阻断查看。
- 探索目录不被误记为业务 E2E。真实工作旅程由 W01–W05 对应特性共用的 Electron 主链证明。
