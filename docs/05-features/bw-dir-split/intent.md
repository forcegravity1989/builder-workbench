## 问题

2026-08-29 对 `.bw/` 五份文件做了一次「谁读谁写」的全链审计,两个问题实锤:

1. **人机混放**。`.bw/` 顶层同时躺着给人读的章程(`PROJECT.md`)和给机器逐字段解析的配置(`project.toml` / `issue-policy.toml` / `managed.toml` / `standard.toml`),还有机器写的流水(`metrics/readings.jsonl`)。打开目录分不出「哪份该人编、哪份机器管」。(注:「注释过多」的直接原因是下条的假配置需要散文解释 + 各 `render()` 硬编码文案,由注释纪律与去冗解决;目录隔离解决的是「分不清谁写谁读」——两个问题相关但不是因果。)
2. **假配置**。一部分字段/文件解析了但**零消费**,注释还在为不存在的行为背书:
   - `issue-policy.toml` 的 `[[tool]]` 段四个字段(`kind`/`probe`/`version_cmd`/`capabilities`)无任何代码读——探活与工具→CLI 解析全部硬编码在适配模块(`tools.rs::probe` / `agent_for` / `probe_env`);
   - `[review]` 整段(`who_can_merge`/`require_pr_for`)除测试外零消费;
   - `ops1_trigger`/`ops2_trigger` 只用于配置屏显示文字,调度器不检查它们(只看 `ops2_schedule` 非空)——把 trigger 改成 `manual` 定时照样触发,是躺着的谎言;
   - `schema_version` 无人校验(metrics 文件有校验,这份没有);
   - `standard.toml`:**解析器**(`standard_file.rs`)全仓零调用,文件头却声称「Workbench 用它做对账」——实际对账正本是 `managed.toml` 指纹。评审轮修正:文件本身有一个真实的使用者——运作活③「规范铺底」的完成判据查的是它在不在 git 提交里(`vm_derive.rs:49`),所以删除时这条判据要改成查别的文件(见 spec);
   - `project.toml` 的 `standard_version` 镜像已失真(本仓自己就是 5.0 vs standard.toml 的 5.8),因为没有代码维护这个一致性。

## 五大拷问速答(02 §2)

1. **谁是客户**:发起人自己——单人 Builder,同时也是被管仓里干活的 agent 会话的运营者。Workbench 拿自己当被管项目用,所以这次变更里客户就是发起人,这一点如实写明。
2. **痛点**:打开 `.bw/` 分不清谁写谁读;更疼的是改了配置以为会生效、实际是硬编码在演(假配置)。
3. **最核心利益**:`.bw/` 里**每个字段都有消费者、每行注释都描述真行为、目录名直接回答「谁写的」**——信任不用靠读源码建立。
4. **怎么知道想要**:不是直觉——发起人先自发观察到「注释过多」,审计给出零消费实证(grep 级证据链,见 STATUS 评审记录),发起人两句定向拍板。
5. **体验长什么样**:见 `prototype.html`——目录树前后对照、瘦身后文件全文、名片上的对账结果、谁能写与写错了怎么办。

## 对齐 03(飞轮检验,三问实答)

1. **加强哪截**:「可信所以敢放手」(目录名直接回答「这份文件谁写的」、对账只反映真人改动)与「架构盘账回流」(资产盘点能按目录问责:state/ 异常=机器问题,config/ 异常=人的决定)。
2. **会不会拽回搬运工/模板代填/开树变主业**:不会——不触待办、gate、开树任何主路径;人对 `.bw/` 的日常交互反而变少(读顶层 Markdown 即可,config/ 只在拍板时碰)。
3. **会不会破坏八条**:逐条过——不涉「做不做人认/聊过≠gate/开树≠gate/没认不动主仓/该升 gate 不许继续/写码队友不给自己放行/定时只建队列」;**强化**「没数据显示未知」(假配置删除、名片上的对账结果如实分类)。无一条被削弱。

## 盼到的结果

- 打开任何被管项目的 `.bw/`,不看文档就能分辨:顶层 Markdown 全是给人(和 agent)通读的;`config/` 是人拍板的输入;`state/` 是机器写、人只审的。
- 配置文件里**每一个字段都有消费者**;每一行机器盖章的注释都描述真实行为,一节至多一行;对账的「人改过」只指真人改。
- `standard.toml` 这类「解析器无人调、文件头撒谎」的文件不存在;给已删设计立传的历史注释一律删掉——历史留在 git 里查,不占数据文件。
