# spec — CodeHub 适配

> **维护约定**：给实现、检视和验收者读取。本篇只维护 CodeHub 来源的当前行为和可观察判据。用户结果与归属见 [intent.md](intent.md)，证据与未验证边界见 [STATUS.md](STATUS.md)。命令形状以 [codehub-cli 指南](../../03-guide/codehub-cli.md) 和本机 `--help` 为准。

## 探索入口与归属

CodeHub 是内部集成提供的任务来源，任务结果归任务管理，计划与归档结果归版本计划和版本验收。它映射到探索 BW 的 W03「构建交付」和 W04「验收成果」。30+ 个功能项是能力入口，不各自生成用户旅程 E2E。

CJ01 是旧的 CodeHub 旅程标识，当前只用于追溯“CodeHub 任务 → 处理 → 重启读回”的片段。C01–C13 是来源适配的验收判据。两者都不创建独立 Explore 旅程。

## 来源选择与身份

1. 远程均为 CodeHub 且 `codehub-cli` 可用时，任务页选择来源 `codehub`。用户手动改过来源时不覆盖其选择。
2. 主机按 CodeHub 主机规则识别，项目身份来自登记的远程，不按目录名或当前活动项目猜测。Issue 与 MR 的项目路径、类型和正整数编号必须与链接一致。
3. CLI 缺失、未登录、无权限或项目身份不匹配时，显示原因和下一步，不切换到 `gh`，也不把同编号的其他来源任务当作目标。
4. 计划和验收中的 `provider: codehub` 引用按 CodeHub 项目路径读取，先尝试 Issue，再尝试 MR。没有链接且无法从远程地址生成网页链接时，读回失败并说明原因。

## 任务页行为

- 列表支持 Issue 和 MR、开放／我的／待评审、搜索、刷新和有界结果提示。结果超过当前范围时不能显示成全量。
- 详情显示标题、评论和平台属性。Issue 支持评论、标题和标签更新、完成／不计划／重复关闭及重新打开。关闭先写原因评论，评论失败不关闭。
- MR 支持评论、关闭、检查项和文件变更。检查项没有数据时显示空态，不显示为通过。文件变更按补丁重建行号，支持行评论，失效锚点只保留在对话中。
- 不提供草稿、Mark ready、表情、已读或修改评论正文。读取、写入和刷新失败都保留可理解的原因与重试入口。

## 计划、验收与归档

- 关联任务沿 CodeHub 项目路径打开同一 Issue 或 MR，详情来源保持 CodeHub。
- 归档卡按登记的 MR 引用读取 CodeHub 原生状态。匹配成功显示已合入、待合入或已关闭。项目身份缺失、当前路径不支持或查询失败时显示未知及原因，不能用 Git 状态替代平台合入证据。
- 主干基线存在可读 `.bw/planning/<版本>/data.json` 的目录才进入验收可选版本。坏目录或不在基线上的目录不列为当前计划。通用规则由[版本验收规格](../version-acceptance/spec.md)维护。

## 验收判据

| 标识 | 场景 | 可观察结果 |
| --- | --- | --- |
| C01 | CodeHub 仓库且 CLI 可用 | 任务页使用 CodeHub 来源，不先显示 GitHub 空列表 |
| C02 | 当前加载范围内搜索无结果 | 文案说明范围，不断言项目没有任务 |
| C03 | 关闭 Issue | 先有原因评论再关闭，评论失败时仍为打开 |
| C04 | MR 详情与关闭 | 可读对话、检查项和文件变更，可关闭且没有草稿动作 |
| C05 | CLI 缺失或未登录 | 显示对应状态，不显示为已连接 |
| C06 | 从计划或验收打开任务 | 详情来自匹配的 CodeHub 项目路径 |
| C07 | 读取归档 MR | 成功时显示真实平台状态，失败时显示未知及原因 |
| C08 | 基线版本目录有 `data.json` | 验收可选择该版本，坏目录不出现 |
| C09 | MR 有检查项 | 列出名称、状态和外链 |
| C10 | MR 有文件变更 | 显示文件树和行级 diff |
| C11 | MR 没有流水线 | 检查项显示空态，不显示为通过 |
| C12 | 文件变更中添加行评论 | 评论按 CodeHub 行锚定，失败时保留草稿 |
| C13 | Issue 修改标签 | 可选择、添加和清空标签，保存后详情与列表一致 |

## 取舍

复用任务管理的来源路由、详情和写操作，只在 CodeHub 适配差异处接入 CLI。归档坚持平台合入证据，读不到时保持未知。W03/W04 的跨特性主链负责用户旅程覆盖，CodeHub 不另建一条 Explore 旅程。
