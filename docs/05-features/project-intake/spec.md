## 范围与入口

入口：项目墙「+ 接入项目」与空态按钮、总览「接入项目」、知识库「请先接入项目」；项目墙卡片「+ 代码仓」走同一向导并附带挂组。

仓库注册与去重、克隆、项目组、工作树基址、路径授权、切换活跃项目全部复用 Orca 原生事务；BW 自有的是名片 `.bw/project.toml`、接入向导与项目墙卡片。不另建仓库管理平行实现。

知识库分类地图（`.bw/knowledge-map.toml`）能力已删除（2026-09-29 用户拍板）：接入不再写地图草稿，知识库分类回到内置规则；地图能力归知识库独立特性重新决策，本特性不承载。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 产物 |
|---|---|---|
| ① 项目地址 | 选「打开本地仓」（填路径或浏览）或「克隆远端仓」（`owner/repo` 简写或完整 URL + 父文件夹）；点下一步做路径授权与存在性检查 | 确定的目标仓路径 |
| ①-探 名片探测 | 本地：读仓里 `.bw/project.toml`，已有则回填表单；远端：**克隆前**经平台 API 读默认分支上的名片（待实施），读到回填、读不到四种原因分开说 | 回填的基础信息或如实的探测结论 |
| ② 基础信息 | 核对/补全名称、对标、想做什么、目标方向（全部选填，名称除外）；确认接入 | 名片意图 |
| ③ 接入事务 | 注册仓库（本地）或克隆（远端）→ 名片写入并经 PR 合入（见行为规则 2）→ 设单仓工作树基址 `.bw/worktrees`（未设时，可见可改）→ 可选挂入项目组 → 激活项目落到总览 | 墙上可见的项目 + 名片（或待合入 PR） |
| 日常 | 点墙卡切项目；卡片显示名片名称与简述；「+ 代码仓」扩组；「删除」移除墙上项目（绝不动仓和 worktree） | 项目切换与组维护 |

## 行为规则与异常

### 1. 名片写入保真

- 仓里已有名片：**只在原文上补空字段**，注释、`[chat]` 段、未知键逐字保留；不整份重渲染。历史别名 `north_star` 原位补值，不另插 `opportunity`。
- 名片文件不可读（二进制/损坏/读取异常）：**不覆盖**，如实报错；项目照接，名片可稍后补。
- 没有名片才按模板新建。写入或合并时确保 `.bw/.gitignore`（`worktrees/`）存在，已有不覆盖。
- 名称为空拒绝写入（表单已挡，此为兜底）。

### 2. 名片经 PR 合入被管仓

目标：名片是团队共享事实源，不是单机文件；后来者接入同一项目直接读到已有名片，不重复填、不重复起 PR；主检出不留脏文件。

- **固定树与分支**：名片只写项目约定固定树 `bw/project`（沿用计划/验收固定树管线，落 `.bw/worktrees/`），**主检出零写入**。
- **提交与 PR**：只提交 `.bw/project.toml`（及首次的 `.bw/.gitignore`），push 后开 PR——GitHub 走 `gh`，CodeHub 走 `codehub-cli`（用户确认支持，命令形态按 main v0.4 正本取证）；开 PR 失败如实提示原因与下一步，不冒充已开。
- **合入后更新主目录**：主检出不自动改动；PR 合入后提供显式「更新主目录代码」入口（主检出快进到含名片的提交），由人触发（行为按 main 正本取证细化）。
- **待合入提示**：PR 未合入期间，墙卡与总览项目卡明示「名片待合入 · PR #n」；合入由人在平台侧完成，**任何自动化不得合入或标完成**（铁律三）。
- **读正与幂等**：合入后名片以仓默认分支 HEAD 为准；HEAD 已有名片或已有开放名片 PR 时，接入只补空字段、**不重复起 PR**。adopted 判定看 HEAD 跟踪态，工作区脏文件不算（main b778da6ac 教训）。
- **编辑与补录**：提供名片编辑入口（main EditProjectCard 的对等物），复用同一固定树与 PR 流；名片写失败后的「可稍后补」由此入口承接。
- **无远端降级**：仓没有可识别远端（或非 git 仓/无提交的空仓）→ 名片就地写入主检出（保真合并语义不变），如实提示「没挂远端，名片只写在本机工作区」，不开 PR 也不冒充已开（main push_and_open_mr 降级语义）。
- **失败不推翻接入**：PR 环节失败（push 被拒、CLI 缺失、无权限）项目照接，如实报一行原因与下一步；不把失败说成成功。

### 3. 远端克隆前预探测

- 远端旅程在填表前**不 clone**，经平台 API raw 读该仓默认分支上的 `.bw/project.toml`，读到即回填表单（人打过的格子以人为准）。
- 四种「读不到」分开呈现：仓不存在/无权限、默认分支名不匹配、未登录/网络不通、确实没有名片——**「没查成」绝不呈现为「没接管过」**（main 4f9d93107 教训）。
- 手打地址点「下一步」时同样探测；探测回执竞态（用户已换目标仓）过期不应用。

### 4. 重复接入

- 同路径重复接入：由 Orca 原生按仓库身份去重，复用并提示「项目已添加」。
- 同远端身份（URL 归一化后同仓）已接入到其他路径：提示已接入的项目并引导复用，不再克隆第二份（2026-09-30 用户确认做）。

### 5. 呈现与落点

- 接入成功激活项目并落到**总览**（与 intent 目标体验一致；此前落项目墙为偏差，已修）。
- 项目墙**不设「本机环境」探测条**（本批已删硬编码绿灯条）。将来若做真实探测，参照 main 正本：只探产品自己会调用的工具（claude / cursor-agent / gh / codehub-cli），三态呈现（可用/不可用+指南/未检测灰），**不探自己不会起的东西，没接实现显示灰不显示绿**；探测清单随墙健康灯一并决策。

## 客户会问

- **为什么名片要走 PR？** 名片是团队共享的项目事实源；PR 让 builders 评审合入，后来者接入直接读到，不用每人填一遍，也不在你主检出里留脏文件。
- **接入会不会动我的仓？** 主检出零写入；名片只进 `bw/project` 固定树的 PR，合不合、何时合由你定。
- **接过的项目再接一次会怎样？** 同路径直接复用；仓里已有名片只补空字段、不重复起 PR。

## 硬核挑战（内部）

- Windows/WSL 路径归一与克隆目标比较（沿用 Orca 原生 canonical key，不自造）。
- `gh`/`codehub-cli` 登录态与权限失败的可解释呈现（区分没装、没登录、无权限、网络）。
- 两人同时接入同一新项目的 PR 竞态：后开者应发现已开放 PR 并转为补空字段。
- 固定树管线复用边界：`bw/project` 与计划/验收固定树共管线但独立身份，不共用会话与提示注入。
