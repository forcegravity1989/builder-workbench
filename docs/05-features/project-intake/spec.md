## 范围与入口

入口：项目墙「+ 接入项目」与空态按钮、总览「接入项目」、知识库「请先接入项目」；项目墙卡片「+ 代码仓」走同一向导并附带挂组。

仓库注册与去重、克隆、项目组、工作树基址、路径授权、切换活跃项目全部复用 Orca 原生事务；BW 自有的是名片 `.bw/project.toml`、接入向导与项目墙卡片。不另建仓库管理平行实现。

知识库分类地图（`.bw/knowledge-map.toml`）能力已删除：接入不再写地图草稿，知识库分类回到内置规则；地图能力归知识库独立特性重新决策，本特性不承载。

## 集合关系

| 数据集合 | 事实源 | 呈现 |
|---|---|---|
| Orca Projects | Orca 本机 profile 与已配对 runtime 的原生仓库/工作树目录 | 保留所有项目、分支和主机 worktree |
| BW 项目墙 | 同一批 Orca 仓库路径上是否存在 .bw/project.toml | 只展示已纳入 Workbench 的项目，并按项目/主机合并卡片 |
| Builder 主机配置 | 用户导入的共享 Orca pairing 配置 | 只描述要配对的主机，不携带项目 clone 清单 |

.bw/project.toml 同时提供项目名片内容和墙上纳入标记。项目墙不因为项目是从 Orca 原生入口还是 BW 入口添加而复制项目；BW 入口复用 Orca 添加事务，成功后写入/读取同一个项目名片。

## 墙卡读数

卡片 = **名片区** + **读数区**。名片区：名称、简述、对标、目标方向（名片字段渲染齐全）、主机来源标签（本机 / Builder 主机名，附连接事实）、名片待合入 chip（PR #n）、代码仓注册行、动作（打开项目总览 / 编辑名片 / ＋代码仓；删除只对本机注册提供）。

读数区四行。**通用规则**：

- 全部现算、不落业务数据库；杀进程重开后数字可重算且前后一致（铁律一）。
- 三态：有数据给真值；读不到给「—」（Unknown，灰字），不装绿、不装零；无版本时版本行显示「版本未定」、承诺进展行不显示。
- 只显数字，不可点击、不跳转；任务明细归总览。
- 文案永不出现健康或验收通过含义；不做健康灯（gate 结论与理由见 intent）。
- 墙头不做跨项目读数聚合：部分项目不可读时聚合会少数、冒充完整。墙头维持共 N 个项目 · N 个工作树、主机连接事实、上次刷新时间与「刷新」。

**各行口径**：

| 行 | 数据源与推导 | 读不到时 |
|---|---|---|
| 版本 | 原生选版偏好 `workbenchSelectedVersion`（人在流程选版器选过一次）+ 主干基线目录命中校验，与总览当前版本同源；不要求计划树对齐（对齐只门控承诺进展的材料新鲜度）；跨主机按仓库 owner/runtime 路由 | 「版本未定」（未选版或目录校验不过；不推断、不猜） |
| 承诺进展 | 该版本 `.bw/planning/<版本>/data.json` tasks × Issue 原生状态现算：**关闭即计「完成」、开放即计「开放」，关闭原因不参与计数**（取舍 9）；GitHub 走 `gh` 每仓 GraphQL 批量读回状态，CodeHub 身份匹配注册行（解析同任务屏）经 `codehub-cli` 逐条 viewTask **只读 Issue、不做 MR 兜底**（cli 错误无法区分「不存在」与瞬时失败，兜底同号 MR 会把别的对象状态计成本任务进展；读失败含引用实为 MR 即整行「—」，数字不猜对象）；计划树须同步主干基线（对齐），未同步时「—」附原因（计划屏「更新代码」可同步）；显示「完成 x · 开放 y」；不以进展冒充验收 | 任一任务读不到（provider 未接入、仓库未注册/坐标不可解析、CLI/RPC 失败）→ 全有或全无整行「—」，不拼半真数字 |
| 在跑会话 | 归属该项目工作树的 live 会话数：Orca 会话状态表（fresh 且非 done，与侧栏/状态栏同口径）× 项目工作树归属；跨主机条目经 Orca session tabs 事件推送链（语义变化秒级、安静期 15min 心跳续租、30min 租约只降 fresh 不删行、离线 ≤25s 判死）；墙数字 store 现算 + 30s 共享时钟自驱，不等刷新按钮、零外部调用 | **离线 ≠ 0**：卡内任一 runtime 来源主机连接事实为离线或未知时显示「—」；本机/SSH 无 runtime 连接语义，不阻塞计数；runtime 主机全部在线才给真实计数（可为 0） |
| PR 待审 | 该项目全部代码仓的 open PR 总数（GitHub 走 `gh`、CodeHub 走 `codehub-cli`、跨主机经 runtime RPC）；名片待合入 chip 是独立的 BW 流程事实，不随该计数变语义 | 「—」，不装 0 |

**已移除元素**（不留假占位）：健康灯 Dot 与墙头健康概览条、周次 chip、版本目标文字、上次交付、进度条。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 产物 |
|---|---|---|
| ① 项目地址 | 选「打开本地仓」（填路径或浏览）或「克隆远端仓」（`owner/repo` 简写或完整 URL + 父文件夹）；点下一步做路径授权与存在性检查 | 确定的目标仓路径 |
| ①-探 名片探测 | 本地：读仓里 `.bw/project.toml`，已有则回填表单；远端：**克隆前**经平台 API 读默认分支上的名片，读到回填、读不到四种原因分开说 | 回填的基础信息或如实的探测结论 |
| ② 基础信息 | 核对/补全名称、对标、想做什么、目标方向（全部选填，名称除外）；确认接入 | 名片意图 |
| ③ 接入事务 | 注册仓库（本地）或克隆（远端）→ 名片写入并经 PR 合入（见行为规则 2）→ 设单仓工作树基址 `.bw/worktrees`（未设时，可见可改）→ 可选挂入项目组 → 激活项目落到总览 | 墙上可见的项目 + 名片（或待合入 PR） |
| 日常 | 点墙卡切项目；卡片显示名片与四项读数；「+ 代码仓」扩组；「删除」移除墙上项目（绝不动仓和 worktree） | 项目切换与组维护 |

**跨主机纳入旅程**：

1. Builder 在 Orca Projects 或 BW 接入向导中拥有项目仓库；仓库里有 .bw/project.toml。
2. 用户在项目墙点击「导入 Builder 主机」，下载模板按「主机名: 配对地址」合成配置（或直接选择已共享的 builder-workbench-hosts.json），确认批量添加。
3. Orca runtime 主机列表更新并刷新各主机仓库目录；不 clone 项目、不新增平行项目记录。
4. 项目墙只显示能读到 .bw/project.toml 的项目卡片；卡内以主机标签标明来源（本机 / Builder 01 / Builder 02）并显示工作树计数；工作树明细与主机级选择由 Orca Projects 原生列表承担，墙不重复展示。
5. 用户点墙卡「打开项目总览」，激活项目进入总览（默认本机主注册）；切换 Builder 主机的工作树在 Orca Projects 中选择，BW 屏沿用该主机上下文。
6. 删除再重新导入同一 Builder 主机后，项目墙不增加第二张卡；刷新后仍按项目/主机稳定身份合并。

**扫墙旅程**：leader 扫墙 → 每张卡读到版本、承诺进展、在跑会话、PR 待审四项事实（或如实的「版本未定」/「—」）→ 数字与 gh/git/Orca 独立读回一致 → 杀进程重开后读数一致。

## 行为规则与异常

### 1. 名片写入保真

- 仓里已有名片：**只在原文上补空字段**，注释、`[chat]` 段、未知键逐字保留；不整份重渲染。历史别名 `north_star` 原位补值，不另插 `opportunity`。
- 名片文件不可读（二进制/损坏/读取异常）：**不覆盖**，如实报错；项目照接，名片可稍后补。
- 没有名片才按模板新建。写入或合并时确保 `.bw/.gitignore`（`worktrees/`）存在，已有不覆盖。
- 名称为空拒绝写入（表单已挡，此为兜底）。

### 2. 名片经 PR 合入被管仓

目标：名片是团队共享事实源，不是单机文件；后来者接入同一项目直接读到已有名片，不重复填、不重复起 PR；主检出不留脏文件。

- **固定树与分支**：名片只写项目约定固定树 `bw/project`（沿用计划/验收固定树管线，落 `.bw/worktrees/`），**主检出零写入**。
- **提交与 PR**：只提交 `.bw/project.toml`（及首次的 `.bw/.gitignore`），push 后开 PR——GitHub 走 `gh`，CodeHub 走 `codehub-cli`（命令形态按 main 正本取证）；开 PR 失败如实提示原因与下一步，不冒充已开。
- **合入后更新代码**：主检出不自动改动；PR 合入后提供显式「更新代码」入口（主检出快进到含名片的提交），由人触发。
- **待合入提示**：PR 未合入期间，墙卡与总览项目卡明示「名片待合入 · PR #n」；合入由人在平台侧完成，**任何自动化不得合入或标完成**（铁律三）。
- **读正与幂等**：合入后名片以主检出 HEAD 为准；HEAD 已有名片或已有开放名片 PR 时，接入只补空字段、**不重复起 PR**。adopted 判定看 HEAD 跟踪态，工作区脏文件不算。
- **编辑与补录**：提供名片编辑入口，复用同一固定树与 PR 流；名片写失败后的「可稍后补」由此入口承接。
- **无远端降级**：仓没有可识别远端（或非 git 仓/无提交的空仓）→ 名片就地写入主检出（保真合并语义不变），如实提示「没挂远端，名片只写在本机工作区」，不开 PR 也不冒充已开。
- **失败不推翻接入**：PR 环节失败（push 被拒、CLI 缺失、无权限）项目照接，如实报一行原因与下一步；不把失败说成成功。

### 3. 远端克隆前预探测

- 远端旅程在填表前**不 clone**，经平台 API raw 读该仓默认分支上的 `.bw/project.toml`，读到即回填表单（人打过的格子以人为准）。
- 四种「读不到」分开呈现：仓不存在/无权限、默认分支名不匹配、未登录/网络不通、确实没有名片——**「没查成」绝不呈现为「没接管过」**。
- 手打地址点「下一步」时同样探测；探测回执竞态（用户已换目标仓）过期不应用。

### 4. 重复接入

- 同路径重复接入：由 Orca 原生按仓库身份去重，复用并提示「项目已添加」。
- 同远端身份（URL 归一化后同仓）已接入到其他路径：提示已接入的项目并引导复用，不再克隆第二份。

### 5. 跨主机与项目墙

- Orca Projects 不接受 BW 的任何过滤；原生列表始终展示全部项目和工作树，两层集合由项目墙一侧按 .bw/project.toml 判据承担。
- 项目墙读取远端项目的 .bw/project.toml 时经 Orca runtime 连接、按仓库 owner/runtime 路由，不能只读导入者本机路径。
- 跨主机判据边界：名片读取与 PR 证据依赖 BW 自有方法（`workbench.charter.*`）；配对的纯 Orca 主机（未运行 Workbench）其注册行判据不可读，如实不上墙、不冒充、不降级绕过——跨主机能力的边界是对端也运行 Workbench（团队内即本产品 runtime）。
- 读不到 .bw/project.toml（不存在或不可读）的仓库留在 Orca Projects，墙上不显示。名片 PR 证据（待合入/已合入未更新）只查本机注册行：该边缘源于本机接入流程（`bw/project` 固定树与 PR 由本机 BW 发起），远端注册行以能否读到名片文件为准。
- 同一项目在多个主机有 worktree 时只生成一张墙卡，卡内以主机标签显示来源；同一主机重复返回的注册与工作树不重复计数。
- 状态与连接：项目墙**不做健康灯**。主机连接事实（在线/离线/未知，由 Orca runtime 实时推导）用于导入反馈、来源标签附注、离线如实提示，以及会话读数的「离线 ≠ 0」判定；不得冒充项目健康。
- 离线诚实：BW 屏读取离线主机的工作树失败时如实呈现失败/无数据，不冒充成功；激活与报错沿用 Orca runtime 行为。
- 刷新语义：项目墙「刷新」= 重新读取本机与已配对 Builder 主机的仓库目录、名片数据与四项读数，作用于整面墙；界面显示上次刷新时间。
- 删除边界：「删除」只对本机注册提供——解除注册后墙与 Orca Projects 同步移除该条目，绝不动仓库与 worktree 文件；Builder 主机注册不呈现为可删行，主机去留随 Orca 主机配对管理。
- 工作树计数口径：按已纳入项目在当前配对目录内的注册行名下全部工作树现算、按 host-qualified 身份去重；不做逐工作树的名片判据。
- 「导入 Builder 主机」是主机批量导入的唯一入口，只调用 Orca 原生主机配对能力，不 clone 项目、不新增独立项目目录；导入对话框提供模板下载，配置结构为「主机名: Orca 配对地址」清单，BW 校验后逐台走原生配对——Builder 只需导出/提供自己主机的配对地址，不要求安装 BW；「接入项目」继续走现有单项目接入向导。
- 共享链接回显：本机设置保存上次生成链接的公开引用，重启后从 Orca 原生授权与密钥恢复同一链接；回显、复制不生成或轮换授权。已撤销、授权不存在或主机身份变化时不恢复；不另存令牌或私钥。生成、撤销仍沿原生语义。升级前未保存引用的链接不能自动找回；回显不代表网络可达，也不承担身份丢失后的旧链接恢复。
- 点墙卡激活项目后，BW 屏幕沿用当前选中项目和 host scope；不增加「跳转 Orca」的独立产品入口，原生 Projects 已在同一侧栏可见。

### 6. 呈现与落点

- 接入成功激活项目并落到**总览**（与 intent 目标体验一致）。
- 项目墙**不设「本机环境」探测条**（不探产品不会调用的工具）。健康灯已决定不做，探测条无回归挂载点；将来若产生探测工具需求，另行决策。

## 验收与衡量

验收点（E2E 用例注册暂缓，稳定后专项回补；点位先定，缺口记 STATUS）：

| 点 | 判据 |
|---|---|
| P-01 本地回填与保真合并 | 仓有名片（含 `[chat]` 与注释）→ 表单回填；提交后已有字段与文件其余内容逐字不变，只补空字段 |
| P-02 坏文件不覆盖 | 名片为二进制/损坏 → 不写入、报错如实、项目已接入 |
| P-03 远端预探测 | 选中有名片的远端仓 → clone 前回填；四类读不到分别提示；探测失败不呈现为「没接管过」 |
| P-04 名片 PR 化 | 接入 → `bw/project` 树提交 → PR 开启 → 待合入提示可见 → 合入后从 HEAD 读正；已有名片/开放 PR 不重复起 PR；主检出零写入 |
| P-05 重复接入 | 同路径复用提示；同远端身份提示已接入项目 |
| P-06 重启读回一致（铁律一） | 杀进程重开后墙卡、名片、组关系、活跃项目一致 |
| P-07 落点 | 接入成功落到总览且项目已激活 |
| P-08 主机批量导入与共享链接回显 | 对话框提供模板下载；导入按模板合成的配对配置后只配对主机并刷新仓库目录：不 clone 项目、不新增平行项目记录、Orca Projects 全量列表不受 BW 影响；生成共享链接后重启仍回显相同链接，复制不新增授权；撤销后重启不恢复该链接 |
| P-09 上墙判据与多主机归并 | 读不到 .bw/project.toml 的项目不上墙；同一项目多主机 worktree 只一张卡、卡内主机标签可辨来源；删除再重加主机不产生第二张卡 |
| P-10 连接与离线诚实 | 主机连接状态由 runtime 推导、仅作事实呈现（导入反馈/来源附注/离线提示/会话读数判定），不冒充项目健康；BW 屏读取离线主机如实失败不冒充成功 |
| P-11 刷新整墙 | 刷新后墙卡、名片数据与四项读数和本机及已配对主机的真实数据一致，并显示上次刷新时间 |
| P-12 删除边界 | 删除只对本机注册提供：解除注册后墙与 Orca Projects 同步移除条目、仓库与 worktree 文件不变；Builder 主机注册无删除入口 |

## 客户会问

- **为什么名片要走 PR？** 名片是团队共享的项目事实源；PR 让 builders 评审合入，后来者接入直接读到，不用每人填一遍，也不在你主检出里留脏文件。
- **接入会不会动我的仓？** 主检出零写入；名片只进 `bw/project` 固定树的 PR，合不合、何时合由你定。
- **接过的项目再接一次会怎样？** 同路径直接复用；仓里已有名片只补空字段、不重复起 PR。
- **墙上为什么没有健康灯？** 灯是机器下的结论，当前没有可靠的推导口径。墙只给可复算的事实——「版本未定」「承诺开放项没动」「会话离线」就是要你行动的信号，判断归人。

## 硬核挑战（内部）

- Windows/WSL 路径归一与克隆目标比较（沿用 Orca 原生 canonical key，不自造）。
- `gh`/`codehub-cli` 登录态与权限失败的可解释呈现（区分没装、没登录、无权限、网络）。
- 两人同时接入同一新项目的 PR 竞态：后开者应发现已开放 PR 并转为补空字段。
- 固定树管线复用边界：`bw/project` 与计划/验收固定树共管线但独立身份，不共用会话与提示注入。
- 会话计数的跨主机归属：会话状态条目按工作树归属到项目；新鲜度租约过期（可计 0）与主机离线（必须显「—」）是两种不同事实，不得混淆。
- 承诺进展的读回：GitHub 按仓 GraphQL 别名批量（无分页语义）；CodeHub 无批量状态接口，逐条 viewTask 只读 Issue（每任务 1 次调用；按项目失效域门控）；任一登记号缺回执或仓库未注册/坐标不可解析即整行 Unknown，不拼半真数字。

## 取舍（已决）

1. **原型边界**：既有已实现补链继续以真壳与 PR 截图为对照；墙卡读数增量用本目录交互高保真供确认，生产实现另行交付。
2. **CodeHub MR 创建**：`codehub-cli` 支持；命令形态按 main 正本取证后实现。
3. `kind` 字段保持文件保真但无编辑 UI（与 main 四字段表单一致）；不在本特性扩。
4. 仓根 `skills/bw-knowledge-docs`（随产品分发）中地图相关内容与原生技能登记：不动，归知识库独立特性裁决。
5. **严格判据掉卡**：读不到名片的项目（含主机离线期间、判据不可证的本机边缘）一律不在墙上显示，判据满足后自动恢复；不做「判据不可证保留卡/提示卡」。
6. **健康灯不做**（2026-10-15 gate）：灯是把动态判断交给机器，无可靠推导口径；卡片给事实，判断与催办归 leader。将来要做灯，另立特性先定推导口径。
7. **卡片只显数字不跳转、墙头不做读数聚合**（2026-10-15 gate）：任务明细归总览，墙保持扫读；跨项目聚合在部分项目不可读时会少数、冒充完整，不做。
8. **会话计数与 Orca 上游语义一致、不造补偿轮子**（2026-10-16 负责人确认）：30s 共享时钟、30min 租约、15min 安静期续租、「安静结束最坏 30min 才掉出计数」均沿 Orca 既有语义（侧栏同表现），BW 侧不掩盖不补偿；总览的当前版本标记保留计划树对齐门控，墙版本行放松为选版偏好+主干目录，未同步态两屏的标记语义差为接受残留（总览同放松归 overview-metrics 特性另行决策）。
9. **承诺进展口径：关闭=完成**（2026-10-16 负责人决策）：统一以 Issue 原生 closed 计「完成」、open 计「开放」，关闭原因（completed/决定不做/重复）不参与计数，CodeHub 项目由此在墙上出真实数字。代价：duplicate/决定不做关闭在墙上计入完成（如 v0.6 #340 以 duplicate 关闭即计完成），负责人接受——不正当关闭归关闭者，读数只如实计关闭事实。GitHub 侧 otherClosed 三分类与读回链 stateReason 字段随之移除（`issue-state-batch` 查询只取 state）；AGENTS.md 铁律三同交付最小修改（删「原生关闭原因区分已完成、决定不做与重复」与「关闭不自动证明目标达成」，补「关闭即计入完成（关闭原因不参与计数）；目标达成仍由人确认」，保留自动化/agent/定时不得自行关闭或确认完成）。
