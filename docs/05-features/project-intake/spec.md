## 添加项目与项目墙重构候选

归属 v1.0 G1，承接 #345、#497、#479、#489、#563、#499。[可点原型](project-settings-prototype.html)按浏览器批注收窄，方向已确认、完整制品待人评审，生产尚未实施。后续章节是现行实现基线，迁移目标以本节为准。

### 连续旅程与本轮边界

1. 原生有效项目直接上墙：本机 Git 仓与普通文件夹不以名片为准入；同仓跨主机沿既有身份归并。个人／团队由人设置，不批量猜测存量。
2. 所有添加入口复用 Orca AddRepoDialog 及打开／克隆／新建、主机选择与原生子流程；取消 BW 名片步骤，不自动提交名片 PR。添加后直接工作。
3. 点击项目名称沿原生激活与恢复继续工作，不自动新建会话。卡片右上角提供代码仓打开、原生仓库设置、远端克隆、总览与项目设置图标。名称继续工作、代码仓打开网页／本机路径是不同动作；总览图标沿现有导航。
4. 项目墙保留单一视图。卡片提供身份、项目负责人、版本目标和一排进展。需要细节直接进入已有 BW 总览、计划、任务、验收，不增加交付依据弹窗。
5. 个人和团队共用一个项目设置页，字段统一叫“项目名称”。沿用 ProjectSettingsRail 的项目信息表单和折叠；编辑按钮在分区标题右侧。原生项目／分组 ⋯ 放在墙卡，侧栏原位置仍保留；不走 PR 的操作不藏在项目信息编辑页。
6. 原生添加、主机、设置／帮助、工作区及会话不重画。原型在这些位置明确写“原型注释：复用 Orca／BW …”，模拟完成按钮也是评审工具，不是产品按钮。

### 数据归属

| 数据                       | 归属与生效                                                        | 显示规则                                                                                |
| -------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 个人／团队                 | 所属主机 Orca 本地配置；缺省个人，用户自行修改，立即保存，不走 PR | 只过滤共享项目墙入口；不撤回已经打开的工作区或会话，不建团队权限体系                    |
| 项目负责人                 | 共享项目信息，沿项目仓库 bw/project 及现有 PR/MR 流程             | 明确标“项目负责人”，空值统一“—”；独立于一个或多个参与者／主机，不从主机名或提交记录推断 |
| 名称、简介、对标、目标方向 | 同一共享信息编辑器；待合入不覆盖正式值                            | 共享名称沿现有名片优先、原生项目／组名回退；不自动覆盖 Orca 本机显示名称                |
| 主机名称与连接状态         | Orca 原生主机目录和状态                                           | 与项目负责人在同一行，来源过长截断并可悬浮读取；不是项目负责人，离线不是项目失败        |
| 版本目标、计划、任务、验收 | 已有计划／验收材料与 Issue 原生状态                               | 只作投影，修改回各自页面；不增加一句话承诺或独立约定验收日期字段                        |

同仓不同主机的类型独立。本机个人副本与远端团队副本可归同一卡；全部范围优先本机分类，团队筛选只保留符合条件的来源。不因有名片、路径或主机名自动分类。原型观察身份切换只供评审。

### 墙卡信息与布局

- 名称与图标操作在顶行；单仓打开／设置直接交接原生 UI，多仓只先选目标仓，不重画设置页。远端克隆也在右上角，不额外增加卡片底行。个人／团队由分组标题表达，不在卡内重复贴标签。项目负责人和主机在同一来源行，空值“—”不塌陷，长姓名和主机名截断并保留完整悬浮值。
- 有版本：显示版本号与实际目标标题，最多两条、每条最多两行；其余为“另 N 项目标”，进入已有版本总览，不自动生成摘要或在墙上罗列所有目标。目标来源是计划 goals，不把 timeWindow.end 或目标 deadline 猜成独立验收日期。
- 底部只有“计划｜任务｜验收”：计划归档状态、本版关联 Issue 完成／总数、人的验收结果。关闭即计任务完成，但任务全关、实现 PR 合入都不能替代人的验收。
- 不展示或为墙卡额外查询全仓 PR/MR 数量，不增加证据弹窗、会话等附加统计。未知如实为“—”或“版本未知”，无有效同版本／同承诺依据不显示达成。
- 无版本的 Git 仓和普通文件夹使用相同布局：已有介绍、负责人、身份与工作入口；不硬套交付读数、不预留大块空白。确认未使用版本与读取未知区分，文件夹类型不额外占一排标签。
- “项目较多”不单独立演示档，日常列表自然可滚动；场景切换只保留首次使用、日常、读取失败、提交失败、待更新和未知状态。

项目分组沿现有 `workbench-wall-projects` 聚合成一张卡，成员仓库可展开。原型以 shunfenger 的 api／web 双仓直接展示，并提供明确标记的移出／重新分组演示。组卡 ⋯ 复用 `ProjectGroupHeaderMenu`（重命名／删除组），成员 ⋯ 复用 `RepoHeaderProjectActionsMenu`（设置、图标、工作树显示、新建／移入／移出分组、移除项目）及其确认；成员 ＋ 沿原生创建器。不同对象不共用一份伪造菜单。分组不合并仓库文件，不累计各仓版本事实；主仓选择沿已有本机优先及组内顺序。真实多仓提交与权限边界仍待实施验证。

### 项目信息编辑与失败反馈

只查看时隐藏底部空状态；编辑后出现“提交评审”（确认无远端则“保存”），点击沿里程碑的短 Popover 列出改动，确认后调用现有项目信息提交流程。待合入显示“查看评审”，确认已合入后显示“更新项目信息”；正式墙卡不提前使用提案值。个人／团队修改即时保存，不进入这条提交链。

失败保留当前进程内的输入，使用 Orca `sonner` 与里程碑同一全局右下角通知，给出简短原因、“重试”和“开会话处理”；不在编辑面板或确认框塞错误条。重试前沿现有提交结果核对，避免重复提交。开会话通过 `open-workflow-draft` 交接项目、所属主机／工作树及失败阶段和原因，用户自行发送，不自动运行 Git 修复。该动作是待实现的薄接线；当前项目信息草稿仅进程内保存，不承诺重启恢复。原型“提交失败”场景只模拟首次连接失败、重试连接恢复，不代表真实修复。

写入范围沿现有 `charter-runtime`：常规编辑 `.bw/project.toml`；缺少 `.bw/.gitignore` 时可能补建，已有文件保留，提交只含这两个受控路径。无远端直接保存只写项目信息文件。保留已有原文校验、串行提交与结果读回，不为单文件编辑另造通用 Git 引擎或要求用户判断底层状态。

### 刷新与原生复用

刷新仍是重新读取已连接主机的目录、工作树及墙卡所需信息，不是重新导入主机地址。当前源实现具有组件内结果和查询键去重；不宣称持久缓存或实时保证。生产接线应保留按项目失效、批量任务读取，并删除不再展示的全仓 PR 计数查询；CodeHub 当前逐任务读取仍有成本，性能需真实数据验证。

不新增常驻大错误横幅或独立重试按钮；失败时用简短“部分主机未更新”及原生提示说明保留旧结果，刷新承担重试。主机连接沿原生主机管理处理。当前原型只模拟提示，不证明原生失败可观察性已经接线。

墙头保留批量导入主机，复用当前 FileInput 图标；更新时间显示具体时刻，不永远写“刚刚更新”。搜索与筛选保留。空态不再加第三个连接主机入口。左栏主机入口薄挂载原生远程主机菜单／servers 设置；原生帮助问号保留，侧栏按钮与上方导航采用相同尺寸。帮助和设置菜单内容沿原生，不复制另一套。

侧栏基线含 #523、#597、#599。全局已固定与当前项目版本区直接标记复用；本轮只呈现底部“其他工作区”（无版本时“工作区”）的当前项目范围。保留主工作区、临时排查与未归版树；原生固定策略决定重复呈现。Workspace Options 仅移除跨项目 Projects 筛选，保留适用的主机、排序、状态。侧栏不额外添加“返回项目墙”，工作区不加独立主机下拉。

原生项目／分组行的 ⋯、＋、展开／收起均保留；本轮不新增目标级或版本级开工入口。目标开工、任务屏任务开工及工作区绑定沿现状，入口易用性由 v1.0 G3 处理。绑定版本改变树中归属，不改变项目墙卡片数量。

设置原型直接引用现有 project-settings.css，继承表单、折叠和提交状态。技术边界放到明确标记的“原型注释”；仅保留项目类型所需的短 Tooltip，删除通用名称／负责人说明图标。类型在卡片“项目设置”顶部修改，本机立即保存；远端只读并说明应在所属电脑修改，不通过项目仓 PR 改类型。重新打开设置读取当前信息；墙头刷新重读墙数据，已有脏草稿不被静默覆盖。

### 实际代码复用与必要接线

这些是候选实现边界，不以原型点击成功代替实现验证：

- **原生多仓已有**：AddRepoDialog 的嵌套扫描和 group／separate 导入、ProjectGroup、moveProjectToGroup 可复用。BW 现有 startAddRepoSlot 仍进入旧 OnboardProjectPage，run-project-onboard 先执行名片流程再挂组；取消名片后须将原生添加结果接到当前项目组。hosted 完成回调目前只回传单个 repoId，批量新增结果和目标组归属需要薄编排，不能直接宣称完整复用已就绪。
- **仓库设置已有，目标路由需补齐**：openSettingsTarget 接收 pane、repoId、hostId。现有 ProjectSettingsRail 用主仓 host 配子仓 repoId 的路径不能照搬；卡片及多仓选择必须捕获同一目标仓及其 owner，同仓有本机副本时优先本机。建组不能依赖漂移后的全局 runtime；操作绑定目标主机。
- **打开仓库已有边界**：有 href 打开网页，本机无链接打开目录；远端无链接不得调用本机 shell.openPath。原型对这种情况说明从所属主机工作区打开。
- **新增数据与投影仍待做**：本机个人／团队属性、项目负责人字段、无名片上墙、目标与阶段读数、侧栏当前项目过滤均是本轮候选，不因复用组件就视作已实现。负责人字段复用现有名片保真编辑和 PR 流程；UI 仍叫“项目名称”，不分个人／团队表单，也不自动覆写 Orca 本机显示名称。

以上按任务树及 main 的 ProjectWallPage、ProjectSettingsRail、wall-project-repo-actions、AddRepoDialog 调用链核对；真实多仓、主机及提交验收留在实施阶段。

## 项目卡片配置增量（已确认设计）

2026-10-20 用户在逐项批注后要求「设计先提交到 GitHub，然后开始修改」，据此确认本轮界面与配置入口设计。下述描述是目标行为，生产实现及真实验证状态见 STATUS；未落实的数据能力单列，不以原型代替实现。价值边界见 [intent](intent.md#项目卡片配置增量已确认设计)，可点原型：[旧配置原型（Git 基线）](https://github.com/forcegravity1989/builder-workbench/blob/b90c743851b98f5beaa33f26b8145beb92782103/docs/05-features/project-intake/project-settings-prototype.html)。设计来源为 2026-10-20 用户在 Claude Code 右栏调研后的明确要求；使用仓内设计系统，原型 HTML、CSS 和 JavaScript 均为可编辑源码，无构建步骤。演示数据与提交结果都是模拟，不调用业务 API、不持久化草稿，不代表已经交付。

### 入口与布局

- 项目墙卡片的「配置」入口打开与卡片绑定的右侧栏，接替独立的「编辑名片」入口。点「配置」只选配置对象，不激活项目、不切主机或工作树；点「打开项目总览」仍走原有激活行为。
- 项目墙标题与刷新、导入 Builder 主机、接入项目、关闭保持同一行；四个入口依次只显示刷新、文件导入、加号、X 图标。导入与接入沿用既有动作，不能因精简呈现拆到两行。按钮悬停／聚焦显示 Tooltip，并提供可访问名称，遵循[全项目极简操作规范](../../04-design-system/guidelines.md#文案)。
- 墙卡保留项目名、愿景与「状态点 + Builder 名称」；总览、配置两个纯图标固定在右上角。状态点只表示来源连接事实，未知不装绿；不恢复主干已移除的项目健康灯。删除仓库数、工作树数、「当前项目」、版本占位和重复仓库名，不为这些信息预留空白。仓库与设备详情只在配置内呈现，不以「开发电脑／构建 Mac mini」代替 Builder。此为本设计原型的墙卡收敛，不宣称生产 G3 界面已变化。
- 配置栏宽约 384–432px，主内容保留项目墙；窄屏改为覆盖式面板。栏头始终显示项目名与关闭入口，栏底始终显示草稿或 PR 状态及对应动作。
- 栏头不常驻「读取自项目主目录／main」这类内部来源信息；仅在待合入、合入后待更新等需要处理的阶段显示状态与动作。
- 分区顺序固定为「项目信息、成员与负责人、代码仓、项目所在电脑」，本轮不增加排序和隐藏配置。各区独立折叠，折叠标题仍保留「2 项待补充」、成员名称、「1 个仓库」以及具体电脑名和离线提示。
- 默认只展开项目信息，其余分区收起；存在离线来源时原型展开项目所在电脑。异常与待提交数量必须在折叠态可见。所有数量来自对应事实源，读取失败为未知，不把未知显示成零或健康。

现有版本、承诺进展、在跑会话和待审 PR 四项真实读数保留在卡片，继续遵循下文「墙卡读数」的数据口径。配置原型聚焦名片与右侧栏，未重画读数区域，不代表删除这些能力。重复仓库信息和技术计数移入配置，新增布局以本节为准。

### 配置对象与操作边界

| 分区         | 摘要与展开信息                                                                                   | 动作及归属                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 项目信息     | 名称、想做什么、对标、愿景；已填、待补或待提交数量                                               | 「编辑信息／补充信息」就地切表单；变更集中在底部查看对比、提交 PR                                                  |
| 成员与负责人 | Builder 名称与负责人；人员独立于执行设备                                                         | 本轮只演示「管理成员」入口；成员来源与维护能力未实现，不把示例人物写入现有名片协议                                 |
| 代码仓       | 仓库数量、主仓、远端、本机目录、已解析的主干基线                                                 | 「添加代码仓」沿现有接入向导并附带项目组；「仓库设置」复用原生设置，不在栏里建立路径、基线、工作树的第二套编辑表单 |
| 项目所在电脑 | 折叠摘要列具体电脑名；展开显示设备名称、本机／远程、可读取的设备标识及连接事实；不显示工作树计数 | 「管理远程连接」打开原生配对设置；不在配置栏删除远端注册，不在此切换当前执行主机或工作树                           |

「电脑」是存放这个项目仓库、可供执行任务的设备，不是人员。设备名来自原生主机名称，设备标识仅在原生数据可提供时展示；缺失时如实说明，不用「Builder 01」或机器数量代替身份。示例中的「开发电脑／DEV-PC」「构建 Mac mini／BUILD-MAC」均为演示设备，不推断设备的所有人。

卡片上的 Builder 与配置内的负责人均为独立演示人物，状态点当前为未知；不根据机器名称、配对名称或主机在线推断成员身份、负责人、人员状态或项目健康。愿景沿用名片 `opportunity` 字段，仅调整界面标签。

多仓项目应按现有组聚合列仓，按明确仓库上下文读写名片；单仓原型不代替多仓来源决策，见待决问题。远端单独注册但无本机主仓时必须按 owner/runtime 路由，离线则禁止对该来源写入，不能退到另一台主机冒充成功。

### 完整主旅程与变更语义

1. 在墙卡点「配置」，读取当前项目的现行名片、原生仓库与主机事实；名片草稿和现行值明确区分。
2. 展开项目信息，点「编辑信息」，修改一个或多个字段。名称必填；其余字段选填。底部实时显示变更数，折叠项目信息后仍可见。
3. 点「查看 N 项变更」，逐字段对照原值与新值，留空也明确显示。未改变不允许提交；「继续编辑」保留草稿。
4. 点「提交 PR」，复用固定树和 PR 流提交；成功后显示「名片待合入 · PR #n」及查看入口，禁止重复提交。当前项目卡片继续显示主检出的现行信息。
5. 人在平台合入后，能读到合入证据时显示「已合入，待更新代码」。CodeHub 须核对同仓 MR 的来源／目标分支及项目身份，并由 MR 原生提交列表证明包含本次名片材料提交；读取或分页失败保持未知，不把同名分支的旧 MR 当作本次合入。人点「更新代码」沿既有快进链并重新读取，成功后墙卡和配置栏使用新信息；快进或读取失败保留旧值并解释失败。读不到合入证据的平台保持「状态未知」，不凭等待时间转成成功。
6. 原型中合入状态通过顶端「已合入待更新」场景手动演示，产品界面不提供自动合入或替人完成动作。

编辑已有非空字段是本提案的**新决策**：接入时原有保真补空行为不变；日常编辑仅应用人确认的字段差异，保留其他字段、未知键、注释、`[chat]` 段及旧别名。提交携带读取时的完整原文；已被别人修改时禁止静默覆盖，重新读取并让人核对冲突。同一来源仓库在所属主机进程内串行提交；这不是跨进程文件锁。

**本轮生产落点与边界**：`ProjectSettingsRail` 接替独立名片编辑页，复用原生折叠、提示和对话框。实际分区为「项目信息、代码仓、Builder 主机」；成员与负责人无事实源，仍仅为原型示例，生产不生成这类记录。卡片沿既有命名主机呈现「状态点 + 名称」，仅表示来源与连接事实，不推断人员所有权。远程 runtime 按 owner 路由；SSH 来源在此只读，旧 runtime 未返回原文时提示升级并禁用编辑。确认没有远端时，对比后显示「保存到主机」并写项目所属主机；远端探测失败不降级成本地写入。CodeHub 未读到合入证据时保留待核对状态与草稿，不自动宣称成功。分区重新打开使用默认展开状态；草稿只在当前进程内保留，不承诺重启恢复。实际验收状态见 [STATUS](STATUS.md)。

### 异常、保存与恢复

- **草稿退出**：关闭、切项目、离开页面或刷新前，有未提交变更时提供「继续编辑／丢弃并离开」。仅展开、收起和切主题不丢草稿；重新打开面板恢复分区展开偏好即可，不另建项目业务存储。本轮原型仅演示面板关闭与切项目保护，浏览器刷新和进程重启不会恢复草稿。
- **权限／网络／提交失败**：就地显示失败阶段和下一步，保留草稿可重试。提交结果不明时先查已有 PR；没有确认不能显示「已创建」或重复创建。
- **损坏名片**：与空字段区分，展示读取失败和「查看文件／重试读取」，禁用编辑与提交，不覆盖损坏文件。
- **离线**：折叠摘要保留离线电脑的名称与离线标识；其余可读来源仍展示。主机在线不等于项目健康。
- **无远端**：沿用现行本机降级语义；对比后按钮明确显示「保存到本机」，结果说明未共享。本次原型未覆盖此场景。
- **已有名片 PR**：打开时核对现行值与已有草稿，显示待合入及 PR；不重复起单。更新已有 PR 的二次编辑本轮暂不提供。
- **键盘与可访问性**：分区使用按钮及 aria-expanded；支持 Tab、Enter/Space；Esc 关闭当前弹层，再关闭配置栏，脏草稿仍受退出保护；关闭后焦点返回对应卡片入口。

### 取舍与待决问题

- **推荐**：固定四分区，摘要可折叠，配置栏与项目墙并存；与原生设置衔接。相比独立配置页，能保留正在配置哪张卡的参照；代价是窄窗口需覆盖式呈现。
- **推荐**：项目信息集中一次对比并提交；不做逐输入框自动保存，避免把半句话写入共享事实源。
- **已确认目标**：允许修改已有名片值及清空选填字段；接入只补空与日常编辑分开，后者使用原文冲突校验与保真字段编辑。真实远端及重启读回尚需验证。
- **本轮边界**：多仓项目沿现有主注册仓读写名片；项目级单一名片跨仓共享不在本轮范围。
- **待落实**：成员、负责人及 Builder 状态的数据来源与维护方式；当前名片没有这些字段，原型的示例人物不构成新增协议或已交付能力。
- 排序、隐藏分区、项目群、会话上下文用量、连接器和后台任务不进入本轮配置设计。仓库设置和主机管理原型只展示交接入口，不模拟已有完整设置页。

## 墙卡读数

卡片 = **名片区** + **读数区**。名片区与动作布局遵循上文「项目卡片配置增量」；本节只定义读数口径。名片待合入及仓库注册操作移到对应配置分区，删除仍只对本机注册提供。

读数区四行。**通用规则**：

- 全部现算、不落业务数据库；杀进程重开后数字可重算且前后一致（铁律一）。
- 三态：有数据给真值；读不到给「—」（Unknown，灰字），不装绿、不装零；无版本时版本行显示「版本未定」、承诺进展行不显示。
- 只显数字，不可点击、不跳转；任务明细归总览。
- 文案永不出现健康或验收通过含义；不做健康灯（gate 结论与理由见 intent）。
- 墙头不做跨项目读数聚合：部分项目不可读时聚合会少数、冒充完整。墙头维持共 N 个项目 · N 个工作树、主机连接事实、上次刷新时间与「刷新」。

**各行口径**：

| 行       | 数据源与推导                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 读不到时                                                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 版本     | 原生选版偏好 `workbenchSelectedVersion`（人在流程选版器选过一次）+ 主干基线目录命中校验，与总览当前版本同源；不要求计划树对齐（对齐只门控承诺进展的材料新鲜度）；跨主机按仓库 owner/runtime 路由                                                                                                                                                                                                                                                                                                                                                  | 「版本未定」（未选版或目录校验不过；不推断、不猜）                                                                                                           |
| 承诺进展 | 该版本 `.bw/planning/<版本>/data.json` tasks × Issue 原生状态现算：**关闭即计「完成」、开放即计「开放」，关闭原因不参与计数**（取舍 9）；GitHub 走 `gh` 每仓 GraphQL 批量读回状态，CodeHub 身份匹配注册行（解析同任务屏）经 `codehub-cli` 逐条 viewTask **只读 Issue、不做 MR 兜底**（cli 错误无法区分「不存在」与瞬时失败，兜底同号 MR 会把别的对象状态计成本任务进展；读失败含引用实为 MR 即整行「—」，数字不猜对象）；计划树须同步主干基线（对齐），未同步时「—」附原因（计划屏「更新代码」可同步）；显示「完成 x · 开放 y」；不以进展冒充验收 | 任一任务读不到（provider 未接入、仓库未注册/坐标不可解析、CLI/RPC 失败）→ 全有或全无整行「—」，不拼半真数字                                                  |
| 在跑会话 | 归属该项目工作树的 live 会话数：Orca 会话状态表（fresh 且非 done，与侧栏/状态栏同口径）× 项目工作树归属；跨主机条目经 Orca session tabs 事件推送链（语义变化秒级、安静期 15min 心跳续租、30min 租约只降 fresh 不删行、离线 ≤25s 判死）；墙数字 store 现算 + 30s 共享时钟自驱，不等刷新按钮、零外部调用                                                                                                                                                                                                                                            | **离线 ≠ 0**：卡内任一 runtime 来源主机连接事实为离线或未知时显示「—」；本机/SSH 无 runtime 连接语义，不阻塞计数；runtime 主机全部在线才给真实计数（可为 0） |
| PR 待审  | 该项目全部代码仓的 open PR 总数（GitHub 走 `gh`、CodeHub 走 `codehub-cli`、跨主机经 runtime RPC）；名片待合入 chip 是独立的 BW 流程事实，不随该计数变语义                                                                                                                                                                                                                                                                                                                                                                                         | 「—」，不装 0                                                                                                                                                |

**已移除元素**（不留假占位）：健康灯 Dot 与墙头健康概览条、周次 chip、版本目标文字、上次交付、进度条。

## 完整用户旅程

| 阶段          | 用户与系统协作                                                                                                                                                | 产物                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| ① 项目地址    | 选「打开本地仓」（填路径或浏览）或「克隆远端仓」（`owner/repo` 简写或完整 URL + 父文件夹）；点下一步做路径授权与存在性检查                                    | 确定的目标仓路径                     |
| ①-探 名片探测 | 本地：读仓里 `.bw/project.toml`，已有则回填表单；远端：**克隆前**经平台 API 读默认分支上的名片，读到回填、读不到四种原因分开说                                | 回填的基础信息或如实的探测结论       |
| ② 基础信息    | 核对/补全名称、对标、想做什么、目标方向（全部选填，名称除外）；确认接入                                                                                       | 名片意图                             |
| ③ 接入事务    | 注册仓库（本地）或克隆（远端）→ 名片写入并经 PR 合入（见行为规则 2）→ 设单仓工作树基址 `.bw/worktrees`（未设时，可见可改）→ 可选挂入项目组 → 激活项目落到总览 | 墙上可见的项目 + 名片（或待合入 PR） |
| 日常          | 点墙卡切项目；卡片显示名片与四项读数；「+ 代码仓」扩组；「删除」移除墙上项目（绝不动仓和 worktree）                                                           | 项目切换与组维护                     |

**跨主机纳入旅程**：

1. Builder 在 Orca Projects 或 BW 接入向导中拥有项目仓库；仓库里有 .bw/project.toml。
2. 用户在项目墙点击「导入 Builder 主机」，下载模板按「主机名: 配对地址」合成配置（或直接选择已共享的 builder-workbench-hosts.json），确认批量导入。每条有效地址交原生验证：新主机新增，同一主机公钥更新已有配对并保留名称与历史；其他主机占用归一后的名称则报冲突，不按名称直接跳过。
3. Orca runtime 主机列表更新并刷新各主机仓库目录；不 clone 项目、不新增平行项目记录。
4. 项目墙只显示能读到 .bw/project.toml 的项目卡片；卡内以主机标签标明来源（本机 / Builder 01 / Builder 02）并显示工作树计数；工作树明细与主机级选择由 Orca Projects 原生列表承担，墙不重复展示。
5. 用户点墙卡「打开项目总览」，激活项目进入总览（默认本机主注册）；切换 Builder 主机的工作树在 Orca Projects 中选择，BW 屏沿用该主机上下文。
6. 删除再重新导入同一 Builder 主机后，项目墙不增加第二张卡；刷新后仍按项目/主机稳定身份合并。

导入结果区分新增、更新与失败。失败条目保留供单独重试，已成功条目不重复提交；同主机重新配对后刷新原生目录与状态，不清除仍属于该主机的工作区。以上是行为判据，运行验证结果以交付 PR 为准。

**扫墙旅程**：leader 扫墙 → 每张卡读到版本、承诺进展、在跑会话、PR 待审四项事实（或如实的「版本未定」/「—」）→ 数字与 gh/git/Orca 独立读回一致 → 杀进程重开后读数一致。

## 行为规则与异常

### 1. 名片写入保真

- 仓里已有名片：**只在原文上补空字段**，注释、`[chat]` 段、未知键逐字保留；不整份重渲染。历史别名 `north_star` 原位补值，不另插 `opportunity`。
- 名片文件不可读（二进制/损坏/读取异常）：**不覆盖**，如实报错；项目照接，名片可稍后补。
- 没有名片才按模板新建。写入或合并时确保 `.bw/.gitignore`（`worktrees/`）存在，已有不覆盖。
- 名称为空拒绝写入（表单已挡，此为兜底）。

### 2. 名片经 PR 合入被管仓

目标：名片是团队共享事实源，不是单机文件；后来者接入同一项目直接读到已有名片，不重复填、不重复起 PR；主检出不留脏文件。

- **固定树与分支**：名片只写项目约定固定树 `bw/project`（沿用计划/验收固定树管线，落 `.bw/worktrees/`），**主检出零写入**。
- **提交与 PR**：只提交 `.bw/project.toml`（及首次的 `.bw/.gitignore`），push 后开 PR——GitHub 走 `gh`，CodeHub 走 `codehub-cli`（命令形态按 main 正本取证）。CodeHub 创建或采用已有 MR 后保留详情返回的真实网页链接；克隆／API 与网页域名不同时，须由原生项目详情证明同仓身份，不能猜链接或丢弃已读到的链接。开 PR 失败如实提示原因与下一步，不冒充已开。
- **合入后更新代码**：主检出不自动改动；PR 合入后提供显式「更新代码」入口（主检出快进到含名片的提交），由人触发。
- **待合入提示**：PR 未合入期间，墙卡与总览项目卡明示「名片待合入 · PR #n」；合入由人在平台侧完成，**任何自动化不得合入或标完成**（铁律三）。
- **读正与幂等**：合入后名片以主检出 HEAD 为准；HEAD 已有名片或已有开放名片 PR 时，接入只补空字段、**不重复起 PR**。adopted 判定看 HEAD 跟踪态，工作区脏文件不算。
- **编辑与补录**：提供名片编辑入口，复用同一固定树与 PR 流；名片写失败后的「可稍后补」由此入口承接。
- **无远端降级**：仓没有可识别远端（或非 git 仓/无提交的空仓）→ 名片就地写入主检出（保真合并语义不变），如实提示「没挂远端，名片只写在本机工作区」，不开 PR 也不冒充已开。
- **失败不推翻接入**：PR 环节失败（push 被拒、CLI 缺失、无权限）项目照接，如实报一行原因与下一步；不把失败说成成功。

### 3. 远端克隆前预探测

- 远端旅程在填表前**不 clone**，经平台 API raw 读该仓默认分支上的 `.bw/project.toml`，读到即回填表单（人打过的格子以人为准）。
- 四种「读不到」分开呈现：仓不存在/无权限、默认分支名不匹配、未登录/网络不通、确实没有名片——**「没查成」绝不呈现为「没接管过」**。
- 手打地址点「下一步」时同样探测；探测回执竞态（用户已换目标仓）过期不应用。

### 4. 重复接入

- 同路径重复接入：由 Orca 原生按仓库身份去重，复用并提示「项目已添加」。
- 同远端身份（URL 归一化后同仓）已接入到其他路径：提示已接入的项目并引导复用，不再克隆第二份。

### 5. 跨主机与项目墙

- Orca Projects 不接受 BW 的任何过滤；原生列表始终展示全部项目和工作树，两层集合由项目墙一侧按 .bw/project.toml 判据承担。
- 项目墙读取远端项目的 .bw/project.toml 时经 Orca runtime 连接、按仓库 owner/runtime 路由，不能只读导入者本机路径。
- 跨主机判据边界：名片读取与 PR 证据依赖 BW 自有方法（`workbench.charter.*`）；配对的纯 Orca 主机（未运行 Workbench）其注册行判据不可读，如实不上墙、不冒充、不降级绕过——跨主机能力的边界是对端也运行 Workbench（团队内即本产品 runtime）。
- 读不到 .bw/project.toml（不存在或不可读）的仓库留在 Orca Projects，墙上不显示。名片 PR 证据（待合入/已合入未更新）只查本机注册行：该边缘源于本机接入流程（`bw/project` 固定树与 PR 由本机 BW 发起），远端注册行以能否读到名片文件为准。
- 同一项目在多个主机有 worktree 时只生成一张墙卡，卡内以主机标签显示来源；同一主机重复返回的注册与工作树不重复计数。
- 状态与连接：项目墙**不做健康灯**。主机连接事实（在线/离线/未知，由 Orca runtime 实时推导）用于导入反馈、来源标签附注、离线如实提示，以及会话读数的「离线 ≠ 0」判定；不得冒充项目健康。
- 离线诚实：BW 屏读取离线主机的工作树失败时如实呈现失败/无数据，不冒充成功；激活与报错沿用 Orca runtime 行为。
- 刷新语义：项目墙「刷新」= 重新读取本机与已配对 Builder 主机的仓库目录、名片数据与四项读数，作用于整面墙；界面显示上次刷新时间。
- 删除边界：「删除」只对本机注册提供——解除注册后墙与 Orca Projects 同步移除该条目，绝不动仓库与 worktree 文件；Builder 主机注册不呈现为可删行，主机去留随 Orca 主机配对管理。
- 工作树计数口径：按已纳入项目在当前配对目录内的注册行名下全部工作树现算、按 host-qualified 身份去重；不做逐工作树的名片判据。
- 「导入 Builder 主机」是主机批量导入的唯一入口，只调用 Orca 原生主机配对能力，不 clone 项目、不新增独立项目目录；导入对话框提供模板下载，配置结构为「主机名: Orca 配对地址」清单，BW 校验后逐台走原生配对——Builder 只需导出/提供自己主机的配对地址，不要求安装 BW；「接入项目」继续走现有单项目接入向导。
- 共享链接回显：本机设置保存上次生成链接的公开引用，重启后从 Orca 原生授权与密钥恢复同一链接；回显、复制不生成或轮换授权。已撤销、授权不存在或主机身份变化时不恢复；不另存令牌或私钥。生成、撤销仍沿原生语义。升级前未保存引用的链接不能自动找回；链接区明确显示“已保存的共享链接，当前连接状态未验证”，无法连接时引导先检查共享服务和网络地址；不因回显改变监听范围，不承担身份丢失后的旧链接恢复。地址变化仍提示旧链接已过时。
- 点墙卡激活项目后，BW 屏幕沿用当前选中项目和 host scope；不增加「跳转 Orca」的独立产品入口，原生 Projects 已在同一侧栏可见。

### 6. 呈现与落点

- 接入成功激活项目并落到**总览**（与 intent 目标体验一致）。
- 项目墙**不设「本机环境」探测条**（不探产品不会调用的工具）。健康灯已决定不做，探测条无回归挂载点；将来若产生探测工具需求，另行决策。

## 客户会问

- **为什么名片要走 PR？** 名片是团队共享的项目事实源；PR 让 builders 评审合入，后来者接入直接读到，不用每人填一遍，也不在你主检出里留脏文件。
- **接入会不会动我的仓？** 主检出零写入；名片只进 `bw/project` 固定树的 PR，合不合、何时合由你定。
- **接过的项目再接一次会怎样？** 同路径直接复用；仓里已有名片只补空字段、不重复起 PR。
- **墙上为什么没有健康灯？** 灯是机器下的结论，当前没有可靠的推导口径。墙只给可复算的事实——「版本未定」「承诺开放项没动」「会话离线」就是要你行动的信号，判断归人。

## 硬核挑战（内部）

- Windows/WSL 路径归一与克隆目标比较（沿用 Orca 原生 canonical key，不自造）。
- `gh`/`codehub-cli` 登录态与权限失败的可解释呈现（区分没装、没登录、无权限、网络）。
- 两人同时接入同一新项目的 PR 竞态：后开者应发现已开放 PR 并转为补空字段。
- 固定树管线复用边界：`bw/project` 与计划/验收固定树共管线但独立身份，不共用会话与提示注入。
- 会话计数的跨主机归属：会话状态条目按工作树归属到项目；新鲜度租约过期（可计 0）与主机离线（必须显「—」）是两种不同事实，不得混淆。
- 承诺进展的读回：GitHub 按仓 GraphQL 别名批量（无分页语义）；CodeHub 无批量状态接口，逐条 viewTask 只读 Issue（每任务 1 次调用；按项目失效域门控）；任一登记号缺回执或仓库未注册/坐标不可解析即整行 Unknown，不拼半真数字。

## 取舍（已决）

1. **原型边界**：既有已实现补链继续以真壳与 PR 截图为对照；墙卡读数增量用本目录交互高保真供确认，生产实现另行交付。
2. **CodeHub MR 创建**：`codehub-cli` 支持；命令形态按 main 正本取证后实现。
3. `kind` 字段保持文件保真但无编辑 UI（与 main 四字段表单一致）；不在本特性扩。
4. 仓根 `skills/bw-knowledge-docs`（随产品分发）中地图相关内容与原生技能登记：不动，归知识库独立特性裁决。
5. **严格判据掉卡**：读不到名片的项目（含主机离线期间、判据不可证的本机边缘）一律不在墙上显示，判据满足后自动恢复；不做「判据不可证保留卡/提示卡」。
6. **健康灯不做**（2026-10-15 gate）：灯是把动态判断交给机器，无可靠推导口径；卡片给事实，判断与催办归 leader。将来要做灯，另立特性先定推导口径。
7. **卡片只显数字不跳转、墙头不做读数聚合**（2026-10-15 gate）：任务明细归总览，墙保持扫读；跨项目聚合在部分项目不可读时会少数、冒充完整，不做。
8. **会话计数与 Orca 上游语义一致、不造补偿轮子**（2026-10-16 负责人确认）：30s 共享时钟、30min 租约、15min 安静期续租、「安静结束最坏 30min 才掉出计数」均沿 Orca 既有语义（侧栏同表现），BW 侧不掩盖不补偿；总览的当前版本标记保留计划树对齐门控，墙版本行放松为选版偏好+主干目录，未同步态两屏的标记语义差为接受残留（总览同放松归 overview-metrics 特性另行决策）。
9. **承诺进展口径：关闭=完成**（2026-10-16 负责人决策）：统一以 Issue 原生 closed 计「完成」、open 计「开放」，关闭原因（completed/决定不做/重复）不参与计数，CodeHub 项目由此在墙上出真实数字。代价：duplicate/决定不做关闭在墙上计入完成（如 v0.6 #340 以 duplicate 关闭即计完成），负责人接受——不正当关闭归关闭者，读数只如实计关闭事实。GitHub 侧 otherClosed 三分类与读回链 stateReason 字段随之移除（`issue-state-batch` 查询只取 state）；AGENTS.md 铁律三同交付最小修改（删「原生关闭原因区分已完成、决定不做与重复」与「关闭不自动证明目标达成」，补「关闭即计入完成（关闭原因不参与计数）；目标达成仍由人确认」，保留自动化/agent/定时不得自行关闭或确认完成）。
