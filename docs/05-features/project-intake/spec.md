## 范围与入口

入口：项目墙「+ 接入项目」与空态按钮、总览「接入项目」、知识库「请先接入项目」；项目墙卡片「+ 代码仓」走同一向导并附带挂组。批量接入不另开入口：同一向导第一步选中的对象多于一个时，第二步变为「接入清单」（旅程 ②′）；从墙卡「+ 代码仓」进入时勾选的仓全部挂进该项目组。

仓库注册与去重、克隆、项目组、工作树基址、路径授权、切换活跃项目全部复用 Orca 原生事务；BW 自有的是名片 `.bw/project.toml`、接入向导与项目墙卡片。不另建仓库管理平行实现。

知识库分类地图（`.bw/knowledge-map.toml`）能力已删除（2026-09-29 用户拍板）：接入不再写地图草稿，知识库分类回到内置规则；地图能力归知识库独立特性重新决策，本特性不承载。

## 完整用户旅程

| 阶段 | 用户与系统协作 | 产物 |
|---|---|---|
| ① 项目地址 | 选「打开本地仓」（填路径或浏览）或「克隆远端仓」（`owner/repo` 简写或完整 URL + 父文件夹）；点下一步做路径授权与存在性检查 | 确定的目标仓路径 |
| ①-探 名片探测 | 本地：读仓里 `.bw/project.toml`，已有则回填表单；远端：**克隆前**经平台 API 读默认分支上的名片，读到回填、读不到四种原因分开说 | 回填的基础信息或如实的探测结论 |
| ①-多 批量来源（草案） | 本地：选的文件夹不是 Git 仓时，复用 Orca 原生嵌套仓扫描列出下面的仓；系统对话框里也可一次多选文件夹。远端：文本框一行一个地址，点下一步逐行归一化、同远端查重、克隆前预探测名片。选「各自成项目 / 合成一个多仓项目」（= Orca 分组导入的 separate / group） | 候选清单：每行仓、名片有无、已接入与否 |
| ② 基础信息 | 核对/补全名称、对标、想做什么、目标方向（全部选填，名称除外）；确认接入 | 名片意图 |
| ③ 接入事务 | 注册仓库（本地）或克隆（远端）→ 名片写入并经 PR 合入（见行为规则 2）→ 设单仓工作树基址 `.bw/worktrees`（未设时，可见可改）→ 可选挂入项目组 → 激活项目落到总览 | 墙上可见的项目 + 名片（或待合入 PR） |
| ②′ 接入清单（草案） | 候选多于一个时替代「基础信息」：勾选、改项目名称（默认名片名或仓名）、看每行名片去向（带入 / 接入后开 PR / 没挂远端就地写）；其余三格不逐个填 | 接入清单 |
| ③′ 逐个接入（草案） | 按清单顺序对每行执行 ③ 的接入事务；每行独立成功或失败并留一行原因，一个失败不挡其他；结束停在本页给汇总，可重试没接入的；「回项目墙」看新卡，不切换活跃项目 | 墙上 N 张新卡 + 各自名片或待合入 PR |
| 日常 | 点墙卡切项目；卡片显示名片名称与简述；「+ 代码仓」扩组；「删除」移除墙上项目（绝不动仓和 worktree） | 项目切换与组维护 |

## 行为规则与异常

### 1. 名片写入保真

- 仓里已有名片：**只在原文上补空字段**，注释、`[chat]` 段、未知键逐字保留；不整份重渲染。历史别名 `north_star` 原位补值，不另插 `opportunity`。
- 名片文件不可读（二进制/损坏/读取异常）：**不覆盖**，如实报错；项目照接，名片可稍后补。
- 没有名片才按模板新建。写入或合并时确保 `.bw/.gitignore`（`worktrees/`）存在，已有不覆盖。
- 名称为空拒绝写入（表单已挡，此为兜底）。

### 2. 名片经 PR 合入被管仓

目标：名片是团队共享事实源，不是单机文件；后来者接入同一项目直接读到已有名片，不重复填、不重复起 PR；主检出不留脏文件。

- **固定树与分支**：名片只写项目约定固定树 `bw/project`（沿用计划/验收固定树管线，落 `.bw/worktrees/`），**主检出零写入**。
- **提交与 PR**：只提交 `.bw/project.toml`（及首次的 `.bw/.gitignore`），push 后开 PR——GitHub 走 `gh`，CodeHub 走 `codehub-cli`（用户确认支持，命令形态按 main v0.4 正本取证）；开 PR 失败如实提示原因与下一步，不冒充已开。
- **合入后更新主目录**：主检出不自动改动；PR 合入后提供显式「更新主目录代码」入口（主检出快进到含名片的提交），由人触发（行为按 main 正本取证细化）。
- **待合入提示**：PR 未合入期间，墙卡与总览项目卡明示「名片待合入 · PR #n」；合入由人在平台侧完成，**任何自动化不得合入或标完成**（铁律三）。
- **读正与幂等**：合入后名片以仓默认分支 HEAD 为准；HEAD 已有名片或已有开放名片 PR 时，接入只补空字段、**不重复起 PR**。adopted 判定看 HEAD 跟踪态，工作区脏文件不算（main b778da6ac 教训）。
- **编辑与补录**：提供名片编辑入口（main EditProjectCard 的对等物），复用同一固定树与 PR 流；名片写失败后的「可稍后补」由此入口承接。
- **无远端降级**：仓没有可识别远端（或非 git 仓/无提交的空仓）→ 名片就地写入主检出（保真合并语义不变），如实提示「没挂远端，名片只写在本机工作区」，不开 PR 也不冒充已开（main push_and_open_mr 降级语义）。
- **失败不推翻接入**：PR 环节失败（push 被拒、CLI 缺失、无权限）项目照接，如实报一行原因与下一步；不把失败说成成功。

### 3. 远端克隆前预探测

- 远端旅程在填表前**不 clone**，经平台 API raw 读该仓默认分支上的 `.bw/project.toml`，读到即回填表单（人打过的格子以人为准）。
- 四种「读不到」分开呈现：仓不存在/无权限、默认分支名不匹配、未登录/网络不通、确实没有名片——**「没查成」绝不呈现为「没接管过」**（main 4f9d93107 教训）。
- 手打地址点「下一步」时同样探测；探测回执竞态（用户已换目标仓）过期不应用。

### 4. 重复接入

- 同路径重复接入：由 Orca 原生按仓库身份去重，复用并提示「项目已添加」。
- 同远端身份（URL 归一化后同仓）已接入到其他路径：提示已接入的项目并引导复用，不再克隆第二份（2026-09-30 用户确认做）。

### 5. 呈现与落点

- 接入成功激活项目并落到**总览**（与 intent 目标体验一致）。
- 项目墙**不设「本机环境」探测条**。将来若做真实探测，参照 main 正本：只探产品自己会调用的工具（claude / cursor-agent / gh / codehub-cli），三态呈现（可用/不可用+指南/未检测灰），**不探自己不会起的东西，没接实现显示灰不显示绿**；探测清单随墙健康灯一并决策。

### 6. 批量接入（草案，待 gate）

- **触发**：第一步候选多于一个才进「接入清单」；恰好一个走今天的「基础信息」，行为不变。
- **候选来源复用 Orca 原生，不另造**：本地扫描 = `scanNestedRepos`（候选带路径、显示名、深度；截断 / 超时 / 停止如实显示）；多选文件夹 = `pickFolders`；各自成项目 / 合成一个多仓项目 = `importNestedRepos` 的 separate / group。BW 只加名片列与接入清单。
- **已接入的仓**（同路径，或同远端身份）列出但不可勾选，显示所属项目名；不是 Git 仓的子文件夹不列（扫描只返回仓）。
- **名片列**：本地候选逐个读 `.bw/project.toml`（有 → 带入；缺 → 用仓名）；远端候选按规则 3 逐行预探测，四种读不到分开写，「没查成」不呈现为「没有名片」。
- **接入事务 = 规则 1–2 对每行各跑一次**：名片保真合并、经 PR 或就地写、不重复起 PR、失败不推翻接入，全部沿用；顺序执行不并发（避免同一平台的 PR 竞态与 CLI 登录弹窗叠加）。
- **结果与落点**：批量不落总览、不切换活跃项目（规则 5 的「落到总览」只对单仓）；结束停在接入页显示每行结果与汇总，提供「重试没接入的」与「回项目墙」；墙卡按规则 2 显示待合入 PR；健康灯按现状 Unknown。
- **中途离开**：点「回项目墙」或关闭不取消已开始的行；未开始的行不再执行；已接入的行不回滚。
- **从墙卡「+ 代码仓」进入**：勾选的仓全部挂进该项目组，不出现「各自成项目」选项。

## 验收与衡量

验收点（E2E 用例注册按 2026-09-29 用户拍板暂缓，稳定后专项回补；点位先定，缺口记 STATUS）：

| 点 | 判据 |
|---|---|
| P-01 本地回填与保真合并 | 仓有名片（含 `[chat]` 与注释）→ 表单回填；提交后已有字段与文件其余内容逐字不变，只补空字段 |
| P-02 坏文件不覆盖 | 名片为二进制/损坏 → 不写入、报错如实、项目已接入 |
| P-03 远端预探测 | 选中有名片的远端仓 → clone 前回填；四类读不到分别提示；探测失败不呈现为「没接管过」 |
| P-04 名片 PR 化 | 接入 → `bw/project` 树提交 → PR 开启 → 待合入提示可见 → 合入后从 HEAD 读正；已有名片/开放 PR 不重复起 PR；主检出零写入 |
| P-05 重复接入 | 同路径复用提示；同远端身份提示已接入项目 |
| P-06 重启读回一致（铁律一） | 杀进程重开后墙卡、名片、组关系、活跃项目一致 |
| P-07 落点 | 接入成功落到总览且项目已激活 |
| P-08 本地文件夹扫出多仓（草案） | 选非 Git 文件夹（下有 ≥2 仓，其中 1 个已接入）→ 列出全部；已接入行不可勾选并标所属项目；名片有无逐行正确 |
| P-09 远端多行（草案） | 粘贴 ≥2 行地址（含 1 个已接入）→ 下一步后已接入行标出跳过，其余逐行预探测结果分开呈现，「没查成」不写成「没有名片」 |
| P-10 接入清单与逐个事务（草案） | 勾选 ≥2 行接入 → 每行独立出结果；缺名片行开 PR、已有名片行不开、没挂远端行就地写；一行失败其余继续；汇总计数与行状态一致 |
| P-11 批量落点（草案） | 结束停在接入页；回项目墙见 N 张新卡；活跃项目不变 |
| P-12 批量后重启读回一致（草案，铁律一） | 杀进程重开后墙卡、名片、组关系与批量结束时一致 |

旅程 E2E 候选（环 6，待注册）：「接入项目 → 墙上见名片 → 切进总览 → 重启读回一致」；批量（草案）：「选一个装满仓的文件夹 → 接入清单 → 逐个接入 → 回项目墙见 N 张新卡 → 重启读回一致」。

指标：本特性不挂独立指标；价值验证走 v0.5 收尾读回（intent 假设节）。

## 客户会问

- **为什么名片要走 PR？** 名片是团队共享的项目事实源；PR 让 builders 评审合入，后来者接入直接读到，不用每人填一遍，也不在你主检出里留脏文件。
- **接入会不会动我的仓？** 主检出零写入；名片只进 `bw/project` 固定树的 PR，合不合、何时合由你定。
- **接过的项目再接一次会怎样？** 同路径直接复用；仓里已有名片只补空字段、不重复起 PR。
- **一次能接多少？** 不设上限，顺序跑；每行各自成败，失败的可重试。名片四格不逐个填，缺的先用仓名，之后在墙卡「编辑名片」补。

## 硬核挑战（内部）

- Windows/WSL 路径归一与克隆目标比较（沿用 Orca 原生 canonical key，不自造）。
- `gh`/`codehub-cli` 登录态与权限失败的可解释呈现（区分没装、没登录、无权限、网络）。
- 两人同时接入同一新项目的 PR 竞态：后开者应发现已开放 PR 并转为补空字段。
- 固定树管线复用边界：`bw/project` 与计划/验收固定树共管线但独立身份，不共用会话与提示注入。

## 取舍（已决）

1. **原型豁免**：在用补链特性不补 prototype.html，以真壳与 PR 截图四件套为对照（2026-09-30 用户拍板）。
2. **CodeHub MR 创建**：用户确认 `codehub-cli` 支持；命令形态按 main v0.4 正本取证后实现。
3. `kind` 字段保持文件保真但无编辑 UI（与 main 四字段表单一致）；不在本轮扩。
4. 仓根 `skills/bw-knowledge-docs`（随产品分发）中地图相关内容与原生技能登记：本轮不动，归知识库独立特性裁决。
5. **远端列仓多选不做（草案）**：Orca 现无 GitHub/CodeHub 列仓 API（CodeHub 特性登记的「分区列仓」待做），本轮用多行地址代替；列仓落地后在同一清单上加勾选，不另开入口。
6. **不加「跳过名片 PR」开关（草案）**：批量 = N 次单个接入，规则 2 一字不改；省掉的是「逐个填四格」，不是「走 PR」。
7. **顺序执行不并发（草案）**：见规则 6。

## 待决问题（批量接入，人拍板）

- 远端批量的名片四格：预探测读到就带入，读不到用仓名——要不要在接入清单里允许逐行填「想做什么」？草案：不允许，去墙卡「编辑名片」补；影响：清单保持一行一仓的密度。
- 批量结束要不要自动切到第一个新项目的总览？草案：不切，停在结果页看汇总；影响：规则 5 的落点只对单仓成立。
- 「合成一个多仓项目」时名片只有一份（挂在主仓）：清单里其余行的名片列是否隐藏？草案：隐藏，只对主仓显示名片去向。
