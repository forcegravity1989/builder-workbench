## 添加项目与项目墙

归属 v1.0 G1，承接 #345、#497、#479、#489、#563、#499、#586。[可点原型](project-settings-prototype.html)经浏览器批注及最终取舍确认；实施与验证按仓外 plan 连续推进。本篇只保留最终目标；被替代的准入和读数方案从 Git 追溯。

### 连续旅程与本轮边界

1. 原生有效项目直接上墙：本机 Git 仓与普通文件夹不以名片为准入；同仓跨主机沿既有身份归并。个人／团队由人设置，不批量猜测存量。
2. 所有添加入口复用 Orca AddRepoDialog 及打开／克隆／新建、主机选择与原生子流程；取消 BW 名片步骤，不自动提交名片 PR。添加后直接工作。
   首次使用且还没有项目时，走完初始设置或点「跳至项目设置」会进入空项目墙，并打开原生「添加项目」弹窗。取消弹窗后留在项目墙，可从空态重新发起添加。
3. 点击项目名称沿原生激活与恢复继续工作，不自动新建会话。卡片右上角提供代码仓打开、原生仓库设置、远端克隆、总览与项目设置图标。名称继续工作、代码仓打开网页／本机路径是不同动作；总览图标沿现有导航。
4. 项目墙保留单一视图。卡片提供身份、项目负责人、版本目标和一排进展。需要细节直接进入已有 BW 总览、计划、任务、验收，不增加交付依据弹窗。
5. 个人和团队共用一个项目设置页，字段统一叫“项目名称”。复用 ProjectSettingsRail 的唯一项目信息表单；编辑按钮在分区标题右侧。#586 在总览名片增加编辑入口，打开同一设置栏，不维护第二套表单。原生项目／分组 ⋯ 放在墙卡，侧栏原位置仍保留；不走 PR 的操作不藏在项目信息编辑页。
6. 原生添加、主机、设置／帮助、工作区及会话不重画。原型在这些位置明确写“原型注释：复用 Orca／BW …”，模拟完成按钮也是评审工具，不是产品按钮。普通文件夹本轮只支持原生名称、工作区及本机类型，不提供 BW 名片编辑；不新建非 Git 保存链。Git 无远端的既有本地保存路径继续保留。

### 数据归属

Windows 新安装的 Workbench 首次生成原生配置时，D 盘存在则将「工作区目录」预设为 `D:\builders-workbench\workspaces`；没有 D 盘时沿用 Orca 的用户目录默认值。已有配置不改写，备份按原生流程恢复，用户以后仍在原生设置中修改。工作区目录为该预设值时，原生克隆的父文件夹为 `D:\builders-workbench`，新建空项目使用同根的 `projects`，保持项目与工作树分开；不迁移已有项目、工作树或应用数据目录。

| 数据                       | 归属与生效                                                        | 显示规则                                                                                |
| -------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 个人／团队                 | 所属主机 Orca 本地配置；缺省个人，用户自行修改，立即保存，不走 PR | 只过滤共享项目墙入口；不撤回已经打开的工作区或会话，不建团队权限体系                    |
| 项目负责人                 | 共享项目信息，沿项目仓库 bw/project 及现有 PR/MR 流程             | 明确标“项目负责人”，空值统一“—”；独立于一个或多个参与者／主机，不从主机名或提交记录推断 |
| 项目名称、想做什么、对标、愿景、项目群 | 同一共享信息编辑器，项目群沿 `.bw/project.toml` 的 `[chat].group_id` | 名片名称优先，回退原生项目／组名。待合入时展示正式值 |
| 主机名称与连接状态         | Orca 原生主机目录和状态                                           | 与项目负责人在同一行，来源过长截断并可悬浮读取；不是项目负责人，离线不是项目失败        |
| 版本目标、计划、任务、验收 | 已有计划／验收材料与 Issue 原生状态                               | 只作投影，修改回各自页面；不增加一句话承诺或独立约定验收日期字段                        |

同仓不同主机的类型独立。本机个人副本与远端团队副本可归同一卡；全部范围优先本机分类，团队筛选只保留符合条件的来源。不因有名片、路径或主机名自动分类。原型观察身份切换只供评审。

### 墙卡信息与布局

- 名称与图标操作在顶行；单仓打开／设置直接交接原生 UI，多仓只先选目标仓，不重画设置页。远端克隆也在右上角，不额外增加卡片底行。个人／团队由分组标题表达，不在卡内重复贴标签。项目负责人和主机在同一来源行，空值“—”不塌陷，长姓名和主机名截断并保留完整悬浮值。
- 有版本：复用侧栏“在制优先、同类版本号降序”取第一版，墙上不新增选版器或跟随最近浏览版本。显示版本号与实际目标标题，最多两条、每条最多两行；其余为“另 N 项目标”，进入已有版本页面，不自动生成摘要或在墙上罗列所有目标。目标来源是计划 goals，不把 timeWindow.end 或目标 deadline 猜成独立验收日期。
- 底部只有“计划｜任务｜验收”：计划归档状态、本版关联 Issue 已关闭／总数、验收归档状态。计划和验收复用对应页面的材料及归档 PR 读取与判定（未创建、待合入、已合入、已关闭、状态未知），不建立墙卡专属状态机。目标达成结论进入验收屏查看，不把任务全关或归档合入变成人工达成。
- 不展示或为墙卡额外查询全仓 PR/MR 数量，不增加证据弹窗、会话等附加统计。未知如实为“—”或“版本未知”，无有效同版本／同承诺依据不显示达成。
- 无版本的 Git 仓和普通文件夹使用相同紧凑布局，不硬套交付读数或预留大块空白。文件夹无名片时负责人为“—”，不画不存在的简介；名称和操作复用原生。确认未使用版本与读取未知区分，文件夹类型不额外占一排标签。
- “项目较多”不单独立演示档，日常列表自然可滚动；场景切换只保留首次使用、日常、读取失败、提交失败、待更新和未知状态。

项目分组沿现有 `workbench-wall-projects` 聚合成一张卡，成员仓库可展开。原型以 shunfenger 的 api／web 双仓直接展示，并提供明确标记的移出／重新分组演示。组卡 ⋯ 复用 `ProjectGroupHeaderMenu`（重命名／删除组），成员 ⋯ 复用 `RepoHeaderProjectActionsMenu`（设置、图标、工作树显示、新建／移入／移出分组、移除项目）及其确认；成员 ＋ 沿原生创建器。不同对象不共用一份伪造菜单。分组不合并仓库文件，不累计各仓版本事实；主仓选择沿已有本机优先及组内顺序。多仓真实操作仍须验证。

### 项目信息编辑与失败反馈

总览名片与设置栏使用同一组字段。打开设置时先回显同一仓库来源已读取的名片，重新核对文件，评审状态单独加载；状态返回后启用提交。项目群填写已有群号，随名片保存与评审，保留同段的通知配置。

只查看时隐藏底部空状态；编辑后出现“提交评审”（确认无远端则“保存”），点击沿里程碑的短 Popover 列出改动，确认后调用现有项目信息提交流程。待合入显示“查看评审”，确认已合入后显示“更新项目信息”；正式墙卡不提前使用提案值。个人／团队修改即时保存，不进入这条提交链。

失败保留当前进程内的输入，使用 Orca `sonner` 与里程碑同一全局右下角通知，给出简短原因、“重试”和“开会话处理”；不在编辑面板或确认框塞错误条。重试前沿现有提交结果核对，避免重复提交。开会话通过 `open-workflow-draft` 在该项目所属主机的原生主工作区预填失败原因和名片输入，用户自行发送。名片提交使用既有 `bw/project` 固定工作树。当前项目信息草稿仅进程内保存，不承诺重启恢复。原型“提交失败”场景只模拟首次连接失败、重试连接恢复，不代表真实修复。

写入范围沿现有 `charter-runtime`：常规编辑 `.bw/project.toml`；缺少 `.bw/.gitignore` 时可能补建，已有文件保留，提交只含这两个受控路径。无远端直接保存只写项目信息文件。配置树名片与提交仅有换行差异且 Git 确认干净时可以提交。保留主检出原文校验、串行提交与结果读回。

直连 SSH 名片沿原生文件入口只读。配对主机转接的 SSH 项目仍可通过墙卡进入工作区，名片显示为未读取。

### 刷新与原生复用

进入项目墙时直接显示 Orca 内存中的项目目录和同来源的墙卡快照，再用当前目录及工作树静默读取一轮版本、计划、任务和验收。已读卡片在更新期间保持可见；普通工作树提交、重排和目录事件不触发整卡重读。新出现的项目来源在可读后补齐。墙头刷新重读已连接主机的目录和工作树，再重读墙卡并强制查任务和归档状态。名片评审期间墙卡保留正式值，墙与总览保存或更新项目信息后只刷新受影响的项目。快照随界面进程退出失效；CodeHub 当前逐任务读取仍有成本，性能需真实数据验证。

目录部分失败时显示“部分主机未更新”。名片读取失败时保留同来源已读名片，并提示“部分墙卡信息未更新”，刷新承担重试。版本及进展读取失败按原有未知状态显示。主机连接沿原生主机管理处理。原型只模拟提示，不证明主机异常已通过真实验证。

墙头保留批量导入主机，复用当前 FileInput 图标；更新时间显示具体时刻，不永远写“刚刚更新”。搜索与筛选保留。空态不再加第三个连接主机入口。左栏主机入口薄挂载原生远程主机菜单／servers 设置；原生帮助问号保留，侧栏按钮与上方导航采用相同尺寸。帮助和设置菜单内容沿原生，不复制另一套。

侧栏基线含 #523、#597、#599。全局已固定与当前项目版本区直接标记复用；本轮只呈现底部“其他工作区”（无版本时“工作区”）的当前项目范围。保留主工作区、临时排查与未归版树；原生固定策略决定重复呈现。Workspace Options 仅移除跨项目 Projects 筛选，保留适用的主机、排序、状态。侧栏不额外添加“返回项目墙”，工作区不加独立主机下拉。

原生项目／分组行的 ⋯、＋、展开／收起均保留；本轮不新增目标级或版本级开工入口。目标开工、任务屏任务开工及工作区绑定沿现状，入口易用性由 v1.0 G3 处理。绑定版本改变树中归属，不改变项目墙卡片数量。

设置原型直接引用现有 project-settings.css，继承表单、折叠和提交状态。技术边界放到明确标记的“原型注释”；仅保留项目类型所需的短 Tooltip，删除通用名称／负责人说明图标。类型在卡片“项目设置”顶部修改，本机立即保存；远端只读并说明应在所属电脑修改，不通过项目仓 PR 改类型。重新打开设置读取当前信息；墙头刷新重读墙数据，已有脏草稿不被静默覆盖。

### 实际代码复用与必要接线

- 添加直接打开原生 AddRepoDialog，不传入覆盖原生完成行为的 hosted 回调。嵌套扫描、批量导入、取消、已有默认工作区交接沿原生；旧 OnboardProjectPage、名片前置、添加前建空组和相应入口清除。已有仓加入分组通过原生菜单，不为多仓增加第二套添加流程。
- 仓库菜单、组菜单及对话框分别复用 RepoHeaderProjectActionsMenu、ProjectGroupHeaderMenu、SidebarWorktreeListDialogs。设置、建组、移动和删除携带同一目标仓或组的主机身份；SSH 目录仍由本机登记管理。
- 墙按原生项目身份归并，版本材料按侧栏实际 Git remote 身份筛选，不能因同 upstream 把 fork 的版本混入。版本排序、目录、材料、归档状态标签和任务端口与现有页面共用。由墙卡进入总览时，名片版本沿该卡的项目来源与筛选范围。多主机流程候选不唯一时状态未知，点击沿现有选择器处理。
- 项目类型接入原生 Repo 更新、持久化与 runtime 目录传输。过滤共享个人来源在聚合前发生；不扩充仓库文件协议。项目负责人扩充现有名片保真读写，旧文件缺字段时为空。
- 原生主机状态菜单仅换到 BW 左栏，原生帮助保留；不复制菜单功能。侧栏保留原生工作区行、固定区和会话，只限制底部当前项目来源。独立 FolderWorkspace 也按当前分组及主机过滤；其原生固定能力不在本轮扩展。

### 原型判据与未验边界

| 判据  | 观察结果                                                                           |
| ----- | ---------------------------------------------------------------------------------- |
| PW-01 | 一面墙可达无名片项目；添加入口明确复用，模拟成功默认个人并进入原生工作区占位       |
| PW-02 | 本机类型立即生效，不改共享草稿或产生 PR；共享墙过滤个人入口                        |
| PW-03 | 项目负责人和主机分开，空值“—”对齐；单一编辑器和待合入隔离保留                      |
| PW-04 | 目标条数与行数受限；计划／任务／验收一排，不把任务全关当成人验收达成；未知不假成功 |
| PW-05 | 未变工作区与侧栏明确复用，只突出当前项目范围；无多余返回入口或主屏主机选择器       |
| PW-06 | 克隆交接模拟本机副本仍归同一卡；全流程真实原生接线未验                             |

| PW-09 | 查看无空页脚，短确认提交；失败全局反馈与保留草稿、会话草稿交接；待评审和待更新分开 |

HTML 全部状态在内存，刷新重置，不读写真实配置或仓库。浏览器原型不能证明 Electron、实际原生 UI 接线、项目负责人字段持久化、真实 provider、双主机、失败重试或完整进程重启。完整创建器与会话恢复已改为明确交接，不再以模拟控件声称这些真实旅程跑通。

## 实现验收

现有真实配置用例入口为 tests/e2e/workbench-cycle-smoke.spec.ts 中的 BW project settings，辅助代码在 helpers/workbench-project-settings.ts；更新原用例验证短确认、负责人保真写入、并发原文冲突、全局通知、退出保护和 renderer 重载。该用例不证明真实远端评审或完整进程重启。

PW-01 至 PW-09 的原型判据同时是生产对照依据；真实验证需另外覆盖普通文件夹无名片可达、类型持久化与共享来源过滤、多主机同仓与同 ID、分组多仓操作、侧栏当前项目范围、墙与对应版本页状态一致。具体执行结果及留白只写 STATUS 和 PR 验证评论。
