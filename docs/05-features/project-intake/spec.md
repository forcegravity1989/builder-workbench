# 添加项目与项目信息规格

> **维护约定**：给设计、实现与验收者读取；本文只管当前目标行为、边界和可观察判据，价值与范围见 [intent](intent.md)，证据与未验范围见 [STATUS](STATUS.md)。行为变化时改对应主题，不记录开发流水或被替代方案。
>
> **原型与旅程**：[当前可点原型](project-settings-prototype.html)是设计输入，不代表生产行为。本特性归入探索 BW 的 W01「找到项目 → 明确共同方向」，W01 的完整定义见[探索规格](../explore-workbench/spec.md#范围与完整旅程)。

## 添加项目与项目墙

本篇只保留当前目标；历史取舍和实现过程由 Git、Issue 与 PR 追溯。

### 连续旅程与当前边界

1. 原生有效项目直接上墙：本机 Git 仓与普通文件夹不以名片为准入；同仓跨主机沿既有身份归并。个人／团队由人设置，不批量猜测存量。
2. 所有添加入口复用 Orca AddRepoDialog 及打开／克隆／新建、主机选择与原生子流程；取消 BW 名片步骤，不自动提交名片 PR。常规添加成功后直接工作。
   首次使用且还没有项目时，走完初始设置或点「跳至项目设置」会进入空项目墙，并打开原生「添加项目」弹窗。取消后留在墙上，可从空态重新添加。从首次弹窗或空墙入口添加第一个项目后，项目卡出现在墙上，由用户点击项目名进入工作区。
3. 点击项目名称沿原生激活与恢复继续工作，仍沿项目默认来源；明确点击主机标记或成员仓库时按该选择打开，不自动新建会话。卡片右上角提供代码仓打开、原生仓库设置、远端克隆、总览与项目设置图标。名称继续工作、代码仓打开网页／本机路径是不同动作；总览图标沿现有导航。
4. 项目墙保留同一项目列表，顶部「紧凑模式／详情模式」统一切换所有卡片的显示密度，默认详情模式。两种模式下卡片尺寸与分区对齐，不按有无版本自动选模式。需要完整细节直接进入已有 BW 总览、计划、任务、验收，不增加交付依据弹窗。
5. 个人和团队共用一个项目设置页，字段统一叫“项目名称”。复用 ProjectSettingsRail 的唯一项目信息表单；编辑按钮在分区标题右侧。#586 在总览名片增加编辑入口，打开同一设置栏，不维护第二套表单。原生项目／分组 ⋯ 放在墙卡，侧栏原位置仍保留；不走 PR 的操作不藏在项目信息编辑页。
6. 原生添加、主机、设置／帮助、工作区及会话不重画。原型在这些位置明确写“原型注释：复用 Orca／BW …”，模拟完成按钮也是评审工具，不是产品按钮。普通文件夹只支持原生名称、工作区及本机类型，不提供 BW 名片编辑；不新建非 Git 保存链。Git 无远端的既有本地保存路径继续保留。

克隆到本机时，百分比只表示当前 Git 阶段；到 100% 后仍在等 Git 时显示「正在完成克隆…」，Git 成功退出后显示「正在导入项目…」，沿原有流程就绪后关窗。

### 数据归属

Windows 新安装的 Workbench 首次生成原生配置时，D 盘存在则将「工作区目录」预设为 `D:\builders-workbench\workspaces`；没有 D 盘时沿用 Orca 的用户目录默认值。已有配置不改写，备份按原生流程恢复，用户以后仍在原生设置中修改。工作区目录为该预设值时，原生克隆的父文件夹为 `D:\builders-workbench`，新建空项目使用同根的 `projects`，保持项目与工作树分开；不迁移已有项目、工作树或应用数据目录。

| 数据                                   | 归属与生效                                                           | 显示规则                                                                                |
| -------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 个人／团队                             | 所属主机 Orca 本地配置；缺省个人，用户自行修改，立即保存，不走 PR    | 只过滤共享项目墙入口；不撤回已经打开的工作区或会话，不建团队权限体系                    |
| 项目负责人                             | 共享项目信息，沿项目仓库 bw/project 及现有 PR/MR 流程                | 明确标“项目负责人”，空值统一“—”；独立于一个或多个参与者／主机，不从主机名或提交记录推断 |
| 项目名称、想做什么、对标、愿景、项目群 | 同一共享信息编辑器，项目群沿 `.bw/project.toml` 的 `[chat].group_id` | 名片名称优先，回退原生项目／组名。待合入时展示正式值                                    |
| 主机名称与连接状态                     | Orca 原生主机目录和状态                                              | 与项目负责人在同一行，来源过长截断并可悬浮读取；不是项目负责人，离线不是项目失败        |
| 版本目标、计划、任务、验收             | 已有计划／验收材料与 Issue 原生状态                                  | 只作投影，修改回各自页面；不增加一句话承诺或独立约定验收日期字段                        |

同仓不同主机的类型独立。本机个人副本与远端团队副本可归同一卡；全部范围优先本机分类，团队筛选只保留符合条件的来源。不因有名片、路径或主机名自动分类。原型观察身份切换只供评审。

### 墙卡信息与布局

- 名称与主要图标操作在顶行，代码仓打开、设置与克隆合并到一个“代码仓操作”菜单，保留总览、项目信息及原生菜单；不以六个常驻图标挤占项目名。多仓菜单先确定目标仓，不伪造可点击功能。项目负责人显示头像及紧跟的姓名；头像无真实来源时用统一人形占位，不生成假照片。人员头像组直接接在墙卡身份行：后一个遮住前一个的 1/3，最多四个圆位，超过四人时前三头像加末位“+N”；点击头像依次向右散开，相邻头像边缘间距为 20px，下方名字淡入，再点从右往左依次收回。头像组折叠时在身份行右对齐；展开层左右均限定在当前项目卡片内部，空间不足在卡内单行横向滚动，不覆盖相邻卡片、不撑高卡片；支持中途反向、Escape、键盘及减少动画偏好。头像内容接团队目录的真实成员头像：负责人按姓名匹配团队成员，来源主机按团队同步时的成员姓名匹配，本机用当前登录成员；匹配不到或头像加载失败保持统一人形占位。解除团队绑定后头像数据源断开，回到人形占位；重新绑定即按新目录恢复。来源语义仍是“项目来源（主机）”，名称入口保留对应宿主继续工作，不能把主机数量当成人数；头像只覆盖团队成员，项目参与者名册仍未接通。
- 有版本：按侧栏的[版本排序](../version-workspace/spec.md#版本排序)取第一版。版本号、来源与发布日期在两种模式都保留的同一行，只出现一处；发布是时间点，显示完整 YYYY-MM-DD 日期，不只显示月份。原型日期为明确样例，当前生产墙卡尚无真实发布日期读数，缺失显示“发布 —”；不得从 timeWindow.end、目标 deadline 或提交时间推算，不新增版本计划协议。详情最多两条单行目标预览，删除版本行的独立展开图标；点击中间目标区域直接弹出完整目标卡片，标题不限行，并可进入已有版本计划。没有目标不输出“暂无更多”“另 0 项”或额外计数占位。
- 底部仅显示“计划｜任务｜验收”，不再保留仓数量或重复版本 meta 行。计划和验收沿当前流程材料读取，按[版本进度规则](../version-overview/spec.md#版本进度与归档证据)各显示一行材料阶段，归档 PR／MR 状态放在悬停提示中，完整证据进入版本总览。任务显示本版关联 Issue 已关闭／总数；目标达成由人在验收页确认。
- 不额外查询全仓 PR/MR、会话、文件数、最近更新等统计填满卡片。未知如实为“—”，无有效同版本／同承诺依据不显示达成。
- 全局模式只改变信息密度，不重读材料或改变筛选、版本来源和项目状态；页面生命周期内保留选择，重新进入默认详情。详情正文压为两行预览所需高度，紧凑隐藏目标与简介；各模式统一卡高和分区基线。长名称单行截断，完整目标、主机、成员及诊断由浮层承载，不因内容撑高。
- 无版本的 Git 仓与普通文件夹沿当前全局模式，版本位置显示“—”，进展为不可点击的“—”。正文有真实简介才展示，不复制“未建立版本”或留 184px 空白。加载或失败提示仅在版本行出现一次，读取失败的卡面短文案为“无”，真实读取状态仍是未知，详细原因从读取问题出口查看，不当作无版本。已识别版本号保留；负责人未设置时头像入口说明“未设置”，不编造人员，不新增文件夹名片保存。
- “项目较多”不单独立演示档，日常列表自然可滚动；场景切换只保留首次使用、日常、读取失败、提交失败、待更新和未知状态。

项目分组沿现有 `workbench-wall-projects` 聚合成一张卡，身份行的“成员”入口通过原生 Popover 查看仓库及既有菜单，不展示仓数量，也不展开撑高墙卡。原型以 shunfenger 的 api／web 双仓直接展示，并提供明确标记的移出／重新分组演示。组卡 ⋯ 复用 `ProjectGroupHeaderMenu`（重命名／删除组），成员 ⋯ 复用 `RepoHeaderProjectActionsMenu`（设置、图标、工作树显示、新建／移入／移出分组、移除项目）及其确认；成员 ＋ 沿原生创建器。不同对象不共用一份伪造菜单。分组不合并仓库文件，不累计各仓版本事实；主仓选择沿已有本机优先及组内顺序。多仓真实操作仍须验证。

### 项目信息编辑与失败反馈

总览名片与设置栏使用同一组字段。总览点「编辑项目信息」直接展开共用设置栏的表单。打开设置时先回显同一仓库来源已读取的名片，重新核对文件，评审状态单独加载；状态返回后启用提交。项目群填写已有群号，随名片保存与评审，保留同段的通知配置。

只查看时隐藏底部空状态；编辑后出现“提交评审”（确认无远端则“保存”），点击沿里程碑的短 Popover 列出改动，确认后调用现有项目信息提交流程。待合入显示“查看评审”，确认已合入后显示“更新项目信息”；正式墙卡不提前使用提案值。个人／团队修改即时保存，不进入这条提交链。

失败保留当前进程内的输入，使用 Orca `sonner` 与里程碑同一全局右下角通知，给出简短原因、“重试”和“开会话处理”；不在编辑面板或确认框塞错误条。重试前沿现有提交结果核对，避免重复提交。开会话通过 `open-workflow-draft` 在该项目所属主机的原生主工作区预填失败原因和名片输入，用户自行发送。名片提交使用既有 `bw/project` 固定工作树。当前项目信息草稿仅进程内保存，不承诺重启恢复。原型“提交失败”场景只模拟首次连接失败、重试连接恢复，不代表真实修复。

写入范围沿现有 `charter-runtime`：常规编辑 `.bw/project.toml`；缺少 `.bw/.gitignore` 时可能补建，已有文件保留，提交只含这两个受控路径。无远端直接保存只写项目信息文件。配置树名片与提交仅有换行差异且 Git 确认干净时可以提交。保留主检出原文校验、串行提交与结果读回。

直连 SSH 名片沿原生文件入口只读。配对主机转接的 SSH 项目仍可通过墙卡进入工作区，名片显示为未读取。

### 刷新与原生复用

项目墙搜索无匹配时可一次清除关键词、来源和类型筛选。墙头问号启动逐步引导，指向搜索、项目名及总览入口；空墙指向「添加项目」，筛选无匹配时指向「清除搜索和筛选」。自动触发和回看遵循[引导规范](../../04-design-system/guidance.md#展示与结果)。进入项目墙时显示 Orca 内存中的项目目录，版本与侧栏共用同仓目录，在各已授权宿主独立发现工作树，再从该版选定来源读计划、任务和验收；未导入、未 clone 不影响读取。已读同来源内容在更新期间保持可见；工作树、绑定、实例和材料基线变化会更新对应目录，普通重排不触发重读。墙头刷新重读主机目录，各卡重新发现同仓已授权各主机的工作树，并强制查任务和归档状态。名片评审期间墙卡保留正式值，墙与总览保存或更新项目信息后只刷新受影响的项目。快照随界面进程退出失效；CodeHub 当前逐任务读取仍有成本，性能需真实数据验证。

目录部分失败时显示“部分主机未更新”。名片读取失败时保留同来源已读名片，并提示“部分墙卡信息未更新”，刷新承担重试。版本及进展读取失败按原有未知状态显示。主机连接沿原生主机管理处理。原型只模拟提示，不证明主机异常已通过真实验证。

墙头保留批量导入主机，复用当前 FileInput 图标；更新时间显示具体时刻，不永远写“刚刚更新”。搜索与筛选保留。空态不再加第三个连接主机入口。左栏主机入口薄挂载原生远程主机菜单／servers 设置；原生帮助问号保留，侧栏按钮与上方导航采用相同尺寸。帮助和设置菜单内容沿原生，不复制另一套。

侧栏基线含 #523、#597、#599。全局已固定与当前项目版本区直接标记复用；侧栏只呈现底部“其他工作区”（无版本时“工作区”）的当前项目范围。保留主工作区、临时排查与未归版树；原生固定策略决定重复呈现。Workspace Options 仅移除跨项目 Projects 筛选，保留适用的主机、排序、状态。侧栏不额外添加“返回项目墙”，工作区不加独立主机下拉。

原生项目／分组行的 ⋯、＋、展开／收起均保留；不新增目标级或版本级开工入口。目标开工、任务屏任务开工及工作区绑定沿现状，入口易用性由 v1.0 G3 处理。绑定版本改变树中归属，不改变项目墙卡片数量。

设置原型直接引用现有 project-settings.css，继承表单、折叠和提交状态。技术边界放到明确标记的“原型注释”；仅保留项目类型所需的短 Tooltip，删除通用名称／负责人说明图标。类型在卡片“项目设置”顶部修改，本机立即保存；远端只读并说明应在所属电脑修改，不通过项目仓 PR 改类型。重新打开设置读取当前信息；墙头刷新重读墙数据，已有脏草稿不被静默覆盖。

### 实际代码复用与必要接线

- 添加直接打开原生 AddRepoDialog。嵌套扫描、批量导入、取消和工作区准备沿原生。常规添加成功后进入默认工作区。从首次引导弹窗或空墙入口添加第一个项目后留在墙上。旧 OnboardProjectPage、名片前置、添加前建空组和相应入口清除。已有仓加入分组通过原生菜单，不为多仓增加第二套添加流程。
- 仓库菜单、组菜单及对话框分别复用 RepoHeaderProjectActionsMenu、ProjectGroupHeaderMenu、SidebarWorktreeListDialogs。设置、建组、移动和删除携带同一目标仓或组的主机身份；SSH 目录仍由本机登记管理。仓库设置和项目菜单中的移除确认显示目标主机与登记路径，仅移除该登记。删组确认显示组所在主机。勾选移除组内项目时，按清单中的主机和路径移除各登记。提交删组前由组所在主机核对真实成员，成员变化时重新确认清单。配对主机须支持按登记移除。确认后登记或配对对象有变化时停止操作。通过配对主机访问 SSH 仓库时，确认同时显示配对主机和 SSH 宿主。
- 墙按原生项目身份归并，版本材料按侧栏实际 Git remote 身份选源，不能因同 upstream 把 fork 的版本混入。版本排序、目录、材料、归档状态标签和任务端口与现有页面共用。同名版按[页面读取来源](../../architecture.md#页面读取来源)选择一台主机。对端独有的版本标出来源，进入该版或其流程时保留选择；项目总览仍沿项目默认来源。墙上筛选只决定可见卡片。同一来源流程候选不唯一时状态未知，点击沿现有选择器处理。
- 项目类型接入原生 Repo 更新、持久化与 runtime 目录传输。过滤共享个人来源在聚合前发生；不扩充仓库文件协议。项目负责人扩充现有名片保真读写，旧文件缺字段时为空。
- 原生主机状态菜单仅换到 BW 左栏，原生帮助保留；不复制菜单功能。侧栏保留原生工作区行、固定区和会话，只限制底部当前项目来源。独立 FolderWorkspace 也按当前分组及主机过滤；其原生固定能力不在本特性扩展。

### 原型判据与未验边界

| 判据  | 观察结果                                                                                                                                                                                               |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PW-01 | 无名片项目可上墙。原型模拟常规添加后默认个人并进入工作区，首次添加留墙由真实用例覆盖                                                                                                                   |
