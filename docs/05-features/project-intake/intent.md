# intent — 添加项目与项目墙（project-intake）

> **维护约定**：给产品、设计、实现与验收者读取；本篇管价值与范围（原则 02 §3.1）。行为细节和原型归 [spec](spec.md)，实现与验证证据归 [STATUS](STATUS.md)。认可的决定直接改写正文，不追加聊天流水。
>
> **状态**：v1.0 G1 经浏览器批注及最终 AskUser 确认；[当前原型](project-settings-prototype.html)为本轮目标，生产验证单独记录。

## 用户与问题

Builder 需要把手上的 Git 项目或普通文件夹加入 Workbench 并继续工作。原 BW 纳入要求先填名片，Orca 添加则不要求；项目墙又以名片为准入，两个入口造成无名片项目不可达。团队共享主机时，个人项目也需要明确的展示边界。扫墙还需要少量可靠的交付事实，而不是再建一套工作系统。

## 目标体验

统一“添加项目”，复用 Orca 原生打开、克隆和新建流程；完成即上墙并进入原生工作区，名片以后按需编辑。再打开项目恢复已有工作区和会话，不自动创建会话。个人、团队都可使用已有版本能力；没有版本不算异常。

墙卡按个人／团队分组，显示项目名、明确的项目负责人、所在主机、当前版本最多两项目标，以及计划归档／任务／验收归档一排事实。点击进入既有工作、总览或对应版本页面。分组沿原生多仓模型合成一张卡，成员可展开，仓库级操作先确定目标仓再复用原生 UI。

侧栏承担当前项目工作：全局已固定、当前项目版本、当前项目其他工作区；没有版本时称工作区。原生项目行的 ⋯、＋、折叠和会话保留。跨项目选择由项目墙承担，Workspace Options 移除跨项目筛选。

## 数据与范围

- 个人／团队是所属主机 Orca 本地配置的展示属性，缺省个人，用户自行切换，不猜测或批量迁移存量，不走 PR。共享墙过滤个人来源，不增加鉴权，也不撤销已打开工作区。
- 项目负责人独立于主机持有人，空值“—”；与名称、简介、对标、目标方向一起在唯一名片编辑器维护，沿项目仓库的 bw/project 和现有 PR/MR 共享。总览的编辑入口（#586）打开同一设置栏。
- Git 项目有远端提交评审，无远端沿现有本地保存。常规修改一个名片文件，保留未知键和已有冲突校验；失败保留输入、用原生全局通知，并可开原生会话草稿让模型处理，用户自行发送。
- 普通文件夹只保留原生名称、工作区及个人／团队设置；本轮不新增非 Git 名片保存路径。
- 计划和验收复用各自归档状态；任务按原生 Issue 已关闭／总数计数。版本沿侧栏在制优先、同类版本号降序取首个。目标达成由人在验收页确认，不由墙卡推断。

## 收窄与相邻特性

G1 承接 #497 的个人项目可达和 #345 的有价值信息呈现；#349 的版本节奏、Builder 交付视图以及详细 PR 证据本轮延后，不能声称满足原三视图范围。#489 只保留四原则一行提示，仪表延后。不新增全仓 PR 计数、会话统计、健康灯、证据弹窗、约定验收日期或一句话承诺字段。

主机管理、批量主机导入和克隆均复用 Orca/BW 已有流程；不新增团队成员或权限系统。任务／目标开工入口易用性归 v1.0 G3。知识库地图、自动化运作和通用 Git 修复引擎不在本轮。

## 成功判据

无名片 Git 项目与普通文件夹能从统一入口添加、上墙、继续工作；本机类型独立读回一致，共享墙只显示团队来源；墙与计划／验收页读取同一归档事实，缺数不装绿；名片编辑从墙和总览都走同一提交路径。原型、源码、远端 CI、真壳与真实双主机证据分别陈述。
