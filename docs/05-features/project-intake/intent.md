# intent — 纳入项目与项目信息记录（project-intake）

> **状态：已 gate**（2026-09-29 用户拍板补登记并确认命名，同日 gate 遗留决定收口：字段维持选填、knowledge-map 草稿能力删除、名片 PR 化本轮实施、本机环境条删除）。行为细节与验收点见 [spec.md](spec.md)（已确认，2026-09-30）；链状态在 [STATUS.md](STATUS.md)。**批量接入扩展（2026-10-09）为草案、待 gate**：改动见「用户与问题」批量痛点、「目标体验」一次接入多个、「范围与边界」；行为见 spec 规则 6 与原型。
>
> **维护约定**：本篇管价值与范围（02 §3.1 骨架）；gate 结论改写正文，不追加聊天流水。

## 用户与问题

- **谁**：被管项目的 Builder（及需要总览多项目的 Leader）。
- **场景**：装好 Workbench 后第一件事是把手上的项目装进来。Orca 原生仓库列表只有路径与仓名，没有业务身份——这个项目做什么、对标谁、想做成什么；版本周期（计划/验收/指标）没有挂载对象。
- **现有做法为什么不够**：手动 clone、脑子记路径，项目信息散落无法跨会话、跨成员一致读回；杀进程重开后没有可重新计算的项目事实源。
- **批量痛点（2026-10-09 补，草案）**：手上有一堆仓（一个人维护十几个，或一个团队的全部仓）时，每个都要走一遍「选仓 → 填四格 → 确认」，十个仓十遍；装好 Workbench 的第一天就卡在这件事上。Orca 原生的「添加项目」已能多选文件夹、扫描非 Git 文件夹下的嵌套仓并成组导入，但那条路不经过名片，接入向导又只收一个路径。

## 价值与依据

- **核心收益**：接入一次、填一次名片（名称/对标/想做什么/目标方向），此后项目墙、总览、版本周期、知识库都认这个项目——接入是全工作台主路径的起点。
- **依据**（可追溯）：03 主张现行主路径「项目墙 / 看板 / 建卡开工 / 人点完成」，用户旅程始于「接入项目并确认基础信息」，接入时回答做什么/对标/成功标准；architecture 用例表「打开或接入项目」；能力已实现且在用（实现落点见文末）。
- **假设（标明）**：尚未经多个真实 Builder 的使用反馈验证；价值效果待 v0.5 收尾读回，不当成已证实。

## 目标体验

侧栏顶部项目名进入**项目墙**：每项目一张卡（名称、简述、对标、目标方向；多仓项目聚合为一张卡，组内增删仓自动建组/收组）。「+ 接入项目」两步——①选本地仓或克隆远端（`owner/repo` 简写归一化为 GitHub 地址；远端在填表前经平台 API 预读已有名片回填，「没查成」不冒充「没接管过」）；②填项目名片。提交即完成一串：写 `.bw/project.toml` **并经 PR 落入被管项目仓、由其 builders 合入**（合入后其他成员接入同一项目时直接读到已有名片、只补空字段，不重复建名片重复起 PR；主检出不留脏文件）；设单仓工作树基址 `.bw/worktrees`、可选挂入项目分组、激活项目落到总览。点卡切项目；总览项目卡展示名片的对标/目标方向。

**一次接入多个（草案）**：①选的文件夹本身不是 Git 仓、但下面有仓时，复用 Orca 原生扫描一次列出全部；克隆远端时一行一个地址。②第二步从「基础信息」换成「接入清单」：勾选、改名、看每行名片是「带入」还是「接入后开 PR」，一键接入。逐个事务顺序跑，一个失败不挡其他；结束停在结果页可重试，回项目墙新卡已在。名片四格不逐个填，缺的用仓名，之后在墙卡「编辑名片」补。「各自成项目 / 合成一个多仓项目」沿用 Orca 的分组导入语义。

> 现状与目标的差距：名片保真合并、落点总览、knowledge-map 与环境条删除、名片经 PR 落仓（`bw/project` 固定树 + 待合入提示 + 更新主目录 + 编辑名片补录）、远端预探测与同远端去重均已实施（PR #285）；真实远端端到端与真壳未验，边界见 [STATUS](STATUS.md)。

## 范围与边界

- **做**：项目接入（本地/克隆）、名片信息记录与读回展示、名片 toml 经 PR 落被管仓并由 builders 合入、远端克隆前名片预探测、项目墙聚合与切换、仓库分组；一次接入多个仓（本地文件夹扫描 / 多行远端地址 → 接入清单 → 逐个事务；2026-10-09 草案，待 gate）。
- **不做（现行边界，可追溯）**：旧 Rust 项目约定完整旅程中除名片 PR 之外的部分（常驻 worktree 供 Issue 运作、三条运作自动化随接入写入等——后者归 F5 定时工作执行裁决）；知识库分类地图（`.bw/knowledge-map.toml`）能力已删除（2026-09-29 用户拍板：知识库未成熟，归独立特性重新决策）；「本机环境」探测条已删除（2026-09-29 用户拍板：不探产品不会调用的工具；将来随墙健康灯按 main 正本清单——claude/cursor-agent/gh/codehub-cli、三态、灰不装绿——重新决策）；无专门可写性探测（仅路径授权 + 存在性 + git 校验）；墙上版本/周目标/健康为占位 Unknown，不装绿，暂不细设计（用户拍板，随版本周期数据接入再看）；远端列仓多选（Orca 现无 GitHub/CodeHub 列仓 API，CodeHub 特性登记的「分区列仓」落地后再议，本轮以多行地址代替）。
- **相邻特性**：总览指标（项目区读名片与仓库数据）、版本计划/验收（在接入的项目上跑周期）、知识库（接入产出仅名片；地图能力已移出本特性）。

## 成功判据与已定决定

**判据**：Builder 无文档能完成接入 → 墙上看到自己项目名片 → 切进总览；杀进程重开后名片与墙读回一致（铁律一）。

**已定决定（gate 结论）**：
- 名片字段（对标/成功标准）维持**选填**：接入门槛低，字段完整性在 PR 评审里协商，「接入时问」以预填引导落实（2026-09-29）。
- 名片 toml **必须经 PR 落被管仓并由 builders 合入**，本轮实施（2026-09-29 确认必要旅程；否则后来者重复填名片、本地留脏文件）。main v0.4 已交付正本：`crates/bw/src/app/project.rs`（create_project——名片只写项目约定专属工作树、主检出不动，已有名片 adopt 只补空字段；edit_project_card——专属 worktree → 写名片 → commit → `push_and_open_mr` → Issue 转 InReview）；实现在 Orca 上重新决策（复用固定树管线与 gh/codehub-cli 执行链，不照搬 Rust）。
- knowledge-map 草稿能力从本特性**删除**（2026-09-29），归知识库独立特性。
- 存量旧仓已有 toml（main v0.4 起写入，字段 `opportunity`）**无需补录**；读取端兼容更早的 `north_star` 字段。
- 克隆远端中断的残留场景暂不处理，看实际用户反馈再定。
