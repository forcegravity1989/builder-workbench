# 总览指标 — 六环状态

> 给接手开发、评审和验收的人读取。只记录认可、实现和证据缺口；有真实认可或运行结果时更新。价值见 [intent](intent.md)，行为见 [spec](spec.md)，工程设计见 [design](design.md)。

目标平台为主干 main（原 bw-orca，2026-09-30 扶正）的 Electron/Orca 叠层。本轮指标闭环已实现：业务只支持日／周历史脚本，每次配置新建原生会话，目录读主干基线（主检出），新采集不被旧计划配置锁定，验收可选择新指标。定向测试、真实 Git 与 Node 历史脚本集成、实际组件的替身端口浏览器检查已运行；真实 Electron 与模型完整旅程尚未验证。既有总览与服务证据见 [PR #277](https://github.com/forcegravity1989/builder-workbench/pull/277)和 [PR #272](https://github.com/forcegravity1989/builder-workbench/pull/272)；它们不替代本轮证据。

## 当前实现

- 业务目录、脚本输出与日／周图表收敛为 script + retro=true；不再接受仅当前 value 输出。源数据及历史存储归用户项目或服务所有，BW 不建立每日采集台账。
- “配置指标”使用 MessageSquarePlus 图标；每次在 bw/metrics-refresh 固定树中新建原生会话，加载 SYSTEM、metrics-refresh 及当前目录问题，保留已有未完成改动。
- 目录与新采集从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取定义和脚本，不在后台 fetch；单次执行固定来源修订，材料草稿树不 merge、不重置。读取失败保留原来源并显示错误；主检出新鲜度由总览「更新代码」按钮负责。
- 验收可从最新目录选择指标补充实测，原计划承诺与 baseline 保留只读；旧配置提交不拦截新采集。证据详情显示来源、采集时间、配置提交与脚本修订；定义指纹保存在材料中，没有专门的口径变化比较或确认界面，不自动判断达成。
- 原型、特性规格、产品 Skill 与协议按同一决定同步；不修改 hifi、共用工作区壳或计划/验收整体布局。项目内建统计仍独立于业务目录，开放 Issue 保留真实当前快照。
- 总览首次准备日／周数据；之后切换和返回复用本次运行的项目快照，「更新代码」（快进主检出并重读目录）或指标刷新按钮（重新采集）才取得新数据。项目事件采集一次后本地落桶，业务两种口径分别采集；刷新失败保留原证据时间，日期显示跟随采集时刻。
- 版本列表按主干基线现有目录，每版本一份当前材料；已迁移的 Git 旧快照不再报重复问题，已删除版本不复活。落后的固定材料树不能覆盖主线文件。真实安装反馈确认了这轮修复范围；未新增测试用例，复验与提交证据随本轮 PR，真壳回验由用户执行。
- BW 自身目录落定（PR #292）：北极星删除（未定义清楚不硬立）；4 条指标 = 纳入项目数、每周闭环 issue 数（gh 采集）、使用周一屏项目数（target 6）、计划制定时长（两层采集，target 待真实基线后拍板）。四个脚本已在真实窗口实跑并用 gh/git 独立读回核对（数字见 PR #292）。

2026-10-14 Issue #355 同步统一批（用户在对齐会话逐项拍板，正本文案见 #355 plan §0）：指标定义与目录改读主干基线（主检出 HEAD 或钉值 `worktreeBaseRef`），删除 adopted-source 独立 fetch、upstream 映射与 main/master 名字探针；目录列举不再隐含网络 fetch；configuration-not-adopted 校验删除（新语义下目录只发主干 HEAD 的修订，草稿天然进不了正式读数）；`BW_METRICS_DATA_COMMIT` 与配置提交统一为同一主干 HEAD，消除数据根与脚本目录不一致。总览新增页头主按钮「更新代码」（快进主检出 + 三类快照缓存换键重读 + 名片重读；SSH 主检出沿原生远端快进链），「刷新版本材料」「刷新项目指标」两个小按钮并入后删除，「刷新业务指标」（真实采集）保留；版本区新增「来源：<分支> @ <sha12>」标注；合入判定与展示同源读主检出，不设第二基准。`bw/metrics-refresh` 仍是草稿树、永不作正式读取源，其 SKILL 补开工前核对树与基线纪律。证据：workbench vitest 全绿 226 例（ratchet 基线 228→226：删旧机制 8 例、增基线解析与同步决策 6 例、指标配置读取 1 例原位改写为无 fetch 语义）、typecheck 0 错、rpc-catalog / bundled-skill-guides / skill-bundle-manifest verify 绿；真壳未运行（用户明示本轮不做启动验证）——总览按钮快进、来源标注、指标配置会话按新纪律开工待用户实机验证。
