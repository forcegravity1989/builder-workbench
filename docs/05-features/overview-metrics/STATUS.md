## 当前实现

- 业务目录、脚本输出与日／周读数收敛为 script + retro=true；不再接受仅当前 value 输出。源数据及历史存储归用户项目或服务所有，BW 不建立每日采集台账。
- “配置指标”使用 MessageSquarePlus 图标；每次在 bw/metrics-refresh 固定树中新建原生会话，加载 SYSTEM、metrics-refresh 及当前目录问题，保留已有未完成改动。
- 目录与新采集从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取定义和脚本，不在后台 fetch；单次执行固定来源修订，材料草稿树不 merge、不重置。读取失败保留原来源并显示错误；主检出新鲜度由总览「更新代码」按钮负责。
- 验收可从最新目录选择指标补充实测，原计划承诺与 baseline 保留只读；旧配置提交不拦截新采集。证据详情显示来源、采集时间、配置提交与脚本修订；定义指纹保存在材料中，没有专门的口径变化比较或确认界面，不自动判断达成。
- 原型、特性规格、产品 Skill 与协议按同一决定同步；不修改 hifi、共用工作区壳或计划/验收整体布局。项目内建统计仍独立于业务目录，开放 Issue 保留真实当前快照。
- 总览首次准备日／周数据，记分牌只显示周窗口；之后返回复用本次运行的项目快照，「更新代码」（快进主检出并重读目录）或指标刷新按钮（重新采集）才取得新数据。项目事件采集一次后本地落桶，业务两种口径分别采集；刷新失败保留原证据时间，日期显示跟随采集时刻。
- 版本列表按主干基线现有目录，每版本一份当前材料；已迁移的 Git 旧快照不再报重复问题，已删除版本不复活。落后的固定材料树不能覆盖主线文件。真实安装反馈确认了这轮修复范围；未新增测试用例，复验与提交证据随本轮 PR，真壳回验由用户执行。
- BW 自身目录落定（PR #292）：北极星删除（未定义清楚不硬立）；4 条指标 = 纳入项目数、每周闭环 issue 数（gh 采集）、使用周一屏项目数（target 6）、计划制定时长（两层采集，target 待真实基线后拍板）。四个脚本已在真实窗口实跑并用 gh/git 独立读回核对（数字见 PR #292）。

2026-10-22 Issue #158 记分牌改版（人确认原型、场景可编辑、聚焦来自计划）：总览内容区首行加四原则一句话；业务指标图表与项目研发统计两区删除，由记分牌替代——场景来自 `.bw/metrics.toml` 新增的可选 `[[feature]]`（name/value，协议、模板、metrics-refresh Skill 同步），每签一结果一引领，聚焦与完成线从版本区所选版本计划的 metricTargets 现算，输赢只比较带方向的完成线与最近数值读数。ECharts 依赖、总览 SDLC 读取编排与只剩测试在用的提交分桶函数一并删除，项目墙保留 sdlcProviderOf。BW 自身目录按保真稿登记四个场景和八个指标；历史来源尚未接入，脚本退出 2，读数保持未知。原先的纳入项目数、周一屏、计划制定时长、每周闭环 issue 数不再注册，采集脚本仍留在 `.bw/scripts`。证据与未验项随本轮 PR。
