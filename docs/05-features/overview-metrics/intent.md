# 项目总览：用阶段成果安排持续交付

> 给 Builder、Leader 和产品评审者判断价值时读取。本文管项目总览的用户问题与范围；行为见 [spec](spec.md)，现行指标实现见 [design](design.md)，认可与证据见 [STATUS](STATUS.md)。价值或边界变化时更新，不承担跨版本持久化协议或版本执行细节。
>
> 状态：既有总览与指标闭环的认可保持；#440 里程碑规划为 **draft，完整 intent/spec 与原型待人确认**。[可点击原型](prototype.html)供内部评审，不代表生产实现。沿已有 overview-metrics 特性维护，不另立页面特性。

## 用户与问题

Builder 与 Leader 要从项目当前情况决定接下来做哪些大需求，也要知道这些需求共同支撑什么阶段成果。只有拉长的版本排期，容易把“做了哪些事”替代“阶段要形成什么能力”，或把一次项目发布、本版验收误认为整个跨版需求完成。

项目背景与指标仍需可核对，帮助人判断方向；手填读数、重复记数或陈旧材料不能成为判断依据。

## 价值与依据

项目总览同时呈现阶段成果与支撑需求：人能说明为何优先做这件事，先交什么供部分用户使用，之后怎样达到约定交付范围，再进入准确版本继续收敛。里程碑是阶段成果；需求的 Pre版本、Release版本节点支撑它。负责人是需求属性，每行一项需求，不设人数或需求量配额。

依据为 [#440](https://github.com/forcegravity1989/builder-workbench/issues/440)、[v0.8 G2 计划](../../../.bw/planning/v0.8/data.json)、[PR #458 共同设计输入](https://github.com/forcegravity1989/builder-workbench/pull/458)及 [PR #460 内部评审](https://github.com/forcegravity1989/builder-workbench/pull/460#issuecomment-6466568756)。三条内部批注已逐项经人对齐：需求分行、直接拖动；11 月六个方向的样例与真实 10 月回看；阶段成果作为里程碑。共同设计未确认的身份与材料协议不在本稿落定；#158、#304/#320 仅作历史参考。

## 目标体验

进入项目总览，保留项目背景、北极星与最新记分牌。阶段成果在里程碑区有明确表达，选择成果后看其支撑需求；横向查看连续日期与项目版本，需求名和负责人常驻。点“规划里程碑”就在总览编辑阶段成果、增减或暂缓需求，拖动 Pre版本、Release版本节点安排交付，也可打开详情直接修改。

Pre版本表示先行可用，允许部分用户试用；Release版本表示该需求约定范围的正式交付。两者是需求交付节点，不决定项目版本名称，也不增加正式验收次数。范围、体验和验收在版本中持续收敛，月初不要求写齐规格与高保真。试用反馈、新需求和 bug 统一转成 Issue，再由版本计划关联相应目标；未纳入计划的反馈不成为本版承诺。

月度取舍、周反馈是可采用的节奏，月初可连续讨论 1–3 天，版本必要时跨周；不硬编码每月 2–3 个需求或每需求两周。讨论与导航使用项目真实版本名称，月份只作时间轴，保留现有侧栏，不新增 C→B 分组或独立月度总览。

## 范围与边界

- #440 负责阶段成果、需求取舍及跨版本安排；#334 负责本版承担的增量、执行与验收。项目发布、需求 Pre/Release 交付、会话结束、PR 合入、Issue 关闭、目标达成分别表达，完成仍由人确认。
- 本轮按人工评审撤去里程碑会话区与独立规划工作区，不新建规划聊天或 Skill。人可直接操作全部安排。模型仍可在项目已有原生会话中辅助梳理，相关建议由人核对；不据此宣称已有自动建议或材料回写能力。
- BW 提前对接预置工作日历，正常日期组件额外标示周六加班；不让用户导入。真实来源尚未接入时标明演示边界，日历不自行移动承诺。
- 不增加立项审批角色，不把效果指标强制作为所有里程碑统一验收门槛。#411 记分牌、指标配置与来源能力沿用；本轮不重做指标，也不建设平行数据库。
- 规划草案拟经 `bw/project` 项目材料的人审流程合入正式来源，编辑不直接覆盖主干。材料位置、准确的需求/版本身份、跨屏导航与并发处理仍待协调，本轮不制定持久化或路由协议。

## 成功判据

评审者能在一个总览里分清阶段成果与支撑需求，调整负责人、优先级与 Pre/Release 安排，不改变固定版本范围；草案、正式安排与人工完成结论能够区分。跨版仍是同一需求，每版承担的范围可核对；缺失记录保持未知，真实发布和人工验收互不替代。

正式实现后再用真实项目验证规划是否更易调整、返回是否保留上下文及草案、交付事实是否可追溯；本轮不预填收益比例或把静态样例当效果证据。

## 本轮原型范围

撤去原“版本计划与验收”大区，将空间给里程碑。三种评审场景为“尚无里程碑 / 制定中 / 已制定 · 跨月”。10 月从真实计划、人工验收及公开发布恢复版本链，“项目管理逻辑收尾”为人工归纳的阶段主题，不能反推月初承诺或整体已达成。11 月六个方向采用演示安排，非真实 v0.8 承诺。

原型说明统一前缀“原型注释:”，旅程写在规格，界面不摆演示步骤。内部评审使用 Orca 原生浏览器批注，PR 不补临时原型截图。原型与规格确认后在同一分支/PR 继续生产实现。
