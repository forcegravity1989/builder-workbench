> 给 Builder、Leader 和产品评审者判断价值时读取。本文管项目总览的用户问题与范围；行为见 [spec](spec.md)，现行指标实现见 [design](design.md)，认可与证据见 [STATUS](STATUS.md)。价值或边界变化时更新，不承担跨版本持久化协议或版本执行细节。
>
> 状态：既有总览与指标认可保持；#440 高保真与本轮范围已由用户确认并授权落地，设计已随 PR #460 合入；产品运行验收仍待进行。[原型](prototype.html)供内部评审，不代表生产实现。沿 overview-metrics 特性维护，不另立页面特性。

## 用户与问题

Builder 与 Leader 需要直接看见和调整项目接下来交付哪些特性、谁负责，以及先行可用与正式交付的时间安排。阶段要形成什么能力也应清楚，但不能挤占泳道图，让规划变成填写说明表单。

项目背景、北极星与指标继续提供判断依据；缺失记录不能被包装成已完成。

## 价值与依据

里程碑是阶段成果，特性的 Pre版本、Release版本节点支撑它。负责人是特性属性，每行一项特性，不设人数或数量配额。月度旗帜挂到该月最后一个有排期版本的轴点，轴下一句成果指向该点；时间导航连接下面的交付安排。

依据为 [#440](https://github.com/forcegravity1989/builder-workbench/issues/440)、[v0.8 G2 计划](../../../.bw/planning/v0.8/data.json)、[PR #458 共同输入](https://github.com/forcegravity1989/builder-workbench/pull/458)及 [PR #460 内部评审](https://github.com/forcegravity1989/builder-workbench/pull/460#issuecomment-6466568756)。用户进一步确认：紧凑时间导航；统一称特性并在泳道就地编辑；保留 Pre/Release 拖动；移除可撤销；未提交、待合入、待更新与还原范围明确区分。#158、#304/#320 只作历史参考。

## 目标体验

保留现有项目总览壳、背景和最新记分牌，把原“版本计划与验收”大区交给里程碑。点击月份或版本定位泳道；点“规划里程碑”，直接改特性名称、负责人，拖动 Pre/Release 节点安排时间窗口，点击版本名改名。添加特性就在泳道出现新行，移除整行后可以撤销，不保留“暂不安排”列表。

月份与特性共用一条连续横向时间轴，默认定位最新规划。先铺周一至周五的浅色周窗口，周末淡化；添加特性后直接拖动 Pre/Release，或在周窗口就地填写版本名，用到时才登记版本。未使用的周只是时间背景，不要求先填版本登记表，也不批量创建版本材料。编辑时始终查看含本次修改的一张泳道，逐步撤销/重做，提交评审后建立新基线；全量放弃使用独立的恢复图标，与逐步撤销区分。

Pre版本表示先行可用，允许部分用户试用；Release版本表示该特性约定范围的正式交付。它们是交付安排，不强制项目版本命名，不增加正式验收次数。完整规格与高保真在版本内收敛；所有反馈、新需求和 bug 统一转成 Issue，由版本计划关联，未纳入的反馈不是本版承诺。

月度选择与周反馈是可采用的节奏，不硬编码数量、周期或发布日。讨论与导航使用真实版本名称，月份只作时间轴，保留现有侧栏，不新增 C→B 层级或独立月度总览。

## 范围与边界

- #440 管阶段成果与跨版本安排；#334 管本版增量、执行和验收。特性整体完成、本版验收、项目发布、PR 合入、Issue 关闭分别表达，完成由人确认。
- 撤去会话区、独立规划工作区和大编辑表单，不新建规划聊天或 Skill。模型可在已有原生会话辅助梳理，不据此宣称自动建议或回写已实现。
- 移除独立日历入口。普通工作周直接体现在时间轴；未来真实工作日来源可用于日期推导，当前不模拟加班日。
- 不增加立项审批角色或统一的效果指标门槛。#411 指标能力沿用，不重做指标或建设平行数据库。
- 编辑作用于草案，拟经 `bw/project` → PR/MR → 主干进入正式总览；还原只撤销最近提交后的修改，更新正式安排不带入未提交改动。材料与写入设计见 [里程碑实现设计](milestone-design.md)；不自行定义 #334 的特性关系协议。

## 成功判据

评审者能把主要注意力放在泳道，直接编辑特性名称、负责人和 Pre/Release 安排，版本改名不丢关联；移除可撤销。阶段成果、规划状态与人工完成结论分得清，更新已合入内容不会丢掉仍在编辑的草案。

同一特性跨版持续推进，不按标题或日期猜对应关系；历史来源可核对，未知保持未知。本轮不预填收益比例，也不以浏览器样例证明产品效果。

## 本轮原型范围

三种场景为“尚无里程碑 / 制定中 / 已制定”。已有版本来源统一为 .bw 规划材料；无排期的历史版本不绘制，不从 Releases 补日期，也不另设旧版本关联入口，可由模型补齐真实材料。11 月六个方向及安排为演示，非真实 v0.8 承诺。本轮连续时间轴与按需登记周版本先更新高保真，待用户结合可见方案评审后接入产品。

原型说明统一前缀“原型注释:”，旅程留在规格。内部使用 Orca 原生浏览器批注，PR 不补临时截图。设计已随 PR #460 合入，Issue 保留；同一任务分支另开开发 PR。实现计划与证据边界见 [里程碑实现设计](milestone-design.md)和 [STATUS](STATUS.md)。未来版本先登记名称与日期、按需开工；月度规划不创建或绑定具体特性 Issue，细化交给版本计划助手。
