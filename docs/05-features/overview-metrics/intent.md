# 项目总览：用阶段成果安排持续交付

> 给 Builder、Leader 和产品评审者判断价值时读取。本文管项目总览的用户问题与范围；行为见 [spec](spec.md)，现行指标实现见 [design](design.md)，认可与证据见 [STATUS](STATUS.md)。价值或边界变化时更新，不承担跨版本持久化协议或版本执行细节。

**认可**：里程碑粗粒度规划、计划与实际日期对照及跨版目标结果已由用户确认，[原高保真](prototype.html?review=551&revision=cells&example=dates)为形态依据。实现和运行证据分别见 STATUS，原型不作为真实交付证明。

## 用户与问题

Builder 与 Leader 需要先安排哪些特性、谁负责、在哪一版上线及维护。里程碑规划时很少能决定目标和逐阶段细节；要求先填这些关系会增加使用负担。想看实际时，最小有用信息是这个特性在本版的目标是否达成，细节可以进入版本总览。

## 目标体验

沿原项目总览的日期旗帜和特性泳道编排，默认展示计划。特性默认前五阶段合一段、后一版 Maintain，内部保留原颜色但只操作整段。5 天只是默认，版本可以更长，同版特性可以更短；单条 Maintain 不再误动其他特性。原规划随时可重新编排，实际验收不回写它。

关键里程碑只填日期与预期成果；特性编排只填特性名、负责人和版本安排，不选择目标。版本计划助手以完整特性名找到带“特性”标签的主 Issue，再放到本版选定的目标下；每目标最多一个特性，同一特性跨版复用同一主单。

实际只读正式目标验收，首次交付用已上线/未上线，后续用维护完成/维护未完成；没有结论不补造。实际不画未采集的 SDLC 工期。实际视图保留规划版本与日期对照，结果明确所属版本；规划日期与本版采用日期分别来自对应材料；默认两段不限制后续版本继续纳入。

## 范围与边界

- 里程碑给预期，首日 Plan 决定本版范围及目标；两者允许有差异。版本照常交付，部分特性未达成可留待后版，不新增延期或版本异常判断。
- 沿现有计划助手、目标验收及 PR/MR 评审完成协作，不增加确认按钮、独立特性结果、绑定表单或冻结流程。旧排期继续可读可改。
- 目标达成由人决定；该结果用于本轮特性上线/维护样式，不代替 provider 发布，也不自动关闭 Issue。内部色条比例不是实际 SDLC 耗时。
- 计划助手把里程碑作为可选参考；未规划也能正常制定版本。确认特性改名时同步主单与里程碑名称，保留身份及历史。
- 版本总览仅共用特性匹配与规划读取；匹配不到保留原默认行为，不改界面、SDLC 开关及统计。原指标、背景、日历和草案耐久/评审链沿用；不增加数据库、审批角色或新工作区。

## 成功判据与证据

人能在熟悉的原高保真上完成粗粒度编排；一个特性的操作不改变其他特性的安排，旧版重排不改实际结论。A 未达成、B 首次达成、C 维护未达成可以一眼分清；只有 A/B 规划时也能读到 C 的正式结果。计划助手职责明确，计划/验收沿现有界面即可配合。
