# 总览指标：用真实数据理解项目与特性

> 给 Builder、Leader 和产品评审者在判断价值时读取。本文管用户问题与范围；行为见 [spec](spec.md)，设计见 [design](design.md)，证据见 [STATUS](STATUS.md)。价值或边界变化时更新。
>
> 状态：既有特性定义已合入。2026-09-28 用户确认本次总览原型并授权实施；现行实现与验证边界见 STATUS。

## 用户与问题

Builder 和 Leader 需要据实际情况制定版本目标、核对交付。bw-orca 总览已接真实指标和版本材料，但计划与验收回看未按对应轮次组织，指标图表及采集能力与原型存在差距，重复的刷新入口和实现术语增加理解成本。手填数字和多屏各自记数不能提供可核对的依据；为补历史而增加每日记账又带来使用负担。

## 价值与依据

让总览、计划、验收读同一个定义与脚本来源；能查历史就查历史，只能查当前就诚实显示当前及时间，缺数据保持未知。依据是 main 已有 UI/协议/采集脚本、目标分支源码和本轮用户反馈。旧 Rust 功能不构成 Electron 交付证据。

## 目标体验

进入总览先看到项目方向、北极星，以及所选版本对应的计划和验收纪要；在研版本可看最新草稿，同版本的不同轮次可回看。业务按“主要／特性”组织滞后及引领指标；项目保留提交、合入 PR、开放 Issue 的日／周折线图。已有脚本直接刷新；需要新指标时点“设置指标”，在独立的 Orca 项目任务内确定口径、补采集脚本并验证，完成后回总览。计划选择有效指标填写目标值，验收刷新实测，由人判断。

## 范围与边界

- 沿 main 保留图表、特性归属、引领/滞后、日/周和来源，优化当前前端呈现；不新增指标侧栏。
- 仅支持脚本实际读数，优先可回溯查询，允许仅当前查询。不新增人工录数、每日采集自动化、常驻记账分支或每日写回链。
- 计划/验收归档保留当时采用的读数证据；这不是持续采集台账。无来源、无当前能力的指标不进入可承诺目录。
- 保留项目方向、北极星和版本记录上下文；多轮计划/验收全文消费两个版本特性现有材料，不新增可编辑副本或里程碑系统。本次仅调整总览及其采集接线；共用工作区壳、计划/验收界面和 hifi 由其他任务维护。

## 成功判据

三个界面对同一定义、窗口和来源显示一致；零、未知、失败和过期可区分；脚本能重算的历史可独立复算，不能回溯的事实不被画成连续历史。首用周收集口径歧义、采集失败和实际数据决策案例，建立有效观测后优化；不先编收益比例或健康评分。
