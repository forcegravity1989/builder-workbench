# 项目总览与指标：用真实效果保持方向

> **维护约定**：给产品、设计、实现与验收者读取。本篇只定义用户结果、价值范围和排除。当前行为归 [spec](spec.md)，实现边界归 [design](design.md)，证据和缺口归 [STATUS](STATUS.md)。认可的决定直接改写正文，不追加开发流水或历史取舍。

## 用户与问题

Builder 和 Leader 需要在连续日期轴上安排里程碑、Build 与 Maintain，也需要回看版本交付和真实效果。固定版本计划承接承诺与任务，验收承接人的结果判断，项目总览负责把持续排期、当前上下文和可核对的指标放在同一处。

只有排期颜色、条长或缺失读数不能证明完成。指标必须带来源、窗口和口径，读取失败、缺数据和真实零要能区分。看到偏差后由人决定是否调整后续计划或任务，系统不替人下结论。

## 目标结果

- 在项目总览中安排连续的版本节奏、关键里程碑、Build 和多轮 Maintain，保留同一特性的身份与历史。
- 以版本的正式计划和人工验收结果回看交付，再以指标记分牌观察实际效果、完成线和走势。
- 从当前版本目标推出聚焦场景，展示可追溯的指标读数。没有可信读数时保持未知，不补演示值或旧值。
- 当人识别出偏差时，能沿既有计划、任务和验收入口继续处理，不自动创建、关闭或修改 Issue。

## 范围与边界

- 总览维护里程碑、连续日期和 Build/Maintain 编排。正式计划、任务和验收仍由各自特性维护，日期交集不自动纳入版本。
- 指标目录、历史脚本采集、来源修订、窗口、缓存和错误语义由本特性维护。计划与验收只保存选用的指标引用和读数证据，不建立每日业务数据库。
- 项目与宿主身份、文件和命令执行沿 Orca 原生能力。配置指标通过固定维护工作树中的原生会话完成，由用户发送并经项目评审流程合入。
- 记分牌只表达读数和可比较的完成线。指标关联不证明因果，完成线颜色不替代人的验收结论。

项目墙、版本计划、版本验收和任务管理承接其所属用户结果。总览不另造版本、任务、Issue、完成台账、权限体系或指标自动化，也不把原型样例当成真实数据。

## Explore BW 归属

本特性归入探索 BW 的 W05「用真实效果保持方向」。它负责查看阶段进展和指标、识别缺数或偏差，并把人决定的后续动作交回版本计划与任务入口。F18 项目里程碑、F21 项目总览和 F28 指标配置与采集是 W05 的能力入口。W05 的完整跨特性旅程由探索 BW 维护，本目录只登记本特性观察到的步骤和证据。

## 成功判据

人能在同一项目中安排持续工作，进入版本查看正式结果，在总览读取带来源的指标并识别未知或偏差，再由人决定后续计划或任务。重启、切换项目或来源失败时，历史材料和读数身份仍可独立核对。原型、静态检查、真实 Electron、外部来源和用户确认分别记录，不互相替代.
