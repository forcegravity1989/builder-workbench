# 项目总览：依据真实情况选择方向、安排交付

> 给 Builder、Leader 和产品评审者在判断价值时读取。本文管项目总览的用户问题与范围；行为见 [spec](spec.md)，现行指标实现见 [design](design.md)，认可与证据见 [STATUS](STATUS.md)。价值或边界变化时更新，不承担跨版本持久化协议或版本执行细节。
>
> 状态：既有总览与指标闭环的认可保持；#440 月度规划为 **draft，待内部评审与 intent/spec 确认**。[可点击原型](prototype.html)使用演示数据，不代表生产实现。2026-10-27 用户授权在已有特性中补月度规划草案、复用设计资源；没有新增独立特性。

## 用户与问题

Builder 与 Leader 要从项目当前情况决定接下来做哪些大需求。已有总览能查看背景、版本材料和指标，但不足以表达一个月内的取舍、先后、跨 B 版本交付和截止时间；只看单版任务也容易把“先行 MVP 可试用”误认为整个大需求完成。

指标仍需可核对：定义合入后，总览、计划、验收应读取有效目录与可回溯脚本；手填读数、多屏重复记数和落后的固定树不能成为判断依据。

## 价值与依据

让人看懂“为何本月优先做这件、先交什么给谁试用、何时完善到约定范围”，再进入对应 B 版本继续收敛和交付。模型整理输入、提出取舍与影响，人决定是否采纳，减少隔天讨论时重新拼上下文的成本。是否实际减少成本仍是待验证假设，不预填收益比例。

依据为 [#440](https://github.com/forcegravity1989/builder-workbench/issues/440)、[v0.8 G2 计划](../../../.bw/planning/v0.8/data.json)与 [PR #458 共同设计输入](https://github.com/forcegravity1989/builder-workbench/pull/458)。共同输入尚未合入时按其提交读取，不能把本草案当作两屏共同协议已定稿。#158、PR #304/#320 只提供设计参考，不替代最新人工澄清。

## 目标体验

进入项目总览，项目方向与指标入口仍可见。月初可以连续讨论 1–3 天：从候选大需求中选择本月重点，调整优先级、主导人、目标 B 版本与截止时间；暂不安排的需求保留理由。泳道让同一个需求的先行 MVP 与后续完善连起来，不要求月初已写齐规格、高保真。

模型帮助比较取舍，结合工作日历说明冲突与改动影响，先出可审查建议，人采纳后更新草案。先行 B 版本完成必要设计握手，并接上开发、测试，形成可供部分用户使用的 MVP；真实试用带来反馈，后续 B 版本修理完善。具体范围、体验和验收在 B 版本中持续收敛。每个 B 版本只做一次正式验收；周中评审与试用不会变成重复正式验收。完成后新 bug、优化和衍生小需求继续走现有 Issue workflow。

既有指标采集、来源详情、配置会话与版本材料回看继续可达；没有数据就显示未知，不把演示图表或任务数量当作健康结论。

## 范围与边界

- 本特性继续承载“理解项目情况并决定下一步”的用户目标。#440 负责月度选择与跨版安排；#334 在既有版本工作区中负责本版阶段、成果、反馈与处理结果。两个页面不自动等于两个新特性。
- 月度规划约定做哪些、优先级、目标版本与截止，不另设立项审批角色，不硬编码每月需求数量、每需求两周或固定人数。B 版本期望按周反馈，必要时可跨周。
- 工作日历作为排期输入，必须有适用时间与来源；无真实样本时仅演示流程。日历和模型不会自行移动已确认承诺。
- 指标可按需支持取舍，不强制成为每个里程碑统一的验收门槛。业务仍仅支持 script + retro=true 的日／周历史采集，源数据归项目；无手填数、每日记账分支或平行数据库。
- 保留指标来源、特性与引领/滞后关系、项目统计及现有材料入口。计划/验收消费现有材料，不复制可编辑正本；历史承诺与证据不被新规划覆盖。
- 共享需求身份、需求与 B 版本关系、导航上下文和公共资源先交主会话协调。本轮只提供具体建议，不改生产 schema、原生会话/工作树、v0.8 真实计划或 #334 文件。

## 成功判据与待审选择

评审者能够在原型里选择与暂缓需求、改安排、理解模型建议的影响，并沿同一需求看懂先行 MVP、部分用户试用、后续完善和持续改善。正式实现后再用真实项目检查：恢复讨论是否保留来源与决定，跨版是否不重复记完成，未知/零/失败/过期是否仍可区分。

首轮推荐以大需求为泳道、Builder 为行内信息，月度选择和本版交付各有一处主表达。与按人分泳道相比，它更易追踪跨版需求；是否适合内部评审，先通过可见原型批注判断。待审问题与共享边界的具体建议集中在 [spec 的取舍与协调](spec.md#取舍与主会话协调)，不在本文重复列协议。
