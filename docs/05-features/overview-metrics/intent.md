# 总览指标：用真实数据理解项目与特性

> 给 Builder、Leader 和产品评审者在判断价值时读取。本文管用户问题与范围；行为见 [spec](spec.md)，设计见 [design](design.md)，证据见 [STATUS](STATUS.md)。价值或边界变化时更新。
>
> 状态：总览改为记分牌（2026-10-22 人确认聚焦来自计划）。2026-10-27 起牌面只留场景、读数和完成线。历史采集、每次配置新建会话及最新目录采用沿用。验证边界见 STATUS。

## 用户与问题

Builder 和 Leader 需要据实际情况制定版本目标、核对交付。指标配置完成并合入后，总览和版本流程应能读取新定义与脚本；不能因为固定工作树落后或旧计划保存了配置修订而一直停在旧目录。手填数字和多屏各自记数不能提供可核对的依据；为补历史而增加每日记账又带来使用负担。

## 价值与依据

让总览、计划、验收从项目最新已合入来源发现指标，用同一套可回溯脚本核对日／周事实；没有历史能力的业务指标不进入可用目录。旧计划与验收证据保留原定义和读数，供人比较。依据是已确认的用户旅程和目标分支实现；旧 Rust 功能不构成 Electron 交付证据。

## 目标体验

进入总览先看到项目方向和北极星，再看记分牌与所选版本的计划、验收纪要；每个版本只显示当前一份计划和验收；在研版本可看有效的当前草稿，已迁移材料正常显示，旧提交不产生重复迁移提示。记分牌按项目自己声明的场景分页签，每签一个结果、一个引领；所选版本计划给哪个场景的指标写了目标值，哪个场景就排在前面，目标值贴在读数旁，点的颜色表示是否达到完成线。场景随指标目录编辑，价值说明留在目录里。首次加载准备记分牌所需的日／周读数，切换与返回复用快照，主动刷新才取得新数据；需要新指标时点“配置指标”，每次在固定维护工作树中新建 Orca 原生会话，确认口径、补脚本并试采，合入后回总览同步目录。计划选择有效指标填写目标值，验收可使用最新指标补充实测，由人判断；原计划承诺不被改写。

## 范围与边界

- 沿用特性归属、引领/滞后、日/周和来源，用记分牌替代原业务指标图表与项目研发统计（提交、合入 PR、开放 Issue）两区；不新增指标侧栏。
- 业务指标仅支持 script + retro=true，脚本按日／周查询历史。源数据及其存储由用户项目或服务拥有；BW 不提供人工录数、每日采集自动化、记账分支或日写回链。
- 计划/验收归档保留当时采用的读数证据；这不是持续采集台账。无来源、无当前能力的指标不进入可承诺目录。
- 保留项目方向、北极星和版本记录上下文；计划/验收全文消费两个版本特性现有材料，不新增可编辑副本或里程碑系统。本轮调整指标配置、目录与采集链，以及验收中的指标选择；共用工作区壳、计划/验收整体布局和 hifi 由其他任务维护。

## 成功判据

三个界面对同一定义、窗口和来源显示一致；零、未知、失败和过期可区分；脚本能重算的历史可独立复算，不能回溯的事实不被画成连续历史。首用周收集口径歧义、采集失败和实际数据决策案例，建立有效观测后优化；不先编收益比例或健康评分。
