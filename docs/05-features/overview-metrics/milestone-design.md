# 项目里程碑：材料与提交设计

> 给实现、计划助手接口维护与检视者读取。本文管里程碑的数据源、编辑状态、提交事务和版本入口；用户行为见 [spec](spec.md)，指标实现仍在 [design](design.md)。协议或代码责任变化时更新；不定义版本总览的 SDLC 采集协议，不收录交付流水。

本文描述自由日期里程碑的材料与事务；运行验证边界见 [STATUS](STATUS.md)。实际只读正式计划和目标验收，不写回规划。

## 材料分工与存量处理

版本以 version + cycleId 标识。`.bw/milestones.json` 使用 schema_version=4，可选 versionPlans 保存预排版本身份和预期日期；仅排期不创建 `.bw/planning/<version>/data.json`。用户主动准备计划工作区时，由材料所有者的现有初始化执行器沿用排期身份和初始日期；无排期时才新建身份。已有计划保持不变，其 timeWindow 是正式采用日期，里程碑重排不覆盖它。两种日期均为包含两端的 ISO 日期，验收按固定 planRef 读历史。

版本目录及各页面继续按已有材料和原生工作区读取，不增加占位过滤或来源字段。旧版遗留的空占位由项目一次性列清单，核对生成来源、实际内容、工作区及验收材料后通过 PR 清理，保留里程碑排期和 Git 历史；不在升级启动或日常里程碑提交时自动删除。正常空计划及已有业务材料不属于清理范围。

同一项目成员升级后再提交只含排期的新版本，旧客户端不支持这种目录语义。升级仍可读取已有计划，但不会自动消除旧占位；完成一次性清理后，纯预排版本不进入版本目录。主动创建的空计划通过原生绑定与材料显示，不以目标数量或日期判断是否开工。

节点按稳定 id 保存 outcome 和 date；仅有月份精度的成果保留 month，人工补日期后替换。特性保存 id、title、可空 owner 与 deliveries；每段为稳定 id、Build/Maintain 和可选 timeWindow，不含版本引用。时间为北京时间民用时间 `YYYY-MM-DDTHH:mm`，结束边界不包含。新安排默认值与拖动规则见 [日期编排](spec.md#日期编排与默认值)。版本窗口只按天修改；前后端共用基线比较，禁止新增或扩大版本交集，保留或缩小存量重叠不阻止提交；阶段按半天调整，Build 碰撞后续维护时保持维护时长顺延。预览保留段的 DOM 顺序，手势结束才按日期整理，避免自由换序中断指针捕获。

编辑以 draft.versions 维护版本窗口，draft.material 不重复保存 versionPlans，自动保存时统一写回。读取 schema 2/3 时，保留节点、特性及段的身份与名称，已记录的前五阶段按外边界归为 Build，维护归为 Maintain；空阶段不造日期。特性旧月份、版本绑定和目标槽位在迁移后移除，当前正本只保存新格式。没有 versionPlans 时借当前可读版本窗口展示，编辑保存时才补存，不能称为原始预期日期。正式材料、工作树文件与旧草稿可读取同一旧格式；工作稿允许字段尚未填完。

版本总览只在固定计划明确纳入且特性唯一匹配时，将自由日期与本版正式窗口求交，分 Build/Maintain 汇总规划跨度；不把完整跨版段重复计入每版，不推造五阶段实际工时。已开工版本可改预期排期，但不通过此入口删除真实版本或改名已建立的执行身份。

## 最小实际投影

1. 从正式版本计划中读 tasks 指向的主 Issue，精确“特性”标签且标题包含完整去首尾空白的里程碑特性名；无候选/多个候选不猜。包含匹配兼容既有 `【版本|目标】` 前缀；不用目标标题作为键。
2. 得到唯一完整 `provider/repository/number` 后，以该主单查询所有正式纳入版本，不依赖里程碑排期段列表。每版主单对应一个 goalId；目标下可有多条同特性执行 Issue，不重复计数。旧材料有多特性目标时保留规划，不制作额外兼容绑定界面。
3. 核对验收归档 PR/MR 已合入、版本身份及固定 planRef，再取人工目标 outcome。未判定/未合入/失败不生成确认结果。历史结果只来自其固定计划，不能用当前草案的 tasks 改写对应。
4. 按正式版本历史顺序计算是否存在前版 met：没有则本版开发，有则 Maintain。本版首次 met 不改变本版类型，只影响后版；后续 not-met 不清除这个事实。首次交付映射已上线/未上线，后续映射维护完成/维护未完成。重排里程碑时间不能改这个顺序。
5. 实际绘制使用各版正式窗口与目标结果，不用 SDLC 分段，不称为特性实测工期；找不到日期不补造时长。读取复用既有 `useVersionOverviewMaterials` 与原生任务缓存，里程碑独立建立目标结果投影，不依赖 SDLC 证据采集；两屏共用特性名称匹配及规划读取，版本总览未匹配时保持原默认行为，不改其界面、SDLC 算法或开关，也不新建采集服务。

这些结论现算，不新增特性结果存储、首次可用确认或版本延期状态。人决定纳入后版，计划助手维护规范关联；详见 [计划配合](../version-planning/spec.md#计划助手与对象动作)。

## 工作树文件与正式来源

项目总览以所属运行时的 `bw/project` 工作树文件为规划来源。没有项目材料工作树时从正式快照浏览，显式编辑或更新才准备工作树。正式材料从主干基线读，供版本总览与历史结果使用。新建计划沿既有计划工作树的准备基线继承排期，项目材料工作稿不参与。待评审、已合入从提交和提供方证据推导，不写入业务文件。

自动保存只对同一文件做内容修订检查，复用文件锁、耐久替换与原生工作树身份。工作稿允许临时空字段，提交前使用正式 schema 和排期约束校验。读回外部修改时保留尚未保存的输入。撤销、重做和视口属于视图，旧 profile 草稿只读并按需迁入或复制，不再写新本机草稿。

## 提交与同步

项目名片和里程碑提交共用串行队列。里程碑提交核对当前文件仍为用户确认的修订，校验版本身份，提交里程碑路径并走已有非强制推送与 PR/MR 创建逻辑。发布失败可继续提交评审，已关闭的旧评审不可冒充当前评审。不再把分支 HEAD、全量计划指纹或无关材料的修改作为草稿门槛。

里程碑「更新代码」复用版本材料工作树的同步入口，只作用于 `bw/project`。由 Git 判断同一工作树的未提交改动能否与更新共存；Git 冲突保持现场，由原生工作树继续处理。已有宿主支持边界保持适用。

## 界面及版本衔接

日期旗帜与特性行共用连续日轴和同一视口；操作见 [关键节点与操作反馈](spec.md#关键节点与操作反馈)。默认计划；实际在原位置切换，版本头对照规划与正式采用日期，结果条按正式窗口并明确版本名；具体呈现见 spec。特性左侧可编辑名称和选填负责人，也可追加 Maintain 或删除整行。独立时间段可自由拖动，维护段可单独删除；不改变正式版本纳入。旧版本同样可重排；版本表头及实际结果条均按准确 version + cycleId 跳转版本总览，返回恢复草案与视口。

空周只在使用时登记，失败或取消不留版本。正式界面和原型共用 `work-calendar.ts`。预置文件 `work-calendar-2026.json` 已按[国务院办公厅年度安排](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html)和月末周六规则列出全部「班／休」日期，显示时直接查表。特性按末段结束日期倒序，编辑时固定行序，新行置顶；纯规划操作不创建主 Issue 或执行会话。

连续日轴只渲染视口附近约一年半的日期，靠近两端重新定位渲染窗口并保留视图与手势位移。首次从今天前十天开始，此后恢复日期、像素偏移和筛选；切月不清空。未知日期保留明确占位，损坏来源保留原文件并报错，不能静默清空。
