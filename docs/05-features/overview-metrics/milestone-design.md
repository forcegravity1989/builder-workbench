# 项目里程碑：材料与提交设计

> 给实现、计划助手接口维护与检视者读取。本文管里程碑的数据源、编辑状态、提交事务和版本入口；用户行为见 [spec](spec.md)，指标实现仍在 [design](design.md)。协议或代码责任变化时更新；不定义版本总览的 SDLC 采集协议，不收录交付流水。

采用已确认的粗粒度规划与目标结果投影，保留现有 Git、草案与事务能力。实际只读正式计划和目标验收，不写回规划；本文描述设计契约，不代替运行验证。

## 材料分工与存量处理

版本以 version + cycleId 标识。`.bw/milestones.json` 使用 schema_version=3，可选 `versionPlans: [{version, cycleId, timeWindow: {start, end}}]` 保存预期版本日期；`.bw/planning/<version>/data.json.timeWindow` 保存正式采用日期。两端均为包含当日的 ISO 日期。里程碑重排不覆盖已有计划的日期及其他字段，新版本才登记最小空计划。验收按固定 planRef 读取历史计划，不从最新规划改写日期或结果。

里程碑节点 milestones 按稳定 id 保存 outcome 和具体 date；仅有月份精度的成果保留 month，补日期后替换为 date。没有成果的月份占位不产生节点。特性保存稳定行 id、名称、负责人、数组顺序与 deliveries；每段有稳定 id、版本引用及 stages。编辑草案以 `draft.versions` 维护预期窗口，`draft.material` 不重复保存 versionPlans；提交时由同一序列化路径写入项目材料。缺 versionPlans 的存量材料可借当前可读版本窗口建立视图，正常提交才补存；不宣称恢复了未记录的原始预期日期。

新特性默认前五阶段一段、Maintain 一段，内部按比例计算。条身移动不扩版，上线段换版冲突时仅顺移自身 Maintain，整次同撤销；边缘伸缩可向外扩容所属窗口，不牵动其他行。默认两段不限制实际跨版数量。表头平移显式移动整版，表头伸缩不能裁掉已有安排。

旧 goalSlot/goalId 在读取时归一化移除，不参与编辑、匹配及提交约束。空阶段旧记录只画版本归属；人重新安排才生成默认段，不把默认比例当历史事实。阶段边界使用北京时间民用时间 `YYYY-MM-DDTHH:mm`；内部等比分界保留分钟精度，外边界按半天操作，版本窗口按天。原型 numeric day/localStorage 不是生产协议。

旧版和已开工版本可重排，恢复、CLI 与服务端采用同一规则；来源修订、并发、引用身份和排期冲突检查继续有效。可重排不等于改写固定验收或删除真实版本。已建立正式执行/归档身份的版本不通过宏观入口改名。确认特性改名由计划助手同步主 Issue 标题和对应行 title，经现有 bw/project 评审，保留行 id、主单身份和历史引用；普通目标改名不触发同步。

## 最小实际投影

1. 从正式版本计划中读 tasks 指向的主 Issue，精确“特性”标签且标题包含完整去首尾空白的里程碑特性名；无候选/多个候选不猜。包含匹配兼容既有 `【版本|目标】` 前缀；不用目标标题作为键。
2. 得到唯一完整 `provider/repository/number` 后，以该主单查询所有正式纳入版本，不依赖里程碑两段列表。每版主单对应一个 goalId；目标下可有多条同特性执行 Issue，不重复计数。旧材料有多特性目标时保留规划，不制作额外兼容绑定界面。
3. 核对验收归档 PR/MR 已合入、版本身份及固定 planRef，再取人工目标 outcome。未判定/未合入/失败不生成确认结果。历史结果只来自其固定计划，不能用当前草案的 tasks 改写对应。
4. 按正式版本历史顺序计算是否存在前版 met：没有则本版开发，有则 Maintain。本版首次 met 不改变本版类型，只影响后版；后续 not-met 不清除这个事实。首次交付映射已上线/未上线，后续映射维护完成/维护未完成。重排里程碑时间不能改这个顺序。
5. 实际绘制使用各版正式窗口与目标结果，不用 SDLC 分段，不称为特性实测工期；找不到日期不补造时长。读取复用既有 `useVersionOverviewMaterials` 与原生任务缓存，里程碑独立建立目标结果投影，不依赖 SDLC 证据采集；两屏共用特性名称匹配及规划读取，版本总览未匹配时保持原默认行为，不改其界面、SDLC 算法或开关，也不新建采集服务。

这些结论现算，不新增特性结果存储、首次可用确认或版本延期状态。人决定纳入后版，计划助手维护规范关联；详见 [计划配合](../version-planning/spec.md#计划助手与里程碑衔接)。

## 正式、已提交与未提交

正式材料固定读取主干基线提交。bw/project 仅提供已提交提案，不能覆盖主干正式投影。按文件内容构造修订，不能以 PR 状态代替实际材料。

应用视图会话保存未提交草案、最近提交基线与视口；从版本页返回恢复原状态。恢复记录通过本机薄 IPC 写入当前客户端 profile 的 `workbench/milestone-drafts/<scope哈希>.json`，以项目、仓库、执行宿主、runtime owner 和工作树隔离，不走远端材料路由。复用原生耐久写入：临时文件刷盘后原子替换；异步保存不阻塞输入，只有最新快照得到落盘确认才算可恢复，不再用独立一行提示正常保存。强退时尚在保存的输入不作已保存承诺。

同 scope 的读取、修订校验和写入串行；客户端一次只有一个在途保存，后续输入合并为最新快照，旧响应不覆盖新输入。清除草案也写入新修订的空记录，避免陈旧窗口复活旧输入。坏文件、读写失败或其他窗口修订冲突保留输入并明确报告，不静默覆盖。恢复允许名称/负责人尚未填完；重启先从 Git 读取最新材料，基线一致才续编，否则保留草案并阻止覆盖。它不是正式数据源，也不跨机器同步；实际提交仍经过同一 .bw 事务。提交成功/全量放弃后清除对应恢复内容；撤销栈不跨重启。提交期间各页面共用写入状态，迟到响应不覆盖另一份编辑。浏览器客户端尚不支持该本机文件恢复，编辑时明确提示，不能假报已保存。

编辑会话在内存中维护撤销/重做快照；一次字段编辑及其失焦整理合为一步，节点拖动、行排序和移除独立成步。版本名清空仅在 Enter/失焦提交编辑时判断撤回：以 cycleId 核对正式/提案快照均无该版本且所有特性均未引用，才移除草案版本；按键中间态和 Escape 不移除。生产沿用此判据；原型按相同约束演示，已提交版本仍受服务端不可删除约束。历史不持久化，不回退 Git；相同基线的刷新/返回保留历史，已确认的新提交清空历史。“放弃本次修改”恢复最近一次提交后的基线；第一次提交前恢复正式基线。外部修订变化后旧草案不能静默提交，须核对；界面保留冲突输入。待合入可继续修改并更新同一 PR/MR；顶栏同一个入口在提交评审、更新评审、查看评审与更新正式安排间切换，不另放评审链接行。推送或创建评审失败可重试已经落盘的提交；读取失败保留异常提醒，不能当作没有评审。

## 写入事务与执行宿主

复用 Orca 原生项目/宿主/工作树解析、bw/project 创建登记、Git runner、现有 GitHub/CodeHub 评审入口。RPC 只接收受信任 scope，不接收任意文件根。当前文件事务支持所属本机/配对 runtime；SSH 执行适配仍未接入，明确返回错误，不把 SSH 路径交本机文件 API。

同项目名片与里程碑提交共用串行队列；多进程通过与材料服务一致的文件锁协作：

1. 核对 bw/project 登记、实际分支、干净工作副本、调用方读到的正式内容修订及分支 HEAD。
2. 只自动快进；分叉保持原样交原生会话合并，不 reset 或强推。
3. 校验所有材料、准确身份和排期冲突；已有计划包括日期在内的全部字段保持，不通过此入口删除已有版本；预期日期只写 versionPlans。
4. 获取变更文件锁，再重查权限、基线、HEAD、分支及所有源文件字节；全部核对后才写入。路径拒绝符号链接和非普通文件。
5. 耐久替换文件、提交指定路径，文件锁持续到提交结束。失败保留工作副本供核对，不自动回滚用户输入。
6. 非强制推送，复用开放评审或创建新 PR/MR。提交、推送、创建评审是不同结果；不得把失败当正式安排或人工验收。

多文件写入与 Git 提交不是跨系统原子事务；进程中断或工具失败可能留下未提交文件，下一次入口检测脏树并停止覆盖。此时用原生会话核对后继续，不静默补写。

## 界面及版本衔接

日期旗帜与特性行共用连续日轴和同一视口；操作见 [关键节点与操作反馈](spec.md#关键节点与操作反馈)。默认计划；实际在原位置切换，版本头对照规划与正式采用日期，结果条按正式窗口并明确版本名；具体呈现见 spec。特性栏只编辑名称和负责人，移除版本标签/选择器，整段拖动决定版本归属，内部阶段不再有交互。旧版本同样可重排；版本表头及实际结果条均按准确 version + cycleId 跳转版本总览，返回恢复草案与视口。

空周只在使用时登记，失败或取消不留版本。工作日历复用 `work-calendar.ts`，未知年度按普通周末。新增、排序、移除、撤销和提交入口保持；纯规划操作不创建主 Issue 或执行会话。

存量格式迁移必须覆盖正式材料、已提交提案和本机恢复草案，保留用户输入及来源冲突提示。可读的旧排期不能因为移除目标关联或开工冻结而失效；确有损坏文件则保留原文并提示核对，不能静默清空。
