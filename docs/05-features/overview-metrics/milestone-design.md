# 项目里程碑：材料与提交设计

> 给实现、计划助手接口维护与检视者读取。本文管里程碑的数据源、编辑状态、提交事务和版本入口；用户行为见 [spec](spec.md)，指标实现仍在 [design](design.md)。协议或代码责任变化时更新；不定义版本总览的 SDLC 采集协议，不收录交付流水。

本文描述自由日期里程碑的材料与事务；运行验证边界见 [STATUS](STATUS.md)。实际只读正式计划和目标验收，不写回规划。

## 材料分工与存量处理

版本以 version + cycleId 标识。`.bw/milestones.json` 使用 schema_version=4，可选 versionPlans 保存预期版本日期；`.bw/planning/<version>/data.json.timeWindow` 保存正式采用日期，均为包含两端的 ISO 日期。里程碑重排不覆盖已有计划；新版本才登记最小空计划。验收按固定 planRef 读历史。

节点按稳定 id 保存 outcome 和 date；仅有月份精度的成果保留 month，人工补日期后替换。特性保存 id、title、可空 owner 与 deliveries；每段为稳定 id、Build/Maintain 和可选 timeWindow，不含版本引用。时间为北京时间民用时间 `YYYY-MM-DDTHH:mm`，结束边界不包含。新安排默认值与拖动规则见 [日期编排](spec.md#日期编排与默认值)。版本窗口只按天修改、不得重叠；阶段按半天调整，Build 碰撞后续维护时保持维护时长顺延。预览保留段的 DOM 顺序，手势结束才按日期整理，避免自由换序中断指针捕获。

编辑以 draft.versions 维护版本窗口，draft.material 不重复保存 versionPlans，提交时统一写回。读取 schema 2/3 时，保留节点、特性及段的身份与名称，已记录的前五阶段按外边界归为 Build，维护归为 Maintain；空阶段不造日期。特性旧月份、版本绑定和目标槽位在迁移后移除，当前正本只保存新格式。没有 versionPlans 时借当前可读版本窗口展示，正常提交才补存，不能称为原始预期日期。正式、提案和恢复草案走同一迁移；恢复允许字段尚未填完。

版本总览只在固定计划明确纳入且特性唯一匹配时，将自由日期与本版正式窗口求交，分 Build/Maintain 汇总规划跨度；不把完整跨版段重复计入每版，不推造五阶段实际工时。已开工版本可改预期排期，但不通过此入口删除真实版本或改名已建立的执行身份。

## 最小实际投影

1. 从正式版本计划中读 tasks 指向的主 Issue，精确“特性”标签且标题包含完整去首尾空白的里程碑特性名；无候选/多个候选不猜。包含匹配兼容既有 `【版本|目标】` 前缀；不用目标标题作为键。
2. 得到唯一完整 `provider/repository/number` 后，以该主单查询所有正式纳入版本，不依赖里程碑排期段列表。每版主单对应一个 goalId；目标下可有多条同特性执行 Issue，不重复计数。旧材料有多特性目标时保留规划，不制作额外兼容绑定界面。
3. 核对验收归档 PR/MR 已合入、版本身份及固定 planRef，再取人工目标 outcome。未判定/未合入/失败不生成确认结果。历史结果只来自其固定计划，不能用当前草案的 tasks 改写对应。
4. 按正式版本历史顺序计算是否存在前版 met：没有则本版开发，有则 Maintain。本版首次 met 不改变本版类型，只影响后版；后续 not-met 不清除这个事实。首次交付映射已上线/未上线，后续映射维护完成/维护未完成。重排里程碑时间不能改这个顺序。
5. 实际绘制使用各版正式窗口与目标结果，不用 SDLC 分段，不称为特性实测工期；找不到日期不补造时长。读取复用既有 `useVersionOverviewMaterials` 与原生任务缓存，里程碑独立建立目标结果投影，不依赖 SDLC 证据采集；两屏共用特性名称匹配及规划读取，版本总览未匹配时保持原默认行为，不改其界面、SDLC 算法或开关，也不新建采集服务。

这些结论现算，不新增特性结果存储、首次可用确认或版本延期状态。人决定纳入后版，计划助手维护规范关联；详见 [计划配合](../version-planning/spec.md#计划助手与里程碑衔接)。

## 正式、已提交与未提交

正式材料固定读取主干基线提交。bw/project 仅提供已提交提案，不能覆盖主干正式投影。按文件内容构造修订，不能以 PR 状态代替实际材料。

应用视图会话保存未提交草案、最近提交基线与视口；从版本页返回恢复原状态。恢复记录通过本机薄 IPC 写入当前客户端 profile 的 `workbench/milestone-drafts/<scope哈希>.json`，以项目、仓库、执行宿主、runtime owner 和工作树隔离，不走远端材料路由。复用原生耐久写入：临时文件刷盘后原子替换；异步保存不阻塞输入，只有最新快照得到落盘确认才算可恢复，不再用独立一行提示正常保存。强退时尚在保存的输入不作已保存承诺。

同 scope 的读取、修订校验和写入串行；客户端一次只有一个在途保存，后续输入合并为最新快照，旧响应不覆盖新输入。放弃或提交草案也写入新修订，避免陈旧窗口复活旧输入；保留视口与筛选偏好。坏文件、读写失败或其他窗口修订冲突保留输入并明确报告，不静默覆盖。恢复允许名称/负责人尚未填完；重启先从 Git 读取最新材料，基线一致才续编，否则保留草案并阻止覆盖。它不是正式数据源，也不跨机器同步；实际提交仍经过同一 .bw 事务。提交成功/全量放弃后恢复内容中的草案与基线一致；撤销栈不跨重启。提交期间各页面共用写入状态，迟到响应不覆盖另一份编辑。浏览器客户端尚不支持该本机文件恢复，编辑时明确提示，不能假报已保存。

编辑会话在内存中维护撤销/重做快照；一次字段编辑及其失焦整理合为一步，节点日期、排期拖动、追加/删除维护及特性移除独立成步。版本名清空仅在 Enter/失焦提交编辑时判断撤回：以 cycleId 核对正式/提案快照均无该版本，才移除草案版本；按键中间态和 Escape 不移除。生产沿用此判据；原型按相同约束演示，已提交版本仍受服务端不可删除约束。历史不持久化，不回退 Git；相同基线的刷新/返回保留历史，已确认的新提交清空历史。“放弃本次修改”恢复最近一次提交后的基线；第一次提交前恢复正式基线。外部修订变化后旧草案不能静默提交，须核对；界面保留冲突输入。待合入可继续修改并更新同一 PR/MR；顶栏同一个入口在提交评审、更新评审、查看评审与更新正式安排间切换，不另放评审链接行。推送或创建评审失败可重试已经落盘的提交；读取失败保留异常提醒，不能当作没有评审。

## 写入事务与执行宿主

复用 Orca 原生项目/宿主/工作树解析、bw/project 创建登记、Git runner、现有 GitHub/CodeHub 评审入口。RPC 只接收受信任 scope，不接收任意文件根。当前文件事务支持所属本机/配对 runtime；SSH 执行适配仍未接入，明确返回错误，不把 SSH 路径交本机文件 API。

同项目名片与里程碑提交共用串行队列；多进程通过与材料服务一致的文件锁协作：

1. 核对 bw/project 登记、实际分支、干净工作副本、调用方读到的正式内容修订及分支 HEAD。
2. 只自动快进；分叉保持原样交原生会话合并，不 reset 或强推。
3. 校验所有材料、准确身份和排期冲突；已有计划包括日期在内的全部字段保持，不通过此入口删除已有版本；预期日期只写 versionPlans。
4. 获取变更文件锁，再重查权限、基线、HEAD、分支及所有源文件字节；全部核对后才写入。路径拒绝符号链接和非普通文件。
5. 耐久替换文件、提交指定路径，文件锁持续到提交结束。失败保留工作副本供核对，不自动回滚用户输入。
6. 非强制推送，复用开放评审或创建新 PR/MR。提交、推送、创建评审是不同结果；不得把失败当正式安排或人工验收。

多文件写入与 Git 提交不是跨系统原子事务；进程中断或工具失败可能留下未提交文件，下一次入口检测脏树并停止覆盖。此时用原生会话核对后继续，不静默补写。

## 界面及版本衔接

日期旗帜与特性行共用连续日轴和同一视口；操作见 [关键节点与操作反馈](spec.md#关键节点与操作反馈)。默认计划；实际在原位置切换，版本头对照规划与正式采用日期，结果条按正式窗口并明确版本名；具体呈现见 spec。特性左侧编辑名称和选填负责人，扳手追加 Maintain，× 删除整行。独立时间段可自由拖动，维护段可单独删除；不改变正式版本纳入。旧版本同样可重排；版本表头及实际结果条均按准确 version + cycleId 跳转版本总览，返回恢复草案与视口。

空周只在使用时登记，失败或取消不留版本。正式界面和原型共用 `work-calendar.ts`。预置文件 `work-calendar-2026.json` 已按[国务院办公厅年度安排](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html)和月末周六规则列出全部「班／休」日期，显示时直接查表。特性按末段结束日期倒序，编辑时固定行序，新行置顶；纯规划操作不创建主 Issue 或执行会话。

连续日轴只渲染视口附近约一年半的日期，靠近两端重新定位渲染窗口并保留视图与手势位移。首次从今天前十天开始，此后恢复日期、像素偏移和筛选；切月不清空。未知日期保留明确占位，损坏来源保留原文件并报错，不能静默清空。
