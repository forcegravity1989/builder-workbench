## 月度规划草案

### 总览与规划入口

讨论和导航以项目自己的版本为单位。月份只作排期时间轴，月度/周是节奏参考；不强制 C/B 命名、按月或按周讨论，也不从日期推导版本归属。本轮保留现有侧栏，不增加 C→B 层级或独立月度总览。示例大版本按用户确认先用 `v1.0.0`，后续小版本号只示范项目风格，不定义生产版本规则。同名显示值不足以承担真实身份，身份与关系载体仍待共同协调。

项目总里程碑的入口就在项目总览。撤去原“版本计划与验收”大区块，把空间交给里程碑；项目背景、北极星与最新记分牌保留。#440 不重新设计同事已落地的指标。原型中 4DX 文字与记分牌沿最新主干，旧“业务指标/项目指标”原型不再挂进新页面。

日常总览显示跨月连续泳道。点“规划里程碑”进入**只针对里程碑的左右工作区**：左侧直接编辑月度取舍与安排，右侧为原生工作模型会话的目标形态；可拖动或键盘调整分隔。返回项目总览仍看正式快照，草案保留，重新进入可续编。窄屏可上下排列以保留操作。

#411 当前指标维护是同一工作区上方原生会话、下方记分牌；里程碑复用其“业务板面 + 原生会话”的能力边界，因板面较宽暂采用左右布局。原型右侧只标“原型注释: Orca 原生会话屏”，列出拟复用固定分支 `bw/project` 和“配套 Skill：名称待确认”；没有自绘聊天输入、固定回复或建议模式下拉，不代表原生会话已接入。生产接入将先核对已有工作区与 `bw/project` 的扩展点。

空态只保留“还没有月度里程碑”；空态和已有安排的入口均叫“规划里程碑”。删除教学式副标题、流程长文案及独立五步旅程卡；旅程留在本文，不混进待落地 UI。小型演示说明和辅助控件统一以 **`原型注释:`** 开头，集中在顶部及右上角设计依据，不能靠大量说明补足界面易用性。

正式/草案不是两个独立排期模型；同一泳道组件消费对应快照。场景切换清除建议、评审中间态和弹窗，不自动采纳或写正式材料。

### 连续泳道与版本事实

按大需求分行，优先级、主导人、整体截止可见；横向是连续月份与版本，按数据提供的范围绘制，不硬编码产品周期。固定四个周范围仅是 11 月样本，不代表每月必须四个版本。今天定位、月份定位、横向拖动、滚动条与键盘滚动均可用；在泳道内滚动，不让整个页面横向溢出。需求名常驻左侧；当月需求在前，历史计划在后。

10 月计划只能放在所属月的历史区域，并写“月内日期未登记”。这是既有计划投影，不把 v0.7 G1—G4 换成 v1.0.0—v1.1.1。点历史对象看原始目标与交付说明；未记录字段保持未知，不按时间推断已完成。

版本条同时表达**月度意图**（先行 MVP / 修理完善）与**该版本材料读回状态**，两个语义不互相替代：

| 读取事实               | 泳道表达   | 进入版本后的内容                                           |
| ---------------------- | ---------- | ---------------------------------------------------------- |
| 读取成功，尚无版本计划 | 未开始计划 | 保留月度安排；具体范围、任务和验收尚无，不显示虚构完成率   |
| 已有确认计划与执行事实 | 执行中     | 显示当前计划及有来源的版本任务事实；不将任务数当大需求进度 |
| 已有人工正式验收记录   | 本版已验收 | 可看本版结论；不能推出整项跨版需求已经完成                 |
| 读取失败               | 状态未知   | 保留月度安排，说明失败可重试；不当成零任务或未开始计划     |

当前样本 v1.0.0 已有人工验收、v1.0.1 执行中、v1.1.0 未开始计划、v1.1.1 读取失败。全部为模拟状态。点击条或版本标题进入对应版本总览；缺计划仍可进入该版上下文，不预先创建版本计划。原型先显示 #334 衔接预览，并链接当前版本工作区原型；不冒称两侧已经联调。

### 人直接编辑与原生模型会话

人可直接勾选纳入/暂缓，修改名称、优先级、主导人、先行与后续版本、截止及取舍理由，无需先问模型。表单保存立即更新草案与泳道；取消不改变。暂缓保留候选，未纳入不算承诺。月度不以完整高保真/规格为纳入条件。

模型帮助汇总项目与候选、比较取舍/并行、提出 MVP 到后续完善的安排、核对日历冲突。建议先显示受影响对象、理由和前后差异；人采纳才更新草案。直接修改草案后，尚未采纳的模型建议须重新核对，不能覆盖新修改；草案变动使旧评审失效。模型不自行决定容量、完成、合入或正式承诺。

本轮原型保留直接编辑与评审状态链，模型参与只以 Orca 原生会话占位表达；建议差异、采纳和会话中的日历核对属于目标行为，不能用原型证明已实现。规划 Skill 的候选名 `milestone-planning` 尚未获确认，未创建或分发；`project-handbook` 仅用于项目开发手册，不能代用。

原生复用候选为工作区壳、[plan-send-menu](../../../src/renderer/src/workbench/plan-send-menu.tsx)、[AnnotationPanel](../../../src/renderer/src/workbench/annotations/AnnotationPanel.tsx)与其 `ReviewNotesSendMenuContent / openAgentSendPopoverTargetMode` 链。生产会话、权限、材料回写须在现有能力基础上接入，不从浏览器模拟生成新的执行协议。

### BW 预置工作日历

华为工作日历是正常月历，额外标出每月的周六加班安排。**由 BW 提前对接和预置，用户无需上传、导入或解析日历。** UI 用周一至周日的正常月格，休息日与加班周六可辨；公共“工作日历”入口改为约 300px 的就近小浮层，支持查看 10/11 月，点击外部或 Escape 关闭；不再用大面积居中弹窗。截止编辑暂沿用原生日期输入，查看器与泳道定位、截止选择的进一步联动待确认，不能让用户承担集成配置。

当前没有经核验的真实样本，10/17、11/14 的加班标记仅说明样式，非真实华为安排；集中用一条“原型注释:”说明边界。删除旧文本/CSV/文件导入和解析路径。正式产品应可核对预置来源、覆盖日期和新鲜度；加载失败或超出覆盖范围仍表达未知，不能用普通周末规则冒充已取得华为加班安排。

日历参与截止检查和讨论，不自动移动承诺，也不因为加班标记就推定团队有额外容量。每月人数、2–3 项大需求、约两周一项仅为讨论参考，均不硬编码。

### 与 #334 的共同交互目标

从项目总览进入版本后，定位并展开关联需求，并能返回实际来源；来源为总览时恢复原版本/规划视图、需求及视口，来源为规划工作区时返回该草案，不覆盖未提交内容。版本总览的“关联版本”展示同一需求在各版承担的范围，可继续进入相应版本定位。这里只同步已确认的交互目标，真实联动与共享字段未定，不按 G1/G2、标题或日期猜对应关系，也不修改 #334 页面。

整体意图、跨版安排和本版增量分开；使用反馈、新需求、bug 统一为 Issue，再由版本计划关联，未纳入不算承诺。实施 Plan 属于开发阶段；intent、spec、原型设计各自评审，工作可以并行或回退。本版验收不推出跨版需求完成，会话结束、合入、用户可用、Issue 关闭、目标达成分别取证。#334 的布局、生产力区域与三时期设计由该窗口负责。

### 草案如何进入正式总览

建议复用 `bw/project → PR/MR 人审 → 主干 → 更新代码重读总览`，不另造传统立项审批角色。正式总览读已合入主干的材料；草案编辑与模型采纳不直接覆盖正式安排。当前 `bw/project` 已有项目名片能力，里程碑材料路径、事务及双机并发仍待协调，**本稿不定义持久化协议**。

原型可核对、提交评审、等待人工合入、待更新并更新正式快照；“模拟人工已合入”是单独标注的原型辅助控件，正式产品合入在人已有的 PR/MR 流程里做。未创建真实 PR/MR；任何编辑都要求重新核对。正式与草案快照分开，返回和重新进入不能丢掉未提交草案。

### 旅程与验收

旅程在规格中审阅，页面不放演示旅程组件：

1. 月度选择：在总览进入里程碑规划，直接编辑取舍，或连续 1–3 天与模型讨论。
2. 先行版本交付 MVP：从泳道进入先行版本，对齐必要规格/高保真，接开发、测试，形成可试用交付。
3. 部分用户试用：真实使用产生反馈；不是第二次正式验收，也不自动判整项需求完成。
4. 后续版本修理完善：沿同一需求进入后续版，根据试用反馈收敛约定范围；前版承诺和验收保持可追溯。
5. 后续 Issue 持续改善：完成后新 bug、优化与衍生小需求继续进入现有 Issue workflow，关闭与完成由人确认。

每个版本只做一次正式验收；周反馈可跨周，不等于固定每周发布。不增加效果指标作为所有里程碑共同验收门槛。

## 入口与用户旅程

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

指标在总览的记分牌里呈现，替代原业务／项目两区；项目研发统计（提交、合入 PR、开放 Issue）不再在总览展示。场景即指标目录里的特性，未指定特性的指标归“主要”页签，不等于项目研发指标。

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/system-prompt/references/metrics.md)。北极星可缺席，占位不成为指标。可选的 [[feature]] 声明场景名称（name）和价值说明（value），决定页签顺序；场景与说明随目录编辑，产品不写死。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义或场景重名提示修正，不随意关联。

“配置指标”每次在独立固定的 bw/metrics-refresh 分支和工作树中新建 Orca 原生会话，并离开总览进入该会话；已有同分支工作树和未完成改动保留，不续接上次会话，不另建 BW 配置面板或登记指标自动化。维护树干净且只是落后于当前基线时，读取目录会把它快进到基线，使会话改的就是记分牌上这份目录。记分牌读基线；维护分支已从该基线提交了新目录时，回到总览重读那次提交。维护工作区里的配置文件直接显示在记分牌上，和已提交内容不同时标为配置草稿；打开这个工作区时，会话在上、记分牌在下，中间的分隔可以拖动高度，文件保存后隔几秒跟上。记分牌上的批注直接发给这个指标配置会话，不再选择会话。读数仍按已提交修订采集，草稿不写入正式读数。工作树定位、创建、目录、登记和宿主路由沿用 Orca，不另设目录规则或删除重建。接入已有指标工作树时保留该项目此前接入的其他工作树；切换计划、验收后指标工作树仍可从侧栏进入。加载项目约定、通用 SYSTEM 与 metrics-refresh Skill；提示携带当前定义、来源问题和返回总览上下文，不注入 week-planning。返回时恢复原总览的版本与指标筛选。

定义和脚本按项目规则评审合入。目录从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取最新已合入修订，不在后台 fetch，不把固定计划/验收树的旧 HEAD 当最新目录，也不向这些材料树合并指标草稿。读取失败保留原目录及其来源并显示错误，不能假报最新。配置树草稿可试采，须标明草稿，未合入前不成为三屏正式目录；主检出的新鲜度由总览「更新代码」按钮负责。

### 采集与可信度

仅 collect.kind=script 且 retro=true 的有效业务定义进入可用目录，脚本按 day/week 返回真实历史 points。retro=false、手填或仅返回当前 value 的输出均不作为可用采集；页面提示配置历史来源，不补造曲线。源数据和必要的历史存储由用户项目或外部服务负责。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

首次加载读取目录及已有采集缓存，并准备最近五周、十四天所需数据。业务日／周口径分别采集，不能用日均值简单合成周均值；记分牌先回显周窗口，日窗口随后准备，准备期间不清空已得数据、不重复联网或跑脚本。仅 not-collected 的缓存缺口自动采集一次，失败不自动重试。缓存缺口及正在采集不计为读取失败，等待时显示“正在读取”；采集结束后才展示本次实际失败，无数据保持未知。之后离开再返回总览仅复用本次应用运行的快照；用户点「更新代码」（快进主检出并重读目录）或对应指标刷新按钮（重新采集）才更新。业务手动刷新维持阻塞遮罩，完成或失败均解除；来源或采集失败保留旧读数及原采集时间，明确提示失败。显示窗口固定于采集时刻，跨日／周不把缓存旧数标成今日或本周。

不引入每日采集自动化、bw/ledger 或每日 readings 写回。每次新采集解析主干基线目录，并在本次执行期间固定同一份定义、脚本及相关依赖修订；项目身份、窗口与来源随结果保存。旧计划 baseline 和归档证据保持只读，不能被刷新覆盖，也不用于阻止新采集。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

记分牌按场景分页签：先列 [[feature]] 声明的场景，再列只在指标上出现的特性，未指定特性的指标归“主要”。每签展示一个结果（计划写了目标值的滞后指标优先，否则该场景第一条）和一个引领（leads 指向这个结果的引领，计划写了目标值的优先；没有则取未关联任何结果的引领，不借用关联其他结果的引领；仍然没有引领时，第二格展示该场景的下一个结果，并标成结果），其余指标列名提示，不被隐藏；缺结果或引领时说明可用「配置指标」补配。每个指标显示最近读数（带单位）、最近五周窗口的走势柱和口径；失败与陈旧证据保持未知并注明原因与原采集时间（有完成线时也不被输赢文案替代），无读数的走势柱与 0 值可区分，字符串读数只作文本。leads 不等于已证明因果。

聚焦由版本区所选版本的计划推出：计划目标里给某个场景的任一指标写了非空目标值，该场景即本版聚焦，排在“聚焦”组，其余在“日常”组；完成线依次取所展示结果、所展示引领、其余指标的目标值。聚焦场景顶部一行写明「指标　从基线到完成线　截至该版验收」，基线取计划保存的 baseline，没有就只写完成线；日常场景写“日常盯防，不在本版聚焦”。输赢只由最近数值读数对比带比较方向的完成线（≥、≤、>、<、=）得出：显示“已达完成线”或“未达完成线”；完成线是纯数字、方向缺失、单位与指标不一致，或没有数值读数时显示“看不出输赢”，不装绿；完成线比较不是验收结论，目标达成仍由人确认。聚焦页签只在已达或未达完成线时标出输赢；看不出输赢时页签不重复这句话。记分牌底部常驻说明输赢怎么算，以及每周短会怎么用这张记分牌（报上周承诺 → 看记分牌 → 每人定下周一两件，承诺落成普通 Issue）；产品不另存承诺记录。

计划只写版本目标，不改项目长期目标；验收可从最新目录选择指标补充实测，实际值由脚本提供。旧 baseline 保留，不能因 definitionHash 或 configurationCommit 与旧计划不同而阻止采集。证据详情展示来源、采集时间、配置提交与采集脚本修订，定义指纹保存在材料中，供人追溯核对；界面不提供专门的定义或单位变化对比，不自动计算跨口径改善幅度或判断达成。新增验收指标不改原计划承诺。

总览从项目主干基线（主检出）的现有 `.bw/planning/<版本>/` 目录列出版本，每个版本只显示当前一份计划和验收；不把 Git 旧快照列成重复数据或迁移告警，不复活已经删除的版本。该版本当前文件是旧格式时才提示迁移，文件已迁移且有效时正常显示。有效的在研工作材料可作为当前草稿显示；落后的固定工作区不能覆盖主线现行数据。计划与验收通过保存的 planRef 核对；计划已更新而验收仍对应较早修订时保留当前计划，右栏提示尚无对应验收，不改读旧计划冒充当前数据。两栏固定等高、各自滚动，切换版本回到正文顶部。读取失败与尚无记录分别表达，并可重试。总览回看不改变计划/验收流程选版。

### 布局与动作

- 顶部沿用既有高保真的项目名片／北极星双卡结构：左侧项目名称与字段，右侧指标名称、当前值、目标和状态。缩小卡片纵向内边距与字段行距，保留字号和完整字段；高度随内容增长，不用固定高度裁切长文本。北极星不重复放刷新、配置按钮，不以“有读数”代称项目健康；缺失字段如实表达。
- 版本区不设“展开纪要”“去计划”“去验收”按钮；全文直接显示，原文来源随正文。版本目录首次进入总览读取，切换版本复用固定修订内容；页头「更新代码」快进主检出并重读现行目录，返回总览重读有效的当前草稿。
- 内容区第一行是高效执行四原则（FranklinCovey 4DX）的一句话：聚焦至关重要目标 · 贯彻引领指标 · 设立振奋人心的记分牌 · 保持相互担责的节奏。纯排版，不是健康信号。
- 记分牌位于名片／北极星之下、版本区之上：标题行是记分牌，旁边是「批注」「配置指标」和一个刷新图标。「批注」打开与计划/验收相同的板面批注：点击本场景的目标行或指标记下讨论，编号角标与面板一致，可复制或发送给会话；批注只留在当次打开的总览里，重启不保留，也不改指标目录和完成线。走势固定为周窗口。刷新同时更新北极星，配置入口只保留一处。没有任何场景时提示用「配置指标」新建会话配置。
- 页面不放迁移过程、协议字段或“为什么尚未实现”的长说明。草稿、未采集、失败和数据日期等影响判断的信息保持可见，具体原因按需展开。

## 布局约束

1280 与 1920 两种窗口宽度下内容铺满 Orca 内容槽，不横向溢出。记分牌结果与引领左右并排，更窄时上下排列；场景页签过多时横向滚动。计划/验收全文默认左右对照，各栏正文高度 16rem、超长独立纵向滚动，标题常驻；更窄设备可转上下排列。页面本身允许纵向滚动。原型读数不是实时采集，真实 Electron 与脚本证据在实施后补齐。

实现与真实数据、Electron 验证边界见 [STATUS](STATUS.md)。
