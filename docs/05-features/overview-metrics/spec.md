## 入口与用户旅程

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

指标仍在总览下，保持 main 的业务／项目两区。业务“主要”表示未指定特性归属，不等于项目研发指标。

| 阶段 | 用户动作                                              | 系统结果                                                                     |
| ---- | ----------------------------------------------------- | ---------------------------------------------------------------------------- |
| 理解 | 看业务主要/特性页签、引领与滞后关系，以及项目研发趋势 | 展示来源、窗口和缺口，不补演示数字                                           |
| 回看 | 切换版本及纪要轮次                                    | 左右对照对应计划与验收全文，草稿可辨，缺记录留空；两栏各自滚动                 |
| 配置 | 点击“设置指标”                                        | 在独立原生项目任务确定口径、采集脚本及可回溯性；返回保持版本、轮次和指标筛选 |
| 观察 | 刷新当前值或选择日/周历史                             | 直接执行登记脚本/原生统计，无需先开模型                                      |
| 使用 | 计划选指标设目标，验收刷新事实                        | 三屏同源，人的判断与数值分别保存                                             |

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/system-prompt/references/metrics.md)。北极星可缺席，占位不成为指标。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义提示修正，不随意关联。

“设置指标”使用独立固定的指标维护分支和工作树，打开原生项目会话屏；不加 BW 右侧指标配置面板，不进入周计划或验收固定分支，也不登记指标自动化。分支定位、工作树创建、目录、登记和宿主路由沿用 Orca，与计划、验收一致；复用已有同分支工作树，不另设目录规则或删除重建。固定维护工作树不等于永久复用一个会话：返回未完成的配置继续原任务，用户显式新开配置时创建新原生会话并复用该树，保留已有未完成改动。项目、宿主和原生 taskId 是身份，不按标题猜。加载项目约定、通用 SYSTEM 与 metrics-refresh Skill；提示携带当前定义、来源问题和返回总览上下文，不注入 week-planning。返回时恢复原总览的版本、轮次与指标筛选。

资产须按项目规则保存、评审并进入总览指定配置基线。配置中的草稿定义可预览和试采，但不得被其他版本自动当成已采用目录。返回总览后重新读取明确的配置修订，未合入时仍标草案，不假报就绪。

### 采集与可信度

仅 collect.kind=script 的有效定义进入可用目录。优先 retro=true 按窗口查历史；retro=false 只返回当前时点值及时间，不能用当前值填过去的周、按窗口重标，或证明一个历史区间目标。旧 manual 定义提示“需配置采集”，无录数入口，不自动把旧人工记录转成实测或删除历史原件。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

不迁入每日采集自动化、bw/ledger 或每日 readings 写回。可重算历史直接查来源；仅当前读数允许会话内缓存及归档证据，不累计伪历史。计划/验收固定所采用的读数、定义指纹与时间，旧记录保持历史身份。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

业务按“主要／特性”展示滞后与对应引领；图例只占一行，超出可用宽度时提供前后滚动，长名称省略但悬停可读全名，点击切换系列显隐。悬浮日期时集中显示该时点可见系列的读数；键盘左右键切换日期，Escape 收起读数。长期目标、类型和定义收进“指标详情”，不在图上方逐条排成常驻表格。采用 [ECharts 可滚动图例](https://echarts.apache.org/handbook/zh/concepts/legend/)与[轴触发提示](https://echarts.apache.org/handbook/zh/concepts/axis/)的交互模式，不限定图表库。leads 不等于已证明因果。同单位可共轴，不同单位用独立刻度或对齐小图。日/周可切；无历史点留空，当前点明确标时刻，字符串不画数值曲线。

项目指标保留三组日／周折线图，标题分别为“提交”“合入 PR”“开放 Issue”。提交按选定分支可达历史和提交时间；合入 PR 按真实 mergedAt，CodeHub 对应合入 MR。远端可读取合入时间时，应完成接口接线并绘制趋势，不把现有映射缺字段当成产品不支持。有完整事件才能重建含重开的开放 Issue 历史；仅当前快照时保留图表并只显示实际采集点，缺点留空，不从 state/closedAt 推造。分页截断、权限失败、离线只影响对应系列；短状态在图内展示，详细原因与口径进入详情。提交数不等于效率评分。两个区分别刷新、切粒度；本期注明截至采集时刻。

计划只写版本目标，不改项目长期目标；验收实际值只读。定义变化要提示原口径及可比较性。总览以版本页签和左右双栏直接呈现计划、验收全文；在研版本默认最新材料，标清“草稿”，历史轮次可在原处切换。两栏标题为“计划”“验收”，正文固定等高、各自纵向滚动，切换版本或轮次后回到正文顶部。验收存在时按其保存的计划引用读取对应修订，不能独立拼接两份“最新”材料；新计划没有对应验收时，右栏显示“暂无验收纪要”。读取失败与尚无记录分别表达。直接消费计划/验收材料，不另存可编辑副本。历史进展、提交证据可作为相关记录查看，不能替代验收。总览切换仅用于回看，不改计划/验收流程的选版。

### 布局与动作

- 顶部沿用既有高保真的项目名片／北极星双卡结构：左侧项目名称与字段，右侧指标名称、当前值、目标和状态。缩小卡片纵向内边距与字段行距，保留字号和完整字段；高度随内容增长，不用固定高度裁切长文本。北极星不重复放刷新、配置按钮，不以“有读数”代称项目健康；缺失字段如实表达。
- 版本区不设“展开纪要”“去计划”“去验收”按钮；全文直接显示，原文来源随正文。归档随进入总览、从工作区返回及版本切换读取，不常驻“刷新归档”按钮。
- 业务区显示“业务指标”、特性页签和紧凑图例，定义、读数及目标按需查看。每区一个刷新图标，带可访问名称与悬停提示；刷新和“设置指标”使用设计系统带边框、底色的次按钮。业务刷新同时更新北极星，设置入口只保留一处“设置指标”。
- 项目区显示三图及本周／今日／当前数量，一个日／周选择和一个刷新入口。单击系列名称查看口径；单条失败不清空其他图。
- 页面不放迁移过程、协议字段或“为什么尚未实现”的长说明。草稿、未采集、失败和数据日期等影响判断的信息保持可见，具体原因按需展开。

## 验收与衡量

| 标识 | 可观察结果                                                                                                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| M01  | 双卡项目上下文、业务/项目两区可读；版本/轮次可切，计划与验收按引用对应；草稿可辨、缺记录不替代、读取失败可重试，全文等高双栏独立滚动；不以 Issue 进度代替验收 |
| M02  | 特性/leads/显隐正确，歧义可见；多系列图例保持单行并可滚动，日期提示读数可达，详情可读；长期目标不被版本目标覆盖                                                                                           |
| M03  | 真脚本以 argv/cwd 运行，正常值、零、字符串及历史点按协议接收                                                                                      |
| M04  | 失败/坏输出/超时/缺测不造数，旧证据标陈旧并可重试                                                                                                 |
| M05  | 三组项目折线图保留，日/周窗口和时区正确；PR/MR 按真实合入时间采集并可独立复算，分页或权限问题不伪装 0；Issue 无历史时只画实际点                   |
| M06  | 三屏同定义/来源/能力，版本实测只读；仅当前值不能验历史目标，定义或执行脚本修订漂移可发现                                                          |
| M07  | 配置打开原生项目会话，加载 metrics-refresh；同次继续/显式新建可区分，返回恢复总览；无独立 BW 配置面板、固定周分支、手填实际值或每日登记链         |
| M08  | 按采集代码/依赖修订去重，常驻树旧脚本不代用、过期响应隔离；重启历史可重算，归档证据可读回，仅当前值不伪造历史                                     |
| M09  | 普通项目无需 BW 源码；缺脚本/权限可修复，配置草稿与已采用目录不混淆                                                                               |
| M10  | main 有效资产定向迁入，manual/占位留缺口；核对重开事件/分页/权限，不把 Rust 结果算 Electron 证据                                                  |

MJ01：普通项目 → 总览配置任务 → 确认口径并实现真实脚本 → 试采/评审采用 → 回总览看当前/历史 → 计划引用 → 验收刷新 → 归档证据 → 重启独立复算。MJ02 覆盖仅当前源、失败修复、真实零、定义变更和跨项目隔离。首用周记录采集/口径卡点及数据辅助决策的案例，先建立基线。

## 布局约束

1280 与 1920 两种窗口宽度下内容铺满 Orca 内容槽，不横向溢出。计划/验收全文默认左右对照，各栏正文高度 16rem、超长独立纵向滚动，标题常驻；更窄设备可转上下排列。页面本身允许纵向滚动，不为塞满首屏把图表压成细条。多系列图例横向滚动，不靠不断加高标题区容纳指标；长定义进入详情。原型快照不是实时采集，真实 Electron 与脚本证据在实施后补齐。

## 待确认

总览原型已获授权实施。配置指标是否继续上次任务与显式新建的交互另行核对；合入时间、完整历史分页与返回筛选属于实现待补，不因静态原型已有图表而标成已完成。
