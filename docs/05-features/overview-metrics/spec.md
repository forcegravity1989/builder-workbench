# 总览指标规格

> 给设计、实现和验收者读取；本文管可观察行为。价值见 [intent](intent.md)，接口见 [design](design.md)，证据见 [STATUS](STATUS.md)。行为变化时更新。
>
> 状态：记分牌替代业务／项目两区（2026-10-22 确认场景可编辑、聚焦与完成线来自所选版本计划）。2026-10-27 起牌上只留场景、读数和完成线，不再放四原则口号、价值说明、口径和输赢文案。业务指标仅支持日／周历史采集、每次配置新建会话、目录读主干基线（主检出）沿用；实施工作与证据见 STATUS。

原型是单文件可编辑源 [prototype.html](prototype.html)，场景页签和版本可点；读数与完成线为示意，刷新不执行真实采集，不证明能力已交付。三屏共用运行包里的旧总览屏（prototype/screen.jsx 等）只作历史参照，不再代表总览现行布局。来源、离线使用与历史附件边界见[版本计划规格](../version-planning/spec.md)。

## 入口与用户旅程

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

指标在总览的记分牌里呈现，替代原业务／项目两区；项目研发统计（提交、合入 PR、开放 Issue）不再在总览展示。场景即指标目录里的特性，未指定特性的指标归“主要”页签，不等于项目研发指标。

| 阶段 | 用户动作                                              | 系统结果                                                                               |
| ---- | ----------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 理解 | 看记分牌：场景页签、结果与引领、读数旁的完成线 | 展示读数和缺口，不补演示数字；没有完成线或读数时点保持灰色 |
| 回看 | 切换版本                                              | 每个版本显示当前计划与验收全文，草稿可辨，缺记录留空；两栏各自滚动                     |
| 配置 | 点击“配置指标”                                        | 在固定维护树中新建原生会话并进入该会话，确定口径、历史来源和采集脚本；返回保持总览筛选 |
| 观察 | 更新代码、刷新日/周历史                               | 读取主干基线定义并直接执行登记脚本，无需先开模型                            |
| 使用 | 计划选指标设目标，验收选择指标并刷新事实              | 新采集采用主干基线定义与脚本，旧计划基线保留，人的判断与数值分别保存                       |

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/system-prompt/references/metrics.md)。北极星可缺席，占位不成为指标。可选的 [[feature]] 声明场景名称（name）和价值说明（value），决定页签顺序；场景与说明随目录编辑，产品不写死。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义或场景重名提示修正，不随意关联。

“配置指标”每次在独立固定的 bw/metrics-refresh 分支和工作树中新建 Orca 原生会话，并离开总览进入该会话；已有同分支工作树和未完成改动保留，不续接上次会话，不另建 BW 配置面板或登记指标自动化。维护树干净且只是落后于当前基线时，读取目录会把它快进到基线，使会话改的就是记分牌上这份目录。记分牌读基线；维护分支已从该基线提交了新目录时，回到总览重读那次提交。维护工作区里的配置文件直接显示在记分牌上，和已提交内容不同时标为配置草稿；打开这个工作区时，会话在上、记分牌在下，中间的分隔可以拖动高度，文件保存后隔几秒跟上。记分牌上的批注直接发给这个指标配置会话，不再选择会话。读数仍按已提交修订采集，草稿不写入正式读数。工作树定位、创建、目录、登记和宿主路由沿用 Orca，不另设目录规则或删除重建。接入已有指标工作树时保留该项目此前接入的其他工作树；切换计划、验收后指标工作树仍可从侧栏进入。加载项目约定、通用 SYSTEM 与 metrics-refresh Skill；提示携带当前定义、来源问题和返回总览上下文，不注入 week-planning。返回时恢复原总览的版本与指标筛选。

定义和脚本按项目规则评审合入。目录从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取最新已合入修订，不在后台 fetch，不把固定计划/验收树的旧 HEAD 当最新目录，也不向这些材料树合并指标草稿。读取失败保留原目录及其来源并显示错误，不能假报最新。配置树草稿可试采，须标明草稿，未合入前不成为三屏正式目录；主检出的新鲜度由总览「更新代码」按钮负责。

### 采集与可信度

仅 collect.kind=script 且 retro=true 的有效业务定义进入可用目录，脚本按 day/week 返回真实历史 points。retro=false、手填或仅返回当前 value 的输出均不作为可用采集；页面提示配置历史来源，不补造曲线。源数据和必要的历史存储由用户项目或外部服务负责。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

首次加载读取目录及已有采集缓存，并准备最近五周、十四天所需数据。业务日／周口径分别采集，不能用日均值简单合成周均值；记分牌先回显周窗口，日窗口随后准备，准备期间不清空已得数据、不重复联网或跑脚本。仅 not-collected 的缓存缺口自动采集一次，失败不自动重试。缓存缺口及正在采集不计为读取失败，等待时显示“正在读取”；采集结束后才展示本次实际失败，无数据保持未知。之后离开再返回总览仅复用本次应用运行的快照；用户点「更新代码」（快进主检出并重读目录）或对应指标刷新按钮（重新采集）才更新。业务手动刷新维持阻塞遮罩，完成或失败均解除；来源或采集失败保留旧读数及原采集时间，明确提示失败。显示窗口固定于采集时刻，跨日／周不把缓存旧数标成今日或本周。

不引入每日采集自动化、bw/ledger 或每日 readings 写回。每次新采集解析主干基线目录，并在本次执行期间固定同一份定义、脚本及相关依赖修订；项目身份、窗口与来源随结果保存。旧计划 baseline 和归档证据保持只读，不能被刷新覆盖，也不用于阻止新采集。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

记分牌按场景分页签：先列 [[feature]] 声明的场景，再列只在指标上出现的特性，未指定特性的指标归“主要”。每签展示一个结果（计划写了目标值的滞后指标优先，否则该场景第一条）和一个引领（leads 指向这个结果的引领，计划写了目标值的优先；没有则取未关联任何结果的引领，不借用关联其他结果的引领；仍然没有引领时，第二格展示该场景的下一个结果，并标成结果）。其余指标不在牌上列出，缺结果或引领时该栏只留角色名。每个指标显示名称、最近读数（带单位）和最近五周窗口的走势柱；有完成线时，完成线原文贴在读数右侧。口径、采集时间和未知原因不写在牌上。失败与无读数都显示未知，无读数的走势柱与 0 值可区分，字符串读数只作文本。leads 不等于已证明因果。

聚焦由版本区所选版本的计划推出：计划目标里给某个场景的任一指标写了非空目标值，该场景即本版聚焦，页签排在前面，名字前有一个点；其余场景隔开一段，不写“聚焦”“日常”。完成线依次取所展示结果、所展示引领的目标值。输赢只由最近数值读数对比带比较方向的完成线（≥、≤、>、<、=）得出：达到时点和数字用成功色，未达到时用警告色；完成线是纯数字、方向缺失、单位与指标不一致，或没有数值读数时点和数字保持中性色，不装绿，也不写“已达完成线”“未达完成线”“看不出输赢”。完成线比较不是验收结论，目标达成仍由人确认。价值说明留在指标目录，不出现在牌上。产品不在记分牌上写每周短会用法，也不另存承诺记录。

计划只写版本目标，不改项目长期目标；验收可从最新目录选择指标补充实测，实际值由脚本提供。旧 baseline 保留，不能因 definitionHash 或 configurationCommit 与旧计划不同而阻止采集。证据详情展示来源、采集时间、配置提交与采集脚本修订，定义指纹保存在材料中，供人追溯核对；界面不提供专门的定义或单位变化对比，不自动计算跨口径改善幅度或判断达成。新增验收指标不改原计划承诺。

总览从项目主干基线（主检出）的现有 `.bw/planning/<版本>/` 目录列出版本，每个版本只显示当前一份计划和验收；不把 Git 旧快照列成重复数据或迁移告警，不复活已经删除的版本。该版本当前文件是旧格式时才提示迁移，文件已迁移且有效时正常显示。有效的在研工作材料可作为当前草稿显示；落后的固定工作区不能覆盖主线现行数据。计划与验收通过保存的 planRef 核对；计划已更新而验收仍对应较早修订时保留当前计划，右栏提示尚无对应验收，不改读旧计划冒充当前数据。两栏固定等高、各自滚动，切换版本回到正文顶部。读取失败与尚无记录分别表达，并可重试。总览回看不改变计划/验收流程选版。

### 布局与动作

- 顶部沿用既有高保真的项目名片／北极星双卡结构：左侧项目名称与字段，右侧指标名称、当前值、目标和状态。缩小卡片纵向内边距与字段行距，保留字号和完整字段；高度随内容增长，不用固定高度裁切长文本。北极星不重复放刷新、配置按钮，不以“有读数”代称项目健康；缺失字段如实表达。
- 版本区不设“展开纪要”“去计划”“去验收”按钮；全文直接显示，原文来源随正文。版本目录首次进入总览读取，切换版本复用固定修订内容；页头「更新代码」快进主检出并重读现行目录，返回总览重读有效的当前草稿。
- 记分牌位于名片／北极星之下、版本区之上：标题行是记分牌，配置草稿在标题旁标「草稿」，旁边是「批注」「配置指标」和一个刷新图标。「批注」打开与计划/验收相同的板面批注：点击指标记下讨论，编号角标与面板一致，可复制或直接发给指标配置会话；批注只留在当次打开的总览里，重启不保留，也不改指标目录和完成线。进入批注时按钮保持按下，牌上不另起说明。走势固定为周窗口。刷新同时更新北极星，配置入口只保留一处。没有任何场景时不另写配置步骤；指标目录未就绪时显示这一状态。
- 页面不放迁移过程、协议字段或解释性长说明。目录和版本读取失败仍在对应位置可见；记分牌上没有读数时只显示未知。

## 验收与衡量

| 标识 | 可观察结果                                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M01  | 双卡项目上下文、记分牌可读；版本可切，计划与验收按引用对应；草稿可辨、缺记录不替代、读取失败可重试，全文等高双栏独立滚动；不以 Issue 进度代替验收 |
| M02  | 场景页签按 [[feature]] 顺序；每签结果与引领配对正确；写了完成线的场景排在前面，完成线贴在读数旁，输赢只在完成线带方向且有数值读数时用颜色表示；长期目标不被版本目标覆盖 |
| M03  | 真脚本以 argv/cwd 按日/周查询历史；正常点值、零和字符串按协议接收，仅当前 value 或 retro=false 不作为可用采集                                            |
| M04  | 失败/坏输出/超时/缺测不造数，旧证据标陈旧并可重试                                                                                                        |
| M06  | 三屏从主干基线发现指标；验收可选新指标，新采集不被旧配置修订拦截；旧 baseline 保留，证据详情可核对来源、时间、配置与脚本修订，不自动判达成         |
| M07  | 每次“配置指标”在同一固定维护树中新建原生会话并进入该会话，加载 metrics-refresh，保留未完成改动，返回恢复总览；无额外 BW 配置面板或指标自动化             |
| M08  | 每次执行固定主干基线的定义/脚本/依赖修订并按其去重；旧脚本不代用、过期响应隔离；重启历史可重算，旧归档证据可读回                                         |
| M09  | 普通项目无需 BW 源码；读取最新目录不 merge 草稿工作树，不丢未完成材料；失败保留来源和错误，草稿试采不成为正式目录                                        |
| M10  | main 有效资产定向迁入，manual/占位留缺口；核对重开事件/分页/权限，不把 Rust 结果算 Electron 证据                                                         |

MJ01：普通项目 → 配置指标新会话 → 确认口径并实现历史脚本 → 试采/评审合入 → 回总览「更新代码」读目录并看日/周历史 → 计划引用 → 验收选择指标和刷新 → 归档证据 → 重启独立复算。MJ02 覆盖来源无历史能力、失败修复、真实零、定义/脚本更新、旧 baseline 留存和跨项目隔离。首用周记录采集/口径卡点及数据辅助决策的案例，先建立基线。

## 布局约束

1280 与 1920 两种窗口宽度下内容铺满 Orca 内容槽，不横向溢出。记分牌结果与引领左右并排，更窄时上下排列；场景页签过多时横向滚动。计划/验收全文默认左右对照，各栏正文高度 16rem、超长独立纵向滚动，标题常驻；更窄设备可转上下排列。页面本身允许纵向滚动。原型读数不是实时采集，真实 Electron 与脚本证据在实施后补齐。

实现与真实数据、Electron 验证边界见 [STATUS](STATUS.md)。
