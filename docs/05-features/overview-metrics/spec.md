## 月度规划草案

### 范围与入口

项目总里程碑在原总览的原“版本计划与验收”位置规划。用户已明确可撤去该大区块，把空间交给里程碑；项目背景与北极星保留，业务指标和项目指标本轮不调整，另有负责人讨论其后续方案。规划编辑留在里程碑区内，讨论按需打开，默认不占右侧栏。

正式总览读主干，草案拟复用 `bw/project` → PR/MR 人审 → 合入主干 → 更新总览。原型已提供“核对并提交评审 → 评审中 → 模拟人工合入 → 待更新 → 更新正式总览”的可点击状态链。实际 PR/MR 中的人工合入由单独的“原型注释:”控件模拟，不画成产品里的自动合入能力。当前 `bw/project` 仅有项目名片评审能力，里程碑材料路径、事务及并发协议仍待主会话确认；未接 Git 或远端 API。

右上角“原型场景”提供三种评审形态：尚无月度版本（空态，可制定首个月度规划）、制定中（选择/编辑/泳道/讨论）、已制定·多月（10/11/12 月切换，10 月为真实 BW 计划投影）。三态只切换里程碑及相关版本入口；指标数据与状态独立保留。场景切换会清除旧建议、评审步骤与弹窗，避免把前一场景的模拟合入状态带入另一场景。

所有设计说明、模拟边界及评审辅助控件统一以 **`原型注释:`** 开头，与正式产品文案区分。当前指标仍使用原有原型历史快照，来源日期保持原样；不把它们说成当前实时采集。原型不调整指标定义、业务分组、趋势、粒度、图例、明细和配置入口。

每行是一项大需求，展示选择与否、优先级、主导 Builder、目标 B 版本、截止时间及取舍理由；泳道按大需求分行，先行 MVP 和后续完善分别进入相应 B 版本。月度需求并不以高保真或完整规格齐备为纳入条件。每月 2–3 项、约两周一项只提供讨论背景，不作为数量/时长限制；原型三项、四版与单月范围只是有限样本。

### 完整评审旅程

| 步骤         | 人的操作                                                    | 可见响应与留下的材料                                                                                   |
| ------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 月度选择     | 勾选/暂不安排候选，编辑优先级、主导人、目标版本、截止与理由 | 选择和泳道同步；暂缓需求仍可见。编辑不代表正式承诺或完成                                               |
| 连续讨论     | 选择需求，补充取舍意见，预览模型建议                        | 先显示理由与前后安排；可继续讨论或采纳，不在生成时改规划。演示提供 MVP、减少并行、日历冲突三种脚本场景 |
| 核对日历     | 提供工作日历材料，核对解析日期与来源，再应用                | 工作/休息/未知可辨；冲突提示与后续建议可见，截止不自动移动                                             |
| 收敛选择     | 核对所选需求、优先级、版本、截止，提交规划评审              | 草案进入评审中；合入由人决定，合入后仍须更新代码才能展示为正式安排。原型辅助控件模拟远端状态           |
| 先行 B 版本  | 点泳道先行 MVP 或旅程第 2 步进入版本总览                    | 带入同一个需求与本版可用增量；设计对齐接开发/测试，产出可运行、可试用 MVP                              |
| 部分用户试用 | 旅程第 3 步查看试用反馈                                     | 试用范围与反馈是独立信息，不冒充第二次正式验收，不判大需求完成                                         |
| 后续完善     | 点后续 B 版本查看修理完善安排                               | 本版承担反馈修理和约定范围，前版承诺、验收证据不覆盖                                                   |
| 持续改善     | 旅程第 5 步进入 Issue workflow 语境                         | 完成后的 bug、优化和衍生需求沿既有 Issue 处理；会话结束不等于完成                                      |
| 内部审阅     | 在 Orca 原生浏览器批注界面提出意见；右上角查看设计依据      | 原型不自建批注系统；是否通过设计由人明确确认                                                           |

月度讨论可以连续 1–3 天；正式产品应恢复同一份安排、来源与已采纳决定，原生会话保留讨论过程。不能靠聊天摘要替代当前材料。此原型仅验证本浏览器恢复，不证明跨机恢复。

### 模型协作与原生复用

模型帮助汇总现有需求和项目情况、比较优先级/并行、提出先行 MVP 与后续完善安排、核对日历冲突，再把建议的影响交给人。月度讨论不提前强迫完成细节设计，不能由模型把容量估计伪装为团队事实。

生产入口优先复用已有 [plan-send-menu](../../../src/renderer/src/workbench/plan-send-menu.tsx) 的原生会话选择/发送能力及 [AnnotationPanel](../../../src/renderer/src/workbench/annotations/AnnotationPanel.tsx) 的批注交接；该链调用 `ReviewNotesSendMenuContent` 与 `openAgentSendPopoverTargetMode`。本页右栏只是交互意图的浏览器表达，不新增聊天系统、agent 执行器或运行时绑定。月度材料归哪棵工作树、如何经已有材料事务回写，待主会话与 #334 统一后再实现。

本原型对自由文本只留作建议依据，**不做语义理解**；下拉选定的场景产生固定建议。采纳时显示受影响需求、版本与日期，页面顶部持续标“演示”。改当前需求、安排或日历后应废弃旧建议，避免误采纳过期影响。

### 工作日历与异常

目标是接收华为工作日历文件/截图或已整理材料，由原生会话辅助解释，人核对来源、适用范围和工作/休息日期后用于排期。没有本轮适用的真实样本，格式识别、OCR、节假日/调休正确性、远端宿主读取均未验证。

首轮仅支持粘贴或载入 UTF-8 文本/CSV，每行“2026-11-DD,工作或休息,说明”。这只是演示适配格式；**不定义华为导入协议**。可填虚构样本：11/13 休息、11/14 工作，其他日期按示例生成。先解析预览再应用，未列日期保持未知，不以普通周末推断华为工作日。样本不含内部日历原件或实际安排。

非法/重复日期拒绝解析，不能静默覆盖；重新编辑文本使预览失效。读取失败保留输入并提示；过大文件拒绝。应用日历只更新可用日期依据和冲突提示，不变更已确认截止。模型可建议下一已知工作日，人看见日期变化后再采纳；范围外日历/版本缺口要求补材料，不偷偷创建新版本。日历来源仅由用户填写，原型不认证发布方。

编辑需求时拒绝空名称/主导人/理由和无效日期。先行版本与后续完善版本必须符合本演示旅程的先后，截止须落在目标版本示例范围；这些样本校验不是“一切大需求必须跨两版”的产品限制。未安排需求可以保留候选安排，不算已承诺。

### #334 衔接与事实边界

泳道和“进入 B 版本总览”先打开衔接预览：需求身份、整体约定、本版增量、负责人、版本、截止及成果入口类别可读；未关联当前需求的版本明确“未安排”。返回保留选择与修改；暂不安排的需求仅显示候选身份，不冒充本版交付。现有版本工作区原型通过独立链接可达，它是 v0.7 基线，不假称已经连接另一窗口的新 #334 高保真。

正式版本总览由 #334 负责。本月选择、阶段成果已形成、评审通过、PR 合入、用户可试用、Issue 关闭和人工验收各有依据；不合为一个自动进度百分比。先行 MVP 与后续完善属于同一大需求的不同增量，各版一次正式验收。正式承诺与进行中成果的来源需要显式区分，未合入成果不能覆盖历史验收。

## 已有指标能力与认可范围

指标仍在总览下，保持旧 main 的业务／项目两区。业务“主要”表示未指定特性归属，不等于项目研发指标。

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/system-prompt/references/metrics.md)。北极星可缺席，占位不成为指标。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义提示修正，不随意关联。

“配置指标”每次在独立固定的 bw/metrics-refresh 分支和工作树中新建 Orca 原生会话，并离开总览进入该会话；已有同分支工作树和未完成改动保留，不续接上次会话，不另建 BW 配置面板或登记指标自动化。工作树定位、创建、目录、登记和宿主路由沿用 Orca，不另设目录规则或删除重建。接入已有指标工作树时保留该项目此前接入的其他工作树；切换计划、验收后指标工作树仍可从侧栏进入。加载项目约定、通用 SYSTEM 与 metrics-refresh Skill；提示携带当前定义、来源问题和返回总览上下文，不注入 week-planning。返回时恢复原总览的版本与指标筛选。

定义和脚本按项目规则评审合入。目录从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取最新已合入修订，不在后台 fetch，不把固定计划/验收树的旧 HEAD 当最新目录，也不向这些材料树合并指标草稿。读取失败保留原目录及其来源并显示错误，不能假报最新。配置树草稿可试采，须标明草稿，未合入前不成为三屏正式目录；主检出的新鲜度由总览「更新代码」按钮负责。

### 采集与可信度

仅 collect.kind=script 且 retro=true 的有效业务定义进入可用目录，脚本按 day/week 返回真实历史 points。retro=false、手填或仅返回当前 value 的输出均不作为可用采集；页面提示配置历史来源，不补造曲线。源数据和必要的历史存储由用户项目或外部服务负责。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

首次加载读取目录及已有采集缓存，并准备最近五周、十四天所需数据。业务日／周口径分别采集，不能用日均值简单合成周均值；当前粒度先回显，另一粒度随后准备。仅 not-collected 的缓存缺口自动采集一次，失败不自动重试。缓存缺口及正在采集不计为读取失败，等待时显示“正在读取”；采集结束后才展示本次实际失败，无数据保持未知。之后切换粒度、离开再返回总览仅复用本次应用运行的快照；用户点「更新代码」（快进主检出并重读目录）或对应指标刷新按钮（重新采集）才更新。日／周切换期间不清空已得数据、不重复联网或跑脚本。业务手动刷新维持阻塞遮罩，完成或失败均解除；来源或采集失败保留旧读数及原采集时间，明确提示失败。显示窗口固定于采集时刻，跨日／周不把缓存旧数标成今日或本周。

不引入每日采集自动化、bw/ledger 或每日 readings 写回。每次新采集解析主干基线目录，并在本次执行期间固定同一份定义、脚本及相关依赖修订；项目身份、窗口与来源随结果保存。旧计划 baseline 和归档证据保持只读，不能被刷新覆盖，也不用于阻止新采集。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

业务按“主要／特性”展示滞后与对应引领；图例只占一行，超出可用宽度时提供前后滚动，长名称省略但悬停可读全名，点击切换系列显隐。悬浮日期时集中显示该时点可见系列的读数；键盘左右键切换日期，Escape 收起读数。长期目标、类型和定义收进“指标详情”，不在图上方逐条排成常驻表格。采用 [ECharts 可滚动图例](https://echarts.apache.org/handbook/zh/concepts/legend/)与[轴触发提示](https://echarts.apache.org/handbook/zh/concepts/axis/)的交互模式，不限定图表库。leads 不等于已证明因果。同单位可共轴，不同单位用独立刻度或对齐小图。日/周可切；无历史点留空，最新读数注明真实覆盖窗口，字符串不画数值曲线。

项目指标保留三组日／周折线图，标题分别为“提交”“合入 PR”“开放 Issue”。提交按选定分支可达历史和提交时间；合入 PR 按真实 mergedAt，CodeHub 对应合入 MR。远端可读取合入时间时，应完成接口接线并绘制趋势，不把现有映射缺字段当成产品不支持。有完整事件才能重建含重开的开放 Issue 历史；仅当前快照时保留图表并只显示实际采集点，缺点留空，不从 state/closedAt 推造。分页截断、权限失败、离线只影响对应系列；短状态在图内展示，详细原因与口径进入详情。提交数不等于效率评分。两个区分别刷新、切粒度；本期注明截至采集时刻。

计划只写版本目标，不改项目长期目标；验收可从最新目录选择指标补充实测，实际值由脚本提供。旧 baseline 保留，不能因 definitionHash 或 configurationCommit 与旧计划不同而阻止采集。证据详情展示来源、采集时间、配置提交与采集脚本修订，定义指纹保存在材料中，供人追溯核对；界面不提供专门的定义或单位变化对比，不自动计算跨口径改善幅度或判断达成。新增验收指标不改原计划承诺。

总览从项目主干基线（主检出）的现有 `.bw/planning/<版本>/` 目录列出版本，每个版本只显示当前一份计划和验收；不把 Git 旧快照列成重复数据或迁移告警，不复活已经删除的版本。该版本当前文件是旧格式时才提示迁移，文件已迁移且有效时正常显示。有效的在研工作材料可作为当前草稿显示；落后的固定工作区不能覆盖主线现行数据。计划与验收通过保存的 planRef 核对；计划已更新而验收仍对应较早修订时保留当前计划，右栏提示尚无对应验收，不改读旧计划冒充当前数据。两栏固定等高、各自滚动，切换版本回到正文顶部。读取失败与尚无记录分别表达，并可重试。总览回看不改变计划/验收流程选版。

### 布局与动作

- 顶部沿用既有高保真的项目名片／北极星双卡结构：左侧项目名称与字段，右侧指标名称、当前值、目标和状态。缩小卡片纵向内边距与字段行距，保留字号和完整字段；高度随内容增长，不用固定高度裁切长文本。北极星不重复放刷新、配置按钮，不以“有读数”代称项目健康；缺失字段如实表达。
- 版本区不设“展开纪要”“去计划”“去验收”按钮；全文直接显示，原文来源随正文。版本目录首次进入总览读取，切换版本复用固定修订内容；页头「更新代码」快进主检出并重读现行目录，返回总览重读有效的当前草稿。
- 业务区显示“业务指标”、特性页签和紧凑图例，定义、读数及目标按需查看。业务区一个刷新图标（真实采集），带可访问名称与悬停提示；刷新和“配置指标”使用设计系统带边框、底色的次按钮。“配置指标”配 MessageSquarePlus 图标，表达新建会话；业务刷新同时更新北极星，配置入口只保留一处。
- 项目区显示三图及实际数据周／日和采集日期数量，一个日／周选择；重读统一由页头「更新代码」触发，区内不设刷新按钮。单击系列名称查看口径；单条失败不清空其他图。
- 页面不放迁移过程、协议字段或“为什么尚未实现”的长说明。草稿、未采集、失败和数据日期等影响判断的信息保持可见，具体原因按需展开。

## 布局约束

1280 与 1920 两种窗口宽度下内容铺满 Orca 内容槽，不横向溢出。计划/验收全文默认左右对照，各栏正文高度 16rem、超长独立纵向滚动，标题常驻；更窄设备可转上下排列。页面本身允许纵向滚动，不为塞满首屏把图表压成细条。多系列图例横向滚动，不靠不断加高标题区容纳指标；长定义进入详情。原型快照不是实时采集，真实 Electron 与脚本证据在实施后补齐。

实现与真实数据、Electron 验证边界见 [STATUS](STATUS.md)。
