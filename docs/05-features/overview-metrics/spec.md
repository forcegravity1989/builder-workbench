# 总览指标规格

> 给设计、实现和验收者读取；本文管可观察行为。价值见 [intent](intent.md)，接口见 [design](design.md)，证据见 [STATUS](STATUS.md)。行为变化时更新。
>
> 状态：已合入并作为实施输入；新增或不确定行为须人工确认，实施证据见 STATUS。[第八版原型索引](prototype.md) 指向共用原型的总览入口，使用 BW 定义和已读取快照；配置、刷新与历史入口是交互演示，不证明服务已接通。

原型为历史评审输入，不表示能力已交付。来源、离线使用与历史附件边界见[版本计划规格](../version-planning/spec.md)。

## 入口与用户旅程

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

指标仍在总览下，保持 main 的业务／项目两区。业务“主要”表示未指定特性归属，不等于项目研发指标。

| 阶段 | 用户动作 | 系统结果 |
|---|---|---|
| 理解 | 看业务主要/特性页签、引领与滞后关系，以及项目研发趋势 | 展示来源、窗口和缺口，不补演示数字 |
| 配置 | 点击“配置指标” | 在独立原生项目任务确定口径、采集脚本及可回溯性；不跳入计划会话 |
| 观察 | 刷新当前值或选择日/周历史 | 直接执行登记脚本/原生统计，无需先开模型 |
| 使用 | 计划选指标设目标，验收刷新事实 | 三屏同源，人的判断与数值分别保存 |

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/system-prompt/references/metrics.md)。北极星可缺席，占位不成为指标。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义提示修正，不随意关联。

“配置指标”使用独立固定的指标维护分支和工作树，打开原生项目会话屏；不加 BW 右侧指标配置面板，不进入周计划或验收固定分支，也不登记指标自动化。分支定位、工作树创建、目录、登记和宿主路由沿用 Orca，与计划、验收一致；复用已有同分支工作树，不另设目录规则或删除重建。固定维护工作树不等于永久复用一个会话：返回未完成的配置继续原任务，用户显式新开配置时创建新原生会话并复用该树，保留已有未完成改动。项目、宿主和原生 taskId 是身份，不按标题猜。加载项目约定、通用 SYSTEM 与 metrics-refresh Skill；提示携带当前定义、来源问题和返回总览上下文，不注入 week-planning。返回时恢复原总览的版本与指标筛选。

资产须按项目规则保存、评审并进入总览指定配置基线。配置中的草稿定义可预览和试采，但不得被其他版本自动当成已采用目录。返回总览后重新读取明确的配置修订，未合入时仍标草案，不假报就绪。

### 采集与可信度

仅 collect.kind=script 的有效定义进入可用目录。优先 retro=true 按窗口查历史；retro=false 只返回当前时点值及时间，不能用当前值填过去的周、按窗口重标，或证明一个历史区间目标。旧 manual 定义提示“需配置采集”，无录数入口，不自动把旧人工记录转成实测或删除历史原件。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

不迁入每日采集自动化、bw/ledger 或每日 readings 写回。可重算历史直接查来源；仅当前读数允许会话内缓存及归档证据，不累计伪历史。计划/验收固定所采用的读数、定义指纹与时间，旧记录保持历史身份。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

业务按“主要／特性”展示滞后与对应引领，系列可显隐、日/周可切、定义可打开；leads 不等于已证明因果。同单位可共轴，不同单位用独立刻度或对齐小图。无历史点留空，当前点明确标时刻，字符串不画数值曲线。

项目指标复用 Git/provider：提交按选定分支可达历史和提交时间；合入 PR 按真实 mergedAt；开放 Issue 是时点存量、排除 PR。有完整事件才能重建含重开的历史；仅当前快照就只展示当前，不从 state/closedAt 推造。分页截断、权限失败、离线只影响对应系列，提交数不等于效率评分。两个区分别刷新、切粒度；本期注明截至采集时刻。

计划只写版本目标，不改项目长期目标；验收实际值只读。定义变化要提示原口径及可比较性。总览沿 main 的版本页签和双栏：切换版本后，直接看到计划摘要与验收摘要；同版本多周可在原处切换，纪要全文在页内展开，不使用多周纪要弹窗。摘要复用计划/验收纪要的派生数据，不另存可编辑副本；读取固定修订，草稿身份可见，缺验收显示暂无记录，不能拿进展或提交记录顶替验收。该区域由版本特性供给，指标模块只消费布局。v0.5 不设计里程碑系统或重构总览其他区域。

## 验收与衡量

| 标识 | 可观察结果 |
|---|---|
| M01 | 原总览上下文、业务/项目两区可读；切换版本/周直接呈现同源计划与验收摘要，缺记录不替代、不弹窗；未配置与错误区分，无演示值混入 |
| M02 | 特性/leads/显隐正确，歧义可见；长期目标不被版本目标覆盖 |
| M03 | 真脚本以 argv/cwd 运行，正常值、零、字符串及历史点按协议接收 |
| M04 | 失败/坏输出/超时/缺测不造数，旧证据标陈旧并可重试 |
| M05 | 两区日/周窗口、时区正确；提交/PR/Issue 存量可独立复算，缺历史不补 |
| M06 | 三屏同定义/来源/能力，版本实测只读；仅当前值不能验历史目标，定义或执行脚本修订漂移可发现 |
| M07 | 配置打开原生项目会话，加载 metrics-refresh；同次继续/显式新建可区分，返回恢复总览；无独立 BW 配置面板、固定周分支、手填实际值或每日登记链 |
| M08 | 按采集代码/依赖修订去重，常驻树旧脚本不代用、过期响应隔离；重启历史可重算，归档证据可读回，仅当前值不伪造历史 |
| M09 | 普通项目无需 BW 源码；缺脚本/权限可修复，配置草稿与已采用目录不混淆 |
| M10 | main 有效资产定向迁入，manual/占位留缺口；核对重开事件/分页/权限，不把 Rust 结果算 Electron 证据 |

MJ01：普通项目 → 总览配置任务 → 确认口径并实现真实脚本 → 试采/评审采用 → 回总览看当前/历史 → 计划引用 → 验收刷新 → 归档证据 → 重启独立复算。MJ02 覆盖仅当前源、失败修复、真实零、定义变更和跨项目隔离。首用周记录采集/口径卡点及数据辅助决策的案例，先建立基线。

## 布局约束

1365×768、1280×720 下默认可见两个指标区核心值和图表、当前版本的计划/验收摘要；纪要全文按需页内展开，使用页面滚动，不给摘要另造滚动容器。长定义进入详情。原型快照不是实时采集，真实 Electron 与脚本证据在实施后补齐。
