## 月度规划草案

### 阶段成果与特性的关系

**阶段成果是里程碑，特性的 Pre版本与 Release版本安排支撑它。** 不等同于平台 Milestone，不把日期经过、项目发布或本版验收推导成整体完成。

撤去大成果卡，上方里程碑轴只按月排列旗帜与一句阶段成果，不重复下方已有的版本名称、日期和小版本点。旗帜与成果来自 .bw/milestones.json 的明确月份记录，成果可留空且不阻止排期提交；编辑时可补写，正式总览不画空成果旗帜。点击旗帜定位下方该月；横向平移不改变特性身份。下方版本窗口以 .bw 规划版本为源，有明确起止日期才绘制；历史无排期先隐藏，不从 GitHub Releases、验收时间或提交时间推算。

每行一项特性，负责人为属性。沿现有侧栏与项目版本名称，不加 C→B 层级；同名版本必须由身份定位，不能按名字、日期或 G1/G2 猜关联。项目背景、北极星、记分牌保留。

生产组件使用设计系统的 Button、Tooltip、Popover 与 Orca token；主操作使用单色强调。产品不显示设计参考按钮，参考依据仅保留在原型右上入口。页面“更新代码”靠右；四原则上方小字为常规字重。高保真特性行常态 88px，同周双节点错开时 104px；上方独立呈现月度旗帜与一句成果，下方泳道只保留 56px 的版本窗口表头。小窗口保留固定名称列、行末操作和水平滚动。同一特性的 Pre/Release 用细线关联，连线随拖动预览更新，同窗口上下错位时显示短折线；空心/实心菱形小图例区分两个节点。版本窗口在今天落入明确起止日期时标记“当前”，只表示时间位置，不推导执行状态；连接线也不表示持续工期。产品按这轮高保真接线；真实显示与指针手感待真机核对。

### 三种评审场景

| 场景       | 可见结果                                                             |
| ---------- | -------------------------------------------------------------------- |
| 尚无里程碑 | 简洁空态，同名“规划里程碑”入口；第一份草案未合入时普通总览仍为空     |
| 制定中     | 同一总览就地编辑，旗帜与泳道可操作；无会话区、独立工作区和大填写弹窗 |
| 已制定     | 仅呈现有排期的规划版本；当前 11 月样例示意 v1.0.1，无日期历史不绘制  |

场景选择仅供评审，不是产品状态设置器。月份是定位方式，不强制项目按月或按周命名和讨论。

### 时间窗口与就地编辑

特性只编辑**名称、负责人、Pre/Release 安排**；不再要求优先级、独立截止、交付说明。新增默认在末尾，行首手柄可拖动排序，Alt+上下键也可移动；排序计入变更摘要与提交快照，刷新后保留。添加即出现可编辑泳道行；名称和负责人可以逐项补齐，未补齐时禁用提交并说明缺项。Enter 离开字段，Escape 恢复该字段进入编辑前的内容。不会要求提前写完整规格或高保真。

不设置三个割裂的工具栏图标、月份选择器或版本登记弹窗。所有月份和特性共用下方同一条连续泳道，默认定位最新规划，可拖动画布回看；不会按月增加独立时间轴或过滤特性。上方里程碑条独立于泳道网格，只画已明确记录的月度旗帜与一句成果，版本点和日期完全留在下方；不会把背景周画成里程碑。上方每个月至少保留 240px 空间以容纳成果，月份较多时在同一条轴横向滚动。点击月份旗帜定位下方月份，两个区域不共享网格、固定名称列或纵向滚动。零特性仍呈现同一画布和“添加特性”，不先要求登记版本。

周一至周五为默认周窗口，周末淡化；已有材料中的起止日期原样呈现，不改成默认周。浅色空周只是背景：新增特性时在当前周放置 Pre/Release，或拖入空周、编辑空周版本名时，才为该周在草案中登记版本。默认名字沿已有版本风格递增，可就地改名；浏览、平移和未使用的空周不创建版本材料。下方时间背景同时覆盖已有明确月份记录，即使该月还没有版本也能由上方旗帜定位，不为此创建版本。生产沿既有 timeWindow 与 cycleId 数据源接入，原型仍只改浏览器演示草案。新特性在当前月当周安排，未来月份优先复用该月首个已有窗口，不因月初落在周末退到前月的空周。泳道末尾“添加特性”生成新行并聚焦名称。

未开工版本名称在泳道顶部直接编辑，时间导航与节点标签同步；正式侧栏只读取已合入安排。已有实际计划、原生版本绑定或其他版本材料时名称只读，提示按真实版本核对，不能改写已发生的版本。项目版本时间边界与日期刻度固定，**特性 Pre/Release 节点仍可拖动**，并非锁死时间安排。

1. 拖动节点吸附到目标项目版本窗口；临近边缘可平移。保持每行特性身份与负责人，不改变项目版本日期边界。
2. Pre 不得晚于 Release，允许同版；无效移动保留原安排并提示。取消指针不保存，结束拖动不误开版本预览。
3. 键盘聚焦节点后 `Shift+←/→` 移动一版；点击或 Enter 进入该版本。不再保留选版大表单。
4. 行尾固定操作区移除整个特性，按钮不与负责人排在一起。移除后不再弹出带撤销的提示，统一通过顶栏撤销恢复该特性和位置；移除和拖动排序各占一步。
5. 没有“纳入/暂缓”复选框或隐藏待安排列表。移除只作用于本次规划，不关闭 Issue 或删除跨版本正本。

版本排期由同一份 `.bw/planning/<version>/data.json` 的可选 `timeWindow` 保存，参见 [实现设计](milestone-design.md)。未来版本实际使用空周时登记名称、默认日期和 cycleId，按需开工，不提前创建工作树或会话。UI 暂不提供日期修改；模型可补旧日期或调整起止日期，读回后节点按原数据源重算，允许跨周。无日期不画，提交端仍独立校验 Pre/Release 关系并拒绝冲突材料。

### 编辑历史、提交与正式来源

进入编辑后保留一张含本次输入的泳道，不再设置“查看正式安排”切换按钮。状态显示“编辑中”，提交按钮按实际变更及材料完整性启用。左右弯箭头逐步撤销/重做一次字段编辑、节点拖动或行排序；字段输入及离开时的空白整理合为一步，输入框内保留原生文本撤销。相同修订的刷新和版本页返回保留历史；提交成功建立新的编辑基线并清空撤销记录，不撤销 Git 提交、推送或合入。撤销/重做使用标准弯箭头图标；旁边以分隔线区分独立的恢复图标，悬停/聚焦明确为“放弃本次修改，恢复最近提交”，直接恢复最近一次提交后的基线；外部冲突时明确以新读到的材料重新开始。

| 当前情况                   | 呈现与动作                           | 结果                                         |
| -------------------------- | ------------------------------------ | -------------------------------------------- |
| 与最近提交一致、无待审记录 | 编辑中；提交禁用，历史按实际记录启用 | 不创建无意义提交                             |
| 有未提交变化               | 编辑中；撤销/重做、提交评审          | 核对只读变更摘要后提交                       |
| 已提交                     | 已提交，待合入；查看评审             | 最近提交成为新的还原基线，正式安排保持原样   |
| 待审时继续修改             | 编辑中；更新评审                     | 提交更新同一评审草案，未提交部分仍独立       |
| 人工合入                   | 已合入，待更新；更新正式安排         | 只采纳已合入的提交快照                       |
| 合入后还有本次编辑         | 编辑中；仍可更新正式安排             | 更新后保留这些修改，不能把它们夹带进正式安排 |

“放弃本次修改”仅恢复到最近一次提交快照，第一次提交前恢复到进入规划的正式基线；不会撤销已提交/已合入内容。普通总览读本机主干基线，编辑读取项目材料提案与本次输入；刷新材料/评审不等于更新主干代码。提交、待合入、待更新不代表阶段成果或特性交付已完成。

复用现有 `bw/project` → PR/MR → 主干的项目材料链，不增加审批角色。正式材料从固定主干基线读取，已提交草案与应用内未提交编辑分别保存。提交前验证内容指纹、分支 HEAD、工作副本与文件修订；冲突保留草案并提示核对。只自动快进，不重置分叉或脏树。失败区分本地提交、推送与评审创建，可重试已提交内容。

应用内切页返回保留月份、编辑和视口；未提交草案与对应基线保存于本机恢复缓存，重启核对 Git 来源后恢复，名称或负责人未填完也保留。保存失败显式提示；基线变化保留输入并阻止静默覆盖。该缓存不跨机器同步，不替代 .bw 正式材料。撤销栈不跨重启，已提交草案和正式材料仍从 Git 重读。具体事务和数据源见 [里程碑实现设计](milestone-design.md)。

### Pre版本、Release版本与版本事实

Pre 是该特性先行可供部分用户使用的交付，Release 是其约定范围的正式交付；不是两种强制项目版本号或 Git 父子分支。节点表示目标安排，不因日期过去自动判已交付。每版计划持续收敛增量，每版只有一次正式验收；实施 Plan 属开发阶段。

缺少关系、尚无计划、未读取、读取失败分别表达。原型 11 月实际版本材料尚未读取，不虚构执行状态、交付百分比或已验收。会话结束、PR 合入、用户可用、Issue 关闭、目标达成分别看证据。

### 无排期的历史版本

历史版本只读 `.bw/planning/v0.4` 至 `v0.8` 的真实计划与对应人工验收，原名、目标和来源保留在原生版本入口及资料来源中。当前没有明确规划起止日期，故不在时间导航或泳道绘制；不再读取发布快照，不把验收、提交或 Release 日期当作版本排期。不另设旧版本关联入口，用户可让模型补齐原材料中的真实日期与关系；缺失的特性对应关系不猜测。

### 工作周与时间背景

取消独立日历按钮、弹窗和“定位最新”按钮。初次打开仍自动聚焦最新规划，此后直接横向平移。周一至周五作为默认窗口，周末用很淡底色区分，不要求按天画密集格子；已有版本按明确排期绘制。真实华为工作日数据尚未接入，未来可用于推导窗口，当前不展示虚构加班日。

### 进入版本与返回来源

从节点准确打开项目版本；有明确关联才定位、展开特性，缺失关系不猜；#334 可查看同一特性在其他版本的范围。返回恢复实际来源、阶段选择、特性和视口；若从草案进入，恢复同一草案，不覆盖未提交修改。

月度规划只保存特性名称、负责人及交付安排，不创建或要求绑定特性 Issue。具体特性 Issue 与版内范围交由版本计划助手收敛；[版本总览规格](../version-overview/spec.md)的主 Issue 身份不由里程碑标题推算。宏观安排与已开始版本不一致时，提醒用户与计划助手核对，不改写历史计划。

本轮核对正式材料 version + cycleId 后打开已有版本页，提供返回项目里程碑入口并恢复草案与视口。没有明确跨屏特性关系时如实显示未关联，暂不自动展开 #334 特性卡；未进入正式材料的版本提示先合入并更新。返回参数只是页面临时来源，不是双方已确认的持久化协议。

### 旅程与验收

旅程只记录在规格：月度选择阶段成果与特性 → 在先行版本交付 Pre / MVP → 部分用户试用，反馈统一转 Issue → 后续版本修理完善并达成约定 Release → 后续 Issue 持续改善。月初可连续讨论 1–3 天，期望周反馈但可跨周；不硬编码数量、时长或统一效果指标门槛。

| ---- | ------------------------------------------------------------------ | -------------------------------------------------------- |

| MP02 | 名称/负责人/版本就地编辑，Pre/Release 拖动、特性行排序，移除可撤销 | 原链路已有本地证据；连续周窗口与行末删除增量待真机       |
| MP03 | 默认工作周窗口与周末底色，无独立日历入口                           | 产品已同步默认周；真实工作日来源未接入，真机待验证       |
| MP04 | 规划节点、原计划/人工验收与未知关系分别呈现                        | 真记录投影与演示安排                                     |
| MP05 | 准确打开版本，有明确关联才定位；返回恢复来源和草案                 | 旧实现的版本入口与视口返回通过；当前增量待真机，特性定位未接入 |
| MP06 | 三场景、变更/提交/合入/更新及最近提交后的还原范围明确              | 原正式读回有证据；本轮草案重启恢复与 provider 真机待验   |

MPJ01：总览 → 点月份旗帜定位 → 规划里程碑 → 就地编辑和拖动 → 移除/撤销 → 核对变更 → 提交 → 再改/还原 → 人工合入 → 更新正式安排并保留未提交修改 → 核对 .bw 版本来源 → 进入版本预览并返回。真实远端提交、合入与更新段尚未运行；本地无远端用例只证明失败保留，历史强退重启证据只证明正式材料恢复；本轮未提交草案恢复已补入原 E2E 路径，尚未运行。

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/system-prompt/references/metrics.md)。北极星可缺席，占位不成为指标。可选的 [[feature]] 声明场景名称（name）和价值说明（value），决定页签顺序；场景与说明随目录编辑，产品不写死。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义或场景重名提示修正，不随意关联。

“配置指标”每次在独立固定的 bw/metrics-refresh 分支和工作树中新建 Orca 原生会话，并离开总览进入该会话；已有同分支工作树和未完成改动保留，不续接上次会话，不另建 BW 配置面板或登记指标自动化。维护树干净且只是落后于当前基线时，读取目录会把它快进到基线，使会话改的就是记分牌上这份目录。记分牌读基线；维护分支已从该基线提交了新目录时，回到总览重读那次提交。维护工作区里的配置文件直接显示在记分牌上，和已提交内容不同时标为配置草稿；打开这个工作区时，会话在上、记分牌在下，中间的分隔可以拖动高度，文件保存后隔几秒跟上。记分牌上的批注直接发给这个指标配置会话，不再选择会话。读数仍按已提交修订采集，草稿不写入正式读数。工作树定位、创建、目录、登记和宿主路由沿用 Orca，不另设目录规则或删除重建。接入已有指标工作树时保留该项目此前接入的其他工作树；切换计划、验收后指标工作树仍可从侧栏进入。加载项目约定、通用 SYSTEM 与 metrics-refresh Skill；提示携带当前定义、来源问题和返回总览上下文，不注入 week-planning。返回时恢复原总览的指标场景页签。

定义和脚本按项目规则评审合入。目录从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取最新已合入修订，不在后台 fetch，不把固定计划/验收树的旧 HEAD 当最新目录，也不向这些材料树合并指标草稿。读取失败保留原目录及其来源并显示错误，不能假报最新。配置树草稿可试采，须标明草稿，未合入前不成为三屏正式目录；主检出的新鲜度由总览「更新代码」按钮负责。

### 采集与可信度

仅 collect.kind=script 且 retro=true 的有效业务定义进入可用目录，脚本按 day/week 返回真实历史 points。retro=false、手填或仅返回当前 value 的输出均不作为可用采集；页面提示配置历史来源，不补造曲线。源数据和必要的历史存储由用户项目或外部服务负责。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

首次加载读取目录及已有采集缓存，并准备最近五周、十四天所需数据。业务日／周口径分别采集，不能用日均值简单合成周均值；记分牌先回显周窗口，日窗口随后准备，准备期间不清空已得数据、不重复联网或跑脚本。仅 not-collected 的缓存缺口自动采集一次，失败不自动重试。缓存缺口及正在采集不计为读取失败，等待时显示“正在读取”；采集结束后才展示本次实际失败，无数据保持未知。之后离开再返回总览仅复用本次应用运行的快照；用户点「更新代码」（快进主检出并重读目录）或对应指标刷新按钮（重新采集）才更新。业务手动刷新维持阻塞遮罩，完成或失败均解除；来源或采集失败保留旧读数及原采集时间，明确提示失败。显示窗口固定于采集时刻，跨日／周不把缓存旧数标成今日或本周。

不引入每日采集自动化、bw/ledger 或每日 readings 写回。每次新采集解析主干基线目录，并在本次执行期间固定同一份定义、脚本及相关依赖修订；项目身份、窗口与来源随结果保存。旧计划 baseline 和归档证据保持只读，不能被刷新覆盖，也不用于阻止新采集。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

记分牌按场景分页签：先列 [[feature]] 声明的场景，再列只在指标上出现的特性，未指定特性的指标归“主要”。每签展示一个结果（计划写了目标值的滞后指标优先，否则该场景第一条）和一个引领（leads 指向这个结果的引领，计划写了目标值的优先；没有则取未关联任何结果的引领，不借用关联其他结果的引领；仍然没有引领时，第二格展示该场景的下一个结果，并标成结果），其余指标列名提示，不被隐藏；缺结果或引领时说明可用「配置指标」补配。每个指标显示最近读数（带单位）、最近五周窗口的走势柱和口径；失败与陈旧证据保持未知并注明原因与原采集时间（有完成线时也不被输赢文案替代），无读数的走势柱与 0 值可区分，字符串读数只作文本。leads 不等于已证明因果。

聚焦由当前版本的计划推出：计划目标里给某个场景的任一指标写了非空目标值，该场景即本版聚焦，排在“聚焦”组，其余在“日常”组；完成线依次取所展示结果、所展示引领、其余指标的目标值。聚焦场景顶部一行写明「指标　从基线到完成线　截至该版验收」，基线取计划保存的 baseline，没有就只写完成线；日常场景写“日常盯防，不在本版聚焦”。输赢只由最近数值读数对比带比较方向的完成线（≥、≤、>、<、=）得出：显示“已达完成线”或“未达完成线”；完成线是纯数字、方向缺失、单位与指标不一致，或没有数值读数时显示“看不出输赢”，不装绿；完成线比较不是验收结论，目标达成仍由人确认。聚焦页签只在已达或未达完成线时标出输赢；看不出输赢时页签不重复这句话。记分牌底部常驻说明输赢怎么算，以及每周短会怎么用这张记分牌（报上周承诺 → 看记分牌 → 每人定下周一两件，承诺落成普通 Issue）；产品不另存承诺记录。

计划只写版本目标，不改项目长期目标；验收可从最新目录选择指标补充实测，实际值由脚本提供。旧 baseline 保留，不能因 definitionHash 或 configurationCommit 与旧计划不同而阻止采集。证据详情展示来源、采集时间、配置提交与采集脚本修订，定义指纹保存在材料中，供人追溯核对；界面不提供专门的定义或单位变化对比，不自动计算跨口径改善幅度或判断达成。新增验收指标不改原计划承诺。

指标依据版本从主干现行目录与有效当前计划读取，固定修订和来源校验沿原材料服务；落后的固定工作树不覆盖正式基线。读取失败与没有材料分别表达。计划/验收全文和相互引用核对在原生版本入口完成。

### 布局与动作

- 顶部沿用既有高保真的项目名片／北极星双卡结构：左侧项目名称与字段，右侧指标名称、当前值、目标和状态。缩小卡片纵向内边距与字段行距，保留字号和完整字段；高度随内容增长，不用固定高度裁切长文本。北极星不重复放刷新、配置按钮，不以“有读数”代称项目健康；缺失字段如实表达。
- 总览不再铺计划/验收全文双栏；不再放独立的指标依据版本选择器，当前版本提供指标聚焦上下文，版本全文由原生版本入口承接。页头“更新代码”快进主检出并重读现行材料，保留未提交里程碑草案。
- 内容区第一行是高效执行四原则（FranklinCovey 4DX）的一句话：聚焦至关重要目标 · 贯彻引领指标 · 设立振奋人心的记分牌 · 保持相互担责的节奏。纯排版，不是健康信号。
- 记分牌位于项目里程碑之下：标题行是记分牌，旁边是「批注」「配置指标」和一个刷新图标。「批注」打开与计划/验收相同的板面批注：点击本场景的目标行或指标记下讨论，编号角标与面板一致，可复制或发送给会话；批注只留在当次打开的总览里，重启不保留，也不改指标目录和完成线。走势固定为周窗口。刷新同时更新北极星，配置入口只保留一处。没有任何场景时提示用「配置指标」新建会话配置。
- 页面不放迁移过程、协议字段或“为什么尚未实现”的长说明。草稿、未采集、失败和数据日期等影响判断的信息保持可见，具体原因按需展开。

## 布局约束

1280 与 1920 两种窗口宽度下内容铺满 Orca 内容槽，不横向溢出。记分牌结果与引领左右并排，更窄时上下排列；场景页签过多时横向滚动。里程碑时间轴在自身区域横向滚动，特性标签固定；不在总览铺开计划/验收全文。页面本身允许纵向滚动。原型读数不是实时采集，真实 Electron 与脚本证据在实施后补齐。
