## 里程碑与版本联动

### 对象与语义

| 对象       | 表达什么                                               | 不代表什么                       |
| ---------- | ------------------------------------------------------ | -------------------------------- |
| 关键里程碑 | 具体日期和预期成果                                     | 自动完成、目标绑定               |
| 特性       | 长期保留的同一工作对象，名称必填、负责人选填           | 只能活在某一版的任务             |
| Build      | 计划集中开发的起止，可连续跨任意数量版本               | 已验收或实测开发工时             |
| Maintain   | 一轮计划维护的起止，可追加多轮；段间空白是没有安排工作 | 永久结束、每天满负荷工作         |
| 版本       | 独立的交付节奏与正式计划入口                           | 泳道的容器或拖动边界             |
| 实际结果   | 正式计划纳入及人工验收结论                             | 根据颜色、今天的位置或条长猜完成 |

计划上的 Build → Maintain 表达预期进入维护；只有正式验收能确认实际完成。最后一段结束不归档或删除特性，再次维护仍沿用同一特性和主 Issue。条长只表示自然日期跨度，不能换算人天、产能或贡献；本版做了什么由该版目标和关联任务承接。

### 连续规划旅程

| 时机             | 人的动作                                                        | 结果                                                |
| ---------------- | --------------------------------------------------------------- | --------------------------------------------------- |
| 月初或任意规划时 | 浏览连续日轴，安排接下来几个版本的日期                          | 月份只是日期刻度，没有强制月初切页；版本窗口独立    |
| 安排新工作       | 点「添加特性」，填名称、按需填负责人，拖动 Build / Maintain     | 先有粗排期，不要求先绑定版本、目标或主 Issue        |
| 首日 Plan        | 参考日期相交的特性，决定本版纳入哪些工作                        | 版本计划正式关联主 Issue 与目标，日期相交不自动纳入 |
| 版本结束但未做完 | 按事实验收；按新预期延长 Build                                  | 后版仍可纳入同一主单；其他特性、版本和历史结果不变  |
| 老特性被重新安排 | 从「全部特性」找到原行，点原行左侧单元格的扳手「添加 Maintain」 | 直接追加新段，按需拖动，不重建特性、不弹日期表单    |
| 回看或交接       | 切「显示实际」，进入对应版本看目标、任务和验收                  | 不用规划阶段代替事实；无结论保持未知                |
| 调整后协作       | 撤销、核对变更、提交评审、合入后更新正式安排                    | 草案与正式安排分开；返回、刷新及失败保留输入        |

### 日期编排与默认值

- 新特性默认从“今天”和“当前视口最左可见日期”中较晚的那天开始，先放一周 Build 和一周 Maintain。默认长度只是可调整的起点。回看过去时新增定位回今天；浏览未来时按正在看的日期起排。新 Build 超出可见范围时定位到其起点附近。无需已有版本，不生成隐含版本。
- 「添加 Maintain」直接在原行追加一周 Maintain。起点取今天、视口起始日、该特性最后一段结束时点三者中最晚者，不补满过去的空档。新段超出画面时自动定位；已有安排保留。
- 本行左侧单元格的扳手直接添加 Maintain，旁边「×」删除整条特性规划；两个动作分别提示「添加 Maintain」「删除特性」，可撤销。删除规划不关闭主 Issue、不删除正式计划或验收。
- 任意一轮 Maintain 均可单独删除，包括已提交的安排；保留特性、其余段及历史验收，不自动移动其他日期。编辑时悬停或键盘聚焦维护条，在其可见部分上方显示小垃圾桶，提示「删除此段 Maintain」，避开条身和伸缩手柄；常态隐藏，不设三点菜单或取消列表。删除是独立的可撤销修改，受当前筛选影响的特性在本次编辑仍保留；提交评审并合入后才改变正式安排。
- 拖条身平移、拖两端伸缩，阶段最少半天，按半天吸附，不限制跨版数量。同一特性的段不重叠，Maintain 可自由调整先后，按日期排列；不同特性可并行。
- 延长或右移 Build 若碰到后续 Maintain，只把本特性被碰到的后续段顺移至不重叠，保留各段时长，不为保留原截止日期压缩维护；未碰到的空档和安排保留，缩短 Build 不把维护自动拉回。连带调整显示在同一预览和评审摘要中，一次撤销恢复。
- 单独移动 Maintain 不连带改其他段；非法位置不提交。Escape 取消拖动；条身落在非法位置恢复拖动前计划，边缘伸缩保留最后合法位置。
- 版本表头移动或伸缩只修改版本预期日期，不带动任何特性。版本预期窗口暂不允许新增重叠；存量重叠可保留或缩小，不阻止无关特性编辑，也不要求一次修完所有旧重叠。新增或扩大的交集提示并阻止本次调整，不自动推移其他版本；不同版本可以连续衔接。正式版本或历史材料中的既有日期仍如实读取，不为满足规划约束改写事实。关键里程碑日期也独立。
- 旧版与已经开始的规划仍可调整，经同一评审链生效；改排期不改固定计划或已归档验收。已建立执行身份的版本沿既有改名保护。

### 浏览、排序与信息密度

首次定位到今天前十天，后续恢复上次视口；日期定位、前后周和横向浏览连续跨月、跨年。日轴每天等宽，标签列固定。月初仍看得到上月，视口不决定版本计划、记分牌或实际验收的上下文。

默认「当前时间范围有安排」，可切「全部特性」找回历史行。按实际可见日期计算范围；未填完的新行及本次正在调整的行保留，避免拖出范围时行突然消失。实际模式按结果日期筛选；没有结果的行仍按其规划日期保留并明确未知，读取失败不能被筛成“没有工作”。人数统计只计当前可见行的非空负责人。

常态按最后一段结束日期倒序，相同日期保持原顺序；不是按条长或重要性排序。进入编辑固定行序，新行置顶，退出后重新排序；追加维护不会让刚操作的行突然跳走。筛选与时间范围只改变呈现，不删除历史资料。

Build 用蓝色、Maintain 用暖黄色并保留文字和维护底线，避免相近蓝色只能靠猜。长条被视口裁切时，阶段名仍留在可见部分；颜色不表达成功失败。长跨度仍可用日期直接定位，日轴按查看位置渲染有限日期范围，不按最远排期一次挂载多年单元格；大数据量性能仍须运行验证。

### 关键节点与操作反馈

节点写具体日期与预期成果，同日可有多个。关键里程碑表头用旗帜、特性表头用列表加号、本行左侧用扳手，分别提示「添加里程碑」「添加特性」「添加 Maintain」。三者沿用紧凑描边按钮，位置和图形共同区分对象；图标使用前景色，不继承浅灰说明色。特性单元格内另保留「×」删除入口，不铺常驻文字按钮，不在右侧放三点菜单。

关键节点区保持 88px。常态成果最多两行，点旗帜或摘要展开全文；编辑时可展开文本，不撑高节点区。同日合并带数量的旗帜，拥挤时收起摘要。节点 X 直接删除，可撤销；它与特性整行移除语义分开。未指定具体日期的旧成果保留原文，由人补日期，不捏造月初月末。

特性名称失焦或提交时为空，字段描边标红；点提交后使用 Orca 全局通知说明具体问题，并定位首个缺失字段。负责人不必填。不能只禁用按钮而不给原因，也不在泳道下额外放笼统错误行。无变化时提交禁用，提交期间锁定重复提交；正常草案保存不占一行，保存失败必须可见。

沿现有问号引导帮助首次编辑，可跳过。工作日与休息日沿现有工作日历着色，日期按自然日编排；版本按天调整。命名空周才登记版本，未提交的空版本可清空名称撤回，不删除真实版本材料。

### 实际：默认不显示，只读目标结论

默认展示计划；实际只消费正式目标验收，当前不采集真实阶段工期。首次交付映射“已上线 / 未上线”，有前版上线后的目标结果映射“维护完成 / 维护未完成”，只指本版工作。未判定、未合入、缺关联、多候选和读取失败不生成完成或失败结论。

首次达成按正式版本历史顺序推导，不按可拖动的规划排序。A 未达成、B 首次达成、C 未达成，分别为 A 未上线、B 已上线、C 维护未完成；C 不抹掉 B 的上线事实。结果不要求泳道已有对应版本或维护段，不自动关 Issue，不回写规划。

开启实际后保留规划日期对照，结果条直接标“版本名 · 结论”，条长来自正式版本采用周期，不是特性实测工期。真实版本重叠时分层展示，不顺延事实。结果不靠落在哪个版本表头下猜归属；切回计划恢复原编排。点击版本头或结果条进入版本总览，返回恢复项目、草案和视口；未正式登记版本提示先合入更新。

### 关联与计划助手配合

日期交集只是规划候选。某版是否纳入、放在哪个目标，以该版计划的主 Issue 与 `tasks.goalId` 为准；拖动泳道、移动版本和跨月浏览均不修改正式关联。维护工作仍要在相应版本计划中体现其目标及执行 Issue，不能只有一条彩条而没有任务内容。

匹配沿现有规则：主 Issue 带精确“特性”标签、标题包含完整去首尾空白的里程碑名称；不做简称或相似度猜测。唯一匹配后以完整 `provider + repository + number` 查后续版本，一个目标最多一个特性、同特性在同版归到一个目标，多执行 Issue 不重复计数。跨版复用同一主单，不按维护轮次重建。无候选或多候选保留规划并提示材料核对。

验收只消费 `planRef` 固定计划、已合入归档与人工 `results[].decision.outcome`，不从当前编辑计划、Issue 关闭、PR 数或日期推断。确认特性改名时同步主单标题与里程碑名称，保留稳定身份和历史；普通目标改名不触发同步。完整步骤见[计划助手与里程碑衔接](../version-planning/spec.md#计划助手与里程碑衔接)。

里程碑预期版本日期与首日 Plan 正式采用周期独立；没有里程碑仍能正常制定版本。仅预排的版本保留在里程碑，不生成空计划、不进入侧栏版本区，也不成为项目墙或总览自动选择的版本。用户从既有「新建版本」入口使用同一名称开始计划时，沿用预排身份与初始日期；主动新建但尚未填写目标的版本正常显示。预排版本的进入提示说明需先开始计划，合入排期本身不等于已经开始。旧空占位需按项目一次性核对并经 PR 清理，升级本身不自动删除；已有计划、验收和固定历史引用保留。相关成员升级后再提交新排期结构。

计划/验收沿现有目标、任务和助手，不增加绑定、特性结果或阶段确认表单。版本总览继续承接版内细节；其规划读取需适配自由日期段，不能把完整跨版条长重复算到每一版，也不能从两段规划伪造五阶段实际工时。

### 编辑历史、提交与正式来源

沿用 `bw/project → PR/MR → 主干` 的项目材料链。正式安排来自固定主干基线；已提交提案、应用内输入与正式安排分开。返回箭头结束编辑但保留草案。恢复快照保存成功后显示「草稿已保存在本机」，退出编辑后可从「继续规划」返回草案；来源不同或并发冲突时保留输入并提示核对，不静默覆盖、重置分叉或脏树。

字段一次编辑、节点/段拖动、追加或删除单段维护和删除特性分别成为可撤销操作。输入框内保留原生撤销；提交成功建立新编辑基线并清空撤销记录，不撤销 Git 提交或合入。独立恢复按钮明确为“放弃本次修改，恢复最近提交”；首次提交前恢复进入编辑的正式基线。

| 当前情况       | 呈现与结果                                 |
| -------------- | ------------------------------------------ |
| 无变化、无评审 | 提交禁用，不创建空提交                     |
| 有输入变化     | 核对只读变更摘要，提交或更新同一评审       |
| 已提交待审     | 查看评审，正式安排保持原样                 |
| 人工合入       | 更新正式安排，只采纳已合入快照             |
| 合入后仍有输入 | 更新正式安排时保留未提交部分               |
| 提交失败       | 保留草案，用原生通知及重试入口区分失败步骤 |

提交前验证内容指纹、分支 HEAD、工作副本与修订，失败可重试已经提交的内容。应用切页保留状态，未提交输入异步耐久保存到本机 profile；名称未填完也保存。只有写入确认的快照可承诺重启恢复，撤销栈不跨重启；缓存不替代正式材料、不跨机器同步。具体事务见[里程碑实现设计](milestone-design.md)。

工作副本检查限定为里程碑与版本材料目录。其他目录的未跟踪文件、已修改或已暂存内容保留，不因这些内容阻止提交，也不随里程碑提交；材料本身有未提交变更或分支同步会覆盖现有文件时，保留草案并提示核对。

存量转换必须保留原行、段身份与已记录日期，旧开发阶段汇总为其已有日期跨度，已有 Maintain 各自保留；没有记录的时间不能补造。移除排期的版本约束不删除正式关联或验收。生产材料协议、迁移和版本总览读取尚未在本原型中实现。

旅程覆盖：连续规划 → 首日计划纳入 → 本版未完成后延长 Build → 人工验收合入 → 隔一段时间再次维护并正式纳入 → 回看历史 → 重启独立读回。规格认可、静态原型验证与 Electron/真实模型/provider 证据分别记录。

## 已有指标能力与认可范围

本节保留 #411 已确认的记分牌与采集行为；#440 不重新设计指标。撤去“版本计划与验收”及游离的指标依据版本选择器后，记分牌从当前版本计划读取聚焦与完成线；无当前版本时取主干现行目录中的最新有效版本，不把里程碑时间轴视口当作指标上下文。

## 入口与用户旅程

项目连接、宿主路由、文件与命令执行沿用 Orca 原生能力；BW 不按本机、Web/配对或 SSH/WSL 另设产品限制。操作在工作树所属宿主执行，连接或权限不可用时呈现原生失败，不切换到其他机器读写。

指标在总览的记分牌里呈现，替代原业务／项目两区；项目研发统计（提交、合入 PR、开放 Issue）不再在总览展示。场景即指标目录里的特性，未指定特性的指标归“主要”页签，不等于项目研发指标。

| 阶段 | 用户动作                                       | 系统结果                                                                               |
| ---- | ---------------------------------------------- | -------------------------------------------------------------------------------------- |
| 理解 | 看记分牌：场景页签、结果与引领、读数旁的完成线 | 展示读数和缺口，不补演示数字；没有完成线或读数时点和数字保持中性色                     |
| 回看 | 查看当前版本的指标承诺                         | 以当前版本计划读取聚焦与完成线；其它版本的计划/验收从已有版本入口查看                  |
| 配置 | 点击“配置指标”                                 | 在固定维护树中新建原生会话并进入该会话，确定口径、历史来源和采集脚本；返回保持总览筛选 |
| 观察 | 更新代码、刷新日/周历史                        | 读取主干基线定义并直接执行登记脚本，无需先开模型                                       |
| 使用 | 计划选指标设目标，验收选择指标并刷新事实       | 新采集采用主干基线定义与脚本，旧计划基线保留，人的判断与数值分别保存                   |

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/references/metrics.md)。北极星可缺席，占位不成为指标。可选的 [[feature]] 声明场景名称（name）和价值说明（value），决定页签顺序；场景与说明随目录编辑，产品不写死。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义或场景重名提示修正，不随意关联。

“配置指标”每次在独立固定的 bw/metrics-refresh 分支和工作树中新建 Orca 原生会话，并离开总览进入该会话；已有同分支工作树和未完成改动保留，不续接上次会话，不另建 BW 配置面板或登记指标自动化。维护树干净且只是落后于当前基线时，读取目录会把它快进到基线，使会话改的就是记分牌上这份目录。记分牌读基线；维护分支已从该基线提交了新目录时，回到总览重读那次提交。维护工作区里的配置文件直接显示在记分牌上，和已提交内容不同时标为配置草稿；打开这个工作区时，会话在上、记分牌在下，中间的分隔可以拖动高度，文件保存后隔几秒跟上。记分牌上的批注直接发给这个指标配置会话，不再选择会话。读数仍按已提交修订采集，草稿不写入正式读数。工作树定位、创建、目录、登记和宿主路由沿用 Orca，不另设目录规则或删除重建。接入已有指标工作树时保留该项目此前接入的其他工作树；切换计划、验收后指标工作树仍可从侧栏进入。准备完整 metrics-refresh Skill 后，在输入区预填一句带 SKILL.md 路径的请求，保留草稿由用户发送；模型按 Skill 读取项目约定、公共规范、维护树定义与来源，不加载计划 SOP。返回时恢复原总览的指标场景页签。

定义和脚本按项目规则评审合入。目录从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取最新已合入修订，不在后台 fetch，不把固定计划/验收树的旧 HEAD 当最新目录，也不向这些材料树合并指标草稿。读取失败保留原目录及其来源并显示错误，不能假报最新。配置树草稿可试采，须标明草稿，未合入前不成为三屏正式目录；主检出的新鲜度由总览「更新代码」按钮负责。

### 采集与可信度

仅 collect.kind=script 且 retro=true 的有效业务定义进入可用目录，脚本按 day/week 返回真实历史 points。retro=false、手填或仅返回当前 value 的输出均不作为可用采集；页面提示配置历史来源，不补造曲线。源数据和必要的历史存储由用户项目或外部服务负责。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

首次加载读取目录及已有采集缓存，并准备最近五周、十四天所需数据。业务日／周口径分别采集，不能用日均值简单合成周均值；记分牌先回显周窗口，日窗口随后准备，准备期间不清空已得数据、不重复联网或跑脚本。仅 not-collected 的缓存缺口自动采集一次，失败不自动重试。缓存缺口及正在采集不计为读取失败，等待时显示“正在读取”；采集结束后才展示本次实际失败，无数据保持未知。之后离开再返回总览仅复用本次应用运行的快照；用户点「更新代码」（快进主检出并重读目录）或对应指标刷新按钮（重新采集）才更新。业务手动刷新维持阻塞遮罩，完成或失败均解除；来源或采集失败保留旧读数及原采集时间，明确提示失败。显示窗口固定于采集时刻，跨日／周不把缓存旧数标成今日或本周。

不引入每日采集自动化、bw/ledger 或每日 readings 写回。每次新采集解析主干基线目录，并在本次执行期间固定同一份定义、脚本及相关依赖修订；项目身份、窗口与来源随结果保存。旧计划 baseline 和归档证据保持只读，不能被刷新覆盖，也不用于阻止新采集。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

记分牌按场景分页签：先列 [[feature]] 声明的场景，再列只在指标上出现的特性，未指定特性的指标归“主要”。每签展示一个结果（计划写了目标值的滞后指标优先，否则该场景第一条）和一个引领（leads 指向这个结果的引领，计划写了目标值的优先；没有则取未关联任何结果的引领，不借用关联其他结果的引领；仍然没有引领时，第二格展示该场景的下一个结果，并标成结果）。其余指标不在牌上列出，缺结果或引领时该栏只留角色名。每个指标显示名称、最近读数（带单位）和最近五周窗口的走势柱；有完成线时，完成线原文贴在读数右侧。口径、采集时间和未知原因不写在牌上。失败与无读数都显示未知，无读数的走势柱与 0 值可区分，字符串读数只作文本。leads 不等于已证明因果。

聚焦由当前版本的计划推出：计划目标里给某个场景的任一指标写了非空目标值，该场景即本版聚焦，页签排在前面，名字前有一个点；其余场景隔开一段，不写“聚焦”“日常”。完成线依次取所展示结果、所展示引领的目标值，贴在读数旁。输赢只由最近数值读数对比带比较方向的完成线（≥、≤、>、<、=）得出：达到时点和数字用成功色，未达到时用警告色；完成线是纯数字、方向缺失、单位与指标不一致，或没有数值读数时点和数字保持中性色，不装绿，也不写“已达完成线”“未达完成线”“看不出输赢”。完成线比较不是验收结论，目标达成仍由人确认。价值说明留在指标目录，不出现在牌上。产品不在记分牌上写每周短会用法，也不另存承诺记录。

计划只写版本目标，不改项目长期目标；验收可从最新目录选择指标补充实测，实际值由脚本提供。旧 baseline 保留，不能因 definitionHash 或 configurationCommit 与旧计划不同而阻止采集。证据详情展示来源、采集时间、配置提交与采集脚本修订，定义指纹保存在材料中，供人追溯核对；界面不提供专门的定义或单位变化对比，不自动计算跨口径改善幅度或判断达成。新增验收指标不改原计划承诺。

指标依据版本从主干现行目录与有效当前计划读取，固定修订和来源校验沿原材料服务；落后的固定工作树不覆盖正式基线。读取失败与没有材料分别表达。计划/验收全文和相互引用核对在原生版本入口完成。

### 布局与动作

- 名片旁的问号启动逐步引导，指向名片展开和编辑入口，说明名片、里程碑和记分牌的分工。首次进入有项目的总览时从名片开始，无项目时可从问号查看添加入口。退出和回看遵循[引导规范](../../04-design-system/guidance.md#展示与结果)。
- 顶部项目名片默认收起一行，显示项目名称与项目墙选中的同一版本。展开显示「项目负责人／想做什么／对标／愿景／项目群」，空值为「—」。编辑图标打开[项目墙共用的设置栏](../project-intake/spec.md#项目信息编辑与失败反馈)，已有名片即时回显，评审状态单独读取。名片 PR 状态行（待合入／已合入未更新／没读到）独立于折叠。字段随内容增长，长文本完整显示。
- 总览不再铺计划/验收全文双栏；不再放独立的指标依据版本选择器，当前版本提供指标聚焦上下文，版本全文由原生版本入口承接。页头“更新代码”快进主检出并重读现行材料，保留未提交里程碑草案。
- 记分牌位于项目里程碑之下：标题行是记分牌，配置草稿在标题旁标「草稿」，旁边是「批注」「配置指标」和一个刷新图标。「批注」打开与计划/验收相同的板面批注：点击指标记下讨论，编号角标与面板一致，可复制或直接发给指标配置会话；批注只留在当次打开的总览里，重启不保留，也不改指标目录和完成线。进入批注时按钮保持按下，牌上不另起说明。走势固定为周窗口。刷新重新采集各场景读数，配置入口只保留一处。没有任何场景时不另写配置步骤；指标目录未就绪时显示这一状态。
- 页面不放迁移过程、协议字段或“为什么尚未实现”的长说明。草稿、未采集、失败和数据日期等影响判断的信息保持可见，具体原因按需展开；目录和版本读取失败仍在对应位置可见，记分牌上没有读数时只显示未知。

## 验收与衡量

| 标识 | 可观察结果                                                                                                                                                                                                                    |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M01  | 可折叠项目名片、里程碑与记分牌可读；指标依据当前版本计划且来源可核对、缺记录不替代、读取失败可辨；不以 Issue 进度代替验收                                                                                                     |
| M02  | 场景页签按 [[feature]] 顺序、聚焦场景排在前面；每签结果与引领配对正确、其余指标不在牌上列出、歧义可见；聚焦与完成线来自当前版本计划，完成线贴在读数旁，输赢只在完成线带方向且有数值读数时用颜色表示；长期目标不被版本目标覆盖 |
| M03  | 真脚本以 argv/cwd 按日/周查询历史；正常点值、零和字符串按协议接收，仅当前 value 或 retro=false 不作为可用采集                                                                                                                 |
| M04  | 失败/坏输出/超时/缺测不造数，旧证据标陈旧并可重试                                                                                                                                                                             |
| M06  | 三屏从主干基线发现指标；验收可选新指标，新采集不被旧配置修订拦截；旧 baseline 保留，证据详情可核对来源、时间、配置与脚本修订，不自动判达成                                                                                    |
| M07  | 每次“配置指标”在同一固定维护树中新建原生会话并进入该会话，加载 metrics-refresh，保留未完成改动，返回恢复总览；无额外 BW 配置面板或指标自动化                                                                                  |
| M08  | 每次执行固定主干基线的定义/脚本/依赖修订并按其去重；旧脚本不代用、过期响应隔离；重启历史可重算，旧归档证据可读回                                                                                                              |
| M09  | 普通项目无需 BW 源码；读取最新目录不 merge 草稿工作树，不丢未完成材料；失败保留来源和错误，草稿试采不成为正式目录                                                                                                             |
| M10  | main 有效资产定向迁入，manual/占位留缺口；核对重开事件/分页/权限，不把 Rust 结果算 Electron 证据                                                                                                                              |

MJ01：普通项目 → 配置指标新会话 → 确认口径并实现历史脚本 → 试采/评审合入 → 回总览「更新代码」读目录并看日/周历史 → 计划引用 → 验收选择指标和刷新 → 归档证据 → 重启独立复算。MJ02 覆盖来源无历史能力、失败修复、真实零、定义/脚本更新、旧 baseline 留存和跨项目隔离。首用周记录采集/口径卡点及数据辅助决策的案例，先建立基线。

## 布局约束

1280 与 1920 两种窗口宽度下内容铺满 Orca 内容槽，不横向溢出。记分牌结果与引领左右并排，更窄时上下排列；场景页签过多时横向滚动。里程碑时间轴在自身区域横向滚动，特性标签固定；不在总览铺开计划/验收全文。页面本身允许纵向滚动。原型读数不是实时采集，真实 Electron 与脚本证据在实施后补齐。

实现与真实数据、Electron 验证边界见 [STATUS](STATUS.md)。
