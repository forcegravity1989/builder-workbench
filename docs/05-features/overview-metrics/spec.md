## 月度规划草案

### 阶段成果与特性的关系

**阶段成果是里程碑，特性的跨版本 SDLC 安排支撑它。** 每行一项特性，负责人为属性；上方独立月度旗帜配一句成果，点击定位下方连续日轴。版本点、日期与阶段只在下方呈现，不与旗帜共用网格。成果可留空，正式总览不画空旗帜，排期仍可提交。

保留项目背景、北极星、记分牌与当前侧栏。不强制 C/B 命名或月度层级。版本来自 `.bw/planning` 的明确身份与起止日期，无日期历史不画，可由模型补材料；不从 GitHub Releases 或验收时间猜排期。同名版本不能仅按显示名称定位，特性也不能按标题、负责人或 G1/G2 猜关联。

三种原型场景沿用“尚无里程碑 / 制定中 / 已制定”。编辑在同一总览进行，无会话区、独立工作区或大填写弹窗。设计依据只在原型右上小文档入口，不进入生产 UI。场景开关和演示说明使用 `原型注释:`；不增加原型批注功能。

### 日轴、工作日历与就地编辑

下方所有特性共用一条连续可横向平移的日轴，每格一天、36px，特性栏宽 220px；时分不是单独的网格。版本名和起止日期位于日轴上方，当前日期对应的窗口标“当前”，仅表示日期位置，不由此判定版本已开始。新版本默认正常工作周；空周只是背景，实际使用或填写名称时才登记，不批量创建材料或启动会话。

工作日历由 BW 预置。参考 [PR #320](https://github.com/forcegravity1989/builder-workbench/pull/320) 的日轴：休息日淡底、调休与加班以“休/班”标识。原型与生产复用独立的 `workCalendarDay(date)` 查询函数；年度班/休数据由构建时预制，每年只建立一次查询索引，未覆盖年份按普通周末。当前没有真实华为样本，不能把普通周末说成已接入华为日历。班/休标记在日期表头，休息日底纹贯穿泳道；不提供日历按钮、用户导入或日期解析弹窗。

1. 特性就地编辑名称、负责人、目标及阶段安排。目标放在特性栏，与负责人同排，按关联版本先后显示“版本名 · G1”标签；规划时展开仅有 G1、G2、G3、G4，色条上不重复放目标选择。版本名使用次级文字，目标保持清楚；较长版本名或多项关联可在目标区横向滚动，负责人保持同排，不缩小特性行的可读空间。目标尚未制定时只是规划位置，有明确版内目标身份时才关联实际进度，不凭序号推断已有事实。末尾“添加特性”生成新行，默认放在尚未开始的版本及其后续版本，名称聚焦；不需先填版本表单。阶段成果可以为空；特性名称与负责人缺失时不能提交。
2. 首版默认 Plan 1 天、Design 2 天、Build 半天、Test 1 天、Deploy 半天；下一明确关联版默认 Maintain。默认分配跳过预置休息日，原型未配置时跳过普通周末。默认值只用于新规划，不覆盖真实记录，也不要求填满版本窗口。
3. 未开始的特性阶段条可整体平移；阶段左右边缘按半天吸附，相邻阶段共享边界，最短半天。拖整条到未来空周时按需登记版本，保留特性身份。边缘与色条可用左右键调整，Escape 或取消指针不保存。
4. 未开始的共享版本窗口仅整体按天平移，带动本版所有计划阶段；时长只拖下方 SDLC。窗口随本版全部首交付特性的最早 Plan、最晚 Deploy 扩缩，可跨周；Maintain 铺满后续版本，没有首交付特性的版本可拖 Maintain 调整时长。同一特性泳道的前后安排不能重叠或倒序，边界相接允许；拖动时即时提示“同一泳道不能重叠”，保留最后合法位置。整版平移、阶段拖动、新增引起的窗口联动都检查全部受影响行，失败不留下新版本或非法草案。不同特性可以并行。变动挤压后续已登记、未开始且未被任何特性引用的空版本时，按原顺序向后平移这些空版本，保留其时长与身份；连续空版本一并顺延，缩短前版不自动把它们拉回。Maintain 引用也算已有排期；若空版本顺延后撞上已开始或已有排期的固定版本，拒绝该候选，不擅自挪动其特性。原有真实并行版本保持并行。连带顺延与本次编辑作为一次撤销。
5. 开始制定版本计划时冻结，不因日期经过推断，也不等计划 PR 合入。原生版本绑定、已有实际计划内容，或留存的原生计划分支中版本名及 cycleId 均吻合的材料，均表示已开始；不能仅凭分支名判断。已开始版本的实际、原计划和版本日期只读，不能拖动改写历史；后续版本仍可调整。未开始版本名可直接编辑，已开始名称按实际版本保持。
6. 行首手柄拖动排序，Alt+上下键可移动；新增在末尾。尚未开工的行可在行尾移除，通过顶栏撤销恢复；含已开始版本的行保留原计划，不能整行删除，但未来阶段仍可调整。不弹重复撤销提示，不保留“暂不安排”列表，不删除真实 Issue。

日轴与色条用同一坐标计算，不叠加不同宽度的格线。月度旗帜区 76px，版本表头每层 52px，日表头 40px；仅真实并行版本增加表头层数。常态特性行 88px，开启原计划对比时 116px。数量统计与 SDLC 图例共用一行，左统计、右图例，窄窗允许自然换行；不另占统计行。淡色阶段有文字与图例，不只靠颜色识别。短实际阶段按真实比例绘制细段，保留可聚焦命中区与精确时间提示，不为放文字伪造工期。

版本跳转只出现在版本表头名称旁；特性阶段条负责排期和显示，不放版本跳转按钮。

历史材料可以只回填明确的特性、版本、目标归属及版本日期，未记录的阶段保留为空。泳道在对应版本窗口内显示只读中性“阶段未记录”条，仅表达版本归属，不表示实际工期或原计划，不自动生成五阶段或完成结论。开关“显示计划”不会隐藏该条或增高空白基线行；没有阶段依据时不连接阶段首尾。历史回填由模型直接修改项目材料并经 PR 评审，界面不增加补历史入口，也不放松已开始版本的冻结规则。

### SDLC 计划与实际

去掉特性的 Pre版本 / Release版本划分。首次版本就是首次交付；后续明确关联版本的关注与修理称 Maintain。项目发布记录仍是另一事实，不额外增加正式验收次数。

| 阶段 | 实际证据边界 | 未开始时默认 |
| --- | --- | --- |
| Plan | 约定的计划起点（北京时间 09:00）至版本计划 PR 合入；#334 当前以首次正式计划合入所在周周一作为起点，是约定基线而非实测开工 | 1 天 |
| Design | 明确关联设计/原型 PR 合入 | 2 天 |
| Build | 明确关联实现 PR 合入；没有可识别实现 PR 才以特性 Issue 关闭作为替代证据 | 半天 |
| Test | 版本验收 PR 合入，并且相关目标人工标记通过 | 1 天 |
| Deploy | 暂未采集，实际显示“未跟踪”；不得填默认时间或按 Releases 推断 | 半天 |
| Maintain | 后续版本明确纳入同一特性后的关注/修理与验收证据；未关联不推断 | 后续版本窗口 |

当前来源核对的是尚未合入主干的 [#334 开发分支 @ 50f34e56](https://github.com/forcegravity1989/builder-workbench/blob/50f34e56aebeac38699b37924b83e3245166cd33/src/renderer/src/workbench/version-overview/feature-timeline.ts)，不以本工作树旧版材料声称已接入。设计/实现角色按显式 PR 关联识别，不能机械取全仓第一个/第二个 PR；多个 PR、缺失或冲突证据按 #334 现有解析边界保留未知。Test 区间包括等待，是事件跨度，不是纯测试或开发工时；本版验收通过不能推出整个跨版本特性完成。

未开始时默认显示可编辑计划。已开始后默认显示只读实际；“显示计划”打开下方淡色原计划，原计划在版本开始时固定，用来比较差距。关闭不删除基线，不影响未来可编辑计划。真实时间按北京时间折算到日格的连续比例，半格或更短均可呈现，提示保留原始时分及证据。进行中阶段右边界仅到明确观测时间，以斜纹区分，并说明不是完成时间；前置事件未知时不补色。Deploy 只有中性未知标签，没有伪造的实际半天段。

原型的 started、时间戳、实际阶段和特性/版本关系均为明确样例，不从浏览器日期或标题推断，也不写入真实版本材料。生产要复用 #334 的读取与证据解析；里程碑宏观特性不创建 Issue，特性主 Issue、对应关系、实际读取及缓存由 #334 负责，并由该侧接入共享函数。#440 本轮独立交付排期和原计划虚影，生产显示“实际进度未接入”；不建立绑定表单或第二套采集/缓存。原型实际色条为后续呈现参考，不证明本轮已接入。

### 编辑历史、提交与正式来源

恢复本机草案时若项目材料已更新，明确提示“当前显示本机草案”，保留输入并由人选择载入最新规划。来源冲突未解决前，不叠加以新材料对比旧草案产生的阶段、日期冻结错误或部分还原入口；提交保护仍有效。Git 回退项目材料不会自动删除本机未提交草案。

进入编辑后保留一张含本次输入的泳道，不再设置“查看正式安排”切换按钮。标题左侧返回箭头结束编辑，回到只读正式安排；草案和本次撤销记录保留，再次点“规划里程碑”继续编辑，不提交也不放弃修改。右侧不为返回新增按钮。顶栏用同一个评审入口表达下一步：有改动时提交或更新评审，无改动且已有 PR/MR 时查看评审，已合入但本机未更新时更新正式安排。正常状态不再另列标签、评审链接行或草案保存提示；保存失败与评审读取失败仍明确提示。提交按钮按实际变更及材料完整性启用，改动摘要内仍可查看已有评审。左右弯箭头逐步撤销/重做一次字段编辑、节点拖动或行排序；字段输入及离开时的空白整理合为一步，输入框内保留原生文本撤销。相同修订的刷新和版本页返回保留历史；若恢复草案时版本已开工，可明确还原已锁定版本的改动；涉及锁定版的新增特性整行移除，已有特性的其他未来排期保留，此操作可撤销。提交成功建立新的编辑基线并清空撤销记录，不撤销 Git 提交、推送或合入。撤销/重做使用标准弯箭头图标；旁边以分隔线区分独立的恢复图标，悬停/聚焦明确为“放弃本次修改，恢复最近提交”，直接恢复最近一次提交后的基线；外部冲突时明确以新读到的材料重新开始。

| 当前情况                   | 呈现与动作                           | 结果                                         |
| -------------------------- | ------------------------------------ | -------------------------------------------- |
| 与最近提交一致、无待审记录 | 提交评审禁用，历史按实际记录启用 | 不创建无意义提交                             |
| 有未提交变化               | 撤销/重做、提交评审          | 核对只读变更摘要后提交                       |
| 已提交                     | 查看评审             | 最近提交成为新的还原基线，正式安排保持原样   |
| 待审时继续修改             | 更新评审                     | 提交更新同一评审草案，未提交部分仍独立       |
| 人工合入                   | 更新正式安排         | 只采纳已合入的提交快照                       |
| 合入后还有本次编辑         | 更新正式安排             | 更新后保留这些修改，不能把它们夹带进正式安排 |

“放弃本次修改”仅恢复到最近一次提交快照，第一次提交前恢复到进入规划的正式基线；不会撤销已提交/已合入内容。普通总览读本机主干基线，编辑读取项目材料提案与本次输入；刷新材料/评审不等于更新主干代码。提交、待合入、待更新不代表阶段成果或特性交付已完成。

复用现有 `bw/project` → PR/MR → 主干的项目材料链，不增加审批角色。正式材料从固定主干基线读取，已提交草案与应用内未提交编辑分别保存。提交前验证内容指纹、分支 HEAD、工作副本与文件修订；冲突保留草案并提示核对。只自动快进，不重置分叉或脏树。失败区分本地提交、推送与评审创建，可重试已提交内容。

应用内切页返回保留月份、编辑和视口；未提交草案与对应基线异步保存于本机 profile 文件，名称或负责人未填完也保留。正常保存不占据独立一行；只有最新快照耐久写入确认后才作为可恢复记录，尚在写入的输入不承诺强退后恢复。重启核对 Git 来源后恢复已保存输入。保存失败显式提示；基线变化保留输入并阻止静默覆盖。该缓存不跨机器同步，不替代 .bw 正式材料。撤销栈不跨重启，已提交草案和正式材料仍从 Git 重读。浏览器客户端未接入本机文件恢复，会明确提示。具体事务和数据源见 [里程碑实现设计](milestone-design.md)。

### 进入版本与返回来源

从表头版本名旁准确打开项目版本；本入口以版本为单位，不擅自挑选某个特性定位。返回恢复实际来源和视口；若从草案进入，恢复同一草案，不覆盖未提交修改。#334 的版内关联特性展开仍由其入口上下文负责。

月度规划只保存特性名称、负责人及交付安排，不创建或要求绑定特性 Issue。具体特性 Issue 与版内范围交由版本计划助手收敛；[版本总览规格](../version-overview/spec.md)的主 Issue 身份不由里程碑标题推算。宏观安排与已开始版本不一致时，提醒用户与计划助手核对，不改写历史计划。

本轮核对正式材料 version + cycleId 后打开已有版本页，提供返回项目里程碑入口并恢复草案与视口。没有明确跨屏特性关系时如实显示未关联，暂不自动展开 #334 特性卡；未进入正式材料的版本提示先合入并更新。返回参数只是页面临时来源，不是双方已确认的持久化协议。

### 旅程与验收

旅程：月度阶段成果与特性选择 → 未来版本安排 Plan / Design / Build / Test / Deploy → 首版可供部分用户使用 → 后续版本 Maintain → 使用反馈、新需求、bug 统一进入 Issue，再由版本计划关联。完整规格与体验在具体版本中收敛，不按周数自动分流反馈。

本轮原型评审重点：日轴和班/休背景可读；版本按天与阶段按半天拖动；始终保留一个特性身份；开始后原计划固定；实际未知不补绿或伪造完成；显示计划可关；撤销/重做、行排序、移除、提交快照和返回保持。生产对应证据见 [STATUS](STATUS.md)，本轮静态检查不替代真机运行。

## 取舍与共同协调

版本身份与排期复用 .bw 计划材料和 `bw/project` 评审链；本机未提交草案恢复沿现有事务设计。生产使用阶段排期结构，原型存储不能直接写入主干材料。已按确认后的高保真更新仓外实施 plan；同一交付删除被替代的节点代码，不保留两套产品路径。试用旧格式材料保留原文件并明确要求核对迁移，不悄悄推导阶段工期或覆盖旧草案。[里程碑实现设计](milestone-design.md)记录当前实现边界。

#334 负责实际阶段证据、版本目标与特性 Issue；#440 负责宏观排期和工作日历。共同协调准确身份、版本内定位与返回来源，不猜对应关系，不自行定义共享协议。尚未接入的 Deploy 保留未知；下一版本 Maintain 不成为自动完成结论。不增加规划 Skill、会话屏或独立反馈系统。

## 入口与用户旅程

指标在总览的记分牌里呈现，替代原业务／项目两区；项目研发统计（提交、合入 PR、开放 Issue）不再在总览展示。场景即指标目录里的特性，未指定特性的指标归“主要”页签，不等于项目研发指标。

## 行为与异常

### 配置与目录

定义来自 .bw/metrics.toml，沿 schema2，协议见 [metrics](../../../standard/system-prompt/references/metrics.md)。北极星可缺席，占位不成为指标。可选的 [[feature]] 声明场景名称（name）和价值说明（value），决定页签顺序；场景与说明随目录编辑，产品不写死。缺文件、坏定义、缺脚本和采集失败分别表达；feature/leads 歧义或场景重名提示修正，不随意关联。

“配置指标”每次在独立固定的 bw/metrics-refresh 分支和工作树中新建 Orca 原生会话，并离开总览进入该会话；已有同分支工作树和未完成改动保留，不续接上次会话，不另建 BW 配置面板或登记指标自动化。维护树干净且只是落后于当前基线时，读取目录会把它快进到基线，使会话改的就是记分牌上这份目录。记分牌读基线；维护分支已从该基线提交了新目录时，回到总览重读那次提交。维护工作区里的配置文件直接显示在记分牌上，和已提交内容不同时标为配置草稿；打开这个工作区时，会话在上、记分牌在下，中间的分隔可以拖动高度，文件保存后隔几秒跟上。记分牌上的批注直接发给这个指标配置会话，不再选择会话。读数仍按已提交修订采集，草稿不写入正式读数。工作树定位、创建、目录、登记和宿主路由沿用 Orca，不另设目录规则或删除重建。接入已有指标工作树时保留该项目此前接入的其他工作树；切换计划、验收后指标工作树仍可从侧栏进入。加载项目约定、通用 SYSTEM 与 metrics-refresh Skill；提示携带当前定义、来源问题和返回总览上下文，不注入 week-planning。返回时恢复原总览的指标场景页签。

定义和脚本按项目规则评审合入。目录从主干基线（主检出 HEAD，或仓库设置钉定的基线）读取最新已合入修订，不在后台 fetch，不把固定计划/验收树的旧 HEAD 当最新目录，也不向这些材料树合并指标草稿。读取失败保留原目录及其来源并显示错误，不能假报最新。配置树草稿可试采，须标明草稿，未合入前不成为三屏正式目录；主检出的新鲜度由总览「更新代码」按钮负责。

### 采集与可信度

仅 collect.kind=script 且 retro=true 的有效业务定义进入可用目录，脚本按 day/week 返回真实历史 points。retro=false、手填或仅返回当前 value 的输出均不作为可用采集；页面提示配置历史来源，不补造曲线。源数据和必要的历史存储由用户项目或外部服务负责。

刷新使用明确项目/宿主/cwd 和 argv，复用权限、失败和超时规则。相同来源/定义/窗口/宿主的并发刷新去重；切项目不串值，旧响应不覆盖新请求。成功标 value、source、collectedAt，历史另有真实窗口。失败保留可识别的陈旧证据，不换新时间、不补 0、不补前值；真实 0 有效。

首次加载读取目录及已有采集缓存，并准备最近五周、十四天所需数据。业务日／周口径分别采集，不能用日均值简单合成周均值；记分牌先回显周窗口，日窗口随后准备，准备期间不清空已得数据、不重复联网或跑脚本。仅 not-collected 的缓存缺口自动采集一次，失败不自动重试。缓存缺口及正在采集不计为读取失败，等待时显示“正在读取”；采集结束后才展示本次实际失败，无数据保持未知。之后离开再返回总览仅复用本次应用运行的快照；用户点「更新代码」（快进主检出并重读目录）或对应指标刷新按钮（重新采集）才更新。业务手动刷新维持阻塞遮罩，完成或失败均解除；来源或采集失败保留旧读数及原采集时间，明确提示失败。显示窗口固定于采集时刻，跨日／周不把缓存旧数标成今日或本周。

不引入每日采集自动化、bw/ledger 或每日 readings 写回。每次新采集解析主干基线目录，并在本次执行期间固定同一份定义、脚本及相关依赖修订；项目身份、窗口与来源随结果保存。旧计划 baseline 和归档证据保持只读，不能被刷新覆盖，也不用于阻止新采集。无可用采集可保存目标草稿并提示配置，不能标成有依据的数值承诺。

### 呈现与关联

记分牌按场景分页签：先列 [[feature]] 声明的场景，再列只在指标上出现的特性，未指定特性的指标归“主要”。每签展示一个结果（计划写了目标值的滞后指标优先，否则该场景第一条）和一个引领（leads 指向这个结果的引领，计划写了目标值的优先；没有则取未关联任何结果的引领，不借用关联其他结果的引领；仍然没有引领时，第二格展示该场景的下一个结果，并标成结果），其余指标列名提示，不被隐藏；缺结果或引领时说明可用「配置指标」补配。每个指标显示最近读数（带单位）、最近五周窗口的走势柱和口径；失败与陈旧证据保持未知并注明原因与原采集时间（有完成线时也不被输赢文案替代），无读数的走势柱与 0 值可区分，字符串读数只作文本。leads 不等于已证明因果。

聚焦由当前版本的计划推出：计划目标里给某个场景的任一指标写了非空目标值，该场景即本版聚焦，排在“聚焦”组，其余在“日常”组；完成线依次取所展示结果、所展示引领、其余指标的目标值。聚焦场景顶部一行写明「指标　从基线到完成线　截至该版验收」，基线取计划保存的 baseline，没有就只写完成线；日常场景写“日常盯防，不在本版聚焦”。输赢只由最近数值读数对比带比较方向的完成线（≥、≤、>、<、=）得出：显示“已达完成线”或“未达完成线”；完成线是纯数字、方向缺失、单位与指标不一致，或没有数值读数时显示“看不出输赢”，不装绿；完成线比较不是验收结论，目标达成仍由人确认。聚焦页签只在已达或未达完成线时标出输赢；看不出输赢时页签不重复这句话。记分牌底部常驻说明输赢怎么算，以及每周短会怎么用这张记分牌（报上周承诺 → 看记分牌 → 每人定下周一两件，承诺落成普通 Issue）；产品不另存承诺记录。

计划只写版本目标，不改项目长期目标；验收可从最新目录选择指标补充实测，实际值由脚本提供。旧 baseline 保留，不能因 definitionHash 或 configurationCommit 与旧计划不同而阻止采集。证据详情展示来源、采集时间、配置提交与采集脚本修订，定义指纹保存在材料中，供人追溯核对；界面不提供专门的定义或单位变化对比，不自动计算跨口径改善幅度或判断达成。新增验收指标不改原计划承诺。

指标依据版本从主干现行目录与有效当前计划读取，固定修订和来源校验沿原材料服务；落后的固定工作树不覆盖正式基线。读取失败与没有材料分别表达。计划/验收全文和相互引用核对在原生版本入口完成。

### 布局与动作

- 顶部沿用既有高保真的项目名片／北极星双卡结构：左侧项目名称与字段，右侧指标名称、当前值、目标和状态。缩小卡片纵向内边距与字段行距，保留字号和完整字段；高度随内容增长，不用固定高度裁切长文本。北极星不重复放刷新、配置按钮，不以“有读数”代称项目健康；缺失字段如实表达。
- 总览不再铺计划/验收全文双栏；不再放独立的指标依据版本选择器，当前版本提供指标聚焦上下文，版本全文由原生版本入口承接。页头“更新代码”快进主检出并重读现行材料，保留未提交里程碑草案。
- 内容区第一行是高效执行四原则（FranklinCovey 4DX）的一句话：聚焦至关重要目标 · 贯彻引领指标 · 设立振奋人心的记分牌 · 保持相互担责的节奏。纯排版，不是健康信号。
- 记分牌位于项目里程碑之下：标题行是记分牌，旁边是「批注」「配置指标」和一个刷新图标。「批注」打开与计划/验收相同的板面批注：点击本场景的目标行或指标记下讨论，编号角标与面板一致，可复制或发送给会话；批注只留在当次打开的总览里，重启不保留，也不改指标目录和完成线。走势固定为周窗口。刷新同时更新北极星，配置入口只保留一处。没有任何场景时提示用「配置指标」新建会话配置。
- 页面不放迁移过程、协议字段或“为什么尚未实现”的长说明。草稿、未采集、失败和数据日期等影响判断的信息保持可见，具体原因按需展开。

## 布局约束

1280 与 1920 两种窗口宽度下内容铺满 Orca 内容槽，不横向溢出。记分牌结果与引领左右并排，更窄时上下排列；场景页签过多时横向滚动。里程碑时间轴在自身区域横向滚动，特性标签固定；不在总览铺开计划/验收全文。页面本身允许纵向滚动。原型读数不是实时采集，真实 Electron 与脚本证据在实施后补齐。

实现与真实数据、Electron 验证边界见 [STATUS](STATUS.md)。
