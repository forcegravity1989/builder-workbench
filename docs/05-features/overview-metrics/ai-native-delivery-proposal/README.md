## 直接体验

打开 [prototype.html](prototype.html)，无需服务和网络，支持单独复制。按桌面窗口设计，建议宽度 1280 及以上；小屏保留桌面结构，不另造移动应用。

默认看总览，再从左侧进入计划、验收。底部评审工具条提供当前受阻、修复后、本版无材料三种示例场景，以及重置、Apple/Claude 配色。场景、人物、项目、任务、会话、读数和归档记录均为虚构，不是内部项目成绩。

## 待评审的呈现取舍

- **总览先供扫读**：项目名片保留一句价值与人员，其他字段点开看；北极星保留读数、时间窗、方向和趋势。版本计划/验收默认各用一句摘要，纪要全文按需打开。这与当前默认并列全文的呈现不同，尚待用户确认。
- **计划只展开正在编辑的目标**：目标和判据默认紧凑显示，点铅笔原位展开编辑。相对现行直接编辑的表单，这是待评审取舍。版本任务默认折叠，范围外建议明确留待以后。
- **验收围绕既有目标行**：默认显示原目标、判据、实测及人的状态；观察表、来源、运行/分发材料与首次失败记录由“证据”打开。没有新增三类证据独立大区或逐份打勾门槛。
- **保持实际动作的位置**：新建计划/验收在右板协作行，归档位于正文末尾；旅程节点只定位，归档只准备左侧未发送草稿。人的判断、材料保存、PR 合入和发布分开。

这些是现有页面上的讨论稿，不是增加新的执行器、指标页面、里程碑系统或业务流程。任务、自动化、知识库、设置及原生工具只保留入口和边界说明，本次不设计其新能力。

## 示例与可操作路径

虚构项目“客户资料导入”已有基础导入，v0.3 聚焦独立导入与自行修错两个目标。项目层的每周人数、成功导入次数及成功率是预置趋势；它们与本版三人试用分开，不以三人复测推出整体增长。

- **总览**：切业务范围与日/周；打开项目名片、指标口径和版本纪要；回看 v0.2；进入已有计划/验收入口。开放 Issue 只画当前点，不补不存在的历史。
- **计划**：展开编辑单个目标，原样保存保持旧判断；实质变更清除旧验收结论，新范围的证据显示 Unknown。延期范围外建议；展开任务；归档请求只进入示例输入区。
- **验收**：按目标查看实测，打开证据，分别记录待核对、达成或未达成。每个目标独立保存缺口与下一步，并进入纪要及归档草稿，不互相覆盖。
- **修复后**：G1 复测为 3/3，仍待人核对；首次 rc.1 的 2/3 保留。只有示例证据匹配且目标判据满足时，达成选项可用；场景切换不会代人确认。
- **本版无材料**：当前指标为 Unknown、当前目标空板，原生协作入口仍可准备请求；已存在的 v0.2 历史记录可以查看，不据此推定当前结果。
- **宿主衔接**：分隔线可拖动或用左右键调整；各工作区展示对应的精简示例历史。输入仅为草稿，没有发送按钮、真实终端、模型请求、文件操作或网络执行。所有状态只在内存；刷新恢复默认，重置恢复当前场景。

## 可编辑来源与构建

- [source.html](source.html)：桌面外框、现有左侧栏、内容槽和评审辅助条。
- [prototype.css](prototype.css)：布局与桌面尺寸适配；配色、字体、间距、圆角、阴影从共享设计系统取值。
- [prototype.js](prototype.js)：示例数据、页面和交互状态。
- [build.mjs](build.mjs)：读取唯一设计系统 styles.css、本地 CSS 和 JS，生成含 SHA-256 来源标识的单文件。

```text
node docs/05-features/overview-metrics/ai-native-delivery-proposal/build.mjs
node docs/05-features/overview-metrics/ai-native-delivery-proposal/build.mjs --check
```

不复制一套设计 token 维护，不从 CDN 加载依赖。source.html 可在仓内直接打开，独立分发使用 prototype.html。
