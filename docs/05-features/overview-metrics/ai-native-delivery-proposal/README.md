# BW 自用：从 v0.5 交付到下一次有依据的决定

> **30 秒导读与边界**：供 Builder、Leader 和设计评审者讨论已有 BW 页面的局部改进。保留 Orca-BW 导航、原生项目工作树、会话与右侧业务板关系；指标留在总览。此目录只保存未批准的设计提案，不替代父特性及版本计划/验收的 intent、spec、已确认原型或产品实现。用户要求围绕 BW 自身审视交付价值与风险；跨屏提案临时归入总览特性子目录。
>
> **结构与维护**：以下为体验入口、问题与差异、事实边界、可操作路径、来源与构建、验证边界。界面或讨论结果变化时同步；source.html、prototype.css、prototype.js 为可编辑来源，prototype.html 为生成的独立单文件，禁止手改生成物。视觉正源为 [设计系统](../../../04-design-system/README.md)。

## 直接体验

打开 [prototype.html](prototype.html)，无需服务和网络，支持单独复制。按桌面窗口设计，建议宽度 1280 及以上；小屏保留桌面结构。

默认使用 **BW 自身 v0.5 已有材料**，底部另有“下一周受阻 / 复测”两个假设演示。三者不混充真实项目成绩。左侧仍是总览、计划、验收、任务、自动化、知识库与原生工作树；计划和验收继续使用左原生会话、右业务板。

## 要回答的问题与实质差异

已有三屏具备目标、指标、材料与判断的载体，但没有因此证明 Builder 能更好地决定方向、每周稳定交付或避免风险。这个原型检验一条连接：**阶段问题 → 本版承诺 → 本周新增证据 → 人的下一步**。

| 原有基础 | 本稿待评审的增量 | 人因此能做什么 |
|---|---|---|
| 总览列项目、版本纪要与指标 | 首屏聚焦已交付、未知与一项待决定事项；周观察与阶段方向相连 | Leader 分清已知进展和证据缺口，判断需要支持什么 |
| 计划形成版本目标、拆任务 | 从 v0.5 G3 的具体缺口带入候选范围，说明服务哪个阶段判断 | Builder 确认先验证什么，拒绝与本轮无关的 Agent 建议 |
| 验收按原目标记录结论与下一步 | 判断和后续安排回到同一总览，并可携带到计划会话 | 用反馈收敛下次投入，而非完成代码即结束 |

这不是把几张屏幕等同于“成为 super builder”。方向选择、接触用户、实际执行和处理依赖仍需要人；显示 Unknown 或阻塞只帮助更早处理，不证明项目无风险。若整理负担超过收益，应减步骤、合并或删减能力。

### 为什么主要在总览加功夫

Leader 不应靠翻三屏和会话拼出项目现状。首屏只突出一个方向、三个进展信号和一个待决定事项；原始目标、口径、材料及观察约定按需展开。总览从同一版本与目标读出摘要，不另存一套“项目健康”结论。

周是观察窗口，阶段目标是版本上下文。10.16 周检与 10.30 阶段回看只是提案，不新增里程碑管理器、第二份周计划或强制定时。阻断一旦可见就处理，不等周五；已能交付也不必等周五。执行、Issue 状态、采集协议及归档仍沿用原有能力。

## 可操作路径

1. **从已有缺口开始**：总览看到“已交付，使用价值待验证”，打开 G3 原材料，辨认 0 的口径，再点“把缺口带入计划”。
2. **用阶段问题收敛本轮**：计划右板出现候选目标，关联 10.30 想判断的问题。可编辑目标及判据；“团队绩效排行”只是 Agent 建议，“本轮不做”将理由带到原生草稿。确认范围只改变原型内状态，不创建真实任务。
3. **让决定可见**：返回总览可看到已形成后续提案或已在原型确认范围；v0.5 的原记录保持只读，没有假装已经补写原验收。
4. **观察而非预填成绩**：默认下一轮验收为 Unknown。切换“受阻演示”，一项目尚未交付、主路径卡住；每个目标独立记录未达与下一步。返回总览会显示该安排，带回计划的草稿保留全部目标安排。
5. **复测不冒充持续价值**：切换“复测演示”可查看首次 1/2 及复测 2/2，由人核对目标。即使全部确认，总览仍保持持续价值 Unknown：第二周复用与整理负担未观测。
6. **变更不污染事实**：实质修改目标使本轮演示证据失效、原型范围需重认；原样保存保持结论。三页选版、各目标下一步和各工作区草稿独立。刷新/重置清空原型状态，不改真实数据。

观察约定包括实际用户反馈、可用版本、首个阻断、等待/协助与人工整理时间。最初的试点观察可作为现有验收材料；没有日/周历史脚本时，不伪装成可配置业务指标。参与项目、负责人、基线和具体日期仍需真实试点落实，不因点一次“确认”自动齐备。

## 沿用与待评审的呈现取舍

- 直接打包一份设计系统 styles.css，复用 token 及 btn/tag/sidebar/table/dialog；保留真实六项导航和原生工作树，不增加指标导航。
- 总览把大段版本纪要、已有曲线降到详情层。当前示例未重采研发活动，因此不填活动数字；这不是已批准删除产品图表。
- 阶段/周观察上下文、缺口带入计划、总结安排回总览、默认摘要与铅笔展开编辑均为本稿待评审变化。现行规格尚未改变，也没有形成新的后端契约。
- 原生会话为界面示意，草稿未发送；原生资源管理器、任务、自动化、知识库和设置保持边界说明。不新造执行器、采集账或远端状态。
