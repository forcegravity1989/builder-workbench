# intent — 经 WeLink 群发起评审（welink-review-invite）

> **30 秒导读**：Builder 在任务屏自己的 Issue 行上点「发起评审」：BW 解析该 Issue 绑定的工作树、自动拼装评审消息，经助手服务以**群助手身份**发到项目 WeLink 群——材料链接直达，评审者不用 Builder 手写通知、翻群贴链接。本篇是意图件：为什么做、做到哪为止；目标行为见 [spec.md](spec.md)，可点样张见 [prototype.html](prototype.html)，链状态见 [STATUS.md](STATUS.md)。
>
> **状态**：草案送审（2026-10-28 随 [#199](https://github.com/forcegravity1989/builder-workbench/issues/199) v0.8|G3 起草；意图 gate 待人确认）。
>
> **维护约定**：给过意图 gate 的人、审这批改动的人读。价值或范围变化、待决拍板时更新本篇；不抄行为清单，不记过程流水。

## 用户与问题

被管项目的 Builder 按逆向工作法把特性材料（intent / spec / 原型 / 高保真）写在独立工作树上，写完后的下一件事是**请人来评审**——这一步今天没有产品承载：Builder 自己组织通知，切到 WeLink、翻到项目群、手写一条带链接的消息；评审者是否知道有材料待审、有没有点开，全靠群里刷到。评审发起是版本迭代流转的关键一步（2026-10-26 版本计划会把它列入现有 5-6 个关键步骤旅程），也是周中节奏——白天对大需求发起讨论、会上批注、发给模型继续改、晚上夜跑——的起点；起点靠手工搬运，材料评审就容易拖成「谁想起来谁催」。

## 价值与依据

核心收益：**Issue 行上一键把评审邀请送到项目 WeLink 群**——工作树与材料由 BW 从 Issue 绑定解析并自动拼装，消息以群助手身份发出、材料链接直达，Builder 不切屏、不手写通知；评审者在群里直接看到「什么材料、请评审什么」。

依据：[#199](https://github.com/forcegravity1989/builder-workbench/issues/199) 由版本计划会拍板纳入 v0.8 G3（2026-10-26，范围按评审批注更新），验收条件即「可经 WeLink 群发起评审群消息（群助手承载）」；项目群配置槽位（`.bw/project.toml` `[chat]` 节）已在仓内预留。**假设（未验证）**：评审到达率与评审提速的真实使用读回还没有，多 Builder 采用后按首用周观察。

## 目标体验

Builder 在任务屏的 Issue 行（已开工、行内已见工作树标签）点开「更多操作」，选「发起评审」：发送卡打开，消息已自动拼装——Issue 编号与标题、绑定工作树分支、工作树里相对 main 有改动的特性材料清单、材料链接（有 PR 挂 PR）——下面是目标群（读项目配置）。点「发送」，主进程经助手服务以群助手身份把消息发到项目 WeLink 群；成功给回执（发到了哪个群），失败如实报原因。群里的人点开链接看材料，意见回到群里和评审会上——这一步即本版交付的旅程；意见如何回流进 BW 由后续站承接（本篇范围外）。

## 范围与边界

- **做**：发起评审旅程的设计、高保真与落地——任务屏 Issue 行入口（复用行内工作树解析，不新建页面或屏）、发送卡（消息拼装 / 目标群）、助手服务发送通道（AK/SK 认证）、消费 `.bw/project.toml [chat]` 的 `group_id`。
- **不做**：评审意见回流接收（群消息 / 会议录音文本——旅程画完整环，实现留下一站）；群文档（issue 明示延后）；`notify` 字段消费（预留）；welink-cli 个人账号通道（owner 认可的备选，本版不实现）；远程批注协作（[#447](https://github.com/forcegravity1989/builder-workbench/issues/447)）。
- **相邻**：reviewer-agent 管 MR/PR 的独立评审，本特性管**特性材料评审的发起**，两个 gate 不混；connectors 管 welink-cli 的安装登录，本特性发送通道是助手服务，不消费个人登录态；评审会与纪要链路归 version-planning。
- **序列**：#199 是两件事——本特性是第一件（发起评审：设计 → 评审 → 落地）；第二件（梳理 5-6 个关键步骤旅程对接 WeLink / 群助手，含 PR #446 设计建议）在第一件落地后头脑风暴、另立特性文档（owner 2026-10-28 定序）。

## 成功判据与待决问题

**判据**：一台配好群与助手服务的机器上，Builder 从任务屏 Issue 行发起评审到项目群收到群助手消息（链接可点开材料）全程不手写通知；发送失败如实可见；杀进程重开，群配置仍从 `.bw/project.toml` 读回，不出现假绿。验收点见 spec 验收表。

**待决（会改变行为的，随 spec 送审）**：助手服务接口契约（消息格式、附件能力）实现期由 owner 提供；AK/SK 本机配置落点（环境变量或本地文件，配置 UI 不在本版）——详见 spec 取舍与待决。
