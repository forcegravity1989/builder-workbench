# spec — 经 WeLink 群发起评审（welink-review-invite）

> **30 秒导读**：行为与验收正本——入口在任务屏 Issue 行「更多操作」菜单，BW 解析该 Issue 绑定的工作树、自动拼装消息（Issue ＋ 工作树材料），发送卡预览组消息、读 `[chat]` 群配置，经助手服务（AK/SK + WebSocket）以群助手身份发送；状态如实，不装绿。给交互设计、实现与验收的人读；行为变化、拍板或验收证据更新时改本篇。来源 [#199](https://github.com/forcegravity1989/builder-workbench/issues/199)（v0.8|G3，2026-10-26 范围批注）；意图见 [intent.md](intent.md)，可点样张见 [prototype.html](prototype.html)，链状态见 [STATUS.md](STATUS.md)。整篇状态：**草案送审，规格 gate 待人确认**。

## 范围与入口

- **入口**：任务屏 Issue 行行尾「更多操作」下拉菜单项「发起评审」。仅该行解析到**唯一**绑定工作树时呈现；无绑定或多候选不呈现（不猜树）。GitHub 与 CodeHub Issue 行同构；PR 行不设入口。
- **不新建页面或屏**：动作长在既有任务屏行内；发送卡是该动作弹出的对话框，用完即关。
- **相邻界面区分**：计划屏「批注」发送给计划助手（屏内会话），本特性发送给 WeLink 项目群（外部群消息），入口与文案不共用；集成页（connectors）管 welink-cli 个人登录，本特性不读它。
- **原型覆盖与限制**：[prototype.html](prototype.html) 覆盖主路径与异常状态（未配群 / 服务未配置 / 发送失败），任务屏与行内菜单为示意（不重绘原生屏全貌，仅标入口位置），发送为演示假体不真发；顶部评审切换条为评审工具，不属产品 UI。

## 完整用户旅程

主路径：

1. Builder 从 Issue 开工（既有链路），在绑定工作树上完成特性材料（intent / spec / 原型 / 高保真，已 commit）。
2. 任务屏该 Issue 行呈现工作树标签；点行尾「更多操作」→「发起评审」→ 发送卡打开：消息预览已按 Issue 与工作树自动拼装（Issue 编号与标题、工作树分支、有改动的特性材料清单、材料链接），目标群显示 `.bw/project.toml [chat]` 的 `group_id`。
3. Builder 核对预览（只读）。
4. 点「发送到群」→ 主动作禁用、过程文字「正在发送…」。
5. 成功 → 卡内回执：已发送到 WeLink 项目群（群 ID），消息摘要可见；关闭发送卡。项目群里出现**群助手身份**的评审邀请消息（Issue、评审材料、材料链接）。
6. 评审者点链接读材料，意见回到群里与评审会（回流接收为下一站，本版不收）。

分支与出错见「行为规则与异常」。

## 行为规则与异常

### 工作树解析

- 复用任务屏行内既有解析核（与 Open/Start 同一归属证明）：范围视图 Issue 按 (version, issue, taskSource) 绑定＋原生 linked 双重证明；无范围视图 GitHub 按原生附件语义（首个未归档 linked 树）；CodeHub 无范围不呈现附件、亦无入口。
- 唯一 → 呈现「发起评审」；无绑定或多候选 → 不呈现。多候选属异常态，本版不猜树、不弹选择器。

### 材料识别

- 发送卡自动识别绑定工作树 `docs/05-features/` 下相对 main（默认主干）有内容改动的特性目录，按实际存在列出材料文件（intent.md / spec.md / prototype.html 等）。
- 工作树没有 `docs/05-features/` 目录、目录为空或无改动时，预览如实空态：「工作树没有特性材料改动」，发送禁用。

### 消息组装

- 消息为纯文本，五行结构：①【发起评审】#<Issue 编号> <Issue 标题>；②工作树：<分支名>；③评审材料：逐特性目录列材料清单；④材料链接：工作树分支有开 PR/MR 时挂 PR/MR 链接，否则挂分支文件的仓库 web 链接；⑤消息末尾一行「请评审后在群内或评审会上给出意见」。
- 预览与实发内容一致；预览只读，材料范围不提供手动增减（取舍见文末）。

### 群配置

- 唯一正本：`.bw/project.toml` `[chat]` 节（`provider` / `group_id`）。发送卡只读展示；`provider ≠ welink` 或缺 `group_id` 时按「未配群」处理。
- `notify` 字段本版不消费，预留。
- AK/SK 与服务地址不入仓：本机配置（落点待决），主进程读取；缺失时按「服务未配置」处理。

### 发送通道

- 主进程经助手服务发送：AK/SK 认证，WebSocket 接口，目标群用 `[chat]` 的 `group_id`；消息身份为群助手。
- 接口契约（认证细节、消息格式、附件能力）实现期由 owner 提供，实现不得先于契约臆造协议。

### 状态与异常

| 状态 | 呈现 | 发送 |
|---|---|---|
| 就绪 | 消息预览 + 目标群 | 可 |
| 未配群 | 行内警示：项目群未配置，指向 `.bw/project.toml [chat]` | 禁用 |
| 服务未配置 | 行内警示：助手服务未配置（服务地址或 AK/SK 缺失），给配置指引 | 禁用 |
| 发送中 | 主动作禁用 + 「正在发送…」 | — |
| 成功 | 回执：已发送到 WeLink 项目群（群 ID）+ 消息摘要 | 关闭 |
| 失败 | 行内错误：原因 + 「重试」 | 可重试 |

- 失败如实报原因，不装绿、不留假回执；重试复用同一消息内容。
- 发送是显式动作：卡内点「发送到群」即发，无二次确认；取消 / 关闭不是 destructive。

### 权限与边界

- 发送不回写任何评审状态：不建台账、不改 Issue、不标「已评审」；评审结果由人在群里 / 会上给出。
- 不代人确认完成（四铁律）；发送记录不留本地库（零业务数据库）。

## 验收与衡量

验收点（真壳，截图四件套随 PR）：

| # | 验收点 | 可观察结果 |
|---|---|---|
| W01 | 群配置读取 | `[chat]` 配好时卡上显示目标群；缺失时如实提示并指向配置，发送禁用 |
| W02 | 入口与工作树解析 | Issue 行解析到唯一绑定工作树时呈现「发起评审」；无绑定 / 多候选不呈现；PR 行不呈现 |
| W03 | 消息组装 | 预览与实发一致：Issue 编号标题、工作树、材料清单、链接（PR 优先）；无材料改动如实空态、发送禁用 |
| W04 | 发送成功 | 群助手身份消息到达配置群，链接可点开材料；卡内回执群名 |
| W05 | 发送失败 | 服务未配置 / 网络失败如实报原因，不装绿，可重试 |
| W06 | 重启读回 | 杀进程重开，群配置仍从 `.bw/project.toml` 读回，无假绿 |

旅程（WJ01）：配置群与服务 → 任务屏 Issue 行发起评审 → 真实测试群读回群助手消息 → 链接打开材料。

衡量：本版不挂指标；首用周观察「评审发起到首条评审意见」的间隔，口径后续按[指标协议](../../../standard/system-prompt/references/metrics.md)再定。

## 取舍与待决问题

**已定（owner）**：

1. 评审对象＝特性材料评审（intent / spec / 原型 / 高保真），非 MR 评审。
2. 通道＝助手服务（AK/SK + WebSocket，群助手身份）；welink-cli 个人账号为认可备选，本版不实现。
3. 群配置＝`.bw/project.toml [chat]`（既有槽位开始消费）。
4. 落地范围＝只发起；回流接收留下一站。
5. 入口＝任务屏 Issue 行「更多操作」（2026-10-28 owner 纠正首稿：不新建页面，评审动作跟着 Issue 走，工作树由 Issue 绑定解析得出）。

**已弃**：

- 版本工作区动作区入口（首稿设计）——owner 2026-10-28 纠正：那是版本级动作区，评审对象是单 Issue 的工作树材料，入口不跟着版本页走。
- 材料范围手动增减（首稿勾选 UI）——按「拼接信息就行」收敛为自动拼装、预览只读，需要再议。
- 会话内代发（助手调工具发消息）——UI 改动最小，但 issue 要求的「用户旅程设计与高保真」交付物落空，发送成败埋进会话。
- 知识页入口——知识页读主工作副本，评审中的材料常在分支 / 工作树，视图对不上。
- welink-cli 个人账号主通道——消息身份是个人、依赖个人登录态；助手服务贴验收原文「群助手承载」且免扫码续期。
- 消息正文可编辑——MVP 预览只读，组装口径稳定后再议。

**待决（实现期输入，不阻塞规格 gate）**：

1. 助手服务接口契约（认证细节、消息格式、附件能力）——owner 提供；附件（原型文件 / 截图）支持才做，否则只发链接。
2. AK/SK 本机配置落点（环境变量或本地文件）——配置 UI 不在本版。
