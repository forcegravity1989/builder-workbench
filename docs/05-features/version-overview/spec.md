## 高保真与原有旅程

- [高保真](prototype.html)与[意图 / 审阅旅程](journey.html)是当前唯一入口；源码在 prototype/overview-app.jsx、overview-components.jsx、overview-data.js 和 CSS。运行 node docs/05-features/version-overview/prototype/build-overview.cjs 更新生成物，--check 核对一致性。生成物已入库，可从仓根静态服务直接预览。
- 复用设计系统、version-workspace 的壳样式与 IconAction、version-planning 冻结 vendor；不复制公共资产。侧栏保留当前项目、知识库、“新建版本”入口、平铺版本、总览 / 计划 / 任务 / 目标 / 验收及原生工作树，窄窗缩宽但不隐去；完整菜单、宿主和会话保持原生能力。
- 所见即所得：产品内容使用拟交付的名称、来源、空态与动作。评审工具、模拟或复用边界、尚未接线说明统一以“原型注释:”开头，不混作产品状态。右上角小文档弹窗记录业界来源及采用范围。

## 三种版本生命周期

顶部情景下拉至少包含以下三种。此选择是原型评审工具；实际产品从侧栏版本上下文进入，不新增第二套产品选版器。

| 情况 | 高保真数据 | 页面行为 |
|---|---|---|
| 版本计划未制定 | v0.9 是未创建版本的布局示例，已标原型注释 | 保留 BW 壳和计划 / 任务 / 验收入口；主区明确计划未制定，提供“开始制定版本计划”，关联既有计划短卡、原生会话及计划板旅程；不伪造目标、任务、负责人或交付比例 |
| 版本计划制定完（版本中） | v0.8 正式计划与 GitHub Issue / PR 固定快照 | 呈现完整 G1–G4 承诺和责任人；分别展开大需求的整体目标、本版范围、成果与待审事项；G4 展示真实任务，未读会话和缺失试用证据保持未知 |
| 版本交付后 | v0.7 已归档验收及其 planRef 指定的计划 | 显示当时承诺、逐目标人工结论、候选包 / 报告 / 发布与归档；后续补丁和下一版另列，不能用后来状态覆盖历史。已归档不等于所有目标达成 |

版本生命周期与大需求的 SDLC 含义不同。需求可以跨版，也可以回到设计修改；不将计划 / 验收 workflow.stage 作为需求阶段，不因切换情景生成状态或重复人工验收。

## 信息层级与真实数据

基础信息保留版本、目标、负责人、范围、确认时间、交付时间、任务、计划 / 验收及纪要、归档、发布入口。缺失截止时间保持“计划未记录”，不从按周反馈推算日期。首屏对照本版承诺与当前成果，完整 G1–G4 可达；两个总览是 G2 的需求，不代替整个版本。

大需求分别显示整体目标、本版承担、当前工作及下一步。按意图、设计 / 高保真 / spec、Plan、开发、测试、上线 / 试用组织成果，允许评审后返回修改；不把六类成果当审批链或百分比。每项成果可核对来源、修订、评审状态与打开入口；待审列表直接指向具体成果。当前 #334 / #440 均为实际设计 Draft PR，不为了表现不同阶段编造某项已试用。

MVP 试用需要候选包 / 部署、提交、适用范围、使用者、验证边界、已知问题与反馈 Issue。当前没有 v0.8 对应证据，呈现缺失空态；不能拿 v0.7 包冒充。未来先行 B 可向部分用户开放，后续 B 按反馈修理；实际范围由人确认。

小任务详情提供“继续处理此任务”，携带完整 provider / repository / number 与本版 G4 上下文，沿既有任务开工、工作区选择和会话能力；会话未知时不猜测已存在的会话，也不自动建树。

小需求与 bug 按 v0.8 G4 任务引用读 GitHub 原生 Issue；关闭只说明该 Issue 的处理状态，不能推导版本或大需求达成。会话未读时“执行中 / 待处理”过滤明确未知，不用开放 Issue 补造会话状态。“已有结果”当前仅列源端已关闭项。PR 线索来自每条 Issue 最近 12 条交叉引用（排除计划归档），必须明示有界范围与提及关系，不自动当作该问题的修复 PR；成果与可用性仍需逐项核对。

数据文件 prototype/bw-snapshot.json 是本轮只读样本，不是业务 schema。source 记录读数时间和提交；正式 v0.8 计划固定在主干 90952d9，v0.7 计划严格按验收 planRef.sourceCommit 读取。GitHub 的 Issue、Draft PR、CI 和 release 是该时点快照，页面不持续联网。当前任务分支的设计文件另行标识，旧修订 CI 通过不证明当前改稿或 MVP 可用。Git worktree 只证明分支 / 路径，不证明 BW 的宿主登记和会话。

### 正式承诺与未合入成果的可见方案

以下是待主会话协调的读取方案，不是新增持久化协议。当前 `version-overview-materials.ts` 经版本目录固定 `sourceCommit/revision`，通过 `nativeVersionHistoryPort` 读取主干已提交计划/验收，再按 `archivePr` 薄读归档状态；没有 PR 分支文件、阶段成果或发布结果装载。`VersionGoalSchema` 已有 owner/deadline/deliverable，任务引用有 provider/repository/number/goalId，尚不能直接表达跨版需求、成果修订及其评审关系。生产页仍为表格汇总。

| 信息             | 建议来源与规则                                                                                                       | 失败与冲突                                                                                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 正式承诺         | 沿已确认且已合入的计划修订，保留 commit、revision、cycleId；只读投影                                                 | 没有正式计划显示承诺尚未确认；草稿入口可见但不补造承诺                                                      |
| 计划修改草稿     | 沿本版绑定计划树已有材料端口读取，与固定承诺并列说明差异                                                             | 没有权限/宿主不可达如实提示；不回退猜另一台机器的路径                                                       |
| 未合入成果       | 从明确关联的任务/PR 和原生已登记工作树出发。PR 文件固定 head SHA；本地草稿标宿主/工作树/文件及读取修订，保留脏稿身份 | 多 PR、多宿主或多个候选修订明确列出供选择；不按名称、最新时间或 G2 猜唯一成果。尚未建立明确关联时显示未记录 |
| 评审结论         | 绑定具体成果和修订的人工意见/认可，PR Review 与规格认可分开                                                          | head 更新后旧认可不能自动覆盖新修订；会话结束不构成认可                                                     |
| 测试、试用、上线 | 实际报告、候选提交/包、访问入口、用户范围和运行环境分别核对                                                          | CI 通过不等于可用；没有入口/环境证据保持未知；不自动创建公开部署                                            |
| 日常任务         | 沿任务源原生 Issue/PR 读取；会话与工作树沿已登记绑定定位                                                             | 关联缺失与远端读取失败分开；不把“无匹配会话”当已完成                                                        |
| 历史验收         | 沿现有 committed planRef 与验收材料修订读当时承诺、人工结论和当时证据                                                | 历史读回失败不以当前材料顶替；当前 Issue/PR 动态另列，不覆盖历史                                            |

每条最新成果应能核对“来源对象、文件/链接、修订或 head、读取时间、是否未提交、是否过期/读取失败”。只读聚合不另存完成状态；具体发现/关联载体、刷新触发与缓存策略在共享对象决定后再定。后续需先验证现有原生 PR/文件读取、provider 和宿主路由是否足够；仅当确须改变核心/协议/路由才提出技术方案，不先另造通道。

### 现有导航与工作会话

沿 #455 的项目进入定位、完整原生任务页和工作树行。项目总览链接由 #440 承接；进入版本总览不激活或恢复工作树。计划/验收走 `navigateVersionWorkflow`，任务走 `openVersionTasks`；目标筛选仍限本版目标，不改变完整任务源。成果评审打开文件/PR 对应的原生预览与评审面；继续工作沿现有任务开工和 `activateVersionWorktree`，保留项目、任务来源和宿主身份。唯一匹配直接打开，多实例使用已有工作区选择器；无匹配使用原生创建器，不后台建树。不能将两屏页面参数或临时演示对象直接当持久化契约。

历史回看固定当时承诺和一次正式人工验收。B 版本跨周仍是同一次正式验收；设计评审、批注、试用反馈分别保留，不能累计成验收轮次。版本收尾和删除树沿现有行为，Git 材料仍可读；不能承诺删除树后恢复全部会话。

## 验收点与共同旅程

共同旅程仍为月度选择 → 先行 B MVP → 部分用户试用 → 后续 B 修理 → 后续 Issue 持续改善；三个版本生命周期为进入和回看的外层情景。月度选择由 #440 承接，计划、验收与工作会话复用现有旅程。B 版本按周反馈、必要时跨周，每版仅一次正式人工验收。

| 判据 | 浏览器原型检查 | 后续产品验证 |
|---|---|---|
| VO1 承诺与最新成果分源 | 真实固定计划与当前设计分别可开 | 固定 / 草稿端口独立读回 |
| VO2 大需求与本版范围分开 | 展开两项需求与成果类别，不编造阶段 | 真实材料、跨版关系与修订核对 |
| VO3 成果 / 评审 / 会话可达 | 打开真实文件与 PR，原生复用说明有前缀 | 真实预览、评审、宿主与会话 |
| VO4 试用边界与后续改善可分 | 缺 v0.8 试用依据时不借旧包填充 | 包 / 人群 / 环境 / Issue 对应 |
| VO5 小任务不误判完成 | Issue 开放与会话未知分开；已关闭有来源 | provider / 会话 / 运行结果读回 |
| VO6 历史固定 | v0.7 planRef、人工结果、交付候选独立于当前编辑 | 历史材料与当前状态隔离 |
| VO7 缺证据未知 | 会话筛选和试用空态说明缺失 | 断链、权限、失败与过期 |
| VO8 可编辑可审阅 | 临时编辑刷新还原、历史只读、参考弹窗及原生批注 | 内部原生浏览器批注由人使用 |
| VO9 三种生命周期 | 未计划有下一步、版本中有成果、交付后有人工结论 | 实际新建 / 版本导航 / 归档 |
| VO10 保留 BW 上下文 | 宽窄窗侧栏均可见，原页面入口可定位 | 隔离 Electron 与真实旅程 |

本轮不新增 UI 单测。浏览器 / 静态检查不代表真实 Electron、provider、权限、持久化、会话和模型行为已通过。完整高保真和规格获人确认后，才在同分支 / PR 继续生产开发。

### 带可见方案交主会话的选择

1. **跨版身份**：建议用现有特性文档身份为大需求锚点，完整 Issue 引用作为任务关联；原型暂以 #334/#440 区分。版本总览已由用户明确独立为特性；跨版任务关联及其他特性的身份由主会话协调。G1/G2 只是本版目标序号，不能作跨版需求身份。
2. **B 版本关系**：建议同一需求分别说明每版承担的增量和后续候选；不自动创建 B 版本，不把未确认 MVP 范围写进归档计划。v0.9 未计划空态不决定月度与 B 编号，也不创建版本。
3. **导航与公共资源**：建议 #440 从需求/版本打开本版总览并定位需求，返回保留月度上下文；精确导航参数由主会话统一。双方复用现有设计系统及冻结 vendor，本轮仅复用工作区壳样式和图标动作，未提取/搬迁共享壳源码。
4. **成果可见性**：本稿推荐未合入成果与正式承诺同屏分区，详情揭示来源与修订；待审入口定位具体成果。需要评审信息密度、默认展开范围与关联缺失时的补充入口，不能在两窗口分别发明状态文件。
5. **MVP 边界**：本稿推荐先做单项目只读聚合与现有工作入口；跨宿主写入、全量阶段自动推断、远程批注系统均未纳入。实际试用人群、候选包与验收标准仍待人确认，当前原型不编造此类记录。
