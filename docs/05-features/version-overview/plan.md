1. **口径（已确认）**：周期起点为首次计划 PR 合入所在周周一 09:00 的固定基线；意图确认取计划 PR／MR 合入，不取纪要确认；设计 PR 合入定稿；开发 PR 合入优先、没有可识别开发 PR 时用特性 Issue 关闭兜底；首次与第二次符合计划关联／目标人工达成的交付分别称 Pre／Release。临时版可承接，未知不补造，同目标多个特性暂沿整体目标结论。
2. **原型与规格（本轮交审）**：修订 11 保留现有壳、目标与原生入口，以同一横轴呈现六节点、五段历时，以及按计划随版／错过目标版后临时版承接两条标明模拟的路径。同步 intent／spec／journey／STATUS，外观经用户确认后实施，不将原型证明为生产能力。
3. **统一实现（待外观确认）**：在本任务完成计划 PR 时间、设计／开发交付、Issue 关闭兜底、Pre／Release 与五段历时的读取、独立解析和展示；复用 GitHub 现有回链以及 CodeHub 的正文链接／原生工作树关联。内部 CLI 反查若缺实现，仅留独立来源函数返回未知与原因，内部助手补函数；不把整屏开发交出，不用 `updatedAt` 猜关闭时间，不解析会话。
4. **验证与交付（待实施后执行）**：维护受影响核心解析／协议检查，按实际接线复验用户旅程；分别做四维及静态 Bug／Plan／原型一致性／证据口径检视。沿 workbench-start 的六项反馈口径提取、标注并维护同一条 PR 指标评论；未知不填零，不以脚本存在称统计接通。验证、提交、push 与 PR 报告仍沿本分支，不合入 PR 或关闭 Issue。
