## 六节点与 workflow 报告增量

1. **时间与范围（已确认）**：周期起点为首次计划 PR 合入所在周周一 09:00 的固定基线；意图确认取计划 PR／MR `mergedAt` 时分，设计 PR 合入定稿；开发 PR 合入优先、没有可识别开发 PR 时用特性 Issue 关闭兜底。目标人工达成只决定是否交付，Pre／Release 时点统一取对应验收 PR／MR `mergedAt`；缺引用、未合入或缺时间保持未知，人工决定继续原位显示。未登记临时出包不自动发现；有明确版本关联、达成与验收合入才识别。单目标多特性暂沿整体结论。
2. **原型与规格（按批注收口）**：修订 13 保留原壳、目标任务入口和人工验收徽标；删除目标范围入口／弹窗、轴工作会话按钮和过程详情面板，在轴／悬停显示六节点五历时，轴下列全部采集来源。AI 面板展示 PR #505 的真实六项报告样例，明确 Issue #469 未纳入固定计划、不计本版汇总。同步 intent／spec／journey／STATUS，按已有批注和实现决定统一落地，不再重复请求总批准；生产已按这些决定接线，原型模拟数据未导入产品。
3. **统一实现（已完成）**：完成时间来源、独立节点／区间解析、来源行和目标布局；页头删除原始计划 JSON 重复入口和常驻时区，版本刷新收进标题工具栏，AI 刷新独立保留。历史截止同步取本版验收 PR 合入时间，缺失保持未知，不用人工决定时间截掉本版交付。复用 GitHub 回链及 CodeHub 正文 MR 链接／原生工作树关联。生产 AI 仅读取当前版本目标内 Issue 关联 PR 评论，按 workflow 正本归并同任务多 PR 的报告，缺报告／缺覆盖未知，不扫描或自动纳入外部任务。基础与 AI 分别刷新，使用来源范围和修订隔离的内存缓存，失败保留同范围旧值及截至时间；不加数据库、不设任意 TTL、不因渲染全量请求。内部 CLI 反查若缺实现，仅留独立未知函数给内部助手补齐；不把主体开发交出，不用 `updatedAt` 猜关闭时间，不读会话正文。
4. **验证与交付（收尾复验中）**：维护受影响核心解析／协议检查，复验验收 PR 时间、未登记交付未知、全部来源入口和 AI 目标范围／去重／覆盖／缓存／独立刷新及错误保留路径；分别做四维及静态 Bug／Plan／原型一致性／证据口径检视。沿 workbench-start 提取、标注并维护同一条 PR 反馈评论，不把 PR 合入视为首次人审通过。验证、提交、push 与报告沿本分支，不合入 PR 或关闭 Issue。
