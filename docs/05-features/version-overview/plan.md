## 本轮原型与设计收口

- [x] **D1 原型与正本同步**：统一 Plan / Design / Build / Test / Deploy / Maintain。Plan 是意图收敛，详细实施 Plan 属 Build；保留原采集依据。首版改称首次交付，后续明确关联版本承接 Maintain，取消特性 Pre／Release 二分。Deploy 未跟踪，不画假时长。Maintain 按用户确认从首次交付连续统计到后续关联版本验收，包含中间等待；不以 Deploy 未知阻止呈现。同步 intent/spec/journey/STATUS、参考弹窗与版本标记。
- [x] **D2 原型检查与独立检视**：构建和生成一致性、受影响格式/lint、三个版本场景及交付样例的静态检查；两位 subagent 分别做四维和静态 Bug/原型一致性/证据口径检视。仅原型和文档增量不启动 Electron、不操控浏览器、不截图。
- [x] **D3 交付审阅**：给出修订 14 预览与关注点，提交/push 至 #474，更新验证报告。说明生产仍为上一口径，待人批注；不自动合入、关闭 Issue、确认目标或发布。

## 原型确认后的生产迁移

- [ ] **I1 同源事实边界**：与 #440 对齐已有 provider/repository/Issue 身份、版本及目标引用、计划与验收材料来源、PR 角色与时间。宏观规划项由版本计划细化时建立显式关系，缺关系保持未关联。先复用现有 `version-overview/` 读取和纯解析形成只读事实投影，不另建采集器或持久化 schema；字段/API 形状需双方实现协调，原型字段不是协议。
- [ ] **I2 替换阶段解析与 UI**：将旧首次 Pre/第二次 Release 分类替换成首次交付与可连续延展的 Maintain。Plan/Design/Build/Test 沿已确认 PR/Issue 与目标验收规则，Deploy 返回明确未跟踪；不按 PR 次序或发布记录补点。历史截止、失败/缺失及当前缓存范围保持原边界，更新原有核心解析检查，清理旧分类和对应文案，不长期并存两套路径。
- [ ] **I3 复验与交付**：复跑受影响纯函数/协议与现有真实 Electron 旅程，对照新原型核对时分、比例、首次及后续交付、Deploy 未知、未关联/未达成/缺证据、重载及进程重启读回。四维与静态 Bug/Plan/原型一致性独立检视后修复、提交、push；同步 STATUS 和验证报告，旧证据与新证据分开。
