读懂一条特性历程

Plan 从首次计划 PR 合入所在周周一 09:00 的统计基线开始，到计划 PR 合入结束。Design 对应 intent、spec 与原型共同评审，明确设计 PR 合入标记定稿。Build 包含详细设计、实施 Plan 和开发，以明确实现 PR 合入优先，没有可识别实现 PR 才用特性 Issue 关闭兜底。

Test 从 Build 结束到目标人工达成且验收 PR 合入，代表验收前交付区间。后续明确关联版本继续完善同一特性时，Maintain 从首次交付连续计至后续验收，包含中间等待。实际历时包含评审和等待，不是人工工时。

Deploy 没有实际部署时点时提示未跟踪。后续默认长度为 Plan 1 天、Design 2 天、Build 半天、Test 1 天、Deploy 半天、Maintain 1 天；只作视觉占位，不生成日期承诺，也不把 Maintain 的真实起点推迟半天。

横条每阶段只打开一个明确来源，缺来源提示未记录；交付卡片保留实际版本号和时分。特性是否随版交付同时需要计划关联、目标达成和验收 PR 合入，其他版本发布不会自动补出交付节点。

定位特性与关联版本

主 Issue 使用“特性”标签，执行 Issue 通过【特性#334】这样的标题引用明确归属。一个目标可包含多个特性，每个特性单独呈现。关联版本用同一主 Issue 确认，不按名称、目标序号或日期猜测。

关联版本是一排版本号标签，悬停看一句范围，点击进入对应版本。项目总览从版本表头进入准确版本；有明确特性引用时可定位卡片，返回沿原有来源上下文。

读懂 AI workflow 生产力

只统计本版目标内 Issue 的 PR 报告。小需求／bug 一个 Issue 对应一次开发交付和一份报告，新开发另开 Issue。六项指标口径沿 workbench-start 真实任务反馈。

主值如 1/4 表示四项有明确结论的任务中，一项有人介入；右上角 2 轮表示这些任务累计两轮。分母按每项指标自身的记录覆盖计算，有报告不代表六项都已有结论。开工额外输入只按任务计数；返工主值统计首次人审退回任务，右上角统计已完成返工轮次。

首次进入后台读取，随后复用缓存；面板内刷新独立重读指标。失败保留同范围上次读数与截至时间，并显示错误。缺报告、待审或覆盖不足保持未知，PR 合入不能推出首次人审通过。

原型注释: PR #505 的单任务快照用于展示读数。其 Issue #469 不在这份固定 v0.8 计划内，样例不计本版汇总；刷新仅重读原型快照。
