同一特性，从设计走向随版交付

周期起点 → 意图确认 → 设计定稿 → 开发交付 → Pre → Release。周期起点取首次包含该特性的计划 PR 合入所在周周一 09:00，延期不重置；计划 PR 合入时分代表意图确认，不使用纪要确认时间。设计 PR 合入代表 intent、spec、原型联合评审定稿；开发 PR 合入优先，没有可识别开发 PR 时才用特性 Issue 关闭时间兜底，保留来源。

相邻节点形成意图收敛、设计评审、开发、测试与随版准备、试用完善五段日历历时，按实际时间比例呈现，端点显示日期、时分与时区。周期基线不是实际开工，历时包含等待，不当作人工工时或独立测得的测试耗时。采集来源行集中列出计划 PR、设计 PR、开发 PR、Pre 验收 PR、Release 验收 PR；没有记录就保留缺口，未来可沿同一入口查看 Issue 或 Release 等真实来源。

正式计划包含特性主单或执行单，目标人工达成决定本版是否计入交付；对应验收 PR／MR 已合入且有 mergedAt 时分，才形成交付节点：第一次称 Pre，第二次称 Release。缺 PR、未合入或缺时间均保持未知，不拿目标人工确认时点补齐。人工决定来源、时间与后续处理仍在目标原位回显，验收 PR 合入也不冒充独立核验的包发布时间。同目标多特性暂沿整体结论，个别例外不能区分。

原型注释: 按计划随版是明确标注的模拟历程；延期而未登记临时出包时，只显示 Pre／Release 未记录，不自动发现或补造 v1.0.1。只有明确临时版本计划关联、目标人工达成和验收 PR 合入记录齐全时，才能按同一规则识别临时版交付。每周一版、两版完成只是规划默认值，不是发布证据。
