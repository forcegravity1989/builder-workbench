大需求与反馈只有一条任务路径

选择需求与目标版本 → 先行版本 Pre（MVP） → 部分用户试用 → 后续版本修理完善 → 后续 Issue 持续改善。进入下一版时，计划明确这个需求本版继续承担什么，具体反馈、新需求和 bug 都通过 Issue 关联到相应目标。

MVP 的版本、包和开放范围留在发布成果里；大需求聚合本版任务与成果，不再保存第二份反馈清单，不按两周以内或以后分流。每版只有一次正式人工验收。

阶段采用意图规划、设计、开发、测试、上线、反馈维护，允许并行与回返。Pre 即 MVP 试用交付，Release 为正式交付，均在上线阶段标记。图中有证据的区间显示历时，不能把等待或跨阶段重叠当纯工时；实际起止缺失时留空，可切换明确标注的完整历程示例审阅效果。
