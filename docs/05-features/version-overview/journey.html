同一特性，从设计走向随版交付

已有 Issue → intent、spec、原型一起准备并评审 → 设计 PR 合入 → 会话中的详细设计、Plan 与开发 → 实现 PR 合入 → 随版本发布 Pre → 试用反馈、修理与回归 → 随后续版本发布 Release。

两个 PR 提供设计与开发的结束节点，不强制拆两个 Issue。测试与修复记录在实际发生的时段，合入后等待出包不全部算成测试时间。阶段时间按小时比例，端点显示时分；点击轴上过程只打开对应 PR／工作会话，资料通过 PR 文件或会话目录查看。

项目版本可因其他目标完成而正常发布，此特性未必随版交付；Pre 与 Release 必须有实际包含范围。所有反馈进入目标关联的 Issue，每版仍只有一次正式人工验收。

特性与目标关系保持清楚

主 Issue 使用“特性”标签，执行 Issue 用标题【特性#334】明确归属。目标下只有执行单时也能定位主特性；未识别到特性则使用普通任务入口，不改目标名称。现有 Feature 任务类型不自动当主单标记。

关联版本是一排版本号标签，悬停看一句范围，点击定位对应版本；项目总览进入后可沿来源返回，规划草案仍保留。版本按项目实际名称讨论，不强制 C/B 或月／周分组。
