版本里面，大需求怎样持续推进

月度选择 → 先行 B MVP → 部分用户试用 → 后续 B 修理完善 → 后续 Issue 持续改善。

月度选择由 #440 项目总览承接；进入版本后，按意图、设计 / 高保真 / spec、Plan、开发、测试、上线 / 试用组织成果。评审可以返回修改，大需求可以跨版。B 版本按周反馈、必要时跨周，每版仅一次正式人工验收。

原型注释: MVP 人群、包和使用反馈需要实际证据。当前 v0.8 尚未记录完整试用依据，因此呈现空态；后续收到真实反馈后再补到对应版本和 Issue，不用情景模拟冒充已经交付。

原型注释: 审阅边界与落地

高保真目标是可用于最终实现的保真方案。当前只更新独立特性资料与浏览器原型，未修改生产代码、共享持久化协议或 BW 运行时。跨版身份、B 版本关系、公共资源与共享导航由统筹会话协调。

完整高保真和规格经人确认后，在同一分支 / PR 继续生产开发；真实 Electron 验证使用隔离实例。设计参考在高保真右上角小文档弹窗。
