# 会议助手：让 BW 会议结果回到工作模型

> 给 Builder、Leader 和评审者读取。本文只定义 G2 的用户价值、范围和边界；行为与验收见 spec，原型见 prototype.html。当前仍是原型阶段。

## G2 要解决的问题

WeLink 负责群通知、视频会议和正式纪要，但它不天然知道 BW 当前项目、版本、worktree、固定会议规则和结果写回位置。BW 的项目助手或验收助手又各自只知道自己的工作上下文，不能承担跨项目、跨团队、不同会议类型的统一定会入口。

用户需要在当前 BW 工作里完成三件事：

1. 用一句话按固定会议规则定好会议；
2. 从 BW 快捷打开 WeLink 会议网站；
3. 会议结束后把确认的结果带回当前 BW 工作模型。

## G2 价值

BW 会议助手的价值不是重画一个视频会议工作台，而是把 BW 工作上下文交给一个能定会、打开 WeLink、再写回 BW 的助手。

从项目 worktree 发起项目原型评审时，助手已经知道当前项目、版本、原型、验收标准、默认参会人和固定会议规则。用户发送一句话后，助手可以直接给出预约结果。会议结束时，助手知道结果应该回到哪个项目和版本。

WeLink 群空间助手仍然负责群和会议事实。它可以成为会议执行入口，但需要 BW 提供项目上下文、固定会议规则和回写目标，才能完成这条闭环。

验收屏助手继续负责验收屏工作。它的上下文适合验收会；会议助手负责跨上下文的统一定会和回写，因此可以处理项目评审会、团队版本计划会、验收会和其他临时会议。

## 主旅程

用户在项目会话当前 worktree 的更多菜单点击「发起项目原型评审会」。

BW 保留当前项目会话，打开一个会议助手悬浮窗。悬浮窗显示：

- 当前会议类型；
- 当前项目、版本和 worktree；
- 已带入的固定会议规则；
- 结果写回位置。

用户按回车发送助手已经准备好的提示词。助手只在缺信息时追问，然后显示预约确认。用户确认后，悬浮窗提供打开 WeLink 的入口。

用户可以在 BW 项目会话继续工作，也可以打开 WeLink 群通知和视频会议网站。G2 不要求 BW 自动检测 WeLink 议题、自动伴飞或重画视频。

会议结束后，用户重新打开悬浮窗，助手展示候选共识和遗留。用户确认后，结果写回当前项目或版本工作模型，并保留会议来源。是否创建 Issue、调整目标或安排下一场会议，仍由人决定。

## 范围

包含：

- 项目 worktree 发起项目原型评审会；
- 会议助手悬浮窗；
- 固定会议规则和项目上下文注入；
- 一句话发送和预约确认；
- 打开 WeLink 会议详情、群通知和视频会议网站；
- 会后候选结果确认；
- 结果写回当前 BW 工作模型；
- 其他入口通过不同上下文调用同一个会议助手。

不包含：

- 全局会议目录和完整会议工作台；
- BW 自己的视频、录音、转写或正式纪要；
- 自动检测 WeLink 议题和自动伴飞；
- 个人议题会话；
- 复杂的会议时间线、议题计时和多主机会话；
- 自动创建、关闭或完成 Issue。

## 入口差异

| 入口 | 注入上下文 | 默认写回位置 |
| --- | --- | --- |
| 项目 worktree | 项目、版本、worktree、原型、目标、验收标准、默认参会人 | 项目 / 版本工作模型 |
| 团队版本计划屏 | 团队、版本、多个项目、团队成员和团队固定会议规则 | 团队 / 版本工作模型 |
| 验收屏 | 验收对象、版本、验收标准和验收参会人 | 验收结果和版本工作模型 |
| 通用会议入口 | 当前可见团队或项目上下文 | 用户确认后决定 |

这些入口只改变注入信息和回写位置，不复制多套会议助手。

## G2 验收

- 从项目 worktree 菜单进入后，会议助手悬浮窗直接打开，不出现模板选择页。
- 一句话发送后能看到固定会议规则、预约信息和 WeLink 入口。
- 悬浮窗能打开 WeLink 会议网站或群通知入口。
- 会议结束后能看到候选共识和遗留，并确认写回当前 BW 工作模型。
- 原型能让评审者理解 BW 相比 WeLink 群助手和单一验收助手多出的价值。
