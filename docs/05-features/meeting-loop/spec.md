# 会议工作台规格

> 给交互设计、实现者和验收者读取。本文定义会议对象、完整旅程、行为规则和验收点，价值与边界见 [intent](intent.md)。可交互原型见 [prototype.html](prototype.html)。当前为原型规格草案，原型中的模拟动作不代表真实接口已经接通。

## 范围与入口

会议工作台是 BW 的全局查看入口，进入点位于 `WorkbenchRail` 的「会议」。它不替代团队或项目工作区，也不在顶部提供一个重复的全局「定会」按钮。项目评审从项目会话当前 worktree 的更多菜单进入完整会议工作台，会议类型已经由入口确定，主会议助手会话和项目评审提示词直接打开；HTML 工件沿用分享工件的输入入口。团队版本计划会从团队版本计划屏发起。全局会议工作台的团队/项目树用于查看、恢复和补发起，不承担替代原工作区的准备动作。

会议目录按以下结构组织：

```text
团队
  团队版本计划会
  项目
    登录体验
      项目原型评审会
      PR 评审会
    权限中心
      其他会议
```

一个团队可以有多个项目，一个项目可以有多场会议。固定会议模板和临时会议都使用同一会议对象。团队验收会可以先挂在团队下，未来项目自行发起验收会时挂在项目下。团队会议的发起人可以是任一成员，发起人变化不会产生新的会议实体。

原型新增项目会话当前 worktree 菜单中的评审入口、项目下的会议工作区、注入提示词会话、快速确认和预约、WeLink 预约/群通知/视频占位、到点自动伴飞、项目会话讲解与批注、议题待确认队列和会后写回。HTML 分享工件输入入口只作为同一提示词入口的说明。WorkbenchRail、Orca 会话头部与工具栏、Orca 浏览器页签和 WeLink 页面均为复用边界。原型文件位于 [prototype.html](prototype.html)，它使用 [设计系统 styles.css](../../04-design-system/styles.css) 和本地 `prototype.css`。

## 对象与数据归属

| 对象 | 作用 | 归属与来源 |
| --- | --- | --- |
| 团队 | 组织跨项目会议和默认参会人 | BW 团队上下文与团队群 |
| 项目 | 组织项目内多场会议 | BW 项目上下文 |
| 会议 | 一场可预约、进行和回看的会议实体 | BW 保存关联范围、模板、时间、WeLink 标识和状态 |
| 会议会话 | 一场会议下的主助手或个人议题聊天 | Orca 原生会话体系，关联会议，不创建项目工作树 |
| 会议模板 | 固定对象、参会人、材料、议题顺序和结果落点 | BW 模板配置，按团队或项目记忆确认设置 |
| 议题 | 固定模板中的讨论单元 | BW 生成候选顺序，WeLink 承载实际会议议题事实 |
| 候选结果 | WeLink 结果结合 BW 上下文形成的共识或遗留候选 | 先进入待确认队列，人确认后才写回 BW |
| 跟踪项 | 人确认后需要在团队、项目或版本中继续关注的结果 | BW 关联展示，不自动代表 Issue 已创建或完成 |

WeLink 是视频、录音、AI 听会、转写、原始 AI 总结和正式纪要的来源。BW 读取经授权的会议结果，并维护会议与团队、项目、版本的关系。计划屏批注继续由现有批注链路发送给计划助手，会议助手读取计划助手已经更新并确认的上下文。

## 模板定义

### 团队版本计划会

- 对象：团队当前版本下的全部项目。
- 参会人：团队群全体成员，可补充项目负责人。
- 自动带入：当前版本项目、上次团队会议遗留、团队成员和已确认的版本目标。
- 固定议题：项目变化和本周期目标 → 资源冲突和需要协同的项目 → 需要确认的风险和决策 → 共识、遗留与下次带入。
- 结果落点：团队版本上下文，并按项目分开显示跟踪项。

### 项目原型评审会

- 对象：当前项目和当前版本。
- 参会人：项目负责人、产品、设计和开发，可沿用上次评审人。
- 自动带入：当前目标、原型入口、验收标准、最近项目变更和上次遗留。
- 固定议题：目标用户和关键路径 → 原型与验收标准的差距 → 需要调整的方案与实现判断。
- 结果落点：项目版本上下文，形成已确认共识和待跟进项。

### 临时会议

没有固定议题。助手只询问会议对象、参会人、希望得到的结果和是否需要把结果带回 BW。

## 完整用户旅程

### 1. 从当前上下文发起

用户在登录体验项目会话里完成原型后，打开当前 worktree `login-experience` 的更多菜单，点击「发起项目原型评审会」。BW 打开完整会议工作台，左侧显示登录体验项目下的项目会话、会议工作台和本场个人议题会话；中间主会议助手已经打开，提示词已经带入当前 worktree、登录体验 · v1.1、当前目标、原型入口、验收标准和最近变更。用户按回车发送提示词，助手快速完成必要确认并展示预约前结果，不再选择模板。若输入只是 HTML 工件，则沿用分享工件的输入入口带入同一种项目评审提示词。

用户在团队版本计划屏发起时，助手带入当前版本下的多个项目、团队群成员、上次团队会议遗留和版本目标。任一成员都可以执行这一步；同一团队已有预约时，助手优先打开现有会议并说明当前发起人，不重复创建。全局会议工作台的团队节点也能补发起，但不要求轮值主持人专门先进入会议目录。

### 2. 发送提示词并快速确认必要信息

用户按回车发送已经注入的项目评审提示词。会议助手能力默认存在，只在信息缺失或会改变预约结果时快速追问；原型只展示“AskUser 已完成必要确认”和预约前结果。项目入口不要求用户选择模板，固定议题、默认参会人和上次遗留由入口上下文和助手处理。

### 3. 生成预览并预约

助手在会话中列出归属、发起人、时间、参会人、议题顺序、关联材料和 WeLink 动作。用户确认后才调用现有会议预订能力，读回会议标识和页面入口，再按现有规范单独预览并发送群通知。预订结果写回会议实体，同一会议不会重复预订。发起人只是当前操作人，会议记录对符合权限的团队或项目成员可继续。

### 4. 开始会中运行

预约后，用户可以从会议工作台打开 WeLink 会议详情和群通知。到开会时间由会议调度自动唤醒会议助手伴飞，不需要用户再次发送提示词。Orca 打开 WeLink 原生视频页作为主要视区，并保留会议助手会话和 BW 会议上下文。视频、共享屏幕、AI 听会、录屏和转写均在 WeLink 完成。

会议助手后台读取议题和时间状态，提供开始、临近结束和超时状态。主持人决定结束或延长，系统不因为助手等待回答而暂停会议。用户可以在间隙通过「新建个人议题会话」整理自己的发言或问题，个人会话共享本场会议上下文，不打断主会议助手。

### 5. 议题结果进入待确认队列

议题结束由 WeLink 事件、主持人操作或可靠的会议状态读取触发。助手读取当前议题的 WeLink 结果，结合 BW 关联目标、项目或版本形成共识和遗留候选。候选结果进入会议上下文的待确认队列，后续议题继续运行。

用户在议题间隙或散会后打开主会议会话，确认哪些候选结果写回 BW。项目讲解和批注从项目会话工作区提交，会议助手把它们和 WeLink 结果合并成候选。选择「继续下一个议题」不会丢弃候选结果，候选仍留在队列中。个人会话中的内容默认不进入主会议，只有用户明确确认后才带回。

### 6. 散会握手、纪要和跟踪

所有议题结束后，助手在主会话中请求一次全场确认，整理共识、遗留和下一次会议带入项。用户确认后，BW 写入已确认的团队/项目/版本跟踪结果。需要写入 WeLink 的纪要内容先生成草稿，用户打开原生 WeLink 纪要页面复核并手动发送。邮件准备可以由助手生成草稿，最终发送由人完成。

BW 右侧上下文显示已写回的结果、来源会议和关联项目/版本，并提供返回原项目或团队工作区的入口。它不自动创建或完成 Issue。后续计划会话可以读取已确认的遗留，由人决定是否纳入新计划。

## 行为规则与异常

### 会话与恢复

- 每场会议有一个主会议助手会话，可新增多个个人议题会话。
- 会话是 Orca 原生会话记录的关联视图，不创建新的工作树、项目目录或平行会话协议。
- 恢复会议时读回会议状态、主会话、个人会话和待确认队列。状态不确定时显示未知并要求人检查，不重复预约或覆盖纪要。
- 个人会话默认只保存个人整理内容。带回主会议或写入 BW 前必须经过人的明确确认。

### 会中与 AskUser

- 会中后台状态、时间提醒和议题结果读取不等待 AskUser。
- AskUser 只用于会前必要选择、议题结果确认和散会握手。
- 用户没有时间回答时，会议继续，候选结果进入待确认队列。
- 计划屏批注仍发送给计划助手。会议助手只读取更新后的计划上下文，不接管批注写回。

### 外部写入与来源

- 预订会议、群通知和写入 WeLink 纪要草稿均先给出完整预览，经人确认后执行。
- WeLink 正式纪要的最终发送由人在 WeLink 完成。
- BW 不复制完整转写或完整纪要，不把候选结果当成已确认事实。
- BW 不自动创建、关闭或完成 Issue。跟踪项必须能回到会议、团队、项目或版本来源。

### 失败与权限

- WeLink 未登录、会议页打不开、议题结果不可读或页面结构变化时，保留会议状态并说明原因，允许用户打开原生页面检查。
- 无法读取团队成员、项目成员或群号时，只询问缺失的那一项，不猜参会人或通知目标。
- 会议重复预约、纪要草稿已有变化或写入状态不确定时，先读回当前状态，再生成新的预览，不盲目覆盖。
- 没有可靠时间或议题事件时显示未知，助手不伪造提醒完成或议题已结束。

## 交互与原型验收

| 标识 | 可观察结果 |
| --- | --- |
| M01 | 从 WorkbenchRail「会议」进入全局查看屏，目录按团队、项目和会议组织，多个会议可以挂在同一项目下 |
| M02 | 从当前 worktree 菜单发起项目评审时，会话首条消息带入当前 worktree、项目、版本、目标、原型和验收标准；从团队版本计划屏发起时带入多个项目和团队成员 |
| M03 | 会议工作台能清楚展示准备并预约、会前查看、到点自动伴飞、确认并写回四段旅程；固定会议规则由助手处理，不要求项目入口选择模板 |
| M04 | 同一团队多个成员可以打开或继续同一场团队会议，会议实体不跟随主机重复创建 |
| M05 | 每场会议拥有主会话，能新建个人议题会话；新会话不创建项目目录，不打断主会话 |
| M06 | 项目入口发送已注入提示词后，助手快速完成必要确认并展示预约前结果；预约和群通知在外部写入前展示预览 |
| M07 | 开始会中后 WeLink 原生视频为主要视区，会议助手和 BW 上下文并列可用，视频能力没有在 BW 重画 |
| M08 | 会中助手后台运行，议题结束后候选结果进入待确认队列，未完成确认不阻塞下一议题 |
| M09 | 计划批注仍进入计划助手，会议助手能看到已确认的计划上下文变化 |
| M10 | 散会时人确认共识和遗留，WeLink 纪要草稿与 BW 跟踪结果各自落在正确来源，并能返回原团队或项目上下文 |
| M11 | 重开或读取失败时如实显示未知、缺失或冲突，不重复预约、不覆盖未知纪要状态、不自动完成 Issue |

交互原型覆盖 M01–M10 的主要路径，按钮和 WeLink 页面为模拟或复用占位。真实 WeLink 事件读取、会议权限、模板持久化、原生会话绑定和 Windows 真壳旅程仍待实现与验证。

## 取舍与待决问题

会议使用全局入口和树形目录，避免把跨项目团队会议塞进单个版本工作区；项目评审入口放在当前 worktree 菜单，HTML 工件沿用分享工件输入入口，团队计划入口放在团队版本计划屏，会议目录只承担查看、恢复和补发起。会议使用多会话关联，满足人在间隙整理个人议题的需要，同时保持一个会议实体和一套上下文。会中采用后台运行和待确认队列，牺牲即时逐项确认换取会议不会被助手卡住。

实现前仍需确定 WeLink 事件与议题结果的正式读取接口、会议模板的持久化材料、会议上下文的权限和个人会话的可见范围。上述决定不改变原型中已确认的对象关系和人工确认规则。
