# G2 会议助手规格

> 本文定义 G2 最小闭环的行为与验收。G2 使用会议助手悬浮窗，不实现完整会议工作台。价值与边界见 intent，原型见 prototype.html。

## 入口与对象

会议助手是一个跨上下文能力。项目 worktree、团队版本计划屏、验收屏和通用入口都可以调用它。入口传入会议类型、上下文材料和结果写回位置。

会议助手保存会议预约和结果关联，但不复制 WeLink 的视频、转写和正式纪要。

## 项目原型评审主旅程

### 1. 从项目 worktree 发起

用户在登录体验项目会话的 login-experience worktree 菜单点击「发起项目原型评审会」。

BW 保留当前项目会话，打开会议助手悬浮窗。悬浮窗显示当前来源、会议类型、固定规则和写回位置。主路径不出现会议模板选择。

### 2. 一句话定会

悬浮窗中的提示词已经带入：

- 项目和版本；
- 当前 worktree；
- 原型入口；
- 当前目标和验收标准；
- 默认参会人；
- 固定会议规则；
- 结果写回位置。

用户按回车发送。助手只追问缺失或会改变预约结果的信息，然后展示：

- 会议名称；
- 时间；
- 参会人；
- WeLink 群通知目标；
- 结果写回位置。

用户确认后才完成预约。

### 3. 打开 WeLink

预约完成后，悬浮窗提供：

- 打开 WeLink 会议详情；
- 查看 WeLink 群通知；
- 打开 WeLink 视频会议网站。

WeLink 负责视频、共享屏幕、AI 听会、转写和正式纪要。BW 不重画这些能力。

G2 不要求 BW 自动检测 WeLink 议题、自动唤醒伴飞或维护会中时间线。用户可以继续在 BW 项目会话工作，悬浮窗保留会议状态。

### 4. 结果回流 BW

会议结束后，用户从悬浮窗进入结果确认。助手展示候选共识和遗留，并标明写回目标。

用户确认后：

- 共识和遗留写回当前项目或版本工作模型；
- 保留会议来源；
- 不自动创建、关闭或完成 Issue；
- WeLink 正式纪要仍保留在 WeLink。

## 入口差异

| 入口 | 会议类型 | 注入内容 | 回写目标 |
| --- | --- | --- | --- |
| 项目 worktree | 项目原型评审会 | 项目、版本、worktree、原型、目标、验收标准、默认参会人 | 项目 / 版本工作模型 |
| 团队版本计划屏 | 团队版本计划会 | 团队、版本、多个项目、团队成员、固定规则 | 团队 / 版本工作模型 |
| 验收屏 | 验收会 | 验收对象、版本、验收标准、参会人 | 验收结果和版本工作模型 |
| 通用入口 | 临时会议或其他会议 | 当前可见上下文和用户补充信息 | 用户确认后决定 |

## 不在 G2 的能力

- 完整会议目录和全屏会议工作台；
- 自动事件检测和议题伴飞；
- 个人议题会话；
- BW 视频、录音、转写、AI 听会和正式纪要；
- 自动 Issue 生命周期；
- 多套按页面复制的会议助手。

## 原型验收

| 标识 | 可观察结果 |
| --- | --- |
| G2-01 | 从项目 worktree 菜单打开会议助手悬浮窗，不出现模板选择页 |
| G2-02 | 回车发送注入提示词后，看到固定会议预约结果并能确认定会 |
| G2-03 | 预约后能从 BW 打开 WeLink 会议详情、群通知和视频会议网站 |
| G2-04 | 会议结束后能确认候选共识和遗留，并写回当前 BW 工作模型 |
| G2-05 | 原型能说明 BW 相比 WeLink 群助手和单一验收助手的上下文与写回价值 |
