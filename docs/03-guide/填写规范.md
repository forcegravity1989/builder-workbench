# Workbench 指南 · 填写规范

> 本文件是产品指南的**填写规范**。现行指南是 [`v4-产品指南.html`](v4-产品指南.html)（入口 [`index.html`](index.html) 指向它），**只有一本使用指导**——按界面操作阶段（第 0–6 站）组织，给第一次打开 Workbench 的人按站查找。怎么建 / 跑 / 测在仓根 [`AGENTS.md`](../../AGENTS.md)；机制为什么这么定在 [`docs/architecture.md`](../architecture.md) 的 §2 特性层（5 个能力模块，每模块「是什么 / 取舍」）+ §3 三 crate 架构与数据流;模块实现的矛盾 / 取舍在 [`docs/06-module/`](../06-module/)。**不在这份 HTML 里再开机制章**——指南只在「得到什么」段用 `.linker` 把读者指回 architecture 对应模块。
>
> 正文只写「点什么、背后、得到什么」。过程话（走过一遍、穿刺仓号、issue 编号）不进指南。每站开头用「这一站能查到」方便扫读。末页是「规矩与查找」，不是缺口台账。

---

## 1. 一本的组织方式

产品指南只有一本：**使用指导**，按界面操作阶段（站）组织。实践推进到哪、能见到哪，就写到哪；不预先猜未来阶段。

> 为什么不在指南里开机制章？同一个机制会被多个站共用，但机制说明的正本在 [`docs/architecture.md`](../architecture.md) 的模块设计里。指南若再开一套机制章，就和 architecture 维护两份、容易打架。指南只在「得到什么」段用 `.linker` 把读者指回 architecture 对应模块，不在指南正文堆机制。

**读者**：最终用户（Builder）。只写「点什么、会看到什么、得到什么」；坑用界面结果描述（灰卡、侧栏没多出连接器、报错提示），**不**写解析器 / 字段名 / P 编号 /「静默失败」「响亮报错」「装表」等开发话术。要深究机制，跟 `.linker` 去 architecture。

## 2. 操作阶段屏结构（三段式）

每屏三段式：**操作 → 背后 → 得到什么**（+ callout 坑 + linker + foot）。「背后」讲这一步做完 Workbench 自动干了啥（白话），「得到什么」讲用户手上多了啥、关注啥。

```
<eyebrow>   使用指导 · 第 0X 站
<h1.disp>   站名
<lede>      一句话定位（用户视角，讲心智不是讲机制）
<h2.sec> 操作        → .ops 有序步骤
<img>       截图按步放（每步下面放该步的截图，不堆在末尾）
<h2.sec> 背后        → .res 三轴白话（见下）
<h2.sec> 得到什么    → .res 用户手上多了啥
<callout>           可选：该站坑 / 边界
<p.linker>          指回 architecture.md 对应模块设计
<.foot>             事实源脚注
```

### 必填内容
- **操作**：界面上的真实操作步骤，按序号写，能照着点。**截图按步放**——每步下面放对应截图，不在末尾堆连续截图；本质上同一 UI 界面的步可共用一张。
- **背后**：点完关键操作（如「确认」）Workbench **一次性**在背后干了啥。用**白话三轴**组织，**不按 `Command::` 代码命令、不用 CRUD 黑话**：
  - **对远端代码仓**（GitHub/CodeHub）：建仓 / 开 Issue / 推提交……
  - **对用户的机器**：clone / 写文件 / 探活……
  - **对 `.bw/` 仓文件**：写名片 / 指标 / 规范件（正本走 MR，本地零库）……
  - 给个地址 + 一笔核心信息描述即可，代码级细节（具体表名 / 字段 / 函数）放 architecture 对应模块，这里只讲用户能感知的。
- **得到什么**：用户建完手上多了啥、该关注啥（不是"看到界面呈现"那种流水账，是"你得到了什么能力 / 资产"）。

### 规范
- **实践边界**：只写已实践 / 已可见的操作屏。还没实践的站**只留章节名占位**（`<h1>` + 一句「待实践补」+ `.foot` 标事实源），不预先填内容、不猜、不发明指标。
- 只写已实践 / 可见的，不猜、不发明指标。
- 表名、文件名、命令、状态值用 `code` 包裹（真实值）。
- 每屏末 `.foot` 标事实源（代码仓文件名用 `code`）。
- `.linker` 指回该站涉及的 architecture 模块设计（可多个）。

## 3. 组件清单（class 名 + 用途）

| class | 用于 | 出现位置 |
|---|---|---|
| `.ops` + `.li` | 操作有序步骤（带序号圆点） | 操作屏·操作 |
| `.res` + `ul/li` | 结果清单（背后干了啥 / 得到什么） | 操作屏·背后 / 得到什么 |
| `.diagram` + `.cap` | 主图外框 + 图注 | 通用 |
| `.ktable` | 关键表 / 字段对照 / 目录 | 通用 |
| `.callout` `.warn/.note/.danger` | 提示框（坑 / 说明 / 铁律） | 通用 |
| `.checklist` + `.chk` | 安装 / 确认清单 | 前置准备等 |
| `.cards` + `.card` | 卡片网格 | 通用 |
| `.flow` + `.node` | 横向流程链 | 通用 |
| `.lights` + `.light` | 健康灯四态 | 总览呈现 / 规矩与查找 |
| `.linker` | 指回 architecture.md 对应模块设计 | 「得到什么」段 / 屏末 |
| `.foot` | 事实源脚注 | 每屏末 |
| `pre.code` | 代码块 | 前置准备等 |

> 新内容优先复用上表组件；为可读性可增少量组件（须落在暖纸 token 内）。禁止为单页发明第三套视觉语言。机制图（分层栈 `.stack` / 横向流程 `.pipe` / 两栏对照 `.split2` / 概念卡 `.cc` 等）属 [`docs/architecture.md`](../architecture.md) 模块设计的语言，不进指南。

## 4. 扩展规范

### A. 加新操作阶段
实践推进到新站（如「阶段交棒」「全局库管理」）：
1. 复制一个现有站 `<section class="screen" id="uX" data-title="第 N 站 · 站名" data-sec-name="怎么用">`，按三段式填。
2. 侧栏加一行 `<div class="nav-item" data-screen="uX">`。
3. 若该站涉及机制细节，用 `.linker` 指回 [`docs/architecture.md`](../architecture.md) 对应模块设计，不在指南里新开机制章。

`data-screen` 指向 `id`，JS 自动接管切换 + localStorage 持久化（key `Workbench-v4-guide-screen`）。无需改 JS。

## 5. 内容规范

- **实践边界**：只写已实践 / 已可见的操作屏；还没实践的站只留章节名占位、标「待实践补」+ `.foot` 标事实源。
- **真实实践优先**：只写已实践 / 已可见的操作；机制只写已落地的，未建留口不假装。
- **用用户语言**：按钮名、界面结果、白话后果；开发契约 / 字段 / 缺陷编号只进 [`docs/architecture.md`](../architecture.md)，不进指南。
- **背后事务用白话三轴**（对远端代码仓 / 对用户机器 / 对 `.bw/` 仓文件），不按 `Command::` 命令、不用 CRUD 黑话；机制细节留 architecture，指南用 `.linker` 指回。
- **事实源脚注**：每屏末 `.foot` 必填；标实跑依据或 [`docs/architecture.md`](../architecture.md) 模块路径。
- **术语统一**：以 [`CONTEXT.md`](../../CONTEXT.md) 为唯一规范词表（Builder / 队友 / 阶段 / 交棒 / Issue / 读数 / 指标 / 信号 / 北极星 等），不自造同义词。
- **诚实口径**：无数据 = Unknown ≠ 绿；Done 永不自动；manual 带徽；数字可 `codehub-cli`/`gh`/`git`/`cat .bw/…` 读回（本地零库，不用 sqlite3）。涉及健康处必须重申。
- **跨站共用的机制不重复**：放 [`docs/architecture.md`](../architecture.md) 对应模块设计，各站用 `.linker` 指回，不在指南正文重写。

## 6. 视觉规范摘要（Workbench 自有设计系统）

- **色**：暖纸底 `#EFEBE2` / clay 主色 `#C5654A`（文本用深调 `#A84A30`）；信号四态：Green 隐身、Amber 黄、Red 红、Unknown 灰。绿色不出声，只有红黄出声。
- **字**：Noto Serif SC（display）/ Noto Sans SC（body）/ JetBrains Mono（code·数字）。
- **字距**：ALL CAPS ≥ 0.06em；display 标题 -0.02em；body 行高 1.6。
- **accent 节制**：clay 作结构色（序号 / eyebrow / 激活态 / 阶段徽），不泛用为 CTA。
- token 全在 `:root`，改一处全局生效。
