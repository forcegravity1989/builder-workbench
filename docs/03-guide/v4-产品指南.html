Workbench MVP · 使用指南

接进来，每周转一圈

Workbench 是单人项目工作台。你说清楚要什么，在路口点头；查资料、写代码、开 MR 交给 agent。正本在仓和代码平台上，不在 Workbench 本地库里。

一条主线：接进来 → 定本周 → 派活 → agent 干 → 你验收。
  • 「完成」永远你点。agent 最远到「评审中」。定时任务只会建活，绝不完成活。
  • 没数据就是灰，不是绿。界面上的数字都能用 codehub-cli / gh 或打开仓文件独立核对。

怎么用 · 第 0 站

把一个项目接进来

只做一次。选仓、填名片。仓里还没有项目信息时，Workbench 自动铺 .bw/ 骨架并开 MR。已有名片不再铺。仓根一个字不动。合入由你点。

这一站能查到
  • 要准备什么、工作区目录怎么改
  • 两步怎么接、这个仓以前被接管过没有
  • 点「完成接入」之后仓里多了什么、谁合那个 MR

你要准备什么

一个 git 仓
GitHub 或 codehub 上的都行，你有它的读权限。
本机装好命令行工具并登录过
gh（GitHub）或 codehub-cli（内部）。项目墙上那条环境条会当场去 PATH 里找这些命令，找得到绿、找不到红。红的不影响别的事，只影响对应那条路能不能走。

工作区目录

「设置」里有一格「工作区根目录」。以后接进来的项目，仓 clone 到这个目录下，一个项目一个子目录。默认在用户目录下的 .builders-workbench/workspaces。要换盘，现在改、点保存：立刻生效，重启还在。已经接进来的项目不会跟着搬家。

接：两步

1
点「+ 接入项目」。第一步只问一件事：这个项目在哪。光标点进「项目地址」那格，Workbench 就去问平台要你账号下的仓，列成下拉框；打字即在这批里检索，点一行即选中。不想理列表就直接把 owner/repo 打进去，一样算数。框里右边那个 ⟳ 是重新拉一次。
2
第二步是基础信息，四格：项目名称、你想做什么、最像的对标、三个月长成什么样。
列不出来的时候会把命令的原话摆给你看（多半是没装或没登录），不会摆一张假列表。

第二步顶上：这个仓被 Workbench 接管过没有

判据是去它远端读 .bw/project.toml：

你会看到意思你该做什么
已经被 Workbench 接管过同事先接过，或者你以前接过四格是回显出来的，直接改就行；接进来时不会覆盖仓里已有的字
还没被 Workbench 接管过仓在、就是没这份文件四格自己填
找不到这个仓地址敲错了、私有仓没权限、没登录先把地址改对，接一个不存在的仓后面每步都会失败
没查成没登录、网不通、或没从列表点选（没带上默认分支时会去查 main）照样能接；仓里真有名片的话，接入时以仓里的为准

最后两行是特意分开的：「没查成」不等于「没被接管过」。混成一句的话，你会照着空格子填一遍，接进去反而把仓里真正的名片盖掉。

点「完成接入」之后会发生什么

界面上一步一句地摆出来，做完的那行原地换成结果——这一下要十几秒，别猛点：

1
取仓——目录里已经是 git 仓就直接用（顺带把它的 origin 报出来给你核对）；目录不在或是空的就 clone；没填远端就建个空目录并说明它是空的；目录里有东西又不是 git 仓就当场弹回，既不敢往里 clone，也不敢把别人的目录当成这个项目的仓。
2
本机清单落一行项目——只存定位：名字、本机路径、远端地址。名片不进这份清单。
3
写名片——.bw/project.toml。仓里已经有就一个字不覆盖、只补空着的字段。
4
仓里还没有名片，才建一张「项目约定」的活——它开一条分支、只写 .bw/project.toml 和 .bw/.gitignore、提一个 MR，然后停在评审中等你合。仓里已经有项目信息、或已经开着一张项目约定 / 残留旧标题活，这一步整段跳过。它不会自动合，也不会自动把活标成完成。
5
自动进这个项目。
6
Orca 开着时会登记这个仓，并写入三条默认关掉的运作自动化。Orca 没开或没打上，进度会说「退回项目墙再点进来会再打」。接入本身照样成功。

第 4 步只铺马上要用的骨架，全在 .bw/ 底下：

文件是什么
.bw/project.toml第 3 步写的名片机读件（仓里已有就不覆盖）
.bw/.gitignore只一条 worktrees/。缺了就补
.bw/PROJECT.md旧铺底才有。新项目不再铺；每周资产盘点会删
.bw/standard.toml旧铺底才有。新项目不再铺，也不再显示「规范版本」；每周资产盘点会删
.bw/managed.toml旧铺底才有。新项目不再铺；每周资产盘点会删
.bw/issue-policy.toml旧铺底才有。新项目不再铺（开工工具跟人走本机 settings）；每周资产盘点会删

指标正文和采集脚本不在这一站预铺，跟第 2/3 站运作活①走。配置屏只改开工工具映射、看技能，不改名片、不再二次铺底。节律在 Orca。

仓里会多什么、不会多什么

  • Workbench 写进仓的东西全在 .bw/。仓根 README.md / AGENTS.md / CLAUDE.md 这一步一个字不碰。自带技能也不进你的仓。
  • 第 4 步没成，前面仍然算数：项目已接进来、仓已在本机。没有第二次铺底命令。仓里已有名片或开着铺底活，再纳入也不会再铺一张。
  • 项目约定还没合进默认分支：总览顶上常驻一条横幅，提醒不合入则配置用不上、别人再纳入也看不出已经被管过。「项目约定」写「已完成」只看默认分支上有没有 .bw/project.toml，关过的旧活不冒充铺过。这颗状态在计划屏，总览不另放芯片。

接错了怎么办

项目卡右上角有个 ✕。点一下先问一句，再点「移走」才真移走。它只把这个项目从工作台移出去（项目行、它所有活的账），仓一个字节都不动——硬盘上的代码还在原地，活自己的工作目录也还在。回执里会告诉你仓在哪儿，你真要删自己去删。

最后一下：你点完成，合那个 MR

接入只把活推到「评审中」。合入永远是人点的——计划屏把这张「项目约定」从「评审中」拖到「已完成」（详情弹窗里那颗「✓ 点完成」是同一下）。松手会弹出确认框，写明先合哪个 MR；确认之后框不关，一步一句写正在合 MR、拉仓、结清（要两三秒）。合不成就整条不算数，活留在评审中，可以重试。

项目墙 ⚑ 只提醒，不在那儿合。「等你合入」告诉你有一张 MR 等着；去计划屏拖到「已完成」，或总览上那颗「合入并完成」。不要只在 codehub 网页关 issue——那不会合 MR。

这一站结束时你手上有什么

  • 本机一个真实的仓（clone 下来的）
  • 工作台上一个项目
  • 默认分支上有 .bw/ 骨架（合入之后才有；合之前只在铺底那条分支上）
  • 那张「项目约定」活已完成，对应 MR 已合
  • Orca 开着时，Automations 里多了三条关掉的自动化；要跑去打开或点 Run now

下一站：第 1 站 · 看总览

怎么用 · 第 1 站

打开总览，看清这一周

看清「这是什么、健康吗、这周要推什么、指标现在几个数」。改名片、项目群也在这里，一张活一次 MR。在研版本看覆盖当天的里程碑。

这一站能查到
  • 健康灯为什么是灰 / 黄 / 红
  • 指标三类怎么看、手填怎么记
  • 怎么改名片、项目群；在研版本从哪来；顶栏刷新真正拉什么

操作

1
项目墙点进这个项目。侧栏默认停在「总览」。
2
从上往下看：项目约定还没合入时顶上会有一条常驻横幅；然后是名片（健康灯在名字旁，在研版本覆盖当天的里程碑，有值带「本周」）和北极星并排、版本计划与进展、滞后和引领同一块（按特性分页签，一张图一条滞后带着它的引领）、项目指标 · SDLC 三条。没有单独的发版记录。
3
本会话第一次打开这个项目，Workbench 会自己采一轮指标和仓统计。卡上先写「正在采…」，采完折线出现。还想再采，用各块上的「立即采集」。
4
顶栏「刷新」会先把打开着的项目拉到远端最新，再重采。主检出上若只脏了读数或接入留下的未提交名片，Workbench 会先让开再拉。只重画界面、不拉仓，会继续看见同事已经合进主干的旧 metrics.toml。
5
改项目名称 / 想做什么 / 对标 / 三个月长成什么样，或改项目群：点「编辑」。编辑表单里「在研版本」下拉永远在，选项是覆盖今天的里程碑，改了只切本机选中、不建 MR。保存名片后这张活在「评审中」（计划屏右上角下拉切「全部 issue」就能看见，不进待办池）。总览横幅或看板拖到「已完成」合入。

背后

  • 对远端代码仓：读 issue 列表和里程碑。每个里程碑都是一个版本。在研版本是覆盖当天的里程碑（多个取最后创建，编辑表单下拉可切）。版本目标来自打了该版本标签的运作活①最新评论里 ## 版本目标 那一段。纳入了哪些活看 bw:plan:<名> 标签。
  • 对你的机器：跑 .bw/metrics.toml 里的采集脚本，窗口近四周。脚本只吐一个当下值时，折线只在本周画一个点。仓统计走 git，再问远端合入的 PR。
  • 对 .bw/：指标定义读 metrics.toml。B 类点「立即采集」，或打开 Orca 里「每日指标采集」后每天 20:00 自动采，把当天的值记进账本 readings.jsonl（同一天再采覆盖这一行，不写主检出）。折线按周画，取那一周最后一天。没有采集脚本的 B 类仍然采不到。C 类在卡上填今天的数，和 B 类同一份流水、同一套覆盖。

得到什么

  • 名片名字旁一颗健康灯。没数据就是灰，不是绿。三条判据只用来推灯，不再占一栏。
  • 北极星单独一块。滞后和引领按所属特性分页签；一张图 = 一条滞后 + 它带着的引领，图例可勾选，可切周/天。有读数才有现值和折线。没写关联的引领挂到该页签第一条滞后。手填写在对应滞后那一行。读到 0 是真值，不是「没采到」。
  • 版本计划与进展：页签切在研 / 历史版本；左版本目标、右每周进展（各 6 行，多了滚）；下面进度条只报数。活的列表在计划屏。
「项目约定」写「已完成」只看默认分支有没有 .bw/project.toml。关过 issue 但 MR 没进默认分支，总览横幅还在。关 issue 不等于铺进了仓。这颗状态在计划屏，总览不另放芯片。

健康灯怎么亮只从数据推，不能手点

灯在名字旁。下面三条只说明怎么推，界面不再列出理由：

  • 本周定了版本目标，仓里也有真实提交。目标要写进运作活①评论的 ## 版本目标，只开着这张活还不算定了。
  • 本周或上周有指标读数。读的是 .bw/metrics/readings.jsonl。点过采集、脚本吐了数，这一条才打勾。
  • 上周有合入或发版。不成立时显示「上周既没有合入也没有发版」。

三条怎么合成一盏灯，见 规矩与查找。没数据 = 灰，不是绿。

下一站：第 2/3 站 · 定本周

事实源 docs/architecture.md 模块 6 / 12 / 13。
怎么用 · 第 2/3 站

在 Orca 定版本，写下目标和纳入的活

一次会话做完「复盘 → 指标 → 确认版本 → 版本目标和活清单」。计划正本挂在运作活①的评论上，不另写周计划文件。到点由 Orca 开会话；计划屏已有这张活也可以 Start。工作台不再有「开始本版本」。

这一站能查到
  • 定版本计划在 Orca 里怎么开
  • 版本目标写在哪、计划屏怎么按版本看卡
  • 「新建活」能建哪几种

操作

1
纳入或打开项目后，Orca 里会有「定版本计划（Workbench）」自动化（默认关）。要跑先在 Orca 里打开，或点 Run now。关着不会到点。
2
会话在常驻树 bw/week-plan。agent 按版本计划剧本走：复盘、采指标、先确认本周版本（推荐 v0.x，别的名字也行），再起草版本目标与纳入清单。你在 Orca 里看着、随时能停。
3
你确认之后，agent 当场建纳入的业务活，并打上 bw:plan:<版本名>（codehub 还挂同名里程碑，起止默认本周周一到周五）。版本目标、纳入清单、指标读数快照写成运作活①的三条评论，标题必须是 ## 版本目标 / ## 本周纳入 / ## 本周指标读数。版本目标那一段一句或一段都行。版本名推荐 vX.X，别的也行。
4
侧栏点「计划」。版本头是版本目标那段，默认只露两行，点右下角小框展开，再点收起。点某个版本只看打了那个 bw:plan:<名> 的活；没打版本标签的切到右上角下拉「全部 issue」就能看见。

背后

  • 对远端代码仓：有光杆未打版本标签的运作活①就复用，没有再新建（标题 更新指标 + 制定版本计划；确认版本后标题带上版本名）。纳入的活是真的远端 issue，不是本地草稿。
  • 对你的机器：改动落在常驻树 bw/week-plan，不写主检出。缺的 metrics.toml 和采集脚本会在这场里铺上（已有不覆盖），经这张活的 MR 合进默认分支。
  • 对 .bw/：指标定义和脚本进仓。版本目标只在 issue 评论里，不另写一份计划文件。

得到什么

  • 总览和计划屏同一段版本目标，杀进程重开还能读回来（读的是 issue 评论）。
  • 本周范围内的活，看板上能点开。旧卡没打类别时，详情里选一次即可。
  • 运作活①可以关。关了不等于第 0 站那张铺底没合入——那是另一张活、另一条 MR。
计划屏「新建 issue」建业务活（标题、正文、五阶段类别；原型默认 Open Design）。要走 Open Design：类别选「原型」，创建后点开卡片再「Start」。

下一站：第 4 站 · 干活

事实源 docs/architecture.md 模块 13。
怎么用 · 第 4 站

把一张活开起来干

开工、作废、去会话、原型进 Open Design。合入、点完成、发版在第 5 站。

这一站能查到
  • 怎么开工（按钮和拖进「进行中」是同一条路）
  • 构建停会话屏 Orca 页、原型停 Open Design
  • 「去会话」只切树、不改活的状态

操作

1
计划屏点开一张卡（看板或列表都行）。业务活详情会带上已有类别；没打的可在详情或开工确认框补一类——不开工工具的活会被拒绝开工，不会悄悄起 Claude。状态下拉只列出从现在能走到的：待办能去进行中/阻塞/拒绝/完成，进行中能去待办/阻塞/拒绝/待评审/完成，待评审能去完成/拒绝/进行中，阻塞能去进行中/拒绝/完成。选了和拖拽是同一条路。不能拖的松手会弹窗说明，不是没拖准。点 Start / Open / Complete 或改状态下拉后详情会自己关。
2
详情「Start」，或把卡拖进「进行中」。确认框写 worktree，业务活可改类别。确认后跳会话屏。
3
原型类默认停在 Open Design 标签，嵌的是本机 OD 首页。不会自动开跑，你在 OD 里打一句发出去，它的 AI 才动。构建类停在 Orca 页，嵌的是本机已配对的 Orca web；agent 在 Orca 里跑，过程在那看。
4
卡住了：待办或进行中拖到待处理列的「阻塞」段，或详情状态下拉选「阻塞」，写原因。阻塞卡可拖回进行中（只改状态，不会再开一轮工），或拖进「拒绝」作废。不想干了：详情状态下拉选「拒绝」，或把卡拖到已完成列的「拒绝」段（待办 / 进行中 / 待评审 / 阻塞都能拖）。写原因。这不是完成——打已取消标签并关掉远端 issue，卡到「拒绝」。
5
作废不会动本机会话行。停止、开 MR、评审在 Orca 里做，或在计划屏拖列；会话屏这版不露「删除会话」按钮（内核命令还在，屏上暂不露）。远端那张 issue 不动。
6
会话屏只剩 Orca / Open Design 两个页签，都常驻；右侧「指南」哪一屏都在，打开就是这份。指南下面是「Issue」：填标题后提交，中间转圈「日志上传中」，成功后底栏说「issue上报成功」。报到的是当前目录 git 的 workbench 仓，并附上本机对照日志，不是打开着的被管项目。

背后

  • 对远端代码仓：开工改状态到进行中。作废写原因、打取消标签、关掉 issue。去会话不碰远端。
  • 对你的机器：每张活一棵工作目录。原型开工后嵌 OD 首页，并尽量灌进系统提示词；灌不上就说没灌上，不假装已经进了某一单对话。构建类在 Orca 里起 Claude（本机本地 pipe 开工）。新树落 <仓>/.bw/worktrees/，旧平级树不搬还能打开。
  • 对 .bw/：会话身份落本机。指标读数不在这一站写——点采集才记。

得到什么

  • 待办拖进进行中 = 开工，和 Start 是同一条路。进行中也可以拖回待办、拖进待评审 / 阻塞 / 拒绝 / 完成。待评审可拖回进行中（只改状态，不开新工）。阻塞拖回进行中只改状态，不开新工。工作态拖到完成：有开着的 MR 确认合入，没有则确认只关 issue。
  • 作废卡不会冒充已完成。已完成列要先切到「拒绝」再松手才是作废；切在「完成」上仍是合入。作废后再点开工，会说这张活已经取消。
  • 原型：会话停在 Open Design 标签。OD 不自动开跑，你打一句发出去它才动。不在 OD 里另建一单。
  • 去会话：先切到这张活的工作目录树；树上有几扇窗、是否正好落到这条对话是其次，切树成功就算跳到了。
Open Design 不会自动开跑。导出怎么稳落进这张活的目录还没做。要最新内容，点顶栏刷新。

下一站：第 5 站 · 验收记发版

事实源 docs/architecture.md 模块 5 / 7 / 9 / 13。
怎么用 · 第 5 站

合入、点完成、记进一个版本

活到评审中之后，你点完成才合 MR、结清。本周做完的活，再点「发版本」记进远端的一个 Release。要安装包，点左侧「出包」。不是到点自动结束一周。

这一站能查到
  • 怎么合入并完成（项目墙 ⚑ 只提醒，不合 MR）
  • 发版先建远端 Release，再打标签；出包是旁边另一颗按钮
  • 在研号不会跟着发版改

操作

1
计划屏把卡拖到「已完成」的完成段（待办 / 进行中 / 待评审 / 阻塞 / 未排期都行），先确认列上切的是「完成」不是「拒绝」，或详情里 Complete / 状态下拉选「完成」。有开着的 MR 就先确认再合；没有开着的确认后只关 issue。点「算了」停在原列。完成永远由人点，agent 不会自己完成。
2
项目墙 ⚑ 只提醒你有 MR 等着，不在那儿合。不要只在代码平台网页关 issue——那不会合 MR。
3
本周有已完成的活，计划屏点「发版本」。号锁死当前版本，不能改。弹窗里的说明会写进远端 Release，也会跟在项目群那条「发版」消息后面。确认后才建远端 Release。要安装包，点左侧「出包」：先出包（黄转圈，过了变绿，可打开产物目录），再验包（写出过了几条 / 一共几条）。验包不过时点「详情」看是哪条用例、报了什么错。出包不打发版标签。弹窗可关掉继续跑，按钮上三个点再点回来；要停就点「停止」，确认后清中间件。
4
去代码平台的版本页，或跑 codehub-cli release list / gh release list，核对远端真有这个版本。总览「已发版次数」优先读远端 Release。

背后

  • 对远端代码仓：先合那张 MR，再关掉 issue。发版先建远端 Release，成功后再给勾过的活打 bw:released:vX。顺序不能反。出包不碰远端 Release。
  • 对你的机器：合入后尽量把主仓拉到最新，收掉这张活的工作目录。点「出包」会在仓里 .bw/release/out/版本号/ 落下安装包；验包在隔离桌面点两屏，不抢你正在用的窗口。
  • 对 .bw/：在研版本不进仓文件。发版也不改名片。号就是刚发的那个里程碑名；下一周若里程碑已截止，总览在研为空。

得到什么

  • 点「出包」：仓里多一份这个版本的安装包（弹窗第一行「打开目录」）。点「发版本」：远端多一个 Release，选中的活带上版本标签；配了项目群且勾了发版通知时，群里那条带上弹窗说明。
  • 总览「在研版本」仍看覆盖当天的里程碑——发版没去改覆盖时间的话，号还在。
  • 总览「已发版次数」跟远端 Release 列表走；远端读不到才退回本机 git 标签。
发版不是只打 issue 标签。第一步是远端 Release，标签是第二步。次数读的是已经发出去的 Release，不是名片上的在研号。

下一站：第 6 站 · 定时盘点

事实源 docs/architecture.md 模块 8 / 13。
怎么用 · 第 6 站

到点建一张盘点，停在评审中

节律在 Orca。周五 15:00 盘点、每天 20:00 采 B 类，默认关。Workbench 开着也不会自己守钟。完成仍要你点。

这一站能查到
  • 三条自动化在 Orca 里、默认关
  • 错过了怎么补跑
  • 周五会不会给总览写每周进展
  • B 类每天几点采

操作

1
纳入或打开项目后，Orca 里会有三条默认关掉的自动化：周一 09:00 定计划、周五 15:00 盘点、每天 20:00 采 B 类。要跑就在 Orca 里打开或点 Run now。
2
盘点、定计划的改动分别在常驻树 bw/ops-audit / bw/week-plan。类别锁成「运作」，改不了五阶段。
3
会话在 Orca 开。最远到评审中。合入、点完成仍是你来。
4
周一回到总览，开始下一圈。盘点报告挂在这张活的评论里（Workbench 资产 / 闭环 / 项目审查）。当周进展另挂在该版本运作活①上（## 每周进展），总览右栏按新到旧列出该版本所有进展。改了 .bw/ 才有 MR；项目审查只出建议，不改业务代码。

背后

  • 对远端代码仓：建一张标题固定的运作活（本周有了就不建第二张；标题含 ISO 周，如 资产盘点 2026-W36），有在研版本就挂 bw:plan:<名>，不打 bw:week:。开工后改状态。先盘 .bw/ 跟上现行契约，再盘项目本周改动（建议落评论，不改业务代码），再给该版本运作活①追加一条每周进展。
  • 对你的机器：Workbench 不自己守钟。Orca 没开就下次打开项目再补打自动化。错过了到 Orca 点 Run now。
  • 对 .bw/：对照现行契约清残留、升格式，让当前工作台读得动；点出未闭环的环。不重写名片，不重定北极星。仓根 AGENTS.md 不由周五盘点代写。

得到什么

  • 多一张运作活②，类别显示「运作」、改不了五阶段。
  • 总览「每周进展」有当周收口（有几条列几条，没有仍空着）。
  • 打开 Orca 里「每日指标采集」后，每天 20:00 采一轮 B 类，按当天写入账本（同一天再采覆盖）。总览「立即采集」也能立刻再采今天。
运作活和五阶段类别是两套。不要把盘点、周计划塞进「优化 / 运维 / 运营推广」。仓根 AGENTS.md 是项目自己的，周五盘点不代写。
