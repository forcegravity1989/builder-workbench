Workbench MVP · 使用指南

接进来，每周转一圈

Workbench 是单人项目工作台。你说清楚要什么，在路口点头；查资料、写代码、开 MR 交给 agent。正本在仓和代码平台上，不在 Workbench 本地库里。

一条主线：接进来 → 定本周 → 派活 → agent 干 → 你验收。
  • 「完成」永远你点。agent 最远到「评审中」。定时任务只会建活，绝不完成活。
  • 没数据就是灰，不是绿。界面上的数字都能用 codehub-cli / gh 或打开仓文件独立核对。

怎么用 · 第 0 站

把一个项目接进来

只做一次。选仓、填名片、Workbench 自动铺 .bw/ 骨架并开 MR。仓根一个字不动。合入由你点。

这一站能查到
  • 要准备什么、工作区目录怎么改
  • 两步怎么接、这个仓以前被接管过没有
  • 点「完成接入」之后仓里多了什么、谁合那个 MR

你要准备什么

一个 git 仓
GitHub 或 codehub 上的都行，你有它的读权限。
本机装好命令行工具并登录过
gh（GitHub）或 codehub-cli（内部）。项目墙上那条环境条会当场去 PATH 里找这些命令，找得到绿、找不到红。红的不影响别的事，只影响对应那条路能不能走。

工作区目录

「设置」里有一格「工作区根目录」。以后接进来的项目，仓 clone 到这个目录下，一个项目一个子目录。默认在用户目录下的 .builders-workbench/workspaces。要换盘，现在改、点保存：立刻生效，重启还在。已经接进来的项目不会跟着搬家。

接：两步

1
点「+ 接入项目」。第一步只问一件事：这个项目在哪。光标点进「项目地址」那格，Workbench 就去问平台要你账号下的仓，列成下拉框；打字即在这批里检索，点一行即选中。不想理列表就直接把 owner/repo 打进去，一样算数。框里右边那个 ⟳ 是重新拉一次。
2
第二步是基础信息，四格：项目名称、你想做什么、最像的对标、三个月长成什么样。
列不出来的时候会把命令的原话摆给你看（多半是没装或没登录），不会摆一张假列表。

第二步顶上：这个仓被 Workbench 接管过没有

判据是去它远端读 .bw/config/project.toml：

你会看到意思你该做什么
已经被 Workbench 接管过同事先接过，或者你以前接过四格是回显出来的，直接改就行；接进来时不会覆盖仓里已有的字
还没被 Workbench 接管过仓在、就是没这份文件四格自己填
找不到这个仓地址敲错了、私有仓没权限、没登录先把地址改对，接一个不存在的仓后面每步都会失败
没查成没登录、网不通、或没从列表点选（没带上默认分支时会去查 main）照样能接；仓里真有名片的话，接入时以仓里的为准

最后两行是特意分开的：「没查成」不等于「没被接管过」。混成一句的话，你会照着空格子填一遍，接进去反而把仓里真正的名片盖掉。

点「完成接入」之后会发生什么

界面上一步一句地摆出来，做完的那行原地换成结果——这一下要十几秒，别猛点：

1
取仓——目录里已经是 git 仓就直接用（顺带把它的 origin 报出来给你核对）；目录不在或是空的就 clone；没填远端就建个空目录并说明它是空的；目录里有东西又不是 git 仓就当场弹回，既不敢往里 clone，也不敢把别人的目录当成这个项目的仓。
2
本机清单落一行项目——只存定位：名字、本机路径、远端地址。名片不进这份清单。
3
写名片——.bw/config/project.toml。仓里已经有就一个字不覆盖、只补空着的字段。
4
自动建一张「规范铺底」的活——它开一条分支、往仓里写规范骨架、提一个 MR，然后停在评审中等你合。它不会自动合，也不会自动把活标成完成。
5
自动进这个项目。

第 4 步只铺马上要用的骨架，全在 .bw/ 底下：

文件是什么
.bw/config/project.toml第 3 步写的名片机读件（仓里已有就不覆盖）
.bw/PROJECT.md项目名片给人看：这个项目是什么、对标谁、北极星是什么
.bw/state/managed.toml记指纹，以后对账用
.bw/config/issue-policy.toml类别 → 开工工具 → workflow 的映射，加上周五资产盘点节律。接入这一次一起铺。

指标正文和采集脚本不在这一站预铺，跟第 2/3 站运作活①走。配置屏只探活和对账，不改名片、不再二次铺底。

仓里会多什么、不会多什么

  • Workbench 写进仓的东西全在 .bw/。仓根 README.md / AGENTS.md / CLAUDE.md 这一步一个字不碰。自带技能也不进你的仓。
  • 第 4 步没成，前面仍然算数：项目已接进来、仓已在本机。配置屏没有第二次铺底，点「对一遍账」能看见缺哪些件。要再铺，接入会认开着的同标题活，不会多建一张。
  • 以前铺过、MR 没合、issue 也关了：默认分支没有 .bw/config/project.toml，仍算没纳入过，接入后再开一张新铺底。总览③写「已完成」只看默认分支上有没有指纹清单 .bw/state/managed.toml，关过的旧活不冒充铺过。

接错了怎么办

项目卡右上角有个 ✕。点一下先问一句，再点「移走」才真移走。它只把这个项目从工作台移出去（项目行、它所有活的账），仓一个字节都不动——硬盘上的代码还在原地，活自己的工作目录也还在。回执里会告诉你仓在哪儿，你真要删自己去删。

最后一下：你点完成，合那个 MR

接入只把活推到「评审中」。合入永远是人点的——计划屏把这张「规范铺底」从「评审中」拖到「已完成」（详情弹窗里那颗「✓ 点完成」是同一下）。松手会弹出确认框，写明先合哪个 MR；确认之后框不关，一步一句写正在合 MR、拉仓、结清（要两三秒）。合不成就整条不算数，活留在评审中，可以重试。

项目墙 ⚑ 只提醒，不在那儿合。「等你合入」告诉你有一张 MR 等着；去计划屏拖到「已完成」，或总览上那颗「合入并完成」。不要只在 codehub 网页关 issue——那不会合 MR。

这一站结束时你手上有什么

  • 本机一个真实的仓（clone 下来的）
  • 工作台上一个项目
  • 默认分支上有 .bw/ 骨架（合入之后才有；合之前只在铺底那条分支上）
  • 那张「规范铺底」活已完成，对应 MR 已合

下一站：第 1 站 · 看总览

怎么用 · 第 1 站

打开总览，看清这一周

看清「这是什么、健康吗、这周要推什么、指标现在几个数」。改名片、在研版本、项目群也在这里，一张活一次 MR。

这一站能查到
  • 健康灯为什么是灰 / 黄 / 红
  • 指标三类怎么看、手填怎么记
  • 怎么改名片、在研版本、项目群；顶栏刷新真正拉什么

操作

1
项目墙点进这个项目。侧栏默认停在「总览」。
2
从上往下看：名片和健康灯（名片上有在研版本和项目群）、北极星、本周计划进度、滞后、引领、代码仓统计、发版记录。
3
本会话第一次打开这个项目，Workbench 会自己采一轮指标和仓统计。卡上先写「正在采…」，采完折线出现。还想再采，用各块上的「重新采集」。
4
顶栏「刷新」会先把打开着的项目拉到远端最新，再重采。主检出上若只脏了读数或接入留下的未提交名片，Workbench 会先让开再拉。只重画界面、不拉仓，会继续看见同事已经合进主干的旧 metrics.toml。
5
改项目名称 / 想做什么 / 对标 / 三个月长成什么样，或改在研版本、项目群：点「编辑项目名片」。保存后这张活在「评审中」（计划屏右上角下拉切「全部 issue」就能看见，不进待办池）。总览横幅或看板拖到「已完成」合入。

背后

  • 对远端代码仓：读 issue 列表。周目标来自本周运作活①最新评论里 ## 周目标 那一段。纳入了哪些活看 bw:week:YYYY-Www 标签。
  • 对你的机器：跑 .bw/config/metrics.toml 里的采集脚本，窗口近四周。脚本只吐一个当下值时，折线只在本周画一个点。仓统计走 git，再问远端合入的 PR。
  • 对 .bw/：指标定义读 metrics.toml。B 类点「采集」或每天 20:00 自动采，把当天的值记进账本 readings.jsonl（同一天再采覆盖这一行，不写主检出）。折线按周画，取那一周最后一天。没有采集脚本的 B 类仍然采不到。C 类在卡上填今天的数，和 B 类同一份流水、同一套覆盖。

得到什么

  • 健康灯和三条理由。没数据就是灰，不是绿。
  • 北极星 / 滞后 / 引领每张卡：有读数才有现值和折线。A 类每次现算四周；B 类采到的当下值进流水；读到 0 是真值，不是「没采到」。
  • 本周计划进度：周号 + 周目标这段 + 五段计数。运作活①本周已关会写「已完成」。侧栏下一格就是计划。
运作活③写「已完成」只看默认分支有没有指纹清单 .bw/state/managed.toml。关过 issue 但 MR 没进默认分支，总览仍写「未建」。关 issue 不等于铺进了仓。

健康灯怎么亮只从数据推，不能手点

灯旁边同时列出这次判断的理由（成立打勾、不成立打圈）：

  • 本周定了周目标，仓里也有真实提交。目标要写进运作活①评论的 ## 周目标，只开着这张活还不算定了。
  • 本周或上周有指标读数。读的是 .bw/state/metrics-readings.jsonl。点过采集、脚本吐了数，这一条才打勾。
  • 上周有合入或发版。不成立时显示「上周既没有合入也没有发版」。

三条怎么合成一盏灯，见 规矩与查找。没数据 = 灰，不是绿。

下一站：第 2/3 站 · 定本周

事实源 docs/architecture.md 模块 6 / 12 / 13。
怎么用 · 第 2/3 站

开始本周，写下目标和纳入的活

一次会话做完「复盘 → 指标 → 本周目标和活清单」。计划正本挂在运作活①的评论上，不另写周计划文件。

这一站能查到
  • 「开始本周」什么时候出现
  • 周目标写在哪、计划屏怎么按周看卡
  • 「新建活」能建哪几种

操作

1
总览顶上「开始本周」。本周还没有这张运作活①、也还没有周目标，才会出现；已经做过（含已完成）不再冒出来。
2
跳到会话屏。agent 按周计划剧本走：复盘、采指标、起草周目标与纳入清单。你在会话屏的 Orca 页看着、随时能停。
3
你确认之后，agent 当场建纳入的业务活，并打上本周 bw:week:YYYY-Www（codehub 还挂同名里程碑）。周目标、纳入清单、指标读数快照写成运作活①的三条评论，标题必须是 ## 周目标 / ## 本周纳入 / ## 本周指标读数。周目标那一段一句或一段都行。
4
侧栏点「计划」。周头是周目标那段，默认只露两行，点右下角小框展开，再点收起。点某一周只看打了那一周标签的活；没打周标签的切到右上角下拉「全部 issue」就能看见。

背后

  • 对远端代码仓：建一张标题为 更新指标 + 制定本周计划 YYYY-Www 的运作活①（同一周不会建第二张）。纳入的活是真的远端 issue，不是本地草稿。
  • 对你的机器：这张活自己的工作目录。缺的 metrics.toml 和采集脚本会在开工时铺上（已有不覆盖），经这张活的 MR 合进默认分支。
  • 对 .bw/：指标定义和脚本进仓。周目标只在 issue 评论里，不另写一份计划文件。

得到什么

  • 总览和计划屏同一句周目标，杀进程重开还能读回来（读的是 issue 评论）。
  • 本周范围内的活，看板上能点开。旧卡没打类别时，详情里选一次即可。
  • 运作活①可以关。关了不等于第 0 站那张铺底没合入——那是另一张活、另一条 MR。
计划屏「新建活」先弹种类、标题、正文。业务活再选五阶段类别（原型默认 Open Design）。运作活选①或②，标题按本周幂等，类别锁成「运作」。周中要补一张计划或盘点，就在这里建，不必等周五。要走 Open Design：种类选业务活、类别选「原型」，创建后点开卡片再「▶ 开工」。

下一站：第 4 站 · 干活

事实源 docs/architecture.md 模块 13。
怎么用 · 第 4 站

把一张活开起来干

开工、作废、去会话、原型进 Open Design。合入、点完成、发版在第 5 站。

这一站能查到
  • 怎么开工（按钮和拖进「进行中」是同一条路）
  • 构建停会话屏 Orca 页、原型停 Open Design
  • 「去会话」只切树、不改活的状态

操作

1
计划屏点开一张卡（看板或列表都行）。业务活详情会带上已有类别；没打的可在详情或开工确认框补一类——不开工工具的活会被拒绝开工，不会悄悄起 Claude。状态下拉只列出从现在能走到的：待办能去进行中/阻塞/拒绝，进行中能去待办/阻塞/拒绝，待评审能去完成/拒绝，阻塞能去进行中/拒绝。选了和拖拽是同一条路。点 Start / Open / Complete 或改状态下拉后详情会自己关。
2
详情「Start」，或把卡拖进「进行中」。确认框写 worktree，业务活可改类别。确认后跳会话屏。
3
原型类默认停在 Open Design 标签，嵌的是本机 OD 首页。不会自动开跑，你在 OD 里打一句发出去，它的 AI 才动。构建类停在 Orca 页，嵌的是本机已配对的 Orca web；agent 在 Orca 里跑，过程在那看。
4
卡住了：待办或进行中拖到待处理列的「阻塞」段，或详情状态下拉选「阻塞」，写原因。阻塞卡可拖回进行中（只改状态，不会再开一轮工），或拖进「拒绝」作废。不想干了：详情状态下拉选「拒绝」，或把卡拖到已完成列的「拒绝」段（待办 / 进行中 / 待评审 / 阻塞都能拖）。写原因。这不是完成——打已取消标签并关掉远端 issue，卡到「拒绝」。
5
作废不会动本机会话行。停止、开 MR、评审在 Orca 里做，或在计划屏拖列；会话屏这版不露「删除会话」按钮（内核命令还在，屏上暂不露）。远端那张 issue 不动。
6
会话屏只剩 Orca / Open Design 两个页签，都常驻；右侧「指南」哪一屏都在，打开就是这份。

背后

  • 对远端代码仓：开工改状态到进行中。作废写原因、打取消标签、关掉 issue。去会话不碰远端。
  • 对你的机器：每张活一棵工作目录。原型开工后嵌 OD 首页，并尽量灌进系统提示词；灌不上就说没灌上，不假装已经进了某一单对话。构建类在 Orca 里起 Claude（本机本地 pipe 开工）。新树落 <仓>/.bw/worktrees/，旧平级树不搬还能打开。
  • 对 .bw/：会话身份落本机。指标读数不在这一站写——点采集才记。

得到什么

  • 待办拖进进行中 = 开工，和 Start 是同一条路。进行中也可以拖回待办、拖进阻塞或拒绝。阻塞拖回进行中只改状态，不开新工。
  • 作废卡不会冒充已完成。已完成列要先切到「拒绝」再松手才是作废；切在「完成」上仍是合入。作废后再点开工，会说这张活已经取消。
  • 原型：会话停在 Open Design 标签。OD 不自动开跑，你打一句发出去它才动。不在 OD 里另建一单。
  • 去会话：先切到这张活的工作目录树；树上有几扇窗、是否正好落到这条对话是其次，切树成功就算跳到了。
Open Design 不会自动开跑。导出怎么稳落进这张活的目录还没做。要最新内容，点顶栏刷新。

下一站：第 5 站 · 验收记发版

事实源 docs/architecture.md 模块 5 / 7 / 9 / 13。
怎么用 · 第 5 站

合入、点完成、记进一个版本

活到评审中之后，你点完成才合 MR、结清。本周做完的活，再点「发版本」记进远端的一个 Release。不是到点自动结束一周。

这一站能查到
  • 怎么合入并完成（项目墙 ⚑ 只提醒，不合 MR）
  • 发版先建远端 Release，再打标签
  • 在研号不会跟着发版改

操作

1
计划屏把评审中的卡拖到「已完成」，先确认列上切的是「完成」不是「拒绝」，或详情里 Complete / 状态下拉选「完成」。有开着的 MR 就先合再关；没有开着的（可能已经在网页合过）确认后只关 issue。待办拖到「完成」不会过——完成只能从评审中来。
2
项目墙 ⚑ 只提醒你有 MR 等着，不在那儿合。不要只在代码平台网页关 issue——那不会合 MR。
3
本周有已完成的活，计划屏点「发版本」。弹窗里填版本号，默认是在研号的下一位，可以改。确认后才建远端 Release。
4
去代码平台的版本页，或跑 codehub-cli release list / gh release list，核对远端真有这个版本。总览「已发版次数」优先读远端 Release。

背后

  • 对远端代码仓：先合那张 MR，再关掉 issue。发版先建远端 Release，成功后再给勾过的活打 bw:released:vX。顺序不能反。
  • 对你的机器：合入后尽量把主仓拉到最新，收掉这张活的工作目录。本机不会多出一个发版文件。
  • 对 .bw/：在研版本仍是名片里那一行，发版不改它。要切号，去总览点「编辑项目名片」，和四字段、项目群一起保存，走同一张活的 MR。

得到什么

  • 远端多一个 Release；选中的活带上版本标签。
  • 总览「在研版本」还是名片上的号——发版没去改那一行。
  • 总览「已发版次数」跟远端 Release 列表走；远端读不到才退回本机 git 标签。
发版不是只打 issue 标签。第一步是远端 Release，标签是第二步。次数读的是已经发出去的 Release，不是名片上的在研号。

怎么用 · 第 6 站

到点建一张盘点，停在评审中

周五 09:00（默认可改）Workbench 开着，会自己建「资产盘点」并开工，最远评审中。完成仍要你点。每天 20:00 自动采一轮 B 类指标。

这一站能查到
  • 盘点什么时候自动建、最远到哪
  • B 类每天几点自动采
  • 运作活①为什么不会自动开始

操作

1
配置屏能看见「资产盘点 · 到点自动建 · fri 09:00」，还有一行「B 类指标采集 · daily 20:00」。盘点节律写在 .bw/config/issue-policy.toml；B 类日采固定 20:00。运作活①仍是人点「开始本周」。
2
Workbench 开着、过了本周那个时刻，计划屏会出现「资产盘点 YYYY-Www」。类别锁成「运作」，改不了五阶段。
3
这张活会自己开工。看会话或详情：最远到评审中。合入、点完成仍是你来。
4
周一回到总览，开始下一圈。盘点报告挂在这张活的评论里；微重构只出建议，不直接改业务代码。

背后

  • 对远端代码仓：建一张标题固定的运作活（本周有了就不建第二张），打本周标签，开工后改状态。每周模式只对账、写报告；首次模式才给老 issue 补周标签。
  • 对你的机器：Workbench 开着每 60 秒判一次「本周这一刻过了没有」。当时没开着，下次开着会补建。注入的是资产盘点剧本，不是构建类那套。
  • 对 .bw/：每周盘点对照指纹看规范件落后没有，只记差异、不擅自升级。仓根 AGENTS.md 不在这一周写。

得到什么

  • 多一张运作活②，类别显示「运作」、改不了五阶段。
  • Workbench 开着、过了本机 20:00，会自动采一轮 B 类，按当天写入账本（同一天再采覆盖）。点「采集」也能立刻再采今天。
运作活和五阶段类别是两套。不要把盘点、周计划塞进「优化 / 运维 / 运营推广」。仓根 AGENTS.md 不会每周五自动写出来——那条路还没接上，见规矩与查找。
