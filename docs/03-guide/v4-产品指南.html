一周一圈，版本贯穿

添加项目只做一次。之后每周：版本规划 → builder → 出包验证 → 版本发布 → 周复盘。同一串名从 bw:plan:<名> 走到出包目录、Release / tag、bw:released:<名>。点一站进正文。

你说清楚要什么，在路口点头；查资料、写代码、开 MR 交给 agent。正本在仓文件和代码平台上，不在 Workbench 本地库。
  • 「完成」永远你点。agent 最远到「评审中」。定时任务只会建活，绝不完成活。
  • 没数据就是灰，不是绿。自动化（Orca）默认关，打开或 Run now 才到点。

怎么用 · 添加项目

把一个仓接进来

只做一次。选仓、填名片四字段。仓里还没有项目信息时，自动开「项目约定」MR；已有名片不再铺。仓根一个字不动。合入由你点。

去哪：项目墙 · 「+ 接入项目」。工作台抽屉里没有项目墙这条跳转，先关指南回到项目墙再点。

操作

1
项目墙点「+ 接入项目」。本机要有 gh（GitHub）或 codehub-cli（内部）并已登录。项目墙上环境条红了只挡这一条路。工作区根目录在「设置」里，默认 .builders-workbench/workspaces；已接入的项目不会跟着搬家。
2
第一步只问仓在哪。点进「项目地址」，会列出你账号下的仓；打字检索，或直接填 owner/repo。列不出来时摆命令原话，不摆假列表。
3
第二步填名片四格：项目名称、你想做什么、最像的对标、三个月长成什么样。顶上会说这个仓被接管过没有——判据是远端有没有 .bw/project.toml。「没查成」不等于「没被接管过」，别把仓里真正的名片盖掉。
4
点「完成接入」，等十几秒，别猛点。然后去计划屏，把「项目约定」拖到「已完成」（有开着的 MR 会先合）。项目墙 ⚑ 只提醒，不在那儿合。

背后

  • 对远端：仓里没有名片才建「项目约定」，开分支 bw/project，提 MR，停在评审中。已有名片或已开着这张活，整段跳过。不会自动合、不会自动完成。
  • 对你的机器：用 gh / codehub-cli clone 到工作区；目录里已是 git 仓就直接用；有东西又不是 git 仓就弹回。
  • 对 .bw/：写 .bw/project.toml（已有不覆盖）；.bw/.gitignore 只一条 worktrees/。指标和脚本不在这一站预铺。Orca 开着时登记这个仓，并写入三条默认关掉的自动化。

得到什么

  • 本机一个真实的仓；工作台上一个项目。
  • 合入之后，默认分支上有 .bw/project.toml 和 .bw/.gitignore。在研版本不写进名片。
  • 接错了：项目卡右上角 ✕ 只从工作台移走，仓一个字节不动。
总览不是下一站。打开项目后侧栏「总览」看灯、指标、改名片。灯没数据就是灰。旧铺底文件（PROJECT.md 等）接入时不碰，周复盘会删。

机制：docs/architecture.md 模块 3 · 项目约定 / 模块 14 · 接入。

下一站：版本规划

事实源 docs/architecture.md 模块 3 / 14。
怎么用 · 版本规划

确认这个版本干什么

一次会话走完：复盘 → 更新指标 → 确认版本与纳入 → 你确认后落盘。计划正本挂在运作活①的评论上。节律在 Orca，周一 09:00，默认关。

操作

1
先打开这个项目。侧栏点「计划」。要开会话：侧栏点「会话」。Orca 里「定版本计划（Workbench）」默认关——要跑先打开，或点 Run now。关着不会到点。工作台不高亮 Orca 里的开关，你自己在嵌页里找。
2
会话在常驻树 bw/week-plan。Skill 是「更新指标与版本计划」：复盘、采指标、先确认本周版本（推荐 v0.x，别的名字也行），再起草版本目标与纳入清单。你在 Orca 里看着、随时能停。
3
你确认之后才落盘：纳入的活打 bw:plan:<名>；运作活①写下三条评论，标题必须是 ## 版本目标 / ## 本周纳入 / ## 本周指标读数。
4
回计划屏。点某个版本只看打了那个 bw:plan:<名> 的活。没打版本标签的，右上角下拉「全部 issue」。

背后

  • 对远端：有光杆未打版本标签的运作活①就复用，没有再新建。纳入的活是真的远端 issue。
  • 对你的机器：改动落在 bw/week-plan，不写主检出。
  • 对 .bw/：缺的 metrics.toml 和 .bw/scripts/ 会在这场铺上（已有不覆盖），经这张活的 MR 合进默认分支。版本目标不另写一份计划文件。在研版本不进 project.toml。

得到什么

  • 仓里：.bw/metrics.toml、.bw/scripts/（经 MR）。
  • 运作活①评论：版本目标 / 本周纳入 / 本周指标读数。纳入的活带着 bw:plan:<名>。
计划屏「新建 issue」建业务活。类别选「原型」再 Start，才走 Open Design。

机制：docs/architecture.md 模块 13 · 周循环与计划。

事实源 docs/architecture.md 模块 13。
怎么用 · builder

把一张活开起来干

看计划屏，拖进进行中或点开工。agent 在 harness 里跑（各类任务运行时）：SYSTEM 说哪张活，references 说改仓怎么落，skill 说这场怎么带人。环心是人守判断。本地 worktree 不是正本。

操作

1
打开项目后侧栏点「计划」。四列：待办 / 进行中 / 待处理 / 已完成。
2
把卡拖进「进行中」，或详情里 Start。确认后跳会话屏。没类别的业务活要先选一类，否则不开工。
3
构建类停在会话屏的 Orca 页；原型类停在 Open Design，不会自动开跑，你打一句发出去它才动。
4
卡住了拖到待处理的「阻塞」；不想干了拖到已完成列的「拒绝」（要写原因）。这不是完成。停止、开 MR、评审在 Orca 里做。合入、点完成见版本发布前的验收，在计划屏拖到「已完成」。

背后

  • 对远端：开工改到进行中。提完 MR 后活到评审中（bw:status:inreview）。作废打取消标签并关掉 issue。
  • 对你的机器：每张活一棵工作目录，新树在 <仓>/.bw/worktrees/。灌 SYSTEM.md.tmpl / build.md / mattpocock-skills。去会话只切树，不改活的状态。
  • 对 .bw/：这一站不写指标、不改名片。正本是 MR 和 issue 标签，不是本地树。

得到什么

  • 一张 MR；活在评审中等你看。
  • 完成仍然你点：有开着的 MR 就合入，没有则只关 issue。

机制：docs/architecture.md 模块 4 · 提示词 / 模块 5 · 状态机 / 模块 7 · 会话。

事实源 docs/architecture.md 模块 4 / 5 / 7 / 13。
怎么用 · 出包验证

先出包，再验包

发版前在计划屏点「出包」。产物落在本机，不合入、不上 issue。Orca 自动出包、每日集成未建。

操作

1
打开项目，侧栏点「计划」，切到这个版本（「全部 issue」里没有「出包」）。
2
点「出包」：已发过的号从那次 tag 另开一棵树出，主工作区不动；在研还没打 tag 就先把工作区拉到最新再出。先出包，再验包。验包不过点「详情」。弹窗可关掉继续跑；要停就点「停止」。
3
Orca 不会替你出包。每日集成未建。

背后

  • 对远端：不建 Release，不打发版标签。
  • 对你的机器：跑仓里 .bw/release/pack/pack.cmd 和验包脚本。产物在 .bw/release/out/<名>/。
  • 对 .bw/：安装包不进 git。号就是当前版本那串名。

得到什么

  • 本机一份这个版本的安装包。弹窗第一行可以打开目录。

机制：docs/architecture.md 模块 13 · 出包（PackRelease）。

下一站：版本发布

事实源 docs/architecture.md 模块 13；协议 docs/adr/0005。
怎么用 · 版本发布

你点「发版本」

不会自动发。先建远端 Release 和 tag，再给勾上的活打 bw:released:<名>。不写仓文件。验收（合 MR、点完成）也在计划屏，同一屏拖到「已完成」。

操作

1
打开项目，侧栏点「计划」。要把活收口：拖到「已完成」（先确认切的是「完成」不是「拒绝」）。有开着的 MR 就先合；没有则只关 issue。完成永远你点。
2
切到在研那个版本（「全部 issue」里没有「发版本」）。点「发版本」：只有在研且还没打过 tag 的号能点，发过就灰着。没有已完成的活也能发。号锁死当前版本。
3
去代码平台核对真有这个 Release，或跑 gh release list / codehub-cli release list。

背后

  • 对远端：先建 Release（顺带打 tag），成功后再给勾过的活打 bw:released:<名>。顺序不能反。可以一张不打。
  • 对你的机器：发版尽量把工作区对齐远端。不出安装包——安装包是上一站。
  • 对 .bw/：不改名片，不写仓文件。在研号仍看运作活①，不进 project.toml。

得到什么

  • 平台上一个 Release <名>、一个 tag <名>；勾上的活带着 bw:released:<名>。
发版不是只打 issue 标签。第一步是远端 Release，标签是第二步。

机制：docs/architecture.md 模块 13 · 发版本（CutRelease）。

怎么用 · 周复盘

周五盘点，停在评审中

Orca「资产盘点（Workbench）」周五 15:00，默认关。Skill 资产盘点：盘 .bw/ → 盘项目 → 收口每周进展。有改才开 MR。完成仍要你点。

操作

1
打开项目。要跑：到会话屏的 Orca 嵌页，打开「资产盘点（Workbench）」或点 Run now。工作台不高亮 Orca 里的开关。错过了同样去 Orca 补跑。Workbench 开着也不会自己守钟。
2
会话在常驻树 bw/ops-audit。类别锁成「运作」。最远到评审中。
3
改了 .bw/ 才有 MR。合入、点完成仍是你来。下周一回到版本规划，同一串名再转一圈。

背后

  • 对远端：本周还没有就建一张运作活②（标题含 ISO 周，如 资产盘点 2026-W36），有在研版本就挂 bw:plan:<名>。
  • 对你的机器：钟在 Orca。Orca 没开就下次打开项目再补打自动化。
  • 对 .bw/：对照现行契约清残留、升格式。不重写名片，不重定北极星。仓根 AGENTS.md 不代写。项目审查只出建议，不改业务代码。

得到什么

  • 这张活的评论：## Workbench 资产 / ## 闭环 / ## 项目审查。
  • 该版本运作活①上追加 ## 每周进展。总览右栏按新到旧列出。
  • 打开 Orca 里「每日指标采集」后，每天 20:00 采 B 类（也是默认关）。总览「立即采集」能立刻再采今天。

机制：docs/architecture.md 模块 14 · 资产盘点。

怎么用 · 规矩

两条规矩

具体操作回各站。这里只留不会变的形状。

1完成永远你点

agent、定时任务、自动化最远到「评审中」。计划屏拖到「已完成」或详情「点完成」才算。有开着的 MR 就合入，没有则只关 issue。不要只在代码平台网页关 issue——那不会合 MR。

2没数据就是灰

灯在总览名字旁，只从数据推，不能手点。没读数、没目标、没合入记录，停在灰，不是绿。界面上的数字都能用 codehub-cli / gh / git / 打开仓文件独立核对。

版本贯穿

同一串名：bw:plan:<名> → .bw/release/out/<名>/ → Release / tag <名> → bw:released:<名>。在研版本不写进 .bw/project.toml。

还没做的先说清楚。Orca 自动出包、每日集成未建。仓根 AGENTS.md 不会在接入或周五盘点时自动写出来。别的没建项看 docs/architecture.md 各模块「没建什么」。
