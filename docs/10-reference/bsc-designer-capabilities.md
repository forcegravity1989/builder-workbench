# BSC Designer 能力评估 · 提炼版

> **30 秒导读**:这是什么——BSC Designer(bscdesigner.com,以平衡计分卡为核心的战略执行软件)的**能力清单与方法论的转述提炼,不是原文**(原文只存链接,2026-09-04 取读)。按「它怎么做 → Workbench 今天怎么样 → 引入 / 改造后引入 / 不引入 / 已有等价」组织,每条落到我们自己的文件或模块。给谁看——做指标体系(运作活①、指标卡、健康灯)后续设计的会话,和要拍板「引哪几条」的人。现在作数吗——**评估稿,待裁决**。裁决用配套的 gate 卡(见文末「引用与状态」),拍板后由会话把结论回写到本篇「裁决结果」段;**本篇不改产品主张**,产品主张仍听 [`01-principles/03`](../01-principles/03-press-release-faq-flywheel.md)。

## 一句话结论

BSC Designer 是「使命 → 战略 → 目标 → KPI → 行动方案 → 复盘」这条完整实施流程的成熟商业实现。Workbench 的北极星 / 滞后 / 引领三层、现算推导、先对后亮,已经覆盖它方法论的骨架,而且在「难造假」上比它硬(它的权重、基线、目标都是人手填的可调参数;我们的灯只能从读数推导)。**值得引入的不是它的建模体量(视角树、权重、总分、级联、预算),而是六条小而准的语义**:引领只预警、滞后才见红;起点→目标的进度现算;到期未填提醒;活与指标挂钩;定义完整度自检;剧本里多问三句。这六条全部能在现有三层与铁律内落地,不加连接器、不加第二份正本。

## 它的实施流程(转述),和我们每一站的对应

BSC Designer 把「一个组织怎么把计分卡建起来、跑起来、复盘」写成了四个缩放层级的同一条链路(五层抽象的战略规划、六步实施系统、八步执行循环、能力建设五阶段),外加一份季度复盘会议议程。压成一张表对我们的站:

| BSC Designer 的环节 | 它的产物 | Workbench 的对应 | 差在哪 |
|---|---|---|---|
| 战略核心:使命 / 愿景 / 干系人 | Settings › Strategy 里的文本 | 接入定框:名片(想做什么 / 最像的对标 / 北极星那句) | 等价;我们只留三句 |
| 战略描述:目标 + 战略地图 + KPI + 行动方案 + 预算 + 风险 | 一棵 Root → 视角 → 目标 → KPI → 行动方案的树 | `.bw/metrics.toml` 三层 + 活(issue) | 我们没有目标层与视角层,**有意的**(见「不引入」) |
| 量化:每个目标一条引领 + 一条滞后 | KPI 的 Context 页选 Leading / Lagging | 引领 / 滞后各 ≤3 | 它的引领 / 滞后**影响计算**(见 C1),我们的只是分层 |
| 级联到部门 / 个人计分卡 | 多张计分卡按数据 / 按上下文 / 按视角连接 | 项目群 + 项目墙 | 单人产品不级联 |
| 执行:行动方案推进,KPI 更新,自动算 | initiative 带进度 / 预算 / 时间线 | 活的看板 + 采集 + 现算 | 它的「行动方案挂 KPI」我们设计了没接(见 C5) |
| 复盘:季度战略复盘会(会前更新指标 → 回顾上次结论 → 找差距根因 → 新因素) | 会议纪要 + 假设当 initiative 入队 | 运作活①(复盘 → 更新指标 → 引导出本周 → 建活),周节律 | 等价,我们更密;它会前「哪些指标没按时更新」的清单我们没有(见 C4) |
| 嵌入:复盘日历、审计标准、治理例程 | Embed 阶段产物 | 周一运作活① + 周五资产盘点(运作活②) | 等价 |

它对创业公司的自述值得记一笔:官方承认平衡计分卡对创业公司的日常目标管理「偏重」,建议自举阶段先用表格或免费版(<https://bscdesigner.com/startup-kpis.htm>)。这一条支持我们的扁平三层,不支持往它的树形结构靠。

## 它的模型(转述,只留对照要用的)

- **一条 KPI 的字段**(<https://bscdesigner.com/webbsc_manual/kpi-properties.htm>):名字 / 描述 / 单位 / 负责人;当前值(按日历日期)/ 最小 / 最大 / **基线 / 目标**;**权重** / 优化方向(越大越好 / 越小越好 / 二值 / 自定义公式)/ 原始数据标记(只存数不参与计算);**引领 / 滞后**;证据要求(按日期或按指标);更新周期;变更历史;依赖。
- **双轨计算**(<https://bscdesigner.com/calculate-metrics.htm>):Performance = 在 [最小, 最大] 上归一化;Progress = (现值 − 基线)/(目标 − 基线)。它明确说两者回答的是不同问题(「总体做得怎样」vs「离目标还有多远」),建议都算。
- **引领 / 滞后的计算语义**(<https://bscdesigner.com/webbsc_manual/formulas.htm>):**只有滞后指标的表现向上卷入容器;引领指标只算本地表现**,用来验证「这个目标背后的假设成不成立」,不直接影响上层。
- **权重上卷与总分**:容器默认按权重加权平均,层层到根得一个「计分卡指数」;官方自己承认这个总分的业务意义「仍有争议」。
- **红绿灯**:每条指标可自定义三色阈值;版本史证实曾有「到某个颜色档就发邮件」的告警,现行手册已弱化成笼统的「负责人通知」。
- **行动方案(initiative)**:挂在目标或 KPI 下,带进度 / 预算 / 时间线 / 状态;进度可以指向一条指标。官方专文强调**活动进度指标与结果指标不能平均混算**(<https://bscdesigner.com/outcomes-vs-activities.htm>),并建议「执行系统导入的项目进度当引领,业务结果当滞后」(<https://bscdesigner.com/connect-strategic-planning-project-management.htm>)。
- **数据采集**:手填、Excel / CSV 导入、七种数据库直连(查询里有 `%%UpdatePeriodStart%%` / `%%UpdatePeriodEnd%%` 占位符)、REST API(每小时 100 次)、Zapier / Power Automate、Google Sheets 插件、Webhook 外推。**值继承**:空白日期可沿用上一个已知值。
- **展示与复盘**:多仪表盘(时间图带目标线、关键指标卡、仪表盘、甘特、总览图),十一种报表(含「KPI 更新状态」= 哪些指标没按时更新),定时邮件报表;质量分(AI 按最佳实践给计分卡打分)。
- **方法论**:「找 KPI」的十步法(定义测量对象 → 找盲点 → 找约束与成功要素 → 测不出来就观察或做受控实验 → 定尺度 → 排优先级 → 找引领与变化指标 → 自测行为影响 → 降低测量成本 → 建地图与计分卡,<https://bscdesigner.com/kpi-system-book.htm>);「定义一条 KPI」的十二步(名字不混目标和单位 → 挂目标 → 现值 / 基线 / 目标 → 采集步骤 → 引领 / 滞后配对 → 权重 → 更新频率 → 到期日 → 测量成本 → 权限 → 用途声明 → 预期行为 vs 实际,<https://bscdesigner.com/kpis-guide.htm>);反模式(先有 KPI 后有战略、虚荣指标、指标本身变目的、用未验证的 KPI 算奖金,<https://bscdesigner.com/avoiding-kpis-misuse.htm>)。
- **它自认的弱项**(<https://bscdesigner.com/strategy-software-comparison.htm>):审批工作流弱、层级优先不擅长网状关联、复盘驱动的执行不如竞品。

## 建议引入的六条:证据 · 结论 · 影响

每条按「今天什么样(带出处)/ 它怎么做 / 批了改哪 / 不批损失什么 / 可逆吗」写。全部不加第二份正本、不加连接器、不违反四铁律。

### C1 · 引领只预警,滞后才见红

- **今天**:`crates/bw/src/derive/mod.rs` 的 `derive_project_health` 把 `red_metrics` 里任何一条越线都判红,不分层;`red_metrics` 由 `app/health.rs` 对三层所有指标跑 `target::breach` 得来。
- **它怎么做**:引领指标的表现只算本地、不向上卷;滞后指标才卷入容器。理由是引领量的是「努力」,用来验证目标背后的假设;滞后量的是「结果」。
- **批了改哪**:`HealthInputs` 把越线拆成「引领越线」与「滞后 / 北极星越线」两组;前者给黄 + 理由「引领预警:…」,后者给红。仍是同一个纯函数、同一处判色,密封类型不动。
- **不批损失什么**:引领指标本来就是先行量,越线一次就把项目打红,人会把引领目标定松来躲红——这正是虚荣指标的温床。
- **可逆**:一处纯函数,改回来一行。

### C2 · 起点 → 目标的进度,从读数现算

- **今天**:`crates/bw/src/derive/target.rs` 只回答「越线没有」;卡上是「现值 + 相对上周」(`docs/architecture.md` 模块 12)。没有「离目标还有多远」。
- **它怎么做**:基线是定指标那一刻的起始值,目标是想到的值,进度 = (现值 − 基线)/(目标 − 基线)。基线是手填字段。
- **批了改哪**:**不加字段**。起点 = 展示窗口内第一个已知读数(可回溯类现算窗口首周,不可回溯 / 手填类取账本里最早一行);卡上画「起点 · 现值 · 目标」三点水位条,不印百分数(基线与目标接近时百分数会夸张)。目标仍是 `target` 那一串。
- **不批损失什么**:滞后 / 北极星这类水位型指标只有「达标 / 越线」两态,看不出趋势正在靠近还是远离。
- **可逆**:纯展示层推导,无持久化。

### C4 · 到期未填提醒,和「谁没按时更新」清单

- **今天**:`docs/architecture.md` 模块 6 与 12 都写着「C 类定时建提醒活没做」;B 类有每日 20:00 自动采,C 类靠人记得。运作活①评论里没有「上周哪些指标没有读数」一段。
- **它怎么做**:每条 KPI 有更新周期,到期提醒负责人;复盘会前先出「KPI 更新状态」报表列出没按时更新的。
- **批了改哪**:①周节律不变(不做逐指标周期):本周还没有手填读数的 C 类指标,周四到点建一张提醒活(标题幂等、只建队列、不代填);②运作活①评论「本周指标读数」段后加一行「未采到:…」,由 Workbench 从流水现算。
- **不批损失什么**:手填指标会悄悄断档,灯因「两周没读数」变灰时人才发现。
- **可逆**:提醒活是普通活,不建就是不建。

### C5 · 给活挂指标,活的完成度不等于指标好转

- **今天**:指标卡样张(2026-09-04)已画「牵动它的活」;`docs/architecture.md` 模块 13「没建」明写「给活挂指标的命令没接(建活时『推的指标』列恒空)」。
- **它怎么做**:行动方案挂在目标或 KPI 下;进度指标与结果指标分开两套字段,官方专文警告两者不能平均;建议「执行系统导入的项目进度当引领,业务结果当滞后」。
- **批了改哪**:接通建活 / 详情里的「推的指标」——挂法用 issue 正文一行 `指标: <名>`(issue 是唯一正本,不加标签、不加本地表);引领卡列出挂了它的开着的活。**第二半句不用改**:活的完成由人点、项目指标不点灯,已经是「活动 ≠ 结果」。
- **不批损失什么**:引领指标越线时,人不知道该去推哪张活;活关完了指标没动,也没人问「为什么」。
- **可逆**:正文里一行约定,删掉即无。

### C6 · 定义完整度自检,三档不打分

- **今天**:`standard/skills/metrics-refresh/SKILL.md` 的质量门(0–40)是 agent 自评、写进 `docs/metrics.md`,内核不看;界面对「写了一半的定义」只在采集时报「没采集方案」。
- **它怎么做**:AI 按最佳实践给计分卡打质量分(有负责人、有目标、引领滞后配对、有行动方案……),显示在角上。
- **批了改哪**:内核从 `metrics.toml` + 流水现算每条指标的「定义完整度」,只查机器能判的四件:定义非空、目标可判读(`target::breach` 认得出方向和数)、采集方案能跑(`CollectPlan::runnable`)、近两周有读数。四件全有=成熟,缺一两件=较弱,只剩名字=无。卡上一枚小字,不进健康灯、不打百分数。
- **不批损失什么**:「目标未设」「写了一半」这类问题散落在采集失败的 toast 里,运作活①每周要人肉翻文件。
- **可逆**:纯派生,不落任何表。

### C7 · 剧本多问三句(只改 `metrics-refresh`)

- **今天**:增量校准四件事(补缺 / 重判 A-B-C / 修采不到的 / 不重排北极星);反指标与自动化免疫检验都是**事前**问;测量成本只在 `docs/05-features/process-metrics/plan.md` 的风险里出现过一次(两步拉取约 90 秒)。
- **它怎么做**:定义一条 KPI 的十二步里,第 9 步算测量成本(成本必须低于价值),第 12 步事后对比「当初期望它诱导的行为」与「实际诱导的行为」;引领指标被定义为「目标背后的假设」,由滞后指标验证。
- **批了改哪**:增量校准段加三问,每问一句话写进 `docs/metrics.md`:①**测量成本**——这条指标每周花多少时间 / 多少次接口调用,值不值;②**行为复核**——上一轮它让我们做了什么不该做的事(事后版反指标);③**传导验证**——上周引领动了,滞后跟着动了吗;连着四周不跟就质疑这条引领。`standard/VERSION` 抬一档。
- **不批损失什么**:引领指标可以长期「绿着但没用」,没人问它到底预测了什么。
- **可逆**:剧本文字。

## 明确不引入的(和为什么)

| BSC Designer 的做法 | 不引入的理由 |
|---|---|
| 视角 / 目标 / KPI 三层树 + 战略地图因果链 | 单人构建者的「框」是名片三句 + 版本目标,不是一棵战略树;03 原则里要维护的全景是 4+1 架构,不是战略地图。树会把人拽回「填框」 |
| 权重 + 加权平均 + 计分卡总分 | 我们的聚合是取最差者:有红则红。总分把一条红平均成黄,正是「假完成靠绿灯掩护」;权重是手填可调参数,等于给「把项目点绿」留了一条路。它自己也承认总分的业务意义有争议 |
| 最小 / 最大归一化 | 只为跨指标加权比较服务;我们不比较、不加总 |
| 级联到子计分卡 | 项目群只需要项目墙上每盏灯 + 取最差者 |
| 预算 / 挣值 / 时间线 / 甘特 / 风险蝴蝶结 | 活的正本是 codehub issue,Workbench 不做项目管理套件;护栏用反指标 |
| 连接器 / 七种数据库 / Zapier / Webhook / Google Sheets | 「一条指标直接指向一个脚本,没有连接器层」是拍过板的;脚本能连任何系统,且脚本本身就是「这个数怎么来的」的文档 |
| 值继承(空白日期沿用上值) | 与我们相反:采不到的点断开,绝不当 0 也绝不补前值 |
| AI 生成样例数据 / 批量改值 | 违反「绝不伪造读数」「agent 不写读数」 |
| 角色 / 审批 / SCIM / 团队 / 公开分享 | 单人 |
| 十一种报表 / 定时邮件 / PDF / 图片导出 | 运作活①评论是周报正本,MR 是审计记录 |
| 模板库 / 同步副本 / 另存模板 | 接入不摊模板;先对后亮反对从模板挑指标(它自己也说「几条量身定制的指标胜过五十条通用的」) |
| OKR / Hoshin 皮肤 | 词表明写不用 KPI / OKR 这些词 |

## 附录 · 它的三张研发相关样例里,可当候选词汇表的指标

只列名字与它标的类型,给运作活①「完整起草」翻;**先对后亮不变**——工程活动量永远坐不了北极星,挑哪条要先过六项判据。来源:项目管理 <https://bscdesigner.com/project-management-kpis.htm>、IT <https://bscdesigner.com/it-kpis.htm>、创业公司 <https://bscdesigner.com/startup-kpis.htm>(在线样张 webbsc.com 只读取读)。

| 样例 | 指标 | 它标的类型 / 单位 | 与我们过程指标目录的关系 |
|---|---|---|---|
| 项目管理 | 周期时间 Cycle time | 天 | 目录已有「变更前置时间」 |
| 项目管理 | 进度偏差 Schedule variance、按时完成率、错过的里程碑 | % | 我们的版本目标 + `bw:plan:v0.x` 完成数可现算 |
| 项目管理 | 返工率 % of rework | % | 目录已有「返工轮数」 |
| 项目管理 | 需求无歧义度、战略 / 项目对齐度 | % | 无对应;我们的替代是意图件被接受 |
| 项目管理 | 已识别风险中有缓解计划的占比、无缓解计划却发生的风险数、重复风险率 | % / 个 | 无对应;目录的「同类复发」相近 |
| IT | 平均无故障时间 / 平均修复时间 / 可用性 | 天 / 小时 / % | 无对应(我们不管运行时) |
| IT | 重复出现的问题数(工单重开率)——它标为滞后 | % | 目录「活存活率」反指标即重开率 |
| IT | 恢复成功率(模拟崩溃后恢复) | % | 无对应 |
| 创业 | 燃烧率——它标为滞后、越小越好 | $ | 无对应 |
| 创业 | 解锁关键功能的客户占比、每日使用时长 | % / 小时 | 使用段候选(北极星判据「落位」过关) |
| 创业 | 免费试用转化率、流失率、推荐数 | % / 个 | 使用 / 价值段候选 |
| 创业 | 有意义的对话数——它明写是「付费订阅」的引领 | 个 | 引领候选,配滞后「付费数」 |
