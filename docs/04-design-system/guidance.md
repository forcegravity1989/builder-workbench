# 引导与旅程规范

> **读者与时机**：盘点 BW 用户旅程、设计引导、更新指南或制作传播素材的人与模型，开始相关工作前完整读取。
> **职责与边界**：本篇维护引导分工、展示规则、覆盖矩阵和产出归属；业务行为与验收归所属特性，研发执行归 [journey-review](../../.claude/skills/journey-review/SKILL.md)，问题与处理进度归 Issue。矩阵记录当前覆盖及已认可的补充方向，不另做项目进度表。
> **结构与更新**：入口分工 → 展示与结果 → 现有内容 → 旅程矩阵 → 产出与维护。新增、调整或验证一条旅程及其引导时，同批更新受影响行和来源。

## 入口分工

面向 2–3 人共同做项目、一个组有多个项目的 builder。每个人使用自己的 BW，共享项目目标、任务与交付事实。用户可以先开始一件工作，再按需要使用版本运作和高级能力。

**旅程是完成一件事的连续过程，可以跨多个屏幕；引导是帮助用户走完其中一段的内容。** 一条旅程可同时用到入门、探索和屏内引导。传播取材于旅程，不决定旅程是否成立。

| 用户的问题 | 承载位置 | 内容边界 |
|---|---|---|
| 怎么准备好，开始第一件事？ | **BW 入门** | 当前工作必需的准备、组件与智能体配置；可选配置标明用途，在需要时再做。包含 BW 采用的 Orca 能力，按 BW 的使用顺序组织。 |
| BW 能帮我怎样工作？这个功能有什么用？ | **探索 BW** | 统一发现和回看入口：按工作结果找到完整旅程，也能按特性/屏幕找到介绍。说明结果、适用场景与起点，并引向实际界面。 |
| 我现在在这个屏幕，该怎么操作？ | **操作中引导** | 当前屏幕的简短介绍、空态提示和问号操作演示。使用眼前真实控件，帮助完成下一步；与探索共用内容依据，不另维护一套业务规则。 |

通用帮助集中在左下角问号；顶部不重复一套帮助。入门、探索持续可回看；屏内问号就地回看当前操作。新功能提示是内容的投放时机，文档是可查阅的说明，海报/漫画是传播产物，都不再增加一套同级引导分类或“旅程中心”。

## 展示与结果

以下是逐条整改的目标规则；现有机制与尚缺的内容见后两节，不能因规范已写就认定界面已经符合。

- **首次安装**只引入开始工作所需的准备。按平台、已有安装和当前任务判断依赖；缺哪个组件就说明用途、安装入口及成功结果。可选集成、第二个项目、自动化和统计不成为所有人的开工门槛。
- **首次进入复杂屏幕**先简短说明“能做什么、从哪里开始”，用户可选开始引导或直接操作。不自动播放长篇演示；简单屏幕或清楚的空态不强加一次弹窗。
- **主动演示与回看**随时可退出。探索提供完整介绍；跳到实际屏幕后才能开始依赖真实控件的操作引导。屏内问号重播本屏相关片段，不让用户先走完整条旅程。目标控件或前提不存在时说明缺什么、怎样继续，不展示悬空步骤。
- **避免叠加**：首次设置、屏内介绍和新功能提示协调显示，一次只处理眼前一件事。新功能提示按是否适用、是否看过或已经使用决定，不因每次升级都弹一次。关闭后仍应能在入门、探索或相关屏幕找到相应内容。
- **引导不能代替易用性**：用户不看教程也应能找到主要动作。先消除多余步骤、含混名称与重复配置，再补必要解释；数据采集失败如实显示未知和恢复入口，只影响依赖该数据的动作。例如可选 SDLC 统计缺数据，不应挡住查看任务和继续工作。

“看过介绍”“配置可用”“实际做成”分别记录与表述：打开演示只能说明看过；配置状态来自真实检测；工作成果来自真实任务/交付事实及必要的人确认。跳过不算完成，不用浏览进度推断项目或旅程完成。重看不重置业务状态，重启后的进度与配置按实际来源读回。

演示形式按用途选：概念和布局用静态示意，操作顺序可用现有交互动画；需要说明真实联动时使用有版本依据的真机录屏，操作中引导使用真实控件。模拟动画必须与真机证据分开，不能把动画里的成功当成已验证能力。

## 旅程覆盖矩阵

下表是一条旅程一行的内容安排。**“待补”是已认可的内容方向，尚未实现；“未验证”不等于不可用。** 现有内容只按上节可核对的片段填写。后续每次走查把相应单元格替换为实际入口、内容/指南链接和证据范围，不因做了一个屏幕就标整条完成。缺口的处理任务关联原 Issue，本轮共用方法来源为 [#607](https://github.com/forcegravity1989/builder-workbench/issues/607)。

| 旅程与可见结果 | 探索内容 | 屏内引导与特性落点 | 首次出现方式 | 用户指南 | 传播形式 |
|---|---|---|---|---|---|
| 新安装 → 准备 → 纳入项目 → 开始第一件真实工作 | 已有入门、工作区/终端片段；完整串联待补 | [项目纳入](../05-features/project-intake/spec.md)、原生创建工作区/会话；已有原生操作引导，纳入部分待走查 | 现有初始设置；项目空态与最短路径待走查，不额外强弹探索 | 未建；需从真实安装验证到实际工作可继续 | 可选“一次开始工作”海报 |
| 修改 → 同伴评审 → 合入，共享可核对的交付事实 | 已有差异、PR 与交付片段；团队串联待补 | [任务管理](../05-features/codehub/spec.md)、[评审通知](../05-features/pr-review-notify/spec.md)与原生评审；缺口随实际 provider 核对 | 进入相关任务/评审界面按需介绍；不用“看完演示”代替真实评审 | 仅有 [CodeHub CLI 参考](../03-guide/codehub-cli.md)，不是整段指南 | 可选两人协作漫画 |
| 多任务并行 → 中断 → 继续，找回各自上下文 | 已有工作区、智能体状态/编排片段；中断接续待串联 | [版本会话管理](../05-features/version-workspace/spec.md)、原生分屏与历史；现有创建/会话引导可复用 | 先开始一件事；首次需要并行或恢复时介绍 | 未建；需核对保留现场与恢复结果 | 可选并行工作短演示或漫画 |
| 多项目日常跟进 → 找到需要处理的事并进入工作 | 已有多仓库设置；BW 扫墙旅程待补 | [项目墙](../05-features/project-intake/spec.md)、[项目总览](../05-features/overview-metrics/spec.md)、[版本总览](../05-features/version-overview/spec.md)；BW 引导待补 | 首次进复杂屏简短介绍；无项目、无材料、无数据分别解释 | 未建；缺数据也要能理解下一步 | 可选多项目日常海报 |
| 确定版本目标/任务 → 开始工作，团队共享本版承诺 | 已有里程碑屏内引导；完整探索内容待补 | [项目里程碑](../05-features/overview-metrics/spec.md)、[版本计划](../05-features/version-planning/spec.md)、[版本会话管理](../05-features/version-workspace/spec.md)；其余片段待补 | 首次进入计划说明起点；依赖按需准备，不要求先配齐指标/自动化 | 未建；需验证目标、任务及开工之间的连贯性 | 可选从目标到开工的漫画 |
| 核对交付 → 人确认验收 → 安排下一版 | 完整探索内容待补 | [版本验收](../05-features/version-acceptance/spec.md)、[版本总览](../05-features/version-overview/spec.md)；相关 BW 引导待补 | 首次验收说明来源、判断与下一步；缺证据保持未知 | 未建；需验证实际证据、人的判断和下一版衔接 | 可选验收接续漫画；持续主题才做多期 |

特性屏的局部内容归上述旅程复用：项目纳入/墙、项目总览/里程碑、版本计划、版本会话、任务/评审通知、版本验收、版本总览均已给出落点。指标配置、自动化和内部集成是按需片段，随使用它们的旅程核对；知识库等未纳入这六条的能力不在本表伪造覆盖，用户选中后再增加相应行。特性归属名称始终沿[特性矩阵](../05-features/README.md)。

## 产出与维护

每条旅程交付**一条真实可走的流程，以及需要的引导和说明**。不是每行都必须有弹窗、动画、海报和漫画；无需的形式写明不采用及理由，未制作与不采用分开。

| 产出 | 合格内容与形式 | 正本位置 |
|---|---|---|
| 旅程与覆盖 | 角色、起点、最短步骤、可见结果、失败后下一步；已有/待补/已验证的范围和来源清楚 | 整体用例在 [architecture](../architecture.md)；本篇只维护引导安排与覆盖；具体行为回所属 spec |
| 产品内引导 | 入门的必要准备；探索的结果/场景/起点；屏内的真实控件和下一步。只新增本旅程需要的片段 | 代码复用现有机制，设计及验收点进所属特性 spec；改变布局时原型仍归该特性 |
| 用户指南 | 使用前提 → 操作 → 可见结果 → 常见失败与恢复；只写已实践的路径，注明适用版本/平台与证据链接 | `docs/03-guide/<journey>/`，沿用已有相关指南，不为每屏强建文件 |
| 演示及传播 | 同一条已验证流程取材；海报讲一个收益，漫画讲场景与协作，多期围绕持续主题。模拟画面、真机录屏和效果主张有明确边界 | 指南同目录保存正式素材及必要可编辑源，指南链接素材；候选分镜/草稿留仓外。制作不等于对外发布 |
| BUG、瘦身与验证 | 问题有复现，修复有复验；引导与简化围绕同一任务，不用加教程掩盖问题 | 任务及遗留在 Issue；变化、运行证据、未验范围在 PR，特性 STATUS 维护适用证据边界 |

维护矩阵的人是当前旅程的交付者：先核对现状，边修边补；同一 PR 同步受影响的行、特性资料、指南和入口。并行窗口先按用户指定旅程划范围；合入前重读其他窗口对同一行的修改，不覆盖已新增的事实。某项仍未验证就保留明确边界，不能填“已完成”凑齐矩阵。
