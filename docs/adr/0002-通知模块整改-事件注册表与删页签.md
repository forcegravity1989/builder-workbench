# 群通知改事件注册表,删通知页签,个人提醒走 OS 弹窗(后建)

issue #18 把通知模块整张重做。原来发群事件是自由字符串(`"review"`/`"merged"`/`"release"`)散在各动作点内联调 `chat_send`,通知页签是应用内列表(等你合入 MR + 现算事件流)。决定:① 群通知改成**固定枚举事件注册表**(`NotifyEvent`),统一 dispatch,加新事件 = 加一个 variant + 在动作点调一次 dispatch;② **删通知页签整片**(屏 + 事件流 + `seen_at` 死字段 + nav + 深链),**保留徽章角标**(改 tooltip、去掉「通知屏」字眼);③ **个人 Windows 弹窗本轮不建**,后续单独会话。理由:枚举让周报这类新发送点低成本接入、不再散落硬编码字符串;页签删后徽章撑着「有几张等你合入」,弹窗到位再替。

## Considered Options

- **事件模型**:自由字符串(现状,灵活但散落、难枚举配置项)→ 选固定枚举注册表(类型安全、配置项稳定、加新事件集中);否决了「仍用字符串 + 一张常量表」——配置开关要按枚举渲染,字符串仍会漂。
- **通知页签**:保留并扩 vs 删。删——个人通知该是推送式(OS 弹窗),不是你得点进来才看得见的列表(页签头注释本就这么说)。
- **徽章角标**:随页签删 vs 留。留——弹窗没落地前它是唯一「等你合入」信号,且便宜;只改过时的 tooltip。

## Consequences

- `ChatConfig.notify` 仍是 `Option<Vec<String>>`(匹配枚举 key),向后兼容旧 `project.toml`;默认集从 3 件(review/merged/release)改为 5 件(week_plan/issue_created/merged/release/weekly),`review` 移除。
- 周报(`Weekly`)有 variant + 配置开关 + dispatch 槽,但本轮**无触发、无生成**——后续会话补,接入点已留。
- `NotifyVm` 瘦成只剩 `unread`(角标用);`to_merge`/`events`/`seen_at`/`NotifyEventVm`/`build_notify_events`/`stamp` 删。
- `Panel::Notify`、`BW_PANEL=notify` 深链移除;项目轨红点 + 项目墙 ⚑ 留。
