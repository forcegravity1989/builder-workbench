# 指标采集与读数

> 30 秒导读:这是「模块」系列的一篇,讲 buddy MVP 怎么把一个项目的指标数采进来、读出来。给写代码和改代码的人看;现状以 `docs/archive/v4-prototype/design.md` §10 为正本,这篇是它的代码落点索引。作数。

## 这个模块是什么(1-2 句)

把项目仓 `.bw/metrics.toml` 里定义的指标真采一遍、读出来。一条判据贯穿全设计:**今天能采到这个数,上周三那天的值现在还能算出来吗** —— 能就是可回溯,一个字都不存、每次现算;不能就落进只追加的读数流水。采集方式只有脚本和手填两种。

## 数据落哪

- **可回溯(A 类)**:一个字都不存,要看几周就现算几个窗口。
- **不可回溯(B 类)+ 手填(C 类)**:设计上的落点是 `.bw/metrics/readings.jsonl`,只追加、永不改已有行(同一指标同时点采到不同值就追加新行,读时取最后一条)。**这条追加写入路径今天还没接**(见下「没建什么」);读取那一端在 `crates/bw-v4/src/app/health.rs:93` 的 `read_metric_readings`,供健康推导与指标卡共用 —— 它属于模块 6,这里只标边界。
- 指标定义:`.bw/metrics.toml`(人手写正本)。脚本:`.bw/scripts/*.py`(铺一次归项目)。采集结果:本机纯缓存(丢了重算,不进仓)。

## 依赖什么

- 仓文件解析器 `metrics_file.rs`(模块 2)读 `.bw/metrics.toml`;`v4_engine::tokio_cmd` 起子进程;`isoweek` 算 ISO 周号;`serde_json` 解析 stdout。**不认识任何远端系统** —— 连 GitHub/codehub、读本地文件、算 git 历史全是脚本自己的事,buddy 只会「起进程、传窗口、读 JSON」。

## 产出与验证

- 产出:`Vec<MetricReadout>`,每条近 N 周、一周一格(`MetricPoint`,`collect.rs:34`),`None` = 这周没采到(不是 0);`current` = 最后一周的值,最后一周没采到就是 `None`,绝不拿上一周顶当现值。
- 读回(不碰本机库、不碰 claude):`cargo run -p bw-v4 --example metrics_smoke -- <仓路径> [周数]` —— 先摊定义(每条标 A/B/C)、再真采一遍、每条附自己复算的命令,三类各走各的路一眼看得出来。
- 界面:总览屏点「↻ 采一次指标」,走桥那对命令/事件。

## 没建什么(如实标 defer)

- **B 类(不可回溯)定时采集 + 追加进 `readings.jsonl`** 没接:`collect.rs:83` 如实报「这条路还没接上」,不假装采过、也不悄悄当成手填。
- **C 类(手填)定时建提醒活** 没做(设计 §10.6)。
- **定时采集**(§10.7 的「定时到点」那条)随 §10.5 一起没做;今天只有人点「采一次指标」通。
- readings.jsonl 的**写入/追加端**没建(读取端在模块 6)。
