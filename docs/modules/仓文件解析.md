# 仓文件解析

## 这个模块是什么

把项目仓 `.bw/` 下的配置/定义文件解析成内存结构,供总览、计划、配置等屏现读现用。仓是正本——人、agent、第二台机器都要看的东西住在仓里走 MR,本地不存第二份;这一层是读写正本的唯一入口,别处不许自己拼路径读 `.bw/*.toml`。

## 代码在哪几层

全在 buddy MVP 内核 `crates/bw-v4/src/` 下,一个目录五个解析器:

- `repo/mod.rs:24` — 共用错误 `RepoFileError`(IO/解析/格式三态);`mod.rs:44` 的 `read_to_string`(文件不存在返回 `Ok(None)`,即「诚实的无事发生」);`mod.rs:57` `write_file`、`mod.rs:72` `parse_toml`、`mod.rs:84` `toml_string`(把多行输入框文字转义成合法 TOML,否则下次读就崩)。
- `repo/project_file.rs:13` — `.bw/project.toml`:项目意图(名称/对标谁/北极星)+ `[chat]` 项目群 + 规范版本/在研版本,这几样都不入库、现读。
- `repo/metrics_file.rs:22` — `.bw/metrics.toml`:指标定义正本,**只认 `schema_version = 2`**(读到旧格式整份拒收、不迁移);**不做** `deny_unknown_fields`(人手写、多一个字段就整份崩,代价太大)。
- `repo/issue_policy_file.rs:12` — `.bw/issue-policy.toml`:开工工具清单 + 类别→工具→workflow 三列映射 + 评审/节律/看板列文案;不入库、每次现读。
- `repo/managed_file.rs:16` — `.bw/managed.toml`:buddy 托管件的指纹清单 + 对账四态(缺/过期/人改过/已是最新),人改过的一律不覆盖只提示差异;指纹算法 `managed_file.rs:78`(`sha256:` 前缀)。
- `repo/standard_file.rs:10` — `.bw/standard.toml`:项目用的是哪版规范、铺了哪几类件(与 buddy 二进制自带的版本是两件事)。
- `standard/mod.rs:45` — 章程 `.bw/PROJECT.md` 的模板 `CHARTER_TMPL` 经 `include_str!`(编译期读进二进制,零 IO)打进产品,是 markdown 模板、**不算解析器**;`mod.rs:152` 的 `render` 做 `{{key}}` 占位符替换。

## 数据落哪

不落本地库——仓文件本身就是正本,解析结果只在内存里给调用方现用。写回时手写渲染(`render`)而非 `toml::to_string`,为把注释留在文件里给人看(这个坑 2026-08-05 在指标文件上踩过一次)。

## 依赖什么

`serde`/`toml` 做反序列化,`sha2` 算指纹,`thiserror` 做错误。五个解析器都走 `mod.rs` 的共用读写口;`metrics_file.rs` 额外依赖 `crate::model::{category_from_key, Category}` 把类别键认成枚举。**对 V3 任何 crate 零依赖**。

## 产出与验证

产出是五个 `read(workspace)` → `Result<Option<File>>`(不存在返回 `Ok(None)`,解析失败返回 `Err` 且绝不写半份缓存)与配套 `write`/`render`。验证靠 E2E:深链启动到总览/计划屏,stderr 见 `[BW_OPEN]` 即渲染成功;本层零库、`sqlite3` 读回不适用;门禁 `cargo check -p bw-v4` 编译过、`cargo test` 现存内联测试过。

## 没建什么

`.bw/metrics/readings.jsonl`(不可回溯类指标的只追加读数流水)的解析器**还没建**——`docs/archive/v4-prototype/design.md §10.11`(第 899 行)明确标「读数流水解析器还没建」。采集执行(起脚本、传窗口、读输出)落在 `crates/bw-v4/src/app/collect.rs`,不在本模块边界内(见模块 12「指标采集与读数」);规范铺底编排(`CORE_TEMPLATES` 的按站落地、对账)见模块 3。
