## 这个模块是什么(1-2 句)

buddy 接入一个项目时,自动建一张运作活③「规范铺底」,把二进制里编进的 `standard/` 模板渲染成 `.bw/` 下的骨架文件,写进这张活自己的 worktree 和分支、开 MR 等人合。全程不起 agent——buddy 自己写文件、记指纹、提交。

## 代码在哪几层

- **模板表与版本号**:`crates/bw-v4/src/standard/mod.rs:32`(VERSION 编译期 `include_str!` 进二进制)、`:35`(`version()` 读 buddy 侧版本号)、`:69-76`(`LayAt` 枚举:Adopt=接入就铺 / OnFirstUse=走到那一站才铺)、`:89-148`(`CORE_TEMPLATES` 八件模板表,按落盘顺序)、`:152-158`(`render()` 把 `{{key}}` 换值;没给到的占位符原样留着,不替成空串)。
- **铺底第 1 步(写核心件)**:`crates/bw-v4/src/standard/bootstrap.rs:53-113`(`write_core_files()`,三条规矩:人手改过不覆盖、指纹清单最后写、落盘方式看仓是不是 buddy 建的)、`:115-164`(`lay_one()` 逐件写:磁盘内容指纹与记录一致才覆盖,不一致跳过并报原因)。
- **探测(这张活跑几步)**:`crates/bw-v4/src/standard/bootstrap.rs:167-222`(`BootstrapProbe` + `probe()` async:查根提交作者判是不是 buddy 建的仓、提交数/标签/CHANGELOG 判有没有历史)、`:228-230`(`issue_title()` 幂等键固定「规范铺底 v{版本}」,不跟探测结果走——否则重跑多建一张活)。
- **指纹清单与对账**:`crates/bw-v4/src/repo/managed_file.rs:16`(`REL_PATH = ".bw/managed.toml"`)、`:48-57`(`Reconcile` 四态:Missing/Stale/HumanEdited/UpToDate)、`:60-75`(`reconcile()`:磁盘指纹≠记录→人改过;指纹一致但版本旧→过期;都没有→缺)、`:78-80`(`fingerprint()` 原始字节 SHA-256,不做空白归一化)。
- **编排(建活→开树→写→提交→推分支→开MR)**:`crates/bw-v4/src/app/bootstrap.rs:31-277`(`run_standard_bootstrap()`,只在活自己的 worktree 里动手;跳过的件/preexisting/被 .gitignore 拒的件如实写进 issue 评论;MR 开着才推「评审中」)、`:280-309`(`reconcile_standard()` 纯读对账,不建活不写仓)。
- **模板正本**:`standard/README.md`(目录说明,含「还没做的部分」)、`standard/08-meta/standard.toml.tmpl`(项目侧规范版本+启用的大类)、`standard/05-issue-policy/issue-policy.toml.tmpl`(五类别→开工工具→workflow 默认映射+评审/节律/看板规则)。

## 数据落哪

铺进项目仓的件全部收在 `.bw/` 下:`.bw/PROJECT.md`(章程,`mod.rs:43`)、`.bw/standard.toml`、`.bw/metrics.toml`、`.bw/issue-policy.toml`、`.bw/scripts/*.py`、`.bw/design/README.md`、`.bw/managed.toml`(指纹清单,最后写)。**仓根一个字不写**——`AGENTS.md`/`CLAUDE.md` 是项目自己的文件,给它们写内容等于「建议改造人家的项目」,归资产盘点。buddy 侧版本号在 `standard/VERSION`(随发布走);项目侧 `.bw/standard.toml` 的 `version` 记「这个项目铺的是哪版」(随项目走),两值常相等但含义不同,不合并。**零本地数据库**——codehub issue+标签是唯一 issue 正本,指纹清单是仓文件不是表。

## 依赖什么

内核内:`crate::repo::managed_file`(指纹读写与对账)、`crate::repo::{write_file, RepoFileError}`(仓文件写入)、`crate::git`(`is_repo`/`root_commit_author`/`commit_count`/`tags`/`commit_paths`/`is_tracked`)、`crate::standard`(模板表/版本/render)、`super::worktree`(worktree 供给)、`super::issue_store`(issue 评论)。外部 crate:`sha2`(SHA-256,`managed_file.rs:13`)、`serde`(TOML 序列化,`:12`)。

## 产出与验证

- **结构化产出 `BootstrapReport`**(`bootstrap.rs:19-34`)三段:written(真写进去的路径)/skipped(跳过+为什么)/preexisting(本来就有且非 buddy 铺的,界面会当正本读,必须显眼报一声)。
- **事件**:`Event::StandardBootstrapped`(`app/bootstrap.rs:253-258`,带 files+committed)、`Event::StandardReconciled`(`:303-308`,带 missing/stale/human_edited)。
- **进度行如实**(`app/bootstrap.rs:225-251`):写了几个件+分支+MR 号;一个都没写=「件本来就都在」;写下了没提交=如实说「不是 git 仓或提交被拒」,不假装。
- **「完成」永远由人点**:MR 开着(`mr.number > 0`)才推「评审中」(`:266-275`);没写东西原地不动。

## 没建什么(如实标 defer)

- **历史回填**:探测到了如实写进活正文,但**没跑**——要起真实 agent 会话,走资产盘点首次模式(`app/bootstrap.rs:9-10`,design.md §4.4)。今天只实现前三条探测判据(提交数/标签/CHANGELOG),远端信号(已关闭 issue/已合并 MR)未实现。
- **给项目写开发手册(`AGENTS.md`)**:归资产盘点的子技能 `project-handbook`,要先问人愿不愿意(`app/bootstrap.rs:7-8`)。
