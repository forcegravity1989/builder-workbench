# 项目群

## 这个模块是什么

适配项目本来就有的一个群(今天只有 WeLink)。buddy 只做两件事:往群里发一条通知(评审中/合入/发版);定计划时拉一段上周群历史当参考。不是发明一个新的协作面,也不做双向机器人。

## 代码在哪几层

全在 buddy MVP 内核 `crates/bw-v4/src/`:

- `chat/mod.rs:60` — 接口 `trait ChatGroup`(发消息 `send`、拉历史 `fetch_history`、可选探活 `probe`);`mod.rs:83` 工厂 `for_project`(认提供方**只在这一处**,认不出落到 `none`);`mod.rs:92` 默认同步三件事 `DEFAULT_NOTIFY`(review/merged/release);`mod.rs:109` 文案 `notify_text`(`【事件】#活号 标题 · MR · 谁该动 → bw://深链`,不 @ 人)。
- `chat/welink.rs:44` — 真实 WeLink 实现:`send`(`:126`)走 `welink-cli im send-to-group`,只发纯文本,link 拼成 `{title}: {url}` 追加(`:67`);`probe`(`:146`)真发一条「【buddy 探活】」;`fetch_history`(`:134`)**永远返 `HistoryUnsupported`**——welink-cli 没有读群历史的子命令;`:57` `bin()` Windows 上传 `welink-cli.cmd`(无 .exe,走 `cmd.exe /c`);`:108` `classify` 把非零退出按文本分流鉴权/网络错。
- `chat/mock.rs:14` — 本机假群:`send`(`:47`)每条往 stderr 打一行 `[BW_CHAT_SENT]` 当证据;`fetch_history`(`:57`)返调用方预置的历史(`:31` `with_history`),没预置就如实说拉不了。
- `chat/none.rs:7` — 「没配群」,send/fetch 一律返 `NotConfigured`,让没配群时别的流程不崩。
- `app/chat_notify.rs:21` — 同步用例 `chat_send`(读 `[chat]` 配置 → 不在勾选名单就跳过 → 工厂建群 → 发);`:69` `chat_notify_issue`(按模板拼文案);`:87` `sync_notify_to_chat`(界面显式触发,没配/没勾选时回一条「跳过了」不静默)。
- `repo/project_file.rs:18` — `[chat]` 段 `ChatConfig`(provider/group_id/notify);`:27` `notify` 用 `Option<Vec>`,**整行没写 = 用默认三样,写了空数组 = 静音**,这两件事不能合成一个 `Vec`;这几样都不入库、现读现解析(`:59` `read`)。

三个事件的调用点:`app/issue.rs:167` 与 `:294`(进评审中,`review`)、`app/ops.rs:266`(合入,`merged`)、`app/plan.rs:198`(发版,`release`,`number=0` 不挂活号不写深链);界面显式触发走 `app/mod.rs:463` 的 `Command::SyncNotifyToChat`。

## 数据落哪

配置在仓文件 `.bw/project.toml [chat]` 段(正本走编辑项目信息的轻量活 + MR,不给群开平行通道)。**发送不落库**——没有「已发送」账本、没有去重键、没有失败重试队列;发送即完成,极小概率下(进程恰在发送前后重启)同一件事会被重推一条,这是已接受的知情代价(设计 §9.5)。探活与「事件流我读到哪了」的时间戳只写本机设置文件,不开表。

## 依赖什么

`welink-cli`(npm 全局装,用户本机自己 `auth login`,buddy 不碰不存凭证)经 `v4_engine::tokio_cmd` shell-out;`Box<dyn ChatGroup>` + `async_trait`、`thiserror`、`time`。App 层依赖 `workspace_of`、`issue_or_err`、`repo::project_file::read`。对 V3 任何 crate 零依赖。

## 产出与验证

产出是 `Event::ChatNotifySent { number, event_type, ok, note }`(成功 `ok=true` 空 note;失败带原文错误,不吞错伪装成功)。验证:E2E 用假群,stderr `grep '[BW_CHAT_SENT]'` 即发送证明;`probe` 人点「测一下」才发一条,不是静默 spam;welink-cli 退出 0 = 发送即完成(token 刷新提示不算失败)。验收#8:配了群的项目,一次评审中/一次合入/一次发版各在群里收到一条;**重复触发允许真的重发一条**——验收时确认它「确实会重复」,而不是反过来验证「不会重复」。

## 没建什么

**群摘要 defer**(LEFTOVERS ⑧):它要 `fetch_history`,而 welink-cli 天生拉不了群历史(只发不读,和钉钉/企微群机器人一个性质),`welink.rs:134` 稳定返 `HistoryUnsupported`,调用方安静跳过——这是正常返回值不是错。设计 §9.5 规定的「定计划那次会话里 agent 引用上周群摘要」因此对 WeLink 还做不到;假群(`mock.rs:31` `with_history`)预置历史可走通管线。不做双向对话机器人、群里点按钮改活状态(违反「完成永远人点」)、一个项目多个群、除 WeLink 外任何一家的正式实现(设计 §9.6)。
