## 这个模块是什么(1-2 句)

项目里的「计划屏」:左栏窄周列表 + 中栏周头/六列看板 + 右侧活详情抽屉,把「这周干什么」和「活的推进状态」装在一个界面里。周是时间单位,用 ISO 周文本(`2026-W34`,周一为起点)表示,按机器本地时区判定「现在是哪一周」;周列表、发版、看板计数**全部现算**——没有周计划索引表、没有发版表。

## 数据落哪

**零本地数据库**——codehub/GitHub 的 issue + 标签是唯一 issue 正本。排期 = 给 issue 打 `bw:week:YYYY-Www` 标签(A 类·issue 数据,buddy 直接改、不走 MR,拖拽落定那一刻标签就是新的);发版 = 在远端建 Release(打 tag + notes)+ 给活打 `bw:released:vX` 标签,按版本号幂等。发版默认版本号现读项目名片文件里的在研版本(`plan.rs:151` `project_file::read`),这个值不在库里、不在索引表里。周列表扫 issues 的 `bw:week` 标签 distinct 得到,并上活缓存里出现过的周取并集去重。

## 依赖什么

内核内:`issue_store`(标签读写 `set_week`/`set_released`/`find_open_by_title`)、`crate::repo::project_file`(项目名片文件读写)、`crate::git`(`pull_ff` 合入后快进主检出)、`crate::isoweek`(周换算)、`crate::trend`(走势现算)、`v4_engine::remote`(按 provider 建 Release/查 MR)、`v4_engine::github`(`issue_branch` 确定性 `bw/issue-<iid>`)。外部 crate:`time`(ISO 周与本地时区)、`tokio`(各周并发)。节律规则读项目仓的 `.bw/issue-policy.toml`。

## 产出与验证

- **事件**:`Event::WeekPlanStarted`/`WeekPlanInProgress`(`plan.rs:28/64`)、`Event::IssueScheduled`(`:119`)、`Event::ReleaseCut`(`:193`,带 `rows_written`)、`Event::CurrentVersionChanged`(`:154`)、`Event::OpsAutoFired`(`ops.rs:150`)。
- **发版两条护栏**:版本号认不出「数字.数字」格式按钮置灰、内核也拒收(`plan.rs:171` 拒含 `(` 或空的版本号);按版本号幂等,同一版本不重复打标签/重复建 Release。
- **验证**:数字一律 SQL 读回/标签读回——排期拖拽后查 issue 的 `bw:week` 标签;发版后查 codehub Release 与 `bw:released` 标签;重启后周列表扫标签现算一致。状态机锁死:`can_transition_to` 守「完成」唯一入口是「评审中」,自动建的活最远也只到评审中。

## 没建什么(如实标 defer)

- **预览 · 未合入**:`plan/mod.rs:209` 做成灰态(开关 disabled),要从活自己的 worktree 读未合入的 `.bw/metrics.toml` 与 ops① issue 评论重渲染周头,未接(design.md §6.7 有设计,代码里没有对应函数)。

- **给活挂指标的命令没接**:建活时「推的指标」列恒为空(design.md §6.9 标注)。
- **切在研版本要不要建活走 MR**:在研版本只存仓文件里,这处张力未消解,留给人拍(design.md §6.9)。
- **macOS 页面内拖放**:还没真机验证过一次(design.md §6.9);Windows 上必须关掉窗口框架自带的文件拖放处理器否则 WebView 屏蔽页面内拖放。
