# 桌面壳

## 这个模块是什么

buddy MVP 的桌面应用壳(bin 名 `bw-v4-dev`,Dioxus 0.7 / wry WebView,macOS+Windows)。壳只渲染和转发意图——健康是什么颜色、活能不能转到那一列、指标有没有读数,全部由内核算好塞进 ViewModel;壳里没有一行业务判断,命令失败就把原话放进 toast,不假装做成了。

## 代码在哪几层

全在 `crates/app-shell/src/` 下,不碰任何 V3 crate:

- `main.rs:29` — `fn main`:起窗口(1440×920,Windows 关掉 wry 拖放处理器免得 WebView2 屏蔽页面拖放)、读深链、launch `Root`;`main.rs:65` `Root` 组件(订阅内核推来的 VM、分发顶层三屏 / 项目内六入口);`main.rs:214` `body()` 内容区分发——**终端挂在屏的外面**,切面板不卸载它,否则 agent 刷屏期间切走再回来字节是真丢的。
- `bridge/mod.rs:415` — `spawn()`:起一条独立 tokio 线程持有 `bw_v4::App`,壳这边只发 `Command`、收 `Vm`;`mod.rs:437` panic 包一层(内核线程崩了就把死因送进「起不来」红字,**宁可显眼地坏也不要安静地坏**);`mod.rs:193` `data_dir()`(Windows 默认 `D:\builders-workbench\data`,D 盘不在退回 `%APPDATA%`);`mod.rs:33` `read_deep_link()`;`mod.rs:55` `Req` 枚举(真命令 + 纯导航);`mod.rs:152` `Bridge` 句柄(全进程一个,clone 都指向同一线程,`PartialEq` 恒真好当组件 props)。PTY 字节流和长命令进度**走 broadcast、不走 ViewModel**——终端一秒几百批,每批重拼整份 VM 会拖垮界面。
- `bridge/nav.rs:9` — `Panel` 六入口枚举;`nav.rs:85` `TopView` 顶层两屏;`nav.rs:57` `PanelNav` / `nav.rs:70` `GuideNav`(纯本机导航信号,切入口开抽屉不经内核、不改数据)。
- `bridge/vm_build.rs`(747 行)/ `vm_derive.rs`(259)/ `vm_kb.rs`(260)/ `vm_panels.rs`(597)— 从内核状态拼装 `Vm` 的四个分文件,各管一块(build 主干 / 派生 / 知识库 / 各屏细节)。
- `vm.rs:11` — `Vm` 全体 ViewModel 类型。**屏与屏之间只经这里共享数据结构**——`screens/plan/` 永远不许 `use crate::screens::overview::…`(守卫拦着)。这一层不算任何东西,每个字段都是内核现算好塞进来的。`vm.rs:425` `SessionTab::OpenDesign` 是内嵌 Open Design 标签(本机网页内嵌类,不起 CLI)。
- `theme/mod.rs:17` — `GLOBAL_CSS`(`include_str!` 整张样式表,正本是高保真那张 `hifi.css`);`mod.rs:20` `signal_color` / `mod.rs:30` `signal_label`(没数据是灰不是绿,配色上也守住)。
- `chrome/mod.rs`(333 行)— `IconRail` / `ProjectRail` / `TopBar` / `GuideDrawer` / `Toast`(外壳框架);`sparkline.rs`(162)走势线。
- `screens/mod.rs:27` — `route()` 六入口分发。九屏各一目录、每屏只对外暴露一个 `View` 组件:**项目墙**(260 行)/ **接入**(711)/ **设置**(128)三顶层 + **总览**(576)/ **计划**(mod 382 + kanban 213 + detail 198)/ **会话**(474)/ **通知**(147)/ **配置**(407)/ **知识库**(368)六项目内入口。每个屏必须是 `#[component]`,普通函数的 hook 落在调用方槽位上,切屏后类型换了 downcast 失败直接 panic。
- `adapters/` — 一个外部能力一个目录,每个目录带一份 README(借自哪/借了什么/没借什么):`terminal_xterm`(585 行,xterm.js + PTY 字节桥,资产 `include_str!` 随二进制走不联网)/ `claude_cli`(23,声明接法+探活,真起进程在内核执行器)/ `codegraph`(140,子进程封装,15 秒超时,装了就现跑没装就灰)。

## 数据落哪

buddy MVP 本地零数据库——本机数据是 TOML/JSONL,落 `data_dir()` 下(注册表 / 设置 / 会话在 `assets/` 子目录)。codehub / GitHub 的 issue+标签是唯一 issue 正本。**壳自己不存任何业务数据**,界面上每个数字都是拼 ViewModel 那一刻从内核现算塞进来的。

## 依赖什么

`bw_v4`(内核 App / Command / Model)、`v4_engine`(`InteractiveCliExecutor` / github / codehub 远端)、`dioxus` 0.7 hard-pin + `wry`、`tokio`。**对 V3 任何 crate 零依赖**。xterm.js 前端资产 `include_str!` 编进二进制,不联网拉。

## 产出与验证

产出是桌面应用 `bw-v4-dev`。验证靠深链:`BW_OPEN`/`BW_PANEL`/`BW_VIEW`/`BW_SEL` 启动到指定视图,stderr 打证据行——`[BW_BOOT]`(项目数+资产路径)、`[BW_OPEN]`(深链解析结果)、`[BW_ENV]`(各开工工具探活)、`[BW_VM]`(活数/会话数/事件数/周数/本周五段计数/最新事件时间戳,都能用 codehub-cli/gh/git/cat 当场对)。三条结构守卫(纯 grep、CI 照跑,设计 `design.md` §12.2 第 961 行):`guard-no-cross-screen-import.sh`(屏不互相引用)、`guard-file-lines.sh`(单文件 1500 行硬上限 / 600 软目标,只查 buddy MVP 三 crate)、`guard-screen-hooks.sh`(用 hook 的函数必须是组件)。

## 没建什么

Cursor 适配模块还没开;Open Design 内嵌标签已在会话屏建好(`SessionTab::OpenDesign`),但没单开 adapter 目录。蒸馏按钮、MR 检查列、「等你输入」那种 agent 细粒度状态(要靠 hook 回传,还没接)未建。会话切走再回来看一个已结束的会话,回放是空的(存不存回放还没做)。Windows 安装包不在本仓。删旧壳的判据一条都不满足(`design.md` §12.6 第 999 行)。
