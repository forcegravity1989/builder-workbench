# 会话与执行

## 这个模块是什么

活怎么被真干起来。▶跑 把交互式 `claude` 起在**内嵌终端**(伪终端 PTY)里,活在 issue 自己的一棵 git worktree 里干,人全程看得见、随时能停;run 成功只推「评审中」,「完成」永远由人点,同一件活绝不记两次。

## 代码在哪几层

执行器与 PTY 在 buddy MVP 能力底座 `crates/v4-engine/src/`,会话生命周期在 buddy MVP 内核 `crates/bw-v4/src/app/`:

- `interactive_cli.rs:1` 起整个模块;`:12` buddy MVP 只有内嵌终端这一条路;`:88` `CLAUDE` 静态 CLI 表(supported=true);`:133` `LaunchPlan`(binary/args/env/cwd/submit_prompt);`:160` `HOST_ENV_PREFIX="CLAUDE"` 按前缀剥宿主会话身份(不按名字列,防随宿主加变量再腐烂);`:205` `apply_child_env`;`:242` `build_startup_plan`(`--append-system-prompt`+位置 prompt+`--dangerously-skip-permissions`+`--disallowedTools "Bash(gh pr merge)"`);`:319` `build_resume_plan`(`--resume <id>` 精确 / `--continue` 回退);`:366` `SkillOutput{completed,summary}`;`:380` `InteractiveExecutor` trait;`:451` `InteractiveCliExecutor` 只实现 `run_skill_pty`、委托 `pty_backend::active()`;`:533` `MockInteractiveExecutor` 自我标注【mock】、不往仓里写一个字。
- `pty_backend.rs:1` 平台接缝;`:7` 两份实现 Windows conpty-oxide / Unix portable-pty,所有平台同路径不 Windows 专属;`:60` `SUBMIT_READY_DELAY=2s`(首启替用户按一次 Enter 提交位置 prompt 的启发式);`:63` `PtyBackend` trait;`:88` `active()` 按编译目标选;`:153` Windows 后端 kill-on-drop Job;`:360` Unix `ChildGuard::Drop` 起独立线程 `teardown_group`(`:519`)按进程组先 SIGHUP 宽限再 SIGKILL 连坐、最后 `wait()` 收割——future 被 `abort()` 丢弃子进程绝不变孤儿。
- `terminal_manager.rs:1` 集中模块(身份用 Uuid,不碰 child handle/平台类型);`:18` `OUTPUT_BATCH_CAP=64`、`:21` 每批 ≤8KB,满丢最老防背压卡 claude;`:25` `ConversationMeta`;`:76` `TerminalManager`;`:118` `attach`(同 id 重 spawn 只关自己不杀 peer);`:190` `close`(丢 sender→input_rx 结束→PTY 收尾);`:195` `drain_events`。
- `workspace.rs:46` `issue_worktree_path`(兄弟目录 `<主仓名>-issue-<号>`);`:60` `provision_issue_worktree`(`git worktree add -b bw/issue-<号>`,重跑幂等)。
- `app/worktree.rs:1` 每张活一棵 worktree(两张活同时跑互不撞车);`:31` `IssueTree{path,branch,isolated}`;`:45` `provision`(非 git 仓/空仓退回主工作区 isolated=false,如实标不假装隔离);`:84` `remove_if_clean`(只在干净时收——脏的是真实劳动成果,「点完成」不构成删它授权);`:114` `mirror_ignored`(被仓拒收的件落主工作区)。

- `app/ops.rs:175` `merge_and_settle`(已 Done 直接短路=绝不记两次;合 MR→set_status Done→收 worktree,`settled=true`)。

## 数据落哪

会话身份(ConversationId/`--resume` 的 claude session_id/worktree 路径/分支名)进 `claude_conversation` 表;进程态(字节流/尺寸/child handle)纯内存,重启即逝。issue 状态与 `settled_at` 的正本是 codehub/GitHub issue+标签,本地零库——`settled_at` 现读远端 `closed_at` 的 RFC3339 串解析(`issue_store.rs:221`),不自己写。

## 依赖什么

`async_trait`+tokio mpsc 做字节/输入双通道;`conpty-oxide`(Windows)/`portable-pty`+`nix`(Unix,crate `#![forbid(unsafe_code)]`,killpg 走 nix 不走 libc 裸调用)做 PTY;`v4-engine` 不依赖任何 V3 crate(cargo tree 读回为 0)。会话屏走单独的 `pty_bytes` watch 通道,**不走事件总线、不走 ViewModel**——终端一秒几百批,重拼 ViewModel 会拖垮,且字节是一次性流(design.md:594)。

## 产出与验证

产出:`SkillOutput{completed,summary}`——`completed` 只表示「PTY 子进程退出了」(`pty_backend.rs:37`),不表示「活干成了」,那由上层(评审→人点完成)判定。验证靠 `cargo run -p bw-engine --example pty_smoke`(起 `bash -c 'echo pty-ok'` 读回)+`-- --teardown`(丢输入端进程组连坐)+`-- --abort`(`abort()` 丢 future 子进程照收尾);真跑 `claude` 受信任对话框/网关影响**不进门禁**(design.md:1080),指挥器全程走自我标注替身。

## 没建什么

不解析 `session.jsonl`(对话摘要 collector 早在 §2.5 砍了,终端滚屏+会话文件本身即记录,`interactive_cli.rs:9`);`SkillOutput` 粗粒度(退出码不看、读错误与正常退出不分,细化留 LEFTOVERS 减负-17);`run_skill` 起系统终端窗口那条路已删(`interactive_cli.rs:448`);Cursor 适配(`interactive_cli.rs:115` supported=false)。探活(模块 8「远端与工具探活」)与 open_design(模块 9,它是 web_embed 工具另讲)不在本模块边界。
