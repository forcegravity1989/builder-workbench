# 系统提示词与渐进加载

> 30 秒导读:buddy 给每张开工的活拼一份系统提示词,并把自带技能摊到自己的资产目录供 agent 按需读。这层不论哪份 workflow 都兜住 buddy 的统一要求。给接手提示词/技能注入的人看。现在作数(buddy MVP)。

## 这个模块是什么
buddy 给每张开工的活现拼一份四段系统提示词,外加把自带技能摊到自己的资产目录。这层不论哪份 workflow 都兜住 buddy 的统一要求(身份、铁律、规范索引),再按活挂的 workflow 注入对应剧本——提示词只放索引,正文让 agent 按需读(渐进加载)。

## 代码在哪几层
- `crates/bw-v4/src/app/bootstrap.rs:364-394` `agent_system_prompt`:拼四段。`:432-457` `base_prompt` 出段①身份与这张活(填活号/标题/类别/workflow)+ 段②铁律(最远到评审中、合并永远是人、指标只来自真实采集、干砸如实停,外加「先读仓根 AGENTS.md」一句)。`:374-383` 段③规范索引,只列**仓里真存在**的 `.bw/` 件,一份一行「路径 —— 一句话」。`:386-392` 段④本活剧本。`:397-421` `SkillPointer` 与 `skill_pointer`(按 workflow 在 buddy 自己的技能目录里找那份 `SKILL.md`)。`:427-430` `allow_skills_dir` 把资产目录加进 CLI 的 `--add-dir`,否则路径给了也读不到。
- `crates/bw-v4/src/standard/skills.rs:26-45` 十份 `SKILL.md` `include_str!` 进二进制;`:52-66` `desc_of` 从 frontmatter 抽 `description`(取不到返回空串,不编);`:84-106` `all()` 摊平返回十份(六方法论 + 四运作剧本)。
- `crates/bw-v4/src/app/issue.rs:130-141` 开工接线:user prompt 放活正文(`issue.body`),system prompt 走 `agent_system_prompt`,再 `allow_skills_dir`。`crates/bw-v4/src/app/mod.rs:163-184` `skills_dir`/`ensure_skill_assets`(摊到 `<asset_root>/skills/`,幂等,写不下返回 `None` 如实少一段);`:207-214` `agent_briefing` 只读预览口子。`crates/bw-v4/src/app/ops.rs:42-51` `skill_slug`:workflow → slug,只映射两个运作剧本(week-planning / asset-audit)。

## 数据落哪
buddy MVP 本地零库。技能正本编进二进制(`include_str!`),开工时摊到 `<asset_root>/skills/`;活号/标题/类别/workflow/正文都是 codehub issue 正本;拼出的提示词是**一次性字符串**,经 `--append-system-prompt` 送进 CLI,不落盘、不缓存。

## 依赖什么
`standard::skills` 与 `standard::CORE_TEMPLATES`(段③来源)、`ops::skill_slug`(workflow → slug)、`v4_engine::LaunchPlan`(`--add-dir`)、Issue 模型、worktree 供给的 `run_dir`、codehub issue 作正本。`docs/buddy/system-prompt.md` 是 **V3 编译资产**,展示前三段结构(身份/铁律/规范索引);buddy MVP 不读它,在代码里现拼。设计依据见 `docs/archive/v4-prototype/design.md` §2.5(五层渐进加载)、§7.5(两批技能两个地方)。

## 产出与验证
产出 = 四段系统提示词。验证靠 `agent_briefing`(`mod.rs:207`)只读读回——试点第一天用户问「我看没有技能路径」,路径其实一直在,只是终端看不见,这个口子就是为它开的(同函数,显示什么 agent 就收到什么)。`ensure_skill_assets` 写不下返回 `None`,段④如实省略不编路径(`mod.rs:169`);段③只列真存在文件,铺底没跑的项目一条都不列(`bootstrap.rs:374`)。活正文进 user prompt、不进系统提示词(`issue.rs:130`)。

## 没建什么(如实标 defer)
**默认 workflow 的打包未实现**:`standard/05-issue-policy/issue-policy.toml.tmpl` 的 `mapping.workflow` 默认指向 `mattpocock-skills`(构建/优化/运维)与 `proto-design`(原型),但 buddy 自带技能库 `standard/skills/` 只打包了那十份,没有这两份;`skill_slug`(`ops.rs:42`)只解析两个运作剧本,所以构建类活的 workflow 命中 `None`,`skill_pointer` 返回 `None`,段④如实省略,不伪造路径——目前诚实化为不默认指向。full bundle(把 mattpocock/proto-design 真正打包进来)留后续。workflow 本身的可换性(项目可改 `mapping.workflow` 换 superpowers 等)见 issue-policy 配置(模块 2「仓文件解析」解析)。
