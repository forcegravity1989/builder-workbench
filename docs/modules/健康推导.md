# 健康推导

## 这个模块是什么

把项目本周的真实状态(仓里有没有提交、有没有指标读数、上周有没有交付)算成一盏健康灯。它是「健康难造假」铁律的代码保障:灯**只能从数据推导、绝不手设**,没数据是诚实的灰(不是绿),连着两周没动是真停了的红。

## 代码在哪几层

全在 buddy MVP 内核 `crates/bw-v4/src/` 下,采集与判定分两处(设计 §5.3,`docs/archive/v4-prototype/design.md:348`):

- `model.rs:102` — `Signal` 枚举四态 `Green/Amber/Red/Unknown`;`model.rs:99` 注释明写「`Unknown` 是诚实的第四态,没数据绝不默认成绿」。
- `derive/sealed.rs:13` — `DerivedHealth` 密封件:**无 `pub fn new`**,构造点 `mint`(`sealed.rs:19`)是 `pub(super)`,只有 `crate::derive` 调得到;`signal()`(`:24`)、`weekly_signal()`(`:31`)只读不写。
- `derive/mod.rs:24` — `HealthInputs`(七条判据,纯数据);`derive/mod.rs:71` — `derive_project_health`(**唯一判颜色的纯函数**,无隐藏状态);`derive/mod.rs:79-91` 判定顺序**先判红**:`any_metric_red || stalled` → 红,三条都真 → 绿,三条都不成立又无「确实停了」证据 → 灰,其余 → 黄。`on_track()`(`:58`)是 (a) 判据。
- `app/health.rs:20` — `collect_health_inputs`(**只读不判断**):查 ops① issue 在不在、`git::week_counts_many` 本周+上周计数、`read_metric_readings`(`:93`)读 `.bw/metrics/readings.jsonl`、`check_metric_red`(`:107`)比对 `metrics.toml` 目标、`git_tag_in_week`(`:171`)查发版;git 读不到一律当「没有」,不报错。
- `app/health.rs:196` — `recompute_health`:收集 → 推导 → `:203` 写回缓存,**唯一写入者**。
- `app/mod.rs:291` — `cache_project_health` 入参是 `&DerivedHealth`(密封类型);`local/registry.rs:251` — `cache_health` 把 `signal`/`weekly_signal`/`signal_derived_at`(`:260-262`)写进项目显示缓存。全仓 grep 无 `set_signal`——**接受裸 Signal 的写方法不存在**,手工把项目点绿在类型上就没有这条路。

## 数据落哪

buddy MVP 本地零库,不存灯。结果只在 `local/registry.rs` 的项目显示缓存里留两列(`signal`/`weekly_signal`)服务项目墙;**总览自己从不拿它们当输入**,只在算完一次后顺手写回。判据每次打开现算(`design.md:350`「库里不存灯」)。

## 依赖什么

上游是模块 12「指标采集与读数」产出的 `.bw/metrics/readings.jsonl`(读数流水)+ `.bw/metrics.toml`(目标定义);本模块只消费读数,不负责采集。另依赖 `crate::git`(周计数/标签日期)、`crate::isoweek`、`crate::repo::metrics_file`。**对 V3 任何 crate 零依赖**;`sealed.rs:1-5` 注释明写这套把戏与 bw-core 的 `Derived<Signal>` 同源、同理由,只是判据换成仓文件与 git 的现算。

## 产出与验证

产出是 `DerivedHealth`(带 `Signal` + 三条 `HealthReason` 给人看的理由,`derive/mod.rs:64`)。验证靠 E2E 读回:杀进程重开,同样的仓现场算出同样的灯(纯函数,`design.md:366`);`sqlite3` 读回不适用(零库)。门禁 `cargo check -p bw-v4` 编译过、`cargo test` 现存内联测试过。失败如实(`design.md:384` §5.5):健康计算中途出错大灯直接灰 + 错误原文,**绝不吞错凑颜色**。

## 没建什么

**B 类读数还没采进 `readings.jsonl`**(`design.md:399` 已知留白):`check_metric_red` 比对逻辑已建且有测试,但读数文件是空的,所以今天灯**不会因读数难看变红**,只会因「git 读得动、连着两周零提交」变红。这是留白,不是 bug。指标采集与读数本身见模块 12,不在本模块边界。
