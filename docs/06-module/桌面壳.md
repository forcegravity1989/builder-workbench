# 桌面壳 — 模块实现心智

> 30 秒导读:这一层是 Workbench 的**壳**——叠在 Orca Electron 上的五屏旅程。设计层「是什么」在 [`architecture.md`](../architecture.md) §2 ⑤;**关键取舍在本页**。叠层代码在 `src/renderer/src/workbench/`。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

现行壳是 Electron（Orca 产品叠层），不是 Dioxus / wry。开关 `WORKBENCH_SHELL=1` / `VITE_WORKBENCH_SHELL=1`；日常热加载 `pnpm run dev:workbench`。叠层负责导航、计划三屏、项目墙与接入；终端、Tasks、Automations、worktree 复用 Orca 执行核，不大段改写。

计划页签左侧是 bw/week-plan 会话（新开会话注入 SYSTEM + week-planning 指针），右侧原生三屏读写 `.bw/planning/<版本>/data.json`。总览 / 知识库仍有演示数据，未建能力不得写成已交付。

## 主要矛盾 / 取舍

- **叠层与执行核分开**:改旅程、计划三屏、皮肤只进 `src/renderer/src/workbench/`。TaskPage、Automations、PTY 核不动。原文件只留 `isWorkbenchShell()` 钩子。
- **计划材料不再另开 HTML**:右侧就是编辑器；离线 HTML 只读缓存，会话禁止 start/serve。
- **壳自己不另存业务正本**:版本计划内容在规划工作树的 JSON；Issue 状态在远端标签。杀进程重开后从文件和远端读回。
