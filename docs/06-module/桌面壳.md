# 桌面壳 — 模块实现心智

> 30 秒导读:这一层是 Workbench 的**壳**——叠在 Orca Electron 上的各屏旅程。设计层「是什么」在 [`architecture.md`](../architecture.md) §2 ⑤;**关键取舍在本页**。叠层代码在 `src/renderer/src/workbench/`。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

现行壳是 Electron（Orca 产品叠层），不是 Dioxus / wry。开关 `WORKBENCH_SHELL=1` / `VITE_WORKBENCH_SHELL=1`；日常热加载 `pnpm run dev:workbench`。叠层负责导航、计划/验收两屏、总览、项目墙与接入；终端、Tasks、Automations、worktree 复用 Orca 执行核，不大段改写。

计划/验收以 AppWorkspaceShell 的 artifacts 槽准备并选择固定工作树（bw/week-plan / bw/week-acceptance），随后进入原生 terminal；`CycleWorkspaceProvider` 在唯一会话工作区旁挂 `CycleWorkspaceShell` 业务板，不扩 TopLevelView union。左侧保留 BW 导航，其下与其他页一样显示项目列表；标签、分屏、新建会话、资源管理器与智能体历史均复用 Orca。收起会话只释放布局，不销毁原生工作区；会话不可见且不可交互，必要绘制仍由原生机制判断，避免浏览器工具停帧。展开沿原会话与已调栏宽恢复。右侧材料经 `workbench.materials.*` RPC 读写 `.bw/planning/<版本>/`，专用工作流入口与普通会话的边界见 [会话与执行](会话与执行.md)。总览已接真实指标读数与归档纪要（无数据 Unknown）；知识库对账与建议仍有演示数据，未建能力不得写成已交付。

## BW 屏幕接入规范

1. **内容宽度跟随 Orca 内容区。** 页面根容器填满外壳分配的宽高，缩小时在内容区内滚动；总览、项目墙等工作台的整页内容不设固定最大宽度，不留下随窗口变宽而扩大的单侧空白。长文、表单等局部阅读区可以限制行宽，但外围仍填满内容区。验收覆盖实际顶层屏、侧栏展开/收起，以及至少两种逻辑窗口宽度，其中一种应大于原页面宽度上限。
2. **窗口顶部归 Orca 外壳。** BW 页面只进入 `AppWorkspaceShell` 的内容槽，不以全窗口固定覆盖层遮住标题栏、侧栏或窗口按钮。BW 非终端屏共用 Orca 标题栏；终端沿用 Orca 标签栏。计划/验收双栏 board 列顶的 36px 拖拽框行由壳挂载层（`AppWorkspaceShell`）渲染，属壳的窗口框而非页面复制；其右端按浮动钮+窗口控制宽度开 `no-drag` 洞。非交互标题栏区域用于拖窗，控件沿用 Orca 的 `no-drag` 边界并避让窗口按钮；页面不复制拖动条、窗口控制或原生窗口行为。拖动、双击顶部和最小化/最大化/关闭必须在实际 Electron 窗口验证；组件测试、样式检查和后台截图只证明对应层，未验证的原生行为在 PR 明列。

## 主要矛盾 / 取舍

- **叠层与执行核分开**:改旅程、计划/验收两屏、皮肤只进 `src/renderer/src/workbench/`。TaskPage、Automations、PTY 核不动。原文件只留 `isWorkbenchShell()` 钩子和明确扩点（清单见 [ref/upstream](../../ref/upstream.md)）。
- **计划材料不再另开 HTML**:右侧就是编辑器；旧离线 HTML 模板与 planning.py 已退役删除，会话禁止 start/serve。
- **壳自己不另存业务正本**:版本计划内容在规划工作树的 JSON；Issue 状态在远端标签。杀进程重开后从文件和远端读回。
