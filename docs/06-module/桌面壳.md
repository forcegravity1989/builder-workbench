# 桌面壳 — 模块实现心智

> 30 秒导读:这一层是 Workbench 的**壳**——叠在 Orca Electron 上的各屏旅程。设计层「是什么」在 [`architecture.md`](../architecture.md) §2 ⑤;**关键取舍在本页**。叠层代码在 `src/renderer/src/workbench/`。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

现行壳是 Electron（Orca 产品叠层），不是 Dioxus / wry。开关 `WORKBENCH_SHELL=1` / `VITE_WORKBENCH_SHELL=1`；日常热加载 `pnpm run dev:workbench`。叠层负责导航、计划/验收两屏、总览、项目墙与接入；终端、Tasks、Automations、worktree 复用 Orca 执行核，不大段改写。

计划/验收以 AppWorkspaceShell 的 artifacts 槽准备并选择固定工作树（bw/week-plan / bw/week-acceptance），随后进入原生 terminal；`CycleWorkspaceProvider` 在唯一会话工作区旁挂 `CycleWorkspaceShell` 业务板，不扩 TopLevelView union。左侧 Rail 常驻全局导航；对象上下文显示原生可缩放侧栏，顶部固定项目标题和原生工具栏，单一列表依次承载全局已固定、当前项目版本和全部项目工作区。模块页使用整页内容。返回版本工作区仅恢复原生内容，不调用计划/验收准备链；标签、分屏、新建会话、资源管理器与智能体历史均复用 Orca。收起会话只释放布局，不销毁原生工作区；会话不可见且不可交互，必要绘制仍由原生机制判断，避免浏览器工具停帧。展开沿原会话与已调栏宽恢复。右侧材料经 `workbench.materials.*` RPC 读写 `.bw/planning/<版本>/`，专用工作流入口与普通会话的边界见 [会话与执行](会话与执行.md)。总览已接真实指标读数与归档纪要（无数据 Unknown）；知识库对账与建议仍有演示数据，未建能力不得写成已交付。

## 帮助与入门

产品分工、内容覆盖和展示规则统一见[引导与旅程规范](../04-design-system/guidance.md)。壳复用原生 setup-guide 承载 BW 入门、feature-wall 承载探索 BW、contextual tours 承载屏内引导；底部帮助统一挂载入口，顶部应用菜单不再重复。首次启动沿用 onboarding，由既有启动门控抑制同一会话的 feature tips，不额外弹出探索。

帮助链接通过 BW 映射选择目的地；快捷键、更新、重启、关于面板和崩溃报告沿原生调用，反馈与报告的表单及上报通道独立维护。配置检测与访问进度沿原生来源，不另建业务完成记录。新增 BW 内容应沿上述扩点接入，具体行为和验证回所属特性，不在本模块维护另一份内容矩阵。

## 原生账号用量

Cursor 套餐用量沿原生 rate-limit 服务进入状态栏、用量列表和「设置 → 账号 → Cursor」，不归 BW 项目指标，也不提供「统计和使用情况」中的每日 token 图表、项目或会话 token 统计。主进程只读本机 Cursor CLI 或 IDE 的现有登录，不代写、刷新或切换凭据；浏览器账号入口不读取宿主凭据，SSH／WSL 中另一个运行环境的登录未接入。账号切换在 Cursor 自身完成，BW 刷新时重新读取；身份与读数通过不含凭据的账号指纹关联，无法确认当前身份、登录失效或账号变化时不沿用旧账号读数。

读数来自 Cursor 用量接口：套餐总量、Cursor Models／Other Models 额度池、启用的按需用量及重置日期；团队账号只映射成员个人额度，不把团队整体支出当作个人读数。Unified 套餐优先采用接口返回的当前周期，不能把旧月度零值当作当前用量。缺少可识别读数时显示未知；同账号临时请求失败可保留最近读数并标明刷新失败。代码接入与 CI 不等同于真实账号验收，实际对账与截图证据由关联 PR 记录。

## BW 屏幕接入规范

1. **内容宽度跟随 Orca 内容区。** 页面根容器填满外壳分配的宽高，缩小时在内容区内滚动；总览、项目墙等工作台的整页内容不设固定最大宽度，不留下随窗口变宽而扩大的单侧空白。长文、表单等局部阅读区可以限制行宽，但外围仍填满内容区。验收覆盖实际顶层屏、侧栏展开/收起，以及至少两种逻辑窗口宽度，其中一种应大于原页面宽度上限。
2. **窗口顶部归 Orca 外壳。** BW 页面只进入 `AppWorkspaceShell` 的内容槽，不以全窗口固定覆盖层遮住标题栏、侧栏或窗口按钮。BW 非终端屏共用 Orca 标题栏；终端沿用 Orca 标签栏。计划/验收双栏 board 列顶的 36px 拖拽框行由壳挂载层（`AppWorkspaceShell`）渲染，属壳的窗口框而非页面复制；其右端按浮动钮+窗口控制宽度开 `no-drag` 洞。非交互标题栏区域用于拖窗，控件沿用 Orca 的 `no-drag` 边界并避让窗口按钮；页面不复制拖动条、窗口控制或原生窗口行为。拖动、双击顶部和最小化/最大化/关闭必须在实际 Electron 窗口验证；组件测试、样式检查和后台截图只证明对应层，未验证的原生行为在 PR 明列。

## 主要矛盾 / 取舍

- **Windows 启动保持主线程可响应**：后台文件权限校验连同用户 SID 查询均走异步进程；配对密钥与运行端点信息的写入依次等待暂存文件权限处理、原子替换与发布路径校验，再对调用方报告结果，沿用安全写入的失败语义。同一路径写入串行，密钥初始化与运行服务启动合并并发请求，退出等待初始化收尾后关闭监听。缺少本机 GitHub/GitLab CLI 时，默认 WSL 回退复用异步发行版探测。启动诊断区分进程预初始化、窗口加载与工作区恢复完成，具体耗时与平台证据随 PR 提供。

- **叠层与执行核分开**:改旅程、计划/验收两屏、皮肤只进 `src/renderer/src/workbench/`。TaskPage、Automations、PTY 核不动。原文件只留 `isWorkbenchShell()` 钩子和明确扩点（清单见 [ref/upstream](../../ref/upstream.md)）。
- **计划材料不再另开 HTML**:右侧就是编辑器；旧离线 HTML 模板与 planning.py 已退役删除，会话禁止 start/serve。
- **壳自己不另存业务正本**:版本计划内容在规划工作树的 JSON；Issue 状态在远端原生字段。杀进程重开后从文件和远端读回。
