# 桌面壳 — 模块实现心智

> 30 秒导读:这一层是 Workbench 的**壳**——八屏的桌面应用。设计层(是什么 + 关键取舍)在 [`architecture.md`](../architecture.md) §2 ⑤;代码落点用 `codegraph` 探索。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

Dioxus 0.7 / wry WebView,macOS + Windows。壳只渲染和转发意图——健康什么颜色、活能不能转到那一列、指标有没有读数,全部由内核算好塞进 ViewModel;壳里没有一行业务判断,命令失败就把原话放进 toast 不假装做成了。

界面只发 Command、只收 Event;`bw/app` 的 `dispatch` 是唯一执行入口。终端字节流不走 ViewModel、也不走事件总线——桥上单开一条 broadcast 通道,内核线程定时往里推。

## 主要矛盾 / 取舍

- **终端挂在屏的外面**:切面板不卸载,否则字节真丢。PTY 字节流和长命令进度走 broadcast 不走 ViewModel——终端一秒几百批字节,每批重拼整份 ViewModel 会把界面拖垮,而且字节是一次性的流,进 ViewModel 每次重渲染都会被重新写进终端一遍。
- **一屏一模块,三守卫钉死**:单文件动辄上万行走不下去。三条规矩靠机制而非自觉:每屏只有一个公开出口(屏内随便拆,但除这一个函数外不再有第二个能被外部引用);共享数据只经共用的 ViewModel 模块流转(永远不允许一屏直接引用另一屏);每个适配模块的 README 固定三段(借自哪个项目哪个文件、借了什么、没借什么)。门禁里还有三条纯文本结构守卫:屏与屏不互相引用、单文件 2000 行硬上限、用 hook 的函数必须是组件。
- **壳自己不存任何业务数据**:每个数字都是拼 ViewModel 那一刻从内核现算塞进来的;对照日志全仓一份 `bw.log`(不写 token / pairing / 提示词正文)。
