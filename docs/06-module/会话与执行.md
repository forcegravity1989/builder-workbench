# 会话与执行 — 模块实现心智

> 30 秒导读:这一层是 Workbench 的**执行层**——会话屏 + 开工一条路。设计层「是什么」在 [`architecture.md`](../architecture.md) §2 ②;**关键取舍在本页**。代码落点用 `codegraph` 探索。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

会话屏只剩两个组件:**Orca**(本地 pipe 客户端)和 **Open Design**(本机网页内嵌)。没有第三栏、没有动作条、没有灌词条。

开工只有一条路 `run_issue`:开 / 复用一棵 git worktree,没会话才打 Orca 会话,有会话只切树。铁律挂启动参数(Cursor 拼进用户话)。完成仍由人点(计划屏拖进已完成 / 合入)。

两条通道刻意分开:**本地 pipe** 是 Workbench 对 Orca 下命令(开工 / 接回),同机读 token、不需配对;**嵌网页** 是把本机已开的 Orca web 给人看、要配对码。跟随网页是 Orca 内核的刀、不是 Workbench 第二条 RPC。

## 主要矛盾 / 取舍

- **旧三栏 / 动作条 / 灌词条不要**:Workbench 不知道人在 Orca 点了哪条会话,灌词条对着「当前会话」会骗人。停止 / 开 MR / 推评审 / 删会话在 Orca 里做或拖列。
- **工具跟人走本机设置,探不通如实回灰**:Cursor 探活失败拒绝开工,不悄悄退回 Claude CLI——与关键信息维护同一条铁律。运作活开工工具跟构建,不写死 Claude。
- **业务活与常驻树都收进项目的 `.bw/worktrees/`**:业务活按 `issue-<号>`,项目约定与三条 Orca 自动化按固定名字落目录。业务活的旧平级树仍按「会话记的路径 → 新目录 → 旧兄弟」接回;常驻树的旧同级目录只检测并报错,不迁、不删、不继续写,避免覆盖人的目录或未提交成果。
- **Open Design 够不上一个适配模块体量**:不起 CLI、不 spawn agent,开工 = 在内嵌标签里用本机已开的 OD 干;探不到返 None 不 panic,不单开 adapter 目录。
- **两条通道的边界**:没贴配对 URL 则嵌页如实空着、不影响开工;带跟随网页刀的 Orca 推配对网页,没这刀的官方包开工和桌面切换仍成立——跟随网页是 Orca 内核的刀、不是 Workbench 第二条 RPC。
