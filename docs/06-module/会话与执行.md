# 会话与执行 — 模块实现心智

> **维护约定**：给修改开工、会话与工作树协作的人和模型读取；只写执行层的结构、边界与取舍，相关实现变化时更新。整体能力见 [architecture](../architecture.md) §2 ②；Orca 协议按需读 ref；不以旧 Rust 嵌入方式解释当前执行核。

## 实现心智模型

Workbench 直接叠在 Orca Electron 上。计划与验收完整复用 Orca 原生会话工作区：顶部新建会话和 Agent 控件、标签/分屏、资源管理器、智能体历史及可收起的工具侧栏均由 Orca 拥有。隐藏原生左侧项目/工作树列表，保留 BW 导航。BW 只在右侧提供业务板，在原生标签栏增加“新建计划”或“新建验收”；不另建聊天、历史或会话绑定。

进入屏由 ensureCycleWorktree 准备固定树，正式选择后切到原生 terminal；CycleWorkspaceProvider 识别固定分支并在唯一 Terminal 旁挂业务板。切换到别的工作区即离开对应业务板，不反复强制重选。“配置指标”仍进入 bw/metrics-refresh。“在会话中处理”通过 start-material-request 携带 SYSTEM、Skill 与具体文件问题创建会话，等待原生发送回执；数据修改仍须用户确认。提示资产见 [系统提示词与渐进加载](系统提示词与渐进加载.md)。

“新建计划／验收”调用对应已登记自动化的原生手动运行，使用用户当前保存的提示、工具和模型；普通原生新建会话不自动注入 BW Skill。首次登记默认关闭定时，按 creationKey 去重，已有条目不覆盖；“配置自动化”打开原生编辑器。每次新运行使用固定工作区、reuseSession=false，历史恢复和运行打开完全沿用 Orca。Tasks 往返沿原生导航历史，右侧筛选/滚动由 view-memory 保留。归档与准备交付只向当前聚焦的原生聊天输入框写草稿，不存 BW 会话绑定或另建恢复流程。

## 主要矛盾与取舍

- **复用执行核**：终端、agent 生命周期、停止与切树由 Orca 管理；不要重新引入旧 Rust 的嵌页、配对 URL 与第二条开工 RPC。
- **上下文与材料一致**：两屏与会话经材料 RPC / `ORCA bw materials` CLI 操作同份版本材料；已有会话不会因文档更新自动获得新提示。
- **能力与可用证据分开**：工具安装、会话创建、模型读取规范、远端操作成功分别验证；缺文件或权限应报告实际原因，不假装已加载。
- **完成仍由人确认**：执行结束、PR 提交和用户验收是不同状态；旧自动化配置与全业务开工旅程随对应特性迁移验证。
