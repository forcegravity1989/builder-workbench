# 会话与执行 — 模块实现心智

> **维护约定**：给修改开工、会话与工作树协作的人和模型读取；只写执行层的结构、边界与取舍，相关实现变化时更新。整体能力见 [architecture](../architecture.md) §2 ②；Orca 协议按需读 ref；不以旧 Rust 嵌入方式解释当前执行核。

## 实现心智模型

Workbench 直接叠在 Orca Electron 上。计划与验收完整复用 Orca 原生会话工作区：顶部新建会话和 Agent 控件、标签/分屏、资源管理器、智能体历史及可收起的工具侧栏均由 Orca 拥有。左侧保留 BW 导航，其下与其他页一样显示项目列表。BW 只在右侧提供业务板：计划屏启动入口是目标区空板卡「与计划助手新建计划」（唯一会话发起入口），验收屏启动入口是空板卡「与验收助手新建验收」（只在空板态呈现，点击先触发计划归档 PR 合入检测；验收开始后不设首行协作卡片）；分支名弱化在页头，“配置自动化”入口也在页头分支名旁——一次性配置不占每周主操作区。原生标签栏不加 BW 按钮，不另建聊天、历史或会话绑定。

进入屏由 ensureCycleWorktree 准备固定树，选择工作区并回显原生 terminal 与材料；进屏不做任何 Git 动作。页头「更新代码」是唯一同步入口：把固定树快进到主干最新（fetch 书签 → 双向 rev-list 对比 → merge --ff-only，经 workbench.trunk.update），期间暂停材料写入，无论快进成败都重读材料与候选；快进不了（分叉、主检出有本地改动、分支失配、远端不可达）保持原样、不换数据源，统一中文提示由用户在会话里带工作模型处理。CycleWorkspaceProvider 识别固定分支并在唯一 Terminal 旁挂业务板。切换到别的工作区即离开对应业务板，不反复强制重选。“配置指标”仍进入 bw/metrics-refresh。首次准备固定树时，优先复用同名本地分支；仅有同名远端分支时，将其作为原生创建的 baseBranch，保留原分支内容和精确分支名。多个远端同名且没有本地分支时，提示用户先检出要使用的分支。复用已有固定树时，按所属项目和宿主追加原生接入登记，保留此前已接入的其他工作树；同项目并发准备串行更新登记，避免计划、验收和指标入口互相隐藏。旧格式或损坏材料在启动入口卡内紧凑提示实际版本与文件（两屏均为空板卡；验收屏空板另有常驻门禁状态行，说明正在核对/已合入/具体阻断原因/未找到计划，空板不会无解释）；启动入口经 start-cycle-automation 手动运行已登记自动化，把当前选版、具体文件与读取问题作为一次性上下文（automation.runNow 的 oneShotPrompt）随保存提示合并为单次递交，等待原生运行打开；不另建会话，数据修改仍须用户确认。归档、拆解与未达跟进都直接在会话中向模型发起，页面不贴终端草稿（贴草稿通道已整体退役）；两屏界面都不渲染灯（验收屏 v10 起旅程/出包/归档灯全部退役，workflow.stage 只作材料内部进度），归档状态行/卡按材料记录的 archivePr 薄读取 PR 合入状态。提示资产见 [系统提示词与渐进加载](系统提示词与渐进加载.md)。

“新建计划／验收”调用对应已登记自动化的原生手动运行，使用用户当前保存的提示、工具、模型及会话复用配置，随后打开、聚焦本次原生会话；定时运行仍在后台。普通原生新建会话不自动注入 BW Skill。首次登记默认关闭定时、使用固定工作区且 reuseSession=false，按 creationKey 去重；已有条目按当前 BW 版本覆盖同步 BW 所有的提示词（BW 持续演进，定时跑的必须始终是新版提示），人所有的设置（启用开关、触发时间、模型、会话复用）保留不覆盖；“配置自动化”打开原生编辑器。历史恢复和运行打开完全沿用 Orca。Tasks 往返沿原生导航历史，右侧筛选/滚动由 view-memory 保留。不存 BW 会话绑定或另建恢复流程。

计划屏与验收屏对称：都读写自己的固定分支，验收屏的可选版本即验收分支上已提交的版本目录（「更新代码」快进后能看到已合入主干的计划）。两屏界面都不渲染灯（计划屏自 G3、验收屏自 v10 起；workflow.stage 只作材料内部进度，供会话校准与自动化）；归档 PR 合入状态按 archivePr 薄读取显示，是提醒信号，不阻塞读取与继续验收。同一版本继续编辑同份材料，切版前先保存当前修改；读不回 PR 状态（如 CodeHub 项目）一律如实保持未知，不假标已合入也不阻断。

## 主要矛盾与取舍

- **复用执行核**：终端、agent 生命周期、停止与切树由 Orca 管理；不要重新引入旧 Rust 的嵌页、配对 URL 与第二条开工 RPC。
- **上下文与材料一致**：两屏与会话经材料 RPC / `ORCA bw materials` CLI 操作同份版本材料；已有会话不会因文档更新自动获得新提示。
- **能力与可用证据分开**：工具安装、会话创建、模型读取规范、远端操作成功分别验证；缺文件或权限应报告实际原因，不假装已加载。
- **完成仍由人确认**：执行结束、PR 提交和用户验收是不同状态；旧自动化配置与全业务开工旅程随对应特性迁移验证。
