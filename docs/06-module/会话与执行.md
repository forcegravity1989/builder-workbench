# 会话与执行 — 模块实现心智

> **维护约定**：给修改开工、会话与工作树协作的人和模型读取；只写执行层的结构、边界与取舍，相关实现变化时更新。整体能力见 [architecture](../architecture.md) §2 ②；Orca 协议按需读 ref；不以旧 Rust 嵌入方式解释当前执行核。

## 实现心智模型

Workbench 直接叠在 Orca Electron 上，执行面复用终端、Tasks、Automations 与 worktree。计划/验收屏共用 `version-cycle/CycleWorkspaceShell`：左侧当前会话（CycleChat，terminal portal 全局单发布者）加固定树历史面板（AiVaultPanel workspaceHost，onOpenSession 精确身份恢复），右侧编辑同一份版本材料；会话不再是独立导航页。

进入屏即 ensureCycleWorktree：计划固定 bw/week-plan、验收固定 bw/week-acceptance，创建/登记走原生 worktree.create，再 setActiveWorktree 正式选择；激活不改 activeView（保持当前 BW 页），paired 宿主再走 activateWebRuntimeSessionWorktree。「配置指标」进入独立固定维护树 bw/metrics-refresh 的原生会话并注入 metrics-refresh Skill 提示。新开会话递交渲染后的 SYSTEM 与对应 Skill，工具按本机 agent 检测选择（useAgentDetectionTargetForWorktree / useDetectedAgents / defaultTuiAgent），不写死 Claude；恢复历史会话只接回、不重递交。路径查找和缺失行为见 [系统提示词与渐进加载](系统提示词与渐进加载.md)。该入口不能证明所有业务 Issue、工具或自动化已接相同规范。

「配置自动化」按钮预填原生自动化编辑器：host 按工作树宿主身份，existing 固定树、reuseSession=false、prompt 不含 cycleId；启用与时间由人确认，不静默登记定时工作。Tasks 往返：会话绑定存 sessionStorage（`bw:cycle:session:<scopeKey>`）重挂复活；计划屏 goalFilter 与滚动位置存 sessionStorage（use-planning-view-memory），验收屏滚动走 recoveryKey；任务详情经原生 openTaskPage 的 returnToPreviousView 跳过 tasks 哨兵按来源返回，屏内上下文由 cycle-view-state 与 view-memory 恢复。

## 主要矛盾与取舍

- **复用执行核**：终端、agent 生命周期、停止与切树由 Orca 管理；不要重新引入旧 Rust 的嵌页、配对 URL 与第二条开工 RPC。
- **上下文与材料一致**：两屏与会话经材料 RPC / `ORCA bw materials` CLI 操作同份版本材料；已有会话不会因文档更新自动获得新提示。
- **能力与可用证据分开**：工具安装、会话创建、模型读取规范、远端操作成功分别验证；缺文件或权限应报告实际原因，不假装已加载。
- **完成仍由人确认**：执行结束、PR 提交和用户验收是不同状态；旧自动化配置与全业务开工旅程随对应特性迁移验证。
