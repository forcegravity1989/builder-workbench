# 会话与执行 — 模块实现心智

> 30 秒导读:这一层是 Workbench 的**执行层**——会话屏 + 开工一条路。设计层「是什么」在 [`architecture.md`](../architecture.md) §2 ②;**关键取舍在本页**。代码落点用 `codegraph` 探索。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

会话屏不再作为独立导航。执行面复用 Orca 终端、Tasks 与 worktree；计划页签左侧直接开 Claude 会话（新开会话注入 SYSTEM + week-planning）。没有第三栏、没有动作条、没有提示词输入栏。

计划页签开工：固定 `bw/week-plan` 工作树，没有会话才创建并递交注入提示，已有会话只接回、不重递交。完成仍由人点。

中止运行与取消 Issue 是两件事。当前 Workbench 尚未接入 Orca 进程停止接口，本机会话状态或中止回执不能证明宿主进程已经停止；停止实际执行仍需在会话宿主中操作。

两条通道刻意分开:**本窗会话**是 Workbench 壳里的 Claude / 终端；**Orca 网页跟随**若仍启用，是给人看已开的网页，不是第二条开工 RPC。

## 主要矛盾 / 取舍

- **旧三栏 / 动作条 / 提示词输入栏不要**:Workbench 不知道人在 Orca 点了哪条会话,提示词输入栏对着「当前会话」会骗人。停止 / 开 MR / 推评审 / 删会话在 Orca 里做或拖列。
- **工具跟人走本机设置,检测失败时如实显示未知**:Cursor 工具检测失败拒绝开工,不悄悄退回 Claude CLI——与关键信息维护同一条铁律。周期工作开工工具跟构建,不写死 Claude。
- **业务 Issue 与常驻工作树都收进项目的 `.bw/worktrees/`**:业务 Issue 按 `issue-<号>`,项目约定与三条 Orca 自动化按固定名字落目录。业务 Issue 的旧同级工作树仍按「会话记的路径 → 新目录 → 旧同级目录」接回;常驻工作树的旧同级目录只检测并报错,不迁、不删、不继续写,避免覆盖人的目录或未提交成果。
- **默认自动化逐项补齐**：工作树准备或任务创建的单项失败不阻断其他任务，失败汇总提示；全部成功才缓存本进程已就绪。旧同级树按组内发布的 v0.4 升级指引一次性整理，目录和 Orca 任务绑定一起核对，返回项目墙重试不能代替升级。产品不增加旧路径兼容或自动迁移。
- **Open Design 够不上一个适配模块体量**:不起 CLI、不 spawn agent,开工 = 在内嵌标签里用本机已开的 OD 干;探不到返 None 不 panic,不单开 adapter 目录。
- **两条通道的边界**:没贴配对 URL 则嵌页如实空着、不影响开工;支持网页跟随的 Orca 推送配对网页,没有该功能的官方包仍可开工和切换桌面——网页跟随是 Orca 内核的功能、不是 Workbench 第二条 RPC。
