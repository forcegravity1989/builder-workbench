# 会话与执行 — 模块实现心智

> **维护约定**：给修改开工、会话与工作树协作的人和模型读取；只写执行层的结构、边界与取舍，相关实现变化时更新。整体能力见 [architecture](../architecture.md) §2 ②；Orca 协议按需读 ref；不以旧 Rust 嵌入方式解释当前执行核。

## 实现心智模型

Workbench 直接叠在 Orca Electron 上，执行面复用终端、Tasks、Automations 与 worktree。计划页签左侧创建或接回规划会话，右侧编辑同一份版本 JSON；会话不再是独立导航页。

计划入口使用 bw/week-plan 工作树，新开 Claude 会话时递交 SYSTEM 与 week-planning 路径，已有会话只接回、不重递交。路径查找和缺失行为见 [系统提示词与渐进加载](系统提示词与渐进加载.md)。该入口不能证明所有业务 Issue、工具或自动化已接相同规范。

## 主要矛盾与取舍

- **复用执行核**：终端、agent 生命周期、停止与切树由 Orca 管理；不要重新引入旧 Rust 的嵌页、配对 URL 与第二条开工 RPC。
- **上下文与材料一致**：三屏与会话操作同份规划 JSON；已有会话不会因文档更新自动获得新提示。
- **能力与可用证据分开**：工具安装、会话创建、模型读取规范、远端操作成功分别验证；缺文件或权限应报告实际原因，不假装已加载。
- **完成仍由人确认**：执行结束、PR 提交和用户验收是不同状态；旧自动化配置与全业务开工旅程随对应特性迁移验证。
