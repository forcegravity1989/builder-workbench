# 系统提示词与渐进加载 — 模块实现心智

> 30 秒导读:本页说明 SYSTEM 的渲染与递交边界：Orca 只在新会话递交；Open Design 每次开工重新生成并尝试递交。自动化另有入口，见下文。设计层「是什么」在 [`architecture.md`](../architecture.md) §2 ③;**关键取舍 + 三层分工 / 维护对照表在本页**。代码落点用 `codegraph` 探索。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

主提示词是**外置模板** `SYSTEM.md.tmpl`,不硬编码在代码里(改身份 / 纪律 = 改 md)。提示词只给「一句话 + 完整路径」——references / 技能文件不在硬盘就如实少一段不编路径。这就是渐进加载:提示词放索引、正文让 agent 按需读。

三层各装什么(主提示词 / references / skills)正本在 [`standard/README.md`](../../standard/README.md),本模块只写怎么注入。三层分工 / 维护对照表见本页下文。

## 主要矛盾 / 取舍

- **正文一律不塞进提示词**:塞进去 = 改身份要改代码、且 agent 上下文被无关正文占满。只给索引 + 路径,agent 按需读。
- **共同纪律的正本在 SYSTEM，实际覆盖取决于入口**:Orca 新会话会递交它；接回已有 Orca 会话只切换工作树，不重新递交。Open Design 每次开工重新渲染，发现本机服务后通过 `start_run` 尝试传入；已有 conversation 记录不会跳过这一步，是否接收以接口结果为准。Orca 周期工作由 `app/orca_inject.rs` 的 `ops_prompt` 单独生成提示并复用 reference/skill 指针，每日采集则走 `collect_prompt`。这些自动化入口尚未复用 SYSTEM，不能只改模板就声称所有会话已获得新纪律；共同纪律覆盖与既有自动化更新仍待单独处理。
- **技能注入只有一个模型 `skill_pointer`**:周期工作技能和业界 workflow 走同一条注入链(workflow→slug→`SkillPack`→入口 SKILL.md 路径),不另开第二条路径。类别→默认 workflow 是产品编译默认,默认 workflow 由 Workbench 打包统一管理、不写进被管仓。周期工作技能入口 body 自足;业界 workflow 入口 body 是 SOP 链 + 指向 `vendor/` 库子技能路径。

## 三层分工与维护对照

> 从 architecture §2 ③ 迁来——三层各装什么、改了哪条流程同步哪份。`AGENTS.md`「按任务读取」指到这里。改 `standard/` 之前先对表。

**分工**(改提示词 / 加 reference / 改 skill 之前先对):

| 层 | 装什么 | 不装什么 | 改它何时 |
|---|---|---|---|
| **主提示词** `SYSTEM.md.tmpl` | 哪个 Issue、读仓根 `AGENTS.md`、按任务加载哪份 reference、和 BW 状态机怎么配合、references/技能的**名字+一句话+路径** | 文件清单、格式版本、某类 Issue 的步骤 | 所有 Issue 都该守的契约变了 |
| **任务规范** `references/*.md` | 执行**这一类**工作必须对照的现行契约 | 怎么一步步干;本周这个项目发生了什么 | 这类 Issue 的协议变了 |
| **技能** `skills/*/SKILL.md` | SOP:先干什么、产出落哪、人点什么 | 现行文件枚举当正本(会漂);铁律副本 | 这类 Issue 的步骤变了 |

本周项目侧变化(`git log`、开着的 MR、指标记录)每次现算,不写进上述任何一层。

**维护**(产品流程变了,同步哪份;目录变了就改 `standard/README` 那张表):

| 变了什么 | 同步哪份 | 在哪些入口提供 |
|---|---|---|
| 所有 Issue 都守的纪律(最远待评审 / 提完 MR 改 inreview 标签 / 只提 MR / 提交优先用户技能) | `SYSTEM.md.tmpl`；同时核对自动化的独立提示入口 | Orca 新会话；Open Design 每次开工尝试传入；自动化覆盖尚有上述缺口 |
| issue 状态机、版本多值归属、程序/模型写入边界 | `references/issue-state.md` | Orca 新会话、Open Design 开工，以及 `ops_prompt` 所列参考；不含每日采集 |
| 指标协议(可回溯、窗口、不许写 0、schema) | `references/metrics.md` + `templates/metrics.toml.tmpl` | 更新指标与版本计划 Issue;资产盘点升级格式时 skill 会再指过去 |
| 更新指标与版本计划 Issue 评论三标题 + 周五每周进展 | `references/week-plan-comment.md` + `week-planning` / `asset-audit` skill / 校验脚本(只查周初三标题) | 更新指标与版本计划 Issue;资产盘点 Issue(只写进展) |
| 改仓:分支 / 提 MR / 合并是人 / 提完 MR 改 `bw:status:inreview` | `references/build.md` | 构建/优化/运维业务 Issue;资产盘点 Issue(改 `.bw` 也是改仓) |
| `.bw` 该有、整份可删、现行格式、与更新指标与版本计划的分工 | `references/bw-assets.md` | 资产盘点 Issue |
| 独立评审只评不改 | `references/review.md` + `REVIEW.md.tmpl` + `mr-review`(尚未派发) | 评审会话 |
| 某项周期工作怎么干 | 对应 `skills/<slug>/SKILL.md` | 挂了那个 workflow 的 Issue |
| 哪类 Issue 注入哪份 reference | `app/bootstrap.rs` 的 `want_ref`；`app/orca_inject.rs` 复用参考选择 | Orca 新会话、Open Design 每次开工与周期工作提示；不含已有 Orca 会话重注入、每日采集 |

漏同步的结果就是周五盘点还在找已经不存在的登记表——协议变了只改内核、不改 reference,现场 agent 对不上。
