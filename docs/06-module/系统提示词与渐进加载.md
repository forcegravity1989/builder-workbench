# 系统提示词与渐进加载 — 模块实现心智

> 30 秒导读:这一层给每张活开工渲染一份系统提示词。设计层(是什么 + 关键取舍)在 [`architecture.md`](../architecture.md) §2 ③;代码落点用 `codegraph` 探索。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

主提示词是**外置模板** `SYSTEM.md.tmpl`,不硬编码在代码里(改身份 / 纪律 = 改 md)。提示词只给「一句话 + 完整路径」——references / 技能文件不在硬盘就如实少一段不编路径。这就是渐进加载:提示词放索引、正文让 agent 按需读。

三层各装什么(主提示词 / references / skills)正本在 [`standard/README.md`](../../standard/README.md),本模块只写怎么注入。对照表在 architecture §2 ④;改 `standard/` 之前先对表。

## 主要矛盾 / 取舍

- **正文一律不塞进提示词**:塞进去 = 改身份要改代码、且 agent 上下文被无关正文占满。只给索引 + 路径,agent 按需读。
- **不论哪个 workflow 都被这层兜住统一要求**:要加「所有项目都该守的统一要求」,改这份 md,不加进 workflow 本身——workflow 是业界来的、Workbench 不替它写统一要求。
- **技能注入只有一个模型 `skill_pointer`**:运作剧本和业界 workflow 走同一条注入链(workflow→slug→`SkillPack`→入口 SKILL.md 路径),不另开第二条路径。类别→默认 workflow 是产品编译默认,默认 workflow 由 Workbench 打包统一管理、不写进被管仓。
