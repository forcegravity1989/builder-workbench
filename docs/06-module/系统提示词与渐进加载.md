# 会话入口与 Skill 加载

> 给维护 BW 会话入口、执行资产与分发的人读；本页说明入口、完整包与原生执行宿主之间的实现边界，不复制 SOP 或开发规则。结构按启动、源与包、宿主、验证组织；加载方式或分工变化时更新。资产写法先读 [standard](../../standard/README.md) 和 [Skill 规范](../../standard/skills/SKILL-MD-SPEC.md)。

## 一句入口，完整正文

计划、验收、指标配置的手动入口先准备完整 Skill，再打开原生会话草稿。草稿是一句用户请求，带执行宿主可读的 SKILL.md 路径；用户可以修改、补充后发送。入口不承载公共纪律、SOP 副本和材料状态快照。普通原生新建与历史恢复不额外注入 BW 规范。

模型发送后先完整读取 SKILL.md，按其开工要求读项目 AGENTS 与公共执行规范，再通过现有原生工具读回工作树、绑定版本、材料与指标。必读 reference 的触发写在动作之前；“有链接”不能替代读取要求。

真正定时运行仍由原生自动化执行。登记时同步 BW 所有的短入口，保留人的启用、时间、模型和会话复用设置；手动会话不再通过一次自动化运行来发出任务。

## 单一来源与完整包

三个 Skill 的正文、方法、模板、脚本分别在 `standard/skills/<topic>/`，公共规则源在 `standard/references/`。构建将实际依赖投影到每个包的 `references/shared/` 并修正相对链接，通过 Orca 原生 bundle 生成器创建可校验的完整包；投影不手改。

包随 BW runtime 构建交付，不要求用户项目存在 standard，不从另一个开发 checkout 临时读源码。安装后的 Markdown 和脚本是实际文件，模型直接读取或运行。Orca 自有的其他内置指南继续沿其原生渠道，本模块只管理 BW 三个工作流。

## 安装由执行宿主负责

BW 薄适配先按原生登记核对项目、工作树与宿主，再调用该宿主的原生上传和 bundle 安装服务。安装位置、版本记录、文件验证、事务和冲突保护归原生安装器；BW 不另建安装目录或覆盖机制。

本机与配对 runtime 使用各自的原生服务。WSL 按工作树实际执行环境安装，并给会话 Linux 路径。SSH 上传与安装都发生在目标宿主，不把桌面暂存编号传给远端。入口使用安装结果返回的路径，不能用客户端路径推断远端位置。

仅允许原生安装器更新未被用户修改的包。本地修改、未知归属、安装失败或宿主不可用时如实报错，不退回旧指南链，也不静默覆盖文件。业务材料仍由原生材料服务管理，Skill 安装不写项目业务文件。

## 验证

依次核对源与投影、包内引用及脚本、真实安装结果、会话草稿、模型实际读取。协议测试中的临时安装不等于安装版真壳，模拟 SSH 路由不等于跨主机验证。每次交付在 PR 分别报告这些证据及未验证范围。
