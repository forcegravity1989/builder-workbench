# 系统提示词与渐进加载 — 模块实现心智

> 30 秒导读：本页说明 SYSTEM 的渲染与递交边界：计划/验收手动开工预填一句内置技能读取草稿，用户发送后由技能调用材料 context 读回公共纪律及动态上下文；周期自动化与「配置指标」继续使用完整 SYSTEM + 对应 Skill。普通原生新建会话不额外注入。设计层见 [architecture](../architecture.md) §2 ③，三层维护对照在下文；实现边界变化时更新，不以静态分发证明模型已读取。

## 实现心智模型

主提示词的唯一正源是 `standard/system-prompt/SYSTEM.md.tmpl`。模板与技能正文均随产品打包，普通被管项目无需 standard/。模板生成物与 renderer raw 导入共用 `shared/workbench/workflow-prompt.ts` 渲染器：自动化和指标配置直接取得完整提示；手动开工只给一句明确的内置技能读取草稿，不自动回车。技能完整指南与 references 经原生 `ORCA skills get` 按需读取，不复制进项目仓。

用户发送草稿后，计划/验收技能先执行 `ORCA bw materials context --workflow plan|acceptance --json`。CLI 从原生终端工作树身份或登记核验后的当前目录解析范围，返回当前选版、项目/仓库/宿主/工作树/路径/真实分支、材料候选与错误，以及由同一 SYSTEM 模板生成的 `instructions`。后续材料命令使用读回的身份参数；不按界面焦点或会话标题猜归属，失败不写材料。绑定版本始终以宿主登记为准；CLI 在所属 runtime 内访问，不把客户端的 owner 投影视为执行宿主。

## 工作流入口与普通会话

“开始计划／验收”使用 BW 当前默认智能体，在所属流程工作树打开 Orca 原生会话，预填一句包含内置技能读取命令的流程草稿，不自动回车；用户直接在原生输入区补充后发送。不增加弹窗或板面输入框，不另加隐藏 BW 长提示。技能先读取同一宿主的材料 context，获取原 SYSTEM 公共纪律、项目/工作树/分支/版本及材料问题；草稿与宿主版本不一致先核对，读取失败不猜身份、不写材料。

定时自动化继续使用完整 SYSTEM + Skill Stub 提示并按原生机制到点执行，prompt 不改成一句话，也不等待用户回车；手动开始不运行或修改自动化。首次登记默认关闭、固定工作区且 reuseSession=false，creationKey 去重；BW 提示按随包版本覆盖同步，用户的启用、时间、工具与会话复用设置保留，“配置自动化”继续打开原生编辑器。

## 当前可达性边界

SYSTEM 模板、技能指南及 references 随产品分发；仅递交短草稿不证明模型已加载。须在真实会话中核对技能读取命令、context 返回的公共纪律及动态身份，并观察后续材料操作。源文件存在、随包分发、入口指针与模型实际遵守分别记录。

## 主要矛盾 / 取舍

- **手动草稿与自动化提示分开呈现、共用正源**：手动开工复用原生 draft，不增加板面输入框或隐藏 BW 长提示；自动化仍递交完整提示。两者的公共纪律由同一 SYSTEM 模板和渲染器承载，不能为了简短删除规则。
- **动态上下文实时读回**：材料 context 在所属宿主核对身份、版本与材料错误，界面焦点不参与定位；无可靠身份或版本不写材料。
- **模板必须完整渲染**：未解析占位符直接报错。完整提示保持 Skill → references → 执行上下文的命令发现顺序；CLI 的 context 在技能已读后返回纪律与上下文，不重复分发另一套 SOP。

## 三层分工与维护对照

> 从 architecture §2 ③ 迁来——三层各装什么、改了哪条流程同步哪份。`AGENTS.md`「按任务读取」指到这里。改 `standard/` 之前先对表。

**分工**(改提示词 / 加 reference / 改 skill 之前先对):

| 层 | 装什么 | 不装什么 | 改它何时 |
|---|---|---|---|
| **主提示词** `SYSTEM.md.tmpl` | 哪个 Issue、读仓根 `AGENTS.md`、按任务加载哪份 reference、原生 Issue 状态与人的处理边界、references/技能的**名字+一句话+路径** | 文件清单、格式版本、某类 Issue 的步骤 | 所有 Issue 都该守的契约变了 |
| **任务规范** `references/*.md` | 执行**这一类**工作必须对照的现行契约 | 怎么一步步干;本周这个项目发生了什么 | 这类 Issue 的协议变了 |
| **技能** `skills/*/SKILL.md` | SOP:先干什么、产出落哪、人点什么 | 现行文件枚举当正本(会漂);铁律副本 | 这类 Issue 的步骤变了 |

本周项目侧变化(`git log`、开着的 MR、指标记录)每次现算,不写进上述任何一层。

**维护**(产品流程变了,同步哪份;目录变了就改 `standard/README` 那张表):

| 变了什么 | 同步哪份 | 规范面向的入口（实际覆盖以上述边界为准） |
|---|---|---|
| 所有任务都守的纪律（完成与合入由人决定 / 提交优先用户技能 / 计划屏不另开 HTML） | `SYSTEM.md.tmpl`；同时核对 cycle-prompt 渲染字段 | 手动计划/验收的材料 context、自动化默认提示与「配置指标」；SYSTEM 同源渲染，手动 context 实时附材料问题，自动化登记同步完整提示并保留用户执行设置 |
| Issue 提单格式与计划补充 | `references/issue-state.md` | cycle-prompt 的 references 指引；其他挂了该 reference 的开工 |
| 指标协议(可回溯、窗口、不许写 0、schema) | `references/metrics.md` + `templates/metrics.toml.tmpl` | 更新指标与版本计划 Issue;资产盘点升级格式时 skill 会再指过去 |
| 旧计划评论核对、修复与导入 | `references/week-plan-comment.md` + 校验脚本(只查旧周初三标题) | 历史材料处理 |
| 版本材料与执行进展写入 | `references/version-records.md` + `week-planning` / `version-acceptance` / `asset-audit` | 原生材料服务已提供且版本明确的任务；旧脚本不作为回退入口 |
| 会议纪要内容标准(共识/遗留条目要素、提炼方法、正反例) | `references/meeting-minutes.md`;两屏 SKILL 纪要节引用 | 计划/验收「整理纪要」注入与会话内纪要整理 |
| 改仓：分支与 PR/MR / 人的合入与关单授权 / 远端读回 | `references/build.md` | 构建/优化/运维业务 Issue;资产盘点 Issue(改 `.bw` 也是改仓) |
| `.bw` 该有、整份可删、现行格式、与更新指标与版本计划的分工 | `references/bw-assets.md` | 资产盘点 Issue |
| 独立评审只评不改 | `references/review.md` + `REVIEW.md.tmpl` + `mr-review`(尚未派发) | 评审会话 |
| 某项周期工作怎么干 | 对应 `standard/skills/<slug>/SKILL.md`；同步重新生成根级 `skills/` Stub 投影 | 手动计划/验收草稿显式读取 week-planning / version-acceptance 指南；自动化及指标配置仍使用对应 Stub |
| 哪类 Issue 注入哪份 reference | `cycle-prompt.ts` 的 references 列表；SYSTEM.md.tmpl 的加载表 | 计划/验收工作流与「配置指标」入口；普通新建与历史恢复不额外注入 |

漏同步的结果就是周五盘点还在找已经不存在的登记表——协议变了只改界面、不改 reference,现场 agent 对不上。

## 周期工作资源与数据读取

week-planning 现只含 SKILL.md、references（goal-guidance、data-and-runtime）与 `check-week-comment.py`（历史评论修复协议，配 `references/week-plan-comment.md`）。三节纪要模板 `assets/minutes-template.md` 已随 G3「预览纪要」退役在同一交付删除；旧离线 HTML 模板 version-plan.html、空数据模板 data-template.json、planning.py 与会议 reference 已随消费方切换在同一交付内退役删除，不再有 HTML 缓存或 start/serve 入口。

计划/验收手动开工携带一句内置技能读取草稿，自动化携带渲染后 SYSTEM + 对应 Skill Stub；右侧材料单页与会话经 `workbench.materials.*` RPC / `ORCA bw materials` CLI 读写同一份 `.bw/planning/<版本>/` 材料，不要再起 HTML 服务。

计划屏/总览读取同一 JSON：两屏界面都不渲染灯（计划屏自 G3、验收屏自 v10 起；workflow.stage 只作材料内部进度，供会话校准与自动化），归档 PR 状态按 workflow.archivePr 薄读取；已登记 bw/week-plan 的同版本草稿覆盖显示，损坏草稿显示未知。summary.progress 是 previous_version 的结果摘要，不算作新版本进展；summary.risks 仅由用户填写（模型通道被人工守卫拒绝）；会议纪要存材料可选 minutes 节（模型只写未确认正文，确认与闭环由人标记）。没有 JSON 时不退回旧评论；首次历史导入由 Skill 处理。

## 版本流程提示的接线现状

[计划设计](../05-features/version-planning/design.md) 与 [验收设计](../05-features/version-acceptance/design.md) 的 SOP 留在内置 Skill。手动入口由 `start-cycle-session.ts` 打开原生会话并预填技能读取草稿，用户发送后，指南要求先调用 `bw materials context`；CLI 使用共享渲染器返回完整 SYSTEM、原生身份、选版、材料问题，以及计划前版验收状态或验收计划来源问题。自动化仍由 `cycle-prompt.ts` 渲染完整 SYSTEM + Skill Stub。#443 的真实会话、草稿补充与技能读取验证待用户通知后执行，历史烟测不能作为本次已通过的证据。
