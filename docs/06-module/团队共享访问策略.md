# 团队共享访问：权限与日志规范

> **维护约定**：给修改团队只读访问策略（`runtime-rpc-team-read-policy.ts`）、宿主访问日志（`runtime-access-audit*`）、新增 RPC 方法或会影响只读成员的界面入口的人和模型读取。只写判定原则、界面动作分类、日志规则、新增/调整时的维护步骤和已知差距；不列方法全表（以代码和测试为准）、不写用户旅程（见[规格](../05-features/team-collaboration/spec.md)）、不写实现落点与身份契约（见[实现设计](../05-features/team-collaboration/design.md)）、不记变更流水。分类原则、日志规则或动作归类变化时更新。

## 先看界面，再看方法

判断一个请求该不该放行，先问「成员在界面上做了什么」，不是「它调用了哪个函数」。正常用户只在界面里操作；主机端按方法名拒绝只是兜底，防止有人绕开界面。所以：

- 策略、日志和测试都以**界面动作**为单位归类，方法名只是动作的实现细节；
- 日志写成员做了什么（「向 Agent 发送消息」），不写调用了什么（`agentSession.send`）；
- 评审一条新规则时，先说它对应成员界面上的哪个动作。

## 四类界面动作

| 类别 | 成员做了什么 | 主机处理 | 日志 |
|---|---|---|---|
| 查看 | 浏览项目墙和侧栏，打开工作树，看文件、Git、PR、计划与材料，看会话和终端输出 | 放行 | 成功不记；失败记 |
| 协作 | 操作共享浏览器页面，选取页面元素并批注（日志写作“选取页面元素”），加删原型批注，收发评审通知，刷新指标 | 放行 | 记，用动作名 |
| 自动副作用 | 只是打开界面，界面自己发出的写请求：切换会话标签页、恢复布局、新增会话终端、保存工作树标签、清理缺失终端、浏览器页面租约、打开新建工作树对话框时的预取 | 拒绝（静默） | 不记，也不当作成员的选择 |
| 主动写入或驱动 | 新建工作树，启动或续接 Agent 会话，开始计划/验收，向 Agent 或终端发消息和输入，新建终端，写删文件，Git 写入，改主机设置，运行浏览器脚本，读写凭据，操作桌面 | 拒绝并给中文提示 | 记，用动作名 |

归类按两个问题走：

1. 这个动作会让主机上多出进程、文件或改动，会动用主机的账号和凭据，或会让成员驱动模型吗？不会，属于查看或协作。
2. 会的话，是成员主动选的吗？不是，属于自动副作用；是，属于主动写入或驱动。

终端订阅流里的键盘输入和窗口大小帧一律丢弃，成员只看输出。浏览器页面只能打开网页地址，不能打开主机本地文件；成员新开的页面不抢主机窗口焦点；成员打开工作树不移动主机自己的窗口。

## 日志规范

- **位置与保留**：主机 `userData/logs/orca-shared-host/`，按天写入，保留 14 天，界面可按动作、结果、时间和成员筛选，也可清理。
- **记什么**：连接建立与断开、授权与撤销、主动类拒绝、请求错误（带错误码）、协作类成功动作。
- **不记什么**：成功的常规读取、自动副作用的拒绝；请求参数、文件内容、模型输入、shell 正文、终端流和凭据任何时候都不进日志。
- **用语**：每个会产生记录的动作都要有精确的中文动作名，写在 `src/shared/runtime-access-audit-labels.ts`；按方法族兜底的通用名只用于没人关心的长尾方法，成员能点到的入口不得只靠它。动作名站在成员视角，不含方法名或内部术语，方法名只作诊断。
- **连接记录**：一位成员在一台客户端上无论开了几条通道，只记一次「建立共享连接」和一次「断开共享连接」；首条通道建立时记建立，最后一条通道断开时记断开，按成员设备计数。
- **成员**：显示 WeLink 姓名和头像，不显示链接所有者；同一链接下每位成员各一条记录。
- **预期内的失败**：例如核对终端面板时主机上没有活进程。这类失败当前仍记为错误，见已知差距。

## 新增或调整时怎么做

1. 新增 RPC 方法或界面入口，先按上面两个问题归类。
2. 在 `runtime-rpc-team-read-policy.ts` 登记：主动类进拒绝清单；自动副作用类同时进静默清单；协作类进审计清单；查看类不用登记。整族都不允许的前缀放前缀表。
3. 凡是会进日志的方法，补精确动作名。
4. 测试遍历全部方法名，名字像写入、却没被拒绝也没登记为「已核对的读取」的会失败，逼每个新方法做一次决定。新类别在已有断言里补一行，不新增测试用例。
5. 分类或日志规则变了，同步改本文。
6. 用两台真机验证：成员以只读身份走一遍该界面动作，在主机日志里读回结果，不用单元测试代替。

## 已知差距

- **入口仍可点。** 主动类入口在只读成员的界面上没有禁用，点了才被主机拒绝，弹出 Orca 通用错误框（带「提交议题」尾部）。理想做法是按访问级别禁用入口并说明原因。本次检查未见渲染端的环境记录使用访问级别，补上需要改 Orca 的环境记录，要单独决策。
- **没有按项目限定范围。** 规格要求个人项目不会因团队目录存在而自动可读，但主机端不按项目过滤读取。这需要给带工作树或项目参数的方法加范围检查，并过滤列表结果，单独设计。
- **宿主范围的读取仍放行。** 宿主全部 AI 会话的列表与搜索、宿主账号列表、SSH 目标、jira/linear/gitlab 只读查询、会话读取接受的自带转录路径、`settings.get` 返回的 agent 启动环境变量（可能含密钥）、浏览器 console/network 日志。界面的后台读取会调用它们，贸然拒绝会让基础协作出错，待逐个核对界面调用方后再定。
- **终端面板无活进程时的读取失败仍记为错误。** 成员看一个主机上没在运行的会话时，核对面板会报错。应当当作预期内失败降噪，待错误信息入日志后确认再做。
- **成员身份是自报的。** 不防冒充，团队内信任下已接受，见实现设计。
