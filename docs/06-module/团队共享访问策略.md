# 团队共享访问：权限与日志规范

> **维护约定**：给修改团队只读访问策略（`runtime-rpc-team-read-policy.ts`）、宿主访问日志（`runtime-access-audit*`）、新增 RPC 方法或会影响只读成员的界面入口的人和模型读取。只写判定原则、界面动作分类、日志规则、新增/调整时的维护步骤和已知差距；不列方法全表（以代码和测试为准）、不写用户旅程（见[规格](../05-features/team-collaboration/spec.md)）、不写实现落点与身份契约（见[实现设计](../05-features/team-collaboration/design.md)）、不记变更流水。分类原则、日志规则或动作归类变化时更新。

## 先看界面，再看方法

判断一个请求该不该放行，先问「成员在界面上做了什么」，不是「它调用了哪个函数」。正常用户只在界面里操作；主机端按方法名拒绝只是兜底，防止有人绕开界面。所以：

- 策略、日志和测试都以**界面动作**为单位归类，方法名只是动作的实现细节；
- 日志写成员做了什么（「向 Agent 发送消息」），不写调用了什么（`agentSession.send`）；
- 评审一条新规则时，先说它对应成员界面上的哪个动作。

## 界面动作分类

默认放行：成员能在界面上点到的操作，只要不落入下面四类，主机都照常处理，包括启动或续接会话、新建和关闭终端与页签、保存计划与材料、改主机设置、操作共享浏览器（含运行脚本）。成员之间是团队内互信，不按攻击者设计。

只拦四类，每类只在核心入口拒绝，入口被拒后面的步骤界面够不到，不再逐个登记：

| 拦的动作 | 为什么 | 拒绝处理 | 日志 |
|---|---|---|---|
| 向终端、Agent 或模型发输入和消息 | 成员不能和模型讲话，也不能替主机敲命令 | 终端流里的输入帧丢弃；相关方法拒绝并给中文提示；启动会话时带提示词也拒绝，不带提示词可启动 | 拒绝时记，用动作名 |
| 读主机上项目之外的文件 | 不越出共享项目 | 拒绝；浏览器地址只能是网页，不能是本地文件 | 拒绝时记 |
| 以主机持有人的账号写回外部系统 | 评论、合并、改状态会以持有人身份出现 | 拒绝并给中文提示 | 拒绝时记 |
| 改项目文件、Git、工作树和项目列表 | 默认只读 | 拒绝并给中文提示 | 拒绝时记 |

整族不允许的前缀另表：主机桌面、模拟器、语音、剪贴板、成员浏览器挂接主机页面。挂接是成员界面自己发出的，拒绝不写日志。

放行的动作里，会让主机上多出进程或改动的记一行日志，读取类成功不记，见下节。
终端订阅流里只丢弃键盘输入，成员看输出；窗口大小照常上报，保证成员看到的终端大小、滚动与主机一致；访问级别按每帧、每次请求读取宿主设备登记，主机持有人在共享访问列表切换成员级别后，已打开的终端也立即按新级别放行或丢弃，不需要重连。浏览器页面只能打开网页地址，不能打开主机本地文件；成员新开的页面不抢主机窗口焦点；成员打开工作树不移动主机自己的窗口。

## 日志规范

- **位置与保留**：主机 `userData/logs/orca-shared-host/`，按天写入，保留 14 天，界面可按动作、结果、时间和成员筛选，也可清理。
- **记什么**：连接建立与断开、授权与撤销、被拒绝的动作、请求错误（带错误码和截断后的主机错误原文，可能含路径）、放行但会让主机上运行或改变东西的动作（运行浏览器脚本、改主机设置与终端快捷命令、新建、停止、重命名或关闭终端与页签、启动或中断 Agent 会话、安装或删除技能、增删或运行自动化任务、发布共享、保存材料等）、凭据无效的请求（持有已撤销或伪造的设备令牌，记为「共享连接凭据无效」，不带成员）、协作类成功动作（提交与撤回原型批注、授予完全访问与恢复只读、评审收发）。
- **不记什么**：成功的常规读取（含观看浏览器画面、截图和指标刷新这类成串或成员常点的只读动作）、成员界面自己发出的拒绝、客户端核对主机终端是否还在时的固定报错（`terminal_not_found`、`terminal_liveness_unavailable`）；同一设备、同一动作、同一错误码和错误原文的拒绝或失败，60 秒内只记第一条（一次尝试常触发成串请求，如成员敲字时每个按键都会上报一次）；请求参数、文件内容、模型输入、shell 正文、终端流和凭据任何时候都不进日志；错误原文只取主机返回的前 200 字。
- **用语**：每个会产生记录的动作都要有精确的中文动作名，写在 `src/shared/runtime-access-audit-labels.ts`；按方法族兜底的通用名只用于没人关心的长尾方法，成员能点到的入口不得只靠它。动作名站在成员视角，不含方法名或内部术语，方法名只作诊断。
- **连接记录**：一位成员在一台客户端上无论开了几条通道，只记一次「建立共享连接」和一次「断开共享连接」；首条通道建立时记建立，最后一条通道断开时记断开，按成员设备计数。
- **成员**：显示 WeLink 姓名和头像，不显示链接所有者；同一链接下每位成员各一条记录。

## 新增或调整时怎么做

1. 先问这个动作是不是上面四类之一。不是就什么都不用登记，默认放行。
2. 是的话，在 `runtime-rpc-team-read-policy.ts` 只登记这个动作的核心入口，不登记它后面的步骤。整族都不允许的前缀放前缀表。
3. 凡是会进日志的方法，补精确动作名。
4. 测试按动作断言：每类拦的动作各有核心入口被拒，常见的放行动作不被拒。新类别在已有断言里补一行，不新增测试用例。
5. 分类或日志规则变了，同步改本文。
6. 用两台真机验证：成员以只读身份走一遍该界面动作，在主机日志里读回结果，不用单元测试代替。

## 已知差距

- **入口仍可点。** 被拒绝动作的入口在只读成员的界面上没有禁用，点了才被主机拒绝，弹出 Orca 通用错误框（带「提交议题」尾部）。理想做法是按访问级别禁用入口并说明原因。本次检查未见渲染端的环境记录使用访问级别，补上需要改 Orca 的环境记录，要单独决策。
- **没有按项目限定范围。** 规格要求个人项目不会因团队目录存在而自动可读，但主机端不按项目过滤读取。这需要给带工作树或项目参数的方法加范围检查，并过滤列表结果，单独设计。
- **宿主范围的读取仍放行。** 宿主全部 AI 会话的列表与搜索、宿主账号列表、SSH 目标、jira/linear/gitlab 只读查询、会话读取接受的自带转录路径、`settings.get` 返回的 agent 启动环境变量（可能含密钥）、浏览器 console/network 日志。界面的后台读取会调用它们，贸然拒绝会让基础协作出错，待逐个核对界面调用方后再定。
- **成员身份是自报的。** 不防冒充，团队内信任下已接受，见实现设计。
