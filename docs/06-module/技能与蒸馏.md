# 技能与提炼 — 模块实现心智

> 30 秒导读:这一层管 Workbench 自带的周期工作技能 + 技能提炼。设计层「是什么」在 [`architecture.md`](../architecture.md) §2 ④;**关键取舍在本页**。代码落点用 `codegraph` 探索。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

四份自有技能(week-planning / asset-audit / metrics-refresh / project-handbook)编译期 `include_str!` 编进二进制,提示词只给「名字 + 一句话 + 完整路径」,正文让 agent 按需读(渐进加载)。`asset-audit` 是资产盘点 Issue 的剧本,对应 §1 用例。

技能正本编进二进制零 IO、全局一份不随项目复制(不进用户仓)。Issue 的 workflow 根据类别默认值或周期工作标题确定。“用过几次”实际按当前打开项目的 Issue 列表聚合 workflow 引用数，不是调用次数；未读取其他项目的 Issue 列表时仍显示 0，这一计数缺口另行跟踪。技能提炼尚未接入，不能将技能列表视为提炼结果。仓里另有一份评审剧本 `mr-review`:规范已收录,尚未编进二进制、未派发。

## 主要矛盾 / 取舍

- **不预建方法论技能**:原六份「阶段方法论」默认 workflow 没打包、一份没被真正派发过,删光。阶段方法论该由业界 workflow(mattpocock / proto-design)提供,Workbench 每个环节挑一个最好的默认——要从实践里长出 Workbench 自己的方法论再建。任务规范约束(references,如指标铁律、改仓规则)归本模块,不和技能混。
- **技能提炼是 Issue 的附属动作**:把一个已完成 Issue 中验证过的做法提炼成技能,始终保留来源 Issue。不预建、不在缺少来源时提炼技能。
- **技能正本编进二进制,不进用户仓**:全局一份、零 IO;用户自己的技能约定放被管仓 `.claude/skills/`(配置表扫成「项目自有」),不拷进 Workbench 资产目录。
