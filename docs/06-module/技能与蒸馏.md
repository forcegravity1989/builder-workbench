# 技能与蒸馏 — 模块实现心智

> 30 秒导读:这一层管 Workbench 自带的运作剧本 + 蒸馏。设计层(是什么 + 关键取舍)在 [`architecture.md`](../architecture.md) §2 ④;代码落点用 `codegraph` 探索。本页讲怎么理解它的**实现内部结构**和**主要矛盾**。

## 实现心智模型

四份运作剧本(week-planning / asset-audit / metrics-refresh / project-handbook)编译期 `include_str!` 编进二进制,提示词只给「名字 + 一句话 + 完整路径」,正文让 agent 按需读(渐进加载)。`asset-audit` 是运作活② 的剧本,对应 §1 用例。

技能正本编进二进制零 IO、全局一份不随项目复制(不进用户仓)。活挂的 workflow 名在 codehub issue 正本上。「用过几次」每次现查 issue 列表聚合、不落表不缓存、不显示胜率(无结算记录)。蒸馏今天没接(会话屏按钮灰着、命令未接)。

## 主要矛盾 / 取舍

- **不预建方法论技能**:原六份「阶段方法论」默认 workflow 没打包、一份没被真正派发过,删光。阶段方法论该由业界 workflow(mattpocock / proto-design)提供,Workbench 每个环节挑一个最好的默认——要从实践里长出 Workbench 自己的方法论再建。阶段规范约束(references,如指标铁律、改仓规则)归本模块,不和技能混。
- **蒸馏是活的附属动作**:把一件做完的活提炼成带做法的技能,永远记着来自哪件活。不预建、不无源蒸馏。
- **技能正本编进二进制,不进用户仓**:全局一份、零 IO;用户自己的技能约定放被管仓 `.claude/skills/`(配置表扫成「项目自有」),不拷进 Workbench 资产目录。
