# 技能与提炼

> 给维护 BW 产品技能与提炼能力的人读；只说明技能职责和方法进入产品的边界，不复制分发设计或 SOP。技能范围或采用方式变化时更新。整体位置见 [architecture](../architecture.md)，加载实现见[会话入口与 Skill 加载](系统提示词与渐进加载.md)。

## 产品技能

计划、验收、指标配置分别由 `week-planning`、`version-acceptance`、`metrics-refresh` 承接。正源在 `standard/skills/`，三个完整文件包通过原生安装能力交给业务会话。项目自己的开发、评审与交付方法仍由项目 AGENTS 及其已有技能决定。

公共规则只维护一个源，Skill 写清动作前的读取要求；流程的完整用户旅程与 SOP 在 SKILL.md，方法和异常处理在 references，确定性操作在 scripts。资产治理先读 [Skill 写作规范](../../standard/skills/SKILL-MD-SPEC.md)，不因重复反馈向入口叠加规则副本。

## 方法采用与提炼

有价值的反馈须有真实任务和来源，按所影响的流程归入现有正本；只改变表达或移动文件不能证明行为改善。外部方法不因被提到就成为 BW 默认派发能力。

技能提炼旨在将已验证的做法收为可复用方法，保留来源 Issue。该产品能力尚未接入；技能目录和安装成功不能作为自动提炼已交付的证据。
