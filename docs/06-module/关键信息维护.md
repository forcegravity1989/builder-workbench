# 关键信息维护 — 模块实现心智

> **维护约定**：给修改事实读取、保存与派生逻辑的人和模型读取；只写事实层的正本边界、实现心智和取舍，数据流变化时更新。整体能力见 [architecture](../architecture.md) §2 ①，Issue 与关联协议见 [issue-state](../../standard/system-prompt/references/issue-state.md)，字段格式按对应 reference，不在本篇复制。

## 实现心智模型

业务正本与运行时状态分开：Issue 的原生字段承载处理状态与关闭原因；仓内文件承载项目约定、版本计划及指标定义。Orca 的会话、工作树和本机设置由执行核管理，不能将旧 Rust 的 projects.toml、settings.toml 或 sessions/*.jsonl 当作当前存储说明。

计划/验收材料经 `workbench.materials.*` RPC 与 `ORCA bw materials` CLI 共用同一材料事务：按 expectedRevision 校验修订，跨进程互斥并原子写入；界面自动保存也须走此路径，冲突保留双方内容。项目名片经 `workbench.charter.*` RPC 在 `bw/project` 固定工作树提交并开 PR 合入被管仓，仅无远端/无工作树时降级直写工作区并如实提示；知识文档保存仍经 preload 文件接口直写当前仓路径，不能宣称已经全走评审工作树。具体来源与未迁边界以 architecture §3 为准；这不改变“仓文件通过分支和 PR 评审”的产品要求。

项目周报是从这些正本提炼的项目过程视图。复用原生项目会话与工作树文件接口，每次更新追加不可变报告文件，当前与历史从文件重算；人工修订有独立记录，之后自动生成遗漏也不丢失。模板与正文 renderer 共用，来源留在内部，不再维护模拟报告更新器；具体设计见 [周报](../05-features/weekly-report/design.md)。该乐观追加协议不等于计划材料的事务锁，本地报告保存也不等于已合入或目标验收。

## 主要矛盾与取舍

- **正本不由展示代替**：计划 JSON 和 Issue 状态各有来源；演示数字、缓存与壳内状态不能作为远端工作已经完成的证明。
- **信号来自数据**：没数据即未知，不能手设健康。旧 Rust 的密封类型不是 Electron 的现成实现；真实指标、推导与重启读回证据随特性迁移补齐。
- **完成由人决定**：自动化与模型不能推到 Done；远端写入结果要独立读回，退出码不替代实际状态。
- **版本关联保留事实**：计划 JSON 的任务引用保存 provider/repository/number 与 goalId；材料写入边界听 [版本材料](../../standard/system-prompt/references/version-records.md)。
- **文件归属先于便利**：知识库来源与保存评审路径需一起重新决策，不能用界面能保存证明已符合协作约定。
