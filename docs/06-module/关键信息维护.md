# 关键信息维护 — 模块实现心智

> **维护约定**：给修改事实读取、保存与派生逻辑的人和模型读取；只写事实层的正本边界、实现心智和取舍，数据流变化时更新。整体能力见 [architecture](../architecture.md) §2 ①，标签协议见 [issue-state](../../standard/system-prompt/references/issue-state.md)，字段格式按对应 reference，不在本篇复制。

## 实现心智模型

业务正本与运行时状态分开：Issue 与标签承载工作状态；仓内文件承载项目约定、版本计划及指标定义。Orca 的会话、工作树和本机设置由执行核管理，不能将旧 Rust 的 projects.toml、settings.toml 或 sessions/*.jsonl 当作当前存储说明。

计划/验收材料经 `workbench.materials.*` RPC 与 `ORCA bw materials` CLI 共用同一材料事务：按 expectedRevision 校验修订，跨进程互斥并原子写入；界面自动保存也须走此路径，冲突保留双方内容。项目约定与知识文档仍经 preload 文件接口读写，接入名片与知识保存可直接写当前仓路径，不能宣称已经全走评审工作树。具体来源与未迁边界以 architecture §3 为准；这不改变“仓文件通过分支和 PR 评审”的产品要求。

## 主要矛盾与取舍

- **正本不由展示代替**：计划 JSON 和 Issue 状态各有来源；演示数字、缓存与壳内状态不能作为远端工作已经完成的证明。
- **信号来自数据**：没数据即未知，不能手设健康。旧 Rust 的密封类型不是 Electron 的现成实现；真实指标、推导与重启读回证据随特性迁移补齐。
- **完成由人决定**：自动化与模型不能推到 Done；远端写入结果要独立读回，退出码不替代实际状态。
- **版本归属保留事实**：bw:plan:<版本名> 可多值，迁移不覆盖历史归属；完整写入边界听 issue-state。
- **文件归属先于便利**：知识库来源与保存评审路径需一起重新决策，不能用界面能保存证明已符合协作约定。
