# Issue 规范与处理决定

> **维护约定**：供处理、创建或改写 Issue 的模型与开发者读取。只写 Issue 的事实来源、正文要求、版本关联和远端写入边界；开发起手判断见目标仓的开发 Skill，版本材料格式见 [version-records.md](version-records.md)。现行 provider 或材料契约变化时同步正文、提示与分发产物。

## 事实来源与处理结果

Issue 的状态由 Orca 使用的远端 provider 读取。GitHub Issue 使用 open / closed；关闭原因可为 completed（已完成）、not_planned（决定不做）或 duplicate（重复，指向已有 Issue）。其他 provider 按其实际能力记录理由，不假定拥有相同字段。

关闭表示问题已经经过处理决定，不要求每次关闭都有代码交付。完成、取消、重复和旧问题失效都可以形成关闭决定；关闭原因应准确，不能把决定不做写成实现完成。Issue 关闭、PR/MR 合入和版本目标达成分别核对，关闭数不自动证明目标达成。指标按项目定义统计，不在清理时擅改口径。

现行 BW 不通过 `bw:status:*` 标签实现待办、进行中、待评审、阻塞或取消状态机，也不通过 `bw:released:*` 或 `bw:category:*` 推导交付与路由。不为本次工作新写这些旧协议标签。已有标签只作历史资料；清理时按用户认可的范围精确处理，不能整张覆盖。

## 处理前核对

读取当前 Issue 正文、讨论、关联 PR/MR、适用版本与当前实现，区分原始用户问题、旧方案和已有证据。问题已解决、重复、只针对已退役实现或已无用户价值时，说明依据并提出准确的关闭建议；仍存在的诉求按当前架构改写。证据不足时保留待核，不仅凭无法复现、代码存在或目录删除判已解决，不为了跑流程恢复旧实现。

关闭、重开、删除关联或写远端内容遵循本次人的决定与授权。已有明确授权直接执行并读回，不重复确认；未获授权时先给具体可审查建议。自动化和模型不能自行把问题判完成、关闭 Issue、合入 PR/MR 或发布。提 PR/MR 后回显真实链接和剩余验证，不再补旧待评审标签。

## 标题、类型与正文

- 标题用一句话说明具体问题或工作。已知版本与目标可供人阅读，但前缀不承担机器关联；没有已确认目标不编版本、周号或目标编号。系统入口沿其真实标题，不强加任务前缀。
- Bug 与 Feature 使用 provider 已有类型或项目约定标签；核对真实字段，不能声称没有标签便默认 Feature。GitHub 可采用 Bug / Feature 类型或项目约定的 `bug` / `Feature` 标签；未知类型先核对，类型不是执行状态，也不承诺界面自动分类。
- 正文至少有“问题与范围”“验收条件”两节；手写可用二级标题，GitHub 表单生成的三级标题同样有效。写清谁遇到什么问题、本次处理什么、怎样判断结果；Bug 另有“复现步骤”“预期与实际”两节，环境与版本写在能帮助复现的位置。
- 预研写清待回答的问题与停止/判断条件，不把模糊设想直接变成本版承诺。尚未确定的范围、复现或验收标待确认，不编造证据填满模板；必要决定明确后再改依赖代码。
- 复用已有 Issue；重复项指向承接单，混合任务在用户确认范围后拆分。改写保留来源、仍有效的决定和关联证据，旧实现说明标历史，避免正文同时指导新旧两套做法。

## 版本与目标关联

现行计划的任务关联保存在 `.bw/planning/<版本>/data.json` 的 `tasks`：provider / repository / number 标识远端任务，goalId 关联该计划已有目标。验收使用固定计划中的任务引用及实际读回的快照；标题前缀、评论和旧 `bw:plan:<版本>` 标签不代替这些引用，不能宣称界面会从它们自动纳入任务或推导遗留。

纳入、移出或改目标按已认可版本与任务范围，经材料工具写入并读回；不顺便关闭 Issue，不回写历史计划或验收快照。既有版本标签仍保留历史含义，是否删除由人明确决定。材料工具、修订和人工验收边界见 [version-records.md](version-records.md)。

## 远端直写与读回

GitHub 标签增删用精确操作。CodeHub 的 `issue update --labels` 可能整张替换：先读全部标签，只改已授权目标，再完整写回。任何 provider 都保留未授权的正文、标签、负责人、版本与历史关联。

写前读最新对象，核对仓库和编号，避免覆盖伴飞或其他人的改动；写后独立读回实际编号、浏览器链接、标题、正文、原生状态、关闭原因（provider 支持时）、类型及本次改动的关联。退出码不代替读回，未取得远端编号的条目只是待建草稿。评论可保留过程与理由，状态以远端字段为准，版本与目标以材料引用为准。
