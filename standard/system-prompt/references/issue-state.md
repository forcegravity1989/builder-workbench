# Issue 状态与版本标签

Issue + 标签是任务执行状态与版本归属的唯一正本。评论可以记录会议过程，但不参与状态、版本归属或遗留计算。

## 标签语义

- `bw:status:{todo|inprogress|inreview|blocked}`：执行状态，单值。开放 issue 没有可识别状态标签时按 `todo`；关闭且没有取消标签就是完成。
- `bw:status:cancelled`：取消并关闭；取消不等于完成。
- `bw:plan:<版本>`：计划纳入关系，可多值。同一 issue 可以同时带 A、B，表示它曾纳入 A、现在也纳入 B；纳入 B 只增加 B，不删除 A。
- `bw:released:<版本>`：实际在哪个版本交付，单值，由人点发版本时 Workbench 写入。
- `bw:category:{prototype|build|optimize|growth|ops}`：类别，单值。

回看已发布版本 A：带 `bw:plan:A` 但不带 `bw:released:A` 的 issue 显示「遗留」；若它除 A 外恰好还带一个 `bw:plan:B`，显示「遗留 B」。这是版本结果标识，不是执行状态。

## 谁可以改

- 人在 Workbench 点按钮或拖卡：程序按动作精确改标签。
- 模型完成代码并提 MR：只可把执行状态改到 `bw:status:inreview`，不得关闭 issue、不得合入、不得标完成。
- week-planning 模型在人确认纳入清单后：可增加指定 `bw:plan:<版本>`，必须保留已有其他 plan、status、released、category 标签，并在写后读回。
- 自动化和定时任务不得把 issue 推到完成。完成永远由人在 Workbench 点。

## 执行状态机

- 未排期 → 待办 / 进行中 / 取消 / 完成
- 待办 → 未排期 / 进行中 / 阻塞 / 取消 / 完成
- 进行中 → 待办 / 待评审 / 阻塞 / 取消 / 完成
- 待评审 → 进行中 / 阻塞 / 取消 / 完成
- 阻塞 → 待办 / 进行中 / 取消 / 完成
- 完成 → 待办 / 进行中

其中“完成”边只允许人触发；“遗留”不在这张状态机里。

## 远端直写纪律

CodeHub 的 `issue update --labels` 可能整张替换：先读回全部标签，只增加或删除目标标签，再把完整集合写回。GitHub 使用精确的 `--add-label` / `--remove-label`。任何 provider 都不得用“替换整个 `bw:plan:` namespace”的方式纳入新版本。

移出版本时只删除人明确指定的 `bw:plan:<版本>`；不清空其他计划版本，不从评论猜历史，不写顺延链。

## 任务 Issue 的标题、类型与正文

业务任务以 Issue 承载，周一屏 JSON 保存目标、总结和评审材料。类型和目标引用采用以下约定；不改变 BW 的 Ops/Light/Business 执行路由。

- 类型使用 `Bug` 或 `Feature` 标签，读取不区分大小写；无类型标签默认 Feature。两者同时出现先按 Bug 展示并要求核对，新建时只选一种。既有 `bw:category:*` 是工作分类，继续保留，不拿它代替 Bug/Feature。
- 标题为 `【v0.4|W38|G1】一句话描述具体任务`。三段分别是目标所属版本、该目标的 ISO 周信息、目标编号；周号须从已核实的规划日期取得，不靠模型猜。逻辑目标身份为 `v0.4/G1`，不是远端父 Issue。没有可核实目标就只写任务标题，解析不到关联留空。
- 排期只认 `bw:plan:<版本>`。跨版纳入追加标签，保留原标签；标题中的目标版本/周号不随延期自动改写。只有人明确改归属时才调整目标引用。
- 正文至少有 `## 问题与范围`、`## 验收条件`；Bug 加 `## 复现步骤`、`## 预期与实际`。不把一段目标口号当任务，不强制逐任务维护交付件清单。执行中的真实进展、阻碍、MR 链接可追加评论。
- 在拆新任务前提醒用户核对现有未排期、遗留和 Bug 是否纳入；复用已存在的 Issue。纳入后读回编号、浏览器链接、标题、正文、类型、全部版本与状态标签；未取得编号的本地条目只是待建草稿。
- 系统版本计划、资产盘点等 Issue 保持系统识别标题，不加上述目标前缀；任务表不把这些流程入口重复列作执行任务。

周一屏采集用结果对应的版本标签查询全部状态的 Issue，不仅查开放项；当前版本计划用本版标签。页面关联链接使用远端返回的真实浏览器地址，不按编号猜仓地址。实际进展由 Skill 阅读 Issue、MR 和用户反馈后简要填写，不把 closed 或 merge 单独翻译成已验收。
