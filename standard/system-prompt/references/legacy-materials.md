# 旧格式材料查找

> 给计划/验收会话在读不出材料、字段对不上或被要求迁移时查；正常流程用不到，默认不读。本文定义旧格式材料的读回行为、字段语义与迁移边界；现行字段契约在[版本材料](version-records.md)。旧格式处置变化时更新。

## 总则

旧格式材料是只读历史：schema 仍接受旧字段以便存量材料可读，但任何界面与模型通道都不得写入、修改或清理旧字段——「顺手清理」也属于迁移，会被人工守卫拒绝。读回永不改写存量文件。把文件真正转换到当前格式属**迁移**，只能按下节在会话中经人确认后执行。

## 旧字段语义（验收材料）

| 字段 | 语义与读回 |
|---|---|
| `results[].rounds[]` | 验收轮次记录与快照；轮次概念已退役，只读呈现 |
| `results[].meetingDirectives[]` | 会议指导：正文 + 处置标签 + 确认状态 + 来源。处置标签：`next-week-plan`（纳入下周计划）、`record-remaining`（遗留背景）、`resolved-this-acceptance`（该次验收已解决）、`pending`（未确认） |
| `results[].deliveries[]`、`results[].materials[]` | 目标级交付件与材料链接；已由版本级交付件与演示环境取代 |
| `results[].progress` | 目标级人工进展文本 |
| `issueMarks[].risk` | 风险标记；风险能力已整体退役，`issueMarks` 只剩 `carry`（延期遗留） |
| `preparationReview` | 人工材料备齐核对记录；界面已不消费，保留原值，不证明命令执行或目标达成 |
| `decision.outcome='pending'` | 历史结论读回保留；板面不写不显，现行结论只有 `met` / `not-met` |

验收屏末尾的旧格式只读折叠区如实呈现这些字段，它们不参与任何结论、纪要与遗留回显。

## 会议遗留回退读法

验收材料没有 `minutes` 节时（旧格式），计划屏「会议遗留」回退读已确认（`confirmed`）且 `tag=next-week-plan` 的会议指导条目，只把这类条目带入本版候选；其他处置标签只作背景：`record-remaining` 保留为遗留背景，`resolved-this-acceptance` 不重复承诺，`pending` 不当作已采纳要求。该版一旦有了人工确认的纪要，以纪要为准。

## 迁移（经人确认后执行）

1. 屏上打不开旧格式时，先用一句话说明：把旧字段收成新计划，对不上的目标问人，确认后再写。不要先讲备份方案。点击「新建计划／验收」只表示开始这次处理，不是同意改文件。
2. 用材料工具的 `migration-preview` 看会变成哪些目标和任务；预览不写文件。目标对得上就 `migrate`。结构以随 CLI 打包的 schema 为准（`ORCA bw materials schema --workflow plan|acceptance --json`），旧结构文件不能直接提交。
3. 对不上的结果或交付物问用户，不猜测归到哪条目标。旧指标写进说明并标为待核，不写成新的指标目标。旧确认不升级成新的认可或采集证据。旧结果只在用户明确要归入上一版、且目标和标题对得上时，才写入那一版的验收草稿；缺计划、版本含糊或对应冲突时不伪造引用。
4. 写入后若同目录留下 `schema2-` 开头的旧副本，删掉，只留新材料。冲突就停，重读后再问，不重试覆盖。多版本先转当前要打开的计划。
5. 迁移保留原件与提交来源；不能无损解释的对象保留待核，不硬凑。
