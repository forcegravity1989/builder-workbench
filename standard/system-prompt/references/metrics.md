# .bw/metrics.toml — 指标定义与脚本采集

> 给准备、调用和核对指标的会话读取。本文是定义、采集和读数语义的正本；SOP 在 metrics-refresh，版本证据引用见 [version-records](version-records.md)。协议变化同步模板、解析器及消费者。
>
> 本文规定现行业务指标契约；实现与验证状态见总览指标特性，不从协议文本推定运行结果。

## 定义

正本为项目 .bw/metrics.toml，schema_version=2。没有文件表示未配置，解析失败表示错误。项目名片属于 project.toml，不复制过来。

北极星可缺席；结构为可选 [north_star]、[[lagging]]、[[leading]]。每条包含 name、def、target、collect；可选 unit 标明读数单位，缺省为空，不推测单位。feature 空归“主要”，有值归对应特性；引领的 leads 指明关联滞后指标，缺省仅在同组恰有一个滞后指标时采用，错误或歧义需修正。

只支持 collect.kind=script 且 retro=true，run 是非空 argv，不经 shell 拼接。脚本必须能按日/周查询历史；没有可信历史来源就保持未配置，不用当前快照补历史。目标是用户约定，实际数字不能手填。模板默认不创建空北极星或无脚本指标。

## 历史脚本输出

脚本按请求粒度返回 points，每点包含 week 或 day 与 value。retro=false 或仅输出当前 value 不受支持；不得补前值、零或伪造过去的点。源数据、凭据及历史存储归用户项目或外部服务所有，BW 读取其真实来源，不代建时序数据库。

调用 cwd 是本次已解析采集代码的隔离工作区，追加 --since YYYY-MM-DD --until YYYY-MM-DD --granularity week|day，窗口左闭右开，时区由项目/宿主明确；默认超时 900 秒。stdout 只接受一个合法 JSON，stderr 为诊断。没有 points 或返回格式与能力不符时报采集失败。

week 请求使用周一到周一的完整 ISO 周日期边界；任意起止日期改用 day，不能把整周 value 裁成部分周的标签。历史点未声明覆盖时表示完整自然日/周，只接受已结束的窗口。未结束的本日/本周或其他部分覆盖必须由脚本为该点返回 coverage={start,end}（带时区偏移的 ISO 时间），value 必须按这个真实范围采集；覆盖范围不能越出点位自然窗口或晚于采集时间。服务保留来源声明的边界，不自行截短时间标签来推断 value 也已截短。

执行器通过 BW_METRICS_TIMEZONE 传入本次明确时区；统计项目源码的脚本通过 BW_METRICS_DATA_ROOT / BW_METRICS_DATA_COMMIT 获得已解析的数据目标，不能把采集器 cwd 当作数据分支。仓内 git-commits.py 模板按真实日历边界过滤提交时刻并返回 coverage，独立运行默认当前目录 HEAD，服务运行必须明确传入数据目标。已铺入其他项目的旧脚本不自动覆盖；缺真实覆盖时按协议报告需修复。

目录同步解析项目实际配置来源的最新已合入提交，不 merge、重置或覆写计划/验收材料树。每次新采集采用最新目录；执行开始后固定这一提交的定义、脚本及受其影响的项目依赖/锁文件，复用 Orca 隔离检出/进程能力。不能从常驻树旧文件或未提交改动代用；正确修订不可取得时报告错误，不伪称最新。定义指纹和执行指纹分别保存；后者至少绑定本次配置提交、脚本内容及声明依赖，缓存/去重键包含这些来源。数据目标（仓库、服务、窗口）与采集代码来源分别记录，不能把采集器隔离树当被统计分支。配置任务试采标草稿，未合入前不成为正式目录。

point.value 可为数或可读字符串。0 是有效读数；非零退出、超时、坏 JSON 或没有适用数据都是未采到，不能补 0。字符串不可伪算趋势/达成比例。

## 使用与证据

UI 正常刷新直接调用采集服务，无需模型会话。“配置指标”每次在固定维护树中新建原生会话，由 metrics-refresh 协助维护定义和脚本；实际跑通后才能标可用。定义指纹、采集时刻、真实窗口、源码/脚本来源随新读数保留。

计划 baseline 和归档 readingEvidence 保留当时采用的定义、结果与来源，只读回看。新采集按名称解析最新定义，不因旧 configurationCommit 或 definitionHash 不同而被拦截；验收可以选择最新目录的新指标补充实测，不改原计划承诺。界面详情显示来源、采集时间、配置提交与脚本修订，definitionHash 保存在材料中；没有专门的口径差异对比或确认界面。会话核对定义、单位与来源后向人说明可比性，不自动计算跨口径改善或判定达成。旧证据中的 instant/observedAt 仍可解释其历史身份，不恢复当前值采集入口。

不支持人工实际数，不登记每日指标自动化，不迁移 bw/ledger。历史 manual 定义与旧日记录只作为迁移诊断/历史材料，不能成为本期有效采集；缺脚本就待准备，不能将手填改名成脚本。日常刷新不往 readings.jsonl 追加日流水。

项目提交、合入 PR、开放 Issue 等内建研发统计复用原生 Git/provider，独立于业务指标目录，不重复定义为业务指标。
