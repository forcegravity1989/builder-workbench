# 运作活①评论格式(Workbench 要解析)

版本目标、纳入清单、读数快照挂在本周运作活①的 **issue 评论**,不动正文。
只追加,不改旧评。Workbench 从新到旧扫,同一段以最新一条为准。

界面展示「版本目标」**整段**(一句或一段都行)。纳入和读数快照人点开这张运作活看。

挂评论之前用同目录剧本里的校验脚本过一遍:

`python <skill_dir>/check-week-comment.py <评论稿>`

过了再贴。缺标题或版本目标空着会非零退出。不规定必须几行。

必须用下面三个二级标题(字要写对;后面可以跟括号说明):

```
## 版本目标
人说的话。一句或一段都可以。

## 本周纳入
- #12 已有活(只打 bw:plan:<版本名>,不新建)
- 新拆:标题……(人确认后你要真建 issue 并打 bw:plan:<版本名>)

## 本周指标读数
(快照,不是读数正本。没采到的不写行、不写 0。)
```

打完 `bw:plan:<版本名>` 之后,codehub 上还要把这张 issue 挂到**同名里程碑**(没有就建,起止默认本周周一到周五)。失败说出来,不回滚标签。GitHub 不投影。会话里 `issue update --labels` **不会**走 Workbench 内核投影,要自己挂。版本名推荐 `vX.X`(例如 `v0.3` / `v1.0`),人要用别的也行。

不要用「周目标」「本周目标」「业务活草稿」当标题 —— 旧评论 Workbench 还能读,新写的必须用上面三个。
