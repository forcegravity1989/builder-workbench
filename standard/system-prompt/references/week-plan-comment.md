# 旧版计划 Issue 评论格式

> 本文件只供旧流程评论的核对、修复与历史导入读取，不指导当前版本写入。当前材料契约见 [version-records.md](version-records.md)，资产盘点进展的写入步骤见 [asset-audit](../../skills/asset-audit/SKILL.md)。不要为新版本复制目标或进展评论。

旧流程的版本目标与每周进展正本在**更新指标与版本计划 Issue 的评论**,不在正文、不在仓文件。只追加,不改旧评。
多条从新到旧扫。版本目标以最新一条为准;每周进展该版本上有几条列几条(新的在前)。纳入和读数人点开这个 Issue 看。

旧流程的周初评论使用这三个二级标题(后面可以跟括号或空格说明):

```
## 版本目标
人说的话。一句或一段。不能空。

## 本周纳入
- #12
- #15（自 v0.2 遗留）
- 新拆:标题

## 本周指标读数
快照。没采到的不写行、不写 0。
```

历史评论修复时才跑 `week-planning` 技能目录里的 `check-week-comment.py`(和注入的 `week-planning/SKILL.md` 同级,不在本 reference 目录,也不在工作区根)。过了再贴。缺任一标题、或「版本目标」「本周纳入」空着会失败。
不要写「周目标」「本周目标」(旧评界面还能读,新写不认)。

`## 本周纳入` 先写已经挂了这个版本的 `#iid`,再写新拆。从别的版本遗留后又纳入本版的,可写 `#iid（自 <旧版本> 遗留）` 给人阅读；评论不是版本归属正本，新拆的不写遗留。

## 历史标签与导入

旧流程曾通过 `bw:plan:<版本>`、`bw:status:*`、`bw:released:*` 与 `bw:category:*` 标签表达纳入、执行和交付关系，并可能挂 provider 里程碑。这些只用于核对当时的记录，不指导现行新写或恢复旧状态机。

导入前保留原评论/提交来源，将用户已确认的版本与目标映射到现行计划的任务引用；未确认关联留待核。当前状态读 provider 原生字段，当前材料契约见 [version-records.md](version-records.md)，Issue 写入边界见 [issue-state.md](issue-state.md)。不改历史评论来伪装当时已采用新契约。
