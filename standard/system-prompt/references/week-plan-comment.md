# 运作活①评论格式(Workbench 要解析)

正本在**评论**,不动正文。只追加,不改旧评。从新到旧扫,同一段以最新为准。
界面只展示 `## 版本目标` 整段。纳入和读数人点开这张活看。

## 挂评前校验

`python <skill_dir>/check-week-comment.py <评论稿>`

脚本和 `week-planning` 剧本同目录。过了再贴。缺标题或版本目标空着会失败。

## 三个标题(字要写对)

```
## 版本目标
人说的话。一句或一段都可以。

## 本周纳入
- #12 已有活(只打 bw:plan:v0.x)
- 新拆:标题……(人确认后才建 issue 并打 bw:plan:v0.x)

## 本周指标读数
快照,不是读数正本。没采到的不写行、不写 0。
```

`## 本周纳入` 先列已经挂了这个 `v0.x` 的 `#iid`,再写新拆。不要写「周目标」「本周目标」。

## 标签和里程碑

纳入的打 `bw:plan:v0.x`(业务活再打类别)。不要打 `bw:week`。
codehub 再挂同名里程碑;挂不上就说,不回滚标签,不阻塞评论。GitHub 不投影。
会话里 `issue update --labels` 不会走 Workbench 投影,要自己挂。
