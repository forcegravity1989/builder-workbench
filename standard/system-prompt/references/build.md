# 改仓 — 和 Workbench 怎么配合

主提示词的纪律照守。这里只补被管仓里看不见的落点；Issue 正文与远端处理边界读 [issue-state.md](issue-state.md)。

## 先判断是否需要改仓

先核对问题是否仍存在、当前实现与已有 PR/MR。旧方案不再适用时回到用户问题判断；已解决、重复或决定不做的任务先给处理建议，不为产出提交继续写代码。证据不齐先做必要调查，不空提交、不开空 PR/MR。

## 改动落在哪

使用宿主已打开的项目、工作树和执行身份，先用 `git rev-parse --show-toplevel` 和 `git branch --show-current` 核对。隔离分支与 PR/MR 按被管项目 AGENTS 和实际 Orca 工作树配置执行，不假定所有项目都使用 `bw/issue-<号>` 或固定物理路径，不碰人的主检出或他人改动。

提交并开 PR/MR 后回显真实地址、实际验证与剩余问题。合入与 Issue 关闭分别遵循人的明确授权；不再通过旧 `bw:status:*` 标签写待评审。

## 不是改仓的事

在用户已授权的范围内改写 Issue、精确增删标签或处理原生状态，直接在远端执行，不为这些操作空开 PR/MR。权限不足或写入失败保留真实错误；写前核对对象，写后按 issue-state 独立读回。
