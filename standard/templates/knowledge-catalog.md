# 知识文档总账(合格 AI-native 项目的标准知识文档集)

> **30 秒导读**:这是什么——一个项目「该有哪些知识文档」的总账:逐件给是什么 / 判据(可读回)/ 谁产 / 缺了怎么补,分**地板件**与**成熟度可选件**两档。从哪来——Workbench 自己仓的实践提炼(知识分层 + 产物链 + 2026-08 文档治理的返工教训)。给谁看——跑运作活②(资产盘点)的 agent 做知识库体检时,以及想知道「我的仓离规范还差几份」的人。现在作数吗——作数(2026-08-27 起,规范 5.10)。**铁律:判据全部可读回**(`git` / `gh` / `codehub-cli` / `cat`),体检**只建活不代写**——写不写、怎么写,永远是人的 gate。

## 怎么用这份总账

- **体检**:资产盘点剧本(`asset-audit`,运作活②)每周按本总账逐件跑判据,三态口径:✅ 过 / ❌ 缺 / ⚠️ 腐烂;判据命令跑不出来记「未查到」,不算缺也不算过、不猜。证据(逐件命令与结果)挂运作活②评论。
- **缺口变活**:体检发现的缺口按幂等标题建活——「补 <文件名>」(缺件)/「<正本名>回填」(腐烂);远端已有**开着的**同名活不重建。建出的活是普通业务活,人在看板决定做不做;没人理会就下周照报,不升级、不催、不自动关。
- **地板件锁 7 类**:想增删地板件要回规范正本过 gate,不许剧本或体检私加。
- **新鲜度阈值**:设计正本的腐烂阈值 N 默认 **4 周**,就在本文件这一行改,体检读这里。

## 地板件(7 类,每个项目都该有;判据全部可读回)

| 件 | 是什么 | 判据(存在性 + 新鲜度) | 谁产 |
|---|---|---|---|
| `README.md` | 门面:是什么 / 怎么跑 | 存在;有「怎么跑」一段 | 人或 workflow(仓根手册问过人才写) |
| `AGENTS.md` + `CLAUDE.md` | agent 开发手册(一页内)+ 一行导入 | 存在;「同一个错误犯两次,修正进手册」回路在转;每周修正频次有数(`handbook-changes.py`) | project-handbook 剧本,人点头 |
| `CONTEXT.md` | 领域词表(选定词 + Avoid) | 存在;新概念高频出现而词表无词条 → 缺口活 | workflow(如 domain-modeling) |
| 设计正本(如 `docs/architecture.md`) | 设计实况一篇正本 + 各模块「没建什么」 | 存在;N 周未动而代码大改 → ⚠️ 腐烂(N 见上,默认 4) | workflow / 人 |
| `docs/adr/` | 难回头决策一条一篇 | 目录存在即可(数量不设指标,防凑数) | workflow |
| `CHANGELOG.md` | 版本变更记录 | 存在;最近一次发版(git 标签)后有对应段 | 人或 workflow |
| `.bw/` 规范件 | 名片 / 指标 / issue-policy / 过程指标总账 / 本总账 | 铺底对账已有指纹机制,体检只引用其结论,不重查 | 规范铺底 |

## 成熟度可选件(4 类;体检只提示不催办,不建活)

| 件 | 什么时候该补 |
|---|---|
| `principles/`(原则:分层 / 主张 / 过程) | 项目出现「同一决策反复重议」或多会话协作时 |
| `changes/<id>/` 制品链(intent / spec / plan / STATUS) | 出现需要人对齐意图与规格的特性级变更时(小修直修不开链) |
| `docs/guide/`(使用指导) | 产品有第二个用户(同事 / 客户)时 |
| 高保真 / 视觉正本 | 有界面且开始返工视觉时 |

## 落进项目的机制(如实说明)

铺进被管仓的落点是 `.bw/knowledge-catalog.md`。新项目随规范铺底;已接入的老项目等规范升级对账机制——机制未接之前手动铺(与 `process-catalog.md` 同一个待接缺口,不单独造轮子)。
