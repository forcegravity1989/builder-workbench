# metrics-refresh：更新指标

## 1. 核心目标

把 `.bw/metrics.toml` 的现状摊给人,一次问一件,人点头再写。脚本当场跑通。不替人定北极星,不编读数。

## 2. When to Use / When NOT to Use

- 用:week-planning 第 2 步点了你。`metrics.md` 已在提示词里。
- 不用:自己开工、资产盘点、给人打分选北极星。

## 3. 前置依赖检查

- 工作区 `<workspace>/.bw/metrics.toml`:没有不是错。
- 名片 `.bw/project.toml`:摊给人看方向,空着就问;不写进本文件。
- 格式正本:`metrics.md`(已注入)。字段不抄进本篇。
- 仓里若有 `.bw/scripts/` 或 `.bw/process-catalog.md`,当选项给人看,荐不荐人定。

## 4. 标准执行流程

**第 1 步 · 打开文件,判分叉**  
走到读文件。

| 看到 | 走 |
|---|---|
| 没有文件 | 告诉人「还没定出来」,问要不要从零写。北极星可以空。 |
| `schema_version = 2` | 把现有三层(名 / 定义 / 采集)摊给人,问改哪条、补哪条、不动哪条。不重推已定北极星,除非人明确要。 |
| 旧格式或解析失败 | 内核整份拒收、不迁移。把原话给人,问要不要按现行格式重写。不要猜旧字段。 |

**第 2 步 · 一次问一件**  
走到问人。每条要写的指标问清:叫什么、怎么算、目标、脚本还是手填。手填再问「能不能写成脚本」(能 / 暂时缺什么 / 永远不能)。可选字段(所属特性、引领盯哪条滞后)听 `metrics.md`,不问清单。总览已画的仓统计(提交、合入 MR、开放 issue)不要再写成业务指标。过程脚本只当菜单,人没点头不写进文件。

**第 3 步 · 人点头再写、再跑**  
走到落定义。按 `metrics.md` 写 `.bw/metrics.toml`。`kind=script` 的当场跑一遍(窗口参数按 reference)。跑不通如实写「脚本已写、未跑通」。采到的数留给 week-planning 第 4 步抄进评论快照;不要手写 `readings.jsonl`,不要写 0。本步不单独开 MR。

## 5. 参考资源

- `metrics.md`(已注入):schema、`collect`、stdout JSON、失败不写 0。写文件前读。
- 仓内 `.bw/scripts/`、`.bw/process-catalog.md`(若有):给人看现成采集,不是必写。

## 6. error_handling

| 现象 | 处理 |
|---|---|
| 文件不存在 | 问人从零写还是本周先空着 |
| 旧格式 | 拒收原话 + 问是否重写,不做迁移 |
| 脚本非零 / 不是 JSON | 不写 0,说明卡在哪 |
| 人没点头 | 不写文件 |

## 7. 示例

没有 `metrics.toml`。问人北极星先空着行不行;人要一条引领「每周闭环 issue 数」、能脚本采。写 `schema_version = 2` + 一条 `[[leading]]`,跑通脚本,停下来等 week-planning 第 3 步。

## 8. 纪律表

| | |
|---|---|
| 必须 | 现状先摊开;人点头再写;脚本真跑 |
| 禁止 | 伪造读数;为点亮改定义;写 0 冒充没采到 |
| 你不做的事 | 打分选北极星;必写 `docs/metrics.md`;把过程指标擅自塞满 |
