# 资产盘点(asset-audit)

周五早上没人在场。只做两步:让这个仓的 Workbench 资产跟得上**当前**工作台,再把本周项目改动过一遍、建议写给人。

**这次会话很可能没有人在场。** 能做的先做,拿不准的写进报告,不要停下来等。

先读开工注入的 `bw-assets.md`(该有 / 整份可删 / 现行格式 / 和①的分工)。升指标格式时再读同目录 `metrics.md`。改仓规矩读 `build.md`。本周这个项目发生了什么现算,不要靠记忆。

读这张活的说明。没有 `mode:` 或写了 `weekly` 就走下面。`mode: first` **本轮不跑**(不打标签、不写 AGENTS.md、不叫 project-handbook);评论里写一句「说明里是首次模式,已按每周两步处理」。

## 第一步 · 盘 Workbench 给项目的 `.bw/`

对照 `bw-assets.md`,在**这张活自己的工作目录**里做:

1. **清残留**——白名单里还在的整份删。不是建议。拿不准的只写报告。
2. **升格式**——旧 `metrics.toml`、旧读数键、缺 `.bw/.gitignore` 的 `worktrees/`、还在的 `standard_version` 行:改到当前 Workbench 读得动。不改名片意图,不重定北极星/口径。
3. **点未闭环的环**——开着的项目约定 / 指标 / 账本 MR、本周没有运作活①、指标读不动、残留 `issue-policy`、读数还躺在主检出。人才能合的只写评论,不 merge、不替人点完成。

脚本对不上现行协议:能改到能跑就改;改了会动口径的,停手写进报告,等人走①。

## 第二步 · 盘项目本身

过一遍本周默认分支上的提交、以及还开着的业务 MR。建议只写进**这张运作活②的评论**,不改业务代码,不为审查另开 MR。

气质对齐仓内 `mattpocock-skills` 的 code-review / `mr-review`:找真风险、真回归、真缺口。没有就写「无」。不要为了看起来有产出硬凑改名建议。需要动业务逻辑或公开接口的,一律只写建议。

## 报告

挂进本张 ops② issue 的评论,三个标题,缺了就写「无」:

```
## Workbench 资产
## 闭环
## 项目审查
```

删了哪些旧件、升了哪份格式、哪条环还开着、建议哪几条,点名写。空话(「整体良好」)等于没查。

## 提交 + MR

`.bw/`(或白名单删除)有真实改动:正常提交,开 MR,把地址打屏。`gh pr merge` / `codehub-cli mr merge` 禁止。

**0 提交不装前进**:两步都只写出评论、仓里没改,就不要空提交、空 MR。评论仍然要挂。

## DoD

- 三个标题的评论挂上了,查过的都点名,没有的写「无」。
- 改过 `.bw/` 或删过残留 → 有 MR;没改仓 → 没有空 MR。
- `git diff --stat` 不见业务代码。最远「评审中」。

## 常见坑

- 把 skill 当现行文件清单(会漂)。清单在 `bw-assets.md`。
- 重写名片或重定北极星。那是项目约定 / 运作活①。
- 为凑产出空提交,或把审查建议做成业务 MR。
- 没人应答就卡住。等不来的。
- 把残留 `issue-policy.toml` 瘦一圈再写回去。整份删。
