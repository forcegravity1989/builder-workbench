# asset-audit：资产盘点

## 1. 核心目标

盘这仓一周(或首次对版本)该盘的东西,能修的旧铺底删掉,拿不准的写进报告。产出是这张活的评论 + 必要时一份只含白名单删除的 MR。很可能没人在场:能做先做,不等回复。

## 2. When to Use / When NOT to Use

- 用:workflow=`资产盘点`。本活无专用 reference。
- 不用:运作活①、业务活、项目约定。不在这里重写指标文件。

## 3. 前置依赖检查

- 这张活正文里的 `mode:`。读不到当 `weekly`,并在报告写明。
- `.bw/project.toml`:该有的名片。缺的只记报告,不补写。
- `codegraph files -j`:有就用,没有就跳过代码图那段并写明。

## 4. 标准执行流程

**第 1 步 · 判模式**  
走到分叉。读 issue 正文 `mode:`。

| `mode` | 走 |
|---|---|
| `weekly`(默认) | 第 2–5 步 |
| `first` | 第 6 步 |

**第 2 步 · 盘五类(`weekly`)**  
走到盘点。每类写「查了什么、发现了什么、要不要人管」:

1. 文档:本周运作活①在不在、Release 有没有落下。
2. 产物与 workflow:新技能 / 新挂 workflow 登没登记。
3. 规范:`.bw/project.toml` 在不在。`.bw/issue-policy.toml` 不再该有。
4. 指标新鲜度:只看本周运作活①评论里的「本周指标读数」。不要在这张盘点树里找 `readings.jsonl`(那份在账本树,这里没有不是错)。旧格式只记一句「去开运作活①」,这里不重写。
5. 大文件:`codegraph files -j` 超限的列入报告。零调用者不当死码删。

**第 3 步 · 删白名单旧件**  
走到清理。只删下面这些(在这张活的工作区,随盘点 MR):

`.bw/standard.toml`、`.bw/managed.toml`、`.bw/PROJECT.md`、`.bw/issue-policy.toml`、`.bw/connectors.toml`、`docs/Workbench/`、`.bw/plan/`、`docs/plan/`、确认没人再跑的 V3 采集脚本。

`issue-policy` 里若 `[cadence]` 不是 `fri 09:00`,报告写一句「他们改过盘点钟点,删后改用产品默认」。不像 Workbench 铺的文件只写报告。

**第 4 步 · 建议只写不改**  
走到建议。格式/命名/该拆的大文件写成优化活草稿(标题 / 说明 / 为何),放进 MR 说明。人周一勾了再真建。动业务逻辑或公开签名的,连草稿都不生成。没有可建议的就写「无」,不硬凑。

**第 5 步 · 报告 + MR(`weekly`)**  
走到交付。报告挂这张运作活②评论。白名单删了几份要点名。提交 + 开 MR,地址打屏。`git diff` 只许白名单删除或空。

**第 6 步 · 首次模式**  
走到对版本。产品定时不会建 `mode: first`;只有人开了这张活才走这里。列出远端已有 issue。能对上已有 `v0.x` 的打 `bw:plan:v0.x`(缺类别的补类别)。对不上的留未分配,不打 `bw:week`,不按提交日期倒推版本。某个版本缺版本目标:只建一张光杆运作活①(标题「更新指标 + 制定版本计划」,workflow=`更新指标与版本计划`),**不代写评论**(这张盘点活没注入评论规范;评论留给 week-planning 那场)。手册缺口、名片缺口只记报告,不在这里写仓根 `AGENTS.md`、不点 `project-handbook`(产品还没自动接上)。读不到 issue 列表就停,报告写缺什么。

## 5. 参考资源

- 这张活自己的正文:`mode`。
- `project-handbook` / `week-plan-comment.md`:本场不读。手册和版本评论不在这张活接。

## 6. error_handling

| 现象 | 处理 |
|---|---|
| 正文无 `mode` | 当 `weekly`,报告写明 |
| 没有 codegraph | 跳过第 2 步第 5 条,报告写明 |
| 读不到远端 issue(`first`) | 停下,报告写缺什么 |
| 没人回消息 | 不停止;能做的做完 |

## 7. 示例

周五定时,`mode: weekly`。查到 `.bw/PROJECT.md` 和 `.bw/standard.toml` 还在,删掉并开 MR。指标是 schema 2、读数新鲜。建议栏写「无」。评论挂上盘点报告。

## 8. 纪律表

| | |
|---|---|
| 必须 | 能做先做;白名单外不动手 |
| 禁止 | 等回复卡住;把疑似死码直接删;盘点里重写 metrics |
| 你不做的事 | 合入 MR;把建议活建成正式卡(等人勾) |
