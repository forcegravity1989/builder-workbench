# asset-audit：资产盘点

## 1. 核心目标

周五没人在场时盘资产、盘项目,再收口当周进展。产出是评论(② 自己一份报告,① 上一条每周进展);`.bw/` 有真改动才开 MR。能做先做,不等回复。

## 2. When to Use / When NOT to Use

- 用:workflow=`资产盘点`。已注入 `bw-assets.md`、`build.md`、`week-plan-comment.md`。
- 不用:运作活①、业务活、项目约定。不重写名片意图、不重定北极星。
- `mode: first` 本轮不跑(不打标签、不写 `AGENTS.md`、不叫 project-handbook)。评论写一句「说明里是首次模式,已按每周流程处理」。没有 `mode:` 或写了 `weekly` 走下面。

## 3. 前置依赖检查

- 已注入的 `bw-assets.md`:该有 / 整份可删 / 现行格式。清单在那里,不抄进本篇。
- 升指标格式时再读同目录 `metrics.md`。改仓规矩读 `build.md`。
- 本周这个项目发生了什么现算,不要靠记忆。

## 4. 标准执行流程

**第 1 步 · 盘 Workbench 给项目的 `.bw/`**  
走到清资产。对照已注入的 `bw-assets.md` 做三件事:清残留、升格式、点未闭环的环。清单和格式在那份里,不抄到这里。在常驻树 `bw/ops-audit` 做。不改名片意图、不重定北极星。脚本对不上协议:能改到能跑就改;会动口径的停手写进报告,等人走①。不要在这张盘点树里找 `readings.jsonl`(那份在账本树,这里没有不是错)。人才能合的只写评论,不 merge、不替人点完成。

**第 2 步 · 盘项目本身**  
走到审查。过一遍本周默认分支上的提交、以及还开着的业务 MR。建议只写进这张运作活②的评论,不改业务代码,不为审查另开 MR。找真风险、真回归、真缺口。没有就写「无」。需要动业务逻辑或公开接口的,只写建议。

**第 3 步 · 收口当周进展**  
走到收口。追加一条每周进展,格式听已注入的 `week-plan-comment.md`(挂在本周在研版本那张运作活①上)。写这一周这个版本实际走到哪;没发生就写没发生。不要改周初那条三标题评论。找不到①就按 reference 写在这张②上并说一句。

**第 4 步 · 报告**  
走到交付。这张②自己的评论三个标题,缺了就写「无」:

```
## Workbench 资产
## 闭环
## 项目审查
```

删了哪些旧件、升了哪份格式、哪条环还开着、建议哪几条,点名写。不要把每周进展抄进这一条顶替第 3 步。

**第 5 步 · 提交**  
`.bw/`(或白名单删除)有真实改动:提交 + 开 MR,地址打屏。只写出评论、仓里没改 → 不要空提交、空 MR。第 3 步和第 4 步的评论仍然要挂。

## 5. 参考资源

- `bw-assets.md`(已注入):现行 `.bw` 清单。写第 1 步前读。
- `build.md`(已注入):改仓落点。有仓改动时读。
- `week-plan-comment.md`(已注入):第 3 步每周进展怎么写。
- `metrics.md`:只在升指标格式时读(本次提示词未必预注入,按资产目录 `system-prompt/references/metrics.md`)。
- `project-handbook`:本场不读。

## 6. error_handling

| 现象 | 处理 |
|---|---|
| 正文是 `mode: first` | 按下面流程走,评论写明 |
| 没有 codegraph / 读不到提交 | 那一段写「没查到」,不编 |
| 没人回消息 | 不停止;能做的做完 |
| 仓里没改 | 不空提交;评论照挂 |

## 7. 示例

Orca 周五 15:00。对照 `bw-assets.md` 删掉 `.bw/PROJECT.md`,补上 `.bw/.gitignore` 的 `worktrees/`。在研 `v0.3` 的运作活①上追加 `## 每周进展 2026-W36`。本周提交没有真风险,项目审查写「无」。② 自己挂三标题评论,开一份只含这两处 `.bw` 改动的 MR。
