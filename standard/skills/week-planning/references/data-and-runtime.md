# 材料与运行能力

> 给计划/验收会话在实际读写、恢复或旧数据处理时读。本文只说明工具能力核对与迁移边界，目标流程在 Skill，业务协议在 [版本材料](../../../system-prompt/references/version-records.md)。运行接口变化时替换对应说明。

## 使用宿主提供的入口

核对项目根、工作区、版本、流程和实际工具路径。已有文件先读修订再改，不依靠宿主 cwd 推断项目。右板编辑会自动保存，“更新代码”先把本屏工作树快进到主干最新、再重读材料（快进不了保持原样并提示交会话处理，材料仍照常重读）；模型写入前仍须重新读取 revision，不能假定刚才看到的值未变。模型与右侧编辑器必须调用同一材料服务，以 expectedRevision 保存；冲突保留双方输入，不能用直接写文件绕开校验。

结构使用 `orca bw materials schema --workflow plan|acceptance --json` 读取；列举、读取与保存的参数分别查看 `orca bw materials list --help`、`orca bw materials read --help`、`orca bw materials save --help`，修订约束以版本材料 reference 为准。宿主未提供入口时，报告缺失、可以讨论并保留草稿建议，但不能编造命令或宣称已保存。自动化只创建/恢复 Orca 运行，不代替用户认可。

## 进展的验收来源

版本进展取自用户明确的已归档验收材料（同版上周或上一版），引用结构见[版本材料](../../../system-prompt/references/version-records.md)。先读取计划已保存的 `summary.progressSource`；没有来源时，在会话中与用户核对待接续记录并把其固定引用写入 `progressSource`，或请用户明确可独立核对的固定来源。版本名大小、提交日期和列表第一项都不能代替这个决定。无来源时不制造成绩，也不清空用户已有进展。计划屏上版回顾的「打开验收屏」入口定位到同一固定来源的只读验收整页，不再弹窗选源；改源由模型在会话中经材料 save 写入 `progressSource`。

从所选固定提交读取验收 JSON，并沿其 planRef 核对当时的计划，不能拿当前验收树或最新计划替代。计划屏上版回顾按固定材料回显延期遗留 / 会议遗留两行（编号 + 标题 / 编号 + 描述，缺项如实显示未记录，不解析 note 自由文本、不按 open 状态推断）；总览计划列直接读取材料存储的 `minutes` 节呈现两块纪要；读取失败如实提示，不回退最新材料。宿主 CLI 当前只提供材料 list/read/save 等入口，不存在 `orca bw history`，不能编造历史命令；会话可用项目已有 Git 能力核对固定提交，但无法核验归档时应明确待核。

整理进展时保留所述版本及依据，复述真实结果、未达项与后续，不把旧人工读数当本期实测。已有编辑先与人核对，按既有授权合并内容，不自动覆盖；用刚读取的 expectedRevision 经材料 save 同时保存 `summary.progress` 与对应 `summary.progressSource`。

## 补写阶段状态（存量材料升级）

本机制之前的计划/验收材料没有 `workflow` 节，验收屏旅程灯会全灰（误显示“尚未开始/尚未进入归档”；计划屏自 G3 起不渲染灯，stage 只供会话校准）。进入计划或验收会话、或恢复会话时，若发现材料缺 `workflow.stage`，按实际进度补写并经材料 save 保存，验收屏右板灯会在下一次轮询点亮：

- 已完成、能追溯归档 PR 的历史版本：写 `stage=archive`；能从 Git 或 provider 诚实定位到那一条归档 PR 时一并写 `archivePr`（provider/repository/number），定位不到就不写，宁缺毋造。
- 进行中的版本：写到实际到达的阶段（计划 preparation/goals/review/breakdown；验收 preparation/showcase），不虚标。
- 判断不了实际进度时问用户，不猜。

这样存量版本的验收灯恢复真实，不必逐文件手工修（计划屏无灯，不受影响）；本仓自身的 v0.4–v0.6 材料已随本机制一次性补齐。

## 显式迁移旧材料

计划屏打不开旧格式时，先用一句话说明：把旧字段收成新计划，对不上的目标问人，确认后再写。不要先讲备份方案。点击「新建计划／验收」只表示开始这次处理，不是同意改文件。

用材料工具的 migration-preview 看会变成哪些目标和任务。预览不写文件。目标对得上就 migrate。对不上的结果或交付物问用户，不猜测归到哪条目标。旧指标写进说明并标为待核，不写成新的指标目标。旧确认不升级成新的认可或采集证据。

写入后若同目录留下 `schema2-` 开头的旧副本，删掉，只留新的 data.json。冲突就停，重读后再问，不重试覆盖。

多版本先转当前要打开的计划。旧结果只在用户明确要归入上一版、且目标和标题对得上时，才写入那一版的验收草稿。缺计划、版本含糊或对应冲突时不伪造引用，也不把旧结果写进这份新计划。

Skill 安装目录是工具与模板来源，项目 .bw 是业务材料；不在项目里复制日常 HTML 编辑器，不另起浏览器服务。普通项目缺产品资产时由宿主补分发，不能要求用户克隆 BW 源码。
