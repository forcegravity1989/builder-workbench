# 材料与运行能力

> 给计划/验收会话在实际读写、恢复或旧数据处理时读。本文只说明工具能力核对与迁移边界，目标流程在 Skill，业务协议在 [版本材料](../../../system-prompt/references/version-records.md)。运行接口变化时替换对应说明。

## 使用宿主提供的入口

核对项目根、工作区、版本、流程和实际工具路径。已有文件先读修订再改，不依靠宿主 cwd 推断项目。模型与右侧编辑器必须调用同一材料服务，以 expectedRevision 保存；冲突保留双方输入，不能用直接写文件绕开校验。

结构使用 `orca bw materials schema --workflow plan|acceptance --json` 读取；列举、读取与保存的参数分别查看 `orca bw materials list --help`、`orca bw materials read --help`、`orca bw materials save --help`，修订约束以版本材料 reference 为准。宿主未提供入口时，报告缺失、可以讨论并保留草稿建议，但不能编造命令或宣称已保存。自动化只创建/恢复 Orca 运行，不代替用户认可。

## 进展的验收来源

版本进展取自用户明确的上版验收材料，引用结构见[版本材料](../../../system-prompt/references/version-records.md)。先读取计划已保存的 `summary.progressSource`；没有来源时，可请用户在进展卡片的“上版验收”中选择已核验归档记录，或在会话明确可独立核对的固定来源。版本名大小、提交日期和列表第一项都不能代替这个决定。无来源时不制造成绩，也不清空用户已有进展。

从所选固定提交读取验收 JSON，并沿其 planRef 核对当时的计划，不能拿当前验收树或最新计划替代。页面提供由固定材料派生的只读纪要及原始验收 JSON；没有独立历史 Markdown 原文接口。宿主 CLI 当前只提供材料 list/read/save 等入口，不存在 `orca bw history`，不能编造历史命令；会话可用项目已有 Git 能力核对固定提交，但无法核验归档时应明确待核。

整理进展时保留所述版本及依据，复述真实结果、未达项与后续，不把旧人工读数当本期实测。已有编辑先与人核对，按既有授权合并内容，不自动覆盖；用刚读取的 expectedRevision 经材料 save 同时保存 `summary.progress` 与对应 `summary.progressSource`。界面明确选择来源只改变引用，不替模型重写进展。

## 显式迁移旧材料

协作卡片“新建计划／验收”在有旧格式或损坏材料时，会把当前选版、具体文件与读取问题作为一次性上下文随本次手动运行带入会话并自动递交；这仅授权开始讨论，不代表同意改写或迁移文件。先核对请求列出的版本、实际文件与读取错误，区分旧格式和损坏数据，向用户简要说明改动、原件备份及风险，得到明确确认后再写入。

候选显示需迁移时，使用宿主明确的计划工作树、版本与 cycleId 调用 `orca bw materials migration-preview`。预览不写文件；展示旧目标、待核来源与 warnings，再根据人的明确迁移指令调用 `migrate --expected-revision <预览的 sourceRevision>`。旧文件在同版本目录以 `schema2-<原字节哈希>.json` 完整保留，之后仍可用 `migration-preview --source-revision <原修订>` 读回。冲突停止，不重试覆盖。

多版本先按依赖顺序迁移计划，再导入所属版本的旧结果；例如 v0.4 results 属于 v0.3、v0.5 results 属于 v0.4，应先准备 v0.3、v0.4 的真实计划。迁移后的指标目标为空是预期，不自动把旧人工指标绑定新定义。

旧 results 只归入其 previous_version。先在验收流程选定并核对该版本的真实 planRef，再展示旧目标与现有 goalId 的对应；得到明确对应后通过普通验收 save 写无认可草稿。缺少真实计划、版本含糊或对应冲突时保留原件待核，不伪造 planRef。旧状态与手填读数只能写入带来源的说明，不能升级为采集证据。

旧 results 属于其明确指出的上版，不按当前目录名猜；旧确认保留历史身份，不自动升级为新计划或验收确认。迁移保持原件/提交来源，错误时停止该对象写入，不替换成空数据。

Skill 安装目录是工具与模板来源，项目 .bw 是业务材料；不在项目里复制日常 HTML 编辑器，不另起浏览器服务。普通项目缺产品资产时由宿主补分发，不能要求用户克隆 BW 源码。
