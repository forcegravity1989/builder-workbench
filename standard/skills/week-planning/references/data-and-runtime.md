# 材料与运行能力

> 给计划/验收会话在实际读写或恢复时读。本文只说明工具能力核对与读写边界，目标流程在 Skill，业务协议在 [版本材料](../../../system-prompt/references/version-records.md)。运行接口变化时替换对应说明。

## 使用宿主提供的入口

核对项目根、工作区、版本、流程和实际工具路径。已有文件先读修订再改，不依靠宿主 cwd 推断项目。右板编辑会自动保存，“更新代码”先把本屏工作树快进到主干最新、再重读材料（快进不了保持原样并提示交会话处理，材料仍照常重读）；模型写入前仍须重新读取 revision，不能假定刚才看到的值未变。模型与右侧编辑器必须调用同一材料服务，以 expectedRevision 保存；冲突保留双方输入，不能用直接写文件绕开校验。

结构使用 `ORCA bw materials schema --workflow plan|acceptance --json` 读取；子命令清单与参数以 `ORCA bw materials --help` 为准（context/select/list/read/save/schema 等），修订约束以版本材料 reference 为准。宿主未提供入口时，报告缺失、可以讨论并保留草稿建议，但不能编造命令或宣称已保存。自动化只创建/恢复 Orca 运行，不代替用户认可。Skill 安装目录是工具与模板来源，项目 .bw 是业务材料；不在项目里复制日常 HTML 编辑器，不另起浏览器服务。普通项目缺产品资产时由宿主补分发，不能要求用户克隆 BW 源码。

## 进展的验收来源

版本进展取自用户明确的已归档验收材料（同版上周或上一版），引用结构见[版本材料](../../../system-prompt/references/version-records.md)。先读取计划已保存的 `summary.progressSource`；没有来源时，在会话中与用户核对待接续的版本并把该版本号写入 `progressSource`（只写 version，不写提交或修订）。版本名大小、提交日期和列表第一项都不能代替这个决定。无来源时不制造成绩，也不清空用户已有进展。计划屏计划准备区的「打开验收屏」入口现行为切到验收屏查看该版本当前材料（钉住具体记录的只读整页属产品待决能力，现行不保证），不再弹窗选源；改源由模型在会话中经材料 save 写入 `progressSource`。

读取该版本已合入主分支的验收 JSON（板面按同一份推导回显），并沿其 planRef 核对当时的计划，不能拿验收工作区草稿、别的版本或最新验收树替代。计划屏计划准备区按该记录回显延期遗留 / 会议遗留两行（编号 + 标题 / 编号 + 描述，缺项如实显示未记录，不解析 note 自由文本、不按 open 状态推断）；总览计划列直接读取材料存储的 `minutes` 节呈现两块纪要；读取失败如实提示，不回退最新材料。材料入口以 `ORCA bw materials --help` 为准；不存在 `bw history`，不能编造历史命令；会话可用项目已有 Git 能力核对材料提交，但无法核验归档时应明确待核。

整理进展时保留所述版本及依据，复述真实结果、未达项与后续，不把旧人工读数当本期实测。已有编辑先与人核对，按既有授权合并内容，不自动覆盖；用刚读取的 expectedRevision 经材料 save 同时保存 `summary.progress` 与对应 `summary.progressSource`。

## 补写阶段状态（存量材料升级）

旧材料可能缺 `workflow` 节，会话恢复校准与自动化因此读不到进度（界面不渲染阶段灯；stage 只供校准与自动化读取）。进入计划或验收会话、或恢复会话时，若发现材料缺 `workflow.stage`，按实际进度补写并经材料 save 保存：

- 已完成、能追溯归档 PR 的历史版本：写 `stage=archive`；能从 Git 或 provider 诚实定位到那一条归档 PR 时一并写 `archivePr`（provider/repository/number），定位不到就不写，宁缺毋造。
- 进行中的版本：写到实际到达的阶段（计划 preparation/goals/review/breakdown；验收 preparation/showcase），不虚标。
- 判断不了实际进度时问用户，不猜。

补写让存量材料的会话校准与自动化读取恢复真实，不必逐文件手工修。
