# week-planning：更新指标 + 制定版本计划

## 1. 核心目标

带人走完一场:复盘 → 更新指标 → 确认版本与纳入 → 人点头后落盘。产出是 `.bw/metrics.toml`(若有改)、采集脚本、这张活的一条评论、纳入标签。不替人定口径、版本目标和纳入清单。

## 2. When to Use / When NOT to Use

- 用:这张活就是运作活①,系统提示词已注入 `metrics.md`、`week-plan-comment.md` 和文末版本块(上一发 / 未发 / 推荐下一号)。
- 不用:业务活、资产盘点、项目约定。本篇不是指标格式说明书。

同标题活已在(人在计划屏又开了一张)→ 先读已有评论,原地补,不推倒重来。

## 3. 前置依赖检查

- 仓根 `AGENTS.md`:没有就说没有,不编。
- 名片 `.bw/project.toml`(`brief` / `benchmark` / `opportunity`):空着就问人,不当指标正本。
- 文末版本块:没有就只问人要哪个版本名,不猜。推荐 `vX.X`,人要用别的也行。
- 子技能:刚读的本 `SKILL.md` 所在目录的同级 `../metrics-refresh/SKILL.md`(Workbench 资产目录,不是这张活的工作区)
- 挂评脚本:本文件所在目录的 `check-week-comment.py`(不是工作区根,也不是 reference 目录)

## 4. 标准执行流程

**第 1 步 · 复盘(只读)**  
走到复盘。读上一张运作活①评论和 codehub Release。没有就说「首次,无历史」。不要用 git log 编上周计划。对人讲完再进第 2 步。

**第 2 步 · 更新指标**  
走到指标。打开并执行本文件所在目录的同级 `../metrics-refresh/SKILL.md`(资产目录,不是工作区)。人没点头指标口径之前,不进第 3 步,不写仓。

**第 3 步 · 确认版本、纳入、版本目标**  
走到计划。一次问一件,等答再问下一件:

1. 本周版本:把文末上一发 / 未发 / 推荐摊开,等人点一个版本名(可 Other)。
2. 列出远端开着的 issue(标题 / 状态 / 有没有 `bw:plan:`)。问哪些纳入、哪些留待办。不要跳过清单直接拆新卡。
3. 还要新拆哪些(标题够用就行)。
4. 版本目标:人说的话你记。给 1–2 个候选并鼓励 Other。人没说「确认」不进第 4 步。

**第 4 步 · 人确认后才落**  
走到落盘。

- 仓文件:第 2 步改过的 `.bw/metrics.toml` 和 `.bw/scripts/`。`git diff` 只许这些路径。
- 评论、标签、标题、里程碑:照已注入的 `week-plan-comment.md`。脚本用本文件同级的 `check-week-comment.py`,非零不贴。
- 提交 + 开 MR,地址打屏。没仓文件改动就不要空提交。

## 5. 参考资源

- `week-plan-comment.md`(已注入):评论标题、标签、里程碑。写评论前读。
- `metrics.md`(已注入):指标文件怎么写。第 2 步读。
- 本文件同级 `../metrics-refresh/SKILL.md`:第 2 步的 SOP。

## 6. error_handling

| 现象 | 处理 |
|---|---|
| 没有上一张运作活① | 第 1 步如实说首次,继续 |
| 指标文件旧格式 / 解析失败 | 按 metrics-refresh 第 4 节分叉,不猜字段 |
| `check-week-comment.py` 非零 | 按 stderr 改评论,过了再贴 |
| 找不到校验脚本或 metrics-refresh | 都在本 SKILL.md 所在资产目录,不要在工作区根找 |
| 人只说「看起来不错」 | 再问一句要不要确认,不当点头 |

## 7. 示例

人点「开始本版本」,文末推荐 `v0.3`。第 1 步无历史。第 2 步仓里没有 `metrics.toml`,问人要不要先空着北极星、只定一条能采的引领;人点头后才写文件。第 3 步人确认 `v0.3`,纳入 #12、新拆一张构建。第 4 步评论过脚本、给本张活和 #12 打标、开 MR。

## 8. 纪律表

| | |
|---|---|
| 必须 | 每步报走到哪;一次问一件;人确认才落 |
| 禁止 | 代写版本目标;跳过已有 issue 清单;新写 `bw:week` |
| 你不做的事 | 定北极星该量什么;合入 MR;把这张活标成完成 |
