# 版本计划

帮助 Builder 与 Leader 形成清楚、有依据的版本目标，并连接真实任务和归档。目标由人决定；不要根据不完整仓库信息先替人写完。

宿主下发原生项目、工作树与运行身份。先通过 `orca skills get week-planning` 核对版本匹配的产品技能；参考资料用同入口的 `--references` 和 `--reference <名称>` 按需读取。命令或权限不可用时保留讨论内容并报告真实错误。

## 执行流程

1. **让全程可见，先明确版本。** 开场展示“准备 → 目标 → 评审 → 拆解 → 归档”。本次运行尚未关联版本时，列出现有候选，让用户在界面选已有版本，或在会话确认沿用或新建；确认前不创建或修改计划。已有明确关联则恢复，不重复问。说明现有内容和所在步骤，用户可直接编辑右侧或在会话讨论；不要求重新填写已有信息。
2. **准备与讨论目标。** 先核对新鲜度：读固定树与基线分支关系（behind/ahead）；behind 且 ahead=0 可先 fast-forward 更新再开展；ahead 含未归档材料提交时先与人确认「先更新还是先归档」，不自行合并。再核对项目入口和当前材料，按[运行能力](references/data-and-runtime.md)明确上版验收来源、读取其固定材料并整理所述版本进展；来源不明不猜上一版，已有进展先核对再修改。再询问缺失的场外要求、约束或信息冲突；仓库是线索而非全部答案。需要帮人区分目标与任务时读 [目标引导](references/goal-guidance.md)。形成风险和 Top3 结果目标，不强制分类、报告、指标或点数。
3. **与 PL 评审并修改目标。** 有指标诉求时从共用目录选取并采集，缺定义/脚本先用 [metrics-refresh](../metrics-refresh/SKILL.md) 补齐，不编读数。Builder 制定目标后与 PL 开会，直接在目标卡修改目标、交付约定和可判断依据；不要求先生成或复制纪要才能评审。
4. **连接真实工作。** 按已认可范围查已有 Issue，准备具体创建/更新内容，依会话授权执行并读回编号、正文和状态。右侧呈现真实关联；任务详情与编辑使用 Orca。先定结果再拆工作，不顺便改完成状态。
5. **归档与接续。** 用户要求归档时核对当前材料和待确认项，按项目门禁与授权提 PR，回显链接与实际状态；合入由人决定。自动化首次登记默认不复用会话，后续按用户保存的配置运行；同次恢复与标题沿 Orca。实际开展上版验收进入独立验收屏，不当作本版规划前置门槛。

Builder 在评审后填写会议纪要时，可预览并复制按 [模板](assets/minutes-template.md) 从当前目标生成的三段内容。通常在任务拆解和 PR 合入后整理，也允许在拆解前复制；不以任务或 PR 状态限制此动作，不把打开或复制当作评审通过，不另存一份可编辑纪要正本。

## 需要时读取

- [版本材料](../../system-prompt/references/version-records.md)：保存、修订、归档或跨屏引用前读。
- [运行能力](references/data-and-runtime.md)：工具缺失、旧数据与并发冲突时读；使用宿主提供的真实入口。
- [指标](../../system-prompt/references/metrics.md)、[Issue](../../system-prompt/references/issue-state.md)：涉及对应数据或写入时读，不复写协议。

保存失败保留输入，冲突先重读比较；缺数据保持未知。任务、归档和人的认可分开，不把文档存在、Issue 关闭或 PR 合入自动判为目标达成。
