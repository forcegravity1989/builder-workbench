# 项目周报

把项目本期的变化提炼成可阅读、可留存的周报：目标推进到哪、交付了什么、有什么风险、哪些工作仍需推进。采用自动取数和渲染、人工兜底；已有周五材料是输入之一，周报正文呈现项目结论。

宿主提供项目、工作区、周期、时区、唯一报告路径和输出结构。已有输入直接沿用。先简短说明“核对事实 → 提炼变化 → 保存周报”，随后执行；只在身份或周期缺失且无法核实时请求选项，不让人逐栏重填。

## 执行流程

1. **核对范围与已有内容。** 读当前项目 AGENTS，核对宿主项目和工作区。按 [保存协议](references/report-storage.md) 读取当前周期的已有报告与生效人工内容；读真实项目约定、计划和验收。明确取数截至时刻，区分报告周期与软件版本。
2. **获取实际进展。** 用已配置的 GitHub/CodeHub 工具完整分页读取 Issue、期间事件、关闭原因、PR/MR 合入记录；命令和字段查本机帮助。目标关联按计划 tasks，验收读人的记录，指标按 [指标协议](../../system-prompt/references/metrics.md) 核对实际读数与窗口；已有周五材料和会话结论须有项目证据支撑。取数缺口只影响对应事实，仍继续完成有依据的部分。
3. **提炼并核对七栏。** 读 [提炼方法](references/report-writing.md)，按宿主给定列填入纯文本。先形成目标、关键进展与风险，再挑能解释这些结论的需求和问题明细；摘要、明细、数字和人工修正前后一致。来源及统计窗口保存在内部 sources，正文只呈现业务内容。
4. **保存并读回。** 依据保存协议再次读取人工内容，生成一个新报告，严格检查宿主输出结构后发布并独立读回。已有报告保持原样。读回成功才回显保存位置与真实缺口；模型启动或提示递交均不算周报已生成。

本 Skill 只生成本地周报。提交、推送、创建 PR/MR、发送或发布需另有明确授权；本流程不关闭 Issue、合入 PR/MR 或代签目标验收。工具不可用或保存未确认时保留原报告和人工内容，说明实际错误与可继续的动作。
