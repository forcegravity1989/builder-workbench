# 周报提炼方法

给执行周报 Skill 的 Agent 读取。本文只管事实选择、七栏提炼及一致性判断；列名和输出结构使用宿主契约，文件发布使用保存协议。提炼方法变化时更新。

## 核对来源与本期变化

按项目 AGENTS 定位实际计划、验收和项目材料；核对当前有效版本、所属分支及材料日期，未合入材料与已归档基线分别处理。已有周五材料、会话、邮件或消息仅在可访问且与项目有关时纳入；其中的完成或效果表述仍须由对应工作项、验收或实际读数支撑。不以个人参与、作者或互动次数筛掉项目的重要变化。

工作项标题不足以解释变化时，补读 Issue、PR/MR 的背景、描述、验收条件和验证结果。提交消息中的编号仅作检索线索，核实仓库与工作关联后采用；它不能替代计划中的目标关联。按需检查已合入 PR/MR 或明确提交范围的 diff，说明改动对象、行为和已有验证；区分已合入、未合入及本地未提交内容，不能由 diff 推定上线、稳定性或目标达成。

Git 补充取证覆盖默认分支和与本期工作有关的未合入分支。同一仓库按完整 commit SHA 去重，保留分支与 PR/MR 关系；跨仓库保留各自归属。Git 按明确采用的提交时间筛选，不能用提交时间代替合入时间。注明实际读取的 refs 和取数截至时刻；本地缓存未核对远端时，不宣称覆盖最新远端变化。完整读取对应范围；条数限制、分页失败或分支不可读须标明缺口。

新增按创建事件、合入按合入事件、关闭和重开按状态事件入期，不能只取本期创建的工作项再按当前状态统计。使用宿主时区，窗口起点包含、终点不包含；取数提前截止时只支持截至该时刻的结论。旧工作本期变化仍纳入；当前快照不能反推缺失的期间事件或期末存量。

资料较多时，先按来源提取事项、本期变化和遗留工作，再按已核实的事项关联汇总。同一工作的 Issue、PR/MR、提交与验证记录支持一条变化，保留全部支持依据，结果不重复计数；不同 SHA 也不足以证明不同交付。区分本项目待推进事项与依赖他人的事项，沿用明确记录的承担者和日期；未知责任或日期不生成新承诺。

## 从变化得到结论

每条主要结论能回答：本期发生了什么变化、对目标或交付有什么影响、当前还有什么未完成。按工作方向合并事项，用读者能理解的结果表述；优先保留能解释目标推进、关键交付或阻塞的变化，重复细节压缩。取证完整性与正文选材分别核对，不为固定条数删掉影响结论的风险或遗留工作。

量化结果说明对象、范围和实际变化；commit、PR/MR、检视和测试数量只是活动证据，不能推算投入占比、生产率、业务价值或质量提升。已有验证只能支持它覆盖的结果；没有相应证据时，不写“保障稳定”“提升质量”等效果结论。

目标来自项目实际计划；关联采用计划 data.json.tasks 中的 provider/repository/number/goalId，标签或标题不足以补出目标。实际验收材料支持“目标达成”，PR/MR 合入支持“已合入”，Issue 原生状态支持“已关闭”，分别写清。not_planned 写“不再计划”，不计入完成关闭。验收缺失时呈现待验收或未知。

历史峰值、当前验收窗口和纳入项目数量分别陈述；数字须有完整分页、可证明事件与相同统计窗口。sources 留明实际证据范围；缺证据写未知，未知与零分别处理。

## 七栏取舍

| 栏目                 | 选取与提炼                                                                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目标                 | 只列真实目标、交付要求、约定日期和当前推进／验收结果。不要从完成任务反造目标。                                                                                |
| 关键进展             | 按方向合并本期关键变化，讲清结果与影响。下周计划来自真实安排；未明确写未知。                                                                                  |
| 关键风险             | 从阻塞、交付偏差或已确认风险提炼影响和现有应对。等级、责任人与关闭日期沿真实约定；信息缺失写未知，不写“无风险”。                                              |
| 里程碑               | 只列已定义节点、达成条件和实际情况。没有定义时保留栏目并输出空数组。                                                                                          |
| 子目标／需求详细进展 | 选能解释目标推进、关键变化或风险的任务，保留真实引用、状态和本期变化。没有关联目标或计划日期时标未知；不搬全量 Issue 清单。                                   |
| 问题单进展           | 依项目既有标题／标签／协议分类问题；Bug、未分类反馈和需求分清口径。新增、完成关闭、不再计划、未关闭分别统计；重开等事件说明统计口径，无法证明期末量时写未知。 |
| 项目成员             | 采用项目名册、职责约定和任务实际指派。未分配写未分配；PR 作者、提交作者不能自动成为责任人。单人项目不编团队角色。                                             |

## 核对

同一事实的摘要、明细和统计一致；人工明确纠正的旧结论不在其他栏复活。支持风险应对或下周计划的资料缺失时留未知，由人补充。七栏和固定列保持，所有表格值为纯文本。页面和 HTML 由宿主共用固定模板渲染，Agent 交付报告数据，不另起 HTML 服务或改变配色。

sources 保留事实来源 URL／仓内路径、支持的结论、统计窗口及取数截至时刻，用于独立核对；取数说明、来源清单和人工标记不作为正文附录。
