# 周报提炼方法

给执行周报 Skill 的 Agent 读取。本文只管事实选择、七栏提炼及一致性判断；列名和输出结构使用宿主契约，文件发布使用保存协议。提炼方法变化时更新。

## 从变化得到结论

每条主要结论能回答：本期发生了什么变化、对目标或交付有什么影响、当前还有什么未完成。按工作方向合并相关 Issue、PR/MR 和验证记录，用读者能理解的结果表述。代码提交、会话过程、测试条数和操作流水不直接冒充交付结果；有交付意义才写入。

目标来自项目实际计划；关联采用计划 data.json.tasks 中的 provider/repository/number/goalId，标签或标题不足以补出目标。实际验收材料支持“目标达成”，PR/MR 合入支持“已合入”，Issue 原生状态支持“已关闭”，分别写清。not_planned 写“不再计划”，不计入完成关闭。验收缺失时呈现待验收或未知。

计划/验收固定树中的未合入材料与已归档基线区别核对，采用当下有效资料并在 sources 留明范围。历史峰值、当前验收窗口和纳入项目数量分别陈述；当前快照只支持截至取数时刻的状态。数字须有完整分页、可证明事件与相同统计窗口；缺证据写未知，未知与零分别处理。

## 七栏取舍

| 栏目                 | 选取与提炼                                                                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目标                 | 只列真实目标、交付要求、约定日期和当前推进／验收结果。不要从完成任务反造目标。                                                                                |
| 关键进展             | 按方向合并本期关键变化，讲清结果与影响。下周计划来自真实安排；未明确写未知。                                                                                  |
| 关键风险             | 从阻塞、交付偏差或已确认风险提炼影响和现有应对。等级、责任人与关闭日期沿真实约定；信息缺失写未知，不写“无风险”。                                              |
| 里程碑               | 只列已定义节点、达成条件和实际情况。没有定义时保留栏目并输出空数组。                                                                                          |
| 子目标／需求详细进展 | 选能解释目标推进、关键变化或风险的任务，保留真实引用、状态和本期变化。没有关联目标或计划日期时标未知；不搬全量 Issue 清单。                                   |
| 问题单进展           | 依项目既有标题／标签／协议分类问题；Bug、未分类反馈和需求分清口径。新增、完成关闭、不再计划、未关闭分别统计；重开等事件说明统计口径，无法证明期末量时写未知。 |
| 项目成员             | 采用项目名册、职责约定和任务实际指派。未分配写未分配；PR 作者、提交作者不能自动成为责任人。单人项目不编团队角色。                                             |

## 核对

同一事实的摘要、明细和统计一致；人工明确纠正的旧结论不在其他栏复活。支持风险应对或下周计划的资料缺失时留未知，由人补充。七栏和固定列保持，所有表格值为纯文本。页面和 HTML 由宿主共用固定模板渲染，Agent 交付报告数据，不另起 HTML 服务或改变配色。

sources 保留事实来源 URL／仓内路径、支持的结论、统计窗口及取数截至时刻，用于独立核对；取数说明、来源清单和人工标记不作为正文附录。
