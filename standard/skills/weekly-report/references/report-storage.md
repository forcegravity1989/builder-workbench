# 周报读取与发布协议

给执行周报 Skill 的 Agent 读取。只说明不可变报告与人工内容的读取、输出检查、发布及失败边界；字段和固定列由宿主输出结构提供，不复制项目当周内容。文件协议变化时同步读取方。

## 读取人工内容

在当前周报工作树读取 `.bw/weekly-reports/<周期开始日期>/` 全部已发布 UUID.json，忽略 `.pending`。只使用结构有效、项目及周期与当前上下文一致的记录；损坏或不可读记录如实报告，不把失败当作没有人工输入。按 generatedAt、稳定文件路径升序排序：最新记录提供既有内容，最近 origin=manual 的记录提供生效 manual，包括显式空对象。没有人工版本时采用最新记录的 manual。

逐字保留生效 manual：每栏 `{text, mode}`，mode 为 append 或 correct。append 补充正文，correct 修正该栏内容；人工版本的空对象是显式清除，不恢复更早补充。后继 conversation 即使遗漏或携带旧 manual，也沿用最近人工版本。旧文件始终保持原文。

## 输出与检查

使用宿主指定的唯一 `.bw/weekly-reports/<开始日期>/<UUID>.json` 路径，origin=conversation，schemaVersion=1；project 和 period 使用宿主真实值，version 取实际关联版本，未明确时 null，generatedAt 为实际生成的带时区 ISO 时间。七栏字段必须完整，每行列数与宿主固定列一致；空栏目用 []，缺失事实用未知。所有单元格都是纯文本，每格不超过 10000 字符、每栏不超过 200 行、sources 不超过 500 条，manual.text 为 1–10000 字符。

先写非候选 `.json.pending` 文件，核对严格 JSON、身份、周期、七栏列数、来源和摘要一致性。发布前再次读取同周期全部已发布文件，重新计算生效 manual；它变化时重新合并并核对相关摘要与明细。读取失败时停止发布，保留旧报告，说明未确认内容。

新目标路径须不存在；使用宿主原生工具或当前平台支持的原子移动发布，避免覆盖同名文件。发布后从正式路径独立读回并检查内容。再次核对生效人工版本；出现并发变化时只撤回本次 UUID 并保留待核内容，说明需要重读重试。通用文件写入是乐观核对，不承诺跨进程事务锁。

## 完成与失败

完成以正式文件独立读回为准，输出位置和实际缺口即可。读取、生成或保存失败保留旧报告与人工输入；结果不确定时明确说未确认，并重新读取核对，避免盲目再次生成。清理仅限本次 UUID 的临时或正式文件，不删除他人报告。不另建索引、当前报告副本、业务数据库或定时任务；本地保存与 PR/MR 共享归档分别处理。
