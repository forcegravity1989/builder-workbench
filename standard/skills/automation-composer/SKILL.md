# 自动化作曲

把用户的一句话目标变成一个配置完整、试跑验证过的定时任务，全程在对话里闭环；启用永远留给用户。调度、运行与编辑复用 Orca 原生 Automations 与 `orca automations` CLI，不新增工具面。

## 执行流程

1. **起草并展示全文。** 把目标翻译成完整配置：提示词（任务要做什么、怎么做、产出什么）、调度、agent、precheck、工作区。先展示全文，确认后再创建；原话有歧义（时区、频率、目标分支）先问清，不猜。
2. **创建禁用状态的任务。** `orca automations create --disabled`；一次性任务 `--trigger once --at <ISO时间>`，循环任务用 `--trigger` 预设。创建后读回确认落盘。
3. **试跑。** `orca automations run <id>` 试跑一次。试跑是真实执行：会改文件、调外部服务——发起前先告知这次试跑会做什么、有什么副作用，确认后再跑。
4. **读回并迭代。** `orca automations runs --json` 读回结果，分析偏差；需要修改用 `orca automations edit` 迭代再试跑。读回失败或结果异常如实报告，不假装成功。
5. **交还启用。** 配置调好后告诉用户去自动化页自己启用；你永远不执行 `--enabled`。

## 边界与失败

- 不执行 `--enabled`：创建永远 `--disabled`，启用是用户的决定。
- 试跑前告知真实副作用：试跑不是演练，是真实执行。
- 读回失败如实报告：不编造运行结果，不把失败说成成功。
- CLI 不可用时报告真实错误并停止，不换可执行文件硬试；命令面以 `--help` 为准，不编命令。
