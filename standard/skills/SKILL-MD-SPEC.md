# Skill 写作与加载规范

> **读者与时机**：维护 Skill、references、assets、scripts、入口提示与包内投影前完整读取。**职责**：规定结构、内容分工、读取契约与验证，不定义产品行为或项目开发规则。**结构**：职责 → 写法 → 加载与分发 → 维护与验证。契约变化时更新，规范与覆盖的存量同批维护。

## 职责

| 资产                   | 写什么                                                 | 不写什么                            |
| ---------------------- | ------------------------------------------------------ | ----------------------------------- |
| 屏幕入口               | 一句用户请求、完整 Skill 的可读入口                    | SYSTEM 正文、SOP 副本、内部状态快照 |
| SKILL.md               | 用户结果、完整旅程、步骤与分支、必读触发、关键失败处理 | 低频细节、公共规范副本、实现历史    |
| 本 Skill 的 references | 某一步的方法、例子、异常处理                           | 未接入的能力承诺、第二套完整 SOP    |
| standard/references    | 跨 Skill 规则与协议唯一正本                            | BW 本仓特性分类、项目自己的开发约定 |
| assets                 | 产出模板与必要示例                                     | 临时执行记录                        |
| scripts                | 已实现的确定性操作                                     | TODO、遗留清单、让模型复制的长脚本  |

运行身份、当前版本、读数和材料状态通过原生工具读取。项目规则从其 AGENTS 及引用读取，不套用 BW 研发目录与四维评审要求。

## 写法

- SKILL.md 含 YAML `name`、`description`；目录名与 name 一致，使用小写连字符。采用通用字段 name、description、license、compatibility、metadata、allowed-tools；宿主扩展须明确声明。
- description 先写触发场景与结果，说明相邻任务边界，不塞 SOP。正文不超过 500 行、约 5000 tokens，围绕用户看得见的旅程组织。
- 开场说明全程与当前位置。已有输入直接采用，日常步骤不反复索取确认；目标、完成、合入、外部写入与发布权限沿用户指令和项目规则。
- 一节一个主题；并列规则用列表，超过约 5 条规则的段落拆分。超过 100 行的 reference 顶部提供目录。
- 路径用正斜杠，文件名说明用途。Skill 直接指向所需正文，不靠 reference 再绕多层寻找必读规范。
- 纪要、目标、报告等产出须规定内容质量：写什么、不写什么、合格判据及必要正反例。权限不能代替内容标准，缺实质内容不凑数。
- 跟随用户语言，讲对象、动作、结果，失败补原因与下一步。内部 ID、协议字段和枚举只作工具参数，旅程使用真实界面分区名。

## 加载与分发

1. 入口指向执行宿主真实可读的完整 SKILL.md。用户发送后先读全文，不把发现摘要当正文或假设模型已知道技能。
2. 开工步骤明确要求完整读取公共执行规范和项目 AGENTS。其他规范在对应动作之前明确写“完整读取”，不能只列“相关资料”。
3. 公共规范源在 `standard/references/`；构建生成完整包的 `references/shared/` 并改写相对引用。副本不手改、不承担另一份职责。
4. 模型直接读包内 references/assets；脚本真实落在 scripts。调用处说明条件、参数、输入输出和失败边界，不让模型从 Markdown 代码块重建脚本。
5. 实时事实和产品操作沿原生 CLI/API。公共执行规范说明 CLI 的选择方法；读取 Skill 文件与执行产品命令是两件事。
6. 复用 Orca 原生完整包、安装、宿主路由与冲突保护，不另做安装目录、版本记录或覆盖机制。安装失败不继续启动依赖缺失的任务，不静默覆盖用户修改。

## 维护与验证

先维护规范，再按完整主题整理存量；逐条核对有价值的反馈，不因重构删掉必要约束，也不把旧句子原样搬成另一堵规则墙。规则只在最能改变决策的一处维护，其他位置明确引用。

被替代代码、过时入口、重复规范和失效模板同批删除，引用与消费者同批切换。历史由 Git 追溯，过程和未验证项放 PR/仓外计划，不进入常驻规范。

验证格式与链接、完整包依赖、目标宿主落盘、入口草稿行为及代表任务。模型验证读 transcript，观察必读正文和用户旅程；静态检查、安装成功或模型自述不证明行为正确。复用既有案例与测试，问题修正对应正本，不为单例叠加重复禁令。
