# 产品 Skill 写作约定

> 给维护 BW 模型面资产的人和模型读。写或改 Skill 及其配套模型面资产（references、assets、发现存根、板面注入句、SYSTEM 模板）前读取。本篇管结构、预算、表达与验证，不规定产品行为；产品行为由特性规格决定。结构或加载约定变化时更新，旧文件小修只处理相关主题，整体重写遵循本篇。

**什么是好的 Skill：简洁、结构良好、经真实使用验证。**模型读完能按用户看得见的旅程带人走完 SOP，产出物过明确的质量标准，对用户说产品的人话而不是协议话。

## 最小结构

SKILL.md 必须有 YAML name、description；name 与目录名一致，使用小写连字符。frontmatter 只依赖六个跨产品规范字段（name、description、license、compatibility、metadata、allowed-tools）；宿主扩展字段视为绑定该宿主，显式声明后才用。

正文按实际任务组织：目的与边界、执行流程、必要失败处理、按需参考。无需固定八章、重复的 When NOT to Use、示例和纪律表；短任务可以更短。主文只保留会改变模型决策的信息，不堆项目历史、目录全表或重复规则。

交互式业务流程先让用户看见完整 SOP 与当前所在步骤，再围绕缺失信息交流。已有输入直接采用，不每步重新索要许可；关键目标和人的判断不由模型代定。用户明确的授权与项目约定优先，Skill 不凭自身出现扩展到外部写入、完成或发布。

## 预算与密度（硬约束）

- SKILL.md 正文不超过 500 行、约 5000 tokens；接近上限即拆入 references，并在正文写明何时读取。
- 一节只承载一个主题；并列规则用列表或 checklist，不写单段长文。单段超过约 5 条规则视为待拆分：低频回退规则（如旧格式处置）下沉 references，不挤占高频主流程。
- 参考文件超过 100 行在顶部放目录，防模型局部预读看不到全貌。
- 引用离 SKILL.md 一层深，不做三级链（正文 → 参考 → 更深参考会导致深层文件只被局部预览）；每处引用写明何时读与执行意图（「运行 X 提取字段」还是「算法见 X」）。
- 文本中的路径一律正斜杠（跨平台）；文件名自描述。

## 触发质量

description 是主要触发面：第三人称陈述做什么与何时用，最重要的触发场景写在最前，包含用户真实会说的关键词；不写「我可以帮你 / 你可以用它」句式，不写「协助处理文档」式空话，不塞 SOP。

产品派发型 Skill（随周期自动化分发、由存根引导加载）以精确边界优先于触发强度：description 同时写明不触发的场景（如「验收已有版本使用 version-acceptance」）。过度触发劫持普通会话的代价高于欠触发；只有完全依赖模型自由发现的 Skill 才需要把触发面写宽。

## 渐进披露

| 内容 | 放哪里 |
|---|---|
| 这次会话怎样带人走完、产物是什么 | SKILL.md |
| 特定任务的思考方法、目标例子、证据判断 | 本 Skill 的 references，主文说明何时读取 |
| 多 Skill 共用的字段/标签/指标/材料协议 | system-prompt/references，保留单一正本 |
| 输出用的纪要等格式 | assets；格式变化同步生成方 |
| 确定性且已实现的机械动作 | scripts 或宿主工具，说明真实输入输出 |
| 当前项目决定、运行记录、产品设计 | 项目正本/特性文件/运行产物，不抄进 Skill |
| 旧数据结构格式（意外不匹配时查找用） | 专门的查找型 reference，默认不加载，读回异常才查 |

允许必要的 references，不把冗长主文原封不动搬过去。删除失效规则前查调用方；仍在使用的脚本与模板随消费方一起退役，不靠改一份 MD 冒充运行时已切换。共用 system-prompt/references 层同样守一层深：Skill 正文直链，不在 reference 内再中转跳。

## 受众与时效纪律

模型面资产（Skill 正文、references、assets、存根、注入句、SYSTEM 模板）只写现行行为。不进模型面文本：

- 版本代号与开发迭代名（如屏内设计的轮次名、里程碑代号）；
- 日期条件规则（「X 月前用旧法」式写法必然过期）；
- 本仓源码路径、编码与校验算法等实现细节；
- 退役沿革、「曾用 X 现改 Y」叙事与修复记录。

确需保留的旧格式行为规则用「旧格式材料」描述，不带代号；历史由 docs/ 与 Git 追溯。开发者契约与模型规则不同篇；一份正本双受众就拆。模型面文本不承诺不存在的界面元素；界面行为变化时，同一交付内更新描述该界面的全部模型面文本。

## 用户面表达

- 与用户对话跟随用户语言，默认中文。模型指令本身不限语言，但发现存根与一切用户可见文本须含产品语言内容。
- 助手讲对象、动作、结果，失败补原因与下一步。协议字段名、stage 枚举值、内部 ID、守卫机制只作命令参数，不出现在给用户的文本里；需要提及内部概念时翻译成人话。
- 旅程口播用板面上用户看得见的分区名；内部阶段标识只供会话校准与自动化，不作为面向用户的步骤名。
- 注入句是用户口吻文本（发送弹窗预览原样展示）：只留人话；CLI 命令与内部文档名归 SKILL/SYSTEM 侧指针。
- 发现存根按用户可见产品文案对待：保留产品语言的最小产品上下文（旅程名与一句定位），CLI 解析样板压缩为可执行规则，趣闻级细节删除；技能服务不可用时，助手不得对旅程一无所知。
- 用户直接消费的产出物（纪要、报告、目标句），Skill 不只写流程规则（谁能写、何时冻结、谁确认），必须同时写内容质量标准：写什么、不写什么、什么算合格，并配正反例。界面已呈现的信息不复述进产出物；无实质内容如实说无，不凑数。

## 自由度匹配

指令的具体程度匹配任务的脆弱性：讨论与信息收集给高自由度——给方向不给表单；脆弱操作与一致性关键区给低自由度——精确步骤或脚本并注明「不得改动命令」。铁律级判断（完成确认、发布授权、结论标记）永远归人，Skill 写清边界，不留例外。

## 规则单点

一条规则只写在一处最能改变决策的位置，其他位置需要时以一句话引用，不复制正文。规则被反复忽视时重构该单点——前移、加示例、补一句理由（解释为什么重要，不堆无理由的全大写 ALWAYS/NEVER），不靠加副本加强。铁律级总则留在 SYSTEM 一处，Skill 与 references 只写对象特有条件。

## 写作与验证

- 按业务主题替换旧内容，不加“本轮补充”流水。已有 Skill 优先改原件，不并列新旧 SOP。
- 协议/规范只引用一次正本，流程不锁定旧 UI 页数或硬编码步骤编号；界面只呈现对象、动作和结果。
- 入口下发实际存在的工具、项目、版本和工作区，Skill 不编命令或路径。设计稿要标明未接入，不能作为已发布能力。
- 术语单一：一个概念全篇一个词，不混用同义词。祈使句优先。
- 输出质量依赖示例处给输入/输出对，示例具体不抽象；严格模板标「照用」，弹性模板标「依上下文裁剪」。
- 轻量评测：改 Skill 后在 fresh session 开/关 Skill 各跑一遍代表任务做基线对比——编写会话的残留上下文会掩盖指令缺口；读 transcript 而不只读产物，发现模型被带偏做的无效功；同一错误重复出现才加规则，从反馈泛化，不为单例过拟合。静态检查通过不代表模型行为改善。
- 来源有冲突先核对用户决定、现行规格与真实能力；不让存量资产自动否决已经认可的新流程。

写作分层见 [standard](../README.md)，注入实况见 [模块说明](../../docs/06-module/系统提示词与渐进加载.md)。其他未涉及 Skill 不因本规范重写而批量改动。
