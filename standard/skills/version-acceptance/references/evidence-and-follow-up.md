# 核对证据与未达安排

> 遇到原承诺歧义、缺材料、指标不可比或未达项时读取。只提供判断方法；人的结论写回验收材料，不在此保存项目记录。

以计划当时约定为准：新能力通常查验收点/旅程和真实报告；反馈优化查反馈处理及实测变化；具体任务查约定交付及使用结果。这些不是周五新增的必填条件。

先分清证据层：代码提交、PR 合入、测试通过、正式发布、用户完成旅程分别证明不同事情。Issue 关闭是任务事实，不能替代目标验收。指标有口径或窗口变化时先说明不可比，缺值不填 0。

逐项向人说明已知结果、具体缺口和可选处理，不先给总通过。人的结论可以基于项目实际材料与说明；记录判断者、范围和来源，模型不得代签。

未达项说明原承诺哪里没达到、原因以及下一步。可以在本版补齐、作为下版候选或明确停止；不得从原计划删除以制造达成。需要修改 Issue 时使用既有权限与状态协议，候选安排不自动改变排期。

归档保留当前承诺修订、证据和结论。后续补证形成新修订，不能无痕覆盖旧报告。报告完整和目标全部达成是两种判断。
