# 验收证据聚合

> 验收会话收到聚合请求后完整读取。本文规定证据来源、提取质量、缺口与登记；旅程在 SKILL.md，报告槽位在模板。证据口径或登记接口变化时维护。

## 读取现成证据

按本版固定计划的目标与任务引用，读取项目约定和各 Issue/PR 已留下的验证产物。有实现交付的任务核对实现 PR/MR 与验证报告；无开发直接关闭的任务核对 Issue 评论中的处理依据。不假定用户项目采用 BW 的研发 Skill 或报告文件名。

验收只聚合，不重新跑开发验证、不反推期望结果或执行路径。已有输入缺字段就标缺，由人确认或补齐。来源可以是截图、CI/流水线、逐条用例结果、修前修后对跑、平台读回或 DOM 断言；判据是人能独立核对事实，不限图片。

## 提取与归并

- 先写一行“验收说明”：这条 Issue 兑现哪条目标承诺。这是归并说明，不当作验证证据。
- 每条现成判据保留一行：用例名、期望、实际结果、证据链接、执行路径一行或原文链接；不压成一段转述。截图保留已钉住的提交 SHA 和文件名，或随报告保存为相对路径。
- 每条 Issue 各留一行门禁实数及未验范围；没跑的写未跑，不推测通过。
- 命令全文、排查过程、独立检视过程及无关改动只留来源链接，不搬入正文。
- 核对证据语义：说明它证明修复后结果还是原问题。来源或语义不明保持缺口，不用大段叙述凑证据。

## 缺口

按下面三类分别列出，由人确认或补充：

1. **已关闭但无合入件**：需要实现交付的 Issue 已关闭，却找不到合入项目实际基线分支的实现 PR/MR。先向人呈现这个结论缺口；无开发关闭项核对评论依据，不要求虚构 PR。
2. **未合入**：实现 PR/MR 仍开放或本版尚无合入件，说明实际状态与安排。
3. **无读数或不可核对**：读数、来源或证据语义不足，明确缺什么。

人已核对通过但未留实物的，记录谁、何时、核对什么，标为“人工核对通过、未留实物”；不把它改写成自动验证通过，也不要求模型代采。报告与演示环境不一致时先提醒人核对候选。

## 生成与登记

完整读取[报告模板](../assets/evidence-report-template.md)，在候选固定后生成一个版本一份的报告，放本版 `.bw/planning/<版本>/`，随带图片放 `shots/`。报告用于逐目标核对，项目若另有发布总结，两者按各自职责维护。

使用开工读回的项目、工作树和宿主身份登记，不能只落盘而不登记：

```bash
ORCA bw materials add-artifact --repo-id <id> --worktree-id <id> --host-id <host> --workflow acceptance --version <版本> --kind verification --location .bw/planning/<版本>/<报告文件名>
```

命令在工作树所属宿主完成读改存：文件必须真实存在；`mtime` 作 `generatedAt`，复用现有 `candidateRef`，同 artifactId 更新；修订冲突自动重读重试一次。候选未固定或保存失败先处理原错误，不直接改材料绕过服务。

可按实际结果提供 `--artifact-id`、`--command`、`--checksum`。完整参数见[版本材料](../../../references/version-records.md)。登记后读回制品引用，再告知用户报告位置；界面约五秒刷新，未亲见板面时不声称界面已亮。
