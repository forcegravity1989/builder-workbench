# 验收证据聚合

> 验收会话收到聚合请求后完整读取。本文规定证据来源、提取质量、无截图逐单判断、待核对、缺口与登记；旅程在 SKILL.md，报告槽位在模板。证据口径或登记接口变化时维护。

## 读取现成证据

按本版固定计划的目标与任务引用，读取项目约定和各 Issue/PR 已留下的验证产物。有实现交付的任务核对实现 PR/MR 与验证报告；无开发直接关闭的任务核对 Issue 评论中的处理依据。不假定用户项目采用 BW 的研发 Skill 或报告文件名。

验收只聚合，不重新跑开发验证、不反推期望结果或执行路径。已有输入缺字段就标缺，由人确认或补齐。来源可以是截图、CI/流水线、逐条用例结果、修前修后对跑、平台读回或 DOM 断言；判据是人能独立核对事实，不限图片。

## 提取与归并

- 每个 Issue 先写**一句人话**：这条 Issue 兑现哪条目标承诺、怎么验、看哪里，人能直接读懂；这是归并说明，不当作验证证据，也不复述下面的用例表。
- **基本用例**逐条占表格一行：用例名、期望结果、实际结果、证据形态与证据、执行路径一行或原文链接；不压成一段转述。证据写清形态（截图/日志/读数/单测/流水线/平台读回/修前修后对跑）；截图用 `<img>` 内嵌并同时给链接，钉住提交 SHA 和文件名，只有本地图片时随报告放 `shots/` 用相对路径。
- 组合、异常、负例与完整门禁细节点名原验证报告链接，不搬入正文；报告只承载人能当场核对的基本用例。
- 每条 Issue 各留一行门禁实数及未验范围；没跑的写未跑，不推测通过。
- 命令全文、排查过程、独立检视过程及无关改动只留来源链接，不搬入正文。
- 核对证据语义：说明它证明修复后结果还是原问题。来源或语义不明如实标注、不当作结论用，不用大段叙述凑证据。

## 无截图逐单判断

不能把「没有截图」一律当缺证，也不能一律放过。逐单判断：

1. **性质本就截不了图**：命令、配置、数据或接口类改动，或改动不在界面上。回到实现 PR/MR 找其他形式的验收证据——日志、读数实数、单测或流水线链接、平台读回、修前修后对跑——有就按字段化子集提取进报告，并写明证据形态。
2. **证据不足或漏截图**：PR/MR 上没有足够的验收证据、漏截图，或开发侧自述未验、缺验证。列为「待核对」：不由模型判为缺证放行，也不代补；报告生成后逐条与人核对，每条给出证据现状、PR 上现有其他形式证据（没有写「无」）和三个处置——在 PR 补充后重新聚合、在本次验收会话补充后加入报告、会上实机演示，由人定。人定之前报告保持「待核对」，不写成结论、不提前记入缺口。

## 缺口

只有人确认后的证据问题才写入缺口，未确认的留在「待核对」。按下面三类分别列出，由人确认或补充：

1. **已关闭但无合入件**：需要实现交付的 Issue 已关闭，却找不到合入项目实际基线分支的实现 PR/MR。核对时先向人呈现，人确认后落到缺口槽位；无开发关闭项核对评论依据，不要求虚构 PR。
2. **未合入**：实现 PR/MR 仍开放或本版尚无合入件，说明实际状态与安排。
3. **无读数或不可核对**：读数、来源或证据语义不足，明确缺什么。

人已核对通过但未留实物的，记录谁、何时、核对什么，标为“人工核对通过、未留实物”；不把它改写成自动验证通过，也不要求模型代采。报告与演示环境不一致时先提醒人核对候选。

## 生成与登记

完整读取[报告模板](../assets/evidence-report-template.html)，在候选固定后生成一个版本一份的报告，落盘为本版 `.bw/planning/<版本>/acceptance-evidence.html`，只有本地图片时放同目录 `shots/`。**报告是 HTML 正本，只有这一种形态**：板面按扩展名经内置浏览器打开，Markdown 源码在编辑器里只是裸文本，不产出 `.md` 版本也不留双格式口子。报告用于逐目标核对，项目若另有发布总结，两者按各自职责维护。

按以下顺序执行，不直接改材料文件：

1. 按模板生成报告并落盘为 `acceptance-evidence.html`；无截图的 Issue 按上节先逐单判断，证据不足或漏截图的列入「待核对」；缺口槽只写人已确认的结论，待定的汇总到文末「会上需要人定的事」，不替人拍板。
2. **逐条核对待核对项并回填处置**：把待核对条目编号列出，每条写明证据现状、PR 上现有其他形式证据与三个处置选项，由人逐条定。人一次回应多条时按编号分别落；只改一条时只更新该条，不重置其他已定项。按人定的处置更新报告后再登记；处置为「会上实机演示」的条目保留该决定，不因没有新增证据而删除；经 PR 或会话补充实体证据的条目移出待核对。人未回应的条目保持「待核对」，不得自行判为缺证或放过。
3. **登记前自检**：缺口槽里没有未经人确认的条目；每个「待核对」条目要么已有处置、要么仍明确标着待核对，不出现空处置或半截条目。自检是交付前复查，不新增外部校验脚本。
4. 使用开工读回的项目、工作树和宿主身份登记，不能只落盘而不登记：

   ```bash
   ORCA bw materials add-artifact --repo-id <id> --worktree-id <id> --host-id <host> --workflow acceptance --version <版本> --kind verification --location .bw/planning/<版本>/acceptance-evidence.html
   ```

   命令在工作树所属宿主完成读改存：文件必须真实存在；`mtime` 作 `generatedAt`，复用现有 `candidateRef`，同 artifactId 更新；修订冲突自动重读重试一次。候选未固定或保存失败先处理原错误，不直接改材料绕过服务。可按实际结果提供 `--artifact-id`、`--command`、`--checksum`；完整参数见[版本材料](../../../references/version-records.md)。

5. 登记后读回制品引用，再告知用户报告位置；界面约五秒刷新，未亲见板面时不声称界面已亮。
