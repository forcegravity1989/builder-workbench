怎么读这份报告
① 归并层（验收侧写）：每个目标先列固定计划里的验收判据原文，再给「判据 → 计划内 Issue → 证据落点 → 缺口」。达成/不达成不在本报告下结论，由人在验收屏逐目标标记。
② 判据层（开发侧验收件的子集提取）：每个 Issue 先给一句人话，再用基本用例表列证据：用例名 · 期望结果 · 实际结果 · 证据（形态 · 钉住的 commit SHA ＋ 文件名，截图直接内嵌）· 执行路径；另有门禁、未验留白、人工核对、待核对与缺口各一行。组合、异常、负例与门禁细节不搬入正文，点名原验证报告链接。
③ 证据一律是各 Issue/PR 合入时留下的现成产物，验收只提取聚合、不重新采集、不反推补写。开发侧没留的字段写「开发侧未留」，不代采、不凑数。缺口与待核对项由人确认，模型不定论。
