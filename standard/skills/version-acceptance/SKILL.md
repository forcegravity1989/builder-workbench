# 版本验收

协助 Builder 走完验收屏四步:**验收准备 → Showcase → 会议纪要 → 归档 PR 及发版本**。本屏为周五验收会议服务:会前把材料备齐(部署好的真机演示环境 + 一份验收证据报告),会中对着勾勾表逐目标演示,会后纪要确认、归档、按需发版。个人对需求的逐项自验发生在周中的会话与开发流程,不在验收屏。典型周四准备、周五开会;版本与项目要求优先,不把时钟当门禁。

通过宿主的 `orca skills get version-acceptance` 读取本流程;`--references` 列出可用引用,`--reference <名称>` 按需读取。只使用实际下发的身份、材料命令和原生执行能力,普通项目无需检出 BW 源码。入口提供当前选版与实际工具身份;先使用这些上下文,不要求用户提供 BW 源码。

## 会话驱动板面

右板各操作与会话的分工:**板面按钮要么直接读回材料,要么把一句话请求注入本会话;实际工作由你按下表做**。板面按钮与人直接在会话里说同一请求完全等价,不因入口不同改变行为:

| 板面动作 | 你做什么 | 写回材料什么(板面读回) |
|---|---|---|
| 「出包」 | 固定逻辑在板面(按项目远端直连出包流水线),无需你执行;包出现后核对四字段对应本次候选,不把旧包当本次交付包 | `candidateRef`(候选固定即写);`preparedArtifacts` kind=package(checksum/location/实际命令) |
| 「部署」 | 注入部署请求:下载最新包,**按项目自有部署入口**部署启动——各服务部署逻辑不同,无固定脚本;桌面应用=安装并启动,web 服务=部署并起前端。缺入口说明缺什么,不虚构命令;缺工具请人安装,不降级绕道 | 演示环境 URL(桌面应用写启动状态);板面「演示环境」行的 URL 点击经内置浏览器打开 |
| 「更新代码」 | 板面原生同步,快进不了时按提示在会话处理 | — |
| 报告未生成提示 | 采集证据、按模板生成验收证据报告(见下节) | 报告文件落 `.bw/planning/<版本>/` 并登记 |
| 「发布」 | 注入发布请求:先呈现知情状态 → 核对一致性 → **经人明确授权**按项目发布入口执行 → 独立读回并在会话中报告 | — (板面无发布行,材料不存发布记录;正本在 Git 标签与 Release 页) |
| 归档(会话中发起) | 核对材料 → stage=archive → 固定树提交推送 → 开 PR → 写 archivePr | 归档引用与状态 |

勾勾表的达成/不达成、Issue 备注与遗留标记、纪要条目及其人工确认,**都由人在界面落**;你不代勾、不代笔、不代确认。助手入口按对象就近放置:纪要区「让验收助手整理纪要」、归档区「让验收助手发起归档」同样经 Orca 原生发送弹窗注入一句话请求,与人在会话里直说等价;Showcase 无模型填写事务,不设助手入口。

## 验收证据报告

一个版本一份,所有目标合并,按[报告模板](assets/evidence-report-template.md)生成:目标 → 验收点 → 验收说明 + 逐条证据(截图、指标读数、平台读回、文件位置);**每个目标必含「本版目标值 vs 本期读数」对比**;适合现场演示的验收点标「现场演示」并附操作路径(从演示环境 URL 起,分步);缺证据的验收点进「缺口清单」如实标缺,不凑数、不用大段文本代替证据。指标证据只进报告,板面不回显指标区。与 workbench-release 的版本收尾总结报告分工:本报告逐验收点罗列证据(给核对与会议用),收尾报告偏总结叙事(给领导与升级试用者);两者独立,不可互相代替。

## 阶段进度(材料内部,界面无灯)

`workflow.stage` 记录最近完成的阶段,只用于会话恢复校准与自动化读取,界面不渲染灯:

| stage 值 | 何时写入 |
|---|---|
| `preparation` | 候选固定、演示环境部署可用、验收证据报告生成并登记 |
| `showcase` | 会议演示完成、每个目标的达成/不达成已由人在界面标记 |
| `archive` | 提交归档 PR 之前;PR 开出后把 provider/repository/number 写入 `workflow.archivePr` |

纪要的人工确认是材料字段事实,不占 stage。恢复会话时先按材料实际进度校准 stage;stage 不代表目标达成,也不代表 PR 已合入或版本已发布。

## 执行流程

1. **恢复本次验收。** 先展示完整四步流程和已有进度(按校准后的 stage),再核对场外要求、实际项目与本版固定验收工作树(绑定版本树为 bw/<版本>/acceptance,无绑定树的旧上下文为 bw/week-acceptance)。入口已给出版本或工作树已绑定版本(绑定即单一正本)时直接恢复该版材料,不再选第二次。没有验收时基于本分支该版已提交计划初始化草稿并自动保存。**计划归档 PR 未合入时验收不能开始**(界面为空板并报「无法开始验收」);人在此状态下要求开始验收时,如实告知计划未合入,建议先合入计划或核对状态,不做草案预验收。开工前核对固定树与基线分支关系:behind 且 ahead=0 可 fast-forward 更新;ahead 含未归档材料提交时先与人确认顺序,不自行合并。同次会议的准备与重试继续原会话,不混用本版计划工作树(绑定版本树 bw/<版本>/plan,旧无绑定树 bw/week-plan)。

2. **出包与部署。** 人在界面点「出包」(或按项目自有出包入口执行);受理后最新包每分钟自动刷新,不重复启动;核对最新包四字段对应本次候选。候选固定后**写入 `candidateRef`**;包出现后**登记 `preparedArtifacts`**(kind=package,含 checksum、location、实际命令)。收到部署请求(板面「部署」或人口头)→ 下载最新包 → 按项目自有部署入口部署启动 → **把演示环境 URL(桌面应用为启动状态)写回材料**,并告知人板面可点击打开。区块报错(无流水线、无权限、远端认不出)如实转告,改按项目自有入口执行并核对;没有包要求就不造包要求。

3. **采集证据、生成报告。** 对着部署后的运行环境,按各目标的验收标准采集:浏览器实操截图(每张记核对哪个验收点、执行路径、期望结果)、真实指标脚本读数(按指标协议写 readings)、平台读回(PR/CI/Issue/Release 链接+摘要)。做**演示分诊**(易现场演示→标操作路径;不易演示/步骤复杂/需等待→落报告),按模板合并生成一份验收证据报告并登记。包重出不自动刷新板面已填内容;检测到包变化时在会话提醒:「包已重出(旧→新),涉及哪些目标的证据,是否重核?」人同意才重核,且只重核受影响部分。板面批注是人的意见输入:收到批注按对象(目标/Issue/板面级)理解意见,回应或修订材料。准备齐后写 `stage=preparation`。

4. **Showcase 支持。** 勾勾表复用计划目标,只读回显。会中逐目标:现场演示的带人走演示环境操作路径,或打开报告对应验收点展示;**行尾达成/不达成由人标记,你不代勾**;未标保持空白,不冒充、不推定,演示过与否不进材料。人标记前如实报告缺口(「该目标还有 N 个验收点未采/未演示」),标不标由人决定。不达成目标:原因与安排进纪要、目标「下一步」与对应 Issue 的备注/「遗留」标记(Issue 只有遗留标记,无风险标记;已关闭 Issue 不计遗留、已存备注只读)。全部目标标记完成后写 `stage=showcase`。

5. **会议纪要。** 纪要固定两块:「共识」与「遗留」,常驻板面;人点「编辑纪要」进入编辑态后才增删改或粘贴。人要求整理时:从板面批注与可选会议转写稿(会议 ID 由人提供;没有稿件或来源不可读时如实说明,不凭空补写会议内容)总结为两块内容呈现,由人在界面逐条编辑、**人工确认后生效**;你不代确认、不代签。已确认的纪要整节冻结,你不得改写;人在界面撤销确认后才能在未确认态重新整理。遗留条目不设闭环状态——会上已解决的写进「共识」或不写入遗留;遗留条目原样成为下版计划屏「会议遗留」的来源,只有人工确认过的纪要才会被下版读取。

6. **归档与发版本。** 归档:人在会话中要求归档时,核对材料与结论状态后写 `stage=archive`;在本版固定验收工作树(绑定版本树为 bw/<版本>/acceptance,无绑定树的旧上下文为 bw/week-acceptance)内提交材料(验收 JSON、证据报告及截图)并推送,创建到主分支的 PR/MR,按项目流程和授权执行,不另建工作树或分支;开出后写 `workflow.archivePr` 并回显链接;屏内只呈现引用、状态与原生 PR 页入口。发版:呈现各目标达成/不达成与遗留——**不达成不阻断发布,由人知情决定**;核对发布提交与验收的包一致,不一致(如会后修复)列出差异与来源待人确认;经人明确授权后按项目自有发布入口执行;发布后**独立读回**(tag、时间、资产、校验值)并在会话中如实报告,**不写入验收材料**——发布读数的正本在 Git 标签与 provider Release 页,板面不设发布行、总览不显示已发布。未经人明确授权不创建 Release、不打标签;不合并 PR、不关闭 Issue、不替人确认版本达成。

7. **归档之后。** 合入后从项目主干基线(主检出)读回,总览每版显示一份当前材料;纪要「遗留」条目与 Issue「遗留」标记分别作为下版计划屏的「会议遗留」与「延期遗留」回显,由下版计划会话与人形成候选,不自动承诺或排期。归档后补证继续编辑同一份验收并保留 cycleId,旧依据从 Git 追溯。出包、合入、Issue 完成和正式发布分别成立,不互相代替。首用时记录材料找不到、报告与演示对不上、重复录入和不达成无安排等实际问题,不预填改善结果。

失败保留草稿和原来源;先核对仍在运行的任务再重试,不能重复开构建、覆写脏树、伪造新读数或替人确认;缺工具请人安装,不降级绕道。
