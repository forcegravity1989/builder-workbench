# 版本验收

协助 Builder 完成“准备交付 → 出包 → Showcase 与验收 → 归档”。典型是周五上午准备、下午展示后归档；版本与项目要求优先，不把时钟当门禁。

通过宿主的 `orca skills get version-acceptance` 读取本流程；`--references` 列出可用引用，`--reference <名称>` 按需读取。只使用实际下发的身份、材料命令和原生执行能力，普通项目无需检出 BW 源码。入口提供当前选版与实际工具身份；先使用这些上下文，不要求用户提供 BW 源码。

## 阶段状态（与验收屏的灯共用）

验收材料的 `workflow.stage` 记录**最近完成的阶段**，验收屏旅程灯直接按它点亮：到 stage 及其之前为绿，之后为灰。旅程里的「出包」灯是唯一例外——它不跟 stage，随出包区块读到的最新制品包点亮，读到真实包才绿；出包不是 stage，不为它写值。每完成一个阶段就用 `ORCA bw materials save` 更新：

| 阶段 | stage 值 | 何时写入 |
|---|---|---|
| 准备交付 | `preparation` | 候选固定、交付件与材料按目标收齐 |
| 展示验收 | `showcase` | 展示完成、每个目标的人工结论都已在界面记录 |
| 归档 | `archive` | 提交归档 PR 之前；PR 开出后把 provider/repository/number 写入 `workflow.archivePr` |

恢复会话时先读回进度并核对轮次，再按本轮实际进度校准 stage；新轮刚开始不写已完成阶段。人工结论（`results[].decision`）仍只由人在界面记录，不代签；stage 只是进度信号，不代表目标达成，也不代表 PR 已合入——合入状态由界面按 `archivePr` 读 provider 显示。

## 执行流程

1. **恢复本次验收。** 先展示完整流程和材料已有进度（`workflow.stage`），再核对场外要求、实际项目与固定 bw/week-acceptance 工作树。入口已给出版本时直接恢复该版材料，不再选第二次。页面读回已有验收；没有验收时基于本分支该版已提交计划初始化草稿并自动保存。版本未明确时先列候选，与人明确后才写材料；保留固定计划来源，未合入计划只能明确标为草案预验收。工作树目录由 Orca 原生创建和登记。开工前核对固定树与基线分支关系：behind 且 ahead=0 可 fast-forward 更新；ahead 含未归档材料提交时先与人确认顺序，不自行合并。新周运行新会话，同次上午/下午与重试继续原会话，不混用 bw/week-plan。
2. **核对并承接轮次。** 此步骤独立于会议转写；普通验收和跨周进展刷新都先执行，完成前不刷新指标或 Issue、不改候选或会议指导。同周继续当前轮，不重复开轮。第一次使用无轮次材料时，与人明确周次，按 [版本材料](../../system-prompt/references/version-records.md) 登记各目标共用的当前轮身份，不由日期或会话名猜。第二周以上周材料为起点，保留进展、备注、材料与未解决遗留/风险，不清空重填。跨周先固定已提交且可读的 planRef，再将当前已保存验收材料提交在固定验收树，取得真实提交及文件原始字节 SHA-256；同一次材料 save 封存旧轮并建立新轮，重置当前目标结论为待核并清除旧 workflow（含阶段与 archivePr），其余材料原样承接。旧材料无显式轮次时在同一次保存补齐已核对的旧轮与新轮；旧轮 snapshot 如实复制封存前的人填值。若已有轮次全部关闭，则保持旧轮原样，只追加新轮；先提交最新完整材料，保存服务会核验本树 HEAD 的验收和固定计划来源。只有来源核验通过并原子承接新轮，才可移除当前 decision 与 workflow；失败先重读并保留输入。新轮刚开始不写 preparation，完成准备后再更新阶段；随后默认刷新本周最新指标读数。历史周从固定 Git 来源只读回看当时整份材料，不用当前数据代替，也不让用户选采集日期范围。
3. **准备交付。** 确定候选提交，读取项目已有测试/交付入口，按已有授权执行并独立核对结果。先查本次原生任务和进程是否仍在运行，再恢复或重试；保持源码执行区检出的提交与候选一致，不能从验收树旧 HEAD 打包。整理项目需要的交付件、报告和 showcase 材料；缺入口明确说明。生成时记录实际命令、工作区、候选、时间与适用的校验值，不凭文件名判断来源。交付与材料按目标收齐后写 `stage=preparation`。
4. **出包。** 需要安装包时用验收屏「出包」区块：它按项目远端自动对接出包流水线，流水线下拉只列可出包的流水线。由人选流水线并点「出包」；启动受理后流水线在平台上运行约数分钟，最新包信息每分钟自动刷新，不重复启动。最新制品包的项目名称、版本号、创建时间与包文件是平台真实读数——核对它们确实对应本次候选，不把旧包当本次交付包；「下载」把最新安装包本体保存到人选择的目录，可直接作交付件。区块报错（无流水线、无权限、远端认不出）时如实转告，改按项目自有出包入口执行并核对；没有包要求就不造包要求。
5. **核对事实。** 原目标、约定交付、验收说明与指标目标保持只读；只按原承诺核对交付件和指标，不为每个目标强加两类材料。页面只显示已承诺或已保存的指标；“刷新指标”采用最新已合入定义执行真实脚本并保存读数，失败不填零。任务通过 Orca provider 刷新，与计划屏共用任务展示。实际材料能打开，失败与缺口显式保留。
6. **Showcase 与判断。** 沿原目标打开同一候选的材料，由人判断达成、未达或待核，用户在页面填写后自动保存，模型不代签；保存不代表验收通过。需要方法时读 [证据与后续](references/evidence-and-follow-up.md)。补某目标的材料只使该目标待重新核对；更换计划修订、源码候选或候选交付包（package）时全部目标待重新核对，即使源码提交不变，也要按实际包更新校验值等来源，保留原结论文字。未达项在原卡写原因和安排，不自动进入下版承诺。Issue 只核对真实状态，不在验收中再次拆任务。全部目标的人工结论记录完成后写 `stage=showcase`。
7. **会后转写总结。** 需要把会议指导与遗留带回材料时，取得当前会话明确的 eMeeting 会议 ID，按 [会议转写](../../system-prompt/references/meeting-transcript.md) 调用随包命令读取全部录制，核对读取范围和本项目议题。**必须启动独立 subagent**，提供本项目转写段落、固定计划承诺、目标与关联 Issue，要求返回指导与遗留、逐条来源和不确定清单；主会话负责范围核对与接收结果，不能直接代替 subagent 总结。不确定发言先向人澄清，不把错字或猜测当决定。获取失败说明原因，让 Builder 在当前会话直接输入关键信息，不设计文件导入兜底；把这段实际会话输入交给独立 subagent 整理，沿同一来源与不确定清单核对流程继续；人工补充使用 manual 来源，不冒充转写，也不让 Builder 再抄到界面。

   将来源明确的 subagent 建议按 [版本材料](../../system-prompt/references/version-records.md) 写成 `pending` 指导：转写总结保留会议、录制/议题定位，人工补充指向实际会话消息，不能编造来源；明示素材来源与 AI 整理身份。三种处置标签为本次验收已解决、纳入下周计划、记录遗留。模型不能写人的确认、结论、Issue 备注或标记。提示 Builder 在验收界面逐条核对、确认或删除，也可人工补记；只有人确认后才写 confirmed 与确认时间。已确认的本次验收要求按授权继续处理；next-week-plan 在周一只成为候选，仍由人选择 Top 3，record-remaining 保留跟进背景，不自动改承诺、关 Issue 或发布。这里不提供“注入会话”按钮，也不因生成、打开或保存指导而点亮阶段灯。
8. **归档接续。** 界面不再有归档按钮，用户在会话中直接要求归档：验收纪要由当前结构化材料派生，核对版本/周次/修订/来源及当时的任务快照后，写 `stage=archive`；在固定 bw/week-acceptance 工作树内提交材料并推送远端 bw/week-acceptance，创建由 bw/week-acceptance 到主分支的 PR/MR，按项目流程和授权执行，不另建工作树或分支。开出后把 provider/repository/number 写入 `workflow.archivePr` 并回显链接。合入后从项目主干基线（主检出）读回，总览每版显示一份当前材料；归档后补证继续编辑同一份验收并保留 cycleId，形成新修订，旧依据从 Git 追溯。出包、合入、Issue 完成和正式发布不互相代替。首用时记录材料找不到、候选不一致、重复录入和未达无安排等实际问题，不预填改善结果。

## 需要时读取

- [版本材料](../../system-prompt/references/version-records.md)：跨树读取、候选、修订、保存、workflow 契约与文本写入要求。
- [指标](../../system-prompt/references/metrics.md)、[Issue](../../system-prompt/references/issue-state.md)：涉及对应事实与远端写入。

失败保留草稿和原来源；先核对仍在运行的任务再重试，不能重复开构建、覆写脏树、伪造新读数或替人确认。
