# Issue 规范

> **维护约定**：供日常提单、计划拆解和 Issue 维护时读取。本文统一规定标题、正文最低要求、提单性质、特性主单关联与处理结果。项目具体归属名称由项目 AGENTS.md 或其引用资料定义；纳入计划的额外动作由计划工作流规定。规则变化时核对相关入口、提单模板与完整 Skill 包。

## 提单与正文

- 先查是否已有相同 Issue，能复用就更新原单。
- 正文只要求一段 **问题描述**：谁在什么场景遇到什么问题，或希望得到什么结果。截图、链接、版本、环境、复现步骤和方案可以一并提供，也可以后补；不知道的内容留空或写待确认，不编造。
- 更新原单时保留原问题、已有事实、有效资料和人工决定。

## 标题与归属

- 标题用一句话说清问题或需求。提单或整理标题前，先读取项目 AGENTS.md 及其引用的归属约定；项目尚未定义分类时，省略归属名称。
- 归属已经明确时，在问题描述前加 `【归属名称】`。沿用项目约定的名称，不自行增加同义分类或新立特性。一个 Issue 标记一个主归属，按它主要解决的用户问题判断；涉及的实现模块或技术来源可以另作说明。
- 版本和目标已经确认时，使用 `【<版本>|<目标>】`，放在归属名称之前。没有已确认的版本或目标时省略这一段，不影响标记特性归属；不猜版本、周次或编号。
- 归属尚不明确时，按项目约定标待定或请人判断；未知归属不妨碍先记录清楚问题。

示例：

```text
【任务管理】修复任务列表筛选后无法刷新
【v0.9|G4】【任务管理】统一特性单量统计口径
【v0.9|G2】【版本总览】【特性#334】补充跨版历程展示
```

示例中的归属名称由各项目自行定义。归属名称只作阅读与检索；**版本成员由 `bw:plan:<版本>` 标签判定，目标关系从标题 `【<版本>|<目标>】` 的目标段读取**（目标段须等于计划材料里的目标 id）。两者都由 Issue 侧维护，不再写进计划原始文件的任务列表。

纳入版本计划时，完整读取计划入口指定的 `week-planning/SKILL.md`，按其中的处理范围、验收条件、计划标签和目标标题建立关联。

## 特性主单与拆分任务

人确认需要整体设计、评审并可能跨版本延续的特性时，复用一条主 Issue 并增加 `特性` 标签。它区别于 provider 的 Bug／Feature 提单分类，不代表阶段或完成。主单与里程碑对应时，标题包含完整、去首尾空白的里程碑特性名，可保留版本／目标前缀。里程碑行与主单须唯一对应，匹配到多个候选时先核对。

按实际分工，可将原型设计和各项研发工作拆成多条执行 Issue。每条执行单在问题描述前写同一个主单引用，如 `【特性#334】`；已有归属名称时将引用放在名称之后。主单编号按同一 provider、仓库解析，不能用特性名称、目标编号或同名标题充当跨版身份。跨版时沿用同一主单。普通任务不为显示或统计强制建立主单、拆分 Issue。

人确认某特性纳入本版时，主单本身必须带上该版 `bw:plan:<版本>` 标签，并在标题写明目标段；一个目标最多一个特性主单，同一主单在同版只归一个目标，已纳入的拆分任务同样带版本标签并写明目标段。归到哪个目标以标题目标段为准，不再依赖计划文件逐条登记任务。确认特性改名时保留主单身份，按[里程碑与版本排期](version-records.md#里程碑与版本排期)同步名称；单独编辑目标标题不触发特性改名。

成果按实际交付关联 PR/MR，可在合入后补链，保留原人工结论。阶段明确时，在关联的 PR/MR 正文独立一行写 `交付阶段：设计` 或 `交付阶段：开发`，也可在主 Issue 正文逐行写 `设计 PR：完整链接` 或 `开发 PR：完整链接`（CodeHub 可写 MR）。同一阶段有多个候选时，总览保留各项证据，阶段完成时间保持未知。

## 提单性质与处理结果

- `Bug` 表示已有行为在实际场景中没有满足预期；`Feature` 表示新增能力或行为。提单按人确认的性质选择 provider 原生分类，讨论或预研使用相应入口。性质不清先向人核对，不从标题、状态、关闭原因或目标名称推断。
- Bug／Feature、标题归属、`特性` 主单标签各有用途，都不表示执行阶段或完成。
- 读回任务时保留 provider 返回的分类。标签中有 `Bug` 或 `缺陷` 时归 Bug；有其他非空标签或没有标签时默认归 Feature。不因此批量补标，也不从标题或关闭原因猜测分类。

Issue 使用 provider 的原生 open / closed。关闭原因按 provider 能力准确记录：已完成、决定不做或重复都表示这条 Issue 已经过处理决定；关闭不等于版本目标或验收自动完成。统计口径遵循项目约定。

## 修改与授权

- 关闭、重开、改标题、改正文和改标签按用户或项目工作流授权执行，写前读最新对象，写后独立读回。重复项指向承接单。
- 整理标题时保留有效的版本／目标、特性归属、主单引用；规范更新不自动授权批量修改存量 Issue。
