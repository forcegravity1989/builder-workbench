# BW 业务会话执行规范

> 计划、验收、指标配置会话开工和恢复时完整读取。本文规定共用执行边界、项目与工具读取方法；具体 SOP 在本 Skill，具体协议在各自 reference。公共执行约定变化时更新，不记录历史或执行流水。

## 项目与人的决定

- 动手前完整读取项目 AGENTS.md，文档与开发规则沿它及引用；没有就如实说明，不代写一套。无关联 Issue 的配置或周期任务不猜编号、不另建任务。
- 完成由人确认；Issue 关闭/重开、PR/MR 合入与发布沿人的明确授权。优先采用项目已有提交、评审与交付技能，不套 BW 研发规则。
- 使用宿主已打开的工作树与执行身份，核对仓根和分支，不另建同用途工作树、编辑服务或平行材料。已有输入不重复索取；事实缺失保持未知。
- 文件改动按项目约定交付，回显真实 PR/MR 与验证；无改动不开空提交或 PR。远端写前读最新对象，只改授权内容，写后独立读回。
- 保存失败保留输入，修订冲突重读比较，不覆盖人的新改动。外部操作失败报告真实结果，不把尝试写成成功。

## 工具与动态上下文

Skill 与依赖直接读本安装包文件。产品命令中的 `ORCA` 是实际 CLI 的占位符，选定后沿用：

1. 有 `ORCA_CLI_COMMAND` 时使用其值。
2. 否则，开发会话有 `ORCA_DEV_REPO_ROOT` 时用 `orca-dev`。
3. 否则，Linux 非 Orca 托管终端用 `orca-ide`，不调用可能属于屏幕阅读器的系统 `orca`。
4. 其余安装版 Orca 托管会话用 `orca`。

不创建名为 ORCA 的 shell 变量，不原样执行占位符。命令不可用报告原错误，不换到另一安装版本；参数不明确读该命令 `--help`，不编造命令。

开工时若终端提供 `ORCA_WORKTREE_ID`，执行 `ORCA worktree show --worktree "id:<ORCA_WORKTREE_ID 的完整值>" --json`；没有时执行 `ORCA worktree current --json` 从当前目录解析。不要拆分或重组工作树 ID；远端 CLI 不支持 current 时报告身份缺口，不按桌面目录猜测。读回原生工作树身份，核对返回的 `worktree.id`、`repoId`、`hostId`、路径与版本绑定，再用本 Skill 的文件或材料工具读实际状态。返回不明确或与当前仓不符时先核对身份，不写材料；不按界面焦点、会话标题、日期或最近访问记录猜版本。

## 用户可见表达

跟随用户语言，默认中文。讲对象、动作、结果，失败补原因和下一步。用屏幕真实分区名；协议字段、阶段枚举、内部 ID 只作命令参数，不当作用户步骤名称。
