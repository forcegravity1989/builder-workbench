## 新闻稿式正文

### 标题

**项目规范知识库:你的仓自己知道缺哪份文档**

### 副标题

给 super builder 的知识文档标准——接入 Workbench 的项目,每周盘点时多一段「知识库体检」:哪份该有的文档缺了、哪份腐烂了,缺口直接变成待办活。

### 痛点

AI 时代一个项目的可驾驭性不取决于代码,而取决于**知识文档齐不齐、新鲜不新鲜**:词表缺了 agent 各叫各的;设计正本腐烂了 agent 照旧文档改新代码;手册没人维护同一个错误犯三次。今天这套「该有什么文档」的标准只存在于 BW 自己仓的实践里,被管项目享受不到,人也没有一个地方能看到「我的仓离规范还差几份」。

### 解决方案

三件事,全部复用现有机制,不开新面:

1. **标准成文**:把 BW 实践 + `principles/01–04` 提炼成一份**知识文档总账**(每件:是什么/判据/谁产/缺了怎么补),体裁与过程指标总账(`process-catalog.md`)同款,随规范铺底进被管仓。
2. **剧本监督**:资产盘点剧本(运作活②)吃这份总账,每周产出「知识库体检」——齐不齐、新鲜不新鲜,证据留在运作活评论里。
3. **缺口变活**:体检发现的缺口按标准建活挂上看板——**只建活、绝不代写**;写不写、怎么写,仍走人的 gate。

### 如何获得

规范铺底(新项目)或规范升级对账(已接入项目)拿到总账;周五资产盘点自动带体检。不装 Workbench 的人 clone 仓也能照总账人工对(总账是仓文件,判据能读回)。

## 五大拷问摘要

| 拷问 | 答案 |
|---|---|
| 谁是客户? | Super builder(自己)与被管仓的后来者(同事、下一个 agent 会话) |
| 痛点/机会? | 「该有什么文档」无标准、缺口无人盘、腐烂无人报;BW 自己已经踩出一套可复制的层次 |
| 核心利益? | 仓自己报告「离规范差几份」,缺口自动变待办;新会话/新人按标准集就能接手 |
| 如何知道? | BW 自身实践:principles/文档治理反复返工(2026-08 一个月内多轮失实修正)证明标准与监督缺位的代价;playbook「手册当代码维护」「政策变更→技能更新」同向 |
| 体验什么样? | 周五盘点活评论里多一段体检表;看板上多几张「补 CONTEXT.md」这类活;人决定做不做 |

## 约束

- **只建活不代写**:监督的产出是体检证据 + 缺口活,绝不自动改被管仓文档(改文档走正常 MR + 人合)。
- **复用不新增**:落点是既有的总账体裁、资产盘点剧本、建活机制;不做独立 doc-lint 工具、不开新屏。
- **判据可读回**:每件文档的「有没有/新鲜不新鲜」必须能用 `git`/`gh`/`codehub-cli`/`cat` 独立查出来,与过程指标同一纯度规则。
- **标准分默认与可选**:单人小仓不强推全套(如 principles/ 对早期项目是可选件),总账里写明哪些是地板、哪些看项目成熟度。

## 飞轮检验(对齐 principles/03)

加强的是「架构盘账回流」与「技能更贴」两截:知识库体检把文档欠账变成下一次迭代的待办,与架构盘账同构;不把人拽回搬运工(体检自动产出,人只过 gate);不破坏「做不做必须人认」(缺口只建活)。定时任务只建队列、不代做判断——与铁律四严丝合缝。
