> **30 秒导读**:这是什么——本次变更的**规格件**:标准知识文档集的定义、监督机制的设计、体检报告的原型与操作逻辑。给谁看——过规格 gate 的人、按 plan 施工的会话。现在作数吗——**草案,待规格 gate**(2026-08-26);上游意图见同目录 `intent.md`。

> **原型形态说明**:本变更没有新界面(落点是仓文件 + 运作活②评论 + 既有看板),规格 gate 要求的「可点原型」以**总账样例段 + 体检报告样例**(见 §3、§4,均为最终产物的逐字形态)承担,「操作逻辑」见 §5。若规格 gate 认为必须有界面原型,退回时写明哪一屏。

## 1. 设计拍板(三条)

1. **标准即总账**:标准知识文档集写成一份**知识文档总账** `standard/templates/knowledge-catalog.md`(铺进被管仓为 `.bw/knowledge-catalog.md`),体裁照 `process-catalog.md`:逐件给「是什么 / 判据(可读回) / 谁产 / 缺了怎么补」,分「地板件」与「成熟度可选件」两档。**本 spec §3 的表就是总账正文的正本**,施工时不复写第二份口径。
2. **监督即盘点**:不新建剧本,**扩展 `asset-audit`(运作活②)**:每周模式加一段「知识库体检」——按总账逐件核存在性与新鲜度,证据(逐件读回命令与结果)写进运作活②评论;缺口按标准建活(幂等键 = 固定标题「补 <文件名>」,已有开着的同名活不重建)。**只建活不代写**。
3. **新鲜度走过程指标**:总账里可量化的新鲜度(手册修正频次已有脚本;设计正本更新间隔为新增)登记进 `process-catalog.md` 的对应格,不另起第二套统计。

## 2. 标准从哪来(BW 实践的提炼)

BW 自己仓走到今天的文档层次 = `principles/01`(分层)+ `principles/04`(产物链)+ 实战教训(2026-08 文档治理:失实引用、术语漂移、V3 残留的多轮返工)。标准集就是把「BW 自己有什么、为什么有」翻译成「被管项目该有什么」。

## 3. 标准知识文档集(总账正文的正本)

**地板件**(每个接入项目都该有;判据全部可读回):

| 件 | 是什么 | 判据(存在性 + 新鲜度) | 谁产 |
|---|---|---|---|
| `README.md` | 门面:是什么/怎么跑 | 存在;有「怎么跑」一段 | 人或 workflow(project-handbook 问过人才写) |
| `AGENTS.md` + `CLAUDE.md` | agent 开发手册(一页内)+ 一行导入 | 存在;错两次进手册(#123 回路);每周修正频次有数(`handbook-changes.py` 已有) | project-handbook,人点头 |
| `CONTEXT.md` | 领域词表(选定词 + Avoid) | 存在;新概念高频出现而词表无词条 → 缺口活 | workflow(如 mattpocock domain-modeling) |
| 设计正本(如 `docs/architecture.md`) | 设计实况一篇正本 + 各模块「没建什么」 | 存在;N 周未动而代码大改 → 腐烂,报体检(N 默认 4,总账可改) | workflow / 人 |
| `docs/adr/` | 难回头决策一条一篇 | 目录存在即可(数量不设指标,防凑数) | workflow |
| `CHANGELOG.md` | 版本变更记录 | 存在;最近一次发版后有对应段 | 人或 workflow |
| `.bw/` 规范件 | 名片/指标/issue-policy/过程指标总账/本总账 | 铺底对账已有指纹机制,体检只引用其结论,不重查 | 规范铺底 |

**成熟度可选件**(总账写明「什么时候该补」,体检只提示不催办):

| 件 | 什么时候该补 |
|---|---|
| `principles/`(原则:分层/主张/过程) | 项目出现「同一决策反复重议」或多会话协作时 |
| `changes/<id>/` 制品链 | 出现需要人对齐意图/规格的特性级变更时(小修直修不开链) |
| `docs/guide/`(使用指导) | 产品有第二个用户(同事/客户)时 |
| 高保真 / 视觉正本 | 有界面且开始返工视觉时 |

## 4. 体检报告原型(运作活②评论里的逐字形态)

```markdown
## 知识库体检 2026-W35

| 件 | 状态 | 证据 |
|---|---|---|
| README.md | ✅ | cat README.md → 有「怎么跑」段 |
| AGENTS.md | ✅(本周改 2 次) | handbook-changes.py → W35: 2 |
| CONTEXT.md | ❌ 缺 | ls CONTEXT.md → 不存在 |
| 设计正本 | ⚠️ 6 周未动,期间合入 14 个 MR | git log -1 docs/architecture.md |
| CHANGELOG.md | ✅ | 最近标签 v3 有对应段 |
| .bw/ 规范件 | ✅ 5.9 在册 | 对账区结论 |

缺口活:已建「补 CONTEXT.md(领域词表)」(#N);「设计正本回填(6 周欠账)」(#M)。
可选件:principles/ 未建——项目仍单人单线,暂不提示。
```

三态口径与健康灯同哲学:✅ 过 / ❌ 缺 / ⚠️ 腐烂;查不出来(如仓临时连不上)如实写「未查到」,不猜。

## 5. 操作逻辑

- **主路径**:周五运作活②自动建并开工(既有机制)→ agent 按剧本读 `.bw/knowledge-catalog.md` → 逐件跑判据命令 → 体检表挂评论 → 缺口按幂等标题建活(打 `bw:category:ops` 外的类别?否——缺口活是普通业务活,按 issue-policy 默认类别 build)→ 人在看板决定做不做。
- **分支**:项目没铺总账 → 体检段写「总账未铺,跳过」并提示铺底升级,不硬跑;判据命令失败 → 该件记「未查到」,不算缺也不算过。
- **出错**:建活失败(远端不可达)→ 体检表照挂,缺口行标「建活失败,原因」;下周幂等重试。
- **人不理会**:缺口活躺看板不推进——体检下周照报,不升级、不催、不自动关。

## 6. FAQ 硬问题(内部)

- **会不会变成文档官僚?** 地板件只有 7 类且判据是「存在 + 新鲜」,不查内容质量;可选件只提示。单人仓 5 分钟能对完一遍。
- **agent 判「腐烂」判错了怎么办?** 腐烂只产 ⚠️ 与一张活,人可作废;阈值 N 在总账里,人改。判据全可读回,错了能对质。
- **和资产盘点现有内容重不重?** project-handbook 管「顶层文档怎么写」,本件管「全集齐不齐」;体检引用手册回路结论,不重查。
- **成功指标?** 被管仓地板件覆盖率(体检表自带);缺口活的接受率(人建了多少/关了多少,现查 issue);BW 自狗食一轮跑通。
- **代价?** 剧本变长(渐进加载兜住,正文按需读);体检每周多几条读回命令,秒级。
