# Spec · native-audit（仓考古）

> **30 秒导读**：这是什么——仓考古能力的**规格件**：判读准则正本、操作逻辑（主路径/仓群路径/出错）、外/内 FAQ。原型在哪——[prototype-report.md](prototype-report.md)（对本仓的真实扫描）+ [skill 草稿](../../.claude/skills/native-audit/SKILL.md)。现在作数吗——意图 gate 已过（拍板记录在 intent 末节），待评审合入。

## 判读准则（正本）

七个维度，每维按**制度化阶梯**打分：**0 = 无/不可考（Unknown）· 1 = 有痕迹 · 2 = 成文 · 3 = 机器强制**。分数只回答「这条纪律被制度化到哪一级」，不评价代码好坏。

| # | 维度 | 量什么 | 3 分长什么样（dsh 实证） |
|---|---|---|---|
| D1 | 规范正本 | AGENTS.md/CLAUDE.md 存在？分层？聊天外有唯一正本？ | 分层正本 + 字数预算上 CI |
| D2 | 决策记忆 | adr/notes/changes 类目录？数量？记不记「打败了谁」？ | 非琐碎变更强制带决策记录 + 格式门禁 |
| D3 | 门禁密度 | CI 检查数、自定义 guard/verify 脚本数 | 规矩尽数脚本化 + 门禁自带测试 |
| D4 | AI 参与方式 | 分支名模式（codex/claude/worktree/copilot）、Co-Authored-By、bot、agent 评审 | agent 产出以 PR 为验收单元 + agent 评审进流程 |
| D5 | commit 卫生 | 类型分布（feat/fix/docs/test 占比）、信息可读性、节奏曲线 | 约定成文且可机械分类；docs+test 占比健康 |
| D6 | 验证证据 | 测试/E2E/快照存在？在 CI？覆盖策略成文？ | 验证策略成文 + CI 强制（形态不限，E2E-only 也算） |
| D7 | 文档反 slop | 死链、历史叙述混入正文、同一规则多处复述 | 反 slop 清单成文 + 死链/预算门禁 |

**Unknown 纪律（对齐四铁律）**：拿不到数据的维度标 Unknown 计 0 并注明原因（浅历史、squash、无权限），绝不推断补分。历史被 squash 的仓，D4/D5 的历史维度标「不可考」。

**判读一致性**：机械指标由电池命令直接出数；0-3 定级由会话对照本表 + prototype-report 的锚定样例（dsh≈门禁层、本仓≈成文层）判，两个锚点写死在 skill 里防评分漂移。

## 操作逻辑

**主路径（单仓）**：入参仓路径/地址 → 若远端则 `git clone --filter=blob:none`（历史全、blob 惰性，巨仓可行）到临时目录 → 跑度量电池（纯脚本出数）→ 读关键规范件样本（AGENTS/贡献规矩/CI 配置，限额防炸上下文）→ 按准则定级 → 出单仓报告（数据表 + 七维评分 + 缺失清单按「升一级最便宜」排序）。

**仓群路径**：入参清单文件（每行一仓）或 codehub 组名（`codehub-cli` 列仓）→ 每仓一个子代理跑主路径（模型 sonnet，难仓 opus，**一律不用 Fable**；并发 ≤5）→ 主线程只收各仓评分卡 → 汇总榜（七维矩阵）+ 全群 top 缺失 + 「BW 铺底可直接补哪些」对照。

**出错**：clone 失败/无权限 → 记入失败清单继续下一仓，报告如实列出；命令超时（巨仓）→ 降级为近一年历史并在报告标注窗口；子代理失联 → 该仓整体标 Unknown。任何降级都出现在报告里，不静默。

## 客户会问（外 FAQ）

- **和资产盘点、知识库体检什么关系？** 资产盘点盘 BW 可见物齐不齐、知识库体检查被管项目 `.bw/` 知识件健康度——都是对着 BW 规范查。仓考古对**任意仓**（不必被 BW 管）量 AI-native 制度化水位，是拉新证据链，不是存量健康检查。
- **不做什么？** 不评代码质量、不做安全审计、不改被扫仓任何东西（只读）、不自动建活（缺失清单转工单由人决定）。
- **报告可信吗？** 电池命令随报告附出，任何数字可复算；判读级别附引用的仓内证据路径。

## 硬核挑战（内 FAQ）

- **`codehub-cli` 本机不可用**：内网仓群扫描必须在装过 buddy 的机器（`%USERPROFILE%\bin\codehub-cli.exe`）或有内网 git 权限的环境跑。skill 启动即探测，不可用则明确报「内网模式在此机不可用」，不装死。**这是首扫的第一风险。**
- **成本**：机械层零 token；判读层每仓一个子代理（读样本 + 定级），10 仓一轮约一顿饭时间。100+ 全量前先用 10 仓校准准则，避免用漂移的尺量全群。
- **准则会不会带 BW 私货**：会，且是本意（发起人指令「结合我们bw的一些理念」）。准则里 BW 特有取舍只有两条：Unknown 纪律、验证形态不限（不因 E2E-only 扣分）。其余七维来自 dsh 实证。
- **成功指标**：首扫 N 仓 N 份报告全出、失败清单为空或有因；缺失清单被引用去开活/铺底 ≥1 次（30 天内）。
