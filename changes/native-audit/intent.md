# Intent · native-audit：把仓库 AI-native 分析固化成可复用能力

> **30 秒导读**：这是什么——本次变更的**意图件**：把 2026-09-01 对 deepseek-harness 的一次性 git 考古（对仓的全量历史与过程制度件做只读分析）方法，固化成可对任意仓/仓群复跑的分析能力（skill，名 native-audit），用于扫内网 10+ 项目、100+ 仓的 AI-native 缺失。给谁看——评审人、后续首扫会话。现在作数吗——**意图 gate 已过**（2026-09-01 决策卡四题，见末节），待评审合入。

**发起人**：Gravity（2026-09-01 /goal，指令原话：「既然我们能扫描dsh的仓，得出native的分析报告，那我们也可以基于内网的实践（10+ 100+仓）去分析其native缺失的部分，当然也要结合我们bw的一些理念，那这样的一个分析能力就可以落成关键的skill或者workflow。」）。**状态**：意图 gate 已过（2026-09-01 决策卡），待评审合入。

## 痛点

内网 100+ 仓的 AI-native 水位从来没人量过：哪些仓有给 AI 看的规矩、哪些决策只活在聊天里、哪些纪律靠自觉在漏水——全凭印象。deepseek-harness 考古证明了「过程制度才是产能来源」，但那次是几小时的手工动作：命令散在会话里、判读标准在脑子里，换个仓、换个会话就得凭回忆重来，量 100 个仓根本不可行。

## 解决方案

把考古拆成两半固化：

- **探针脚本**：一组纯 `git` + 文件检查命令（已在 dsh 与本仓两个真仓上验证），零 token、任何人可复算——历史跨度、作者集中度、commit 类型分布、AI 参与痕迹（分支/署名/评审）、门禁密度、决策记录存量、规范正本字数。
- **判读准则**：九段三十七条（按 AI-Native SDLC 六阶段 + 贯穿机制 + 治理四条组织，正本 [rubric.md](rubric.md)），每条按**制度化阶梯**打分——0 无/不可考（Unknown 就是 Unknown，不猜）→ 1 有痕迹 → 2 成文 → 3 机器强制。这个阶梯就是 dsh 教科书的内核，也是 BW 自己的理念（规矩从「记得住」到「CI 拦得住」）。

单仓半小时出一份考古报告；仓群模式出汇总榜 + 排序后的缺失清单。缺失清单的每一项都对得上 BW 规范铺底能补的件（AGENTS.md 铺底、决策记录、门禁、skill）——**扫描结果直接变成 BW 推广与铺底的证据和建活依据**。

## 如何获得

任何 Claude Code 会话里 `/native-audit <仓路径|仓地址|清单文件>`。内网仓群扫描在装有 `codehub-cli` 的机器上跑（本机没有，见 spec 风险）。

## 五问简答

**谁是客户**——Gravity 本人（评估内网项目群、决定 BW 铺底优先级）；间接客户是被扫项目的负责人（拿到自己仓的缺失清单）。**痛点真伪**——今天就有 100+ 仓没有任何 AI-native 度量；dsh 报告被广泛讨论说明这类分析有真实需求。**核心利益**——从「凭印象说该推什么」变成「按数据排缺失」。**怎么知道想要**——发起人 /goal 原话；且同方法的 dsh 报告当天已被验证有用。**体验长什么样**——见 [prototype-report.md](prototype-report.md)（对本仓的真实扫描输出，非演示数据）。

## 飞轮检验（对齐 principles/03）

加强「架构盘账回流」（仓群的过程水位第一次可盘可比，结果回流成待办）与「技能更贴」（缺失清单指向该铺哪份规范件）。不把人拽回搬运工：扫描全自动，人只看报告拍优先级。不破坏铁律：没数据的维度显示 Unknown，绝不猜绿。
