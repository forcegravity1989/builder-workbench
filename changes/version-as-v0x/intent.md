> **30 秒导读**：这是什么——本次变更的**意图件**：计划版本、自建版本、发版号收成同一个 `v0.x`；对人说的「周目标」改成「版本目标」。给谁看——过意图 gate 的人。现在作数吗——**draft**（2026-09-01 谈定，等人审 spec）。

**发起人**：产品会话 2026-09-01。**状态**：draft（见 `STATUS.md`）。

## 痛点

仓里有三套「版本」，对人不对齐：

- 周版本叫 `2026-W35`，标签 `bw:week:*`，里程碑同名
- 人起名的版本随便叫（占位还是「MVP收尾」），标签 `bw:plan:*`
- 发版号已经是 `v0.1` / `v0.2`，标签 `bw:released:*`，和上面不是一回事

每周定目标仍叫「周目标 / 本周目标」，创建版本没有上一发 / 未发，发版还能另填一个号，也不能改未发布的名字。人无法回答「这周在推哪个版本、上一个发出去的是谁」。

## 解决方案（体验语言）

一个版本就是一个 `v0.1`、`v0.2`。创建、排期、里程碑、发版用同一串字。

- 每周点「开始本版本」，会话里模型已经知道上一发、未发、推荐下一号；你确认本周这个版本，活打上 `bw:plan:v0.3`，里程碑就叫 `v0.3`。
- 自己创建版本时，弹窗写明上一发 / 未发，默认推荐下一号；不能和已有计划版本或已发号重名；未发布的可以改名。
- 在某个版本视图里点「发版本」，发出去的就是创建时的那个号，不能改。

ISO 周仍是节律（多久开一次运作活①、健康看哪几天），不再当版本名。

## 飞轮检验（对齐 03）

- **加强哪一截**：定框——版本目标是你确认的方向，不是从周号自动长出来的。
- **不把人拽回搬运工**：不新人肉对账三套号；创建时提示上一发 / 未发，会话里确认一次。
- **不破坏铁律**：完成永远人点；发版仍是人在该版本视图点的那一下；没数据不装绿。

## 约束

- 号的格式：`v` + 数字 + `.` + 数字（`v0.1`、`v1.0`）。标签 `bw:plan:v0.x`，里程碑标题同字，发版同字。
- 不再写 `bw:week:*`，不建周号里程碑。
- 已发的号锁死，不能改名。
- `principles/03` 先不动（主张另议）。词表立「版本目标」。
