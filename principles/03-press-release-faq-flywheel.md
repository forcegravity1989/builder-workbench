## A. 新闻稿（Press Release）

> 模拟产品「可对内/对外讲清」当天的公告。人话，约一页。技术细节不进正文。

### 标题

**Builders' Workbench：你定要做什么，队友把其余跑完**

### 副标题

给 Super Builder 的 AI 时代工作台。你定项目是什么、往哪走、这一周推什么；每天只看两件事：这件事要不要做，和它长什么样、怎么操作。看着不对就当场跟队友聊；聊不够、或你要亲手试，就在这个 gate 上开一棵独立 worktree 自己干。风险大的方案才来找你。规划到运营在同一个平台上搞定。

### 总结

Builders' Workbench（仓库名 loop-buddy，产品里的 AI 程序自称 buddy）是本机桌面工作台，面向 **super builder**：一个人从想法 own 到持续运营的构建者。

AI 时代写代码已经很快，六个阶段（规划、设计、构建、发布、维护、运营）可以一周走完一个迭代。方向不能外包：项目是什么、对标谁、成功长什么样、近期往哪走、这一周要推动什么，必须是你定的。框定下来之后，你只在**少数几个 gate** 上出现——gate 就是必须你拍板才能往下走的那几处：**这件事做不做**，以及**它长什么样、怎么操作**——后者必须有能点的原型和写清楚的操作逻辑，不能只有一段文字。技术方案默认不来烦你，只有风险大的才送到你面前。中间的活——把方案拆开、动手实现、自己先跑一遍检查、准备发版、日常维护——队友自动干完。

gate 不是「同意 / 退回」两个按钮。很多时候你既不满意也说不清该怎么改，那就**在 gate 上直接聊**：把队友的方案质询到你满意，来回几轮换出一个新方案。聊完的结论就地改写这件事的正文——想清楚的东西留在这件事上，而不是散在某个聊天窗口里。这场对话跟着这件事存着，下次接着聊不用重新交代背景。还有时候文字和原型都不够，你要亲手摸一下代码或试一条路——那就**在这个 gate 上开一棵独立 worktree**：改动不污染主工作区，干完把结论带回这件事；开树不等于过 gate，合回与往下走仍要你显式认。

架构上的欠账不靠你逐份读方案、逐行读代码。工作台持续维护一份**架构全景**，随代码更新。你和**架构师队友**定期对着全景和真实代码盘一遍：哪笔债现在还、哪笔先记着。盘出来的结论变成**下一次迭代要做的事**，回到你的 gate 上。进度与健康只来自真实记录：没有数据就显示灰色「未知」，绝不假装绿。

### 痛点

Super builder 要带着 agent 做完所有事，但今天的工具要么让人当搬运工，要么把 gate 开成审批流：

- **人被按成项目经理或陪跑打字员**：AI 已经能写方案、改代码、跑检查，人却还在五个窗口之间拷上下文、催进度、盯着屏幕上一行行输出。一周本够走完一次迭代，时间耗在换工具上。
- **要点头的地方太多，等于没有 gate**：每一份方案、每一处改动、每一次合并都要你同意，队列变成审批瀑布。人疲于点「同意」，真正该想清楚的「做不做」和「长什么样」反而糊弄过去。
- **gate 只给「同意 / 退回」，商量与动手都没有地方**：真实情况常常是「不对，但也不是简单退回」；有时还要亲手试一版才知道怎么认。今天你只能另开聊天窗口或另开编辑器，上下文全断；聊出来的方案、试出来的改动都得手工搬回工单。想清楚的过程、动手试错的过程，和这件事本身是断开的。
- **方向被代填，或根本没人定**：创建向导和周报模板会替你编一套看起来很完整的目标；或者工具只给一块看板，方向仍在你脑子里。框是空的，后面所有判断都无处对齐。
- **架构欠账没有正本**：风险散落在评论和聊天里。没有一份跟着代码走的架构全景，欠账要么被绿灯盖住，要么靠你临时回忆。最快的假完成，就是「方案我看过了」，而架构的真实样子从没人更新。

### 解决方案

一张工作台把六个阶段收成**同一次迭代**：每一段在台上做完「这次迭代的最小动作」，做完的东西交到下一段接着干。不是把设计工具、编辑器、托管、监控六套软件焊进一个窗口；要更深的专才工具可以出去用，结论回到这张台上。

人在台上的工作分两层。第一层是**定框**，低频，但必须是你：

- **基础信息**：这项目做什么、对标谁、三个月成功长什么样。
- **发展方向**：近期往哪走；对外可见的版本是方向落地的记号，不是另做一份甘特图。
- **周目标**：这一周要把哪几件事、哪几个数字往哪推。周目标与基础信息同类：是你定的方向，不是从卡片堆里自动长出来的。

队友可以给草稿，正本只能你确认。没有框，后面的「做不做」无从判断。

第二层是**迭代**。每天的主界面是你的待办判断，里面**只该出现必须你拍板的少数几件事**：

1. **要不要做**（意图 gate）：这件事值不值得做、是否落在本周目标里、范围砍掉哪些。这个 gate 几乎每次迭代都有。
2. **长什么样、怎么操作**（规格 gate）：必须配**能点的原型**和**操作逻辑**——用户怎么走完、边界情况和出错时怎么办。缺这两样，这个 gate 直接退回，不往下走。
3. **偶发：风险大的方案**：技术方案默认不进你的待办，队友按你认过的样子自己拆、自己做。只有可能伤到数据、权限、对外承诺，或者发出去收不回来的，才升级到你面前。什么算「风险大」由产品判定，不靠队友临场决定要不要请示。
4. **架构盘账**：你和架构师队友对着架构全景与真实代码盘欠账与风险，把结论变成下一次迭代要做的事。这不是每天多一道技术审批，而是让欠账有地方被看见、有出口被排上。

每个 gate 上除了「认」和「退回」，还有两个并列选择：

- **接着聊**：就地跟队友对话——追问为什么这么设计、给出你的顾虑、让它出两个备选、拿掉你不要的部分。聊到满意，这件事的正文就按谈定的结果改写，然后你再认。这场对话属于这件事，随它一起存着，隔天回来接着聊不用重新交代背景；架构盘账也是这样谈出来的。
- **开独立 worktree**：当你觉得聊不够、或必须亲手试一条路时，就在这个 gate 上开一棵挂在这件事上的 worktree，自己改、自己跑，也可以在树里继续带队友干。改动落在这棵树上，不直接进主工作区；试清楚之后把结论写回这件事的正文（或带着证据回来再认）。**开树、在树里干活，都不等于过 gate**——合回与往下走仍是显式「认」。

聊过 ≠ 过 gate，开过树 ≠ 过 gate：一次都没点「认」的东西不会往下走。默认路径仍是认过之后队友自动跑；开 worktree 是 escape hatch，不是把你拉回全职实现岗。

除此之外**默认自动跑**：实现、自检、准备发版、日常维护的探测与起草。你认过「做不做」和「长什么样」，中间就不该再排队等你点头。自己用的时候发现别扭、线上发现异常，写成下一次迭代要做的事——而不是在每一棒后面再加一道「人点完成」。

### 为何做（负责人视角）

我们相信：AI 时代 super builder 的稀缺能力不是「会不会写代码」，也不是「能不能把每个 gate 都点一遍」，而是**先能定框，再把判断压在少数几个 gate 上**。框是基础信息、发展方向、周目标。gate 是「做不做」、「长什么样怎么操作」、偶发的大风险方案，以及把架构盘出来的欠账排进下一次迭代。点一百张绿卡片、让检查替你签字、让模板替你写目标，那都不算判断。工具应把能自动跑的段交给队友，把人的日程还给定方向、少而硬的评审、和架构的真实样子。再做一块会发光的看板或又一条审批流，解决不了真实的项目问题。

### 客户会怎么说（目标体验，非虚构背书）

「接入时我对标谁、三个月算成功，是我填的，工作台没替我编。这周目标就一句：登录能走通。待办里只有两类：第三方登录本周不做，我砍掉；登录页原型点开一看，验证码那段不是我要的——我没退回，就在这件事上跟队友聊了十几分钟，它给了两个方案，我们并成第三个，正文当场改成新的，我才认。大风险那次会话迁移方案升上来，我光聊不放心，就在那个 gate 上开了一棵独立 worktree，自己试了回滚路径，确认能退才认。技术方案平时没来烦我，队友自己做完了。周中架构师队友拿出全景，说会话这块欠了账，我们聊完写成下周第一件事：先还这块，再加社交登录。我没有在五个窗口里找进度，也没有把聊出来的方案、试出来的改动手工搬回工单。」

### 如何获得

本机安装桌面应用（macOS / Windows）。干活需要本机可用的 AI 命令行工具。当前以内部构建者试用为主；对外分发与签名仍在路上，不以本文冒充已上架商店。**现在实际做到哪、哪些还只是主张**，见内部 FAQ「现在做到哪」。

## B. 外部 FAQ（客户会问）

**这不就是又一块看板吗？和 Jira / Linear 差在哪？**  
差在你坐在哪、要点头的地方有多少。Jira / Linear 的主角是工单状态，交棒靠评论和列；派给云端 agent 之后，人还是在列之间搬。这里的主角是一件事从想法走到上线：要不要做 → 长什么样怎么操作 → 队友做完 → 发出去 → 用起来的反馈回到下一次迭代。你每天面对的是自己的判断队列，不是一块全生命周期审批板。

**那不就是 Cursor / Claude Code 外面套一层壳？**  
不是。它们是构建段的手，解决「这段代码怎么改」。迭代的瓶颈在手的两边：这件事该不该做、长什么样才算对、架构欠了什么账、下一次迭代改什么。Workbench 管整个迭代，构建段默认自动跑，不把你按在编辑器里旁观打字。把「写代码更快」当成核心利益，是买错产品。

**Lovable / Bolt 已经能从想法到 URL，为什么还要 gate？**  
因为 URL 不是运营，检查全绿也不代表这是你要的东西。提示生成应用把 gate 省光，假完成最快。我们是把 gate **收少**，不是取消：做不做、长什么样，仍要你认；风险大的仍要升级到你。真正缺的是敢交给用户，以及能把欠账和用起来的别扭写回下一次迭代。

**我不满意，但也说不清该怎么改，只能退回吗？**  
不。gate 上除了认和退回，还有两个选择：接着聊，或开一棵独立 worktree 亲手试。聊：追问它为什么这么设计、说出你的顾虑、要它出两个备选、把你不要的部分拿掉；来回几轮换出新方案，正文就地改写，然后你再认。开树：改动落在挂在这件事上的独立树上，不污染主工作区；试清楚把结论带回这件事。聊和开树都不是绕过 gate——一次都没点「认」的东西不会往下走。

**这不就是在待办里塞个聊天框？会不会最后变成聊天软件？**  
差别是对话有归属、有出口。它绑在具体这件事上，不是一条通用聊天流：隔天回来接着聊不用重新交代背景，聊出的结论必须落回这件事的正文，否则等于没聊。会话记录是过程，正文才是正本——下游队友照正文干活，不去猜你们聊天时的语气。产品要是让你只剩一个大聊天框、什么都靠翻记录，那就做砸了。

**开独立 worktree 不就是又把我按回写代码吗？和 Cursor 差在哪？**  
差在座位和归属。你是从**这件事的 gate** 上开树，不是另开一个和工单断开的编辑器窗口。树挂在这件事上：干完结论要落回正文，合回与往下走仍要你显式认。默认路径仍是认过之后队友自动跑；开树是 escape hatch——聊不够、或大风险必须亲手验证时才用，不是每天主业。

**项目基础信息、发展方向、周目标，是不是也在待办里点一下就行？**  
不是。那是**定框**，和审一件具体的事不是一类。接入时你要回答：做什么、对标谁、成功长什么样；方向变了你改方向；每周要有一句周目标。队友可以起草候选，正本必须你确认。没有周目标，本周的事无处对齐，应该先拦住你去定框。

**AI 能不能自动帮我写目标和周目标？**  
能起草，不能生效。没经你确认的目标视同没定。这与「中间自动跑，但定框和 gate 不代做」是同一条底线。

**技术方案我是不是永远不用看？**  
默认不用。队友按你认过的样子自己拆、自己做。只有风险大的才送到你面前：动到不可逆的数据、扩大权限与密钥、改变对外承诺、发出去收不回来。什么算风险大由产品判定，不靠队友临场觉得「这个是不是该请示一下」——那样要么事事请示，要么从不请示。

**为什么规格必须配原型和操作逻辑？**  
因为纯文字最容易「看起来很完整，做出来不是那回事」。原型让你能点；操作逻辑写清主路径、分支和出错怎么办。缺这两样这个 gate 直接退回，不许拿「先让队友做着」跳过。这是把设计段的最小动作留在台上，而不是把你赶去另一个设计工具再口头对一遍。

**架构全景是什么？谁维护？**  
一份跟着代码走的架构说明：系统由哪些部分组成、跑起来怎么交互、代码怎么组织、部署在哪，再配上关键场景。由架构师队友持续更新，你定期和它一起盘：哪笔欠账现在还、哪笔先记着。盘出来的结论变成下一次迭代要做的事，不是在待办里多出一列「请批准这份重构方案」。

**我很会写代码。为什么不自己打开 IDE 把关？**  
你会写代码，是你盘架构、判断大风险、以及必要时在 gate 上开独立 worktree 亲手验证的资格，不是把你拉回全职实现岗。默认路径是：样子认过 → 队友自动跑 → 你在架构全景上看真实结构。另开一个和工单断开的 IDE，正是这套「少 gate」要淘汰的断上下文；在 gate 上开树则挂在这件事上，合回与往下走仍要显式认。开树是 escape hatch，不是每天主业。

**我不太会写代码，是不是用不了？**  
Super builder 仍要 own 后果：发出去的版本、数据、密钥、能不能回滚。你可以少写实现，但不能不定「做不做」和「长什么样」，也不能对架构全景里标红的欠账长期装作没看见。gate 上的原型和操作逻辑应该用人话写清；看不懂风险大的方案就退回去，让队友讲明白再来。不适合的人：只想口头说一句「做个 App」，既不定对标和周目标，也不认样子。

**AI 说全绿了，我还要干什么？**  
绿的是它自己给自己的检查，不能替你认「做不做」和「长什么样」，也不能把架构欠账涂绿。你的活仍是：定框、过那几个 gate、和架构师队友把欠账排进下一次迭代。全绿却跳过规格 gate、或让模板代填周目标，比没有工作台更危险，因为假完成会进真实用户。

**还要自己试用吗？和「自动跑」冲不冲突？**  
不冲突。自动跑的是中间的实现和检查；增量能点的时候你仍应自己走一遍，别扭写成下一次迭代要做的事。试用不是卡在每一棒后面的强制 gate，而是回流的燃料——发现问题就进下一次迭代，而不是拦着队友把你已经认过的东西做完。

**没有大风险时，队友能不能直接改代码？**  
可以——前提是「做不做」和「长什么样」你已经认过。样子没认就动代码，不行；该升级的风险没升级、或升级后你没认就往下做，也不行。去掉的是「每份方案都得等人」，不是「什么都没定也能动手」。

**人既定产品又盘架构，职责分离还成立吗？**  
分离的是**人和 agent**，不是两个工种的人。同一个人可以既定范围又盘架构，但写出这份改动的队友不能宣布你的 gate 已经过，也不能自己把欠账悄悄勾掉。你是 gate 和欠账的主人，它是手。

**这不就是把我变成瓶颈？一周还怎么迭代得完？**  
gate 少了才转得快。定框是低频；日常待办只有那两类，风险大的才加塞。真瓶颈是把自动跑的段又做成等你点头，或者把架构盘账做成每天一场答辩。产品要是让你在终端里逐次点「允许」，或者每份方案都排进你的队列，那是设计失败，不是迭代节奏失败。

**「一站式」是不是六套软件焊在一起？**  
不是。一站式 = 六个阶段在这次迭代里的最小动作能在台上做完并交棒，你不当搬运工。不自建完整的设计器、编辑器、托管、投放。原型和操作逻辑是规格 gate 的一部分，不是另做一套设计产品。

**六个阶段一周迭代一次，跟不上怪谁？**  
先怪产品。标志：没有你确认的周目标却在报进度；没有原型也能过规格 gate；没有大风险却塞满技术方案；架构全景长期不更新却说欠账可控；反馈和欠账写不回下一次迭代。再怪使用：一律盲过、从不点原型、从不盘架构。

**高效体现在哪？**  
你的日程是定框 + 几个 gate + 定期盘架构，不是陪跑，也不是全段审批。看着不对就聊，必要时开独立 worktree 亲手试；样子认过，中间自动跑完。你反复退回的东西会被记住，下一次迭代少解释一遍。方向和周目标不会被「自动替你想产品」。

**高可靠是什么意思？AI 会替我过 gate 吗？**  
不会。目标、周目标、做不做、长什么样，必须你确认；风险大的方案升级后也必须你认。自动跑不等于自动过 gate。没有数据就显示灰色「未知」。定时任务可以把事情推进队列，绝不代做定框和 gate 上的判断。

**数据在哪？要上云吗？**  
默认本机。要做什么、长什么样、架构全景、发过哪些版本、回流了什么，正本都落在你自己的代码仓，和代码同一套历史。AI 用你本机的命令行工具。

**怎么开始？**  
安装桌面应用 → 接入项目并确认基础信息 → 定这周目标 → 队友起草落在这个目标里的事 → 你在待办里过「做不做」和「长什么样」→ 认过之后看队友跑完；周期性和架构师队友盘一次欠账，排进下一次迭代。

## C. 内部 FAQ（硬核挑战 · 实现与现状）

> 本节承接实现质疑：怎么做、怎么防作弊、现在做到哪、代价与风险。术语可以用工程话。

**现在做到哪，哪些还只是主张？**  
草稿里已有：完成权在人、没数据不装绿、agent 能在真实目录改文件并留运行记录；接入时问对标与成功标准、V4 有周目标链与会话表 / 内嵌终端，issue worktree 供给已在干活路径存在，仍是草稿形态。**尚未交付**：少 gate 待办主界面、gate 上会话（绑制品、续聊、谈定即改写正文）、**gate 上「开独立 worktree」**（树挂制品、合回≠过 gate）、规格 gate 强制原型与操作逻辑、大风险升 gate 清单、认过之后中间段真正自动跑完、架构全景（4+1）正本与「盘账 → 下一次迭代的意图」回流。现行主路径仍是项目墙 / 看板 / 建卡开工 / 人点完成，是脚手架，不得对外讲成新闻稿里的形态。签名分发等欠账写进 architecture 留白或对应 `changes/`，不另开第二份总表。

**架构全景具体是什么？**  
Kruchten 4+1：逻辑、过程、开发、物理四视图 + 场景。正本在项目仓，由架构师队友对照代码持续更新。人读的是「相对上次变了什么、哪笔债建议进下一次迭代」，不是读一篇全量文档。长期无更新却报绿 = 腐烂指标。盘账的产出必须是意图候选，不是又一篇永久 wiki。

**gate 上的会话怎么做，才不会把待办退化成聊天流？**  
四条约束。（1）**有归属**：会话绑定具体制品（这份 intent / 这份 spec / 这次盘账），不是项目级通用聊天；同一制品可多轮续聊，历史随制品加载，不靠人重新粘上下文。（2）**有出口**：会话的产出必须是**制品修订**——谈定即改写 intent / spec 正文并留下版本痕迹。只有会话记录、正文没动，视为没结论。（3）**聊 ≠ 过 gate**：接受仍是显式动作；禁止用「聊过了」「上面聊过一版」推断已接受。（4）**正本分层**：正文是正本，会话是过程证据；下游自动跑段读正文，不读聊天记录，避免把语气当规格。

**会话与内嵌终端 / 干活会话是同一条东西吗？**  
不是同一用途，可共用底座。gate 上会话是**商量制品**（改文本、出备选、质询设计），默认不落代码改动。**开独立 worktree** 是另一条显式动作：从该 gate / 制品起一棵隔离树，人（可带队友）在树里改文件、跑检查；用途是亲手验证或探路，不是悄悄合进主工作区。共用执行器与会话存储可以，但三条不得破：（1）开树 ≠ 过 gate；（2）树内改动不得自动合回主工作区或自动推进下一棒；（3）合回 / 往下走仍须显式「认」。禁止把「接着聊」默默打通成改仓——那等于绕过「没认过样子不动主仓」。V4 已有会话表、内嵌终端与 issue worktree 供给可作底座，gate 入口形态仍是草稿。

**gate 上开独立 worktree 怎么防「开了就算过」？**  
四条。（1）**有归属**：worktree 绑定具体制品 / gate 条目，不是项目级随便开的旁路目录。（2）**有出口**：试清楚后的结论应写回制品正文或作为该 gate 的可核证据；只有脏树、正文不动，视为没结论。（3）**开树 ≠ 过 gate**：接受与合回都是显式动作；禁止用「我改过了」「树里绿了」推断已接受。（4）**主仓隔离**：未认之前，自动跑段与主工作区不得吃这棵树的改动。escape hatch 用得多到变成主路径（人天天在树里陪跑）→ 产品失败信号，不是特性成功。

**「大风险」升 gate 标准怎么定，才不会退化成事事请示或从不请示？**  
产品给可核清单（初值可含：破坏性迁移、权限/密钥面扩大、对外契约变更、不可逆发布、跨边界数据流出）。命中则强制进人队列；未命中不得进。清单可演进，变更要留痕。禁止「模型自觉重要」当升 gate 条件。

**默认不审实施计划，实施会不会漂出规格？**  
会，这是工程要扛的风险。已接受的 spec（含原型与操作逻辑）是基准；自动跑段必须能对照 spec 自检并标出偏差。漂出且命中升 gate 清单 → 停跑并升 gate。漂出但不命中 → 记入架构全景 / 盘账，必要时生成下一次迭代的意图，而不是默默当完成。禁止「做完再补一份好看的 plan」冒充依据。

**规格 gate 如何强制「有原型 + 操作逻辑」？**  
用类型或提交守卫：缺原型附件/链接、或缺操作逻辑段，不得从该 gate 接受。口头「就是那个按钮」不算。现行草稿无此 gate，主张如此。

**无规格不得改仓，怎么保证不是提示词自觉？**  
状态机：spec 未接受则 `RunIssue` 一类开工命令不得进入改文件路径；命中升 gate 清单而人未接受同理。这条要进类型或钩子，不靠提示词。

**写代码的和盘架构的是同一个模型，架构全景是不是装样子？**  
所以人必须参与盘账确认：哪笔债进下一次迭代、哪笔接受暂缓。架构师队友可起草视图与候选意图，不能自行宣布债已还清、不能让周目标生效。禁止同一会话改完代码后把开发视图里的债项静默勾掉。写代码的会话不得给自己过任何 gate。

**测试全绿但产品不好用，以谁为准？**  
体感与 spec。绿只能证明自动跑段里写过的检查。不好用写成反馈或新意图；禁止用 CI 绿关闭「spec 已兑现」。修 bug 时禁止改测试取绿。

**过生产 / 发版还要人吗？**  
命中升 gate 清单的必须升 gate。常规发版可走自动跑，但要留可核记录，且沿用灰灯规则（无数据 = Unknown，不装绿）。「敢不敢给这批用户」若改变了范围相对周目标的关系，走意图 gate，不塞进技术方案队列。

**维护段：模型诊断 vs 人，谁说了算？**  
越线检测尽量确定性脚本（阈值 / 控制带），不用模型决定「有没有事」。模型可起草诊断与新意图。人经意图 gate 决定现在修、排期、或关掉并写明为何不是故障；关掉必须留痕，不能用嘴把灯按灭。维护段同样更新过程 / 物理视图。

**我们会不会做成带 AI 的 GitHub 或又一条审批流？**  
若主路径变成「每 PR 必审」或「去托管网站点完成再回来点一下」，就是做成了。目标主路径：少 gate（意图 / 规格 / 偶发大风险）→ 自动跑 → 4+1 盘账回流意图。GitHub / codehub 是仓与合入的执行面，可以是正本所在，不是人每天的主座位。

**主要技术难点？**  
少 gate 状态机（无 spec 不改主仓；升 gate 未接受不继续）；gate 上会话与制品的双向绑定（续聊上下文、谈定即改写正文并留版本痕迹、聊过不算过 gate）；**gate 上开独立 worktree**（树挂制品、隔离于主仓、开树/合回均≠过 gate）；spec 制品强制原型与操作逻辑；升 gate 清单与自动跑的交接；4+1 与代码对照及「盘账 → 意图」回流；接受即真正启动下一棒。本机终端、灰灯派生、agent 真改仓仍是底座。V3/V4 只覆盖底座切片。

**成本与代价？**  
工程：从「双 gate 密审 + 人点完成」收敛到「少 gate + 自动跑 + 4+1」，草稿路径让路，不为旧主路径留兼容层。用户：本机 CLI 与配额；必须愿意定框、认 spec、周期性盘架构。不愿 own 技术后果的人不是客群，不能用「降低门槛」去卖。

**周目标和 gate 上的判断如何分工？**  
周目标是框。单次意图问：是否服务这句目标。盘账产出的意图同样要对齐框。改目标走定框，不走「接受这份意图」。禁止从完成卡片反推周目标。

**Agent 代填基础信息、目标、周目标怎么办？**  
起草必须标明草稿；未确认不得点灯、不得当正本、不得当对齐基准。铁律，不是文案偏好。

**还可能翻车的产品风险？**  
待办又被方案和日志塞满；gate 上会话滑成通用聊天框，结论只在记录里、正文不动，或「聊过」被当成已接受；**开独立 worktree 变成每天主业**，或开树/树内绿被当成过 gate、脏树自动合回主仓；规格 gate 不强制原型；升 gate 清单过宽或过窄；4+1 变文档坟场；用第二个 agent 静默过 gate；对外把草稿看板讲成已交付；创建流用生成文本冒充用户已定方向。扩大客群到不愿定框、不认 spec 的人，或做成团队全员收件箱，须先改本文。

**成功怎么量？**  
一周内同一张台上：有你确认的周目标；意图与带原型的 spec 被真接受；接受后中间段自动跑完而无需密审方案；4+1 有更新或明确「无变化」记录；至少一笔欠账 / 体感回流成下一次迭代的意图；全部仓内可核。正向信号还包括：gate 上聊过的制品有对应正文修订（谈定→改写的转化率）。**反指标**：无大风险却高频方案入队、无原型仍过规格 gate、代填目标未确认却生效、4+1 长期不动却报绿、盲过留痕率为零、会话轮次涨而正文修订数不涨（聊了不落）。不设公开营收 KPI。

**为何不是云多人协作？**  
假设 1 个 Super builder + Agent Loop（含架构师队友）。他人可靠同一代码仓审和合，不在产品里建成员、群聊、全员收件箱。多人审批流是另一类产品，先改本文再开 `changes/`。

**现行看板、开工、人点完成怎么处置？**  
脚手架。保留铁律：gate 是人过、agent 真改仓、灰灯未知。主界面迁到少 gate 待办；中间段改为自动跑；完成键不得冒充意图 / spec 已过。特性若方案仍是「加一列看板」或「每份方案进队」，对齐本文驳回。

## D. 飞轮（The Flywheel）

```text
         ┌──────────────────────────────────────────────────────────────┐
         │                                                              │
         ▼                                                              │
   你定的框：基础信息 / 发展方向 / 周目标                               │
         │                                                              │
         ▼                                                              │
   少 gate 待办：做不做 → 长什么样怎么操作 →（偶发）大风险方案          │
         │                                                              │
         ▼                                                              │
   gate 上聊，或开独立 worktree 亲手试 → 结论落回正文，然后你认         │
         │                                                              │
         ▼                                                              │
   你认过之后，队友自动跑完中间段，迭代在台上推进                       │
         │                                                              │
         ▼                                                              │
   架构全景养账；你与架构师队友盘一遍 → 排进下一次迭代要做的事          │
         │                                                              │
         ▼                                                              │
   灯不装绿、gate 少但硬 → 你更敢让队友自己跑更久                      │
         │                                                              │
         ▼                                                              │
   做过的打法蒸馏成技能 → 下一次迭代更贴你，待办更干净 ────────────────┘
```

**飞轮检验（任何特性级变更都要答）：**  
它加强的是上面哪一截（人定的框 / 少 gate 待办 / gate 上聊或开树探路 / 认过即自动跑 / 架构盘账回流 / 可信所以敢放手 / 技能更贴）？  
会不会把人拽回「盯终端、拖卡片、当搬运工」，或「每份方案、每处改动都要点头」，或「好方案聊出来了 / 试出来了却要手工搬回工单」，或「让模板与 agent 代填方向和周目标」，或「开独立 worktree 变成每天主业」？  
会不会破坏这几条：做不做与长什么样必须人认 / 聊过不等于过 gate、谈定必须落成正文修订 / 开树不等于过 gate、树内改动不得自动合回主仓 / 没认过样子不动主仓 / 该升 gate 的没认过不许继续 / 没数据显示未知 / 写代码的队友不能给自己放行 / 定时只建队列、不代做判断与定框？  
说不清、削弱上面任一条、做成团队协同云、六套车间并集或密审批流 → 意图 gate 应驳回或拆小。
