# distill — 去掉任务障碍

本篇改写自 Impeccable 的 distill 方法；固定版本见 [impeccable-source.json](../impeccable-source.json)，保留 [原命令](../upstream/impeccable/distill.md) 与 [许可](../licenses/pbakaus--impeccable/LICENSE)。不执行原工具链、相邻命令或创建新的设计上下文。

## 确定核心任务

完整读取 [本目录适用边界](../README.md)、[设计系统 guidelines](../../../../docs/04-design-system/guidelines.md) 与 [开发规范](../../../../docs/development.md)。从用户目标、已有特性规格和真实使用路径确定本次任务，不把当前截图当作全部需求。缺必要决定时用 AskUserQuestion 提供具体选项。

## 简化

1. 列出妨碍当前任务的重复读数、冗余操作、无效装饰、错误层级与无依据差异；给出位置、实际影响和已有行为依据。
2. 先复用统一原语和术语，去掉重复展示、无意义外壳、只为好看添加的标签。不要删除恢复入口、失败信息、来源身份、权限说明或数据未知状态。
3. 渐进披露必须保留清楚入口；移走内容前检查用户何时需要它以及现有旅程，不用“更简洁”掩盖信息不可达。
4. 合并控件或削减步骤前核对作用对象、确认点和数据契约。需要改用户路径、布局结构或能力范围时，按已有特性确认规则说明差异并确认；仅依赖该决定的改动暂停。
5. 文案写对象、动作、结果，沿用领域词；精简后仍说明失败原因与下一步。不要靠省字删除关键操作条件。

## 验证

复走主路径与恢复路径，核对鼠标/键盘、长内容、空/加载/失败状态。对照应有能力而非只比较元素数量，按开发规范报告真壳证据与未验范围。简化产生的稳定定义写回所属正本，过程和删除理由留 PR，不新增第二份规格。
