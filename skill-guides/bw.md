# Monica 使用指南

> 面向使用 BW 的同事和答疑模型。按任务查阅 BW 专属操作。
> 操作变化时核对实际控件、对应旅程指南和引导矩阵，然后重新生成 CLI 制品。

`ORCA` is the executable you resolved in the stub. 使用当前 BW 安装提供的 CLI。
工作区、终端和其他 Orca 原生操作，查 `ORCA skills get orca-cli`。
跨设备回答时先核对用户版本与执行端版本，按用户看到的入口给出下一步。

## 按问题查资料

通过同一 CLI 执行 `ORCA skills get bw --reference <主题>`。问项目墙和方向取 `project-direction`，问版本计划取 `version-planning`，问版本验收取 `version-acceptance`，问交付与评审取 `issue-delivery`。随版正文可以在没有源码的机器读取。旧版界面可能显示 BW。先给用户眼下要做的一步，对方想看演示时再给帮助路径。

## 这个版本做得怎么样？为什么没有读数？

打开该版「版本总览」，核对目标、任务和已有验收结果。想看产品实际效果，打开「项目总览」，在记分牌选指标并核对读数所属周，再和计划中的目标比较。空读数表示还缺数据；点刷新再看。若提示来源或配置问题，查看详情，选「配置指标」打开草稿并核对后发送。将仍需调查的偏差记进原任务或下一版计划。帮助里的“看效果”演示使用样例数据。

## 用户是在问产品还是当前业务项目？

用户提到按钮、异常或“这个项目”时，结合原话确认对象。已经说清是 Monica 自身的问题时，可先说明用法；仍想反馈就保留原问题、已试步骤与结果，使用改进助手。远端 Bot 只能使用自己所在宿主可读的信息。需要用户所见画面时请对方在出问题的页面批注；不要求普通用户克隆 BW 源码。明确要求处理业务项目任务时沿该项目的工作方式继续。

## 开始使用

- 打开「项目墙」，按项目名搜索。找不到时清除搜索和筛选；要纳入自己的 Git 项目，从「添加项目」选择。项目卡出现后点击项目名进入工作区。要看名片和里程碑，打开项目卡的「项目总览」。
- 没有项目时也可从左下角「帮助 → 探索 Monica → 工作旅程」播放样例，按需要选择项目方向、版本计划、构建交付或验收成果。
- 准备版本计划时，展开对应版本并点「计划」。首版从「新建版本」进入。点「开始计划」，核对原生会话里的草稿并发送。
- 核对本版成果时，展开同版的「验收」。点「开始验收」可打开预填会话；从「验收准备」和 Showcase 对照已有证据，由人确认各目标结果。

## 反馈 BW 界面里的问题

1. 在问题页面按 Windows `Ctrl+Alt+B` 或 macOS `⌘⌥B` 唤起批注。若修改过快捷键，在「设置 → 快捷键」搜索「批注」。
2. 选中对应控件，写一句发生了什么并保存。点批注浮窗复制旁的纸飞机，在浮动工作区核对批注和起手提示，再按回车发送给改进助手。
3. 如果已经和助手排查过，可以把原问题、已试步骤、版本和可用截图放进批注或补到反馈草稿里。请改进助手按实际材料查重并整理 Issue。需要机器现场时，在出现问题的那台机器上采集。
4. 拿到 BW Issue 链接后，愿意修复的同事可从链接菜单选「开始修复」，在原生开工弹窗选择可用的 BW 项目和宿主。

只想发文字或截图时，用「帮助 → 发送反馈」。崩溃时用「发送崩溃报告」，补一句刚才正在做什么，并按界面选择是否附诊断。网页原型的意见用网页工具栏的元素批注。

## 同事问的其他操作

| 用户想做什么           | 从哪里继续                                                                                                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 找任务、继续之前的会话 | 从任务页查看 Issue、PR/MR，先核对来源和项目。找已规划的工作，从侧栏展开对应版本和目标；历史版本没有绑定工作区时仍可回看。                                                                            |
| 请同事评审             | 在工作树上下文菜单选「发送评审…」。若置灰，先确认这棵树关联了开放的 PR/MR。收件人从「待我评审」打开原生详情；在托管平台上的评论与合入沿用自己的权限。                                                |
| 分享本地报告           | 在本机打开可分享的 HTML 产物，从分享弹层生成链接，复制后给同事。已分享记录可从「设置 → Artifacts」找回；移除后原链接会失效。远程或网页客户端提示在主机打开时，回到文件所在的桌面端。                 |
| 连接内部服务           | 对 CodeHub 任务，先确认项目远端和登录身份；本机可用 codehub-cli auth status 核对登录。对 WeLink 团队目录，从团队设置核对绑定的群和群空间，以及本人的空间权限。登记地址后仍须在远程主机入口完成连接。 |
| 查看构建、部署或验收   | 在版本验收的准备区检查本项目配置的出包、部署与现成证据。配置缺失时仍可核对目标与报告。实际部署按项目已有流程和权限执行。                                                                             |
| 了解持续维护、沉淀复用 | 帮助中的这两条完整工作旅程标为建设中。先询问要完成的具体动作，再定位已有功能。                                                                                                                       |
